## 2026-09-29 그룹 한도 = 인당 한도로 전환 (설계안)

owner: Claude · reviewer: Codex(설계 승인 2026-09-29 — 수정 요청 2회 반영 · 코드 리뷰 승인 2026-09-29 — 수정 요청 4회 반영) · status: 검증 중(로컬 시험 통과 · 공유 서버 배포 전)

`frontend/src/lib/creditPlan.ts` · `CreditPoolSection.tsx` · `MemberTable.tsx` · `CreditPlanFields.tsx` · 관련 프런트 시험 · 이 문서

**Jay 결정(2026-09-29)** — 아래 09-23 §1·§2 의 "그룹 한도 ÷ 인원"과 09-28 의 "4,000 을 여러 명에게
나누면 각자 몫은 작다"를 **대체**한다.

- 그룹 한도 칸의 뜻 = **한 사람이 이번 기간에 쓸 수 있는 양**(인당). 실례: artist_test 한도 4,000 →
  멤버 각자 4,000(지금은 4,000÷7 = 571.43 으로 보이고, 09-28 거절 규칙이 배포되면 거기서 막힌다).
- 지갑(HF 잔액)은 매니저가 정기·긴급 충전으로 채운다. **인당 몫의 합이 충전액을 넘어도 정상**이다
  (경고하지 않는다).
- 그룹 카드의 남은 양은 **이번 기간만**(이월 없음) — 개인 몫(이월 없음)과 같은 규칙.

**계산 규칙(새)** — `L`=그룹 한도(인당, NULL=무제한), `o_i`=개인 덮어쓰기, `U`=이번 기간 사용.

```
내 몫     Q_i = o_i 있으면 o_i, 없으면 L            # L=NULL 이고 o_i 없으면 몫 없음(제한 없음)
그룹 몫합 T   = Σ Q_i  (L=NULL 이면 T=NULL)
그룹 남음 R   = T − U_group(이번 기간)              # 이월 없음. base_balance 를 쓰지 않는다
```

- 멤버 0명: `T=0`, `R=0 − U`(배정 없는 그룹의 사용은 0 이므로 0).
- `L=0`: 덮어쓴 사람만 몫이 있다.
- 소수: 계산은 원값, 표시만 둘째 자리(기존 규칙 유지).

**API(서버가 먼저 배포되므로 구버전 앱과의 호환을 지킨다)**

- `groups[]`: `quota_auto` = `L`(인당 기본 몫 — 구버전 앱의 '1인 몫' 칸이 그대로 맞는 값이 된다) ·
  `quota_fixed` 유지 · `quota_over` 는 항상 `false`(뜻이 없어짐) · **새** `quota_total`(=T).
  `remaining` = 새 R.
- `members[].quota_source`·`my_quota_source`·my-quota `source`: `auto` 의 뜻이 "그룹 인당 한도"로 바뀐다(값 이름은 유지).
- `my_group.group_carryover`: 0 으로 준다(구버전 앱이 '그룹 여유분'을 띄우지 않게). 새 앱은 표시하지 않는다.
- `remaining_override`(대시보드 '추정 → 힉스필드 값 맞추기'): 새 계산이 base_balance 를 안 쓰므로
  **받아도 무시**한다(400 을 내면 구버전 앱의 그룹 저장이 깨진다). 새 앱에서 '맞추기' 단추를 없앤다.
- `base_start`·`base_balance` 칸: 스키마·마이그레이션은 그대로 두고 **값을 동결**한다 — 기존 그룹 UPDATE 는 두 칸을
  쓰지 않고, 새 그룹 INSERT 만 `base_start`=이번 기간 시작(NOT NULL)·`base_balance`=0. 이월 함수
  (`_group_remaining`·`_carry_in`·`_rebase_month_groups_for_anchor`)는 호출을 모두 끊은 뒤 주석 처리하고,
  덩어리 삭제 규칙(주석 처리 → 재확인 → 정리)에 따라 다음 단계에서 지운다.

**화면**

- 대시보드 그룹 표: `한도` 칸 = "인당 4,000/월", `1인 몫` 칸 = 기본 몫 + 직접 정한 사람 표시,
  사용률·색 = `used ÷ T`, "한도 합 … 충전 초과" 경고 제거(한도 합 = Σ T 로 표시만).
- 내 몫 카드: "그룹 한도 ÷ N명" → "그룹 인당 한도", '그룹 여유분' 줄 제거.
- 관리 표: 그룹 시트 `한도` 머리글 "인당 한도", 그룹 남은 양 = 새 R. 멤버 배정 시트의 `남은 양 / 한도` 칸은
  **'인당 한도'(그룹 L)** 로 바꾼다(개인 몫·남은 양은 PM 권한인 '크레딧' 시트에만). 크레딧 시트 몫 칸 자리표시
  "자동 ○○" → "그룹 ○○".
- 그룹 편집 창: `한도` → "인당 한도", 주기 설명의 '다음 달로 넘어갑니다' 문구 제거.
- 생성은 몫을 확인하지 않는다(09-30 되돌림 — `my-quota` 는 계정 메뉴 표시만 읽는다). 계정 메뉴는 몫 계산은 그대로,
  문구(자동 배분 → 그룹 인당 한도)와 아래 '제한 없음' 표시만 바꾼다.

**제한 없음일 때(Jay 2026-09-29 추가)** — 그룹 한도가 없어 내 몫이 없으면(`source=unlimited`) 계정 메뉴는
"한도 없음" 대신 라벨 **"워크스페이스 잔액"** 으로 HF 보고 잔액(`activeCredits`, 이미 메뉴에 있는 값)을 크게 보여 준다.
**미배정도 같다(Jay 2026-09-29 뒤 결정 — "미배정은 지금처럼 '미배정'"을 뒤집음)**: 그룹에 들지 않은 사람(`unassigned`)도
기본으로 워크스페이스 남은 크레딧을 본다. 라벨·잔액·고리는 제한 없음과 같고, 안내 문구만 "그룹 미배정 · …"으로 가른다.
판정은 `showsWorkspacePool()`(`frontend/src/lib/myCreditQuota.ts`) 한 곳이다. (생성 때의 '미배정' 경고는 09-30 생성 확인 되돌림으로 함께 없어졌다.)

- **고리(Jay 2026-09-29 같은 날 추가 결정 — 처음엔 그리지 않기로 했던 것을 뒤집음)**: 잔액 ÷ 이번 충전 달 총량.
  총량 = 정기 충전(손 입력, 없으면 프로젝트 '매월 예산' 합) + 이번 충전 달 긴급 충전. `my-quota` 에 `pool_total`
  로 싣되 **몫이 없는 사람(source=unlimited·unassigned)에게만** 준다(몫이 있는 사람에게 충전 정보를 넓히지 않는다).
  이월로 잔액이 총량보다 크면 100% 로 꽉 찬다. 총량을 모르면(구서버·충전 미설정) 숫자만 보이고 고리는 없다.
- 견적·미확인 건수 안내는 '내 사용량'의 불확실성이라 잔액 표시 때는 숨긴다.

## 2. 계산 규칙

기호: 그룹 한도 `L`(NULL=무제한), 주기 `P`(day/week/month), 사람별 덮어쓰기 `o_i`(NULL=자동),
이번 기간 내 사용 `U_i`.

```
고정분  F   = Σ o_i (덮어쓴 사람들)
자동몫  a   = (L − F) / (자동인 사람 수)       # 분자가 음수면 0, 자동 인원 0명이면 a = null
내 몫   Q_i = o_i 있으면 o_i, 없으면 a
내 남음 R_i = Q_i − U_i                        # 음수면 "초과"로 표시(막지 않는다)
```

**경계 (전부 인수 시험으로 고정한다)**

| 경우 | 결과 |
|---|---|
| 자동 인원 0명(모두 덮어씀) | `quota_auto = null` — 나눗셈을 하지 않는다 |
| 그룹 멤버 0명 | 그룹 카드만, 개인 값 없음 |
| `L = 0` | 자동 몫 0 · 모두 "쓸 몫 없음" |
| `L = NULL`(무제한) | 자동 몫 없음. **덮어쓴 사람만** 그 값이 몫이 된다(개인 목표치). 나머지는 "제한 없음" |
| `F > L` | 자동 몫 0 + 그룹 카드에 "덮어쓴 합이 한도를 넘음(F/L)" 경고. 저장은 막지 않는다 |
| 소수 (100÷3) | 반올림하지 않는다. 화면은 둘째 자리까지 `≈` 로 표시하고, 합이 한도와 0.01 어긋나도 경고하지 않는다 |
| 입력값 | 유한한 0 이상 숫자만. NaN·무한대·음수는 400 |

**기간과 시계**

- 기간은 그룹 주기 `P` 를 따르고, 달 경계는 충전 기준일(`topup_day`)을 쓴다 — 그룹 카드와 같은 시계.
- 시계는 **KST 고정**이다(2026-09-23 구현 완료, §5 P0-2). 서버 OS 가 UTC 여도 경계가 안 밀린다.
- **개인 몫에는 이월이 없다.** 기간이 바뀌면 `U_i` 가 0 부터 다시 센다. 그룹 카드의 이월은 지금 그대로 두고
  화면에서 **'그룹 여유분'** 으로 따로 보여 준다(Codex 지적 ①-3: 두 숫자가 다른 돈을 가리키면 안 된다).
- 한도를 올리면 즉시 반영된다. `Q_i` 는 저장값이 아니라 그때의 `L`·인원·덮어쓰기로 매번 계산한다.
  Jay 예시: `L=4,000`·자동 1명 → `Q=4,000`, `U=4,000` → `R=0`. `L` 을 5,000 으로 올리면 `R=1,000`. ✓

**개인 사용량이 실제 차감과 다를 수 있는 자리 (화면에 그대로 밝힌다)**

- **미상**(실제·견적 둘 다 없는 생성물)은 0 으로 세고 건수만 센다 → 남은 양이 실제보다 커 보인다. 건수를 함께 표시.
- **환불**은 개인에 반영하지 않는다(Jay). 팀 거래 장부(`ledger`)에만 있다.
- **긴급 충전**은 그룹·개인 몫을 늘리지 않는다(풀 카드 표시용) — 늘리려면 매니저가 한도를 올린다.
- **날짜 없는 삭제분**(tombstone with no `created_at`)은 기간 집계에서 빠진다 → 그룹 카드의 '미분류'로 표시.

| 1 | **자동 몫을 계산 중간에 반올림** — 100÷3 을 33.33 으로 깎아 세 사람 합이 99.99, 33.335 를 쓴 사람이 −0.01 초과로 보였다 | 계산은 원값, 표시만 둘째 자리(`_shown_quota`). 경계 시험 2개가 되돌리면 깨진다 |
| 2 | 반올림 판별 도구가 **로컬 값이 있으면 서버 팩트를 안 봤다** — 화면이 읽는 값은 서버 쪽 | 로컬·서버를 각각 분류(`ok_metrics`/`ok_fact`/`rounded_*`) |
| 3 | 팀 잔액 합계가 **계정 훑는 순서로 옛 값**을 쓸 수 있었다 | 등록부(`workspace_registry`)를 단일 출처로 |
| 4 | `TZ` 를 `setdefault` 로 둬 밖의 `TZ=UTC0` 에 밀렸다 | 덮어쓰고, 바꿀 땐 `CONTENT_HUB_TZ` 로만. `serve.py` 는 uvicorn 보다 `app.config` 를 먼저 import(순서 시험) |
| 5 | 드릴이 **상단 통계·크레딧 카드까지 안 갔다** | 통계도 드릴 범위로. 카드는 워크스페이스 전체라고 화면에 밝힌다 |
| 6 | 내보내기 조건이 화면과 다를 수 있었다 | 내려받기 메뉴에 '담기는 범위'를 먼저 보여 준다(기간이 안 담기면 이유까지) |
| 7 | **구서버**에 새 화면이 붙으면 저장이 조용히 무시된다 | 몫·정기 충전 칸을 잠그고 "서버 업데이트 뒤"로. 멤버 카드도 '제한 없음' 대신 '—' |
