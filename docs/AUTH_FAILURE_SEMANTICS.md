# 인증 실패 의미 보존 계약 (RL-09)

기준 구현: `590298cb`

이 문서는 공유 서버 또는 로컬 허브가 반환한 `401`을 어떻게 해석할지 정한다. 핵심 원칙은
**업무 요청 하나가 거부됐다는 사실만으로 로그인 전체를 지우지 않는 것**이다.

## 1. 해결하려는 문제

기존 프록시는 공유 서버의 임의 API가 `401`을 반환하면 저장된 로그인 토큰을 즉시 삭제했다.
비밀번호 확인 실패, 권한 부족, 일시적인 서버·네트워크 문제도 로그인 만료처럼 취급될 수 있었고,
그 결과 사용자는 로그아웃되거나 화면이 로컬 모드로 바뀌어 데이터가 사라진 것처럼 보였다.

`401`은 다음 세 가지 의미를 구분해야 한다.

| 의미 | 예 | 로그인 처리 |
|---|---|---|
| 세션 자체가 무효 | 같은 토큰으로 `/api/auth/me`를 조회해도 `401` | 현재 토큰만 삭제하고 재로그인 요구 |
| 요청만 거부 | 비밀번호 불일치, 특정 동작 거부, `/api/auth/me`는 `2xx` | 로그인 유지 |
| 판정 불가 | 네트워크 단절, `5xx`, 확인 시간 초과 | 로그인 유지 후 다음 요청에서 재확인 |

## 2. 서버와 브라우저 사이의 표시

응답 헤더 `X-MVHub-Auth-State`가 판정 결과를 전달한다.

| 값 | 뜻 | 브라우저 동작 |
|---|---|---|
| `invalid` | 세션 무효가 확인됨 | 저장 토큰 삭제, 로그인 요구 이벤트 발생 |
| `preserved` | 요청별 거부 또는 판정 불가 | 기존 로그인 유지, 원래 오류를 화면에 전달 |
| 헤더 없음 | 구버전 서버 응답 | 이전 버전과 동일하게 토큰 삭제 |

`/api/auth/login` 같은 인증 API의 `401`은 로그인 시도 자체의 실패이므로 전역 로그인 토큰을
자동 삭제하지 않는다. 해당 화면의 로그인 처리 로직이 결과를 다룬다.

## 3. 판정 흐름

```text
업무 API 401
  └─ 같은 토큰으로 /api/auth/me 확인
       ├─ 401  → invalid → 현재 저장 토큰과 같은지 재확인 → 삭제
       ├─ 2xx  → preserved → 로그인 유지
       └─ 연결 실패·5xx·기타 → preserved → 로그인 유지
```

`/api/auth/me` 자체의 `401`은 이미 세션 확인 결과이므로 다시 조회하지 않는다.

확인하는 사이 사용자가 재로그인하거나 다른 계정으로 전환할 수 있다. 이때 늦게 도착한 옛 토큰의
`401`은 새 토큰을 지우지 않는다. 삭제 직전에 **보낸 토큰과 현재 저장 토큰이 같은지** 다시 비교한다.

## 4. 동시 요청과 장애 보호

한 화면에서 여러 API가 동시에 `401`을 받아도 같은 토큰의 `/api/auth/me` 확인은 한 요청만 수행한다.
나머지 요청은 확인 완료를 기다리거나 서버 스레드를 점유하지 않고 `preserved`로 처리한다.

- 확인 제한 시간: 5초
- 판정 공유 시간: 2초
- 메모리 캐시 상한: 8개 토큰·서버 조합
- 캐시 내용: 프로세스 메모리에만 존재하며 로그·DB에 새로 기록하지 않음

2초 안에 실제 토큰이 폐기되면 첫 확인 요청이 토큰을 지운다. 동시 후속 요청은 그동안 로그인을
보존할 수 있지만, 다음 요청에서 다시 인증 상태를 확인한다. 이 짧은 유예는 장애 순간의 확인 폭주와
작업 스레드 고갈을 막기 위한 의도적인 선택이다.

## 5. 적용 범위

- 로컬 허브의 JSON 프록시
- 공유 서버 파일 다운로드 프록시
- 중앙 전달 라우터와 스트리밍 전달 라우터
- 일반 계정 토큰과 10분 슈퍼 관리자 workspace 권한 토큰
- 로컬 서버 인증 미들웨어
- 프론트엔드 공통 HTTP 오류 처리

슈퍼 관리자 토큰은 일반 `Authorization`을 대체하지 않고
`X-MVHub-Super-Session` 헤더로만 추가 전달한다. 이 토큰은 다른 사람 생성물의
워크스페이스·프로젝트 귀속 변경에만 쓰며, 작성자·내용·삭제 권한으로 확장하지 않는다.
만료되면 슈퍼 관리자 토큰만 정리하고 본인 로그인 토큰은 건드리지 않는다.

발급 조건은 현재 로그인 계정의 영구 `admin` 역할과 현재 비밀번호 재확인이다. 서버가 서명 만료와
활성 세션 행을 함께 검사하므로 화면을 오래 열어 두거나 PC 시간을 바꿔도 10분 뒤에는 거부된다.
같은 계정이 재발급하면 이전 세션은 즉시 해제되며, 수동 해제와 관리자 역할 제거도 즉시 반영된다.

## 6. 검증 계약

PowerShell에서 프로젝트 루트를 기준으로 실행한다.

```powershell
cd backend
py -3 -m pytest tests\test_proxy_auth_semantics.py -q
py -3 -m pytest tests\test_super_admin.py tests\test_generation_routes.py -q

cd ..\frontend
npm.cmd test -- --run tests\httpAuthPolicy.test.ts
```

필수 경계 조건:

- `/api/auth/me`가 `2xx`면 원래 업무 API가 `401`이어도 토큰을 보존한다.
- `/api/auth/me`가 `401`일 때만 현재 토큰을 삭제한다.
- 확인 중 네트워크 오류가 나도 토큰을 삭제하지 않는다.
- 옛 응답이 새 로그인 토큰을 삭제하지 않는다.
- 100개 동시 `401`에서 인증 확인 네트워크 호출은 한 번만 실행된다.
- 느린 확인 중 두 번째 요청은 기다리지 않고 로그인을 보존한다.
- 실제 TCP 테스트 서버에서도 위 두 판정이 동일하게 동작한다.
- 브라우저에서 로그인 후 주요 탭을 전환해도 강제 로그아웃과 콘솔 오류가 없다.
- 슈퍼 관리자 토큰을 일반 로그인 토큰으로 사용할 수 없다.
- 다른 사람 생성물의 워크스페이스를 바꿔도 `creator_uid`는 유지되고 원 작성자의 수정 권한도 유지된다.
- 재발급·수동 해제·10분 만료 후에는 이전 슈퍼 관리자 토큰이 거부된다.

## 7. 남은 외부 확인

자동 테스트와 격리 브라우저는 통과했지만 아래 항목은 운영 배포 Gate에서 다시 확인한다.

- 실제 공유 서버에서 유효 토큰으로 요청별 `401`을 재현했을 때 로그인 유지
- 실제 만료 토큰으로 `/api/auth/me`가 `401`을 반환할 때 재로그인 화면 전환
- 구버전 로컬 허브와 새 공유 서버, 새 로컬 허브와 구버전 공유 서버의 혼합 업데이트

이 외부 확인 전에는 RL-09 내부 계약 완료와 운영 배포 완료를 같은 의미로 사용하지 않는다.
