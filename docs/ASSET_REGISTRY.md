# 에셋 대장(Asset Registry)

공유 서버가 PM 프로젝트 폴더(NAS)의 그림·영상마다 **번호(registry_asset_id)** 를 붙여 관리한다. 누가 탐색기에서 이름을
바꾸거나 옮기거나 같은 자리에 고쳐 저장해도 대장이 따라가 기록한다. 그래서 캔버스 레퍼런스가 끊기지 않고, 레퍼런스 찾기가
빨라지고, 생성 기록이 "어떤 그림의 어느 판을 썼는지"를 번호로 남긴다.

## 1. 무엇이 달라지나(사용자 눈으로)

| 상황 | 대장 전 | 대장 뒤 |
|---|---|---|
| 에셋 창에서 끌어온 그림의 NAS 파일 **이름을 바꿈** | 못 찾고 '서버에 없음'(빨강)으로 잘못 뜸 | 대장이 옛 이름을 기억해 새 이름으로 잇는다 |
| 그 파일을 **다른 폴더로 옮김**(같은 프로젝트 안) | 판정 보류 | 새 자리로 잇는다 |
| 같은 자리에서 **고쳐 저장** | 캔버스는 새 그림을 보여 준다 | 그대로(같은 번호의 새 판). 생성 기록은 그때 쓴 판을 지킨다 |
| 레퍼런스 찾기 | 매번 폴더를 훑는다 | 대장 후보를 먼저 보고, 확인되면 훑지 않는다 |
| "이 그림을 쓴 결과물" | 알 수 없음 | `GET /api/asset-registry/usage/{번호}` — 판 확인(1)과 가능 연결(0)을 나눠 준다 |

바뀌지 않는 것: 지문 없는 옛 `imports` 참조(원본 PC 에서 레퍼런스 찾기로만 이어진다), PC 가 NAS 를 못 보는 문제(드라이브·권한),
각 PC 의 개인 등록 폴더(서버가 볼 수 없다).

## 2. 구조

```text
[공유 서버]  services/asset_registry.py(관리자) ──자식 프로세스──▶ services/asset_registry_scan.py(NAS 읽기만)
                 │  완주한 결과만 한 번에 반영(BEGIN IMMEDIATE)            │ 결과 JSONL(작업 폴더)
                 ▼                                                          ▼
            content_hub.db: asset_registry · asset_registry_event · asset_registry_scan · reference(+판·번호 칸)
                 ▲
   routers/asset_registry.py  POST /lookup(가시 프로젝트만) · GET /usage/{id} · POST /scan · GET /status(관리자)
                 ▲  (로컬 허브는 데이터 프록시로 서버에 묻는다 — /api/asset-registry 는 로컬 전용 경로가 아니다)
[각 PC 로컬 허브]  routers/assets.py locate — '대장 먼저' → 이 PC 마운트로 풀어 열고 판 확인 → 아니면 직접 훑기
[캔버스]  lib/sceneAssetRelink.ts — SceneRef.registry_asset_id, open_ids, 같은 번호의 답만 받기
[에이전트]  agent_push.py — 실제 제출 파일의 sha256·bytes 를 begin-submission 에 ref_digests 로
[관리자 PC]  서버가 NAS 를 못 읽을 때 — services/asset_registry_helper.py 가 같은 훑기 자식을 이 PC 로 돌려 서버에 올린다(§10)
```

- 표: `asset_registry`(파일마다 한 줄 — 번호·프로젝트·경로·지문·크기·수정시각·상태), `asset_registry_event`(변화만 —
  new·edited·moved·missing·back, moved 는 old_path), `asset_registry_scan`(프로젝트마다 마지막 훑기 한 줄). 공유 서버의
  `content_hub.db` 코어 표라 서버 백업·이사 도구가 그대로 챙긴다(두 도구 모두 모든 표의 행 수를 복원 전후로 대조한다).
  필수 표 목록에는 넣지 않는다 — 대장 표가 없는 옛 백업도 복원할 수 있어야 한다.
- 번호는 **다시 만들 수 없는 데이터**다(생성 기록이 가리킨다). 대장을 지우고 다시 훑으면 번호가 새로 난다.
- 이름 주의: `registry_asset_id` 는 생성 결과물 `asset.id` 와 다르다.

## 3. 정체 규칙(판정)

| 사건 | 규칙 |
|---|---|
| 새 파일 | 안정적으로 읽혀 지문이 나오면 새 번호 |
| 같은 경로 내용 변경 | 같은 번호의 새 판(edited) |
| 이름 변경·이동 | **같은 완주 훑기 · 같은 PM 루트 · 미판정 0** 에서 같은 지문으로 사라진 것 1개와 생긴 것 1개가 각각 유일할 때만 같은 번호(moved). 애매하면 새 번호 — 틀린 연결보다 끊김이 낫다 |
| 없어짐 | 미판정 없는 완주 훑기에서 **연속 2번** 없을 때 missing. 번호·이력은 남긴다. 다시 나타나면 back |
| 복사본(같은 지문 여러 경로) | 서로 다른 번호 |
| 프로젝트 간 이동 · 이동과 수정 동시 | 새 번호 |
| 대소문자만 바뀐 이름 | 같은 번호(경로 비교는 path_cf, 유일 키 아님) |

`size + 수정시각` 이 같으면 이번엔 지문을 다시 읽지 않는다 — 성능 최적화일 뿐 판정 근거가 아니다.

## 4. NAS 읽기 안정성(합의안 12절)

- **격리**: NAS 목록·열기·지문은 자식 프로세스만 한다. 자식은 DB 를 열지 않는다(풀 epoch·유지보수 관문은 부모 메모리에만 있다).
  부모만 결과를 반영한다. 서버가 살아 있는지(health·ready)는 NAS 와 무관하다 — NAS 가 멈춰도 워치독 재시작 루프가 없다.
- **반영**: 루트 목록 실패·시간 초과·자식 비정상 종료·결과 상한 초과면 그 루트 결과 전체를 버린다. 잠김·읽기 실패·0바이트·
  읽는 중 바뀜은 그 파일만 미판정(기존 행 유지, 새 파일은 아직 등록 안 함). 미판정·대기가 있는 루트는 이동·missing 을 보류한다.
- **부하**: 지문은 1 MiB 단위 평균 속도 상한(수동 8 · 자동 5 MiB/s), 목록은 폴더 읽기(scandir) 초당 20번 이하(항목 수 아님).
  목록을 먼저 끝내고 지문은 예산 안에서 — 못 한 것은 다음 주기가 먼저 한다. 예산을 혼자 넘는 큰 파일은 같은 속도로 따로 읽는다
  (최대 45분, 넘으면 관리자 창에 '큰 파일 N 수동 대기').
- **수명**: 자식은 늘 하나. 시간 상한 + 30초가 지나거나 서버가 꺼질 때 `taskkill /T /F`. 서버가 강제로 꺼져도 자식이 2초마다
  부모를 확인해 스스로 멈춘다(고아 방지). 반영 안 한 결과는 버린다. 서버가 꺼지느라 끊은 훑기는 NAS 상태가 아니므로 마지막 훑기
  기록을 덮지 않는다(덮으면 다음 완주 전까지 찾기가 그 프로젝트의 대장을 안 쓴다). 강제 종료가 남긴 작업 파일은 다음 기동 때 지운다.
- **관측**: 로그는 프로젝트별 요약(`asset_registry_scan`·`asset_registry_run`), 경로 목록은 남기지 않는다.

## 5. 레퍼런스 찾기·캔버스·생성 기록

- **레퍼런스 찾기**(`routers/assets.py` locate): 참조마다 대장에 번호 → 지문 → 경로 끝(옮기기 전 경로 포함) 순으로 후보를 묻고,
  후보를 이 PC 의 PM 마운트로 풀어 **파일을 열고** 크기와 **지문**이 대장이 훑은 그 판과 같을 때만 잇는다(크기·수정시각만 보는
  지름길은 쓰지 않는다 — 같은 크기로 바꾸고 시각을 보존하면 다른 그림이 붙는다, Codex P1). 그 프로젝트의 마지막 훑기가 완주가
  아니거나 대장이 없으면(옛 서버·꺼짐·실패) 아무것도 하지 않고 지금의 직접 훑기가 맡는다.
  예외 — 번호·지문 없는 참조의 후보 중 **지금 경로**가 참조와 같은 것이 있으면 대장은 잇지 않는다. 잇기는 직접 훑기(개인 등록
  폴더까지 세어 물리 파일로 유일할 때만)가 하고, 그 답이 대장 후보와 같은 물리 파일이면 **번호만** 붙인다(판은 적지 않는다).
  대장은 PM 만 훑어 개인 폴더의 같은 경로 다른 파일을 못 세고(Codex), 이런 후보까지 지문을 읽으면 찾기가 6배 느려진다(§9).
  그래서 대장이 직접 잇는 것은 이름 변경·이동(옮기기 전 경로)·번호·지문으로 찾은 것뿐이다.
  '서버에 없음'·'이 PC 에만' 판정은 대장이 내지 않는다(훑기 사이 틈). 열리는 참조에는 번호만 알려 준다(`open_ids`, 같은 물리 파일일 때만).
- **캔버스 표시**(Jay 2026-09-30 시안 결정 — 연결 안 된 레퍼런스는 모두 빨간 테두리 + 이유 한 줄):

  | 판정 | 카드 |
  |---|---|
  | 열림·이어짐 | 그림, 평소 테두리 |
  | 서버에 없음(missing) | 빨간 테두리 + 붉은 빗금 + "서버에 없음" |
  | 판정 보류(locate `held` 의 이유) | 빨간 테두리 + 붉은 빗금 + 이유: 후보 여럿("연결 안 됨 · 후보 N곳 / 프로젝트들에 같은 파일 / 워크스페이스를 고르면 이어짐") · 사본+서버에 같은 이름(A안 — 글로만, 자동 잇기 없음) · 이름만 같음 · 내용이 다름(같은 자리) · 그 밖 "연결 안 됨" |
  | 이 PC 에만(local) | 그림 + 오른쪽 위 마크, 테두리 없음(09-29 모양 유지) |
  | 판정 못 끝냄(incomplete) | 회색 "확인 못 함"(빨강 아님 — 없는지 모른다). 저장하지 않고 이번 실행에만, 다시 물었는데 못 끝내면 옛 판정을 지운다 |
  | 판정 전 + 그림이 안 뜸 | 회색 "확인 중…" |

  보류 판정은 이유와 물을 때 실은 공간을 함께 기억한다(선택 워크스페이스가 바뀌면 자동 복구가 다시 묻는다). 탭에 공간이 없으면
  찾기는 지금 선택된 팀 워크스페이스의 프로젝트부터 본다(판정 열쇠는 탭 기준 그대로).
- **캔버스**: 참조에 `registry_asset_id` 를 적는다(서버 답 `open_ids`·`fixed` 로만). 번호도 지문처럼 한 토큰의 참조가 **모두 같을 때만**
  서버에 싣는다. 번호가 있는 참조는 **같은 번호의 답만** 받고, 넣을 때 판(`content_sha`)과 지금 판이 달라도 따라간다(넣을 때 판은 보존).
  판정 기억 열쇠는 번호가 없으면 예전 모양 그대로다(저장된 판정이 무효가 되지 않게). 에셋 창에서 끌어온 참조도 한 번 물어 번호를 받는다.
- **생성 기록**: 에이전트가 CLI 에 넘기기 직전의 실제 파일에서 낸 지문(`ref_digests`)을 허브가 제출 전이 트랜잭션 안에서 같은
  `file_path` 레퍼런스에만 고정하고 곧바로 대장 번호를 붙인다(`version_verified=1`). 요청 데이터가 보낸 판·번호는 받지 않는다 —
  먼저 채우면 COALESCE 가 실제 지문을 막는다. 서버 동기화·공유 번들은 지문만 나르고 번호는 서버가 지문으로 다시 붙인다.
- **옛 생성 기록**: 첫 완주·미판정 0 훑기 뒤, `asset:<이름>|<경로>` 의 이름이 그 PM 프로젝트 이름과 정확히 같고 그 경로 그대로
  파일이 하나일 때만 '가능 연결'(`version_verified=0`, 판 미확인). 옛 경로 이력·이름·다른 이름의 프로젝트로는 채우지 않는다.

## 6. 운영

1. 공유 서버 환경변수(서버 기동 스크립트에 넣는다):
   - `CONTENT_HUB_ASSET_REGISTRY=1` — 켠다(기본 꺼짐).
   - `CONTENT_HUB_ASSET_REGISTRY_DRIVES=Z:=\\192.168.1.203\millionvolt;X:=\\192.168.1.51\millionvolt` — 서버가 볼 드라이브 → 공유 주소.
     서비스·예약 작업 계정에는 사람이 연결한 드라이브(Z:)가 안 보일 수 있다. 대응표에 없으면 경로 그대로 읽는다.
   - `CONTENT_HUB_ASSET_REGISTRY_MIBPS=8,5` — 지문 읽기 속도 상한(수동, 자동 MiB/s). NAS·작업자 체감 부하를 보며 조절.
     1 미만은 받지 않고 기본값으로 돈다(1 MiB 조각마다 쉬는 동안 부모 감시가 멈추지 않게).
   - `CONTENT_HUB_ASSET_REGISTRY_INTERVAL_MIN=0` — 자동 훑기 간격(분). 첫 수동 훑기로 부하를 잰 뒤에 켠다(예: 10).
2. 서버 PC 의 서버 실행 계정으로 두 NAS 를 **읽을 수 있는지** 먼저 본다(없으면 그 프로젝트 훑기가 '실패 — 루트 폴더를 열 수 없음').
   서버 자동 시작은 SYSTEM 계정이라(SERVER.md) NAS 로그인 정보가 없어 못 읽을 수 있다 — 그때는 NAS 에 읽기 전용 계정을 주거나
   **§10 도우미 PC 훑기**로 간다(`CONTENT_HUB_ASSET_REGISTRY_HELPER=1`, DRIVES 대응표는 그대로 필요).
3. **첫 전체 훑기**: 관리자 창 → 에셋 대장 → [지금 훑기] → [시작]. 사람이 적은 시간에. 표의 상태가 '완료'가 되면 끝이다.
   '일부 대기'는 잠긴 파일·예산 밖 파일이 남은 것 — 다음 훑기가 이어서 한다.
4. 서버 이사 때는 서버를 멈추면 훑기도 멈춘다(반영 안 한 결과는 버린다). 대장 표는 `content_hub.db` 와 함께 옮겨진다.
5. 끄려면 `CONTENT_HUB_ASSET_REGISTRY=0` 로 다시 띄운다. 대장이 없으면 앱은 예전 방식(직접 훑기)으로 돈다. 옛 서버 + 새 앱도 같다.

## 7. 한계

- 대장을 만들기 **전에** 이미 이름이 바뀌거나 옮겨진 파일은 옛 이름을 몰라 못 잇는다(대장은 만든 뒤의 변화부터 따라간다).
- 미판정 파일(잠김 등)이 있는 루트에서 생긴 이동은 새 번호가 된다(끊김). 참조가 지문을 들고 있으면 내용으로 다시 이어진다.
- 이동과 수정을 한꺼번에 하면 새 번호다.
- 서버가 강제로 꺼진 직후 그 PID 가 곧바로 재사용되면 고아 자식이 자기 시간 상한까지 돈다(Job Object 는 필요해지면).
- "이 그림이 들어간 최종 파일 목록"은 최종 저장 기록이 각 PC 디스크에 있어 1차 범위 밖이다(레퍼런스 ↔ 생성 기록까지).

## 8. 결정(2026-09-30, 권장안으로 진행)

1. 같은 자리 고쳐 저장 = 같은 번호의 새 판
2. 캔버스는 최신 판을 따라가고 생성 기록은 그때 판을 고정
3. 프로젝트 간 이동 = 새 번호
4. 서버 PC 에 NAS 읽기 권한, 첫 훑기는 서버 이사 뒤
5. 1차 추적 범위는 레퍼런스 ↔ 생성 기록
6. 옛 생성 기록은 '판 미확인' 가능 연결
7. render·개인 등록 폴더 제외
8. 첫 훑기 수동, 자동 주기는 부하 측정 뒤

## 10. 도우미 PC 훑기(서버가 NAS 를 못 읽을 때, 2026-09-30)

Jay: "대신 훑게 하는 걸 만들자 · NAS 를 읽을 수 있을 때 작동 코드는 그대로 유지". Claude 설계 → Codex 적대적 검토(수정 요구
P0 6·P1 4 전부 반영) → 합의 → 구현(`1520d67a`) → Codex 코드 리뷰 2회 반영(`bb37d684`·`f18c1472`).

**흐름**: 관리자 창 → 에셋 대장 → [이 PC 에서 훑기] → 이 PC 의 로컬 허브(`/api/registry-helper/scan`, 로컬 전용)가
서버에 프로젝트 목록을 묻고, 프로젝트마다 **서버 자리(lease)** 를 받아 지금의 훑기 자식을 이 PC 로 돌린 뒤 **완주 결과**를
`/api/asset-registry/helper/result` 로 올린다. 판정·번호 발급·backfill 은 서버의 기존 `_apply` 그대로 — 번호는 서버만 만든다.

| 규칙 | 이유 |
|---|---|
| 서버 자체 훑기 코드는 그대로. 둘은 자리 하나로 서로 막는다(`request_scan` 이 자리를 보고, 자리는 서버 훑기 중엔 안 준다) | 자동 주기는 `/scan` 을 거치지 않는다(Codex P0) |
| 자리는 프로젝트 하나의 일반 훑기 → 큰 파일 → 다시 훑기 **전체**를 감싼다. 만료 10분, 도우미가 1분마다 연장, 반영 중엔 만료 없음 | 큰 파일 재훑기 중 서버 훑기가 끼어들지 않게, 도우미가 죽어도 오래 막지 않게 |
| 서버가 루트의 공유 주소(UNC)를 알아야 한다(루트가 UNC 거나 DRIVES 대응표). 도우미는 자기 드라이브의 공유가 그것과 같을 때만, 자식에게 그 **UNC** 를 루트로 준다 | 다른 NAS·로컬 디스크에 걸린 Z: 를 대장에 넣지 않게(Codex P0) |
| 결과는 엄격히 받는다 — 상대 경로·숨김·render 폴더·미디어 확장자·중복·지문 모양(ok⇔64자 hex·크기>0)·10만 개·본문 32 MiB(파싱 전 차단) | 서버 훑기가 절대 만들지 않는 행이 들어오지 않게 |
| 같은 순번·같은 내용 재전송 = 저장한 답, 다른 내용·낡은 순번 = 409 | 응답 유실 뒤 재전송이 두 번 반영되지 않게 |
| **미완주는 대장도 마지막 훑기 기록도 바꾸지 않는다**(서버 훑기의 failed 기록과 다름) | 도우미 PC 사정(그 PC 의 NAS 끊김 등)이 완주 기록을 덮지 않게 |
| 시작할 때의 서버 주소·토큰으로만 부른다. 로그인이 바뀌거나 401·403·옛 서버(404·405)·도우미 꺼짐(503)이면 **전체** 멈춤, 409·413·422 는 그 프로젝트만 실패. 1분 연장이 로그인 바뀜·자리 잃음을 알면 도는 자식을 **곧바로** 끝낸다. 자리 반납만은 시작 때 토큰으로 보낸다 | 도중에 다른 계정 권한으로 이어 가지 않게, 멈춘 도우미가 서버 훑기를 10분 막지 않게(Codex P1·재검토) |
| 자동 주기 없음(수동만). 앱을 켜 둔 동안만 돈다 | 결정 8 |

**운영**: 공유 서버에 `CONTENT_HUB_ASSET_REGISTRY_HELPER=1` + `CONTENT_HUB_ASSET_REGISTRY_DRIVES=…`(서버 자체 훑기는
`CONTENT_HUB_ASSET_REGISTRY=0` 이어도 된다). 관리자 계정(영구 system)으로 로그인한 PC 에서 [이 PC 에서 훑기] → [시작].
그 PC 는 Z:·X: 가 같은 NAS 에 연결돼 있어야 한다. 끝날 때까지(첫 훑기 약 30분) 앱을 켜 둔다. 서버 표에는 note '도우미 PC' 로 보인다.
