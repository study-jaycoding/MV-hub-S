# MV Hub (Content Hub) — 투자자용 소개 문서

> AI 생성 콘텐츠 시대의 팀 제작 스튜디오를 위한 **생성물 관리·협업·프로덕션 관리 플랫폼**
>
> 2026년 7월 · 프로젝트 설계·기능·운영 문서 전체 + 캔버스/ComfyUI 통합(2026-07) 개발 이력 기반

---

## 1. 한 줄 요약

**MV Hub 는 Higgsfield 등 AI 생성 도구로 만든 이미지·영상을 팀이 한곳에 모아
탐색·검색·공유·재사용하고, 크레딧(비용)·제작시간·일정까지 관리하는 풀스택 협업 도구입니다.**

---

## 2. 문제 — AI 콘텐츠 제작 팀이 겪는 실제 고통

AI 영상·이미지 생성이 프로덕션 워크플로우에 들어오면서, 제작 팀에는 기존 DAM(디지털 자산 관리)
도구가 풀지 못하는 새로운 문제들이 생겼습니다.

1. **생성물이 개인 계정에 흩어진다.** 팀원 각자가 자기 계정·자기 PC에서 생성하므로,
   "팀이 이번 주에 뭘 만들었는지"를 한눈에 볼 방법이 없다.
2. **프롬프트와 레퍼런스(출처)가 유실된다.** 좋은 결과물이 나와도 "무슨 프롬프트로,
   어떤 레퍼런스로 만들었는지"가 남지 않으면 재현·변형·재사용이 불가능하다.
3. **계보(어떤 결과물이 어디서 파생됐는지)가 없다.** 수백 개의 시행착오 속에서
   원본→파생 관계를 추적할 수단이 없다.
4. **비용(크레딧)과 제작시간이 블랙박스다.** 생성형 AI는 건당 과금(크레딧)인데,
   "어느 프로젝트에, 누가, 얼마를 썼는지"를 관리자가 알 수 없다.
5. **보안 딜레마.** 팀 공유를 위해 API 토큰을 한곳에 모으면 계정 보안이 무너진다.

## 3. 해법 — MV Hub 의 핵심 설계

### 3-1. "서버는 생성하지 않는다" — 푸시(push) 모델

```
[팀원 A PC]  본인 Higgsfield CLI ─┐
[팀원 B PC]  본인 Higgsfield CLI ─┤── push(메타데이터) ──▶ [공유 서버 = 팀 DB] ──▶ 전원이 브라우저로 공유
[팀원 C PC]  본인 Higgsfield CLI ─┘
```

- **생성은 각자 본인 PC·본인 계정·본인 크레딧으로.** 서버는 결과 메타데이터만 모으는 공유 DB.
- **API 토큰은 각자 PC 밖으로 절대 나가지 않는다** — 서버는 자격증명을 저장하지 않는다.
  (보안 문제 5번의 구조적 해결)
- 허브 화면의 "생성" 버튼도 서버가 실행하지 않는다. 요청만 큐에 남기고, **그 사람 PC의
  에이전트가 가져가 본인 CLI로 실행**한다. 결과·비용·귀속 모두 실행한 사람의 것.
- 팀원은 **설치 없이 브라우저 접속만으로** 탐색·정리·공유 가능. 본인 결과물을 올릴 때만
  표준 라이브러리로만 만든 단일 스크립트 에이전트를 켠다(추가 설치 0).

### 3-2. 출처 보존(Provenance)과 계보(Lineage) — 재사용 가능한 자산화

- 모든 생성물에 **프롬프트·레퍼런스·모델·파라미터를 원본 그대로 보존** → 클릭 한 번으로
  같은 조건 재생성, @소스 피커로 레퍼런스 재사용.
- **타입드 계보 그래프**: 재생성·가져오기(`derived`), 레퍼런스 참조(`reference`)를 엣지로
  기록하고, **히스토리 보드**가 원본→파생을 무한 캔버스 트리로 시각화.
- 즉, 생성물이 "일회성 출력물"이 아니라 **재현·변형·추적 가능한 팀 자산**이 된다.
  (문제 2·3번의 해결 — 이 프로젝트의 최우선 설계 가치)

### 3-3. 프로덕션 관리(PM) 대시보드 — 비용·시간·일정의 가시화

- **실제 크레딧 차감액**을 계정 거래내역과 자동 매칭(모델+시각 매칭, 실측 검증:
  시각 오차 0.02~0.28초, 모델 일치율 100%, 오귀속 0건).
- 생성 요청→시작→완료 3지점 타임스탬프로 **제작 소요시간** 자동 측정.
- 프로젝트 → 에피소드 → 시퀀스 → 컷 계층으로 **진척도·예산 대비 실적·담당자별 현황**을
  관리하는 통합 대시보드(영상 프로덕션의 실제 작업 구조를 그대로 반영).
- 숫자 정직성 원칙: 측정 불가한 항목은 0으로 속이지 않고 "측정 N/전체 M" 커버리지를 항상 표기.
  (문제 4번의 해결)

### 3-4. 제작 워크플로우 통합 — 캔버스와 ComfyUI (2026-07 확장 완료)

- **씬 캔버스 = 기획 보드이자 실행 엔진**: 무한 캔버스에 생성물·레퍼런스·텍스트 카드를
  자유 배치하고, **카드를 연결하면 그 조합이 그대로 생성 입력**이 된다(텍스트→프롬프트,
  미디어→레퍼런스 자동 파생). 컬러 그룹·행 인식 자동 정렬·undo/redo·미니맵,
  결과물을 행으로 나열해 선별하는 리스트/렌더 행, 이미지·영상 동기 재생 비교까지 —
  기획→생성→선별이 한 화면에서 순환한다.
- **ComfyUI 노드 통합**: ComfyUI 워크플로우(JSON)를 캔버스 카드로 불러와 체크한
  파라미터만 노출하고, 실행 계획(DAG)에 따라 단독·배치 실행. **출력은 '내 작업'
  라이브러리에 자동 저장(물질화)**되어 Comfy 결과물도 계보·공유·비용 관리 체계에
  그대로 합류한다. 로컬 ComfyUI·클라우드 모두 지원 — **Higgsfield 단일 의존을 벗어난
  첫 멀티 백엔드 사례**.
- **에셋 파이프라인**: 내 PC 폴더 마운트 + 화면 캡쳐·외부 파일 임포트(sha256 중복 방지)로
  재료를 수집하고, 캔버스·생성 레퍼런스로 바로 연결 — 재료 관리까지 원스톱.
- Assets 분리창·PM 분리창 등 **떼었다 붙였다 가능한 모듈 구조**로, 기능 추가가
  코어를 훼손하지 않는다(사이드카 원칙).

### 3-5. 엔드투엔드 워크플로우 — 결과물이 다시 재료가 되는 순환

```
① 재료 준비    →  ② 기획·생성     →  ③ 정리·선별    →  ④ 공유·피드백      →  ⑤ 확정·관리
에셋 분리창        캔버스 배치·연결     태그·컬러·소스      발행(S)·코멘트         최종(골드) 지정
폴더 마운트        프롬프트 도크        검색·프로젝트       팀 작업 탭             렌더폴더 저장
캡쳐·임포트        Comfy 워크플로       재생성 → 계보       가져오기=계보 연결      PM 대시보드

        ↻ 결과물을 다시 소스(@소스)로 등록 → ①로 되돌아가는 재사용 순환
```

제작의 전 과정(재료→기획→생성→선별→공유→확정)이 한 도구 안에서 닫힌 루프로 돌고,
모든 단계의 관계가 계보로 기록됩니다 — 개별 생성 도구·DAM·PM 툴을 조합해서는
얻을 수 없는 **MV Hub 의 통합 가치**입니다.

## 4. 제품 현황 — 이미 동작하는 풀스택 제품

문서 기준으로 아래가 **구현·검증 완료** 상태입니다.

| 영역 | 상태 |
|---|---|
| 라이브러리(무한 스크롤·가상 스크롤·그리드/리스트·날짜 그룹) | ✅ |
| 분류·검색(태그·자동태그·컬러·소스·FTS5 전문 검색·다중 필터) | ✅ |
| 생성/재생성(로컬 실행 큐·에이전트·실시간 진행률 WebSocket) | ✅ |
| 팀 공유(발행·가져오기·번들 export/import·코멘트 스레드·알림) | ✅ |
| 계보 시각화(히스토리 보드)·씬 캔버스(그룹·리스트/렌더 행·미디어 비교) | ✅ |
| Assets 분리창(폴더 마운트·캡쳐/임포트·중복 방지·개인 메타+공유 코멘트) | ✅ |
| 프로젝트·멤버·등급(RBAC)·로그인/승인 보안 | ✅ |
| 크레딧 집계·PM 대시보드(팀 텔레메트리 포함) | ✅ (통합 대시보드 고도화 진행 중) |
| ComfyUI 노드 통합(파라미터 노출·DAG 실행·출력 자동 물질화) | ✅ (병합 전 안전 리뷰까지 완료) |
| 운영 인프라(자동 백업·휴지통·썸네일 파이프라인·미디어 캐시) | ✅ |

- **기술 스택**: FastAPI(Python) + React/TypeScript + SQLite(WAL) — 단일 오리진 서빙으로
  폴더째 복사만으로 배포 가능. PostgreSQL 이중 백엔드 기반 마련.
- **운영 성숙도**: 자동 백업(온라인 백업 API), 별도 DB 휴지통, 테스트 서버 분리,
  CLI 버전 pin + 계약 스모크 테스트(외부 CLI의 파괴적 변경에 방어) 등
  실사용 팀 서버 운영을 전제로 한 장치들이 이미 갖춰져 있음.
- **개발 방법론**: AI 페어(클로드 설계·통합 + 코덱스 검증)의 상호 리뷰 체계로
  실측 검증 기반의 문서화 문화 정착 — 신규 인력·외부 실사(due diligence)에 유리.

## 5. 차별점 요약

| | 기존 DAM / 클라우드 생성 플랫폼 | **MV Hub** |
|---|---|---|
| 생성 주체 | 중앙 서버·중앙 계정 | **각자 로컬 CLI·본인 계정** (토큰 무집중) |
| 프롬프트·레퍼런스 | 결과물만 보관 | **출처 전체 보존 → 재현·재사용** |
| 계보 추적 | 없음 또는 수동 | **자동 타입드 계보 + 시각화** |
| 비용 관리 | 계정별 청구서 수준 | **잡 단위 실제 크레딧 매칭 + 프로젝트 귀속** |
| 제작 관리 | 별도 PM 도구 병행 | **에피소드/시퀀스/컷 계층 진척 관리 내장** |
| 배포 | SaaS 종속 | **로컬 우선 — 사내망 한 대로 팀 전체 운영** |

핵심 포지셔닝: 생성 API 제공사(Higgsfield 등)와 경쟁하지 않고, **그 위에서 팀의
데이터·비용·워크플로우를 소유하게 하는 계층**. 로컬 우선 + 선택적 발행 원칙으로
민감한 작업물이 동의 없이 중앙에 모이지 않습니다.

## 6. 확장 로드맵

과설계를 경계하며, 규모 신호가 관측될 때 착수하는 조건부 로드맵이 문서화되어 있습니다.

- **단기**: 통합 관리 대시보드 완성(계층 트리·신원 3축 배지), 캔버스/ComfyUI 기능 본선 병합.
- **중기**: 미디어 byte-cache(원격 URL 만료 대비 영구 보존), durable outbox(오프라인 내성 동기화),
  ID 체계 단일화(uuid 앵커) 마이그레이션.
- **장기**: 중앙 fact/index(팀 전체 검색·통계 — 단, 로컬 우선 원칙을 침식하지 않는 범위),
  PostgreSQL 전환·리버스 프록시 배포(설정 문서 기보유).
- **구조적 확장성**: CLI 브리지가 추상화되어 있어 Higgsfield 외 다른 생성 백엔드로의
  확장이 구조적으로 열려 있음(ComfyUI 통합이 첫 사례).
