# 편집 탭 — 비디오 클린 피드의 지연 없애기(켜기·재생·클립 넘김) — 2026-10-26 (Jay 지시)

owner: Claude · reviewer: (Jay 가 검토를 지시할 때 묶음으로 — 피드 화면 쪽 작은 변경) · status: 완료(dev 87d72e64 코드 — Jay 5173 확인 남음 · 원격 안 올림) · touched_paths: 아래 계약 · updated: 2026-10-26

## Jay 가 5173 에서 다시 볼 것

1. 편집 탭에서 클린 피드를 켠다(모니터 고르기) — 전보다 빨리 맞는 화면이 나오는가(빌드판 실측 약 1.37 → 1.04초, 개발 화면 약 1.47 → 1.11초).
   **백엔드는 그대로라 test_dev 를 다시 켤 필요 없다**(화면 쪽만 바뀜 — 5173 핫 리로드로 들어간다. 이미 열린 클린 피드 창은 껐다 켜야 새 코드).
2. Space 재생·멈춤, J/K/L, 훑기 — 피드가 바로 따라오는가 · 재생 중에 피드가 혼자 멈칫하거나 되감기는 일이 없는가(팀원 생성이 끝날 때 등).
3. 클립(컷)이 넘어가는 순간 — 검은 화면·멈칫 없이 바로 다음 클립이 나오는가 · 넘어간 뒤 타임라인 판과 어긋나 보이지 않는가.
4. 그래도 켜기가 느리게 느껴지면 다음 후보는 허브 쪽(창이 생기자마자 세션 받기 · 메뉴를 열 때 크롬 미리 띄우기)이다 — 말해 주면 그쪽으로 간다.

Jay: "비디오 클린피드 이제 잘 나오긴 하는데 켜지는데 딜레이가 있고 재생하는데 딜레이가 있다. 그리고 클립넘어갈때도 딜레이가 있다.
이 클린피드는 딜레이가 없어야한다. 그리고 바로바로 반응해야한다."

## 잰 방법(격리 실측)

- 격리 허브(커밋 고정 사본 · 임시 데이터 · AUTH 끔 · 루프백 · 자기 LOCALAPPDATA)가 **실제 키오스크 크롬**을 실제 오른쪽 세로 모니터에 띄우고,
  피드 화면은 실제 빌드(`vite build`)를 허브가 준다. 앱(main) 쪽은 스크립트가 HubFeed 와 같은 글(장면·시계 표본·active·resync 응답)을 보낸다.
- 시험 영상 = 실제 생성 영상과 같은 형식(1920×1080 H.264 High · 24fps · 약 19Mbps · **키프레임 맨 앞 하나** · moov 파일 끝) 5초 셋.
  화면 위 띠에 프레임 번호·클립 번호 바코드 → **화면을 직접 읽어**(GDI) 그 순간 보인 프레임을 안다. 허브 쪽은 시간 기록 래퍼.
- 개발 화면(Jay 의 5173 과 같은 Vite 개발 서버)은 따로 띄운 Vite(다른 포트·자기 의존성 캐시 — Jay 의 5173·`node_modules/.vite` 는 안 건드림)로 쟀다.
- 스크립트는 스크래치(`cfd\measure.py`·`hubwrap.py`) — 저장소에 넣지 않았다. 앱 쪽을 실제 편집 탭으로 띄우지는 못했다(격리 사본에 미디어·편집 문서가 없다) —
  앱 쪽의 몫(앱 영상의 재생 시작·앱 주 스레드가 바쁜 시간)은 코드로만 봤다.
