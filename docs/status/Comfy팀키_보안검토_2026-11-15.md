# Comfy 팀 키 보안 검토 — D8 (2026-11-15)

> Jay 11-15: "서버에 키 등록하면 다른 사람들이 그대로 쓰는 건데, 이거 어떻게 보안에 도움이 되게끔 검토". 검토·제안만 — 코드 변경 없음. 대상 설계는 [Comfy 팀 키 서버 배포](Comfy팀키_서버배포_2026-11-04.md). Claude 분석 + Codex 독립 검토 `01a1df08`(읽기 전용, gpt-6-astra).

## 지금 구조가 막는 것과 못 막는 것

- 서버 저장: DPAPI machine scope 암호화 — NAS 로 복사된 DB 사본으로는 못 푼다. 서버 PC 안에서 그 파일에 접근할 수 있는 사람까지 막지는 못한다.
- 배포: 승인 계정이 Bearer 로 `GET /api/team/comfy-key` 를 부르면 키 원문을 **LAN HTTP 평문**으로 받는다. 허브는 메모리에만 둔다.
- 근본 한계: 각 PC 의 ComfyUI 가 키를 들고 comfy.org 로 직접 나가므로 **키는 결국 모든 팀원 PC 에 간다**. 서버 등록은 **배포·교체 편의**이지 팀원에게서 키를 숨기거나 퇴사자를 즉시 막는 장치가 아니다. 서버에서 키를 지우거나 바꿔도 이미 복사된 옛 키는 comfy.org 에서 폐기해야 무효가 된다.
- 받아 간 기록은 '누가 언제 받았나' 뿐이고, 그 뒤 키로 쓴 생성·비용은 알 수 없다.

| 안 | LAN 외부인 도청 | 승인 팀원 | 분실·감염 PC | 퇴사자 | 규모(1명, 거친 추정) |
|---|---|---|---|---|---|
| A 운영 통제 | 망 접근만 줄임, HTTP 도청은 남음 | 키 복사 가능 | 공용 키 유출 = 팀 전체 영향 | comfy.org 에서 키 폐기해야 차단 | 0.5~1일 |
| B HTTPS + 인증서 고정 | 키·Bearer 도청과 서버 사칭 방어 | 못 막음 | 못 막음 | A 와 같음 | 3~7일 |
| C 키 주입 중계 + B | TLS 로 보호 | 회사 키 추출 방어(허용 API 남용은 별도 제한) | 회사 키 없음, 계정 차단 전까지 토큰으로 사용 가능 | 서버 계정 차단 뒤 새 요청 거절 | 2~4주 |
| D 팀원별 comfy.org 키 + B | TLS 필요 | 자기 키는 추출 가능 | 그 키만 폐기 | 그 키만 comfy.org 에서 폐기, 다른 팀원 영향 없음 | 3~7일 |

- C 의 근거(1차 자료로 확인): ComfyUI 에 `--comfy-api-base`(기본 `https://api.comfy.org`)가 있고 유료 API 노드가 그 주소로 경로를 만든다(로컬 ComfyUI 0.38.0 `comfy/cli_args.py:265`·`comfy_api_nodes/util/client.py`). 그래서 로컬 ComfyUI → 로컬 허브 → 공유 서버(회원 확인 뒤 외부 인증 헤더를 지우고 회사 키를 붙임) → api.comfy.org 로 중계하면 키가 서버 밖으로 나가지 않는다. 조건: 고정 상류·허용 경로만, 회원별 작업 ID 귀속(남의 결과 조회·취소 차단), 회원별 요청량 제한, 과금 POST 임의 재시도 금지, 바이너리 스트리밍, 서버의 인터넷 연결·가용성(서버 장애 = 팀 전체 API 노드 장애), 각 PC ComfyUI 실행 인자 설정, 지원 ComfyUI 버전 계약 시험, 기존 원문 배포 API 폐쇄 + 이미 배포한 키 폐기. 서명된 절대 URL 업로드·다운로드는 PC 가 직접 하므로 PC 인터넷은 여전히 필요하다.
- D 의 근거: comfy.org 는 여러 API 키 생성·개별 삭제를 공식 지원한다([공식 문서](https://docs.comfy.org/development/api-development/getting-an-api-key)). 키별 사용량·지출 상한·자동 폐기 API·같은 잔액 공유 여부는 **미확인**.
- B 의 조건: 공개 인증서·공개키 고정만 릴리스에 넣고 개인키는 서버에만 · 인증서 오류 때 검증 끄기·HTTP 재시도·다른 호스트로 인증 헤더 전달 금지 · 키 조회만이 아니라 로그인·일반 API·WebSocket 등 같은 토큰이 지나는 경로 전부 · 인증서 만료·주소 변경·고정값 교체·옛 설치본 처리 · TLS 앞단을 두면 원격 요청이 '서버 PC 로컬' 로 오인되지 않게(관리자 API 의 로컬 판정 `services/request_guards.py`). Bearer 는 가진 사람이 쓰는 자격증명이라 전송 기밀성이 필요하다(RFC 6750 §5).
