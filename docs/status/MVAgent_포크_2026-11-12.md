# MV Agent 대화 포크 — 지금까지를 복사해 따로 이어 가기 (2026-11-12)

owner: Claude(설계·구현) · reviewer: Codex(설계 적대적 검토 → 구현 뒤 다른 세션 독립 리뷰) · status: 완료(dev — 독립 리뷰 3차 통과, Jay 화면 확인 전) · updated: 2026-11-12

## 1. 요청

- Jay 11-12 서랍 메뉴 "Claude 앱 세션 메뉴처럼" 때 포크만 "따로 설계"로 뺐다(`MVAgent_서랍메뉴_2026-11-12.md`) → 11-12 "모두 구현하자. 설계부터 확정하고 바로 구현".
- 포크 = 지금 대화를 통째로 복사한 새 대화. 새 대화는 **누른 그 시점까지의** 흐름(AI 가 기억하는 맥락)을 갖고 시작하되, 그 뒤로는 원래 대화와 따로 간다.

## 2. 설계(4판)

### 2-1. 포크 요청 — 허브
- `POST /api/agent-chat/conversations/{id}/fork` 본문 `{request_id: uuid}`(칸 인증 그대로) → 200 `{conversation: 요약}`. 차례 시작과 같은 신원 잠금(`_turn_lock`) 안에서.
  - 404 대화 없음 · 409 진행 중인 차례가 있음(이 신원 어디든) · 409 Codex 대화(이번엔 Claude 만) · 409 이어 갈 세션이 없음(`cli_session_id` 없음 — 아직 첫 말을 안 한 포크도 여기 · `resumable=0`) · 413 너무 긺(끝난 차례 500개 또는 사건 20,000개 넘음) · 503 칸 연결 발급 실패.
  - **중복 방지**: 같은 `request_id` 로 다시 오면 그때 만든 포크를 그대로 돌려준다(응답을 잃고 다시 눌러도 복사본이 또 생기지 않게 — 대화 표 새 칸 `fork_request` 에 고유 색인). 이 조회는 원래 대화 존재·바쁨 검사보다 **먼저** 하고, 찾은 행의 `fork_from` 이 요청한 원래 대화와 다르면 409(다른 대화에 쓴 요청 번호). 화면은 응답을 잃은 뒤 다시 누르면 같은 번호를 쓴다(성공할 때까지 원래 대화마다 하나). 복사한 차례의 중복 방지 키는 따로 `fork-<새 uuid>`.
- 새 대화 = 칸 연결을 새로 발급(`issue_panel_client`). 엔진·모델·깊이·`project_override`·`cli_home`·`cli_cwd` 는 원래 것, 제목 = "원래 제목 (포크)"(80자). `cli_session_id` 는 비우고 새 칸 **`fork_session`** = 원래 `cli_session_id`, **`fork_turn`** = 복사한 마지막 차례(원래 쪽 id), **`fork_from`** = 원래 대화 id. 고정·보관·읽지 않음은 0. 새 칸은 처음 열 때 없는 칸만 더하는 지금 방식.
- **복사는 한 거래**: 새 대화 행 + 끝난 차례(생성 순서) + 사건을 SQL `INSERT … SELECT` 로(옛 차례 id → 새 id 는 거래 안 임시 표) — 사건을 메모리에 펼치지 않는다. 진행 중 차례는 잠금 때문에 없다. 복사는 요청 때 고정한 신원 DB 경로에서 **버리지 않는 작업 스레드**(`to_thread_non_abandon` — 요청이 취소돼도 작업이 끝날 때까지 잠금을 쥔다)로 하고, 작업이 끝난 뒤 **커밋됐는지로** 정리한다: 커밋 전 실패(신원 바뀜 포함)면 발급한 칸 연결을 회수(`mcp_v2 store.revoke`), 커밋됐으면 응답을 잃었어도 회수하지 않는다(다음 같은 `request_id` 가 그 포크를 받는다). 발급 자체 실패는 `issue_panel_client` 가 이미 회수한다.
- **계획**: 계획 묶음(`agent_chat_plan_binding`)은 복사하지 않는다. 복사한 `plan` 사건에는 `plan.forked = true` 를 얹는다 → 화면 카드는 "포크 전 계획 — 보기만"([실행]·[고치기] 없음). 허브도 막는다: 사람 [실행]·견적 입구가 **`conversation_id` 를 꼭** 받아(없거나 null 이면 422) 묶음의 대화와 다르면 404(이 대화의 계획이 아님) — 지금은 plan_id 만으로 원래 대화의 연결을 찾아 포크 카드로 원래 계획이 실행될 수 있었다(Codex 1차 P1-1, 2차 P1: 생략을 허용하면 갱신 전 창이 우회한다). 허브와 화면은 같은 릴리스로 함께 바뀐다. 화면은 요청을 시작하는 순간의 대화 id(늘 최신을 읽는 참조)를 싣는다 — 닫힌 콜백의 옛 id 가 아니라.

### 2-2. 포크의 첫 차례 — 누른 시점 고정
- 포크에 `cli_session_id` 가 없으면 첫 차례 전에(라우터, 신원 잠금 안) **원래 대화가 누른 때와 같은지** 본다: 원래 대화가 있고 · `cli_session_id == fork_session` · 마지막 차례(성공·실패·취소·중단 모두 — 진행 중은 신원 전체 `has_active` 검사로 이미 막힘) = `fork_turn`(그 뒤 새 차례 없음).
- **원래 지우기와 겹침**: 그 원래 세션에서 `--fork-session` 으로 **가르는 첫 차례가 도는 동안** 원래 대화 지우기는 409 "포크한 대화가 이 대화에서 가르는 중이에요" — 원래 세션 파일을 CLI 가 읽는 사이 지우지 않게(Codex 2차 P2-3, 3차 P2 '첫 차례가 끝날 때까지 보수적으로', Claude 합의 2차 — 새 id 를 저장한 뒤 차례가 끝나기 전도 막힘). 갈라진 뒤 자기 세션을 이어 가는 차례는 막지 않는다(독립 리뷰 2차). 판정 = 허브가 쥔 실행 중 차례의 `fork_source`(이 원래의 세션 id), 지우기 라우터가 신원 차례 잠금 안에서 본다(새 차례 시작도 같은 잠금이라 확인과 지우기 사이에 가르기가 끼지 않는다). 포크 첫 차례 확인(라우터)과 요약의 `fork_state` 는 같은 판정 조각 하나를 쓴다. 다르면 409 "원래 대화가 포크한 뒤 이어져서 그 시점으로 가를 수 없어요 · 다시 포크하세요", 원래가 지워졌으면 409 "원래 대화가 지워져 이어 갈 수 없어요". → 누른 뒤의 맥락이 섞이지 않는다(Codex 1차 P1-2, 작은 대안).
- 명령 = `--resume <fork_session> --fork-session`(Claude Code 2.1.322 도움말 "When resuming, create a new session ID").
- **원래 세션 보호**: 포크 차례의 시작 사건 세션 id 가 `fork_session` 과 같으면(가르기 실패) 저장하지 않고 바로 끄고 "포크하지 못했어요 — 원래 대화는 그대로예요"(Codex 1차 P1-3). 새 id 를 받아 저장한 뒤부터는 지금처럼 그 id 로만 이어 간다.
- **재시도**: 새 id 를 받기 전 실패(시작 실패·답 없음·오류)는 포크 대화를 잠그지 않는다(`resumable` 그대로) — 다음 말이 같은 확인을 거쳐 다시 가른다. 지금의 '이어 가기 + 시작 사건 없음 → resumable=0' 은 포크 첫 차례에는 쓰지 않는다(원래 세션이 멀쩡할 수 있다). 원래 세션 파일이 없으면 CLI 오류가 그대로 보인다.
- **실측 필수(실사용 전)**: 실제 Claude Code 로 칸 명령과 같은 옵션(`--setting-sources local`·`--strict-mcp-config`·`--tools ""`)에 `--resume X --fork-session` → 새 id · 원래 세션 파일 해시 그대로 · 새 파일 생김. 임시 작업 폴더·Haiku·짧은 말(구독 사용량만, MV 생성 없음), 만든 세션 파일은 실측 뒤 지운다.

- **실측(11-12, 통과)**: ① 칸과 같은 옵션 + `--resume X --fork-session` → 새 id · 원래 세션 파일 해시 그대로 · 새 파일 생김(`forkmeasure/result.json`). ② 포크 세션 파일은 앞 대화를 **통째로 새 id 로 다시 적은 파일**(31줄 모두 새 sessionId, 옛 id 0줄) — 지우기 검사(`_belongs`: 앞 50줄에 새 sessionId+cwd)를 통과하고, **원래 세션 파일을 치운 뒤에도** `--resume <새 id>` 가 앞에서 기억하라고 한 단어를 답했다(`result2.json`). → 포크가 첫 말로 갈라진 뒤에는 원래를 지워도 포크 기억은 남는다(Claude 합의 1차 중대 지적 확인).
- **시작 전 포크의 상태를 미리 알린다**(Claude 합의 1차 보통 2): 아직 갈라지지 않은 포크의 요약·대화 응답에 `fork_state` = `ready`(원래가 그대로) · `source_changed`(원래가 이어짐) · `source_gone`(원래가 지워짐)을 허브가 싣는다(라우터의 첫 차례 확인과 같은 판정). 화면은 그 포크를 열면 입력칸 위에 한 줄 — ready: "첫 말을 보내면 이 시점에서 갈라져요" · 그 밖: "원래 대화가 이어졌거나 지워져 이 포크는 시작할 수 없어요 — 지우고 원래 대화에서 다시 포크하세요"(보내기 잠금). 원래 대화 쪽에서 미리 경고하는 것은 하지 않는다(남은 불편으로 적음).
- AI 안내: GUIDE 에 "계획 카드가 '포크 전 계획'이면 이 대화에서 실행할 수 없다 — 필요하면 새로 계획한다" 한 줄(포크의 AI 는 원래 계획 id 를 기억하므로).

### 2-3. 지우기·기록 읽기
- 지우기는 지금처럼 그 대화의 `cli_session_id` 세션 파일만 — 포크를 지워도 원래 세션 파일(`fork_session`)은 건드리지 않는다. 원래를 지우는 것은 포크의 첫 차례가 끝날 때까지만 막는다(Codex 3차 P2 — 보수적으로), 그 뒤엔 포크 파일이 혼자 서므로(실측 ②) 막지 않는다.
- MCP 대화 기록 읽기(`agent_chats`)는 포크도 한 대화로 보인다(복사된 차례 포함).

### 2-4. 화면
- 대화 요약과 **단일 대화 응답**에 **`can_fork`·`fork_block`**(까닭: codex·no_session·not_resumable·forked_unstarted)을 허브가 싣는다 — 화면이 차례 수·세션을 몰라도 되게(Codex 1차 P2-7, Claude 합의 작음 5). [포크]의 title = "지금까지를 복사한 새 대화 — 이후는 원래와 따로".
- 목록 합치기: 목록을 보낸 뒤 이 창에서 받은 요약 중 **지우지 않았고 응답에 없는 줄은 맨 앞에 붙인다**(지금은 응답에 있는 줄만 고쳐 맨 위에 넣은 포크가 늦은 목록 응답에 사라진다 — Claude 합의 작음 4).
- 포크 전 계획 카드(`plan.forked`): 견적을 청하지 않고 비용·경고 줄을 숨기며, 진행 표시는 회전 없이 "포크 전 상태 · 결과는 라이브러리에서"(Claude 합의 보통 3).
- 서랍 행 메뉴·머리글 제목 메뉴(공용 `ConversationMenu`)에 **[포크]**(단축키 F, 같은 검사) — 이름 바꾸기 다음. `can_fork` 아니거나 이 칸이 바쁨(보내는 중·차례 진행)이면 흐리게, 까닭은 title.
- 누르면 `request_id` 하나로 한 번만(누르는 중 다시 못 누름) → 받은 요약을 목록 맨 위에 넣고 '이 창에서 바꾼 줄'로 남겨 늦은 목록 응답이 지우지 않게 → 그 대화를 연다(바쁘면 열지 않고 안내). 계정이 바뀌었으면 응답을 버리고, 같은 계정이어도 그사이 다른 대화를 열었거나 새 대화를 시작했으면(화면 전환 번호 `ticket`) 목록에만 넣고 자동으로 열지 않는다. 실패는 머리글 안내 줄.
- 계획 카드: `plan.forked` 면 "포크 전 계획" 표시 · [실행]·[고치기] 없음. 사람 [실행]·견적은 지금 대화 id 를 싣는다.

## 3. 시험
- 저장: 끝난 차례·사건·붙인 자료 복사(사건 순번 그대로)·`plan.forked` · 계획 묶음 안 함 · 새 연결·`fork_session`·`fork_turn`·`fork_from` · 거래 실패면 행 0·연결 회수 · 같은 `request_id` = 같은 포크 · 413 상한.
- 라우터: 404·진행 중 409·Codex 409·세션 없음 409(첫 말 전 포크 포함) · 같은 request_id 재요청 = 같은 포크(바쁨·원래 지워짐보다 먼저) · 다른 원래 대화에 같은 request_id = 409 · 실행·견적 `conversation_id` 없으면 422·다르면 404 · 포크 첫 차례 도는 중 원래 지우기 409 · 복사 실패면 연결 회수, 커밋 뒤엔 회수 안 함.
- 실행: 첫 차례 명령 = `--resume <원래> --fork-session` · 원래가 이어졌으면/지워졌으면 409 · 시작 사건 id 가 원래와 같으면 저장 안 하고 끔 · 새 id 저장 뒤 둘째 차례 = `--resume <새 id>` · 첫 차례 실패 뒤 resumable 그대로·다음 말이 다시 가름 · 원래 대화의 다음 차례는 원래 id.
- 지우기: 포크를 지워도 원래 세션 파일은 남음.
- 화면: 메뉴 항목·`can_fork` 잠금·한 번만·목록 맨 위·늦은 목록 응답이 안 지움·열기 · 포크 전 계획 카드에 [실행] 없음 · [실행]이 대화 id 를 실음.
- 실측(위 2-2).
