# 실패 사유를 못 받은 카드 — 힉스필드 웹에서 확인하라는 안내·링크 — 2026-10-28 (Jay 요청)

owner: Claude(구현 — 세션 f12e0dff) · reviewer: 없음(Codex 크레딧 문제 — [점검 대기](Codex_사후점검_대기_2026-10-28.md)) · status: 완료(dev — Jay 화면 확인 남음) · touched_paths: 아래 계약 · updated: 2026-10-28

요청(Jay): 생성 정보 창이 "상세 사유를 받지 못했습니다" 만 보여 어떤 실패인지 바로 알 수 없다. 힉스필드에서 확인해 보라는 안내, 또는 누르면 힉스필드 웹으로 가서 그 생성물의 실패 사유를 볼 수 있는 링크.

## 조사(직접 확인, 무과금 조회)

- 실패 잡 `d78efedb`(Kling 3.0 Omni Edit) 을 CLI 1.2.3 `generate get --json`·사람용 출력·`generate wait` 와 힉스필드 MCP(`show_generation_by_ids`·`jobs_wait`·`job_display`)로 조회 → 모두 `failed` 만, 사유 칸 없음. CLI 실행 파일 속 `fail_reason` 은 영상 분석 등 다른 구조에만 있다.
- 힉스필드 웹은 `https://fnf-api-gw.higgsfield.ai/fnf/jobs/{id}` 를 웹 로그인 토큰으로 불러 잡의 `fail_reason` 을 보여 준다(공개 웹 코드: "A backend failure reason replaces the default guidance"). MV 가 이 비공개 주소를 쓰는 방식은 PC마다 웹 로그인·비공식·계정 권한 위임이라 하지 않는다.
- 웹 경로 목록(공개 코드)에 **생성 하나를 바로 여는 주소는 없다** — `/soul/job/{id}` 는 Soul 공개 이미지 전용, `/canvas/{imageId}/{jobSetId}` 는 캔버스 전용. `https://higgsfield.ai/asset` 은 내 생성물 전체 화면(`/ko/asset/all`, 제목 "에셋")으로 열린다(비로그인 실측).
- `cli_bridge._error_text` 는 이미 `fail_reason` 을 찾는다 → CLI 가 내주면 앱 수정 없이 사유가 보인다.

## 2차 — 종류별 히스토리로(Jay: "실제 실패카드들은 이미지, 비디오, 오디오의 히스토리에서 가면 각각의 생성물의 실패카드를 볼 수 있다")
