# 어셋 탭 원본 끌기 — 20장 넘게 끌면 422 — 2026-10-28 (Jay 발견)

owner: Claude(구현 — 세션 83842c80) · reviewer: 없음(Codex 크레딧 문제 — [점검 대기](Codex_사후점검_대기_2026-10-28.md)) · status: 완료(dev — Jay 실제 끌기 확인 남음) · touched_paths: 아래 계약 · updated: 2026-10-28

증상(Jay 화면): 어셋 탭(`/?embed=assets`)에서 카드 30장을 골라 Windows 폴더로 끌면 `Error: 422 … "loc":["body","paths"] … "List should have at most 20 items after validation, not 30"` 가 그대로 뜨고 아무것도 복사되지 않는다. 20장까지는 된다.

## 원인(코드 확인)

- 어셋 카드를 끌면(Windows·로컬 크롬) `exportDrag.ts` `startNativeAssetDrag` 가 고른 카드 전체의 경로를 `POST /api/assets/native-drag` 로 보낸다. 서버는 그 파일들로 **Windows 원본 파일 끌기(OLE, 복사 전용) 한 번**을 연다. 앱 안에 "카드를 다른 폴더로 옮기는" API 는 없다 — Jay 의 "다른 폴더로 옮기기"는 이 끌기로 탐색기 폴더에 놓는 것이다.
- 서버 요청 모델 `NativeDragIn.paths` 에 `max_length=20`(`backend/app/routers/assets.py`). 프런트는 개수를 보지 않고 다 보내 Pydantic 오류 원문이 그대로 떴다.
- 20 을 둔 근거 문서는 이 폴더에 없다(`서비스구조_근본진단_2026-10-18.md` 는 "최대20개 … 제한은 유지한다"만 적었고, 시험 `test_over_limit_is_rejected_not_truncated` 는 "넘으면 자르지 말고 거부"만 고정한다). 코드로 본 실제 제약은 **시작 시한**이다: 브라우저가 끌기를 시작한 뒤 1.5초(`windows_drag.START_WINDOW_MS`) 안에 모든 파일 확인 + 도우미 프로세스 시작 + 파일마다 Shell ID 만들기(`SHParseDisplayName`)를 마쳐야 끌기가 열린다. 늦으면 "원본 준비에 시간이 걸려 …" 로 끝난다.

## 왜 "20장씩 나눠 보내기"가 아닌가

이 요청은 이동 API 가 아니라 **마우스를 누르고 있는 끌기 한 번**이다. 한 번의 끌기에 파일 목록이 하나다. 20장씩 두 번 보내면 두 번째는 서버 잠금(409 "이미 파일을 끌고 있습니다")에 걸리거나, 첫 끌기를 놓은 뒤라 마우스가 눌려 있지 않아 시작되지 않는다. 그래서 `lib/batching.ts` 의 `chunked` 는 쓸 수 없다.

## 상한을 얼마로 — 실측(이 PC 로컬 디스크, 끌기는 열지 않음)

`windows_drag.data_object`(끌기 직전 준비)만 임시 파일로 잼. 스크립트는 세션 스크래치패드(`measure_drag_prep.py`).

| 개수 | 파일 확인 | Shell ID 목록 만들기 |
|---|---|---|
| 20 | 4 ms | 100 ms |
| 30 | 6 ms | 104 ms |
| 50 | 10 ms | 183 ms |
| 100 | 20 ms | 344 ms |
| 200 | 38 ms | 690 ms |
| 500 | 96 ms | 1683 ms |

도우미 파이썬 시작 약 100 ms. 100장이면 로컬에서 약 0.45~0.5초로 1.5초 한도에 여유가 있다. **NAS 폴더는 재지 않았다**(지시: 실제 NAS 금지) — 파일마다 네트워크를 타므로 더 느리다. 느려서 시한을 넘기면 서버가 끌기를 열지 않고 안내만 띄운다(파일 손상·부분 복사 없음).
