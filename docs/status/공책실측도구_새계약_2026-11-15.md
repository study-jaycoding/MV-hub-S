# 허브 공책 브라우저 실측 도구를 복원 세대 계약에 맞춤 (2026-11-15)

> 배포 후보 점검([Gate 6-A](배포후보_Gate6A_2026-11-15.md))의 남은 일. 제품 코드는 바꾸지 않는다 — `tools/browser_measure/canvas_notebook.py` 와 그 단위 시험만.

## 왜

`tools/browser_measure/canvas_notebook.py` 의 8경우(bootstrap·cross_browser·normal_handoff·crash_takeover·delete_crash·lease_races·offline·rollback)가 후보에서 모두 30초 안에 "browser and hub did not converge" 로 실패했다(`212797d7`·`61eba19a` 둘 다). 도구는 옛 계약(브라우저 로컬 씬이 그대로 공책을 시작)을 전제한다. 1C-1(`dde729bb`) 뒤 첫 합류는 **허브 미러를 기준**으로 삼는다 — 로컬이 미러와 다르면 로컬을 `nr` 보관함에 넣고 캔버스를 미러로 바꾼다(`frontend/src/lib/sceneNotebook.ts` `adoptRestoredNotebook`). 빈 허브에서 씨앗 씬을 든 브라우저가 열리면 캔버스가 비어 수렴할 수 없었다. 이 경로(빈 미러 첫 전환)는 이번 판에서 공책을 기본 끔으로 둔 이유와 같다([기본 끔 기록](배포후보_공책기본끔_2026-11-15.md)).

## 무엇을 바꿨나

- 첫 브라우저 전에 **공책 끔으로 허브를 띄워 미러를 채우고**(`PUT /api/scenes/backup`, 브라우저 직렬화와 같은 간결 JSON), 그다음 `=1` 로 다시 띄운다(`seed_mirror`). 공개판 미러 경로에서 올라온 팀원의 허브와 같은 출발점이다. 빈 미러 첫 전환은 재지 않는다(보고서 `limitations` 에 적음).
- 수렴 판정(`synced`)에 **시작된 공책**과 브라우저의 **이 복원 세대 합류 기록**(`["nj", 계정]`)을 더했다. 씬이 같아도 공책이 시작되지 않았거나 다른 세대·다른 공책에 합류했으면 수렴이 아니다. 시작 전 미러에 합류한 브라우저는 제품이 `notebookId` 를 `""` 로 둔다(`sceneNotebook.ts` 727행) — 이것은 받는다.
- bootstrap 의 보관함 확인을 옛 `["na", …]` 에서 복원 보관함 `["nr", 계정]`(목록, 항목마다 `scenes[버킷]`)으로.
- lease_races 의 늦은 쓰기·계정 ABA 직접 호출에 현재 복원 세대를 싣고, 늦은 쓰기는 상태 409 와 함께 오류 `writer_required` 까지 확인한다(세대 거절과 구분).
- `make_env`·`Hub.start` 에 `writer` 선택(기본 켬). 끔 준비 단계에서는 허브 기능 표식이 실제로 꺼졌는지 확인한다.
