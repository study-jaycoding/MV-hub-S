# 앱 창을 고르면 별도 창(Assets·관리)도 앞으로 — 2026-10-26 (Jay 지시)

owner: Claude · reviewer: (Jay 가 검토를 지시할 때 묶음으로) · status: 완료(dev 커밋 · Jay 화면 확인 남음) · touched_paths: 아래 계약 · updated: 2026-10-26

Jay: "지금은 별도창이 열려있을떄 다른 프로그램을 선택하면 그 창이 안보였다가 원래 프로그램을 선택해도 그 창은 따라서 위로 올라오지 않는다.
그래서 다시한번 별도창을 눌러서 띄워야하는데 우리 프로그램을 선택하면 별도창들도 위로 올라와서 보이게 할수있나?"
→ 같은 날 "편집도 별도창으로 나와야한다" 를 물었더니 **"편집은 일단 나두자"** — 이번 범위는 Assets·관리 창만.

'별도창' = 머리줄 Assets·관리 단추가 `window.open` 으로 여는 창(`lib/popupWindows.ts` — 단추 설명 "… — 별도 창").
클린 피드 창은 이미 '앱에 있을 때만 보임' 규칙이 있다(전용 창·팝업 방식 모두 — `EditCleanFeed`·`services/clean_feed_window`).

## 0단계 실측(격리 크롬 — 스크래치 프로필 + 내가 띄운 메모장, 2026-10-26)

| 방법 | 결과 |
|---|---|
| 앱 창 focus 때 `별도창.focus()`(opener · 누름 없음) | **아무 일 없음** — 별도 창은 메모장 밑 그대로, 초점은 앱 창 |
| 허브(다른 프로세스)가 `SetWindowPos(HWND_TOP, NOACTIVATE)` | 메모장 위로는 오지만 **앱 창 바로 밑**에 놓인다 — 앱 창이 크면 가려진 채 |
| 허브가 `HWND_TOPMOST` → 바로 `HWND_NOTOPMOST`(NOACTIVATE) | **앱 창 위로** 온다 · 맨 앞 창(초점)은 앱 창 그대로 · 앱 `document.hasFocus()` = true |

- 창 제목(Win32): 앱 창(--app)·그 팝업은 페이지 제목 그대로, 일반 크롬 창은 뒤에 ` - Chrome` 이 붙는다(Jay 의 5173 창 = "Millionvolt Hub - Chrome").
- 앱 창이 `window.open` 직후 별도 창에 단 `blur` 듣기는 첫 페이지 로드 뒤에도 남는다(같은 출처 — 초기 빈 문서의 창 객체를 다시 씀).
- 실측 중 Jay 의 기존 메모장 창 하나를 잘못 잡아 자리(0,0·1300×950)를 옮겼다 — 내용·저장 상태는 그대로(닫히지 않음). Jay 에게 알림.
