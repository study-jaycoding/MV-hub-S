**이 실측이 Claude 의 회귀를 잡았다.** Codex 2차 검토가 "`resolve()` 부작용은 실측 필요"라고 경고했던 자리다.
Claude 가 이 PC 의 `M:`·`X:`·`Z:` 로 재현: `Path.resolve()` 는 네트워크 드라이브 문자를 UNC 로 바꾸고, SQLite 는
`file://server/share/…` 의 server 를 authority 로 읽어 `invalid uri authority` 로 거부한다. 옛 손조립(`file:Z:/…`)은
열렸으므로 `82c2a8e0` 은 **DB 가 네트워크 드라이브에 있는 경우를 깨뜨렸다.** 게다가 기존 두 헬퍼
(`validate_hub_db` 용·`backup_verify` 용)는 처음부터 `resolve()` 였다 — NAS 의 DB 를 연 적이 없다(RL-23 복원 훈련에서
밟을 자리였다). `1ba19252` 에서 `absolute()` + UNC 는 `file:////server/share/…`(빈 authority)로 고쳤고, 루프백 공유의
실제 DB 를 특수문자 경로까지 읽기 전용으로 여는 것을 시험으로 고정했다(새 시험 4 · 관련 25파일 714 통과).

**미실측**: 실제 원격 NAS 위의 SQLite 파일 열기(주소 해석까지만 확인 — NAS 에 파일을 쓰지 않았다), 브라우저에서의
Esc·Alt-Tab 수동 재현, 유료 생성·Resolve·운영 설치본.
