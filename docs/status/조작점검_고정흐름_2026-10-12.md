# 조작 점검 — 고정 흐름 확인 시나리오(27회차, 2026-10-12)

조작 전수 검토([조작점검_2026-10-10.md](조작점검_2026-10-10.md))를 닫기 위한 **고정 범위**다 — 회차를 더 늘리지 않고, 이 31개를 고친 빌드로 격리 실측해 새 P1·P2 가 없으면 끝낸다. 초안은 Codex(2026-10-12, 상대 보고), 실행 결과는 아래 '결과' 절과 본 문서 4절에 적는다. 다음에 조작을 크게 바꾸면 이 목록을 회귀 확인으로 다시 돈다.

흐름: 선택 → 편집 → 저장 → 되돌리기 → 대상 전환 → 다시 열기. 본창·분리 창·편집 탭.

## 공통 실행 계약

- 에이전트마다 별도 임시 브라우저 프로필·별도 가짜 상태 저장소(mockStore). 시나리오 시작마다 초기 fixture 로 복원.
- 앱 최초 접근 **전에** 팝업·분리 창을 포함한 컨텍스트 전체에 Fetch 가로채기를 설치.
- 조회도 가짜 응답. 등록하지 않은 요청은 실제 서버로 보내지 않고 기록 후 차단. 무조건 `{ok:true}` 금지.
- 허용한 가짜 저장은 mockStore 를 갱신하고 후속 GET·새로고침도 그 저장값을 돌려준다(저장 왕복 검사).
- `POST /api/projects/folder-counts/batch` 같은 POST 조회가 있다 — 메서드가 아니라 경로별 허용 목록.
- 생성·재생성·Alt+Enter·Comfy 실행·다운로드·Resolve 보내기·업데이트·공지·DB 내보내기·Assets 등록·업로드·삭제·비밀번호·로그아웃은 가짜 응답이 있어도 **누르지 않는다**. Delete·Backspace 삭제 키도 쓰지 않는다.
- 캔버스·편집 문서의 저장은 브라우저 저장소 — 임시 프로필의 IndexedDB/localStorage 만.
- 판정: "즉시" = 의도적 대기 없이 다음 입력. 요청·입력·렌더 시각 기록. 경합 구간을 못 만들었으면 `미재현/미확인`. 저장 확인은 요청 발생뿐 아니라 mockStore/브라우저 저장값 → 다른 대상 → 복귀 → 새로고침까지. 캔버스·편집 탭은 Undo/Redo 검사(서버 태그·역할·코멘트에 앱 Ctrl+Z 는 요구하지 않음). 기본 1280×800, 메뉴·초점 시나리오는 900×600 도. 선택자는 가짜 ID 로 범위를 좁힌다 — 없거나 둘 이상이면 준비 실패로 기록.
- 공통 자료: 워크스페이스 W1·W2, 프로젝트 P1·P2, 생성물 G1·G2·G3(구별되는 제목·내용), 미디어는 격리 정적 이미지, Assets 폴더 AP1·AP2 에 같은 상대 경로 `same.png`(태그·코멘트는 다르게), 관리는 가짜 관리자 권한(승격·로그인·로그아웃 조작 금지).
- 결과 한 줄 형식: `ID | PASS/FAIL/BLOCKED | 빌드·fixture 식별자 | 조작/요청 순서 | DOM·저장값 근거 | 실제 서버 전송 0 여부 | 미확인 범위`. FAIL 은 최초로 어긋난 DOM/저장 필드. BLOCKED 는 통과 수에 넣지 않는다. 금지 요청이 우발적으로 나가면 차단 기록과 함께 그 시나리오 중단.
