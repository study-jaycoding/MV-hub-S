# MV Agent 사건 기록 지연 조사

owner: Codex · reviewer: 설계 합의 전 · status: 검토 요청 · touched_paths: 제품 변경 없음 · updated: 2026-11-12

[진행 인계](Codex인계_진행중작업_2026-11-12.md)의 flood 실패 조사다. 기준은 dev `379c0a835f2305657d25b32ceaaf29e3c96cd4ce`. `backend_failure_triage`가 아래 실험을 직접 실행했고, 총괄은 출력과 해당 코드 경로를 대조했다. 원래 실패 당시의 원시 traceback이 없어 그때의 원인을 확정하지는 않는다.

## 현재 근거

`repo/agent_chat.py`의 `append_event`는 사건마다 연결을 열고 거래를 확정한 뒤 닫는다. 지연 없는 한 실행에서 flood 10.739초 중 기록 1,001회의 합계가 10.447초였다. text 기록마다 40ms를 더하자 원래 40초 시험 기한에 725건을 기록한 상태로 실패했다. 교착이 아니라 계속 기록 중이었다. 시험 기한을 늘리거나 제품 코드를 바꾸지는 않았다.

다음 대조는 `_run` 소유 스레드에서 거래 없는 연결 하나를 추가로 유지했다. SQLite WAL의 마지막 연결 종료 비용을 줄이는 가설이다. 기존 사건별 거래·COMMIT·알림은 그대로다. 두 실험 사이에 카메라 계측·다른 빌드/시험을 실행하지 않았다.

| 쌍 | 순서 | 기존 전체 시간 | 연결 유지 전체 시간 |
|---|---|---:|---:|
| 1 | 기존→유지 | 9.615925초 | 1.617123초 |
| 2 | 유지→기존 | 10.615622초 | 1.293932초 |
| 3 | 기존→유지 | 10.386698초 | 1.493716초 |

전체 시간은 시험 본문부터 fixture 정리와 유지 연결의 최종 close 완료까지다. 수집·fixture 준비 시간은 제외한다. 중앙값은 10.386698→1.493716초로 이 실험에서 85.62% 줄었다. 기록 1,001회 합계 중앙값은 9.677→0.584초, 일반 연결 종료 합계는 4.527→0.105초였다. 유지 연결 close는 flood 5.5~5.9ms, 긴 줄 차례 4.8~327.5ms이며 전체에 포함했다.

6회 모두 exit 0. flood는 `failed/too_many_events`, 저장 1,002행, 마지막 사건 `state`; 긴 줄은 `done`과 예상 문자열 검증을 유지했다. Job 닫힘·자식 종료·실행 수명 종료를 확인했다. 유지 연결은 조회를 완결하고 전후 `in_transaction=False`였다. `text_delta`는 이 시험에 0개이므로 짧은 조각의 실시간 표시/경쟁 순서 검증은 아니다.

원시 출력: 기존1 `efcaa1`, 유지1 `62a801`, 유지2 `59e5e0`, 기존2 `d69986`, 기존3 `08664b`, 유지3 `1208f3` (같은 자식 세션). 첫 명령 `1cf0d2`에 아래 코드가 있다. 관련 제품·시험 4파일은 전후 변경 없음이었다.

## 다음 설계에서 지킬 경계

- 성능 가설 검증만 끝났다. **실제 구현·Claude 사전 합의·독립 리뷰는 아직 없다.** 시험 기한·사건 상한을 완화하지 않는다.
- 연결은 고정된 `runtime.path`를 사용해 같은 실행 스레드에서 열고 닫는다. 다른 스레드와 연결 객체를 공유하거나 읽기 거래를 계속 열어 두지 않는다.
- 아래 대역은 연결 확보 실패를 원래 `_run`의 오류 처리로 연결하지 않는다. 실제 구현은 시작 실패·취소·시간초과·종료 오류·파일 교체를 별도로 다뤄야 한다.
- 짧은 글 조각(감시 스레드의 0.3초 flush), 상태/끝남 사건 순서, 계정 변경과 종료를 관련 시험으로 검증한다.
- 병렬 진단이 확인한 [SQLite WAL 잠금/종료](https://www.sqlite.org/walformat.html#locking_matrix), [자동 checkpoint](https://www.sqlite.org/wal.html#automatic_checkpoint), [NORMAL 동기화 특성](https://www.sqlite.org/pragma.html#pragma_synchronous)에 따르면 연결 유지는 마지막 close의 checkpoint를 늦춘다. 앱 충돌과 전원차단의 보존 범위는 다르다. 현재 `synchronous=NORMAL`에서 전원차단 때 유실 가능한 이미 COMMIT된 사건 범위가 커질 수 있으므로, 의미가 전혀 안 바뀌는 최적화라고 취급하지 않는다. 1-B 백업 편입/복원 시 WAL을 포함한 SQLite 백업·파일 교체 경계와도 맞춰야 한다.

## 재현 코드

저장소 루트에서 전용 venv로만 실행했다. 아래 Python 블록을 PowerShell `$probe` here-string에 넣고 `python.exe -B -c $probe baseline pair1-B`처럼 모드·회차를 전달한다. 기존/유지/유지/기존/기존/유지 순서이며 각 호출은 별도 프로세스다. 부모 환경은 `CONTENT_HUB_NO_PROXY=1`, `PYTHONDONTWRITEBYTECODE=1`. pytest conftest가 만든 임시 DB·가짜 CLI만 사용한다. 실사용 DB·서버로 바꾸지 않는다.

```python
import contextlib, json, statistics, sys, threading, time
from collections import defaultdict
import pytest
MODE, TRIAL = sys.argv[1:3]
class Probe:
    def __init__(self):
        self.patch=pytest.MonkeyPatch()
        self.phases=defaultdict(list)
        self.appends=defaultdict(list)
        self.runs=[]
        self.finished=[]
        self.guard=threading.Lock()
        self.wall_start=None
    def pytest_runtest_call(self,item):
        from app.repo import agent_chat as store
        from app.services import agent_chat as chat, agent_chat_process as process
        self.store=store
        self.wall_start=time.perf_counter()
        original_connect=store.connect
        @contextlib.contextmanager
        def connect(path):
            started=time.perf_counter()
            closing=None
            try:
                with original_connect(path) as conn:
                    self.phases['db_open'].append(time.perf_counter()-started)
                    try:
                        yield conn
                    finally:
                        closing=time.perf_counter()
            finally:
                if closing is not None:
                    self.phases['db_close'].append(time.perf_counter()-closing)
        self.patch.setattr(store,'connect',connect)
        original_append=store.append_event
        def append(path,turn_id,kind,payload):
            started=time.perf_counter()
            try:
                return original_append(path,turn_id,kind,payload)
            finally:
                self.appends[turn_id].append(time.perf_counter()-started)
        self.patch.setattr(store,'append_event',append)
        original_run=chat.AgentChat._run
        def run(service,runtime):
            finished=threading.Event()
            with self.guard:
                self.finished.append(finished)
            record={'turn':len(self.finished),'mode':MODE}
            started=time.perf_counter()
            closing=None
            try:
                with contextlib.ExitStack() as stack:
                    if MODE=='anchor':
                        opened=time.perf_counter()
                        anchor=stack.enter_context(original_connect(runtime.path))
                        statements=[]
                        anchor.set_trace_callback(statements.append)
                        with contextlib.closing(anchor.execute('SELECT rootpage FROM sqlite_schema LIMIT 1')) as cursor:
                            cursor.fetchall()
                        record['anchor_open_seconds']=round(time.perf_counter()-opened,6)
                        record['anchor_in_transaction_before']=anchor.in_transaction
                        assert not anchor.in_transaction
                    original_run(service,runtime)
                    if MODE=='anchor':
                        record['anchor_in_transaction_after']=anchor.in_transaction
                        record['anchor_statements']=statements
                        assert not anchor.in_transaction
                        closing=time.perf_counter()
            except BaseException as exc:
                record['error_type']=type(exc).__name__
                raise
            finally:
                record['anchor_close_seconds']=round(time.perf_counter()-closing,6) if closing is not None else None
                record['run_with_close_seconds']=round(time.perf_counter()-started,6)
                try:
                    turn=store.get_turn(runtime.path,runtime.turn_id)
                    events=store.events_after(runtime.path,runtime.turn_id,0,limit=10000)
                    record.update(status=turn['status'],reason=turn['reason'],runtime_events=runtime.events,stored_events=len(events),last_kind=events[-1]['kind'] if events else None,text_count=sum(e['kind']=='text' for e in events),delta_count=sum(e['kind']=='text_delta' for e in events),overflow=runtime.overflow,done=runtime.done.is_set(),job_closed=runtime.job.closed if runtime.job else None,child_exited=runtime.job.exited() if runtime.job else None)
                finally:
                    with self.guard:
                        self.runs.append((runtime.turn_id,record))
                    finished.set()
        self.patch.setattr(chat.AgentChat,'_run',run)
    def pytest_sessionfinish(self,session,exitstatus):
        complete=all(event.wait(5) for event in self.finished)
        wall=time.perf_counter()-self.wall_start if self.wall_start else None
        def summary(values):
            values=sorted(values)
            return dict(count=len(values),total=round(sum(values),6),max=round(max(values,default=0),6),p95=round(values[min(len(values)-1,int(len(values)*.95))],6) if values else 0)
        runs=[]
        for turn_id,record in self.runs:
            record['append']=summary(self.appends[turn_id])
            runs.append(record)
        if not complete or any(r.get('error_type') or not r.get('job_closed') or r.get('last_kind')!='state' for r in runs):
            session.exitstatus=1
        print('\nAB_PROBE '+json.dumps(dict(trial=TRIAL,mode=MODE,pytest_exit=int(exitstatus),lifecycle_complete=complete,call_and_all_closes_seconds=round(wall,6) if wall else None,phases={k:summary(v) for k,v in self.phases.items()},runs=sorted(runs,key=lambda r:r['turn']))))
        self.patch.undo()
raise SystemExit(pytest.main(['-q','-s','--tb=short','-c','backend/pytest.ini','--rootdir','backend','-o','pythonpath=D:/ClaudeCode/MV-hub-S-dev/backend','-p','no:cacheprovider','backend/tests/test_agent_chat_runtime.py::test_event_flood_and_huge_line_are_bounded'],plugins=[Probe()]))
```

`db_open/db_close`에는 시험 폴링과 결과 확인용 연결도 들어 있다. anchor 자체는 별도 측정이다. `run_with_close_seconds`는 유지 연결 close까지이며 뒤의 결과 조회를 제외한다. 전체 `call_and_all_closes_seconds`는 그 결과 조회와 완료 이벤트 대기도 포함한다. 이 차이를 합쳐 제품 전체의 일반적인 속도 향상률로 표현하지 않는다.
