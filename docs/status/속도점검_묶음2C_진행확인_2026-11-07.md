## 지금 동작(소스 확인, dev `58b11aa2`)

**2-7** — `frontend/src/lib/useGenerationAutoRefresh.ts`: 보이는 목록에 처리 중(pending·running) 카드가 하나라도 있으면 3초마다 `reload(true, true, "check")` = 첫 쪽 200건 전체 다시 받기(로컬 목록 한 장 3.38MB·약 47ms — `useGenerationLibraryData.ts` 주석 실측값) + 메타. 팀 탭이면 허브 → 공유 서버 왕복. 진행률·완료는 WS `progress` 가 주 통로이고 이 3초 폴링은 WS 누락 보강이다(파일 주석). `/api/generations/batch` 는 '라이브러리 안 바꿈' 경로이고 캔버스가 진행 중 카드를 이것으로 확인한다(`useSceneGenData`). 팀 탭은 `authority: "team"` 으로 목록과 같은 출처(서버 행 + 덧씌우기)를 받는다.

## 고칠 안(Claude 설계 v3 — 합의 검토 Codex `01a1b4dc` P2 3+1·Claude `71b73a6a` P2 1 반영)

**2-7 — 생성 중에는 처리 중 카드만 3초마다 확인하고, 바뀌었을 때만 목록을 받는다.**
- 3초 틱(처리 중 카드가 있을 때): 보이는 목록의 처리 중 카드 id 를 `api.getGenerationsBatch(ids, undefined, { authority: 팀 탭이면 "team", signal })` 로 한 번에 묻는다. 응답의 각 카드에서 **화면에 보이는 진행 필드**(status·error·execution_phase·provider_status·recovery_probe_status·check_failures) 중 응답에 있는 것이 목록 값과 다르거나, 카드가 missing·응답에 없음이면 지금처럼 `reload(true, true, "check")`. 같으면 목록을 받지 않는다.
- **확인 제한 시간 8초**(v2): 넘으면 요청을 실제로 끊고(`AbortSignal` — `getGenerationsBatch` 에 `signal` 선택 인자를 더해 `jsonFetch` 로 넘긴다) '바뀜'으로 보아 목록을 받는다(목록 쪽은 자기 30초 제한 `timedLibraryRequest`). 허브가 멎어도 확인이 `inflight` 를 끝없이 쥐어 주기 틱·창 복귀·안전망을 막지 않는다(Codex·Claude P2).
- 안전망(v2 — 경과 시간): 처리 중 카드가 있는 동안 **마지막으로 목록을 받은 지 15초가 지나면 비교 없이** 받는다(틱 수로 세면 멈춘 확인이 안전망까지 미룬다 — Codex P2). 확인 시각(last_checked_at·next_check_at) 툴팁, 다른 탭에서 새로 생긴 카드, 팀원의 다른 변경을 15초 안에 맞춘다(팀 탭 유휴 주기와 같은 간격).
- **늦은 응답**(v2): 확인을 기다린 뒤 목록을 받기 전에 이 주기가 아직 살아 있는지·쉬기·숨김을 다시 본다. 주기가 정리되면(탭 전환·compose·언마운트) 떠 있는 확인을 끊는다 — 늦게 온 '바뀜' 응답이 새 첫 쪽을 기다리는 목록을 무효화하지 않게(Codex P2).
- 그대로 두는 경우(지금처럼 매 틱 목록): 처리 중 카드 중 `_comfyPending`(서버에 없는 임시 카드)이 있을 때 · 확인 요청이 실패할 때(오류·시간 초과·`GenerationAuthorityUnsupportedError`·멈춤) — 실패를 '바뀜 없음'으로 보지 않는다.
- 그 밖(쉬기·숨김·진행 중 겹침 막기·창 복귀 5초 가드·팀 탭 유휴 15초·compose 제외·`LIBRARY_POLL_TICK` 알림)은 그대로. 확인 요청도 `inflight` 로 겹치지 않게 한다.
- 효과(계산 추정): 생성이 도는 동안 목록 전체 다시 받기가 3초마다 → 15초마다(+ 실제 바뀜). 완료 감지는 지금처럼 최대 약 3초.

**2-11 — 포트에 아무 줄도 없으면 포트 정리 PowerShell 을 띄우지 않는다(실측으로 범위를 좁힘).**
- `MV_agent.bat`: PowerShell 호출 앞에 netstat 확인. **netstat 이 성공했고**(v2 — 실패를 빈 포트로 보지 않는다, Codex P2: 실패해서 건너뛰면 옛 허브가 health 에 답해 옛 코드로 그대로 진행될 수 있다) 그 포트가 들어간 줄(`findstr /c:":%PORT% "`)이 **하나도 없을 때만** 건너뛴다. 줄이 하나라도 있거나(듣기·연결·닫는 중, 상태 글자 무관 — 언어판 차이 없음, IPv4·IPv6 모두) netstat 이 실패하면 지금처럼 PowerShell 의 소유자 확인·정리·실패 시 중단. 건너뛰는 경우 PowerShell 도 듣는 프로세스를 못 찾아 `exit 0` 이었다. 오탐(다른 연결이 그 포트 번호를 씀)은 지금처럼 PowerShell 을 돌릴 뿐이다. v3(Codex 재검토 P2 — 두 번 부르면 두 번째만 실패해도 '줄 없음'이 된다): netstat 은 **한 번** 임시 파일(`%TEMP%\mvhub_ports_<포트>.txt`)로 받고, 성공했을 때만 그 파일을 `findstr` 로 찾아 **종료 코드가 정확히 1(일치 없음)일 때만** 건너뛴다 — 0(찾음)·2(파일을 못 읽음)는 지금처럼 검사. 임시 파일은 바로 지운다.
- 하지 않기로 한 것(실측·시험 근거): ① 허브 대기 반복 바꾸기 — 격리 허브 3회씩: 실제 뜬 시각 2.41~2.52초 · 옛 curl 방식 2.38~2.52초 · 0.25초 파이썬 확인 2.39~2.43초 — 첫 curl 이 닫힌 포트의 재시도 대기(약 2초) 중에 허브가 열리면 바로 붙어 손해가 없다. ② 옛 실행 창 정리를 기다리지 않고 따로 돌리기(약 0.9초) — 그 정리가 새 세션의 cmd 를 '세션 친척 없는 옛 창'으로 볼 수 있는 경합이 생겨 기존 시험 `test_guard_closes_background_children_after_normal_batch_exit` 가 실제로 실패했다(가드 경로가 설치 폴더 밖인 경우). 되돌렸다. ③ 허브 시작의 CLI 신원 캡처(최대 8초)를 뒤로 미루기 — 그 뒤의 계정·생성자 연결 순서에 닿아 이번 범위 밖. ④ 의존성 import 검사(약 0.57초) — 패키지 누락을 잡는 계약이라 유지.
- 효과(실측): 실행마다 약 1초(PowerShell 1.10~1.21초 → netstat+findstr 약 0.07~0.11초).
