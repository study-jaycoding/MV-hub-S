# 서버 업데이터가 명령줄의 `>` 조각에서 멈춤(IsPathRooted 예외) — 2026-10-22

owner: Claude 총괄 · reviewer: Codex(읽기 전용) · status: 완료(dev 커밋 — main 반영은 다음 판·Jay 지시) · touched_paths: 아래 계약 · updated: 2026-10-22

## 원인(소스 직접 확인)

- `tools/run_update_git.ps1` 의 `Get-GitUpdateRole` 은 서버 루트가 든 프로세스 명령줄과 예약 작업 인자를 `Split-UpdateCommandLine` 으로 조각낸 뒤 조각마다 `Test-UpdatePathArgument` → `[IO.Path]::IsPathRooted()` 를 부른다(작업 인자는 120줄에서도 직접 부름).
- Windows PowerShell 5.1(.NET Framework)의 `IsPathRooted`·`GetFileName` 은 `<>|"` 같은 문자에 ArgumentException 을 던진다. `cmd /c "… > 로그 2>&1"` 처럼 리다이렉트가 든 명령줄의 `>`·`2>&1` 조각이 그대로 들어가 역할 판정 전체가 예외로 끝난다.
- 서버는 로그를 리다이렉트로 남기며 돌기 때문에 **다음 정기 서버 업데이트(staged 경로)도 같은 곳에서 멈출 수 있다.** 기존 시험의 작업 인자·프로세스 명령줄에는 리다이렉트가 없었다.

## Codex(읽기 전용, gpt-6-astra/high, thread `01a162f9-da50-7f61-9209-269a08ff0b19`) — 1차 수정 요청

- 원인·예외 처리 방향 동의. 남은 `GetFileName` 은 경로 판정이 참일 때만 실행돼 안전, `Assert-LocalUpdatePath` 는 유지.
- **새 위험**: 공백 경로 + cmd 바깥 두 겹 따옴표 + 리다이렉트이고 다른 서버 증거가 없으면, 고치기 전엔 예외로 멈췄는데 고친 뒤엔 `worker` → 옛 worker 실행(Codex 가 판정 함수만 메모리로 PowerShell 5.1 에서 실행해 확인). 조각 나누기 결함은 기존 것이지만 예외를 삼켜 위험 경로에 닿게 한 건 이번 변경 영향.
- 최소 보완: 원문에 이 설치의 서버 진입점 전체 경로가 있는데 조각에서 확인 못 하면 판정 불명으로 중단. 두 겹 따옴표 회귀 시험과 `Get-UpdatePathLeaf` 예외에 닿는 python 조각 시험 추가 → 반영(아래 계약 `unparsed-fails-closed`).

- 2차(같은 thread) **수정 요청 2건**: ① 이름이 'MVHub Server' 가 아닌 예약 작업이 이 설치의 `MV_server.bat`·`task_launch.bat server` 를 두 겹 따옴표로 실행하면 조각을 건너뛰어 `worker` → 작업 이름과 무관하게 원문에 서버 실행이 있는데 확인 못 하면 거부 ② cmd 래퍼의 supervisor 경로 조각이 모호성 검사만 면제받고 서버 증거가 아님 → 서버 증거로. 둘 다 반영·회귀 시험 추가.
- 3차 **동의**: Codex 가 판정 함수만 메모리로 실행해 다른 이름 작업 2·supervisor 래퍼 거부, watchdog·다른 설치 서버 작업·일반 작업자 `worker`, 검증된 supervisor+잠금 `server` 유지를 확인. 실제 서버 업데이트는 확인 범위 밖.
