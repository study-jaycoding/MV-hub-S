# 휴지통 목록이 옛 `/media` 주소를 원본 인터넷 주소로 바꾸지 않던 것

owner: claude · reviewer: codex(차이 리뷰 PASS) · status: 완료 · touched_paths: backend/app/routers/library.py, backend/tests/test_url_only_media_policy.py

## 발견 (11-18)

- Jay: 라이브러리 '휴지통' 보기에서 카드 대부분이 '원본 없음'(미디어를 못 불러옴).
- Codex 진단(`01a1ee39-22d4-75b3-be04-629f6ab10320`, read-only): 일반 목록·한 건 조회·묶음 조회는 응답에서 `_prefer_remote_source_urls()` 로 옛 `/media/...` 주소를 `source_url`(원본 인터넷 주소)로 바꾼다(`library.py:1019·1154·1237·1335`). **휴지통 목록 `GET /api/trash`(`library.py:1121`)만 이 보정을 거치지 않는다.** 그래서 로컬 파일은 없고 인터넷 원본은 살아 있는 항목도 휴지통에서는 '원본 없음'이 될 수 있다.
- Jay 의 dev 휴지통 32건을 읽기 전용 사본으로 세어 봤다(`backend/data_test/db/content_hub_trash.db` 를 스크래치로 복사):
  - 완료 28건은 모두 이미 힉스필드 CloudFront 주소(`file_path` 가 http)다. 옛 `/media` 주소는 0건이다. 7월 3일·8월 24일에 지운 것들이다.
  - 4건은 '생성 중'으로 남은 실패 생성(HF 확인 필요)이라 파일이 없다.
  - → **이번 Jay 화면의 '원본 없음'은 이 결함 탓이 아니다.** 힉스필드 쪽 원본이 이미 없어졌을 가능성이 크다(인터넷에 확인 요청은 보내지 않아 미확인).
- 결함 자체는 실제다. 배포 전엔 낮음도 고친다는 규칙에 따라 휴지통 복구 고침과 같은 배포에 넣는다.

## 고침

- `list_trash` 가 돌려주기 전에 다른 목록처럼 `_prefer_remote_source_urls(rows)` 를 부른다. 저장된 휴지통 내용은 그대로이고 응답만 바꾼다.

  - 반환 사전은 호출마다 새로 만들어 저장 내용·캐시를 바꾸지 않는다(`trash.py:787·859`).
  - 응답 모델에 맞는다.
