# 리졸브 패널 — stage 는 없는 빈을 만들지 않고 보류 (2026-11-12)

앞 기록: [빈 띄우기](리졸브패널_빈띄우기_2026-11-11.md) 「live 실측 1차」의 위험 신호.

## 문제

리졸브 `AddSubFolder` 는 새 빈을 **지금 빈으로 바꾼다**(11-11 밤 mv test 실측, panel_live2 ①).
`panel_operation` 의 stage 는 목적 빈이 없으면 `_destination_folder` 로 직접 만들었다. 그래서
"가져오기는 지금 빈 == 목적 빈일 때만, 아니면 보류하고 [맞추기]"(앞 기록 결정 5) 검사가 건너뛰어지고,
사용자가 보던 빈이 말없이 바뀌었다. 데이터 손실은 없다(가져오기는 맞는 빈으로 감).

생기는 때: 컷 고르기(target)가 실패한 뒤의 15초 다시 보기·[다시 시도] · 사용자가 리졸브에서 MV 빈을 지운 뒤.

## 고침 (A안 — Jay "고쳐 줘" 11-12, A/B 중 A 를 고른 이유는 아래)

stage 는 목적 빈이 없으면 만들지 않고 모든 항목을 `deferred` 로 돌려준다. 빈 만들기는 target(컷 고르기·[맞추기])만 한다.
화면은 이미 `deferred` 를 "새 공유물 N · 리졸브 지금 빈이 선택한 컷과 다릅니다 [맞추기]" 로 보이고,
[맞추기]는 target(create) → stage 라 빈을 만들고 지금 빈으로 고른 뒤 가져온다(프런트 변경 없음).

B안(만든 뒤 원래 빈으로 되돌리기, Codex 제안)을 고르지 않은 까닭: 앞 기록 결정 5 에서 "임시 선택·복원 — 사용자가 고른 빈과 겹침" 으로 이미 기각한 길이고,
A안은 쓰기를 하나 없앨 뿐 새 쓰기를 더하지 않는다.
