# 편집 탭 타임라인 휠 — Alt = 재생헤드 기준 확대 · Shift = 트랙 높이 — 2026-10-23 (Jay 요청)

owner: Claude 총괄 · reviewer: Codex(묶음 검토 때) · status: 완료(dev 커밋 — Jay 화면 확인·Codex 검토는 묶음 때) · touched_paths: 아래 계약 · updated: 2026-10-23

손잡이 고침: `EditSplit`(새 파일) — 막대 윗변의 6px 손잡이(자리 0 · 풀 폭 손잡이와 같은 라임 선), 끄는 동안 뿌리의 `--ed-tl-h` 만 고치고 놓으면 `EditTab` 이 `ch.editTimeline.tlHeight` 에 적음 · 더블클릭 = 기본 · 취소 = 끌기 전 · Tab 으로 온 ↑↓ = 16px(편집 화면 키로 안 감) · 끈 뒤 초점은 끌기 전 자리로. CSS `.ed-tl` = `height: var(--ed-tl-h, 40%)` · `min-height 120px` · `max-height: calc(100% - 204px)`(위쪽 160 + 막대 44) — 내용만큼 크던 것(max 52%)을 고정 칸으로 → 트랙을 키우면 칸 안에서 스크롤. 번역 두 줄. 시험 `editTimelineSplit` 4.
실제 브라우저(앱 CSS 만, 900px 화면): 기본 칸 360px(40%) — 트랙 140px 로 키워도 360 그대로·안에서 스크롤 · 정한 400px — 트랙 6×160 이어도 400 · 800 을 주면 696(위쪽 160 남김) · 손잡이는 막대 윗변(자리 0).
Jay 3차 "Alt 누르고 휠 이동할 때 앵커가 튀어 보인다": 원인 = 확대가 바뀐 뒤 재생헤드 그리기(`paint`)가 `useEffect`(그린 뒤)라 한 프레임 옛 자리에 남음 → `useLayoutEffect`(가로 스크롤 맞춤과 같은 프레임). jsdom 은 프레임을 못 봐 시험으로는 못 잡는다 — Jay 창에서 확인.

Jay 2차(풀 폭 손잡이 그림): "밑에 타임라인 크기 조절은 이미지처럼 내가 잡고 늘리면 조절되게 하고, 트랙 높이 조절하는 것은 그 조절된 크기 안에서 조절이 되는 거다. 다빈치에서도 그렇게 조정된다." 지금: `.ed-tl { flex: none; max-height: 52% }` — 내용만큼 커지다 52% 에서 멈춘다(트랙을 키우면 칸이 커진다).

고침: `EditTimeline` 휠 — Alt 는 커서 기준을 빼고 확대 맞춤의 재생헤드 기준만(쓸모없어진 `anchor` 정리) · Shift = `laneH`(58 → ×1.12 / ÷1.12, 30~160) · Ctrl = 좌우(그대로). 높이는 `.ed-tl` 의 `--ed-lane-h` → CSS `.ed-h-v, .ed-l-v`. 썸네일 칸 수도 그 높이로.
검증: 새 시험 3(`editTimelineWheel` — Alt 는 커서 500px·10px 와 무관하게 재생헤드 60px 유지 · Shift 는 65px·한계 30/160·좌우 그대로 · Ctrl 좌우) + 편집 탭 시험 3파일 통과 · tsc 0 · 구조 lint 0. 고치기 전 코드로 돌리면 Alt 시험은 scrollLeft 121(커서 기준), Shift 시험은 높이 58·좌우 이동으로 실패한다(계산으로 확인 — 실제 되돌려 돌리지는 않음). 실제 다빈치·실제 화면 조작 감은 Jay dev 창에서 확인.
뒤이어 빠진 곳 고침: 클립·빈 칸(`.ed-clip, .ed-slot`)·자른 나머지 빗금(`.ed-clip-rest`)·끌어 놓을 칸 강조가 따로 `height: 52px` 였다 — 트랙만 커지고 클립은 그대로였을 것 → `calc(var(--ed-lane-h, 58px) - 6px)`. 실제 브라우저(5173 이 내준 앱 CSS 만 불러 DOM 을 그려 잼): 트랙 58·100·30px 에서 머리·줄 = 그 값, 클립·빗금·빈 칸 = 52·94·24px.

Jay: "우리 타임라인 시프트 누르고 휠 움직이면 다빈치처럼 작동되게 한다. alt 누르고 휠 하면 타임라인의 앵커 기준으로 확대 축소가 되는데 지금 우리 것은 확대 축소는 되는데 기준점이 없다. 그것도 다빈치처럼." → 물음 답: 다빈치의 Shift+휠 = **트랙 높이**.

지금(코드 확인): `EditTimeline` 의 휠 — Alt = 확대(커서 아래 시각 기준), Ctrl·Shift = 좌우. 트랙 높이는 CSS `.ed-h-v, .ed-l-v { height: 58px }` 고정(썸네일 칸 수 계산도 `LANE_H = 58`). 이 PC 의 다빈치 설정(`%APPDATA%\Blackmagic Design\DaVinci Resolve\Preferences\config.user.xml`, 읽기만): `IsZoomAroundMousePointerEnabled=false` — Jay 의 다빈치는 마우스가 아니라 **재생헤드 기준**으로 확대한다.
