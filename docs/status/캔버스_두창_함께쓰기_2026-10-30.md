조사(코드 확인 — 실측 아님):
1. 떠 있는 동안 메인 창도 씬에 쓰는 배경 작업이 돈다 — 생성 결과 이어 붙이기(useCanvasGenerationLinks 2.5초, 띄우기 전 제출의 결과 붙이기 포함), MCP 캔버스 카드 붙이기(mcpCanvasTasks 15초), 레퍼런스 자동 복구(5초)·처음 복구, 카드 소속 합치기. 떠 있는 창은 남이 쓴 활성 씬을 받지 않고(알림만) 다음 저장에서 배열을 통째로 덮는다 — MCP 카드는 처리 기록(mcpAttachmentReceipts)이 남아 다시 붙지 않는다.
2. 되돌리기 기록은 창 메모리(sceneUndoStore)라 넘어가지 않는다. 닫은 뒤 메인 창의 Ctrl+Z 가 떠 있던 창의 작업을 건너뛸 수 있다(기록은 lastCommit 이 씬과 같을 때만 이어 쓰고 아니면 버린다 — useSceneHistory).
3. 띄우기 전에 건 Comfy 실행은 건 창(메인)이 끝까지 돈다(결과는 내 작업에 저장). '생성중' 표시는 창 메모리(sceneComfyRunningStore)라 떠 있는 창에 안 보인다 — 다시 누르면 두 번 실행된다.
4. 복사한 노드는 창 메모리(useSceneClipboardDrop)라 창 사이로 안 넘어간다.
5. 보기 설정·생성 폴더·자동 태그는 열 때만 같은 값에서 출발하고 그 뒤 따로 움직인다(저장은 하나 — 읽기는 켤 때만).
6. 창 올리기 — Jay 10-26 규칙 그대로(바꾸지 않음). 7. 라이브러리 카드 → 떠 있는 캔버스 끌어 놓기 — 브라우저 끌기 데이터(DRAG_TYPES.generation)라 될 것으로 보나 창 사이 끌기는 자동 시험·CDP 로 재지 못해 Jay 확인.

## 결과 (2026-10-30)

- ① 배경 씬 쓰기 쉼: `useCanvasGenerationLinks`(새 표식·결과 붙이기·표식 걷기·복구 주기 — `isCanvasFloating()`), `mcpCanvasTasks`(작업 목록 받기부터), `useSceneCoordination`(레퍼런스 자동 복구·처음 복구·카드 소속 합치기 — followStore). 보드가 비킬 때 내보내는 밀린 입력은 막지 않았다.
- ②④ 창 메모리: `lib/popupWindows.ts` 의 `registerCanvasMemory`·`shareCanvasMemory`(메인 창, main.tsx) — 캔버스 창은 `announceCanvasWindow` 때 opener 손잡이로 받고, pagehide 에서 'closed' 보다 먼저 돌려준다. 등록: `sceneUndoStore`("sceneHistories" — 열린 보드는 `useSceneHistory` 가 `registerLiveSceneHistory` 로 먼저 남긴다)·`useSceneClipboardDrop`("sceneClipboard" — 스냅샷과 클립보드 표식).
- ③ `sceneComfyRunningStore` — `shareWindowLive("comfyRunning")`(채널 mvhub-window-live): 창마다 자기 실행 목록, 다른 창 몫은 `isComfyRunning` 에 함께, 그 창이 닫히면(pagehide 'gone') 지운다.
- ⑤ `useLibraryFilters` — 캔버스 창이거나 메인 창에서 캔버스가 떠 있는 동안 storage 알림으로 보기 설정·생성 폴더(armedFolder·generationScope)·자동 태그를 다시 읽는다(자동 setter, 같은 값이면 안 바꿈). 보던 자리(filtersV2)는 아님.
- 시험: 새 `canvasTwoWindows`(6 — ①②③④⑤) · `canvasFloatingFollow` 에 ①(레퍼런스 복구·카드 소속 합치기) 1 · 고친 모듈을 쓰는 97파일 1303건 통과 `a0f3533b…` · 빌드 `03ad2953…` · `lint:architecture` `8d93b97c…` · 통합 검사 통과 · `check_code_map` 빠짐 0 · **프런트 전체 479파일 5553건 통과**(시험 기록 밖 — 공용 모듈을 고쳐 한 번 돌렸다).
- 확인 못 한 것(Jay 5173): 실제 두 창에서 ①~⑤, 특히 띄운 채 메인 창 라이브러리 카드를 캔버스 창으로 끌어 놓기(⑦ — 코드 변경 없음, 창 사이 끌기는 자동으로 못 잰다)·창을 닫은 뒤 메인 창 Ctrl+Z.
- 남은 한계: 떠 있는 창을 닫으면 그 창에서 돌던 Comfy 실행은 함께 멈춘다(앱을 닫을 때와 같다). 띄우기 전에 건 Comfy 실행의 결과는 내 작업에 저장되고 카드에는 붙지 않는다 — 한 창에서 실행 중 탭을 옮길 때와 같다. 메인 창을 새로 고친 뒤 띄운 캔버스 창은 opener 가 새 문서라 되돌리기 기록이 비어 있을 수 있다(메인 창이 들고 있던 기록이 새로 고침에 사라졌다).
