## 결과

- 구현: `AssetsSidebar` 맨 윗줄을 `.proj-row` 구조로 바꿨다. 개수는 폴더 줄과 같은 계산(`assetFileCount`)이고, 마크 id 는 `useAssetProjectData` 가 `/api/projects` 에서 이름으로 찾는다. 글자는 `project-sidebar.css` 의 `.assets-tree` 규칙 두 줄이다.
- 화면 확인: 스크래치 시험 화면에서 실제 부품 + 실제 CSS 를 쟀다. 맨 윗줄 이름과 폴더 이름이 같은 세로줄(38px), 마크 색이 메인과 같음(같은 id), 줄 36px·글자 17px, 폴더 15·13·13·고른 줄 14px, 맨 위를 보면 18px 파랑과 눈 아이콘.
- 화면에서만 잡힌 것 2건: ① `sticky` 의 `top: 0` 은 스크롤 칸의 안쪽 여백 안에서 멈춰 위쪽 8px 틈으로 폴더가 비쳤다 → `top: -8px`, 고친 뒤 멈춘 위치 0px 로 재확인. ② `body::before` 의 옅은 빛 위에서 불투명한 맨 윗줄이 띠로 보일 수 있어 `.assets-tree` 전체에 `var(--bg)` 단색을 깔았다. 사이드바 안의 아주 옅은 빛은 사라진다.
- 시험 대역 2곳에 새 값을 더했다: `assetsSelectionFocus` 의 훅 대역 `projectIds` · `failureFeedback` 의 API 대역 `projects`.
- 작업 트리 빌드는 다른 세션의 작업 중 파일 때문에 쓰지 않고 HEAD 사본에서 통과를 확인했다.
- 이름이 같은 프로젝트가 있거나, 내 탭 목록에 없는 프로젝트는 마크 색이 메인과 다를 수 있다. 실제 프로젝트 데이터로는 확인하지 않았다.
