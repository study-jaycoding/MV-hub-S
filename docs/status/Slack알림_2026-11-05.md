## 4. 결정

### D1. 배달부 = **저장 때 깨우기 + 5초 안전망**, 최근 창을 끝까지 다시 훑는다

**깨우기(v0.4 새로, Jay 결정)**
- 선례 그대로: `PeriodicShareStateReconciler`(확인 `services/share_state_reconciler.py:927-975`) — `kick()` 은 `loop.call_soon_threadsafe(event.set)` 만 하고, 작업 고리는 `wait_for(event.wait(), timeout=5초)` 뒤 `clear()` → 한 바퀴. 동기 라우트(threadpool)에서 불러도 안전.
- 코멘트가 서버 DB 에 들어가는 곳은 **세 곳**(확인): `repo/assets.py:449` 새 코멘트 INSERT, `repo/share.py:647` 번들 INSERT OR IGNORE, `repo/trash.py:704` 휴지통 복원 `_insert_row`. (v0.4 의 "두 곳뿐"은 틀렸다 — 내 grep 이 `INSERT INTO generation_comment` 글자만 찾아 `_insert_row(conn, "generation_comment", …)` 를 놓쳤고, Codex 3차가 짚어 다시 확인했다.)
- **즉시 깨우는 것은 정상 새 작성·번들 발행 두 길**:
  1. `routers/generation.py:1221` 공개 코멘트 저장(`repo.add_generation_comment`) **성공 반환 뒤** — 저장 함수가 스스로 COMMIT 한 뒤 반환한다(Codex 확인 `repo/assets.py:460`). 비공개 길(`:1194`)·서버로 넘기는 길(`:1209`)은 깨우지 않는다(넘겨받은 서버가 자기 자리에서 깨운다).
  2. `routers/publish.py:350` 번들 받기(`repo.import_bundle_payload`) **반환 뒤** — 명령 처리기 길(`usecases/share.py:69`, `publish.py:339-350`)도 이 안에서 돈다(확인).
- **안전망(5초)이 잡는 것**: 휴지통 복원(옛 시각 보존이라 보통 floor·30분 창 밖), 번들 부분 성공(항목별로 확정하므로 뒤 항목 실패로 예외가 나도 앞 항목 코멘트는 저장됨 — Codex 확인 `repo/share.py:860-865`), 깨우기를 놓친 경우.
- 깨우기는 **선례의 저수준 `kick()` 만** 쓴다 — 바깥 `kick_share_state_reconciler()` 는 DB 세대 검사를 먼저 하므로 그대로 따라 하지 않는다(확인 `share_state_reconciler.py:952,981`). 보내기만 하고 기다리지 않는다. 예외는 삼키고 기록만(코멘트 저장 응답을 절대 바꾸지 않음). DB 를 건드리지 않는다. 배달부가 안 도는 곳(로컬 허브·토큰 없음)에서는 loop 가 없어 아무 일도 안 한다(선례 `kick` 의 `loop is None` 검사).
- 한 바퀴 도는 중 여러 번 깨워도 한 바퀴만 더 돈다(Event 하나). 깨우기를 놓쳐도(저장 직후 서버 종료 등) 5초 안전망이 잡는다.
- 이 변경이 코멘트 저장 코드에 들어가는 것은 **두 자리에 한 줄씩**뿐이다(휴지통 복원 길은 건드리지 않는다).

**한 바퀴(Codex 2차 [P1] 500행 누락 반영)**
- 후보 = `is_private=0 AND julianday(created_at)` 이 아래 조건을 모두 만족하는 줄. SQLite `julianday` 는 `YYYY-MM-DD HH:MM:SS`·`T` 구분·소수 초·`Z`/`±HH:MM` 을 모두 읽고, 못 읽으면 NULL → 제외(추정 — SQLite 문서 기준, 구현 첫 단계에서 서버 사본의 실제 형식 분포를 세어 NULL 이 되는 형식이 있으면 파이썬 해석으로 보완).
  - `julianday(floor) <= jd <= julianday('now','+2 minutes')`
  - `jd >= julianday('now','-30 minutes')`
- `(jd, id)` 순서로 **500개씩 끝까지 넘긴다**(keyset: 다음 쪽 = `(jd, id) > (마지막 jd, 마지막 id)`). "최신 500개만 다시 보기"는 하지 않는다. rowid 는 쓰지 않는다(삭제·VACUUM 재배치, 확인 `schema.sql:535`).
- 비용: 색인이 없어 바퀴마다 표 전체를 훑는다(추정 — 코멘트 수만 줄이면 수 ms). 구현 때 서버 사본 크기로 실측. 느리면 그때 색인을 검토하되 **이름표·옛 검사기 영향부터 확인**(D4).
- 그다음 받을 사람 계산(D2) → `slack_dm_outbox` 에 `INSERT OR IGNORE`(UNIQUE(comment_id, recipient_email)). 같은 코멘트를 여러 번 훑어도 중복 줄은 안 생긴다.

**floor(이 시각 전 코멘트는 안 보냄)** = `app_setting.slack_notify_floor`
- 처음 켤 때 = 그 순간. **DB 세대가 바뀌었을 때(`_install_db` 로 복원·교체·이사)** = 그 순간(D3 세대 검사와 함께).
- 토큰을 **다른 Slack 팀**으로 바꾸면 = 그 순간. **같은 팀 토큰 교체는 floor 유지**(밀린 최근 알림은 이어서 보냄 — J7 추천안).
- 관리 창 [다시 켜기](일시 멈춤 뒤) = 그 순간 + 미발송 줄 모두 닫기(`resumed`). 단순 파일 복사 복원 절차는 "멈춤 → 복원 → 다시 켜기"(D3).

**남는 한계**: 배달부가 30분 넘게 멈추면 그동안 코멘트는 Slack 으로 안 간다(알림 종엔 남음, J5). 시각 없는 옛 번들 코멘트는 들어올 때 now 가 붙어 새 알림처럼 갈 수 있다(확인 `share.py:647`, J6 — 실제 대상은 D2 로 걸러짐).

### D2. 받을 사람 = 알림 종 규칙, **받는 사람 계정으로** 다시 계산 (v0.3 그대로 — 2차 해소)
- 후보 ID: 생성물 `creator_uid`, 부모 코멘트 `author`(확인 `_common.py:55-58`). 작성자 본인 제외. 빈 값·`me`·모호한 uid 는 **제외**.
- ID → 계정: `user_…` 는 `account.creator_uid` 로, `acct:<email>` 은 `account.email` 로 찾되 **지금 account 행이 있고 `status='approved'`**.
- uid가 plain email인 옛 행은 알림 종과 같이 대상이 아니다(제외). 2차 리뷰 후 총괄 결정 (a)에 따라 B7의 이메일 직접 조회와 그 시험을 제거했다. approved 조건과 발송 직전 재확인은 유지한다.
- 볼 수 있는지: 그 계정의 `actor_uid`, `read_all`(그 계정 global_role), `my_member_projects(actor_uid)` 로 `ALERT_COMMENT_TARGET_PREDICATE` + `alert_comment_visibility_clause` 를 그 사람 기준으로. 요청 문맥은 쓰지 않는다.
- **같은 함수**를 대기열 넣을 때와 보내기 직전에 쓴다. `muted` 는 옛 칸이라 무시.

### D3. 대기열·선점·**보내기 시작 기록**·정산 (Codex 2차 [P1] lease·5xx·복원 반영)

**줄의 상태**: `대기` → (선점) → `보내는 중`(`send_started_at` 기록·커밋) → `보냄` / `닫힘(사유)`, 그리고 `인증 대기`. **한 번 `보내는 중`이 된 줄은 다시 `대기`로 돌아가지 않는다** — 예외는 **"처리되지 않았음이 확실한" 응답 셋뿐**: 연결 전 실패 · 429 · 토큰 오류(아래). 그 셋만 `send_started_at` 을 지운다.

- 선점: `lease_token/lease_until`(선례 `asset_destination_outbox`, 확인 `services/asset_destination.py:96-104`). **`send_started_at` 이 있는 줄은 lease 가 끝나도 다른 배달부가 집지 않는다** — 선례와 다른 점(선례는 만료 작업을 다시 집음, Codex 확인 `:98`).
- 보내기 직전: D2 다시 확인 + 연결 유효(D6 team_id 일치) + 코멘트 아직 있음·비공개 아님·생성물 안 지워짐 + **줄의 `db_generation` = 지금 DB 세대**. 아니면 닫음.
- 보내기 시작: `send_started_at = now`, `token_revision` 을 **먼저 커밋**한 뒤 HTTP. lease 시간(60초) > HTTP 제한 시간(10초) → 살아 있는 배달부는 lease 안에 끝낸다.
- 결과:
  - `ok:true` → `sent_at`.
  - **연결 전 실패**(DNS 실패·연결 거절 — 요청을 보내기 전임이 확실한 것)만 → `send_started_at` 지우고 백오프 `min(3600, 60·n²)`.
  - **1차 리뷰 후 정정(2026-11-05)**: urllib은 연결/전송 시간 초과를 구분하지 못하므로 **연결 시간 초과는 `unknown`으로 닫음(중복 방지 쪽)**.
  - 429 → Slack 이 처리하지 않았다고 알려 준 것 → `send_started_at` 지우고 `Retry-After` 뒤.
  - **HTTP 5xx·응답 대기 중 시간 초과·연결 끊김 = 결과 불명** → `unknown` 으로 닫고 다시 보내지 않는다(J4).
  - 영구 오류(`user_not_found`·`channel_not_found`·`account_inactive`·`is_bot`…) → 닫음(지우지 않음).
  - **토큰 오류**(Slack 이 `ok:false` + `invalid_auth`·`token_revoked`·`not_authed` 로 답함 = 메시지가 만들어지지 않음, 추정 — Slack 문서 기준, 구현 때 확인) → `send_started_at` 을 지우고 **`인증 대기`**(그 호출에 쓴 토큰 revision 기록). 그 revision 은 멈추고, **같은 팀 새 revision 이 등록되면 `인증 대기` 줄은 `대기`로 돌아가 이어서 보낸다**(J7). 다른 팀 revision 이면 `team_changed` 로 닫는다. `인증 대기` 도 아래 15분 stale 시계(대기열에 넣은 때부터)를 따른다 — 15분 안에 토큰을 고치면 이어서 가고, 넘으면 `stale`(J9). (Codex 3차 [P1]: v0.4 대로면 시작 표시가 남아 lease 만료 뒤 `unknown` 으로 닫혀 새 토큰으로도 못 보냈다.)
- **되살리기(서버 재시작 때·바퀴마다)**: `send_started_at` 이 있고 결과가 없으며 lease 가 끝난 줄 → `unknown` 으로 닫는다(다시 보내지 않음).
- **오래된 줄**: 대기열에 넣은 지 **15분** 넘은 `대기`·`인증 대기` 줄 → `stale` 로 닫는다(v0.3 의 1시간에서 줄임 — 백오프 재시도는 사실상 3번까지, J9).
- **DB 세대**: 줄마다 넣을 때의 영속 DB 세대값(`share_db_generation`, Codex 확인 — `_install_db` 가 바꾼다 `routers/db_transfer.py:170`)을 적는다. `db.pool_epoch()`(프로세스 안 값)는 쓰지 않는다. 세대가 다른 미발송 줄은 `db_changed` 로 닫고, floor = 지금.
- **단순 파일 복사 복원**(서버를 끄고 DB 파일을 덮어쓰는 경우)은 세대값이 같이 되돌아가 알아챌 수 없다 → 복원 절차에 "Slack 멈춤 → 복원 → [다시 켜기]" 한 줄을 넣는다(다시 켜기 = floor 지금 + 미발송 닫기). 절차를 안 지키면 최근 30분 안 코멘트 알림이 한 번 더 갈 수 있다 → J8.
- 정산은 그 줄의 `lease_token` 이 그대로이고 같은 DB 세대일 때만. 네트워크 왕복은 DB 잠금 밖.

### D7. 열기 = 사람이 누른 것만, 창 하나만, 실제로 열렸을 때만 성공 (Codex 2차 [P1] 반영)

**받는 조건**
- 허브 `GET /api/open/generation/{gen_id}?c={comment_id}` — `_LOCAL_PREFIXES`. `for` 는 **뺀다**(`acct:` 는 uid 전환 때 바뀌고 이메일이 들어 있음). 대신 "지금 로그인한 계정이 그 코멘트를 볼 수 있나"로 판단(아래).
- 검사는 **두 층으로 나눈다**(Codex 3차 [P1]):
  1. **보안 검사 — 실패하면 바로 거절**(403·고정 문구, 단추 없음): 접속 주소(client) 루프백 + `Host` = `127.0.0.1:<허브 포트>` + prefetch 아님(`Sec-Purpose`/`Purpose: prefetch` 거절) + 전역 제한(2초에 1번).
  2. **사람이 누른 것인지 — 부족하면 단추 페이지**: 최상위 탐색(`Sec-Fetch-Mode: navigate`·`Sec-Fetch-Dest: document`) + `Sec-Fetch-User: ?1`. 보안 검사를 통과한 정상 로컬 요청에서 **이것만 부족할 때만** 바로 열지 않고 고정 안내 페이지의 [MV hub에서 열기] 단추를 준다.
- **로컬 처리기 셋 모두(단추 POST · `/api/open/claim` · `/api/open/ack`) 가 각자 직접** 보안 검사(루프백 client + Host) + 같은 출처(`Origin` = 허브 주소, `Sec-Fetch-Site: same-origin`)를 한다. 기본 미들웨어의 원격 차단은 설정으로 꺼질 수 있어 그것에만 기대지 않는다(Codex 확인 `main.py:1044`, `config.py:131`).
- Slack 앱이 기본 브라우저로 링크를 넘길 때 `Sec-Fetch-User` 가 붙는지는 (추정·P2 실측) — 안 붙으면 늘 단추 한 번을 더 누르게 된다.

**창 하나만 맡기**
- 허브: `ws.broadcast({type:"open_generation", gen_id, comment_id, open_id})`(AUTH off 소켓 = 이 허브의 모든 창, 확인 `ws.py:188-196`).
- 프런트 메인 창(`?embed` 아님, 숨김·최소화 포함)은 **Web Locks(`navigator.locks`) 로 창 안 대표를 하나** 둔다 — 대표가 닫히면 잠금이 다음 창으로 자동으로 넘어간다(죽은 대표 교체). 대표만 처리.
- 대표는 `POST /api/open/claim {open_id, window_id}`(허브 로컬) → 허브가 **처음 신청 하나만 승인**(허브 프로세스 안 원자적 사전), 나머지는 409. 브라우저 프로필이 둘이라 대표가 둘이어도 한 창만 연다.

**코멘트 확인 → 열기 → 결과**
- 대표 창: 그 생성물 코멘트 목록을 직접 불러와(서버 권한 그대로 — `require_view_generation`, 확인 `generation.py:1168`) **그 `comment_id` 가 그 생성물에 있고 지금 계정에 보이는지** 확인 → 있으면 `openComment(gen_id)` + 그 코멘트 읽음 처리(확인 `NotificationCenter.tsx:325`) → `POST /api/open/ack {open_id, window_id, ok:true}`.
- 목록 불러오기 실패·코멘트 없음·안 보임 → 열지 않고 `ack ok:false, reason`. 지금 패널은 조회 오류를 삼키므로(Codex 확인 `GenCommentPanel.tsx:47-59`) **열기 처리는 패널과 따로 결과를 받아** 판정한다.
- `/api/open/claim`·`/api/open/ack` 는 `_LOCAL_PREFIXES`(허브 로컬). 허브는 ack 를 **대기 중 open_id + 승인한 window_id + 열기 시작 때 계정**이 모두 같을 때만 받는다.
- 허브는 최대 3초 기다려 문구를 고른다: "MV hub 에서 열었어요(이 탭은 닫아도 돼요)" / "열지 못했어요 — 이 계정에서 볼 수 없는 코멘트예요" / "MV hub 창이 꺼져 있거나 응답이 없어요".
- 로컬에 없는 생성물은 현재 계정의 서버 권한으로 조회됨(확인 `library.py:1136-1142`).
- 창 앞으로: (추정·**P2 실측으로 결정**) 후보 = 허브가 메인 창 HWND 를 복원(SW_RESTORE) + TOPMOST→NOTOPMOST → 못 하면 작업표시줄 깜빡임 + 탭 문구. 지금 `raise_over_foreground` 는 맨 앞이 앱 창일 때만(Codex 확인 `app_windows.py:25,54`).
- 링크 포트: 관리자 설정 `open_base_url`(기본 `http://127.0.0.1:8010`, 확인 `MV_agent.bat:29`). 포트를 바꾼 PC 는 v1 한계.

## 11. 구현 조건 (Codex 3차 — 합의 판단과 분리, 구현·리뷰 때 지킬 것)

- **깨우기**: 저수준 `kick()` 만 재사용(바깥 함수의 DB 세대 검사 안 따라 함). 예외까지 삼켜 저장 응답 보존.
- **최근 창 조회**: 한 바퀴 안에서 floor·현재 시각·DB 세대를 고정. 쪽마다 표 전체를 다시 읽을 수 있으니 **여러 쪽 + 연속 깨우기를 포함한 전체 비용**을 실측. 기존 `created_at` 색인은 `julianday(created_at)` 정렬용이 아니다(Codex 확인 `schema.sql:546`). DB 작업은 이벤트 루프 밖에서, 긴 쓰기 잠금 없이.
- **보내기 시작**: 시작 기록은 유효한 lease 소유자만 원자적으로 확정. 10초 제한은 각 네트워크 단계가 아니라 **HTTP 작업 전체**에. 시작된 줄은 다른 배달부가 다시 보내지 않는다.
- **대기 코드**: 계정 생성 시각은 초 단위(Codex 확인 `schema.sql:220`) — 그것 하나로 재가입을 가른다고 가정하지 말고 재생성 때 반드시 달라지는 값을 실제로 고른다.
- **열기**: 목록 조회 뒤 계정이 바뀌면 패널 표시·읽음 요청도 멈춘다(ack 거절만으로는 늦음). 대표 창이 닫히는 순간의 요청은 다시 넘기거나 분명한 실패로.
- **Slack 출구**: 검사한 user id 와 실제 보내는 목적지가 같아야 한다. DM 채널을 쓰는 호출은 **검증된 user ↔ 채널 대응**으로만(따로 받은 user id 만 보고 다른 채널로 보내는 꼴 금지).
- **정제**: 사본을 만드는 모든 호출자에서 실패가 전파되는지 확인. 기존 Comfy 정제 변경은 섞지 않는다.
- 줄 상태(`인증 대기` 등)를 칸 하나로 둘지 기존 칸 조합으로 둘지는 구현 때 정한다.
- **인증 대기 해제**(Codex 4차): 토큰 등록 순간의 처리에만 기대지 않는다. 새 revision 등록 직후 옛 요청의 토큰 오류가 늦게 도착해도, **다음 바퀴에서 현재 revision·team 과 대조해 재개**할 수 있어야 한다(D3 재개 계약의 시험 항목).
