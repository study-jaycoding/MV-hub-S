## 확인한 것

- 재현(격리 빈 프로필): npm **12.2.2** 로 이 판의 `frontend/package-lock.json` 을 `npm ci` 하면 같은 실패 — `npm ci can only install packages when your package.json and package-lock.json are in sync` · `Missing: @emnapi/core@1.11.3 from lock file` · `Missing: @emnapi/runtime@1.11.3 from lock file`. npm 11.6.2(릴리스 제작)는 통과. **공개판 `3d0ff280` 의 lock 은 npm 12 에서도 통과** → 이번 판의 lock 변경에서 생겼다.
- 생긴 곳: dev `f1879e21`(vite 7.3.8·vitest 4.1.12·audit fix) — 새로 들어온 `@napi-rs/wasm-runtime` 1.2.4 가 `@emnapi/core`·`@emnapi/runtime`(`^1.7.1 || ^2.0.0-alpha.4`)를 peer 로 요구하는데 lock 의 최상위 항목이 없다(npm 11 은 넘어가고 npm 12 는 막음).
- CLI 1.2.2(npm·GitHub 받을 파일)는 멀쩡 — 같은 설치 명령이 이 PC 격리 환경에서 통과.

lock 에 **빠진 두 항목만** 넣는다(npm 12.2.2 `install --package-lock-only` 가 만든 그 두 블록 그대로, 다른 줄은 손대지 않음 — npm 12 가 덤으로 바꾸는 `peer` 표시 18곳은 넣지 않는다). 기존 패키지의 판·체크섬·의존성 변경 0. 이 판으로 npm 12.2.2·11.6.2·11.21.2 의 `npm ci` 가 모두 통과한다(격리 시험). npm 11 실제 설치에서는 wasm 대체 경로 전용 선택 패키지 2개(`@emnapi/wasi-threads`·`tslib`)를 더 이상 깔지 않는다(382 → 380) — 화면 빌드·시험 영향은 새 후보의 새 설치 전체 시험으로 확인한다.
