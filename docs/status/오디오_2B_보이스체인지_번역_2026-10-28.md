# 오디오 2-B — Voice Change · Translate(더빙)를 프롬프트 바에서

요청 근거: Jay 2026-10-28 — "보이스 체인지와 번역도 내가 프롬프트에 영상을 넣고 오디오에서 되게 하고 싶다" → 모의 화면 확인 → "이대로 설계 계약".
선행: [오디오 2-A](오디오_2A_TTS모델_2026-10-28.md) — 세 가지 일 전환·기능 표시 게이트 방식·오디오 모델 정의 표를 이 계약이 그대로 쓴다. **2-A 구현·리뷰 뒤에 시작한다.**
순서 변경: 1차 검토 때 Codex 는 "영상 카드 바로가기부터"를 권했고 Jay 도 그렇게 정했으나(10-28 오전), Jay 가 이후 **프롬프트 바에서 영상을 넣는 방식**을 골랐다. 카드 우클릭 바로가기는 이 계약 밖(나중에 같은 화면을 여는 단추로만).

## 확인한 사실(2026-10-28, 앱 런타임 CLI 1.2.3 — 1.2.2 와 같음)

- `workflow get voice_change`: `input_video`(object)* · `voice_id`* · `voice_type`(기본 preset) · folder_id. 견적 `cost_params`: `duration`* 만. type=video.
- `workflow get dubbing`: `input_video`* · `target_language`*(eng,cmn,fra,hin,ita,jpn,kor,por,rus,tur,spa,deu,ara,pol,ind,fil,swe,fin). 견적 `cost_params`: `duration`* · `fps`(기본 25). type=video.
- 무료 견적(`generate cost workflow …`, prompt 없이): voice_change 8초 1 크레딧 · 30초 3 / dubbing 8초 24 · 30초 90(fps 24 도 24) — **번역은 비싸다.**
- 기존 영상 수정 `draw_to_video` 는 `video`(object)를 `--video <업로드 id 또는 파일>` 로 받는다(CLI 도움말 예시). `input_video` 도 같은 방식(`--input-video`)으로 추정 — **유료 제출로 확인하지 않음.**
- 앱 코드: `cli_bridge.py:731` 은 모델 스키마의 `params` 만 보존 → `cost_params` 에만 있는 `duration`·`fps` 가 견적에서 빠진다(Codex A2, 직접 확인). 견적·제출이 늘 `--prompt` 를 붙인다(`cli_bridge.py:1140`, `agent_push.py:2537`). `GenerationCreate.prompt` 최소 1자(Codex A3). `_role_flag` 는 모르는 역할을 `--image` 로 보낸다(`agent_push.py:1261`). 워크플로 판정이 `draw_to_video` 이름에 박혀 있다(`cli_bridge.py:725·1139`, `agent_push.py:1678·2537·2965`).

## 설계

1. **화면** — Audio 의 세 가지 일 중 Voice Change / Translate 를 고르면: 레퍼런스 칸이 열리고 "영상 1개" 입력칸이 된다(에셋 창·탐색기·카드에서 끌어 놓기, 이 모드에서는 프롬프트 칸에 놓아도 레퍼런스 칸으로). 글 칸은 안내 문구만(입력 없음). 모델 칩·고급 없음. Voice Change = 목소리 칩(필수, 1단계 검색 창 그대로) · Translate = 언어 칩(18개 한국어 이름 ↔ CLI 코드).
2. **개수** — 두 워크플로는 **각 대상 카드당 요청 1개로 고정한다. 일반 제출·외부 count·batchOverride·씬 반복 모두에 적용하되 서로 다른 대상 카드 선택과 구분한다**(Codex C6 — `useSpotlightSubmit.ts:220`, `useSceneGenerationSubmission.ts:282`). 1/4 단추는 숨긴다. 번역 30초 ×4 = 360 크레딧 같은 실수를 막는다. *(모의 화면의 1/4 에서 바뀐 점)*
3. **입력 검사** — 영상 0개·2개 이상·영상 아닌 파일이면 제출 전에 막고 이유를 보인다(프런트·서버·에이전트 같은 규칙).
4. **저장 계약** — 실행 키 `voice_change`·`dubbing`, command=workflow. `prompt` 는 이 두 워크플로에 한해 빈 값 허용(그 밖은 지금처럼 1자 이상), CLI 에는 `--prompt` 를 보내지 않는다(A3). 영상은 기존 `references` 계약(파일·출처·지문)으로 한 개 저장하고 역할을 `input_video` 로 둔다 — params 에 복제하지 않는다. params = voice_change `{voice_id, voice_type}` / dubbing `{target_language}`.
5. **에이전트 제출** — `input_video` 역할을 `--input-video` 로 바꾸고(모르는 역할을 `--image` 로 떨어뜨리지 않는다), 참조 관측 목록에 input_video 를 넣는다(A3). 결과는 영상. **기존 참조 해석 결과의 파일/ID 전달 방식을 확인하고, 미확인 형식을 검증 완료로 기록하지 않는다**(Codex — `--input-video <업로드 id>` 는 아직 추정).
6. **견적(A2·C4·C5)** — 생성용 옵션과 견적용 옵션을 나눈다: 견적은 `cost_params`(duration, dubbing 은 fps 기본 25)만, 파일 경로·prompt 없이.
   - **견적 문맥 저장·전달 위치**: `params.cost_context = {duration, fps(dubbing만), input_ref}` — `input_ref` 는 그 영상 참조의 `asset_content_id`(없으면 `file_path`). 서버는 이 키를 허용하고, **에이전트는 CLI 제출 인자에서 뺀다.** 신규 제출·정보 창(`InfoPopup.tsx`)·재생성·씬 제출이 같은 문맥을 쓰며, **없거나 현재 입력과 불일치하면 미상으로 표시하고 기본 길이를 만들지 않는다**(Codex C4 — 지금 접수 후 견적·정보 창은 저장 params 만 넘긴다, `usecases/gen_requests.py:182`).
   - **길이 읽기**: 참조 URL 변환과 기존 파일 접근 경로를 재사용해 **실제 입력 파일의 메타데이터**를 읽는다(라이브러리 생성 옵션의 duration 을 실제 길이로 단정하지 않는다). 입력·계정·서버가 바뀌면 이전 측정을 폐기한다. 라이브러리·에셋·탐색기 입력 각각의 성공과 읽기 실패를 검증한다(Codex C5 — `promptParts.ts:10`, `download.ts:37`).
   - 영상을 바꾸면 앞 견적을 지운다. **길이를 못 읽으면 제출을 막는다**(기본 4초·이전 가격 금지).
7. **결과·계보(A9)** — 새 영상 카드, 원본은 그대로. 레퍼런스 칸의 영상이 라이브러리 생성물이면 `source_gen_id` 로 reference 계보(원자적 참조 저장 재사용, 성공 뒤 중복 계보 추가 금지). 목적지는 지금 무장한 프로젝트·폴더. 탐색기 외부 파일은 부모 생성물을 만들지 않는다.
8. **보호(A1·C1)** — 새 기능 표시 `video-voice-v1`(2-A 와 같은 세 곳 검사, 서버는 `/api/auth/config` features 로 알림). **기능 미지원 시 신규 선택뿐 아니라 저장값 복원·재생성·씬 제출도 차단한다. 신규 capability 는 기존 capability 선언을 유지하면서 추가한다.** 확장자 없는 결과의 영상 판정·재사용·씬 복원은 실행 키로(A4).
9. **관리** — 그룹 허용 모델·사용량 집계에 `voice_change`(보이스 체인지)·`dubbing`(번역)이 이름과 함께.
