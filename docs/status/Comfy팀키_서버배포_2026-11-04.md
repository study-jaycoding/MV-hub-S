## 전제(코드로 확인)

- 캔버스 Comfy 카드는 `routers/comfy.py` 가 이 PC 의 ComfyUI 로 워크플로를 제출한다. comfy.org API 키는 PC 마다 `app_setting.comfy_api_key` 에 있고 제출 때 `extra_data.api_key_comfy_org`(로컬)·`X-API-Key`(Cloud)로 실린다(`services/comfy_client.py submit`). 라우터 전체가 `_require_local_comfy`(AUTH on 이면 loopback 만)이고 `_proxy._LOCAL_PREFIXES` 라 서버로 위임하지 않는다.
- 로컬 ComfyUI 의 유료 API 노드는 그 PC 의 ComfyUI 가 키를 들고 comfy.org 로 나가므로 **키는 결국 각 PC 로 간다**. 허브는 설정에 적힌 어떤 http(s) 주소로든 키를 실어 보내므로 승인 팀원은 누구든 키를 읽을 수 있다 → 서버 보관은 비밀 유지가 아니라 **배포·교체 편의**다.
- `_target_fingerprint`(comfy.py:350)는 키 해시를 실행 지문에 넣어, 키를 바꾸면 그 전 실행의 결과 회수(`:1923`)·부팅 취소(`:693`)가 막힌다.
- 서버 DB 에 새 표·migration 이름표를 더하면 서버 업데이트가 막힌다(docs/CODE_MAP.md §5) → 기존 `app_setting` 한 값만 쓴다. 백엔드에 암호화 도우미는 없다. 서버는 Windows 예약 작업(SYSTEM)으로 돌고 DB 는 NAS 로 자동 백업 복사된다.
- 서버 관리 창 전용 API 의 기존 패턴 = `routers/account_cleanup.py _require_console`(AUTH on + 서버 PC 로컬 요청 + admin) + `_proxy.py` 자기-404 목록. 허브→서버 인증 호출 = `shared_connection.token()`·`base_url()` + urllib Bearer.
- dev 허브 DB 셋에는 Comfy 설정·실행 기록이 0건(11-04). 이 PC 의 ComfyUI = `D:\ComfyUI_NextSept\ComfyUI-Easy-Install`(0.38.0).
