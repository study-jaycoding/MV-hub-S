## 고칠 것

- **A 열기 대표 잠금**(Codex 1) — `frontend/src/lib/useOpenGeneration.ts`: 다른 탭 로그아웃으로 **멈춘(API pause) 탭이 대표 잠금을 쥔 채** 열기를 거절하고, 같은 종류의 정상 탭은 대표가 아니라 무시 → Slack 링크가 안 열린다. 고침: `useSyncExternalStore(subscribeApiPause, getApiPause)` 로 멈춤을 읽고, 잠금 요청·해제를 '멈추지 않았을 때만 요청, 멈추면 놓음' effect 로 묶는다(Codex 수정안 — 손으로 `requested` 관리하지 않음). 잠금 콜백은 받는 순간 멈춤이거나 언마운트면 바로 반환.
- **B 재개 직후 같은 초 코멘트 누락**(Codex 2) — `backend/app/repo/slack_notifications.py` `recent_comments`: 코멘트 `created_at` 은 초 단위(`datetime('now')`), 기준 시각은 소수 초 → 12:00:00.800 재개 뒤 .900 코멘트(12:00:00 저장)가 빠진다. 고침: 저장한 기준 시각은 그대로, **조회 아래 경계만 정수 초로 내리고(`math.floor(lower)`) 경계를 Julian day 로 바꾸는 계산을 SQL 의 `julianday(?, 'unixepoch')` 로** 한다(별도 Claude 합의 지적: Python 의 `S/86400 + 2440587.5` 는 SQLite 의 `julianday('…:SS')` 와 마지막 자리가 어긋날 수 있어 그 초의 코멘트가 `BETWEEN` 에서 빠진다 — 같은 SQLite 계산을 쓰면 같은 값). 위 경계도 같은 식. 재개 직전 같은 초(최대 1초 앞) 코멘트가 대상이 될 수 있음을 받아들인다(누락보다 낫다, 중복은 outbox 의 `UNIQUE(comment_id, recipient_email)` 가 막는다).
- **C 429 대기를 배달부 전체로**(Codex 3) — `backend/app/services/slack_notify.py`: `rate_limited` 를 받아도 그 줄만 미루고 다음 줄을 바로 보낸다. 고침: 모듈 값 하나 `_send_pause_until`(monotonic) — rate_limited 면 그 줄은 지금처럼 pending(Retry-After 뒤) + `_send_pause_until = now + delay` + 배달 반복 끊기. 다음 바퀴·kick 에서도 그 전에는 **배달 단계만** 건너뛴다(모으기·enqueue 는 계속). 연결 확인 DM(`slack_link`)은 이 대기와 별개.
- **D 연결 시작의 이메일 오류**(Claude 1) — `slack_link.start`·`slack_client`: Slack `users.lookupByEmail` 의 '없음'은 `users_not_found`(복수 — Slack 문서 기준, 실호출 확인은 안 함)인데 통과 목록엔 단수 `user_not_found` 만 있어 `unknown` → "관리자에게 확인" 문구, 게다가 1분 제한이 조회 전에 기록돼 고쳐서 다시 못 받는다. 고침: 통과 목록에 `users_not_found` 추가 · 조회의 `users_not_found`/`user_not_found`/`invalid_email` 은 `LinkError('그 이메일을 쓰는 Slack 사람을 못 찾았어요')` · **그 '이메일 오류'일 때만 자기 요청의 1분 제한을 푼다** — 시간당 조회 횟수(10회)에는 계속 넣는다(Codex 합의 지적: 같은 기록으로 두 제한을 세므로 기록을 지우면 시간당 상한까지 우회된다). 구현은 1분 제한용 '마지막 요청 시각'을 시간당 기록과 따로 두고, 이메일 오류면 그 값이 자기 요청 시각일 때만 지운다. 429·통신 장애·그 밖의 실패는 두 제한 그대로.
- **E 배달 바퀴(5초) 비용**(Codex 4 + Claude 4) — `slack_notifications`: ① `scan_context` 의 outbox 세대 정리 `state NOT IN('sent','closed')` → `state IN ('pending','auth_wait','sending')`(같은 뜻, 색인 `idx_slack_dm_due` 를 탈 수 있게) ② `recipient_emails` 는 **지금처럼 승인 계정 전체에서 UID 가 하나로 정해진 뒤에** `slack_link` 가 있는 이메일만 남긴다(Codex 수정안 — 먼저 JOIN 하면 모호한 UID 가 하나처럼 보인다; 연결 대조는 `delivery_target` 과 같이 `norm_email` 로 — 별도 Claude 권고) → 연결 안 한 수신자는 `delivery_target` 을 매 바퀴 다시 돌지 않는다. 코멘트 조건의 `julianday(created_at)` 는 **그대로**(문자열 비교는 공백형·T형·시간대 표기가 섞인 옛 코멘트를 놓친다 — Codex). 보낸·닫힌 줄 지우기는 안 함(잔여).
- **F DM 채널 재사용**(Codex 5) — `slack_client.send_dm`: `_channels[(revision, user)]` 가 있으면 `conversations.open` 생략(캐시 읽기·쓰기는 `_lock` 안, 네트워크는 밖). **기억한 채널로 보낸** `chat.postMessage` 가 `channel_not_found` 면 실패한 채널이 지금 캐시 값과 같을 때만 그 칸을 지우고 `not_connected`(재시도)로 돌린다 — Slack 이 명시적으로 거절해 보내지지 않은 것이 확실하므로 다시 보내도 중복이 없고, 닫으면 낡은 캐시 때문에 알림이 사라진다(별도 Claude 합의 지적). 다음 시도는 채널을 새로 연다. 방금 연 채널에서 나온 `channel_not_found` 는 지금처럼 닫는다.
