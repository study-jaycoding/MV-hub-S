## 범위와 순서

이번 변경(계약 A)은 **스위치를 켜지 않는다(기본 0 그대로)**. 그래서 **기본 설정에서는 로그인 창을 만들지 않는다**(합의 Codex `01a1ece3` 2·Claude `611dae3d` 낮음 1).

- 버튼으로 로그인 창이 뜨는 흐름은 스위치를 켠 허브에서만 보인다.

- 그 뒤 실제 PC 시험(아래)을 한다. 통과하면 결과를 Jay 에게 보인다.
- Jay 가 확인하면 **계약 B(작은 변경)** 로 기본값을 `1` 로 바꾼다. 계약 B 의 범위는 `config.py` 한 줄 + 기본값 시험 + `env_vars.md`·`CODE_MAP.md` 다.
- 되돌리기 = `CONTENT_HUB_AGENT_CHAT_LOGIN_WINDOW=0` 을 준 뒤 MV Hub 다시 시작.

**지원 범위:** 한 Windows 세션에서 MV Hub 를 쓰는 보통 경우다.

- 같은 Windows 사용자가 원격 데스크톱 등으로 **두 세션에서 동시에** MV Hub 를 켜는 경우는 범위 밖이다. 잠금이 세션별(`Local\`)이고, MV Hub 실행기 잠금도 원래 그 범위다(`run_agent_session.py` `acquire_launcher_mutex`).
- 원격 데스크톱으로 한 세션만 쓰는 것은 범위 안이다.

## 고침 (계약 A)

1. **창을 띄우기 전 거절**(`agent_chat_claude.py` `open_login_window`, 스위치 확인 다음·잠금 전):
   - 허브 프로세스가 **관리자 권한(상승 토큰)** 이면 새 예외 `LoginUnsupported("elevated")`.
   - **세션 0(서비스)** 이면 `LoginUnsupported("service")`.
   - 허브 프로세스의 사용자가 **그 세션에 로그인한 사용자와 다르면**(같은 화면에서 '다른 사용자로 실행' 등) `LoginUnsupported("other_user")`. 대조는 허브 토큰 사용자와 세션 사용자(`WTSQuerySessionInformation` 사용자·도메인)다(합의 Codex `01a1ece3` 1).
   - 토큰·세션·사용자 **조회가 실패하거나 판정이 불명**이면 `LoginUnsupported("unknown")`. 보통 사용자·보통 세션으로 치지 않는다.
   - 넷 모두 잠금·기록·프로세스 생성 **전에** 끝난다. 설치용 검사(`run_agent_session.py` `_claude_token_problem` 의 `token_unknown`)와 같은 원칙이다.
   - 라우터(`routers/agent_chat.py`)는 기존 머리 `X-MVHub-Claude-Error: login_window_unsupported` 를 쓴다. 까닭 문구는 **응답 본문 `detail`(글자)** 에 담는다. 새 머리는 만들지 않는다. 지금 `openClaudeLogin` 이 본문 `detail` 을 읽는다(`agentChatApi.ts:289-295`). 이메일·경로는 싣지 않는다(합의 Claude `611dae3d` 낮음 2).
   - 정상 판정(관리자 아님·세션 0 아님·같은 사용자)이면 지금 창 띄우기 경로 그대로다.
   - 다른 판정·잠금·기록·창 띄우기 코드는 바꾸지 않는다.
   - 브라우저 없음·자동 열기 차단·CLI 즉시 종료는 미리 알 수 없다. 이런 경우는 기존처럼 창이 닫히면 `unfinished` 로 간다. 그래서 안내에 "브라우저가 안 열리면 그 창에서 c 를 눌러 주소 복사"를 둔다.
2. **프런트 연결 흐름**(`useAgentChat.ts` `connect`·`agentChatApi.ts` 오류 코드):
   - `login_window_unsupported` 는 `note=terminal` 이다. 본문 `detail` 의 까닭 한 줄을 함께 보인다(백엔드가 정한 문구).
     - elevated: "관리자 권한으로 켠 MV Hub 라 버튼 연결을 쓸 수 없어요"
     - service: "이 Windows 로그인에서는 버튼 연결을 쓸 수 없어요"
     - other_user: "다른 Windows 사용자로 켠 MV Hub 라 버튼 연결을 쓸 수 없어요"
     - unknown: "권한을 확인하지 못해 버튼 연결을 쓸 수 없어요"
   - `not_needed`(그새 다른 곳에서 연결됨)는 오류 대신 `recheck()` 해서 지금 상태로 맞춘다.
   - 연결 요청은 **한 번에 하나**다. 설정과 대화 칸 어느 쪽에서 눌러도 진행 중이면 더 보내지 않는다(진행 중 표시).
   - 연결 요청에서 난 오류는 별도 상태(`connectError`)로 둔다. 설정이 그것만 보인다. 일반 `chat.error` 는 그대로다(합의 Claude 낮음 3).
   - 연결 요청·상태 조회가 칸을 닫은 뒤 늦게 끝나도 자동 확인 타이머를 다시 만들지 않는다(지금 `mounted` 확인을 지킨다).
