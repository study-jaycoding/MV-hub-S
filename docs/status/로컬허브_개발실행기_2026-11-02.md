# 로컬 허브 전용 화면을 핫 리로드로 보는 실행기 (2026-11-02)

owner: Claude · reviewer: Codex·별도 Claude 세션(계약 합의까지, 독립 코드 리뷰 전) · status: 검증 중(dev 코드 커밋 `be072238` · Jay 실제 계정 화면 확인 남음) · touched_paths: 아래 계약 · updated: 2026-11-02

`test_dev.bat` 은 `CONTENT_HUB_AUTH=1`·`CONTENT_HUB_NO_PROXY=1` 인 서버 모드라 5173 에서는 로컬 허브(AUTH off) 전용 화면이 안 보인다(관리자 창 [업데이트] 탭, 슈퍼 관리자, 워크스페이스 전환, 캔버스 보관·불러오기). 8012 를 공유 서버로 삼는 두 번째 백엔드와 두 번째 Vite 를 띄우는 실행기를 더한다. 제품 동작은 바꾸지 않는다.

## 실측 (2026-11-02, Claude)

`backend/data_test` 를 읽기 전용으로 복사한 일회용 AUTH-on 서버에 붙였다. 실제 8012 에는 로그인하지 않았고 생성 버튼은 화면에서 누르지 않았다. 시험 자료는 지웠다.

| 대상 | 결과 |
|---|---|
| 화면 | 관리자 창 [업데이트]·열쇠, 씬 패널 보관·불러오기(불러오기 창 열림, `/api/scene-keeps` 200), 계정 메뉴 워크스페이스 목록·동기화 상태 |
| CLI 를 뺐을 때 | `/api/workspaces`·`/api/models` 502 → CLI 를 되살리는 쪽으로 결정 변경 |
| 핫 리로드 | 5173 이 쓰지 않는 임시 파일로 확인, `[vite] hot updated`, 새로 고침 없음. 임시 파일은 지웠다 |
| HTTP 차단 | 허브 로그인에 문서용 주소 192.0.2.1 을 주자 요청이 죽은 프록시 자리로 들어왔고 저장 주소는 그대로 |
| LAN 직접 연결 | **고치기 전 재현**: `/api/shared-server/url` 로 이 PC 의 LAN 주소를 넣자 허브가 `GET /ws` 를 Bearer 토큰과 함께 바로 보냈다(`proxy=None`). **고친 뒤**: 수신기 연결 0건, 허브 오류 `PermissionError`, 주소를 되돌리면 재연결 |
| 생성 요청 | API 로 개인·팀 공간 각 1건 → 둘 다 201 `pending`. 허브 `gen_request` +2, 서버 49 → 49, Higgsfield 최근 작업 목록 전후 동일. 에이전트 없음 |
| 씬 백업 | 허브 `PUT /api/scenes/backup` 200 → 허브 0 → 1, 서버 17 → 17 |
| 실제 실행기 | `test_dev_hub.bat`(브라우저 없음, 실제 8012, 로그인 없음): 공유 주소 8012, Job 을 끊으면 5273·8013 이 내려가고 남은 프로세스 없음. 두 번째 실행은 포트 안내를 내고 멈춘다(허브 pid 그대로) |
| 주소 변경 뒤 재기동 | 앱에서 주소를 바꾼 데이터로 다시 켜면 안내를 내고 종료 코드 1 |
| 기존 세션 | 5173·8012 프로세스·시작 시각 그대로, 공용 Vite 캐시 그대로 |

코드로만 본 것(미실측): 다른 계정 로그인 때 8012 에이전트 계정 변경과 그 계정 대기 요청 제출(`routers/auth.py` `_activate_local_agent`·`routers/gen_requests.py` `pending_gen_requests`), 어셋 창의 NAS 접근, 허브 로그아웃이 8012 에 닿지 않음(`routers/publish.py` `shared_server_logout`), Higgsfield 직접 호출이 이력 읽기뿐임(`services/higgsfield_history.py` `show_generations`, 호출부 `history_autofill` 뿐).

합의 왕복(대조 근거): Codex 는 4차에서, 별도 Claude 세션은 3차에서 동의했다. 그 사이 고친 것 — 허브 데이터 겹침 검사, 사설망 직접 연결 차단(Codex 가 차단 범위를 물어 찾은 실제 누출), 이름은 다시 풀지 않고 거절, 세션 자동 교체 삭제(프로세스를 끄지 않는다), 생성·씬 실측과 문구 범위.

미해결(실행기로 못 막음): 다른 계정으로 로그인하면 8012 에이전트가 그 계정의 대기 요청을 실제로 제출할 수 있다. 막으려면 제품 코드(`_activate_local_agent`)를 바꿔야 하므로 Jay 결정이 필요하다.

못 잰 것: 8012 에 실제 계정으로 로그인한 뒤의 화면, 5173 과 같은 계정 동시 사용, 화면의 Generate 단추, 수정·오디오 생성 경로(같은 `/api/gen-requests` 인지 코드로만 봄).
