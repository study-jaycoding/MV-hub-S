# 저장 통합 설계안 — 작업물 저장을 한 통로·한 창고로 (2026-11-12)

owner: Claude(설계) · reviewer: Codex(적대적 검토 미요청) · status: 설계 중 · touched_paths: 이 문서만(코드 0) · updated: 2026-11-12

Jay 요청(11-12): "캔버스 저장·편집 저장 등 우리가 만든 파일 저장이 다 따로 관리되고 방식도 제각각이다. 저장 관련된 것을 모두 찾아 잘 관리할 수 있게. 파악부터 → 통합 설계안을 만들고 이해하기 쉽게 이미지로도."

이 문서는 **설계 초안**이다. 구조·DB·백업 삭제 규칙을 바꾸는 중요 작업이라, 코드 전에 Codex 적대적 검토와 양측 합의를 거친다(`docs/AGENT_WORKFLOW.md`). 숫자(백업 개수 등)는 제안값이고 Jay 결정 전이다.

## 1. 지금 상태 (11-12 조사)

조사 방법: 읽기 전용 에이전트 3개(브라우저 저장소 · 백엔드 DB·파일 · 작업물별 저장 흐름)가 dev 코드를 읽었다. 실제 데이터 파일은 열지 않았다. **직접 대조한 것**은 ✔ 로 표시했고, 나머지는 에이전트 보고다.

## 2. 원칙 (세 줄)

1. **잃으면 안 되는 작업물은 원본을 이 PC 허브 DB 한 곳에 둔다.** 브라우저는 "빨리 보이는 사본 + 보낼 대기열"이다.
2. **모든 작업물은 같은 저장 통로 하나를 지난다.** 쓰는 창 하나(임대) · 판 번호 대조 · 충돌하면 사본 · 저장 입구 모양 검사 · 실패하면 다시.
3. **백업은 세트 단위로 오래 남기되 솎는다**(최근 · 날마다 · 주마다). 허브 DB 밖에 있는 작업물도 세트에 넣는다.

자동 저장을 **꺼 두면**(§4-4) [지금 저장]을 누르기 전까지는 브라우저 사본이 더 새것이다. 원칙 1 은 "켜져 있을 때 원본은 허브"로 읽는다.

주의: 여기서 "허브 DB" 는 **이 PC 의 로컬 허브**다. 다른 PC 와 자동으로 같아지지는 않는다(그건 공유 서버 발행의 일이고 이 설계 범위 밖). 얻는 것은 ① 브라우저를 바꾸거나 사이트 데이터를 지워도 남는다 ② 백업 세트에 들어가 작업자 백업으로 서버까지 복제된다 ③ 같은 PC 의 다른 창(리졸브 패널 포함)이 같은 값을 본다.

## 4. 설계

### 4-1. 공통 저장 통로 ("작업 문서 저장소")

지금 캔버스 허브 공책이 이미 갖춘 장치(쓰기 임대 `/api/scenes/writer` · 판 대조 · 충돌 사본 · 닫을 때 넘기기 · `local_only` 대비)를 **종류(kind)를 받는 공용 통로**로 넓힌다.

- **브라우저 쪽** 한 모듈(가칭 `workDocClient`): 바꾸면 화면·브라우저 사본에 즉시 반영 → 보낼 대기열 → 2초 묶어 허브로 → 실패하면 늘어나는 간격으로 다시 → 허브 판이 다르면 덮지 않고 충돌 사본.
- **허브 쪽** 한 묶음: 종류별 문서(kind · 계정 범위 · doc_id · 판 번호 · 본문 · 지운 표시)와 충돌 사본. 저장 입구에서 종류별 모양 검사(씬은 11-12 `a4ceae96` 에 이미 있음 — 그 자리를 공용으로).
- **허브가 꺼졌을 때**: 화면은 브라우저 사본으로 계속 쓰고 대기열에 쌓는다. 허브가 켜지면 보낸다(공책의 `local_only` 와 같은 길).
- **크기**: 원본이 허브가 되면 5MB·1MB 상한은 "한 번에 보내는 양" 문제가 된다. 나눠 보내기 vs 상한 올리기는 Codex 검토에서 정한다.

**결정 갈림(Codex 검토 요청)** — 허브 표를 어떻게 둘까:
- A안: 새 공용 표(`work_doc`·`work_doc_copy`)를 만들고 **새 종류(편집 문서·회색)부터** 태운다. 캔버스는 지금 `scene_notebook*` 표 그대로 두고 코드만 공용 통로를 쓴다. → 갓 안정된 캔버스 데이터를 옮기지 않는다. **추천.**
- B안: 기존 `scene_notebook*` 표에 kind 칸을 더해 모두 거기로. → 표는 하나지만 캔버스 데이터 이관이 필요하다.

### 4-2. 백업

- 지금: 세트 7개, 바뀐 뒤 5분 잠잠 + 최소 15분 간격 → 바쁜 날 약 2시간치.
- 제안(숫자는 Jay 결정): **최근 8세트(약 2시간) + 날마다 1세트 14일 + 주마다 1세트 8주**. 세트 단위로 솎는다(파일 수 아님).
- 세트에 더할 것: Agent 대화 DB, `asset_mounts.json`. `manage_hub.db` 변경도 변경 감지에 넣는다.
- 디스크 어림(추정): 콘텐츠 DB 약 65MB(10-31 측정 사본) × 최대 30세트 ≈ 2GB/계정. 실제 크기는 1단계 전에 잰다.
- 서버 NAS 복제(`tools/backup_replicate.py` `KEEP_PER_DIR=30`, 파일 수 기준)도 세트 기준으로 — **서버 실제 상태는 Jay 확인 필요**(공유 서버 직접 접속 금지).

### 4-3. 이름·코드 정리

- 브라우저 키 규칙: `mvhub.<분류>.<기능>.<이름>`, 계정 범위는 끝에 `:<계정>` 하나로. 옛 키는 읽기만 하고 옮긴다. 계정 바꿀 때 지우는 대상은 "나. 개인 설정" 목록으로 명시.
- 브라우저 저장은 `lib/storage.ts` 하나로, IndexedDB 열기 하나로.
- 백엔드 파일 원자 쓰기는 `services/atomic_io.py` 하나로(자식 프로세스·단일 파일 `agent_push.py` 같은 정당한 예외는 `docs/CODE_MAP.md` §5 대로 유지).
- `docs/DATA_OWNERSHIP.md` 를 이 설계의 "저장 지도"로 갱신.

**자동 저장 간격의 뜻**: 화면과 브라우저 사본은 어떤 값이든 늘 바로 저장된다. 이 칸은 허브 DB(원본)로 옮겨 적는 때만 정한다. 그래서 10초로 둬도 창이 꺼져서 일을 잃지는 않는다(다시 열면 대기열이 보낸다).

**꺼짐(Jay 11-12 "꺼짐 버튼도 넣자")**:
- 상태가 주황으로 바뀐다: "자동 저장 꺼짐 · 안 옮긴 변경 N". 묶음 제목 밑 줄에도 같은 문구가 나와 접어 둬도 보인다.
- [지금 저장] 단추로 손으로 옮긴다.
- 브라우저 사본은 계속 바로 저장된다 — 창이 갑자기 꺼져도 다시 열면 남아 있다.
- 창을 닫을 때 안 옮긴 변경이 있으면 저장할지 묻는다.
- 대가: 옮기기 전까지는 백업에도, 같은 PC 의 다른 창(리졸브 패널 등)에도 안 들어간다. 안내 문구로 보인다.

**설정을 어디에 두나(Codex 검토 요청)**: 백업 시점·보관 양은 허브가 쓰는 값이라 **허브 설정**(`app_setting` 같은 허브 DB 값)이어야 한다. 자동 저장 간격도 같은 PC 의 모든 창(메인·분리 창·리졸브 패널)이 같은 값을 써야 하므로 허브 설정으로 둔다(추천). 브라우저마다 따로 두면 창마다 저장 시점이 달라진다.

**고르는 칸의 범위(제안)**: 백업 찍는 때 = 조용히 1·5·10분 / 최소 간격 5·15·30·60분. 남기는 양 = 최근 4·8·16장 / 날마다 7·14·30일 / 주마다 4·8·12주. 예상 용량은 실제 최근 세트 크기 × 남길 세트 수로 계산해 보인다(어림값을 박아 두지 않는다).

## 6. 바꾸지 않는 것

- SQLite + 목적별 DB 파일 구성(11-06 Claude·Codex 같은 결론).
- 생성물 기록 소유(계정별 로컬 DB · 발행분 공유 서버)와 발행 흐름.
- 미디어 파일은 백업하지 않음(의도).
- NAS 완료본 이름 규칙, 코멘트 저장 위치(이미 DB).

## 8. 위험과 대비

- 허브가 꺼지거나 느리면 편집이 멈춘다 → 화면은 브라우저 사본으로 즉시, 보내기만 늦게(원칙 1).
- 옮기다 잃는다 → 옛 자리를 지우지 않고 읽기 전용으로 남기고, 옮기기 전 파일로 받아 둔다(캔버스 `ch.scenes` 흡수 때와 같은 방식).
- 편집 문서는 조작마다 저장 → 허브 쓰기가 늘어난다 → 2초 묶음, 시험으로 쓰기 횟수 확인.
- 공용 통로가 갓 안정된 캔버스를 흔든다 → 3단계에서 캔버스는 "동작 같음" 시험으로 묶고, A안이면 표 이관 없음.
- 백업을 늘리면 디스크가 는다 → 1단계 전에 실제 세트 크기를 재고, 숫자를 조정한다. 칸에 예상 용량을 보인다.
- 자동 저장을 꺼 둔 채 잊는다 → 주황 상태 줄(접어도 보임) · 안 옮긴 변경 수 · 닫을 때 묻기. 꺼 둔 동안 브라우저 사이트 데이터를 지우면 안 옮긴 변경은 잃는다 — 안내 문구에 적는다.
- 사용자가 고른 값이 엉뚱해 백업이 너무 적거나 많다 → 고르는 칸을 정해진 범위 목록으로만 둔다(자유 입력 없음).
