# 캔버스 — 휴지통 결과가 카드 결과 수에 세어짐 · '카드 생성물 담기' 영상·음성 썸네일이 검은 칸

owner: claude · reviewer: codex(1차 차이 리뷰 PASS · 2차 독립 리뷰 PASS) · status: 완료(화면 눈 확인 남음) · touched_paths: 1차 14개(계약 `canvas-trash-count-media-thumbs-20261118`, 커밋 a6f48b89 판) · 2차 = 아래 작업 계약의 8개

## 증상 (Jay, 11-18 dev)

1. 워크스페이스에서 카드 하나를 휴지통으로 보내 캔버스 카드의 결과가 8개가 됐는데, 카드 배지는 ▤ 9, '생성 결과' 창 제목은 '9개 · 8개 표시'.
2. 카드 생성물 붙이기 창의 '카드 생성물 담기'(와 '카드 생성물 복구') 목록에서 이미지 썸네일은 보이는데 영상·음성은 검은 칸.

## 원인 (확인한 것)

- 1: 휴지통 결과는 카드 기록(`genIds`)에서 지우지 않는다(복구 후보로 남김). 격자는 `deleted` 를 빼고 그리지만(`SceneBoard.tsx` `variantView` `shown`), 수는 기록 전체를 센다 — 창 제목 `total: ids.length`, 생성 카드 배지 `GenerationCard.tsx` `variantIds(card).length`, Comfy 카드 배지 `ComfyCard.tsx`, 리스트 카드 생성물 줄 `ListCard.tsx`·GPU 판 `boardCanvasDraw.ts`.
- 2: `media.ts` `mediaThumbUrl` 이 음성이면 그림을 주지 않고(null), 아직 받지 않은 영상(원본이 인터넷 주소)에 포스터가 없으면 null 이다 → `SceneRecoveryPanel` 이 빈 칸을 그린다.

## 고침 (Jay 시안 승인 "이대로 만들어" · "이번 배포에 넣기")

1. `scenes.ts` 에 `shownVariantCount(card, genData)` — 휴지통(`deleted`) 결과를 뺀 수. 자료가 아직 안 온 id 는 센다(곧 보일 것, 격자 선택 규칙과 같음). 창 제목·생성 카드 배지·Comfy 카드 배지·리스트 줄(DOM·GPU)이 같이 쓴다. 카드 기록은 그대로(복구 후보).
2. '카드 생성물 담기·복구' 목록 썸네일(`SceneRecoveryPanel` `RecoveryThumb`):
   - 이미지 = 지금 그대로.
   - 영상 = 첫 장면(그림 주소가 있을 때) + 가운데 재생 표시(앱의 `play-badge`) + 오른쪽 아래 길이.
   - 영상인데 그림이 없음 = 검은 칸 대신 재생 표시 + '영상' 글자 + 길이.
   - 음성 = 음표 + 파형 막대 + 길이.
   - 길이는 기존 칩과 같은 값(`generationListMeta` `duration`), 없으면 생략.

## Codex 차이 리뷰 1차 — CHANGES 중간 3 (`01a1eda5-560e-7690-81f1-2b06357b615b`, gpt-6.1-sol·read-only) → 모두 고침

1. GPU 판 배지 수(`SceneBoard.tsx` `buildGpuScene` 의 `variantCount`)가 옛 계산 그대로 → 같은 함수로.
2. 캔버스 도구 줄 결과 수(`typeCount`)가 휴지통 결과를 셈 → 뺀다.
3. 대표(`genId`)가 휴지통에 가고 결과가 하나 남으면 배지가 사라져, 남은 것을 대표로 고를 결과 창에 들어갈 길이 없어짐 → `scenes.ts` `variantBadgeCount`: 2개 이상이면 그 수, 대표가 휴지통이고 1개 남았으면 1, 그 밖은 0(배지 없음). 생성 카드(DOM)·GPU 판이 같이 쓰고 GPU 판 배지 조건을 `n > 0` 으로(시험 기본값 0).

## 2차 — Jay "휴지통에 있는데 아직 ▤ 9·'9개 · 8개 표시'"(11-18 17시, dev eee661c2 위)

- 원인(코드로 확인): 휴지통으로 보낸 결과는 서버 묶음 조회에서 `missing`(404/410)으로 온다. 그러면 `useSceneGenData.ts` 가 그 id 를 자료에서 **지우고**(`delete next[r.id]`) `missingIds` 에 넣는다. 1차의 `shownVariantCount` 는 자료의 `deleted` 만 보고 '자료가 없는 id = 곧 보일 것'으로 세었다. 그래서 휴지통 결과를 9번째로 셌다. 1차 시험은 자료에 `deleted: true` 를 넣은 경우만 봤다.
- 고침: `shownVariantCount`·`variantBadgeCount` 에 '서버에 없음' 판정(`isGone`)을 **필수**로 받는다(빠뜨리면 빌드가 막는다). 휴지통 결과 = 자료의 `deleted` 이거나 `missingIds` 에 있는 것. 부르는 곳은 모두 같은 판정을 넘긴다.
  - `SceneBoard`: 결과 창 제목·도구 줄 수(`typeCount`)·생성 카드 배지(DOM 두 곳·GPU 판).
  - `ListCard`: 새 속성 `missingIds`(SceneBoard 가 편집·읽기 두 곳에서 넘김).
  - `ComfyCard`: `graph.missingIds`.
  - `boardCanvasDraw`: 기존 `ctx.genMissing`.
  - (고치다 찾음) `RenderCard` 생성물 줄의 ▤ 수는 1차에서도 빠져 기록 전체(`variantIds(gc).length`)를 셌다 → 새 속성 `missingIds` 로 같은 함수.
- 복구하면 서버가 다시 돌려주고 `missingIds` 에서 빠지므로 수가 되돌아온다(기록 genIds 는 그대로).
- 검증(11-18):

  - 시험 기록: 프런트 전체 `f5f5653e`(584파일 7,893 통과) · 경계 `278c860b` · 빌드 `4d9ade2e` · 코드 지도 `edbab53c` 통과.
  - 첫 프런트 전체 기록 `ab9270fd` 는 exit 1 이었다. 실패는 `mcpConnection.test.tsx` 의 'cards 실패는 get_plan에 안전하게 보이고 재제출하지 않는다' 1건으로, 이번 변경과 무관한 MCP 시험이다. 같은 트리에서 직접 전체 실행·혼자 3회·재기록 모두 통과했다 → 전체를 함께 돌릴 때만 나는 흔들림. 원인은 미확인.
