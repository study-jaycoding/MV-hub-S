# 캔버스 — 붙여넣기·새 노드가 마우스보다 위에 놓이던 것 (2026-11-10)

owner: Claude(구현) · reviewer: Codex(묶음 독립 리뷰 `01a1c3a6…`) · status: 완료 · touched_paths: 아래 계약 · updated: 2026-11-10
위 속성의 `active`는 이 작업의 진행 기록이라는 문서 위상이며, 구현 완료·검토 완료·배포 승인을 뜻하지 않는다.

## 요청

## 원인 (격리 실측 — dev `9c44d59c` 고정 사본, 빈 DB 격리 허브, 헤드리스 크롬 2560×1400)

- `.scene-board` 는 `overflow: hidden` 이라 손으로는 안 굴러가지만, 브라우저는 초점·캐럿을 보이려고 스스로 스크롤한다.
  캔버스 바닥판(`.scene-canvas::before`, 120000px)과 격자 층(`inset: -64px`) 때문에 스크롤 범위가 아래·오른쪽으로 약 60000px 이다.
- 화면 아래쪽 글 카드에서 줄을 치자 보드가 121px 스크롤됐고, Esc·화면 이동·휠 줌 뒤에도 남았다(되돌리는 코드 없음).
- `toCanvas`(`lib/useSceneViewport.ts`)는 보드 스크롤을 빼지 않아 붙여넣기·Tab 노드 창이 정확히 121px 위에 놓였다(편집 전 0px).
  카드 끌기(끈 거리로 계산)·범위 선택(`computeMarquee` 가 보정)은 어긋나지 않았다.
- 노드 수에 따른 지연은 원인이 아니다: 끊김이 생겨도 잡은 자리는 유지되고 손을 멈추면 16ms 안에 제자리였다(글 카드 500장, CPU 4배 흉내 포함).

## 결정

- 보드가 스크롤되면 그 양을 카메라 팬으로 옮기고 스크롤은 0 으로 되돌린다. 보이는 자리는 브라우저가 옮긴 그대로(캐럿 보이기 유지)이고 좌표는 늘 맞다.
- 기각: `overflow: clip`·스크롤만 0 으로 되돌리기 — 어긋남은 없어지지만 화면 끝에서 칠 때 캐럿이 보드 밖으로 가려졌다(주입 실측).
- 이번에 안 하는 것: 붙여넣기 중심 어림(`pasteSceneClipboard` 의 `h ?? 130`)이 머리·자동 높이 카드에서 조금 위로 붙는 것 — 코드로만 확인, 별도.
