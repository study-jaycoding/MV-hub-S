# 서버 이사 시험 — 보존 폴더 정리 경쟁 시험이 전체 게이트에서만 흔들림 (2026-11-16)

owner: Claude · reviewer: Codex · status: 완료(dev 커밋, Codex 리뷰 PASS) · touched_paths: 아래 계약 · updated: 2026-11-16

> 배포 후보(설정 창 추가, 후보 사본 `0c310641`)의 전체 게이트에서 `backend/tests/test_server_move.py::test_archive_cleanup_race_preserves_original_failure_and_foreign_file` 하나만 실패(10,927 통과). 이 후보 추가분은 백엔드를 바꾸지 않았다(백엔드 트리 같음).

## 확인한 것

- 실패: 시험이 끼운 가짜 `Path.rmdir`(raced_rmdir)이 보존 폴더(`_before_move_*`)로 한 번도 불리지 않음(`retained == []`). 안쪽 롤백 시험의 출력은 정상(롤백 완료, '되돌리기 실패'·'보존 폴더 정리 실패' 없음) → `tools/server_move.py:912` 의 `archive_dir.is_dir() and not any(archive_dir.iterdir())` 가 거짓이라 `rmdir` 을 건너뜀.
- 단독 3/3, 파일 42/42, 60회 반복, 게이트 순서의 `test_s*` 28파일 묶음 — 모두 재현 안 됨. `pathlib` 을 다시 불러오는 시험 없음.
- Codex 읽기 전용 진단 `01a1e3dd` DIAG TEST: 가장 유력 = 전체 게이트 중 출처 모를 외부 파일이 보존 폴더에 먼저 생김(같은 시험 파일에 2026-10-02 전체 게이트에서 제품 이름을 대문자로 바꾸고 `.tmp` 를 붙인 외부 파일 기록 — `_left` 주석). `_rollback` 은 원래 DB 가 돌아왔는지만 보므로 다른 파일이 있어도 True, 그러면 정리를 건너뛴다. **제품 동작은 안전**(비어 있지 않으면 지우지 않고 남긴다). 다음 후보 = 일시 접근 오류로 `is_dir()` 거짓(3.14 는 접근 불가도 False) — 증거 부족. SQLite 늦은 GC·환경 누수·패치 우회는 낮음.
- 고침(Codex 제안): 이 경쟁 시험에서만, 롤백 뒤 보존 폴더의 사전 검사(`is_dir`·`iterdir`)를 '빈 폴더'로 고정 — 이 시험이 보려는 것은 '빈 폴더 확인 뒤 정리 직전 경쟁'이다. 원래 실패 보존·외부 파일 보존·DB 복구 확인은 그대로, 별도의 WAL 롤백 시험도 그대로. 제품에 강제 삭제·재시도를 넣지 않는다.

## 구현·검증

- 고침: 경쟁 시험에 `Path.iterdir`·`Path.is_dir` 를 보존 폴더(`_before_move_*`)에서만 '빈 폴더'로 답하게 끼움(raced_rmdir 와 같은 판정 함수 `is_archive`). 그 밖의 경로는 원래 동작.
- Codex 리뷰(`01a1e3dd` resume, read-only): **PASS** — 패치는 보존 폴더 경로에만 걸려 롤백 실패·정리 오류 보고·원래 실패 다시 던지기를 가리지 않음, `is_dir(**kwargs)` 는 3.14 서명과 맞음. 낮음 1(주석이 외부 파일을 원인으로 '확정'한 표현) → '유력한 원인'으로 고침.
- 시험 기록(주석 고친 뒤): file `a78e514d`(파일 42 통과) · stray `30fa2273`(고치기 전 판 = `e8299bf9~1`). 처음 기록: file `bb1eba84` · stray `f57b83a8` — 스크래치 `servermove_proof/test_stray_proof.py`: 롤백이 보존 폴더에서 DB 를 꺼낸 직후 실제 외부 파일 `CONTENT_HUB.DB-JOURNAL.tmp` 를 심으면 HEAD 시험은 게이트와 같은 실패(정리를 건너뜀)이고 제품은 폴더·파일을 남김, 고친 시험은 통과.
