# 캔버스 폴더 창에서 생성물을 끌어 씬에 놓기 — 2026-10-22 (Jay 요청)

owner: Claude 총괄 · reviewer: Codex(설계 검토 완료·구현 검토 예정) · status: 검토 요청 · touched_paths: 아래 계약 · updated: 2026-10-22

Jay: "캔버스에서 폴더를 열고 생성물을 바로 레퍼런스로 사용하려고 하는데 드래그로 끌어오기가 안 되네. 끌어와서 바로 캔버스 씬에 불러와서 사용 가능하게 해서 생성에도 문제가 없는지 검토해 보자." · "드래프트로 보니까 이미 이렇게(생성물 카드를 캔버스에 두고 새 카드에 연결) 가져와서 사용은 되게 되어 있네. 참고해라."

지금(코드 확인): 캔버스 놓기(`lib/useSceneClipboardDrop`)는 에셋·파일만 받는다 — 생성물 카드 끌기(`DRAG_TYPES.generation`)는 받지 않는다. 폴더 창이 뜨면 바깥 막(`.folder-peek-catcher`, 화면 전체)이 보드를 덮고 뒤 화면(`.body`)은 `inert` 라 놓기 자체가 닿지 않는다. 생성물 카드 모양은 MCP '캔버스에 추가'(`lib/mcpCanvasTasks`)의 `{kind:"generation", genId, genIds:[id], prompt, status}` — Draft 그림의 왼쪽 카드와 같다. 연결하면 `features/canvas/references` 가 genData 로 레퍼런스를 만든다.

격리 실측(10-22, 실제 크롬)에서 찾은 것: 놓은 카드의 첫 Ctrl+Z 가 헛돌았다(두 번째에 사라짐). Tab→N 으로 만든 새 카드도 같다 — 이번 수정 전부터. 원인 = 프롬프트 칸(`SpotlightPrompt`)이 카드를 고를 때 카드 프롬프트를 되살리며 '되살린 값'을 **원문**(평문·빈 글자)으로 기억하는데 편집기 저장 형식은 조각 목록 JSON(`[]`·`[{"t":"text",…}]`)이라, 되살리기를 편집으로 오인해 카드에 다시 저장했다(되돌리기 기록 1개 추가). 저장본 비교로 확인: 첫 Ctrl+Z 는 그 프롬프트 형식만 되돌렸다.

Codex 설계 검토(읽기 전용, gpt-6-astra/high, 세션 `01a16155-8091-79f3-ad33-96627874918d`) 정정: `pasteNodes` 는 결과(genId)를 지워 빈 카드로 만든다 → 새 편집 명령으로 · `.body` inert 도 끄는 동안 풀되 사이드바·상단바로는 놓기가 닿지 않게 · 카드 본문과 ⠿ 손잡이 둘 다 끌기 시작을 알림 · 생성물을 실제로 조회해 상태를 정하고(nsfw→failed), 조회 사이 씬·보드가 바뀌면 넣지 않음 · genData 를 미리 채워 '레퍼런스가 빠진 생성' 틈을 없앰 · 넣기에 성공하면 끌기가 끝난 뒤 폴더 창을 닫음.
