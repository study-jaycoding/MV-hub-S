# 편집 탭 — Alt+휠 확대의 기준 자리를 기억하기 · 눈금자의 작은 눈금(다빈치처럼) — 2026-10-26 (Jay 지시)

owner: Claude · reviewer: (Jay 가 검토를 지시할 때 묶음으로 — 화면 조작 둘) · status: 완료(dev 커밋 · Jay 화면 확인 남음) · touched_paths: 아래 계약 · updated: 2026-10-26

한 것: ① `EditTimeline` 의 확대 맞춤이 기준(time·offset·맞춘 scroll)을 `anchor` 에 기억 — 재생헤드가 같고 스크롤이 맞춘 값 그대로면 기억한 offset, 아니면 새로 잰다
(맞춘 뒤 브라우저가 자른 scrollLeft 를 그대로 적는다). ② 눈금자: `--tick-minor`·`--tick-mid` 를 확대에 맞춰 주고 `.ed-ruler` 의 그라디언트 두 겹으로 그린다 ·
큰 눈금은 눈금자 높이 전체(`#85858b`). 내장 브라우저에 같은 CSS 의 미리보기 페이지(스크래치 `blackcheck/ruler.html`)로 20·45·60·120·400px/초를 그려 봤다
(처음 색이 다빈치보다 흐려 한 단계 밝힘). 시험 `editTimelineWheel`: 줄여 0 에 걸린 뒤 키우면 60 으로(옛 코드는 약 62.4) · 사용자가 넘긴 뒤엔 그 자리로 ·
눈금 간격 10/50px(20px/초)·400/24·200px(400px/초).
시험 기록: 편집 탭 전부(792)·`tsc -b` 는 **HEAD 사본 + 내 세 파일**로(스크래치 `vitest-head-plus.ps1`·`tsc-head-plus.ps1`) — 같은 폴더의 클린 피드 세션이
`useEditFollow` 등을 고치는 중이라 작업 트리 전체로는 `editRound7` 의 '한 트랙만 보기: 실제 길이가 0초인 영상' 하나와 `CleanFeedApp.tsx` 타입이 그쪽 변경으로
실패했다(그 세션에 알림). 다빈치에서 직접 확인하지는 않았다(Jay 설명·그림대로).

Jay(다빈치 눈금자 그림 · 우리 눈금자 그림): "alt 휠로타임라인 확대 축소를 하고 있는데 다빈치에서는 원래 앵커 위치를 기억하고 있어서 확대 했을떄 그자리로
가는데 우리 프로그램은 그 기억이 없는지 위치가 바뀐다. 다빈치랑 비교해서 어떻게 다른지 파악하고 다빈치처럼 작동되게 해라. 이미지1번이 다빈치 타임라인쪽
표기인데 우리 프로그램(이미지2)에는 저런게 없다. 다빈치처럼 표시되게 하자"

다른 점(코드 확인): 확대·축소 때마다 재생헤드가 지금 화면 어디 있는지를 **새로 잰다**(`EditTimeline` 의 layout effect — `offset = time × 옛 확대 − scrollLeft`).
줄이다 스크롤이 0(또는 맨 끝)에 걸려 재생헤드가 화면에서 밀려나면 그 밀려난 자리가 새 기준이 되어, 다시 키워도 처음 자리로 돌아오지 않는다. 다빈치는 처음 자리를
기억한다(Jay 설명 — 다빈치 실측은 안 했다). 눈금자: 다빈치는 큰 눈금(시각 글자) 사이에 위에서 늘어뜨린 작은 눈금·중간 눈금이 있고 큰 눈금은 눈금자 높이 전체다.
우리는 큰 눈금(아래 12px)과 글자뿐이다.
