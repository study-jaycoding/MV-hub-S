# 편집 탭 — 재생헤드의 선(눈금자 밑)을 잡아도 끌린다(다빈치처럼) — 2026-10-26 (Jay 지시)

owner: Claude · reviewer: (Jay 가 검토를 지시할 때 묶음으로 — 조작 한 군데) · status: 완료(dev 커밋 · Jay 화면 확인 남음) · touched_paths: 아래 계약 · updated: 2026-10-26

한 것: 재생헤드 안에 선을 잡는 자리 `.ed-phead-grab`(눈금자 28px 밑부터 끝까지·선 둘레 9px·커서 ↔ — 재생헤드는 `pointer-events: none` 그대로라 자식만 받는다)
· `EditTimeline` 의 `grabHead`(누를 때 선 가운데와의 틈을 적고 움직일 때 그만큼 빼서 `onSeek` · 눈금자 훑기와 같은 끝내기·`scrubbing`) · 더블클릭은 폴더 창을
열지 않는다(`openCutAt` 이 거른다). 시험 `editPlayheadTrack`: 누르기만 = 그대로 · 40px 끌기 = 2초 · 되돌아가기 · 왼쪽 단추가 떼어진 움직임 = 끝 · 밑의 클립 안 고름.
타입 검사는 HEAD 사본 + 내 세 파일로 했다(같은 폴더의 클린 피드 세션이 `CleanFeedApp.tsx` 등을 고치는 중이라 작업 트리 전체의 `tsc -b` 는 그쪽 미완성 변경으로 실패 —
스크래치 `tsc-head-plus.ps1`). 다빈치에서 직접 확인하지는 않았다(Jay 의 설명대로).

Jay(재생헤드 그림): "여기서 앵커부분의 헤드 부분을 잡아야 이동이 가능한데 다빈치에서는 그밑에 라인부분을 잡고도 이동이 가능하다. 다빈치에서 조작되는거
확인해서 우리도 그것처럼 움직이게 하자"

지금(코드 확인): 재생헤드 `.ed-phead` 는 `pointer-events: none` — 머리(오각형)를 누르는 것은 실은 그 밑의 눈금자(`.ed-ruler` 의 `scrub`)가 받는다.
선은 누름이 그대로 밑의 클립·빈 곳으로 간다.
