# 캔버스 버벅임 — 원인 실측과 ④-1 스크롤 칸 정리 (2026-09-29)

> 요청: Jay "캔버스에 노드가 많으면 버벅인다" → 진단 → "코덱스랑 같이 ④부터 검토 진행" → "진행".
> 참여: Claude(측정·설계·구현) · Codex(적대적 검토 동의, 코드 리뷰 승인 — 주석 1곳 보정 반영).

## 결론

- 많이 축소해 카드가 많이 보일 때의 끊김은 React 다시 그리기가 주원인이 아니었다. 주원인은 **크롬 합성 레이어가 수백 개로 불어난 것**이다.
  - 카드 안 스크롤 칸(`overflow:auto`)은 넘치면 합성 레이어가 된다.
  - 그 위에 겹쳐 그려지는 포트·크기 손잡이·번호 배지·카드까지 "Overlap" 레이어가 된다.
  - 화면을 움직일 때마다 드는 레이어 재구성(Layerize) 비용이 이 수만큼 커진다.
- **④-1(이번 변경)**: 카드 안 스크롤 칸 9종은 평소 `overflow:hidden` 이고, 마우스를 올리거나 키보드 포커스가 들어간 카드만 `auto` 다. 막대는 숨긴다.
- 남은 것
  - 12% 화면 이동에 남은 끊김의 주 후보는 ①이다. viewRect 를 0.5px 문턱으로 rAF 마다 갱신해서, 걸음마다 카드 전체가 다시 그려진다(Codex).
  - ②(확대 % 저장소)는 휠 확대 때만 관여한다.
  - ④-2(켠 뒤에도 남는 겹침 레이어)는 시험 뒤 기각했다(아래 남은 일).

## 측정 조건

- 씬은 Jay 의 실제 씬 `뻘뻘뻘_프롤로그_part2`(카드 412장)다. 격리 서버 S, 창 1680×1000 에서 쟀다.
- 그림: 격리 복사본은 프로젝트 폴더 경로를 비워 썸네일이 모두 404 다. 합성 JPG 70장을 넣고 씬 사본의 토큰을 바꿨다([TESTING.md](../TESTING.md) 격리 브라우저 실측 요령 ⑤).
- 브라우저: 헤드리스 크롬 153 과 창 있는 크롬을 둘 다 썼다. **둘 다 실제 GPU(ANGLE D3D11)** 를 쓴다. 절대값보다 같은 실행 안의 전후 비교를 본다.
- 도구: 크롬 trace 의 메인 스레드 자기 시간, `LayerTree.compositingReasons`, rAF 프레임 간격, React 커밋 수. 스크립트는 저장소에 두지 않았다.

## 진단 근거 (12% 배율, 카드 412장 모두 마운트)

| 항목 | 값 |
|---|---|
| 합성 레이어 | 357 (Overlap 313 · OverflowScrolling 35) |
| 캔버스 transform 만 바꾼 20걸음(React 0·격자·미니맵 끔) | 메인 1,422ms 중 Layerize 자기 시간 1,208ms(17회) |
| 카드 안 스크롤 칸 | 102개(넘치는 것 71). DPR 1.5 에선 넘치는 칸이 전부 합성되어 레이어 386 |
| ①② 완벽 가정(React 0)만 | 화면 이동 50ms 초과 프레임 33 → 30. 휠은 개선 없음 |

정정 두 가지: 앞서 한 두 추정은 틀렸다.
- "축소 휠의 나머지 시간은 래스터"라고 했지만, 실측해 보니 메인 스레드 Layerize 였다.
- "헤드리스는 GPU 없음"이라고 했지만, 그래픽 정보를 찍어 보니 ANGLE D3D11 을 쓰고 있었다.

## ④-1 결정

- `scene.css` 의 "카드 안 스크롤 칸" 규칙 한 쌍이 스크롤 여부를 혼자 정한다. 9개 기본 규칙의 `overflow(-y): auto` 는 지웠다.
- 대상 9종
  - 여러 장 레퍼런스 본문 `.scene-card-body:not(.single)`
  - 텍스트 보기, 모델 노드 본문
  - 리스트 행 `.scene-listrows`(리스트·렌더 카드) — Codex 가 짚어서 넣었다
  - 리스트 썸네일 격자
  - 뷰 카드 텍스트
  - Comfy 본문·오류·출력 텍스트
- 제외
  - 한 장 레퍼런스(원래 `overflow:visible`)
  - 편집 textarea(텍스트·세트 태그)
  - 모달·팝업·메뉴
- 막대 숨김(`scrollbar-width:none`)을 고른 이유
  - 켤 때 막대가 생기면 글 폭이 480 → 470 으로 줄어 다시 줄바꿈된다.
  - 막대 자리를 늘 비워 두는 방법(gutter)은 폭 160~216 인 작은 리스트의 썸네일을 3열에서 2열로 떨어뜨린다(계산값).
  - 크롬 121 미만에서는 막대가 다시 보이고 옛날처럼 폭이 바뀐다. 기능 문제는 없다.
- 휠 핸들러(`useSceneViewport`)는 고치지 않았다. 이벤트가 일어난 순간의 computed overflow 로 "칸 스크롤이냐 확대냐"를 가르기 때문이다.

## 검증

- `npm run build` 통과. 프런트 전체 시험 202파일 2,120건 통과.
- 기능 점검: 헤드리스와 창 있는 크롬의 결과가 같았다. 순서 끌기는 옛 동작(CSS 로 되살림)과 같은 결과였다.
  - 평소 hidden/폭 480 → 호버 auto/폭 480. 재줄바꿈이 없다.
  - 호버한 글 위 휠은 100px 스크롤되고 배율은 그대로다. 작은 휠(4)은 4px 스크롤된다. 빈 곳 휠은 확대된다.
  - 떠났다 돌아와도 scrollTop 40 이 유지된다.
  - 카드 안 단추에 포커스가 있으면 마우스가 없어도 auto, blur 하면 hidden 이다.
  - 더블클릭하면 편집으로 바뀌고, 끝나면 보기로 돌아온다.
  - 한 장 레퍼런스는 호버해도 visible 이다.
  - 카드 위에서 시작한 가운데 버튼 이동은 기대한 만큼 움직인다.
  - 리스트 순서 끌기(가로 썸네일·세로 행 손잡이)가 된다.
  - 카드를 끌어 놓은 직후 마우스를 움직이지 않고 휠을 굴려도 글이 스크롤된다.
- 성능: 12% 배율, 옛/새를 같은 실행에서 두 번씩 번갈아 쟀다. 칸마다 50ms 초과 프레임 / 전체다.

| 동작 | 헤드리스 옛 | 헤드리스 새 | 창 크롬 옛 | 창 크롬 새 |
|---|---|---|---|---|
| 화면 이동 30걸음 | 31/57 · 32/51 | 31/53 · 30/53 | 30/55 · 33/52 | 30/57 · 30/54 |
| 휠 확대 12번 | 10/51 · 4/62 | 2/68 · 1/72 | 10/53 · 5/63 | 5/61 · 1/70 |
| 휠 축소 12번 | 10/52 · 6/59 | 5/64 · 2/69 | 10/52 · 10/56 | 10/56 · 3/70 |

- 화면 이동의 메인 스레드 시간: 약 35% 줄었다(3,691·4,298 → 2,563·2,460ms).
- 레이어
  - 88%: 126 → 56
  - 12%: 242 → 81
  - DPR 1.5(CSS 주입 시험): 271 → 61
- 화면 이동의 끊긴 프레임 수가 줄지 않은 것은 ④-1 실패가 아니다(Codex). 걸음마다 남은 React 커밋(①)과 남은 합성 비용 탓이다. 주입 시험 때는 이동도 31·33 → 18·7 로 줄었다. 실행 간 편차가 크다.

1. **①** viewRect 문턱(`901feef7`).
   - 첫 측정만 즉시 갱신한다.
   - 팬·줌·창 크기 변화는 네 변 중 하나가 `SCENE_CULL_REFRESH_DISTANCE`(= `SCENE_CULL_MARGIN / 3` = 500 canvas px) 넘게 움직였을 때만 갱신한다.
   - "크기가 바뀌면 즉시 갱신"은 휠 한 칸마다 다시 그리게 되어 뺐다.
   - 가장자리에서 카드가 늦게 나타나 보이면 문턱을 250 으로 줄인다.
2. **②** 확대 % 는 `sceneZoomStore` — 툴바 % 글자만 다시 그린다(`901feef7`).
3. **⑤** 격자·미니맵.
   - 격자는 보드 배경 대신 `.scene-grid` 층이다. 한 칸 안에서만 transform 으로 밀고, 미는 양은 화면 픽셀로 반올림한다(소수 픽셀이면 GPU 보간으로 점이 번졌다).
   - 옛 보드 배경과 같은 화면을 찍어 픽셀을 비교했다. 점 위치는 같고, 0.5px 이내 안티앨리어싱 차이만 있다.
   - 들어오는 카메라 확대값은 `clampSceneZoom` 으로 5~250% 에 맞춘다. 씬 파일의 z:3·z:0 이 64px 여백 가정을 깨고 NaN 을 냈다(Codex).
   - 미니맵은 바뀐 값만 쓰고, 뷰 박스를 transform 으로 옮긴다.
4. **③** 25% 이하 단순화(보드 `data-lod-low`).
   - 포트·손잡이·제목줄·번호·결과 수 배지·복사 단추·연결선 끝 점을 숨긴다.
   - 마우스·선택·포커스 카드는 복구하고, 연결 중·자르기 중에는 전부 보인다.
   - 끝 점은 선택하면 보인다. 호버로는 안 돌아온다 — 시안과 같다(Codex 동의).
5. 넘침 아래 흐림(Jay 시안 C) — 스크롤 타임라인 CSS 라 자바스크립트로 넘침을 재지 않는다.
   - 흐림은 칸마다 합성 레이어를 늘렸다(41% 레이어 97 → 184, 메인 스레드 +10%). 고정 mask 도 레이어는 같았다.
   - 그래서 툴바 50% 미만(`data-text-far`, 글을 못 읽는 배율)에서는 끈다.
6. 재측정(창 있는 GPU 크롬 2560×1400, 카드 412장, 가운데 버튼 60걸음, ①② 뒤 → 이번 셋 뒤)

   - 40%: Paint 139~146 → 10~12ms, 메인 1,443~1,505 → 1,274~1,341ms
   - 25% 의 Paint(약 130ms/60걸음)는 그대로다. 프레임당 1ms 미만이라 쫓지 않았다(원인 미확인).
