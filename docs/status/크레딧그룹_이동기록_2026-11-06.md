# 크레딧 그룹 이동을 '어디서 어디로'까지 감사 기록에 (2026-11-06)

Jay 11-06: 그룹 설정 저장 감사 기록(`workspace.credit_plan_changed`)에 "누구의 그룹이 언제 바뀌었다"만 남고 어느 그룹에서 어느 그룹으로 갔는지는 없다 → "기록하게".

지금(코드 확인): `_record_settings_edit`(`backend/app/repo/manage_credit_plan.py`)가 바뀐 칸 이름만 `fields` 에 적는다(`members.account:<지문>.group_id`). 값은 없다. 개발 DB 사본(10-31)에 설정 저장 20건·그룹 바뀜 13건이 있다.

바꾸는 것: 같은 감사 줄의 `details` 에 `group_moves` 목록을 더한다 — 한 줄 = `account:<지문>: <전 그룹 id> → <후 그룹 id>`(앱이 만든 32자리 id), 그룹이 없으면 `없음`. 정렬해 50줄까지, 넘치면 `group_moves_complete=false`.
- 감사 기록 규칙(`repo/event_journal.py` — 한 단계 값만·목록 50개·글자 200자·이메일/주소 지움)을 그대로 따른다.
- 옛 형식 그룹 id(사용자 글이 들 수 있음)는 `legacy`, 이메일이 아닌 배정 키는 `account:?` — 기존 시험 `test_legacy_identifiers_are_not_copied_to_journal_paths` 의 '원문 없음' 조건 유지.
- **그룹 이름은 남기지 않는다** — 감사 기록엔 사람이 쓴 글(그룹 이름·메모·색)을 남기지 않는 규칙(기존 시험 `test_credit_http_conflict_paths_are_private_and_resource_scoped` 가 고정)이 있어서다. 이름은 볼 때 그룹 표(`workspace_credit_group`)에서 id 로 푼다. 나중에 지운 그룹은 id 만 남는다.
- 읽는 곳(충돌 설명 `_edit_conflict_detail`·서버 관리 창 `activity.py`)은 `fields` 만 써서 영향 없다. 표·칸 변경 없음.
- 몫·색·한도만 바뀐 저장은 `group_moves` 가 빈 목록.

적용 = 서버 업데이트(그룹 설정 저장은 공유 서버가 한다). 옛 기록은 그대로(값이 없던 줄은 채우지 않는다).
