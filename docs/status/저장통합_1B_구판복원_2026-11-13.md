1. L은 v1/v2 서버 세트 복원 두 입구, `/latest` 단일 content 폴백, 단일 `.db` import의 후속 보호를 구현한다. P2 최종 커밋 위에서 시작하며 P2의 전송 규칙과 미커밋 작업을 섞지 않는다. `backup.CAPTURE_VERSION=2`, `backup_manifest.VERSION=2`, 구판 성공 응답 `{"ok": true, "relogin_required": true}`를 유지한다. v3 present/absent와 수신 검증의 기존 의미를 유지한다.

2. 모든 구판 복원은 새 `new_secret`과 `restore_id`를 생성한다. content 설치·`init_db` 후 `_post_install_security_init`의 같은 SQLite 거래에서 전송 비밀 제거, DB 키·비밀번호 표식·공유 복원 세대 회전, 복원 content의 전체 MCP 자격 회수, 대상 폴더 확인 표식의 새 ID·빈 confirmed 설정을 수행한다. 어느 단계라도 실패하면 성공을 반환하지 않고 보상 롤백한다. 환경 키 우선 규칙을 유지하며 비밀 원문을 기록·응답에 넣지 않는다.

3. 폴더 표식은 실제 소비 키에 쓴다. AUTH off 로그인 상태에서는 접수 포인터 email, 로그아웃과 AUTH on에서는 빈 email을 사용한다. 구판 복원이 JSON·owner를 변경하거나 옛 confirmed를 승계하지 않는다. 확인 전 이름 참조는 기존 소비자가 차단하고, 현재 복원 ID와 실제 경로를 확인한 명시 요청 뒤에만 허용한다. 고정 내장 경로의 기존 예외는 유지한다.

4. Agent 채택 대상은 이 로컬 허브에서 접수한 한 계정이다. AUTH off는 접수 포인터 email, AUTH on 로컬 import는 인증된 요청 관리자 email을 별도로 고정한다. 공유 팀 서버 본체와 계정 없는 import는 Agent 채택을 하지 않는다. Agent 기능의 일시적 비활성만으로 이미 존재하는 해당 계정 기록을 버리지 않는다. 폴더용 email과 Agent용 email을 혼용하지 않으며, 다른 계정이나 옛 hub 파일을 디렉터리 검색으로 추측 채택하지 않는다.

5. 접수에는 content 경로, 두 AUTH 설정, 명시 DB 설정, 포인터 email·uid, Agent 대상 email, 환경 키 지문, Agent 디렉터리, 폴더 JSON 경로, 로컬/공유 서버 구분과 DB·계정 세대를 고정한다. import는 첫 await 전에 DB 연결 없이 이 값을 잡고, 잠금이 즉시 확보되지 않거나 유지보수 중이면 503으로 종료한다. 옛 DB 키·Identity 조회는 non-abandon 작업 스레드에서 하고 앞뒤 접수 값을 비교한다. 서버 복원도 다운로드 전 대상 신원을 고정한다. 설정·계정·세대·신원이 달라지면 파일 교체 전 409로 거절한다.

6. Agent 대상 계정이 있으면 새 키와 환경 키 우선 규칙으로 최종 Identity를 계산한다. 옛 Identity가 있으면 함께 guard에 포함한다. 파일이 아직 없더라도 계산된 신원은 guard 대상이다. 기존 `restore_guard`로 실행·발급 중이면 상태 변경 없이 409, 실제 연결 배수 실패면 503으로 종료한다. 잠금 순서는 Agent admission 닫기·배수 → account transition → content maintenance이며, 구판은 JSON을 쓰지 않으므로 JSON 잠금을 추가하지 않는다. guard 획득 뒤 대상 재확인, maintenance 안의 재확인은 기존 `flush_pool`보다 먼저 수행한다.

7. 옛 키나 Agent 파일의 확인된 부재만 채택 생략으로 처리한다. 키 조회·파일 접근 실패, 일반 파일이 아닌 대상, 손상된 Agent DB는 전체 복원을 실패시킨다. 구판 역할 부재를 v3 absent로 취급하여 최종 파일을 삭제하지 않는다. 옛 경로와 최종 경로가 다르면서 최종 경로가 이미 존재하면 409로 거절한다. Agent 경로가 content·trash 등 다른 역할과 충돌해도 거절한다. 채택 생략 시 빈 Agent DB를 만들지 않는다.

8. 채택할 Agent는 배수 후 WAL을 정리하고 독립 `.bak`을 확보한다. WAL에만 있던 확정 기록을 포함한 상태가 보존 기준이다. 체크포인트 이전 주 DB 파일과의 바이트 동일성을 약속하지 않는다. `.bak`에서 최종 경로와 같은 볼륨의 준비 사본을 만들고 크기·SHA-256을 대조한 뒤 기존 Agent 구조 검증을 수행한다. DB 키·고정 키 모두 검증한 준비 사본을 교체하고 `adopt_restored`를 호출한다. 다른 경로의 옛 Agent DB는 채택하지 않고 보존하며, 같은 경로에서는 `.bak`이 채택 전 원본이다.

9. Agent 채택은 content·trash 설치와 같은 보상 롤백 경계 안에서 수행한다. 대화는 `restored_from=restore_id`, `resumable=0`으로 바꾸고 CLI 실행·삭제 식별자와 연결 자격을 제거한다. 원문 사건·plan binding은 읽기용으로 보존한다. 이어 쓰기·포크·기존 계획 실행·견적을 기존 서버 검사가 차단하며, 참고자료로 새 대화를 만드는 기존 기능은 유지한다. 이 기능 때문에 외부 CLI를 실행하거나 기존 세션 파일을 삭제하지 않는다.

10. content·trash·Agent 교체, 스키마 초기화, 보안 초기화, Agent 채택, 계정 해제 실패는 기존 존재 상태와 보존 스냅샷으로 복구한다. 새로 만든 Agent 경로와 이번 작업의 준비 파일은 정리하고 기존 JSON·manage는 변경하지 않는다. 보존 단계 실패에는 아직 교체하지 않은 파일을 불필요하게 되돌리지 않는다. 롤백 자체가 실패하면 500과 수동 복구 필요를 보고하고 `.bak`을 남긴다. 이는 기존 예외 보상이며 프로세스 강제 종료·정전에도 다중 파일 원자성이 보장된다는 뜻이 아니다.

11. 구판 반환값·AUTH/loopback 진입 제한·content/trash B1 검증·업로드 및 압축 검증·non-abandon 취소 처리를 유지한다. `expected=None`인 기존 내부 호출도 MCP 회수와 실제 폴더 소비 키 초기화를 수행하되 요청자를 추측하여 Agent를 채택하지 않는다. 늦은 Agent 요청의 503, 채택된 기록 동작의 409, 회수된 MCP 자격의 403, 인증 미들웨어의 401을 구분한다. 시험은 실제 실행·발급·전송이 일어나지 않았음을 함께 검사한다.

12. 이 계약은 L부터 기존 클라이언트 복원 계약 7항 중 구판 Agent 바이트 유지 조건을 대체한다. JSON 바이트 유지와 다른 계정 비채택은 유지한다. 격리 합성 자료로 완료 조건을 검증하고 설계·구현에 참여하지 않은 별도 Claude 리뷰에서 높음·중간 미해결이 없어야 실사용 적용 준비가 끝난다. 이번 설계 응답 자체는 그 리뷰나 실행 승인이 아니며, A·1C·저장 통합 나머지 단계의 완료를 뜻하지 않는다.
