## 설계(Codex 확정 차이 반영)

### D1 서버가 직접 TLS 로 듣는다 — 8010 그대로, 프록시 헤더 끔
uvicorn 의 기존 TLS 를 쓴다(앞단 프록시는 이번 범위에서 제외 — 더 작다). 공유 서버(TLS) 실행에서는 **uvicorn `proxy_headers=False` 를 명시**해 원격 요청의 위조 X-Forwarded-For/Proto 가 client·scheme 을 바꾸지 못하게 한다. 앱의 loopback 헤더 처리(`request_guards.client_host`)와 개발용 Vite 경로(test_dev 8012/5173)는 그대로 두고 따로 시험한다.

### D2 신뢰 = 사설 신뢰 앵커 + 이름(IP) 검증 유지
- 클라이언트 컨텍스트 = `ssl.create_default_context(cafile=<릴리스의 공개 인증서 묶음>)` — 시스템 저장소를 넣지 않고 `CERT_REQUIRED`·`check_hostname=True`·STRICT·PARTIAL_CHAIN 유지. 공개 인증서 묶음 `backend/app/resources/tls/shared_server.pem`(교체 기간엔 여러 장).
- 의미를 정확히: cafile 에 넣은 인증서가 CA 역할을 하면 **그 키로 서명한 다른 인증서도 통과**한다(정확한 leaf 고정이 아님). 그래서 **인증서 형식을 하나로 정한다** — 자체 서명 leaf, `CA:FALSE`, keyUsage `digitalSignature`(RSA 면 `keyEncipherment` 도), EKU `serverAuth`, SAN, SKI·AKI. 이 leaf 를 신뢰 앵커로 직접 쓴다(PARTIAL_CHAIN). CA:FALSE 라 그 키로 서명한 다른 leaf 는 발급자가 CA 가 아니어서 거절돼야 한다. **이 형식이 Python 3.14(STRICT) 핸드셰이크를 통과하지 못하면 다른 형식으로 조용히 바꾸지 않고 멈춰 설계를 다시 연다**(CA:TRUE 로 바꾸면 신뢰 범위가 달라진다 — Codex N2). 이름 검증을 유지해 허용 범위를 더 좁힌다. 개인키 유출 때는 옛 인증서를 신뢰 묶음에서 빼는 릴리스가 필요하다(D7).
- SAN = 서버 IP·`127.0.0.1`·`localhost`(·안정된 DNS 이름이 있으면 그것). **서버 이전(IP 변경)은 새 인증서 발급·배포**가 필요하다(이전 공지는 주소만 알려 줄 뿐 인증서 이름을 해결하지 않는다).
- 서버 쪽 확인 도구(D6)는 같은 공개 인증서로 `127.0.0.1` 이름 검증(지금 `server_activation.py:192` 와 같음) — 클라이언트와 서버 도구의 신뢰 정책을 같은 파일·같은 규칙으로 쓴다.

### D3 인증서 만들기 — 서버 PC 의 OpenSSL 관리 명령(첫 판), 화면 단추는 나중
Git for Windows 의 `openssl.exe` 를 기존 신뢰된 Git 설치 탐색(`server_console/install.py:168`)으로 찾아 위치·버전·확장 지원을 확인한 뒤 PEM 키·인증서를 만든다. 권한은 파일마다 나눈다(Codex N3): `%PROGRAMDATA%\MVHub\server-tls\` 아래 **개인키 `server.key` = SYSTEM·Administrators 만 읽기**(서버는 SYSTEM 예약 작업으로 돈다 — 키를 쓰기 전에 ACL 을 먼저 건다) · **공개 인증서 `server.pem`·설정 파일 = Users 읽기, Administrators 쓰기**(상태 조회자·관리 창이 읽음). 없으면 분명한 안내로 멈춘다. `cryptography` 의존성은 더하지 않는다(모든 클라이언트에 실림). `New-SelfSignedCertificate` 는 저장소 기반이라 PEM 키 변환이 따로 필요하고, `run_https_soak.ps1:131` 의 PEM 내보내기는 PowerShell 7 이상이라 기본 Windows PowerShell 에 기대지 않는다. 만든 인증서는 릴리스 파이썬 3.14 핸드셰이크로 검증한다. 공개 인증서는 화면·NAS 정해진 자리에 보이고 저장소 `resources/tls/` 에 커밋한다(사람 손).

### D4 클라이언트 전송 — 경로별 명시 표 + 공통 도우미
공통 도우미 `backend/app/services/shared_transport.py`: `transport_url(url)`(공유 서버 주소의 스킴을 전송 단계에서 https 로 — 저장된 신원은 그대로, D5) · `ssl_context()`(D2) · `opener()`(D2 컨텍스트 + **리다이렉트 거절** + 지금 `_SERVER_OPENER` 의 빠른 연결 제한·환경 프록시 처리 유지 — 프록시 CONNECT 안에서도 고정 인증서로 끝까지 확인).

| 경로 | 처리 |
|---|---|
| 주 출구 `routers/_proxy.py` `_open`(`raw_request`·`proxy_json`·`stream_download`·`_forward*`) 과 그 호출자 전부 | 도우미 opener |
| 실시간 다리 `services/remote_realtime.py` | `wss` + `ssl=ssl_context()` + **리다이렉트 명시 거절**(Bearer·쿠키를 다른 목적지로 보내지 않음) + 목적지 변경 시험 |

완료 확인은 '모든 http 를 https 로' 구조 검사가 아니라 **이 표의 경로별 호출 시험**으로 한다.

### D5 전환 = 새 릴리스부터 무조건 HTTPS(잠금·주기 확인 없음, http 로 안 내려감)
- 새 앱은 공유 서버로 가는 모든 전송을 https 로만 한다. TLS 실패는 '서버 인증서 확인 실패' 로 멈춘다(http 재시도 없음).
- **논리적 신원과 전송 주소를 나눈다**: 저장된 `shared_server_url`·대기열·해시·작업자 상태 키는 기존 값 그대로(DB 일괄 이전 없음). 같은 호스트·포트를 `https://` 로 다시 입력하거나 이전 공지가 같은 호스트·포트의 다른 스킴을 주면 **기존 신원을 보존**한다. 다른 호스트·포트를 같은 신원으로 합치지 않는다. 실제 서버 이전(호스트 변경)은 별도 신원·대기열 문제이며 이 설계가 해결한다고 주장하지 않는다. 화면의 열기·복사 링크는 실제 https 주소, 로그는 신원과 전송 주소를 구분해 보인다.
- 순서: ① 서버 쪽 도구가 TLS 를 견디게(동작 변화 없음, git 으로 서버 업데이트) → ② 서버 PC 에서 인증서 생성·공개 인증서 커밋 → ③ 그 인증서가 실린 앱 릴리스를 후보로만 준비(`latest.json` 공개 안 함) → ④ **공지한 전환 시각**에 서버 TLS 켜기 + 릴리스 공개 → 팀원은 업데이트(그 전까지 옛 앱은 서버에 못 붙지만 NAS 로 업데이트 가능) → ⑤ 전환 확인 = **대상 PC 별 설치 판·TLS 접속 성공 확인과 미확인 PC 목록**('http 로 붙는 PC 0' 은 증거가 아님 — TLS 전용 포트엔 http 클라이언트가 도달하지 못하고 꺼진 PC 는 셀 수 없다).
- 서버 쪽: https 요청이면 세션 쿠키에 `Secure`. 서버 화면을 브라우저로 직접 여는 사람(PM 대시보드 등)은 인증서 경고를 본다 — 관리 창 주소 쪽에 https 주소와 '이 PC 에 인증서 신뢰 추가' 방법 안내(자동 설치 안 함 — 시스템 보안 설정 변경).

### D6 서버 전용 TLS 설정 하나를 모든 운영 도구가 읽는다
- 서버 전용 설정(예: `%PROGRAMDATA%\MVHub\server-tls\` 의 설정 파일 — 인증서·키 경로)을 서버 시작(`serve.py`·`MV_server.bat`)·감시기·`restart_server_task.ps1`·관리 창(`server_api`·`status`·`power`·`install`·`ui`)·활성화(`server_activation`)·이전 도구·스모크가 함께 읽는다. **기기 전역 환경변수를 쓰지 않는다**(같은 `serve.py` 를 쓰는 작업자 허브가 TLS 로 뜨지 않게 — AUTH off 허브는 그 설정이 있어도 http).
- 상태 조회자는 **공개 인증서만** 쓴다(개인키를 읽지 않음). 서버 시작만 키를 읽는다. `status.py` 의 CERT_NONE 은 검증하는 컨텍스트로 바꾼다. 관리 창 로그인·전원 조작의 TLS 거절을 없애고 `https://127.0.0.1:<포트>` 로 부른다.
- 인증서 누락·불일치는 **http 전환이나 무한 재시작으로 처리하지 않는다**(분명한 오류·안내).
- 이전 도구는 로컬 ready 외에 옛 서버 원격 조회(`server_move_easy.py:940`)·주소 표시(`:552,:1108`)도 https 로 — 서버 이전 때는 새 PC 인증서 발급·배포(또는 승인된 키 이전 절차)를 단계로 명시한다.

### D7 인증서 수명·키 보호·배포 검사
- 릴리스 검사: 공개 인증서 파일 내용 검증(파싱·형식) + **`PRIVATE KEY` PEM 블록이 든 파일을 거절**(확장자 금지만으로는 키가 든 `.pem` 을 못 막음 — `make_release.ps1:310` 은 `backend/app` 하위를 넓게 허용).
- 정상 교체: 옛·새 인증서를 함께 실은 릴리스 → 팀 업데이트 확인 → 서버 교체 → 옛 인증서 제거 릴리스. **유출**: 옛 인증서를 뺀 릴리스 + 서버 즉시 교체(업데이트 전 PC 는 끊김을 감수). 만료 예고(관리 창에 남은 날)·미업데이트 PC 처리 절차를 둔다.

## 묶음과 완료 조건

추정 5~8 인일(Codex 재산정 — 읽은 범위 기준 추정, 실측 아님; 서버 환경·인증서 발급·배포 조율은 별도). 묶음마다 리뷰하고, 실사용 TLS 전환은 네 묶음 모두 검증 뒤.

1. **서버 준비**(D1·D6): 서버 전용 TLS 설정·`proxy_headers=False`·감시기·재시작·관리 창·활성화·이전·스모크. 완료 = TLS 켠 격리 서버에서 감시기 정상·관리 창 로그인·재시작 대기·이전 도구 통과, 위조 XFF/XFP 가 로컬 관리 권한·쿠키 정책을 못 바꿈, AUTH off 허브는 설정이 있어도 http(`test_serve.py`·`test_server_watchdog_console.py`·`test_server_console*.py`·`test_server_move_easy.py`·`test_server_activation.py`·`test_request_guards.py`).
2. **전송 경계**(D2·D4): 도우미·`_proxy`·WSS(리다이렉트 거절)·하위 프로세스. 완료 = 시험용 TLS 서버에 고정 인증서 통과, 다른 자체 서명·시스템 신뢰 인증서 실패, IP SAN 불일치 실패, Bearer 실은 HTTP·WS 요청이 3xx 를 따라가지 않음(다른 호스트·http), D4 표의 경로별 호출 시험(`test_shared_transport.py` 새·`test_proxy_offline_paths.py`·`test_remote_realtime.py`·`test_comfy_team_key.py`·`test_worker_backup_v3_delivery.py`·`test_asset_sync*.py`·`test_db_backup_streaming.py` 갱신).
3. **호환성**(D5): 신원 보존·주소 입력·이전 공지 https 강제·프런트 비교·Secure 쿠키. 완료 = 전환 전에 쌓인 공유 의도·어셋 대기열 줄이 전환 뒤 같은 신원으로 처리, 같은 호스트·포트의 `https://` 입력이 신원을 안 바꿈, 다른 호스트는 안 합침, 이전 공지 `http://` 도 전송은 https(`test_server_relocation.py`·`test_auth_session_cookie.py`·프런트 `serverRelocation.test.ts`·`assetLocalSync.test.ts`).
4. **배포 검증**(D3·D7): 인증서 생성 명령·릴리스 개인키 검사·교체 절차·릴리스 파이썬 3.14 격리 통합 시험(서버·허브·실시간 다리·작업자 백업 하위 프로세스가 TLS 로 끝까지). 완료 = 생성 인증서(D2 형식)가 3.14 STRICT 로 핸드셰이크 통과 · **그 키로 서명한 다른 leaf 와 같은 이름의 다른 자체 서명 인증서는 거절** · 생성 파일 ACL(개인키 SYSTEM·Administrators, 공개 인증서·설정 Users 읽기) · 개인키 PEM 이 든 파일이면 릴리스 거절 · **교체**(옛·새 묶음을 가진 클라이언트가 새 인증서 서버에 붙음) · **유출**(옛 인증서를 뺀 묶음의 클라이언트가 옛 인증서 서버를 거절) · **만료**(관리 창이 남은 날을 보이고 정한 기준 아래면 경고) 시나리오 시험 · 전체 게이트(`tools/predeploy_gate.ps1`) 통과. 실사용 서버(192.168.1.171)는 시험에 쓰지 않는다.

**실제 전환 완료 조건**(운영, 묶음 4 뒤 Jay 와 — Codex N4): 서버가 TLS 로 인증된 요청마다 계정과 허브 판(새 허브가 보내는 판 머리글)을 기록하고, 관리 창에 **'TLS 접속 확인된 계정·PC 와 판 / 아직 확인 안 된 팀원'** 목록을 보인다. 전환 완료 = 대상 팀원 모두 확인, 확인 안 된 사람은 이름으로 남겨 따로 연락(꺼진 PC 는 셀 수 없으므로 '0' 이 아니라 이름 목록으로 판단).
