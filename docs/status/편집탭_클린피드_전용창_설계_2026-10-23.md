## 왜 크롬 팝업으로는 안 되나(확인한 사실)

- 크롬 155 실측: `window.open` 이 누름 권한을 써 버려 같은 누름으로 전체 화면 불가 · `fullscreen` 창 옵션 효과 없음 · 다음 누름에 권한을 넘기면 됨.
- **'자동 전체 화면'은 사람이 켤 수 없다**: `chrome://settings/content/automaticFullScreen` 화면에 사이트 추가 단추가 없고, `localhost:5173` 사이트별 권한 목록에도
  그 항목이 없다(팝업·창 관리는 있음). 회사 정책(레지스트리 `AutomaticFullscreenAllowedForUrls`)으로만 켜진다 — PC마다 관리자 권한·'조직에서 관리함' 표시.
- 웹 창은 스크립트로 숨기거나 최소화할 수 없다 → 떠나면 닫고 돌아오면 다시 열어야 했다(창 만들기 + 영상 다시 불러오기 = 지연).

## 생각(한 줄)

**이 PC 의 로컬 허브(파이썬)가 크롬을 '키오스크'(처음부터 전체 화면·주소줄·안내 없음)로 따로 띄우고, 떠나면 닫지 않고 윈도우 기능으로 숨겼다가 돌아오면 보인다.**
피드 창은 우리 앱의 작은 화면(`?embed=cleanfeed`)이고, 무엇을 언제 보여 줄지는 편집 탭이 허브를 거쳐 보낸다.

## 구성

```
편집 탭(앱 창) ──WS role=main──┐                ┌──WS role=feed── 피드 창(키오스크 크롬, 전용 프로필)
  · 장면(배치·문서·클립 주소)   │   로컬 허브     │     · useEditFollow + visibleClip(지금 부품 그대로)
  · 시계 표본(시각·때·재생·배속) ├─ 중계 ────────┤     · 키를 앱으로 되돌려 보냄
  · 초점(focus/blur)           │   창 제어       │
  POST open / close ───────────┘ (spawn·ShowWindow·SetWindowPos·WM_CLOSE)
```

### 1) 로컬 허브 — 창 제어(새 `backend/app/services/clean_feed_window.py`, 윈도우 전용 ctypes)

- **띄우기**: 크롬(없으면 엣지)을 `--user-data-dir=%LOCALAPPDATA%\MVHub\clean-feed\<브라우저>-<설치 id>` `--kiosk` `--app=<피드 주소>`
  `--window-position=<고른 모니터의 가운데>` `--no-first-run --no-default-browser-check --autoplay-policy=no-user-gesture-required` 로 띄운다.
  - **전용 프로필**이어야 하는 까닭: 크롬은 같은 프로필의 브라우저가 이미 떠 있으면 새 명령줄을 그쪽에 넘기고 끝나 `--kiosk` 같은 시작 옵션이 안 먹는다.
    또 앱 창 런처(`run_agent_session.py` 의 앱 창 감시)는 앱 창 프로필의 창을 센다 — 같은 프로필이면 피드 창을 앱 창으로 오인한다.
  - 크롬 찾기는 런처의 `_find_app_browser`(App Paths → Program Files)와 같은 규칙을 **백엔드에 따로 둔다** — 런처는 저장소 루트라 staged 업데이트로
    바뀌지 않는다(백엔드가 루트 모듈을 import 하면 판이 어긋난다). 합치면 안 되는 중복으로 `docs/CODE_MAP.md` §5 에 적는다.
- **창 찾기**: 피드 화면이 제목을 `MV hub Clean Feed <세션 id>` 로 둔다 → `EnumWindows` 로 클래스 `Chrome_WidgetWin_*` + 그 제목인 창을 찾는다
  (PID 로 찾지 않는다 — 크롬은 루트 프로세스가 바뀌거나 남을 수 있다. 런처의 앱 창 감시도 창을 앵커로 삼는다).
- **자리 확인**: 뜬 뒤 `MonitorFromWindow` 가 고른 모니터(`MonitorFromPoint(가운데)`)와 다르면 `SetWindowPos` 로 그 모니터 영역에 맞춘다(배율이 다른 모니터 대비).
- **숨김/보임**: `ShowWindow(SW_HIDE)` / `ShowWindow(SW_SHOWNOACTIVATE)` — 보일 때 **초점을 뺏지 않는다**(키는 앱 창에 남는다). 창을 닫지 않으므로
  영상·화면이 그대로 있다 → 돌아올 때 지연은 창 하나 보이는 시간뿐.
- **언제 보이나**(다빈치 규칙): 지금 맨 앞 창(`GetForegroundWindow`)이 **앱 창 또는 피드 창**이면 보임, 아니면 숨김. 허브가 피드를 켜 둔 동안 0.1초마다 본다.
  '앱 창'은 편집 탭이 focus 를 알릴 때(WS `focus`)의 맨 앞 창으로 기억한다(그 순간 앱 창이 맨 앞이다). focus 알림이 오면 기다리지 않고 바로 판정.
- **닫기**: `WM_CLOSE` → 2초 안에 안 닫히면 그 창의 프로세스를 끝낸다. 사람이 피드 창을 닫으면(Alt+F4) 허브가 창이 사라진 것을 보고 편집 탭에 `closed`.
- **한 PC 에 하나**: 새 편집 탭이 열면 앞 것은 닫고 앞 편집 탭에 `taken`. 허브가 시작할 때 전용 프로필의 남은 창(제목 접두로 찾음)을 닫는다(지난 고아).
- 허브 프로세스가 끝나면(업데이트 재시작 등) 피드 크롬도 같이 끝나게 한다(Job 밖으로 빼지 않음 — 앱 창은 BREAKAWAY 로 살아남지만 피드는 다시 열면 된다).
  편집 탭은 WS 가 다시 붙고 모니터가 켜져 있으면 다시 연다.

### 2) 로컬 허브 — API·중계(새 `backend/app/routers/clean_feed.py`)

- `POST /api/local/clean-feed/open` `{origin, screen: {left, top, width, height}}` → `{session, key}` · `POST /api/local/clean-feed/close` `{session}` ·
  `GET /api/local/clean-feed/status`(지원 여부 — 윈도우·브라우저 있음·허브 판).
- `WS /ws/clean-feed?session=&key=&role=main|feed` — 같은 세션의 main↔feed 사이 글을 그대로 넘기는 중계(메모리, 세션 하나). 허브가 끼어드는 글: `closed`·`taken`·
  `visible`(보임/숨김 바뀜 — 피드 화면이 다시 맞춤).
- **지키는 것**: 모든 경로 `require_local_machine_request`(접속 IP + 브라우저 문맥이 이 PC — DNS 리바인딩·CSRF) · `AUTH_ENABLED`(팀 서버)면 404 ·
  `origin` 은 `http://localhost|127.0.0.1:<포트>` 만(피드 주소 = origin + `/?embed=cleanfeed&session=&key=`) · 실행 파일·인자는 허브가 정한다(요청은 모니터 자리와
  origin 만) · `key` = 세션마다 새 난수(WS 붙기 조건 — 이 PC 의 다른 페이지가 끼어들지 못하게).
- Vite 개발 서버는 `/ws` 접두를 이미 넘긴다(`vite.config.ts`) — `/ws/clean-feed` 도 그대로 간다.

### 3) 피드 화면(새 `frontend/src/components/timeline/CleanFeedApp.tsx`, `?embed=cleanfeed` 청크)

- `main.tsx` 에서 Assets·관리 창처럼 **씬 저장소 부팅 전에 갈라** 이 화면만 그린다(로그인·폴링·씬 저장 없음 — 전용 프로필이라 localStorage 도 따로다).
- WS(role=feed)로 받은 **장면**(`layout`·`doc`·클립 열쇠 → `EditSource`)과 **시계 표본**으로 지금의 `useEditFollow`(+ `visibleClip`)를 그대로 돌린다 —
  `now() = t + (지금 − at) × rate`(재생 중) · `t`(멈춤). 시각은 두 창 모두 `performance.timeOrigin + performance.now()`(같은 PC 라 같은 시계).
- 미디어 주소는 앱과 같은 출처(`/media/…` 상대 · CDN 절대)라 그대로 열린다 — 로컬 허브는 인증을 끈 이 PC 전용 모드라 `/media` 에 로그인이 필요 없다.
- 검은 바탕 · 글·단추 없음 · 소리 없음(지금과 같다). 키는 WS 로 앱에 되돌려 보낸다(앱이 본문에 다시 보냄 — 지금 방식). 보임(`visible`)을 받으면 시계를 다시 맞춘다.

### 4) 편집 탭(`EditCleanFeed.tsx`·`EditTab.tsx`)

- `useCleanFeed` 에 **허브 방식**을 더한다: 고르기 → `open`(누름 권한 필요 없음) · 끄기·탭 떠남·앱 창 닫힘 → `close`(닫힘은 `sendBeacon`).
  WS(role=main)로 장면(바뀔 때, 0.1초 묶음)·시계 표본(재생·멈춤·이동·배속이 바뀔 때 + 재생 중 0.25초마다)·초점(focus/blur)을 보낸다.
- 허브가 안 되면(윈도우 아님·브라우저 없음·옛 허브 404·status 거부) **지금의 크롬 팝업 방식**으로 간다(두 방식은 한 훅 안에서 고른다).
- 단추·메뉴·`클린 피드 · 모니터 n` 표시는 그대로.

## 2차 설계(1차 검토 반영 — 위와 다르면 이것이 우선)

**A. 보임/숨김** — 앱 창의 HWND 를 기억하지 않는다. **보임 = (앱이 알린 `active`) 또는 (맨 앞 창이 내 피드 창)**.
- `active` = 앱 문서의 `document.hasFocus() && visibilityState === "visible"` — focus·blur·visibilitychange 때 바로, 그리고 1초마다 WS 로 보낸다. 앱 WS 가
  끊기면 `active=false`. 일반 크롬에서 다른 탭으로 가도 숨는다(문서가 hidden).
- 허브의 0.1초 폴링은 **'맨 앞 창이 내 피드 창인가'만** 본다(사람이 피드 창을 눌렀을 때). `active` 가 false 가 되면 0.15초 뒤에 판정(앱 → 피드로 옮기는 사이).
- 파일 선택창·개발자 도구로 앱 문서가 초점을 잃어도 숨는다(다빈치도 다른 창이 앞이면 사라진다 — 그대로 둔다).

**B. 내 창인지·수명** — 범위는 **이 설치·허브당 하나**.
- 내 창 = `Popen` 으로 띄운 PID 가 소유한 창(`GetWindowThreadProcessId`) **이고** 제목에 세션 표식(`MV hub Clean Feed <세션>`) **이고** 클래스 `Chrome_WidgetWin_*`.
  숨긴 창도 HWND 를 들고 있되 쓸 때마다 `IsWindow` + 소유 PID 로 다시 확인. 닫기·강제 종료도 그 순간 다시 확인된 것만.
- 띄우기 전: 전용 프로필이 쓰이는 중이면(남은 고아 — 크롬이 프로필의 잠금 파일을 쥐고 있다) 명령줄에 **정확히 그 프로필 경로**가 든 크롬만 찾아(CIM 1회) 끝낸다.
  못 끝내면 띄우지 않고 알린 뒤 팝업 방식으로.
- 수명: 허브가 **자기 Job(KILL_ON_JOB_CLOSE)** 을 만들어 피드 크롬을 넣는다 — 허브 프로세스가 어떻게 끝나든(업데이트 재시작·강제 종료) 핸들이 닫히며 피드도
  끝난다(런처 Job 과 따로 — 중첩 Job). 정상 종료는 `WM_CLOSE` 먼저.
- 세션마다 세대 번호 — 늦게 온 옛 세션의 close 는 무시 · `taken` 을 받은 탭은 스스로 다시 열지 않는다(사람이 다시 고를 때만).

**C. 경로·보안**
- HTTP 는 `/api/clean-feed/*` — **`_proxy._LOCAL_PREFIXES` 에 넣는다**(위임 모드에서 서버로 안 가게) + 회귀 시험. WS `/ws/clean-feed`(`is_local_path` 가 `/ws` 를
  로컬로 본다 — 670줄).
- **허브가 이 PC 주소로만 열려 있을 때만** 켠다(`HOST` 가 loopback — 팀 서버는 `0.0.0.0`, `MV_server.bat` 63줄). 모든 HTTP 는 `require_local_machine_request`.
- **앱 출처**: 요청 본문이 아니라 open 요청의 `Origin` 헤더를 쓰고, 그것이 **믿는 앱 출처**여야 한다 — 허브 자신(`http://127.0.0.1|localhost:<허브 포트>`) 또는
  설정으로 준 개발 출처(`test_dev.bat` 이 Vite 포트로 `CONTENT_HUB_TRUSTED_APP_ORIGINS` 를 준다 — 새 설정). 그 출처를 세션에 고정한다.
- WS 는 **accept 전에**: 접속 IP loopback · `Origin` = 세션의 앱 출처 · `key` 일치 · 역할(main·feed)마다 연결 하나(새 연결이 옛 것을 끊음).
- 역할별로 보낼 수 있는 글을 고정한다 — main: `scene`·`clock`·`active` · feed: `ready`·`key`·`error`. 허브 글(`closed`·`taken`·`visible`)은 허브만 만든다.
  글 크기 상한(장면 512KB), 상대에게 못 보낸 글은 **종류마다 최신 하나만** 남긴다(밀리면 옛 장면·표본을 버림), 보내기 제한시간. close·미디어도 `key`.
- `key` 는 피드 주소(크롬 명령줄)에만 둔다 — 허브 접근 로그에서 query 를 가린다(지금 로그 설정 확인 필요). 세션이 끝나면 버린다.

**D. 미디어(dev 는 인증이 켜져 있다)** — 피드 창은 `/media` 를 직접 못 읽는다. 앱이 장면에 넣은 미디어만 허브가 `/api/clean-feed/media/<번호>?s=&k=` 로 내준다:
`/media/…` 상대 주소 → `MEDIA_DIR` 안의 그 파일(경로 이탈 거부, Range 는 지금 `/media` 와 같은 Starlette 응답) · CDN 절대 주소 → 그대로. 이 경로만 인증 미들웨어의
공개 예외에 넣고 라우터가 `key`·로컬을 검사한다(Resolve 의 `transfers/pending` 과 같은 방식 — `main.py` 817~). 인증 끈 로컬 허브·dev 둘 다 같은 길.

**E. 시계** — 앱이 재생 중 0.1초마다 + 이동·재생·멈춤·배속·반복 경계·장면 바뀜 때 즉시 표본 `{rev, t(초), at(ms = performance.timeOrigin + performance.now()), playing, moving, rate}`.
`moving` = 지난 표본 뒤로 `t` 가 움직였나(버퍼링·탐색 대기면 false). 피드는 **`moving` 일 때만** 외삽하고, 마지막 표본에서 0.3초가 넘으면 외삽을 멈춘다.
장면에 `rev` — 피드는 표본의 rev 가 지금 장면과 같을 때만 쓴다. 허브는 세션의 **최신 장면·표본을 들고 있다가** 피드가 (다시) 붙으면 먼저 보낸다.
장면 = 피드가 `visibleClip`·`useEditFollow` 에 쓰는 것만(배치 + 그 함수가 읽는 문서 칸 + 클립 열쇠 → `EditSource`) — 무엇을 읽는지는 구현 전에 함수에서 뽑는다.

**F. 키** — 피드는 모든 keydown 을 그 자리에서 막고(키오스크 화면엔 쓸 기본 동작이 없다) WS 로 앱에 보낸다. 앱은 지금처럼 본문에 다시 보낸다. Alt+F4 는 OS(닫힘 →
허브가 보고 `closed`).

**G. 진입점** — `EMBED_MODES` 에 넣지 않고 따로 `?cleanfeed=<세션>`(분리 창 `WINDOW_OPTIONS` 에 안 걸리게). `main.tsx` 에서 씬 저장소 부팅 전에 가른다.

**H. 방식 고르기** — 메뉴를 열 때 `status` 를 미리 물어 방식을 정한다(누름 권한은 팝업 방식에만 필요). 허브 open 이 실패하면 알리고 메뉴를 다시 누르게 한다(그때는 팝업).

**I. 창 제어 구현 규칙** — 창 제어·폴링은 허브의 전용 스레드 하나(이벤트 루프를 막지 않음) · ctypes 는 argtypes/restype 명시 · 그 스레드는 per-monitor DPI v2 ·
모니터는 앱이 `getScreenDetails` 의 자리(DIP)·`devicePixelRatio`·`isPrimary` 를 보내고 허브가 `EnumDisplayMonitors`(물리)·`GetDpiForMonitor` 와 견줘 고른다 ·

**J. 시험·실측 보강** — 위 M1~M7 에 더해: (창) 앱 문서 blur 직후 다른 프로그램 · 같은 크롬 창 탭 전환 · 숨긴 창 추적 · 제목 설정 전 실패 · (수명) 허브만 재시작 ·

## 3차 설계(2차 검토 반영 — 2차와 다르면 이것이 우선)

1. **`active` 신선도** — 앱은 1초마다 + 바뀔 때 보낸다. 허브는 받은 때를 적고 **2.5초 넘게 안 오면 false**. 새 main 연결은 false 로 시작(첫 글을 기다림). 걸어 둔
   '0.15초 뒤 숨김' 판정은 그사이 `active`·세션·연결이 바뀌면 거두고 최신 값으로 다시 판정. 목표 시간(M6 0.2초)은 정상 때 것이고, 통신이 막히면 늦어도 2.5초 뒤 숨는다.
2. **내 것만 끈다** — open·close·정리는 허브 안에서 하나씩(잠금 하나). 띄우기 전 전용 프로필을 쓰는 크롬이 있으면: 그것이 **지금 세션의 것으로 확인되면** 다시 쓰고,
   아니면 **끄지 않고 거절**한다("클린 피드 창이 이미 떠 있습니다 — 그 창을 Alt+F4 로 닫고 다시") — 허브가 죽으면 자기 Job 이 피드를 끝내므로 고아는 Job 이 실패했을 때뿐이다.
   명령줄은 인자 단위로 읽는다(런처 `_browser_processes` 처럼). 잠금 파일·조회 실패는 고아 근거가 아니다.
3. **띄우기 순서** — 런처와 같은 **멈춘 채 생성(CREATE_SUSPENDED) → 허브 자기 Job(KILL_ON_JOB_CLOSE, BREAKAWAY 불허) 배정 → 재개**. 배정·재개 실패면 그 프로세스를
   끝내고 open 실패. Job 핸들은 허브만 쥐고 상속하지 않는다. 피드는 BREAKAWAY 를 청하지 않는다. 생존은 PID 숫자가 아니라 **쥐고 있는 프로세스 핸들**로 본다. 그 PID 의
   창을 못 찾으면 실패(다른 PID 로 넓혀 찾지 않는다). 런처 Job(BREAKAWAY_OK, 988줄) 안의 중첩 Job — 크롬 자식 Job 까지 회수되는지는 **M8 실측**.
4. **켜는 곳** — `not is_shared_team_server()` **그리고** 허브가 loopback 에 열림 **그리고** 윈도우 **그리고** 브라우저 있음. 하나라도 아니면 `status` 가 거절 → 팝업 방식.
5. **믿는 앱 출처** — 허브 자신(`http://127.0.0.1:<포트>` · `http://localhost:<포트>`) + `CONTENT_HUB_TRUSTED_APP_ORIGINS`(쉼표). 설정값은 **정확한 loopback 출처**
   (`http://127.0.0.1|localhost|[::1]:<포트>`)만 받고 나머지(다른 이름·와일드카드·경로·query·userinfo·`null`)는 그 항목만 버린다(넓히지 않는다). `test_dev.bat` 은
   **포트를 고른 뒤의 실제 Vite 포트**로 넣는다. WS 접속자는 HTTP 와 같은 `client_host` 규칙(Vite 프록시는 마지막 전달 주소)으로 본다.
6. **미디어 중계** — 앱이 장면에 넣는 미디어마다 허브가 세션 안에서 **새 번호**(다시 쓰지 않음)를 준다. `GET/HEAD /api/clean-feed/media/<세션>/<번호>?key=` 만 인증 공개
   예외(정확한 경로 꼴 — 접두가 아님). 번호 → 원래 주소 **종류를 확인**(`/media/…` · `/api/media-thumb?…` · CDN 절대 주소)하고 **기존 처리를 그대로 부른다**: `/media` 는
   로컬 파일 → 없으면 지금처럼 공유 서버 스트리밍(세션을 연 계정 문맥에 고정), 썸네일은 그 핸들러, CDN 은 그대로(중계하지 않음). 아무 주소나 받는 프록시가 아니다.
   계정 전환·로그아웃·세션 끝 → 그 세션 미디어 거절. 캐시는 `no-store`.
7. **키 이름** — 쿼리 이름은 `key`(로그 가리기 정규식이 가리는 이름). WS·미디어·오류 로그에 query 를 남기지 않는 것을 시험으로 확인.
8. **시계(오차 예산)** — 앱은 **재생 중 매 화면 프레임(rAF)** 표본 + 이동·재생·멈춤·배속·반복 경계·장면 바뀜 때 즉시. 표본 = `{rev, t, at, playing, moving, rate, limit}`
   (`moving` = 그 프레임에 `t` 가 앞으로 갔나, `limit` = 반복 끝·타임라인 끝). 피드는 **`playing && moving` 일 때만**, 표본의 `at`(만든 때) 기준 **타임라인 0.05초까지만**
   외삽하고 `limit` 을 넘지 않는다. 표본이 0.1초 넘게 끊기면 **멈춘 것으로**(추종기에 `playing=false` — 150ms 정체 감지를 기다리지 않음).
   오차 예산 = 지금 추종기 허용(0.2초) + 원격 시계(멈추는 순간 최대 0.05초, 평소 1프레임 + 전달 지연). M7 기준을 이것으로 바꾼다. 대역 = 작은 글 60개/초(실측으로 확인).
9. **rev 순서** — 허브는 세션의 (장면, 그 rev 의 마지막 표본)을 쌍으로 들고 있다가 피드가 붙으면 장면 → 표본 순으로 보낸다. 피드는 지금 장면보다 새 rev 의 표본은 장면이 올
   때까지 들고 있고, 옛 rev 표본은 버린다.
10. **보낼 글 대기열** — `scene`·`clock`·`active` 는 종류마다 최신 하나만 남긴다. **`key` 는 순서 있는 대기열(최대 64)** — 넘치면 버리고 앱에 `error`. 연결마다 연결 id —
    옛 연결의 정리는 지금 연결 id 가 자기일 때만 상태를 지운다(새 연결·`active` 를 지우지 않음).
11. **넘기는 키** — 편집 탭이 듣는 키 코드 목록을 한 상수로 뽑아(`EditTab.onKey` 가 쓰는 것) 피드와 같이 쓴다. 그 목록의 키만 넘기고, Esc·F11·Alt·Win 조합은 넘기지 않는다
    (OS 예약 키는 JS 가 다 못 막는다고 보고 M5 로 확인).
12. **모니터 고르기** — 앱은 고른 화면의 DIP 자리·크기·**그 화면의** `devicePixelRatio`(ScreenDetailed 마다 있다)·`isPrimary` 를 보낸다. 허브는 물리 모니터(`EnumDisplayMonitors`
    + `GetDpiForMonitor`)에서 `물리 크기 ≈ DIP 크기 × 그 배율(±2px)` 이고 주 모니터 여부가 같은 것을 고르고, 둘 이상이면 양쪽을 (left, top) 순으로 세운 같은 차례로
    가른다. **그래도 하나로 안 정해지면 고르지 않고 거절**(팝업 방식).
13. **시험 보강** — J + 위 반례: `active` 정체·연결 교체 경쟁 · 동시 open·옛 close · 모르는 프로필 사용자(끄지 않음) · 배정 실패 회수 · 미디어 공개 경로(번호·key·세션 끝·
    계정 전환·공유 서버 원본·썸네일) · 키 대기열 넘침·Space 두 번 · 4배속 버퍼링 오차 · 모니터 애매 → 거절 · 로그에 key 없음.

**구현 때 지킬 것(Codex P2 — 구현 리뷰에서 결함으로 본다)**

1. 미디어 중계는 '기존 핸들러를 그대로 부르기'가 아니다 — 공유 서버에만 있는 `/media` 의 **썸네일**은 미들웨어가 `/api/media-thumb?src=/media/…` 를 보고 서버로
   넘긴다(`_proxy.py:764`). `media_thumb()` 만 부르면 로컬에 없을 때 404(`library.py:781`). `_forward_stream()` 은 받은 요청의 경로·쿼리와 지금 토큰을 쓴다(787) —
   클린 피드 요청을 그대로 넘기면 피드 경로와 key 가 나간다. **등록된 원래 경로와 고정한 계정 문맥으로** 부를 것. 썸네일의 장기 공개 캐시(799)를 덮어 `no-store` 가

2. 미디어 번호는 **같은 원본을 계속 보이는 동안 그대로** — 장면을 보낼 때마다 새로 주면 `useEditFollow` 가 주소가 바뀌었다며 영상을 다시 불러온다(`useEditFollow.ts:93`).
   '다시 쓰지 않음' = 버린 번호를 다른 원본에 주지 않는다는 뜻.
3. `moving=false`·표본 만료를 **추종기의 실제 정지**(`playing=false`)로 잇는다 — `now()` 만 멈추고 `playing=true` 면 정체 감지 전까지 재생·보정이 이어진다(107).
   이동·반복 직후·버퍼링·역재생을 한 시험으로. 0.2 + 0.05초는 목표 예산이지 디코딩·seek 까지 증명된 값이 아니다.

   늦게 온 표본을 지금 상태처럼 쓰지 않는지 확인.
5. 모니터 `(left, top)` 차례 대응은 후보 규칙일 뿐 — 같은 크기 두 대·위아래 배치·배율 섞임에서 **고른 화면 = 실제 나온 화면**을 대조(값이 없거나 안 맞으면 거절은 그대로).
6. Alt 조합을 안 넘기면 피드에 초점이 있을 때 Alt+↑↓·Alt+I/O/X/M·Alt+/ (`EditTab.tsx:1269`)가 안 먹는다 — 예약 키(Alt+F4·Alt+Tab)와 편집 Alt 키를 나누거나 의도한
   한계로 적는다(구현 때 정함).
