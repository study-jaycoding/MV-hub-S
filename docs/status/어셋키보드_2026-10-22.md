# 어셋 탭 키보드 이동·선택 — 2026-10-22 (Jay 요청)

owner: Claude 총괄 · reviewer: Codex(묶음 검토 때) · status: 완료(dev 커밋 — Jay 화면 손 확인·Codex 검토 전) · touched_paths: 아래 계약 · updated: 2026-10-22

고침: 파일 격자 키 처리를 원래 이벤트로 받게 바꾸고 `useLooseKeys` 를 걸었다(파일 격자일 때만·Backspace 제외) · 폴더 보기는 `AssetFolderGrid` 가 선택과 키(←→↑↓ 이동·초점 이동, Enter 열기, Esc 풀기)를 쥐고 표 보기에 넘긴다 · 직계 파일 카드·줄도 누르면 골라진다(크게 보기는 그대로) · `lib/keyGate.useLooseKeys` 에 받을 키를 거르는 선택 인자 — 받은 키는 '처리됨'이 되어 같은 창의 Backspace(상위 폴더로)가 죽었다(첫 구현에서 기존 시험 5건 실패로 발견). 같은 ref 를 두 격자가 쓰므로 파일 격자는 `.assets-virtual` 일 때만 받는다.
Codex 독립 검토 3(읽기 전용, gpt-6-astra/high, 세션 `01a160f4-f511-7f53-81d8-44168e79656e`, 대상 `9b4a825f`·`ca0282c9`) — 지적 2, 둘 다 고침(앞 검토의 R1·R2 고침은 맞다고 확인):
- K1 P2 어셋 툴바(`.assets-crumb`) 단추를 누른 뒤 초점이 거기 남으면 초점 잃은 키가 거절됐다(공용 허용 목록에 없음) → `keyGate` 허용 목록에 `.assets-crumb` 추가. 폴더 탭은 제 방향키(탭 사이 이동)를 쓰므로 넣지 않았다.
- K2 P2 폴더 보기에서 Tab 으로 옮긴 카드가 아니라 이전 선택에서 방향키가 출발했다 → 초점 카드·줄을 먼저 기준으로(공유 탭 컷 카드와 같은 순서). 고치기 전 판에서 새 시험 2 실패 확인.

검증: 고치기 전 판에서 새 시험 2 실패 → 고친 뒤 프런트 전체 410 파일·4,896 시험 통과(종료 코드 0) · 빌드·lint:architecture 통과. 표 보기 시험(`assetFolderTable`)은 앱처럼 AssetFolderGrid 로 그리게 바꿨다(확인하던 것은 그대로). 실제 창의 손 확인·Codex 검토는 묶음 검토 때. 남는 것: 폴더 보기의 여러 장 고르기(Shift·Space)·초점 BODY 일 때의 Esc 는 넣지 않았다(초점 잃은 키는 Esc 를 받지 않는 공용 규칙).

Jay: "어셋탭에서도 워크스페이스나 공유에서처럼 키보드로 카드 이동 선택 등이 가능하게 한다."

지금(코드 확인):
- 파일 격자(`AssetsView` 의 `.assets-virtual`): 방향키·Shift·Space·Enter·Ctrl+A·s/#/c/r/g/b/d 가 있지만 **격자에 초점이 있을 때만**(onKeyDown) 받는다. 워크스페이스(`ThumbnailGrid`)·공유 탭 컷 카드(`FolderCardGrid`)는 초점이 BODY·툴바에 있어도 받는다(`lib/keyGate.useLooseKeys`).
- 폴더 보기(`AssetFolderGrid` 카드·목록, `AssetFolderTable` 표): 누르면 하나 고르고 Enter·더블클릭으로 연다. **방향키 이동이 없다.** Tab 으로만 옮겨 다닌다.
- 어셋은 별도 창(`AssetsWindow`)이라 다른 격자와 키를 다투지 않는다.
