## 구현 메모

- 합의 과정에서 고친 것: 휴지통 변경 감지를 건수·시각에서 `PRAGMA trash.data_version` 으로(Codex — 같은 초의 들고남을 놓친다), 시스템 계정을 실제 `CONTENT_HUB_ADMIN_EMAIL` 값까지로 넓히고 `ensure_admin_account` 도 표식(별도 Claude — 지운 부트스트랩 관리자가 시작 때 표식 없이 다시 생기면 옛 토큰이 관리자로 통과한다), 범위에 시험 5개와 생성 목록 3개 추가(별도 Claude).
- 합의 뒤 구현 중 더한 것: `scene_keep.owner` 를 이력에 넣었다. 다른 세션이 만드는 새 표인데 분류 시험이 잡았다(이메일 칸, `_col_exists` 로 그 표가 없는 트리에서도 안전).
- `require_agent_account` 자체는 바꾸지 않았다 — async 핸들러도 부르는 함수라 동기 DB 조회를 넣으면 이벤트 루프를 막는다. def 쓰기 핸들러(`manage._push_acc`·`ingest._agent_write_acc`·`comfy._comfy_request_scope`)와 async `create_gen_request`(`asyncio.to_thread`)에서 `deps.assert_account_current` 를 부른다.
- 깨진 JSON 휴지통 행은 `_ensure_trash_job_id_col` 이 먼저 터질 수 있다(job_id 가 빈 행) — 그때는 삭제가 500 으로 끝나 아무것도 지우지 않는다. 판정 쪽 거절은 job_id 가 있는 행에서 시험했다.
- 일반 쓰기 경로(사람이 앱에서 보내는 요청)는 재확인하지 않는다. 차단 전에 인증을 통과한 요청이 삭제 뒤에 끝나면 고아 행 1개가 남을 수 있다. 손실은 아니고 합의한 틈이다.
