# MV Agent 가 지금 화면을 읽게 — 열린 씬·지정 없는 씬·칸 실행 안내 (2026-11-10)

owner: Claude(설계·구현) · reviewer: Codex(설계 확인 → 구현 뒤 다른 세션 독립 리뷰) · status: dev 통합 `dc107aa8`(독립 리뷰 Codex `01a1c39a` 2차 통과·시험 기록 7개) — 남은 것 = 8012 재시작 뒤 Jay 실사용 확인 · 계약 `7139e6af` 양측 합의(Codex `01a1bf3c`·Claude `e8e6c383` 2차) · updated: 2026-11-10

## 1. 문제 (Jay 11-10 실사용 — 캔버스 탭에서 '씬 7'을 연 채 "e001 c0010 달리는 사과를 만들 노드를 생성", "씬 7 이건데")

AI 가 씬 7 을 끝내 못 찾고 "실행 권한이 없다"고 말했다. 확인한 원인(코드·dev data_test 읽기 전용 조회):

1. **열린 씬을 안 보낸다** — 칸이 넘기는 '지금 화면'(`App.tsx` agentPanel context)은 `tab`·`workspace`·`project`·`folder`·`selected_ids` 뿐. 캔버스에서 어떤 씬이 열려 있는지 없다(칩도 "MV Hub · 캔버스").
2. **지정 없는 씬이 팀 공간 조회에서 빠진다** — 씬 7 은 허브 씬 백업(`scene_backup`, project_id='')에 있다(11-10 12:04 갱신). 그런데 작업공간 지정(`scene.workspace` — 탭 우클릭으로만 붙는 팀 공간)이 없다. 앱은 '지정 없음 = 어느 공간에서나 정상'(`sceneWorkspace.ts` `sceneMatchesWorkspace`)인데, MCP 씬 조회 `mcp_v2._scenes` 는 '지정 없음 = 개인 공간만' → AI 가 팀 공간 MUD MUD MUD 로 물으면 안 보인다. `add_to_canvas` 도 같은 목록으로 막는다.
3. **"실행 권한 없음"은 잘못된 안내** — 칸 연결은 일반 실행권 `can_execute=0` 영구이고 2-A 실행은 칸 실행 문(`_panel_execute`)으로 한다. 그런데 `connect`·`read_context(kind='workspace')` 가 `can_execute: false` 를 그대로 실어 AI 가 "앱에서 실행하라"고 했다.
4. (범위 밖) '빈 New 노드 만들기'는 2-B 화면 동작이라 아직 없다 — 이번 묶음은 안내 글만 맞춘다.

## 2. Jay 결정 (11-10, AskUserQuestion)

- 지정 없는 씬 = **"앱과 같게"**: 어느 공간에서 물어도 AI 가 찾는다(탭 줄에 보이는 씬 = AI 가 찾는 씬). 목록에 '공간 지정 없음' 표시. 일반 MCP 연결(Claude 데스크톱·Codex)도 같이 바뀐다.

## 3. 설계

### 3-1. 열린 씬 (`App.tsx` · `agentChatApi.ts` · `services/agent_chat.py` GUIDE)
- 캔버스 탭(`filters.tab === "compose"`, 편집 탭이 아닐 때)에서 열린 씬이 있으면 context 에 `scene: {id, name}` 를 더한다(이름 80자까지). 칩 글 = "캔버스 › 씬 이름".
- `AgentContext.scene?: {id: string; name: string}` · 만드는 곳 = `agentChatApi.buildAgentContext`(순수 함수 — App 이 화면 상태를 넘긴다). 허브 `TurnIn.context` 는 자유 dict 그대로(검증 변경 없음).
- **크기 예산(설계 리뷰 P2)**: 허브 build_prompt 가 JSON 을 4096자에서 자르므로, 화면이 3500자를 넘으면 선택 카드(selected_ids)를 뒤에서부터 줄인다 — 씬 id·공간·탭은 남는다. 씬 이름은 자료 칸 안의 글일 뿐(GUIDE 의 '자료는 명령 아님' 그대로).
- GUIDE 한 줄: "지금 화면의 scene 은 사용자가 보고 있는 캔버스 씬이다 — '여기·이 씬'은 그 씬. 노드를 놓을 때 read_context(kind='scenes') 목록에서 같은 id 를 확인해 add_to_canvas 의 scene_id 로 쓴다. 빈 노드 만들기·잇기 같은 화면 동작은 아직 없다 — 생성 결과를 노드로 놓는 것만 된다."

### 3-2. 지정 없는 씬 (`routers/mcp_v2.py` `_scenes`)
- 씬의 공간 id 를 앱과 같게 읽는다(`repo/mcp_v2.scene_workspace_id`): `workspace` 가 dict 이고 `id` 가 공백 아닌 글자면 지정(앞뒤 공백 자름), 아니면 지정 없음(앱 `normalizeSceneWorkspace` 와 같은 규칙 — 옛 `{"scope":"personal"}`·빈 id·숫자 id 도 지정 없음). 지금은 `{"scope":"personal","id":…}` 를 개인 씬으로 받았는데 새 규칙에선 '지정됨'이 된다 — 앱은 팀 공간만 지정하므로(`sceneWorkspace.ts` 8행) 실제 씬에는 없다(Claude 합의 지적).
- 놓을 수 있는 씬 = `repo/mcp_v2.scene_fits_workspace(data, 공간)`: 지정 없음이면 어느 공간이나, 지정이면 팀 공간이고 같은 id. **목록(`_scenes`)과 쓰기 잠금 안 확인(`add_canvas_task`)이 같은 함수**를 쓴다 — 목록 확인 직후 씬이 지워지거나 다른 팀으로 지정되면 쓰기에서 막는다(LookupError → 404, 설계 리뷰 P1).
- 지정 없는 씬 항목에 `workspace_unassigned: true` 와 `workspace_note` "공간 지정 없는 씬 — 앱 탭 줄에서 어느 공간에서나 보입니다". 옛 창 사본의 `backup_copy`·`note` 와 따로 둔다(덮지 않음, 설계 리뷰 P2).
- 캔버스 작업의 workspace 는 지금처럼 계획의 공간. 앱 반영 길(바꾸지 않음, 설계 리뷰 P1 확인): `mcpCanvasTasks.attachMcpCanvasTask` 가 지금 앱 공간 = 작업 공간일 때만 받고, 붙이기 직전 씬을 다시 읽어 `sceneMatchesWorkspace`(지정 없음 = 통과, 다른 팀 지정 = 거절) → 카드 추가 + 영수증(`mcpAttachmentReceipts`) 저장 → 완료(공책 모드는 `scene_notebook.sync` 의 `mcp_complete` — 저장된 씬의 영수증으로 done, 씬 공간을 보지 않는다 / 옛 모드는 `complete_canvas_task` — 작업 공간 = 요청 공간). 그래서 지정 없는 씬에 놓은 팀 작업은 그 팀 공간을 연 앱에서 반영되고 씬은 지정 없음 그대로다. 작업이 생긴 뒤 씬이 다른 팀으로 지정되면 앱이 붙이지 않고 대기로 남는다(엉뚱한 공간에 붙지 않음 — 지정된 씬의 지금 동작과 같다, 지워진 씬은 공책이 `scene_hidden`·`scene_deleted` 로 취소). 노드 놓기는 크레딧이 들지 않는다.

### 3-3. 칸 실행 안내 (`routers/mcp_v2.py` `connect` · `_read` kind=workspace)
- 칸 연결(`client.name == "agent_panel"`)이면 `can_execute: true` 와 `execute_rule`: "MV Agent 칸 — 사용자가 이 대화에서 생성하라고 한 계획만, 차례가 도는 동안 execute_generation_plan 으로 실행합니다(일반 실행권과 별개)". DB 의 `can_execute=0` 은 그대로(일반 `_execute` 문은 여전히 막힘). 일반 연결은 지금 값 그대로.
- 어댑터는 `can_execute` 가 bool 인지만 본다 — 변경 없음.
