# 빠르게 누르면 카드가 안 골라지던 것 — 2026-10-22 (Jay 보고)

owner: Claude 총괄 · reviewer: Codex(묶음 검토 때) · status: 완료(dev 커밋 — Jay 화면 손 확인·실측 전) · touched_paths: 아래 계약 · updated: 2026-10-22

Jay: "어셋이나 워크스페이스나 카드들을 빠르게 마우스로 클릭하면 바로바로 선택이 되지 않는다. 조금 천천히 클릭하면 제대로 클릭이 되는데. 일부러 딜레이를 주었나? 빠르게 클릭이나 입력 등이 반응할 수 있게 전체적으로 파악해서 고쳐라."

원인(코드 확인 + 조사 에이전트 전수 — 실측 전):
- 고르기에 거는 시간 지연(타이머·디바운스)은 없다. 카드 고르기는 **손을 뗄 때**(mouseup·click) 정하고, 누른 뒤 4~5px 움직이면 '끌기'로 보아 그 클릭을 버린다. 빠르게 이어 누르면 손이 움직이는 채로 눌러 문턱을 넘는다.
- 워크스페이스 격자(`ThumbnailGrid` — '생성 결과' 창·폴더 창도)와 어셋 격자(`AssetsView`)는 카드가 끌 수 있는 요소(프롬프트 재사용·파일 내보내기)라 브라우저 끌기가 먼저 걸려 mouseup 이 아예 오지 않는다 — 가장 민감하다.
- 같은 계열: Resolve 프로젝트 탐색기(카드에서 5px 움직이면 뒤따르는 click 을 버림 — 카드 끌기 기능이 없는데도), 편집 탭 풀(5px 움직이면 타임라인 끌기), 계보 보드(노드 이동), 캔버스(칸 한 칸이 바뀔 만큼 움직이면 선택 대신 이동).
- 고르기 외의 지연(참고): S 단추 한 번/두 번 구분 220ms(공유/최종 — 의도), 검색 적용 300ms 디바운스(친 글자는 바로 보임).

고침(탐색기 방식): **아직 고르지 않은 카드는 누르는 순간 고른다**(그냥 = 그 카드 하나, Ctrl = 더하기, Shift = 범위 — 화면마다 지금의 규칙 그대로). 이미 고른 카드·Ctrl 로 빼기는 지금처럼 뗄 때 정한다(여러 장 끌기 유지). 누를 때 고른 것은 뗄 때 다시 고르지 않는다(Ctrl 이 두 번 뒤집히지 않게). 놓친 끝·Esc 는 클릭이 아니다(조작 규칙) — 누를 때 고른 것을 누르기 전으로 되돌린다. Resolve 탐색기는 **고르지 않은** 카드에서 시작한 끌기 뒤의 click 을 버리지 않는다(고른 카드를 흔든 click 은 지금처럼 버림).

범위를 줄인 이유: 처음엔 캔버스·편집 탭 풀·계보 보드에도 넣었다가 프런트 전체 시험 13건이 깨져 되돌렸다 — 그곳에는 '고르지 않은 카드를 끄는 동안의 삭제·되돌리기 대상은 기존 선택', '풀 카드를 뷰어에 놓을 때 원본 뷰어를 바꾸지 않음' 같은 정해 둔 규칙이 있다. 셋은 카드가 브라우저 끌기 요소가 아니라 4~5px 문턱만 있어 덜 민감하다(캔버스는 칸 맞춤 한 칸을 넘어야 이동). Jay 가 그곳에서도 느끼면 따로 정한다.

검증: 고치기 전 판에서 새 시험 2(워크스페이스·어셋) 실패 확인 → 고친 뒤 프런트 전체 410 파일·4,892 시험 통과(종료 코드 0, 처리되지 않은 오류 0) · 빌드·lint:architecture 통과. 바뀐 기대값 2(어셋 '누른 파일이 사라짐', 폴더 창 '창이 닫힌 뒤 옛 콜백') — 지키려던 것(그 자리에 온 다른 파일을 고르지 않음·닫힌 뒤 다시 부르지 않음)은 그대로 단언한다. 실제 브라우저의 빠른 클릭 실측·Codex 검토는 묶음 검토 때.
