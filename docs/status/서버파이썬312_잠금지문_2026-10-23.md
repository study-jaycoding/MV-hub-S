# 서버 업데이트가 의존성 지문에서 멈춤 — 서버 Python 3.12 용 지문을 잠금에 더한다 — 2026-10-23

## 왜

도장 제거판(`bcada51a`)을 서버에 들인 뒤 Jay 가 `update_git.bat` 더블클릭 → UAC → 검증 Python 준비까지 됐고, 준비 단계가 `prepare_step_exit_1` 로 멈췄다(실행 중 서버는 그대로, ready 200 — Jay 화면). 준비 기록(`server-prepare-9caa6348….log`)의 원인: stage venv 의 `pip install --require-hashes --only-binary=:all: -r backend/requirements.lock.txt` 가 `websockets-16.0-cp312-cp312-win_amd64.whl` 을 받아 지문 불일치(Expected `c0ee0e63…`, Got `5569417d…`). **서버 Python 은 3.12**(run_py.bat 이 `where python` 으로 고른다)인데 잠금에는 배포판 Python 3.14 휠 지문만 있다.

재현(이 PC, 직접): Python 3.12.10 새 venv 에서 같은 명령 → 같은 파일·같은 Got 지문으로 실패.

## 선택 — B(잠금에 cp312 지문을 더한다)

- A. 서버 Python 을 3.14 로 맞춤: 상주 supervisor 를 3.14 로 다시 띄우고 저장소 트리 서버의 의존성도 3.14 에 새로 깔아야 한다(지금 의존성은 3.12 site-packages). 실행 중인 공유 서버를 크게 건드린다.
- **B. 잠금의 컴파일 휠 6개에 cp312-win_amd64 지문을 하나씩 더한다.** 판은 그대로, 지문은 PyPI 가 공개한 값과 내려받은 파일 두 쪽이 일치한 것만. 3.14 배포판 설치는 기존 지문으로 그대로 통과(pip 는 나열된 지문 중 하나와 맞으면 통과). 실행 중 서버는 건드리지 않는다.
- C. 서버만 지문 없이 requirements.txt: 공급망 방어를 버린다 — 제외.

더할 6개(이 PC 3.12.10 의 `pip download --only-binary=:all: --no-deps` 결과, 전부 PyPI 공개 sha256 과 일치): `websockets==16.0`·`Pillow==12.3.0`·`pydantic-core==2.41.5`·`httptools==0.8.0`·`PyYAML==6.0.3`·`watchfiles==1.2.0`. 나머지 17개는 `py3-none` 휠이라 이미 같은 지문이 있다. 지원 범위는 **CPython 3.12·3.14 Windows x64** 뿐이다(32비트·ARM64 지문 아님 — 서버 로그가 win_amd64 휠을 골라 64비트 확인).

**사전 검토 반영(1차)** — Codex(`01a16557-7530-7ee0-9f3f-77dd0e0acf6c`)·Claude(`487fdc56-0859-43bb-a8e9-3b0498c01b4d`) 모두 B 에 찬성하며 같은 막힘을 지적: `test_release_frontend_build.py:77` 의 `len(pins) == len(hashes)` 가 지문을 더하면 깨진다 → 시험을 '판마다 지문 1개 이상·여러 지문 허용·지문 줄 64자·항목 안 줄 이음 `\` 확인·6개 컴파일 패키지는 2개 이상·판은 requirements.txt 와 같음'으로 바꾸고 변경 범위에 넣는다. 잠금 머리말·`make_release.ps1` 주석·`release/README.md`(243·249행 절차, 81행 숫자)를 3.12·3.14 둘 다로 고친다. 기존 시험 목록에 `test_release_contract.py`·`test_server_activation.py` 추가. 메모: 잠금 바이트 지문은 커밋마다 새로 계산되므로(release_contract·server_activation) 새 배포판은 계약·qualify 를 새로 만든다(옛 기록 재사용 금지). stage venv 는 prepare 를 돌린 Python 으로 만들어지고 supervisor 가 그 기반 Python 경로·지문을 대조하므로, 서버에 3.14 를 따로 깔면 `update_git_worker.bat`(py -3)과 `run_py.bat`(where python)이 다른 Python 을 고를 수 있다 — 지금은 둘 다 같은 3.12.
