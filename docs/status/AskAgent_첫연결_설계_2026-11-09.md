## 2. 사실 확인 (11-09)

- 공식 설치(https://code.claude.com/docs/en/setup): PowerShell `irm https://claude.ai/install.ps1 | iex` · 관리자 권한 필요 없음 · 실행 파일 `%USERPROFILE%\.local\bin\claude.exe` · 설치 뒤 "새 터미널" 필요(= 이미 켜진 허브의 PATH 엔 안 보임).
- 계정: Pro·Max·Ultra·Team·Enterprise·Console 만 Claude Code 를 쓴다. 무료 claude.ai 는 못 쓴다. Console = API 요금 → 이 칸은 막는다.
- 로그인 명령(이 PC 2.1.296): `claude auth login [--claudeai|--console|--email|--sso]` · 상태 `claude auth status`(JSON). **로그아웃 상태면 종료 코드 1** — 지금 dev 코드(`_status_output`)는 종료 코드가 0 이 아니면 출력을 버려 "로그인 안 됨"이 "확인 못 함"으로 보인다(이번 묶음에서 고침).
- 구독 사용: 칸의 대화는 각자의 Claude 구독 사용량을 쓰고, 그 사람이 Claude 쪽 추가 사용을 켜 두었다면 그 설정을 따른다. MV 크레딧은 [실행]만 쓴다.

## 3. Claude 상태 판정 (허브)

`claude_state()` — 차례 시작 전 판정(`engine_problem`)도 같은 함수를 쓴다(화면과 실행이 같은 판정).

| 상태 | 조건 | 칸 화면 |
|---|---|---|
| `not_installed` | 실행 파일 없음 | B 설치 안내 |
| `outdated` | 판이 최소 판(0단계에서 정함)보다 낮음 | "Claude Code 를 업데이트하세요" + 명령(`claude update`) + [다시 확인] |
| `unknown` | 실행 실패·시간 초과·JSON 아님 | "Claude 상태를 확인하지 못했어요" + [다시 확인] |
| `not_logged_in` | `loggedIn:false`(종료 코드 1 이어도 JSON 이 있으면 이것) | [Claude 연결] |
| `not_subscription` | `authMethod != claude.ai` 또는 `apiProvider != firstParty` | [구독으로 다시 연결] |
| `no_plan` | 구독 로그인인데 `subscriptionType` 이 **확인된 무료** | "이 계정엔 Claude Code 를 쓸 수 있는 구독이 없어요(Pro·Max·Ultra·Team·Enterprise)" + [다른 계정으로 연결] |
| `subscription_unknown` | `subscriptionType` 이 없거나 모르는 값 | 대화는 허용(Claude 가 거절하면 그 까닭을 보임) · 띠에 "구독 종류를 확인하지 못했어요" — Team·Enterprise 처럼 값이 다르게 오는 계정을 막지 않으려고 |
| `login_window` | 이 PC 에 로그인 창이 열려 있음(어느 허브가 열었든) | "열린 창에서 로그인을 마쳐 주세요" + [그만두기](기다림만 멈춤) |
| `ready` | 알려진 유료 종류(pro·max·ultra·team·enterprise) | 연결 끝 띠 → 평소 칸 |

- `subscription_unknown` 은 실행을 막지 않는다 — 막는 판정은 확인된 사실(로그아웃·API 키·확인된 무료)만. 대화가 Claude 쪽에서 거절되면 그 오류를 사람 말로 칸에 보인다. 0단계에서 실제 값(무료·누락)을 모은다.
- 실행 파일 찾기: PATH → npm 셰임 옆 `claude.exe`(지금) → `%USERPROFILE%\.local\bin\claude.exe`(새로). **둘 이상이면 판이 높은 쪽**, 같으면 공식 위치. 로그인·상태·대화가 같은 실행 파일을 쓴다(아래 4절).
- 내보내는 것: 상태 · 판 · 구독 종류(표시용). 이메일·조직 id·경로는 내보내지도 남기지도 않는다.

## 4. 같은 조건으로 부른다 (로그인·상태·대화)

- 세 경로 모두 **같은 실행 파일 · 같은 작업 폴더(`AGENT_CHAT_DIR/work`) · 같은 자식 환경 · 같은 설정 출처**로 부른다. 자식 환경은 지금 빼는 것 + **`ANTHROPIC_` 로 시작하는 변수 전부**를 뺀다(제공자 전환·키 변수가 늘어도 막히게).
- 설정 출처: 대화는 `--setting-sources local`(지금). `auth status`·`auth login` 에도 같은 옵션이 먹는지 0단계에서 본다 — 안 먹으면 사용자 설정의 `apiKeyHelper`·제공자 설정이 상태 판정에 끼는지 확인하고, 끼면 그 PC 는 `not_subscription` 처럼 막는다(설정은 고치지 않는다).
- 관리 정책(조직 설정)이 구독 로그인을 막거나 API 키를 강제하면 설정을 바꾸지 않고 "이 PC 의 Claude 관리 설정 때문에 연결할 수 없어요"로 안내한다.

## 5. HTTP (접두사 `/api/agent-chat`, 기존 지킴 그대로 — 루프백 브라우저 + `X-MVHub-Expect-Account` + 칸 표)

| 경로 | 하는 일 |
|---|---|
| `GET /claude` | 캐시 없이 지금 상태 `{state, version, subscription, login_window: bool, login_window_enabled: bool}` — `login_window` = 이 PC 에 로그인 창이 열려 있나, `login_window_enabled` = 스위치(6절)가 켜져 있나(꺼져 있으면 화면은 터미널 안내) |
| `POST /claude/login` | 상태가 `not_logged_in`·`not_subscription`·`no_plan` 이고 이 PC 에 열린 로그인 창이 없으면 **보이는 로그인 창**을 연다 → `{opened:true}`. `ready`·`subscription_unknown` 이면 409, 창이 이미 열려 있으면 409 `login_window_open` |

- 끄는 경로는 없다 — 로그인 창은 사람이 닫는다(6절). 칸의 [그만두기]는 기다림만 멈춘다.
- 기능 표식 `agent_chat_connect_v1`(없으면 옛 화면처럼 엔진 사유만).
- 로그인 창이 닫히거나 [다시 확인]을 하면 **엔진 캐시를 비우고**, 화면은 `/session` 의 엔진 목록·모델 선택을 다시 받는다.

## 6. 로그인 창 (v0.7)

**왜 보이는 창인가**: 공식 문서에 로그인 때 브라우저 자동 열기를 끄는 방법이 없다(11-09, code.claude.com authentication·env-vars). 로그인은 대화형이다 — 브라우저가 열리고, 안 열리면 창에서 `c` 로 주소 복사, 필요하면 받은 코드를 창에 붙여 넣는다. 숨긴 프로세스로는 이 흐름을 할 수 없고, 허브의 Job 에 넣으면 사용자 브라우저를 끌 위험이 있다. 그래서 v0.2~0.5 의 '숨긴 로그인 프로세스·주소 뽑기·[브라우저 열기]'를 버리고 **사람에게 보이는 로그인 창**을 연다.

- **띄우는 법**: 허브가 `claude.exe --setting-sources local auth login --claudeai` 를 **`CREATE_NEW_CONSOLE | CREATE_BREAKAWAY_FROM_JOB`** 으로 띄운다(4절의 같은 실행 파일·자식 환경·작업 폴더). `--setting-sources` 는 `auth` 앞(0단계 확인).
  - **Job 에서 빠진다**: 배포판 런처의 Job 은 `KILL_ON_JOB_CLOSE | BREAKAWAY_OK` 이고(`run_agent_session.py` 1154), 앱 창·링크 처리도 같은 방식으로 빠져나간다(778–797·1114–1130). 그래서 허브·런처가 꺼져도 로그인 창과 그 창이 연 브라우저는 남는다. **빠져나가기가 거절되면**(탈출을 허용하지 않는 다른 Job 아래) 창을 열지 않고 "터미널에서 `claude` 를 실행해 로그인하세요" 안내 + [다시 확인]. 빠져나가지 못한 채로는 절대 띄우지 않는다.
  - **입출력은 새 창의 것**: stdin·stdout·stderr 를 넘기지 않는다(`STARTF_USESTDHANDLES` 없음 — 새 콘솔의 핸들). 허브 출력이 로그 파일·파이프인 배포판에서도 로그인 주소·코드·이메일이 허브 로그로 가지 않고, 코드 붙여 넣기가 그 창에서 된다(0단계 4에서 배포판 런처 아래로 확인).
  - **띄우기 직전 신원 다시 확인**: 요청의 신원(허브·DB·계정)을 고정하고 창을 만들기 바로 전에 다시 대조 — 다르면 열지 않는다.
- **스위치 뒤에 둔다**: 로그인 창은 허브 설정 `CONTENT_HUB_AGENT_CHAT_LOGIN_WINDOW`(기본 `0`)가 `1` 일 때만 연다. `0` 이면 [Claude 연결] 대신 "터미널에서 `claude` 를 실행해 로그인하세요" 안내 + [다시 확인]. 7절 4번 실측을 통과하고 Jay 가 확인한 뒤에만 기본값을 `1` 로 바꾼다(별도 작은 변경). 실측을 안 했거나 실패하면 `0` 그대로.
- **그 창은 사람의 것**: 허브는 창을 Job 에 넣지 않고 끄지도 않는다(`taskkill` 없음). 사람이 창을 닫으면 로그인도 멈춘다. 허브는 창의 글을 읽지 않는다.
- **로그인 창 기록**(`%LOCALAPPDATA%\MVHub\claude\<자격 열쇠>-login.json` — 창 pid·프로세스 시작 시각·연 신원의 표식, 원자적 쓰기. 독립 리뷰 1차로 위치를 기록 폴더 밖 사용자마다 한 곳으로 옮기고 이름을 Claude 자격 폴더로 정함, 15절): 어느 허브든 **기록의 창 프로세스가 살아 있으면(pid·시작 시각 일치)** 새 창을 열지 않는다(409 `login_window_open` — "열린 로그인 창에서 마쳐 주세요"). 허브가 다시 켜져도 이 기록으로 판단한다. 기록을 읽을 수 없으면 새 창을 열지 않고 "로그인 창 기록을 확인하지 못했어요 — 열린 Claude 로그인 창을 닫고 [다시 확인]" (사람이 창을 닫으면 창 프로세스 판정으로 풀린다; 기록 파일이 깨진 경우만 [다시 확인]에서 그 파일을 치운다 — 살아 있는 claude 로그인 창이 없을 때만).
- **기다림 제한과 중복 막기는 따로**: 칸의 2초 확인은 10분까지만(그 뒤 "아직 로그인 창이 열려 있어요 — 마치면 [다시 확인]"), 중복 막기는 창이 살아 있는 동안 계속.
- **대화와 겹치지 않게**(v0.5 의 PC 뮤텍스를 되살림): 같은 Claude 자격을 쓰는 허브들이 `Local\MVHub.Claude` 를 나눠 쓴다.
  - **차례**는 띄울 때부터 회수까지 쥔다. 쥔 뒤 로그인 창 기록을 보고 창이 살아 있으면 놓고 409 "Claude 로그인 창이 열려 있어요 — 마치거나 닫은 뒤 보내 주세요".
  - **로그인**은 창을 만들 때만 잠깐 쥔다: 쥐고 → 로그인 창 기록·상태 확인 → **① 기록에 `launching`(연 허브 pid·시작 시각)을 먼저 쓴다 → ② 창을 `CREATE_SUSPENDED` 로 만든다(아직 아무것도 실행 안 함) → ③ 기록을 `open`(창 pid·시작 시각)으로 바꾼다 → ④ 그다음에야 창을 재개한다** → 놓기. 다른 허브에서 대화 중이면(뮤텍스를 못 얻음) 409 "다른 MV Hub 에서 Claude 가 일하는 중이에요".
    - 이 순서라 **추적 안 된 로그인은 실행되지 않는다**: ①~③ 사이에 허브가 죽으면 창은 멈춘 채(인증 안 함)거나 없다 → 다음 허브는 `launching` + 연 허브가 죽음 = "실행 중인 로그인 없음"으로 보고 새 기록을 쓴다(멈춘 빈 창이 남으면 사람이 닫는다 — 인증을 못 하니 대화와 겹치지 않음). ③~④ 사이에 죽으면 기록이 `open` 이고 창(멈춤)이 살아 있어 그 창이 닫힐 때까지 새 로그인·차례를 막는다("열린 Claude 로그인 창을 닫아 주세요").
    - 로그인에는 'Job 닫힘으로 정리됨' 추론을 쓰지 않는다(창은 Job 밖) — 판단은 창 기록과 창 프로세스로만.
  - 주인 기록(`claude-owner.json`, `running|clean`)·버려진 뮤텍스 판정은 v0.5 그대로: 정상·버려진 획득 모두 먼저 기록을 보고, `running` 인데 주인이 내가 아니면 주인 허브가 죽었을 때만 이어 가고(커널의 Job 닫힘 규칙) 살아 있으면 기록을 건드리지 않고 거절 · `clean` 은 자기 Job 0개 확인 뒤에만.
  - 밖(터미널)에서 로그아웃·만료되면 진행 중 차례는 CLI 오류로 끝나고 다음 차례 전 재판정이 잡는다.
- **PC 단위** 안내: 한 PC 의 MV 계정 여럿은 같은 Claude 로그인을 쓴다 · 다시 연결은 그 PC 의 다른 Claude 사용처(터미널 등) 로그인도 바꾼다 · 창 안내는 연 신원 기준(다른 계정이면 "다른 계정에서 연 로그인 창이에요").
## 7. 0단계 실측
