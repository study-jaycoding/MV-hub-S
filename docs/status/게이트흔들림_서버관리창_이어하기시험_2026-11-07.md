# 게이트 흔들림 — 서버 관리 창 '이어서 하기' 시험의 작업 순서 (2026-11-07)

배경: 속도 점검 묶음 2-B·2-C 를 합친 배포 후보 `b1e40e39` 의 게이트(백엔드 9,150 중)에서 `test_server_console.py::test_runner_rechecks_the_same_release_target_then_deploys_and_resumes` 하나가 실패했다 — 이어서 하기로 배포가 끝난 뒤에도 `release.find_resumable` 이 첫 작업을 '이어 갈 작업'으로 돌려줌.

원인(소스 확인): `tools/server_console/jobs.py` `_job_dirs` 는 작업 폴더를 `request.json` 수정 시각 순으로 정렬한다. 시험은 첫 작업을 돌린 직후 몇 ms 안에 두 번째 작업을 만들어, 바쁜 PC(게이트 중)에서는 두 `request.json` 의 수정 시각이 Windows 파일 시각 단위(약 15ms) 안에 같아질 수 있다 — 그러면 정렬이 첫 작업을 먼저 보고 '끝나지 않은 배포'로 판정한다. 단독 실행 8/8 통과. `tools/server_console` 은 앞 후보 `446ec589` 이후 바뀐 줄이 없다(이번 묶음과 무관한 기존 흔들림). 실제 사용에서는 두 작업이 몇 분 간격이라 순서가 뒤바뀌지 않는다.

고침: 같은 파일의 다른 시험이 이미 쓰는 방식 그대로 — 두 번째 작업을 만들기 전에 첫 작업의 `request.json` 수정 시각을 오래전으로 고정한다(`test_server_console.py:642` 의 `os.utime(..., (1, 1))`, 같은 줄기의 `test_resumable_deploy_is_found_from_recent_jobs` 는 `time.sleep(0.05)`). 제품 코드는 그대로.
