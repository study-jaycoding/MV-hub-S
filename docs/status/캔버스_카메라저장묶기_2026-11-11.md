1. **역할**: viewport = 카메라 대기·타이머 · SceneBoard = 떠남 순서를 한 함수로 · 문서 저장소 = 접수 뒤 재시도(지금 그대로).
2. **대기·타이머**: 실제 카메라 변경 지점(휠 — 배율이 바뀐 때만, 보드 스크롤 접기, 팬 걸음 — 이동량이 있을 때만, commit=true 인 navigateTo·frameRects·stepZoom 끝)마다 `markCameraDirty()` = 대기 표시 + (팬 중이 아니면) 타이머 `CAMERA_IDLE_SAVE_MS`(초안 3000, 실측으로 정함) 재시작. 기존 400ms 휠·스크롤 타이머는 지운다. 팬은 누르는 순간 타이머 취소(새 조작이 예약을 미룸), finish(up·blur)가 mark. 타이머가 울릴 때 팬 중이면 아무것도 안 함. 최대 대기 없음.
3. **대상 고정**: 대기 = `{ target }`. target = SceneBoard 의 `canvasSession.target`(frozen `{accountNamespace, sceneId, openEpoch}`) — SceneBoard 가 렌더에서 `cameraOwnerRef` 에 넣고, viewport 는 자기 ownerRef 를 **씬 바뀜 passive effect(첫 마운트 포함)에서만** 설치한다. 설치 전 mark 는 무시. 불변식: 대기가 있는 동안 카메라 refs 는 대기 target 씬의 카메라다. 커밋 = App `onCameraChange(camera, target)` → `canvasDocument.commit(target, recordCamera)`(커밋 때 활성 씬으로 target 을 만들지 않는다 — 계정이 바뀌었으면 authorized 가 거절). 단독 사용(owner ref 없음)은 씬 ID 를 owner 로.
4. **거절 처리**: receipt.queued = true → 대기 지움(이후 재시도는 저장소). 유휴 타이머 flush 가 거절되면 같은 유효 owner 일 때만 대기 유지·자동 재예약 없음. `leaveCamera()` 는 성공·거절과 무관하게 대기 제거·타이머 취소(반환 'none'|'queued'|'refused'). owner 교체·실제 언마운트는 옛 대기 제거·재생 금지. 인계·분리 창도 거절분은 잃는다 — 밀린 입력 확정과 같은 조건부 보장(settleSceneWrites 는 저장소 pending 만 본다). flushingWriter 는 hubPaused 만 우회하므로 권한·공책 잠금으로도 거절될 수 있다(관문을 더 풀지 않는다).
5. **떠남 함수 하나 `viewport.leaveCamera()`**: (1) 팬 중이면 SceneBoard 가 연결한 settlePan(= settleDrag, 팬일 때만 — 다른 끌기 정책 그대로)으로 밀린 rAF 걸음 반영·팬 finish (2) 대기 flush (3) 타이머 취소·panning 초기화.
   주 경로: selectScene(setActiveSceneId 직전, sceneActionRef 새 멤버 `flushCamera`) · onCanvasMemoryReturn 등록(허브 넘기기·분리 창 돌려주기 — setSceneWriterFlush 의 flushCanvasMemoryReturn 이 settle·lost·blocked·hidden·pagehide 에서 부른다) · 캔버스 분리 창 열기(App openCanvasWindow 의 flush 함수) · hidden·pagehide 리스너(라이터 기능이 꺼진 허브용). blur 는 저장 신호가 아니다.
   보조 경로: `useLayoutEffect(() => () => leaveCamera(), [sceneId])` — 씬 ID 가 바뀔 때(옛 owner·옛 refs·살아 있는 팬, viewport 의 passive replaceCamera·SceneBoard 의 passive abortDrag 보다 먼저)와 언마운트 때(끌기 세션 dispose 보다 먼저) 같은 일. unmounted 표시는 하지 않는다 — 수명은 viewport 의 별도 `useEffect([], activeRef)`(StrictMode 재설정 견딤, 비활성이면 타이머·mark·flush 무시).
   **구현 위치(합의 뒤 조정)**: 이 레이아웃 정리와 hidden·pagehide 리스너는 SceneBoard 가 아니라 **useSceneViewport 안**에 둔다 — useSceneViewport 는 SceneBoard 에서 useCanvasSession·useSceneDragSession 보다 먼저 호출돼 레이아웃 정리 순서가 같고(먼저 선언된 훅의 정리가 먼저), 단독 사용(시험)에서도 같은 규칙이 된다. 팬을 끝내는 손잡이(settleDrag)는 SceneBoard 가 `beginPan(e, beginDrag, settleDrag)` 로 넘긴다(팬일 때만 쥔다).
   재귀: adapter.flushPending(입력 전용) 은 그대로, flushCamera 는 별도 멤버라 커밋 안에서 다시 불리지 않는다.
   **SceneBoard 래퍼**: 지금의 '씬을 바꾸는 틈이면 저장하지 않음'(switchingRef) 검사는 카메라 기록에서 뺀다 — 그 검사의 까닭(부모가 지금 활성 씬에 쓴다)이 고정 target 으로 사라졌고, 남겨 두면 보조 경로의 떠남(틈에 돈다)이 0회가 된다. 틈(그림 뒤 passive effect 전)에 생긴 표시는 owner 교체 때 버린다. 저장 직전 입력 확정(flushPendingRef = 이 판의 canvasSession.flush)은 **target 이 이 판의 지금 세션 target 이고 틈이 아닐 때만** 한다 — 떠난 씬의 밀린 편집은 전환 직전 selectScene 의 확정이 넘겼고, 커밋 안의 adapter.flushPending(flushScenePending)은 활성 씬일 때만 입력을 확정한다. 계정이 바뀐 대기(target 계정 ≠ 지금 계정)는 래퍼가 쓰지 않고 '처리 끝'으로 돌려줘 대기를 지운다(창 쓰기 권한 거절 = false 와 구분).
6. **같은 값**: viewport 에 '마지막 보낸 값'을 두지 않는다. session.ts `recordCamera` 가 working 씬 카메라와 같으면 그 씬 그대로(쓰기 0). 외부 C2 수신 뒤 C1 복귀는 쓴다.
