# 편집 탭 — 클린 피드 넘김의 '앞 그림 멈춤' 줄이기 — 2026-10-26

owner: Claude(세션 f011c565) · reviewer: (Jay 가 검토를 지시할 때 묶음으로 — 화면 쪽 작은 변경) · status: 완료(dev — Jay 5173 확인: "잘 된다" 2026-10-26 저녁) · touched_paths: 아래 계약 · updated: 2026-10-26

요청(이 세션, 2026-10-26 저녁): "앞 그림 멈춤도 줄이자" — 앞 작업 [넘김 검은 화면](편집탭_클린피드_넘김검은화면_2026-10-26.md)이 검은 화면을 없앤 대신, 다음 클립
데이터가 넘김까지 안 오면 그 동안 앞 클립의 마지막 그림에서 멈춘다(느린 중계 격리 실측 약 0.5초).

## 왜 멈추나(앞 작업 실측)

피드는 다음 클립을 **정방향 재생 중에만** 미리 받는다(`useEditFollow` — 멈춘 채 훑을 때마다 받으면 요청이 두 배). 그래서 멈춘 자리에서 재생을 누르면 그때부터 받기
시작하고, 경계가 가까우면(격리 측정: 재생 시작 1.2초 뒤 경계) 서버 중계(첫 응답 0.3초·moov 뒤라 범위 요청 세 번)로는 넘김까지 못 받는다.

## 고침

- 멈춰 있어도 **시각이 0.3초 넘게 그대로이고 지금 클립이 그림을 냈으면(readyState ≥ 2, 영상이 아닌 자리는 바로)** 다음에 보일 영상을 뒤 요소에 그 시작 자리로 미리 받아 둔다.
  훑는 동안(시각이 계속 바뀜)은 받지 않는다. 짝이 아닌 판(영상 하나)은 미리 받기가 없어 그대로.
- 재생 중 규칙·받는 것(다음 하나)·짝의 앞 그림 두기는 그대로.

## 실측(격리 — 같은 장치 · 소리 트랙 시험 영상 · 가짜 서버 느린 중계 첫 응답 0.3초·60Mbps · 멈춘 자리에 약 2초 둔 뒤 재생 → 1.2초 뒤 경계 · 매번 새 허브·크롬 3번씩)

고치기 전 = 앞 작업 빌드(distL — dev 23760141 의 화면) · 고친 뒤 = 작업 트리 빌드(distM) · 백엔드는 둘 다 dev d47e6578 사본.

| 넘김 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 처음 받는 클립(첫 바퀴 5초) — 새 클립이 보이기까지 | 0.57~0.61초(그 동안 앞 그림 멈춤) | **0.05~0.06초** |
| 두 번째 바퀴 5초(되감아 다시 — 받아 둔 것을 처음 자리로 되돌림) | 0.55~0.57초 · 검정 28·33ms 각 1번 | **0.30~0.31초** · 검정 0 |
| 10초 넘김(재생 중 미리 받음) | 0.03~0.05초 | 0.04~0.07초 |
| 검은 화면 | 12번 중 2번(28·33ms) | **12번 모두 0** |

- 두 번째 바퀴가 0.3초 남는 것: 앞 바퀴 끝까지 틀어 둔 다음 클립 요소를 처음 자리로 되돌리면 그 앞부분을 다시 받는다(중계 응답이 no-store) — 이번 범위 밖.
- 계속 재생 중에는 지금처럼 클립이 시작될 때 다음 것을 받는다 — 클립이 받는 시간보다 짧거나 서버가 더 느리면 앞 그림 멈춤이 남을 수 있다(실제 서버 속도는 재지 않음).
