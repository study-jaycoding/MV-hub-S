## 1. 업데이터 신뢰성 — 이 기간 가장 큰 사고

`2026.09.02-0951` 을 받은 PC 는 **이후 모든 업데이트가 90% 에서 실패하고 롤백**됐다. 원인은
`update_release_worker.bat` 의 완료 마커 커밋 한 줄이다.

```powershell
[System.IO.File]::Replace($TempPath, $VersionPath, $null)   # ← 실패
[System.IO.File]::Replace($TempPath, $VersionPath, [NullString]::Value)  # ← 정상
```

Windows PowerShell 5.1 은 `[string]` 매개변수에 `$null` 을 주면 빈 문자열로 바꿔 넘긴다. 그래서
"The path is not of a legal form." 이 세 번째 인자가 아니라 **경로**를 가리키며 났다. 두 형태를
같은 파일로 각각 실행해 재현·확인했다(**실측**).

**구조 문제**: 업데이트를 실행하는 주체가 그 PC 에 설치된 그 파일이라, 고친 릴리스를 배포해도
설치할 주체가 고장 나 있어 자가 복구가 안 된다. "강제 업데이트" 는 사전 검사만 건너뛰고 같은
워커를 같은 방식으로 실행하므로 결과가 같다.

**대응 3층**:

1. `[NullString]::Value` 로 수정(`476117f1`)
2. `release/make_release.ps1` 이 패키징 전에 스테이징된 워커를 검사해 결함이 있으면 빌드 중단
   (`d9a82e8e`) — 업데이터의 실패 분기는 평소 실행 경로가 아니라 회귀 테스트에 잘 안 걸린다
3. 외부 복구 스크립트 `Z:\mvutil\MV_hub_S\packages\MVHub_Fix_Updater.bat` — 최신 릴리스 zip 에서
   고쳐진 워커만 꺼내 원자 교체. 실행 전 `[NullString]::Value` 포함 여부를 검사해 고장난 파일로
   덮어쓰지 않는다. 팀에 공지 완료(Jay).

Jay PC 에서 업데이트 성공까지 확인(**실측** — `[3/3] Update complete.`).

## 2. 캔버스 씬 백업이 서로를 지우던 사고

`fe5b6778`(09-01)이 런처를 바꿔 앱 창을 **전용 브라우저 프로필**로 띄우기 시작했다
(`--app` + `--user-data-dir`, 프로필 이름 = `<브라우저>-<설치경로 sha1>`). 그전에는 사용자의 기본
브라우저(일반 프로필)를 열었다.

캔버스 씬 원본은 브라우저 `localStorage` 에 있다. 그래서 프로필이 갈리는 순간 **작업물이 사라진
것처럼** 보였다. 한 PC 에 프로필 3개가 쌓인 것을 확인했다(**실측**).

더 나쁜 것은 안전망 쪽이었다. `sceneBackup.ts` 의 삭제 미러가 "서버에만 있는 id 는 전부 삭제" 로
계산해, **프로필을 번갈아 열 때마다 서로의 백업을 지웠다**(코덱스 적대적 검토에서 확인).

**대응**(`32e327dd`, `9cbb35f0`):

- 삭제 미러를 "이 세션에서 로컬에 있던 씬이 사라진 것" 만으로 좁혔다(`lastPushed` 가 tombstone
  역할). 버킷 키가 없으면(읽기 실패) 로컬을 신뢰하지 않아 삭제하지 않는다.
- `saveScenes` 가 저장 성공 여부를 반환한다 — 복구가 저장에 실패하고도 "복구됨" 을 반환하면
  다음 sync 가 빈 로컬을 기준으로 서버를 지운다.
- 복구 적용을 합집합으로 바꿨다. 종전엔 조회 중 씬이 하나라도 생기면 복구를 통째로 포기해,
  빈 프로필에서 씬을 만든 순간 DB 백업에 영영 닿지 못했다.
- 자동 복구가 닿지 못하는 자리(이 브라우저에 씬이 있는데 다른 프로필 백업이 DB 에 있음)를 위해
  씬 탭 줄에 **명시적 가져오기**를 노출한다. 로컬은 덮지 않는다.
- 런처가 한 번 쓴 브라우저를 고정한다(`preferred-<install_id>.txt`). 승인된 앱 창을 확인한 뒤에만
  쓰고, `MVHUB_APP_BROWSER` 는 이번 실행만 우회하며 고정을 바꾸지 않는다.

**이미 지워진 백업은 되돌릴 수 없다** — 실제 DELETE 라 이력이 남지 않는다.

## 4. Resolve 전송 파일명 (Jay 규칙 확정)

최종 규칙은 **"폴더에 남아 있는 마지막 번호 + 1"** 하나다(`<폴더경로>_<번호 2자리>`). 설계 과정에서
장부(sequence 파일)와 알파벳 꼬리를 거쳤지만 Jay 지시로 둘 다 제거했다 — 장부는 디스크와 어긋나고,
같은 생성물도 번호로 들어오면 알파벳이 필요 없다.

스틸 이미지는 **한 경로씩** 반입한다. 여러 스틸을 한 번에 넘기면 Resolve 가 이미지 시퀀스로 묶어
`[00-01]` 한 클립이 된다(**실측**). 영상·오디오는 종전대로 한 묶음.
