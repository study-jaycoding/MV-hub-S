## 고칠 것

### A. 팀 PC 업데이트(`update_release_worker.bat`, `update_release_contract.ps1`) — 고친 판이 깔린 **다음 업데이트부터** 효과(지금 설치된 판의 워커가 업데이트를 돌린다)

1. 압축 풀기를 `[System.IO.Compression.ZipFile]::ExtractToDirectory($ZipPath, $ExtractDir)` 로(어셈블리는 이미 불러옴). `$ExtractDir` 는 매 실행 새 GUID 임시 폴더 아래라 덮어쓰기 차이가 없고, 실패는 .NET 예외로 그대로 멈춘다. ZIP 경로 검사는 앞의 `Get-QualifiedRelease` 그대로.
2. 단계 시각: `Write-UpdateState` 의 이른 반환(상태 파일 없음) **앞**에서 `[HH:mm:ss] <메시지>` 한 줄. 상태 기록이 없는 구간은 같은 형식으로 정지 직전·정지 직후·DB 사본 직후·설치 파일 재검사 직후에 한 줄씩. 상태 파일 내용·형식은 그대로.
3. `Write-InstallRecord`: `File.Replace`/`File.Move` 만, 안쪽 예외까지 풀어 Win32 코드 **5·32·33** 일 때 같은 임시 파일·같은 바이트로 약 2초(0.1초 간격) 다시 시도. 판별은 계약 파일 안에 따로 둔다(워커의 `Get-TransientLockCode` 는 이 파일을 쓰는 다른 곳에 없다). 그 밖의 오류는 즉시. 끝내 실패하면 지금처럼 '디스크 바이트가 이미 같은지' 확인 뒤 오류, 임시 파일 정리는 그대로. `Set-InstallPhase` 는 감싸지 않는다(디스크 비교·성공 뒤 메모리 갱신 순서 유지).

### B. 서버 업데이트 창(`tools/run_update_git.ps1` 서버 분기) — 표시만, 업데이트 흐름·종료 코드는 그대로

1. coordinator 를 지금과 같은 명령으로 띄우되 기다리는 동안 1초마다, coordinator·supervisor 가 **이미 쓰는 파일만 읽어** 단계가 바뀔 때 `[HH:mm:ss] [n/6] <한국어 단계>` 를 찍는다: ① 새 코드 받기(새 run 의 `server-prepare.json` running) ② 파이썬 패키지 설치(stage `.venv`) ③ Higgsfield CLI 설치(stage `runtime\higgsfield`) ④ 화면 설치·빌드(stage `frontend\node_modules` 또는 `frontend\dist\index.html`) ⑤ 새 판 시험 기동(stage `server-stage.json`) ⑥ 서버 바꿔 끼우기(`prepared` 뒤 journal 의 이 run 단계: 요청 마무리 → 약 30초 멈춤·DB 사본 → 새 판 켜기). 단계는 뒤로 가지 않는다. 파일은 삭제 공유를 허용해 열고(쓰는 쪽의 교체를 막지 않게) 읽기 오류는 '아직 모름'.
2. 끝나면 크게 한 번. **판정은 coordinator 의 종료 코드만 쓴다**(coordinator 는 자기 run 의 journal 이 `committed` 이거나 이미 최신일 때만 0 을 낸다 — `server_release_update.py` `main`). 0 → "완료: 서버가 최신 판으로 동작 중입니다." · 그 밖 → "실패: 업데이트가 끝나지 않았습니다(종료 코드 N). 위 메시지를 확인하고 이 화면을 보내 주세요." 실패 때는 서버 상태('이전 판 그대로' 등)를 단정하지 않는다(원인은 그 위의 coordinator 출력). 새 판 커밋·'바꿀 것 없음' 같은 덧붙임은 **붙이지 않는다**: coordinator 는 준비 잠금을 풀고 전환을 기다리므로 그사이 다른 실행이 기록을 쓸 수 있어, 파일로는 그 기록이 이번 실행의 것임을 증명할 수 없다(재합의 때 Codex 지적, `server_release_update.py` `main`). 진행 줄은 창이 coordinator 를 띄운 시각 이후에 만들어진 `server-prepare-<run>.json` 의 run 하나만, 도는 동안 처음 본 것으로 고정해 보여 준다(종료 뒤에는 새로 고정하지 않고 마지막 단계만 한 번 더 본다). 한계: 같은 순간 누가 coordinator 를 손으로 따로 돌리면 진행 줄이 그쪽을 보여 줄 수 있다 — 결과 줄은 종료 코드라 바뀌지 않는다. coordinator 가 run_id 를 직접 넘길 수 있게 되면(stage 검사 도구를 바꿀 수 있을 때) 그때 덧붙임을 되살린다. 콘솔에서 깨지는 em dash 는 쓰지 않는다.
3. 표시 쪽 예외는 기다림·종료 코드와 떼어 놓는다: 기다림은 `while (-not $Process.WaitForExit(1000))`, 판별·출력은 어떤 예외든 잡아 무시하고 기다림을 계속, 결과 출력이 실패하면 한 줄 대체 안내, 반환은 지금처럼 `$Process.ExitCode`.
4. 이 창이 도는 동안 콘솔 빠른 편집(QuickEdit)을 끄고, **결과 줄을 찍은 뒤** 바깥 `finally` 에서 원래 모드로 되돌린다(입력이 넘겨진·콘솔 없는 실행은 건너뜀, 실패해도 무시).
5. 한국어 문구 때문에 파일을 UTF-8(BOM)로 저장한다(Windows PowerShell 5.1 이 한글을 바르게 읽도록). 이 파일을 utf-8 로 읽어 utf-8-sig 로 다시 쓰는 `test_sparse_checkout_scripts.py` 는 BOM 이 두 번 붙지 않게 utf-8-sig 로 읽도록 고친다.

**서버에 넣는 법**: `run_update_git.ps1` 은 서버 루트 코드라 한 번 반입해야 한다. 서버가 지금 stage 로 돌고, 이번 변경은 검사 도구 지문(`server_activation.py`·`server_release_update.py`·`qualify_release_artifact.TOOLS`)을 건드리지 않으므로 **서버를 멈추지 않고** 루트를 앞감기(fetch → 루트 HEAD 가 예상 커밋이고 작업 폴더가 깨끗한지 → 앞감기 범위의 커밋 목록이 예상한 것뿐이고 diff 가 그 지문 파일·`server_supervisor.py`·supervisor 가 불러오는 `backend/app` 파일을 안 건드리는지 확인 → `merge --ff-only` → 작업 폴더 깨끗함 확인)만 하면 된다. 절차는 SERVER.md 에.
