1. **범위와 완료 명칭:** 이번 작업은 1C-1 복원 세대 보호다. 합의안 1-C의 `[되돌리기]`와 로컬 세트 복원은 1C-2로 남기며, 두 부분이 끝나기 전 1-C 전체 완료로 기록하지 않는다.

2. **세대의 출처:** 복원 세대는 대상 content DB의 기존 `app_setting.share_db_generation`을 사용한다. 정상 재시작은 값을 유지하고 지원되는 DB 복원은 기존 보상 롤백 경계 안에서 회전한다. 세대를 요청 처리 중 생성하거나 누락 요청에 현재 값을 채워 넣지 않는다. 세대는 권한 증명이 아니다.

3. **서버 쓰기 보호:** 공책 시작·저장·닫기, 옛 씬 미러, 카드 소속, 편집 백업 저장·복원의 일곱 경로는 실제 변경과 같은 `BEGIN IMMEDIATE` 트랜잭션에서 세대를 검사한다. 검사 실패 시 본문·삭제·되살리기·순서·시작 자료·요청 영수증·MCP 완료·편집 사본을 변경하지 않는다.

4. **오류와 기존 권한:** 인증·계정·필요한 쓰기 임대 검사를 유지한다. 유효한 요청에서 세대 누락 또는 null은 409 `restore_generation_required`, 불일치는 409 `restore_generation_changed`다. 빈 문자열·잘못된 형식·200자 초과는 422다. 서버의 세대 값이 없거나 잘못되었으면 서버 오류로 중단하며 누락끼리 같다고 통과시키지 않는다.

5. **읽기와 응답의 일관성:** 네 읽기 응답은 내용·기준판·`restore_generation`을 같은 연결과 읽기 트랜잭션에서 얻는다. 성공한 쓰기와 영수증도 실제 적용 세대를 반환한다. 닫기 요청은 바깥 요청과 모든 `pending_requests`의 세대를 재생 전에 검사한다.

6. **옛 자료 자동 전송 금지:** 다른 세대 또는 세대가 없는 대기열·기준판·시작 진행·자동 미러 후보는 복구 후보로 보존한다. 새 세대 조회, 판 기억 삭제, 새로고침, 재로그인, online 이벤트, 다음 편집을 이유로 그 자료에 새 세대를 붙여 자동 전송하지 않는다. 대상 행이 없거나 본문이 같아도 옛 대기열을 자동 실행하지 않는다.

7. **캔버스 전환:** 공책은 복원 전 로컬 씬·충돌·기준판·삭제·되살리기·순서·시작 및 전송 진행을 보관한 뒤 복원본을 채택한다. 보관과 로컬 전환은 하나의 IndexedDB 트랜잭션으로 확정한다. 실패하면 원래 로컬 상태와 전송 차단을 유지한다. 공책이 없는 빈 복원본에서도 옛 로컬 씬으로 자동 시작하지 않는다.

8. **편집·옛 미러·카드:** 편집과 옛 미러는 로컬 원문을 유지하면서 자동 전송을 중지한다. 카드 제거·되살리기뿐 아니라 옛 씬을 스캔하는 자동 백필과 서로 다른 세대의 카드 병합도 차단한다. 보존 성공을 확인하기 전 기존 기록을 삭제하지 않는다. 다시 켜도 차단과 복구 후보가 남아야 한다.

9. **늦은 응답과 동시 동작:** 요청은 계정·문서·복원 세대·요청 또는 의도 식별자를 캡처한다. 응답으로 새 세대나 새 의도를 정리하지 않는다. 성공 응답 뒤 새로 시작한 조회로 같은 세대를 확인하고, 로컬 확정 트랜잭션에서도 캡처 상태를 재검사한 뒤 해당 요청만 완료 처리한다. 확인 실패·복원 감지·계정 변경이면 대기열을 보존한다. 요청 취소를 서버 취소로 간주하지 않는다.

10. **복구 선택과 공개 조건:** 복구 후보를 보내거나 복원본을 채택하는 것은 대상·내용·현재 세대를 확인한 명시적 사용자 행동이어야 한다. 기존 내보내기·가져오기·편집 백업 선택 흐름을 우선 재사용하며 옛 제어 자료를 자동 재실행하지 않는다. 세대 없는 허브에는 자동 저장을 재개하지 않는다. 관련 격리 시험과 설계·구현에 참여하지 않은 독립 리뷰가 끝나기 전 실사용 데이터로 실행하지 않는다.
