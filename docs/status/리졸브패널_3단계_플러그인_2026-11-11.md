## 2단계 리뷰 P3 (같이 고침)

① `services/resolve_panel.py` 순번 기록의 창 64개 상한을 **창 단위 최근 쓴 순서**로 — 기록할 때 그 창의 모든 채널(cache·target) 키를 함께 맨 뒤로 옮긴다(한 채널 키만 옮기면 그 창의 다른 채널 키가 앞에 남아 가장 오래된 창으로 잘못 지워짐 — Codex C1-7).
② `useResolvePanel.ts` 처음 `authConfig()` 가 실패하면 다시 시도한다(몇 초 뒤·창 초점 때) — 허브가 늦게 켜져도 새로 고칠 필요 없이 열린다.
③ `useResolvePanel.ts` adopt 의 `not_prepared` 는 실패 문구·[다시 확인]보다 **재준비를 먼저** — 재준비가 성공하면 adopt 한 번만 다시, 실패하면 그 까닭(2단계 adopt 상태 표 그대로).

## 플러그인 `com.mvhub.resolve` — 창과 끌기만

- 자리(저장소): `backend/app/resources/resolve_panel/com.mvhub.resolve/` — `manifest.xml`(Id `com.mvhub.resolve` · Name `MV Hub` · Version `1.0.0` · FilePath `main.js`) · `package.json` · `main.js` · `preload.js` · `rules.js`(전자 모듈 없이 시험할 수 있는 순수 판단) · `offline.html` · `img/drag.png`.
  설계 1·2판의 `integrations/resolve-panel/` 대신 이 자리 — 릴리스가 `backend\app` 을 통째로 복사하므로(`release/make_release.ps1:597`) 릴리스 스크립트를 바꾸지 않고 팀 PC 에 실리고, 설치기가 메뉴 스크립트 자원(`resources/resolve/`) 옆에서 찾는다.
- **리졸브 API 를 부르지 않는다** — `WorkflowIntegration.node` 를 싣지 않는다(빈 정리·표시는 허브의 파이썬 길). 실제 리졸브에서 이 껍데기만으로 창이 뜨는지는 실측 몫(안 뜨면 설치 때 리졸브의 `Developer\Workflow Integrations\Examples` 에서 그 파일을 복사하는 안으로 다시 연다).
- 주소: `%LOCALAPPDATA%\MVHub\resolve-panel\hub.json` 의 `url` 을 **URL 로 해석해** 스킴 `http` · 호스트 정확히 `127.0.0.1` 또는 `localhost` · 포트 있음 · 사용자 정보·경로(`/` 밖)·질의·조각 없음일 때만 그 출처, 아니면 기본 `http://127.0.0.1:8010`
  (`http://127.0.0.1:8010@evil.example`·`http://localhost.evil.example:8010`·https·포트 없음은 거절). 창 = `<출처>/?embed=resolve-panel`. 창을 열 때·다시 시도할 때마다 다시 읽는다.
- **허브 출처는 main 한 곳**(`rules.js` 의 작은 상태 — 지금 출처 하나)만 들고, `loadURL` 바로 앞에서만 바꾼다. 이동 허용·IPC 출처 검사·preload 의 다리 노출이 모두 이 값을 본다 — 재시도 중 주소가 8010→5173 으로 바뀌어도 셋이 함께 바뀐다(Codex C1-5).
  preload 는 페이지가 열릴 때마다 main 에 동기 IPC `hello` 로 `{origin, supported}` 를 묻는다(`additionalArguments`·`process.argv` 를 쓰지 않음 — sandbox preload 에서도 되는 IPC 만, Codex C1-4).
  main 은 그 IPC 의 `event.senderFrame` 을 쓸 수 없는 판이면 `supported:false` → preload 는 다리를 내주지 않는다(닫힌 쪽으로 실패 — 화면은 2단계의 '리졸브 밖' 읽기 전용 안내).
- 허브가 안 열리면(주 프레임 `did-fail-load`) `offline.html` "MV 앱을 켜 주세요 — 켜지면 저절로 열립니다" → 3초마다 다시 시도.
- 창: 맨 위 고정 · 제목 `MV Hub` · 크기·자리 기억(`%LOCALAPPDATA%\MVHub\resolve-panel\window.json`, 지금 화면들 안에 들 때만 되살림) · 별도 영구 세션(`persist:mvhub-resolve-panel` — AUTH-on 개발에서 한 번 로그인하면 남게) ·
  `contextIsolation` 켬 · `nodeIntegration` 끔 · `sandbox` 켬 · 새 창 열기 거부 · 허브 출처 밖으로 이동 거부.
- 끌기 다리(2단계 약속): preload 는 **`hello` 가 supported 이고 페이지 출처가 그 출처와 같고 최상위 프레임일 때만** `window.mvhubResolve = {protocol: 1, accepts: {min: 1, max: 1}, startDrag(path, {protocol})}` 를 내준다.
  `startDrag` 는 main 에 동기 IPC 로 묻고 그 판정(boolean)을 돌려준다. main 은 ① 보낸 창이 이 창 ② 최상위 프레임 ③ 그 프레임 주소의 출처 = 지금 허브 출처 ④ `opts.protocol` 이 정수이고 `accepts` 안 ⑤ 경로가 절대 경로·실제로 있는 일반 파일·허브가 다루는 매체 확장자(영상·그림·소리 — `prepare` 가 만드는 종류에서 정함)
  — 모두 맞을 때만 **답(true)을 먼저 보낸 뒤** `startDrag({file, icon: img/drag.png})` 를 부른다(윈도 끌기 고리 동안 화면이 멈추지 않게 — 실제 내장 Electron 에서 이 순서가 되는지는 아래 '릴리스 전 필수 실측'). 하나라도 어긋나면 false 이고 끌지 않는다.
  **true 의 뜻 = "끌기 요청을 받아 시작을 시도함"**(Codex C1-3). 그 뒤 `startDrag` 예외(그 사이 파일이 사라짐 등)는 main 이 기록만 하고, 화면에는 사용자가 Esc 로 끌기를 그만둔 것·놓지 않은 것과 똑같이 보인다 —
  셋 다 화면이 구별할 수 없고, 2단계 adopt 표의 `not_seen` 길("확인 못 함 — 놓지 않았거나 다른 빈" · [다시 확인])이 이미 받는다. '빈에 있음'으로 잘못 보이는 길은 없으므로 다리 약속을 바꾸지 않는다.

## 설치기 `services/resolve_panel_installer.py`

- 설치 자리: `%PROGRAMDATA%\Blackmagic Design\DaVinci Resolve\Support\Workflow Integration Plugins\com.mvhub.resolve\`. `…\DaVinci Resolve\Support` 가 없으면 리졸브가 없는 PC 로 보고 아무것도 만들지 않는다(`no_resolve`).
- 같음 판정 = 상대 경로 목록 + 파일마다 sha256 이 묶음과 정확히 같음. 같으면 손대지 않는다.
- 설치본 판정(Claude 합의 검토 3): 설치 자리의 `manifest.xml` 을 읽어 Id·Version 을 본다. 폴더가 있는데 manifest 가 없거나 깨졌거나 Id 가 `com.mvhub.resolve` 가 아니면 **우리 것이 아니므로 덮지 않는다**(`foreign` — 자동·수동 모두 손대지 않고 경로를 알림, 메뉴 스크립트 설치기가 관리 표식 없는 파일을 보존하는 것과 같은 원칙).
  판은 점으로 나뉜 정수(`^\d+(\.\d+)*$`, 모자란 자리는 0)로 비교한다. Id 는 우리 것인데 판을 읽을 수 없으면 `damaged`(자동도 다시 깜).
- 교체: 임시본과 보존본은 **플러그인 폴더 밖** `%PROGRAMDATA%\MVHub\resolve-panel\`(`staging\<무작위>` · `backup\<무작위>`) — 리졸브는 `Workflow Integration Plugins` 의 하위 폴더를 모두 플러그인으로 읽으므로 그 안에 사본을 두면 같은 Id 가 둘이 된다.
  임시본을 쓰고 sha 를 검증 → 기존 폴더를 보존본으로 옮김 → 임시본을 설치 자리로 옮김 → 설치 자리를 다시 검증 → 실패하면 보존본을 되돌림.
- **한 번에 하나·꺼져도 복구**(Codex C1-1): 설치·상태 확인은 `%PROGRAMDATA%\MVHub\resolve-panel\install.lock` 의 OS 잠금(열린 핸들 — 프로세스가 죽으면 OS 가 풂)을 못 잡으면 하지 않고 `busy`(자동은 건너뜀, 수동은 "다른 설치가 진행 중").
  첫 이동 **전에** `journal.json`(임시본·보존본 경로 · **작업 전 설치가 있었는지와 그 상대 경로·sha 목록** · 새 설치의 기대 상대 경로·sha 목록)을 원자적으로 쓰고 성공 뒤 지운다. 잠금을 잡을 때마다 먼저 복구한다(Codex C2-1·C3-1 — 첫 설치인지는 보존본이 있는지로 추정하지 않고 기록으로 안다):
  · 설치 자리가 **새 설치의 기대 경로·sha 와 정확히 같으면** 완료로 확정(남은 임시본 지우고 기록 지움) — 폴더가 있다는 것만으로는 완료가 아니다.
  · 설치 자리가 **작업 전 설치와 정확히 같으면**(옮기기 전에 끊김, 또는 되돌린 뒤 기록을 지우기 전에 끊김) 그대로 두고 남은 임시본과 기록을 지운다.
  · 그 밖(설치 자리가 없거나 둘 다와 다름)이고 보존본이 있으면: 다른 설치 자리를 `backup\<무작위>` 로 비키고 보존본을 되돌린 뒤 기록을 지운다.
  · 기록상 작업 전 설치가 **없었으면**(첫 설치): 다른 설치 자리는 `backup\<무작위>` 로 비키고 기록을 지운 뒤 평소 판정으로(`not_installed`).
  · 비킨 폴더는 바로 지우지 않는다(그사이 사람이 손으로 넣은 폴더일 수도 있음 — Claude 합의 검토 3차 참고). 보존본 정리 규칙(새 설치 검증 뒤 하나만)이 나중에 정리한다.
  · 작업 전 설치가 있었는데 설치 자리도 보존본도 그것과 맞지 않거나, 되돌리기가 실패하거나, 기록을 읽을 수 없으면 **기록·보존본·설치 자리를 그대로 두고** 새 설치를 하지 않고 `damaged`(기록·보존본 경로를 상태에 보임).
  옛 보존본은 새 설치를 검증한 뒤에만, 기록이 가리키지 않는 것만 지워 마지막 하나만 남긴다.
  상태 확인(GET)도 잠금을 잡으면 이 복구를 먼저 한다 — 끊긴 설치를 원래 상태로 돌리는 쓰기뿐이고, 의도한 동작이다.
- 판: 자동 설치는 **낮은 판으로 내리지 않는다**(설치본 `Version` 이 묶음보다 높으면 `newer_installed` 로 두고 손대지 않음 — 개발 PC 의 수동 설치본을 릴리스 허브가 덮지 않게). 같은 판인데 sha 가 다르면(손상·덜 깔림) 다시 깐다.
  수동 [설치]는 묶음과 **똑같이 맞춘다**(낮은 판으로도 — MV 롤백 뒤 되돌리는 출구). 판 불일치로 끌기가 막히는 것은 끌기 다리의 판 확인이 화면에 알린다.
- 실패를 나눈다(Codex C1-6): 파일 잠김(공유 위반) → `deferred`(다음 허브 시작 때 다시).
  접근 거부(WinError 5)는 윈도가 **열린 파일이 있는 폴더를 옮길 때도** 내므로(리졸브가 패널을 열어 둔 채 업데이트 — Claude 합의 검토 2차) 바로 권한 문제로 보지 않는다:
  설치 자리의 부모 폴더와 `%PROGRAMDATA%\MVHub\resolve-panel\` 에 시험 파일을 써 보고(쓰고 바로 지움) 둘 다 되면 `deferred` — 단 원인을 잠김으로 확정하지 않는다(부모에 쓸 수 있어도 대상 폴더만 따로 옮기기가 막혔을 수 있음, Codex C3-2):
  설정 칸 "파일이 쓰이는 중이거나 플러그인 폴더 권한 문제입니다 — 리졸브를 끈 뒤 다음 시작 때 다시 시도합니다. 계속 실패하면 폴더 권한을 확인하세요(경로)".
  시험 쓰기도 거부될 때만 `permission_denied`(다른 Windows 사용자가 만든 폴더 등 다시 켜도 안 풀림 — 설정 칸에 "이 PC 의 관리자가 리졸브 플러그인 폴더 권한을 열어야 합니다"와 경로).
  다른 오류도 허브 시작을 막지 않는다. **디스크 설치와 리졸브 적용은 다르다** — 리졸브는 켤 때 플러그인 목록을 읽는다. 리졸브가 다시 켜졌는지는 재지 않으므로, 상태는 '마지막으로 파일을 바꾼 시각'을 그대로 보이고
  설정 칸은 조건부로 말한다: "설치 파일을 바꿨습니다(그 시각) — 그 뒤 리졸브를 다시 켜지 않았다면 다시 켜야 적용됩니다"(Codex C2-2 — 허브 수명과 묶지 않음).
- 마지막 설치 결과는 잠금 안에서 `%PROGRAMDATA%\MVHub\resolve-panel\last_result.json` 에 원자적으로 쓴다 — '마지막 시도'(시각·결과·까닭)와 '마지막으로 파일을 바꾼 시각'을 따로 두어, 바꾸지 않은 재실행·허브 재시작·다른 허브의 조회가 바꾼 시각을 지우지 않는다.
  다른 허브(예: 개발 허브)의 설정 칸도 릴리스 허브가 남긴 `deferred`·`permission_denied` 까닭을 본다(Claude 합의 검토 7).
