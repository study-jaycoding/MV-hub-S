## 결과

- 구현: 폴더 종류는 `assetFolderKind`(`assets/assetsViewModel.ts`) 한곳에서 정하고 값이 그대로 CSS 클래스다. 아이콘 색은 `FolderIcon` 의 `tone`. 있음 여부는 `reloadFolderInfo` 가 `/api/assets/mounts` 로 받는다.
- 배포 후보 독립 리뷰의 지적으로 색 조회를 `reloadFolderInfo` 로 나눠 어셋 변경 알림에서 뺐다(`bc77c53c`, 이 작업보다 먼저 커밋). `assetMounts` 조회도 같은 자리에 넣었다.
- 화면 확인: 스크래치 시험 화면에서 실제 부품 + 실제 CSS 를 쟀다. 입력·단추 36px, 탭 28px, 첫 초점은 경로 칸, 목록 아이콘 초록·파랑·빨강, 깨진 소스 탭의 단추 색이 시안과 같다.
- 시험 범위: 이번에는 시험을 훅·API 이름(`useAssetProjectData`·`assetProjects`·`assetMounts`·`MountManager`·`AssetsView`·`AssetsSidebar`·`FolderIcon`)으로 찾아 14개 파일을 돌렸다.
- 전체 프런트 시험(다른 세션 작업을 뺀 사본): 5,985건 중 5,983건 통과. 실패 2건은 `tests/sceneBackup.test.ts` 로 하나는 5초 시간 초과였고, 같은 사본에서 그 파일만 3번 돌리면 39건 모두 통과했다. 이 작업은 씬 백업을 건드리지 않아 전체 실행의 부하 탓으로 본다(추정, 원인을 끝까지 파지는 않았다).
- 화면 글자 끝의 말줄임표를 뺐다(`등록 중`·`찾는 중`·`정리 중` — Jay 규칙).
- 찾을 수 없는 폴더의 빨강은 조회가 끝난 뒤 뜬다. 어셋 변경 알림에서는 다시 받지 않으므로, 폴더가 어셋 창을 연 뒤에 없어지면 다음에 열거나 공간을 바꾸거나 폴더 등록 창에서 무언가 바꿀 때 반영된다.
- 실제 NAS 가 끊긴 상태, 실제 프로젝트 데이터의 마크 색은 확인하지 않았다. Jay 5173 화면 확인 전이다.
