# 내 계정 창에 MCP 버전 표시 — 2026-10-22 (Jay 요청)

owner: Claude 총괄 · reviewer: Codex(묶음 검토 때) · status: 완료(dev 커밋 — Jay 화면 손 확인·Codex 검토는 묶음 때) · touched_paths: 아래 계약 · updated: 2026-10-22

고침: `/api/mcp/app/setup` 이 `adapter_version` 을 더 돌려준다(어댑터 파일의 `ADAPTER_VERSION = "…"` 줄을 정규식으로 읽음 — 실행·import 없음, 없으면 null). 내 계정 창이 창을 열 때 한 번 조회해 'CLI 버전' 다음 줄에 'MCP 버전' 을 보이고, 값을 모르면 줄을 숨긴다. 문서 `MCP_INTEGRATION.md` 의 setup 응답 설명에 한 줄.
검증: 백엔드 `test_mcp_bridge.py` 63 통과(새 시험 2 — 실행되면 깨지는 줄을 둔 가짜 어댑터에서 버전만 읽힘·파일 지우면 null, 저장소의 실제 어댑터 줄이 읽힘. 기존 setup 응답 비교 2곳에 새 칸) · 프런트 계정 창 시험 4 파일 42 통과(새 시험 2) · 프런트 전체 411 파일·4,898 통과(종료 코드 0, 아래 계정 메뉴 수정 포함)·구조 lint·빌드 통과 · `gen_inventory --check`·`check_code_map` 통과. 이 변경은 GitHub 후보 `0be464b8` 에 들어 있지 않다.
Codex 독립 검토(읽기 전용, gpt-6-astra/high, 세션 `01a1612c-fe0b-7dd3-ac6a-99ad665eaca2`, 대상 `e7f6ed68`·`0458e37b`·`7ac83025`) — 지적 1, 고침:
- R1 P1 서버 주소(`http://<IP>:8010`)로 연 브라우저는 보안 문맥이 아니라 `crypto.randomUUID` 가 없다 → 계정 창의 MCP 조회가 인자를 만들다 던져 창이 깨졌다(`.catch` 가 못 잡는 동기 오류). → `randomUUID` 가 있을 때만 조회(이 조회는 이 PC 앱에서만 답한다). 고치기 전 판에서 새 시험 실패(`crypto.randomUUID is not a function`) 확인 → 고친 뒤 통과. 같은 함수를 쓰는 다른 곳은 없을 때를 거르거나(`canvasGenerationRecovery`·`comfyApi`·`libraryBroadcast`·`librarySync`·`sceneAssetRelink`) MCP 창 전용이고, `useMcpCanvasTasks` 는 부르는 곳이 없다(코드 검색).
dev 백엔드 전체(`e7f6ed68` 뒤): 6,943 통과·2 skip·9 실패 — 9 개는 모두 `test_trash_transfer.py` 의 하위 프로세스 시험으로, 시험을 backend 폴더가 아닌 곳에서 돌린 탓(같은 파일을 backend 폴더에서 다시 돌리면 36 통과). 제품 결함 아님.
나머지 경로(정규식·CRLF·BOM, 옛 MCP 창이 새 칸을 무시, 늦은 응답 `alive` 차단, 상태줄 칸의 inert·폴더 창 차단, 초점·피커)는 Codex 가 결함을 특정하지 못했다. 배포 판단 = 추천 A(위 후보를 그대로, 이 묶음은 다음 판). 보이는 값은 **이 앱 폴더의 어댑터** 버전이다 — 앱을 업데이트한 뒤 Claude·Codex 가 MCP 를 다시 불러오기 전에는 옛 어댑터가 돌 수 있다(구분은 하지 않음, 아래 결정).

Jay: "여기 CLI 버전 밑에 MCP 버전도 들어가서 어느 버전인지 알 수 있게 하자." (내 계정 창 — 이메일·역할·플랜·크레딧·계정 식별자·CLI 버전 줄)

지금(코드 확인):
- 내 계정 창(`components/ManageAccount.tsx`)의 'CLI 버전' 은 에이전트가 보고한 값(`cliVersion`), '앱 버전' 은 릴리스 상태의 `current_version`(설치본 VERSION.txt)이다.
- MCP 버전 = 앱 폴더에 든 어댑터 `tools/mcp_adapter/server.py` 의 `ADAPTER_VERSION`(지금 `2026.10.16.5`). 어댑터가 MCP 서버 이름과 함께 LLM 에 알리는 값이고 `check_connection`·`connect` 응답에도 실린다. 허브(백엔드)는 지금 이 값을 모른다.
- `/api/mcp/app/setup`(MCP 연결 창의 '처음 연결 설정')이 이미 같은 어댑터 경로와 있는지 여부를 돌려준다 — 이 PC 앱에서만(loopback·탭 헤더) 열린다.
