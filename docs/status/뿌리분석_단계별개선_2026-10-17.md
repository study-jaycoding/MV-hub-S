## 유지·검토 범위

- SPA+CSR, 가상 목록·화면 밖 카드 생략·지연 로딩·낡은 응답 차단은 유지하고 측정한다.
- 개인 데이터·팀 데이터의 원본 소유권을 유지한다. DB 이전은 분석의 검토 후보로서 이관·동시 수정·구버전·복원 비용을 판단한다.
- URL 기록과 실제 미디어 보존, 브라우저 저장과 DB/외부 백업은 따로 확인한다.
- SSR/SSG·새 프레임워크·LangGraph·RAG·LLM 교체는 분석에서 적용 근거가 없다고 분류한 사항이다. 용어를 반영하려고 새 기능을 추가하지 않는다.

## 수행 기록

### 설계 합의와 경계

Claude 설계/합의 세션 `4f6e6e46-9506-4560-b93d-17bfcbecbb06`, 요청·실제 모델 모두 `claude-fable-5-1`, 요청 추론 `high`.
원응답은 `claude-design.jsonl`, `claude-agreement.jsonl`에 있으며 실제 승인 응답을 회수했다. 설계 호출의 초기 도구 목록에는
Read/Glob/Grep 외 진행표 MCP 두 개도 포함돼 있어 OS 읽기 전용 격리로 표현하지 않는다. 제품 변경은 Codex가 소유한다.

- **1단계 DB 검토 결론**: 현재의 개인 편집 문서와 파일 복구를 유지한다. 분석은 DB 원본화를 검토 후보로 제시했으며
  자동 다기기 동기화·자동 외부 보관은 확정 요구가 아니다. 이관·문서 버전·구버전 창·충돌·실패 복원·백업 경계를 새로
  바꿀 필요에 비해 현재 확인한 문제는 파일 보관·복원으로 대응한다. **보관하지 않은 편집은 프로필 손실 시 유실될 수 있다.**
  자동 보관 요구 또는 복원 파일로 해결되지 않는 실제 문제를 확인하면 DB 이관을 다시 설계한다. DB 자동 백업 구현 완료라는 뜻이 아니다.
- **2단계**: 기존 저장실패·백업누락 경고는 유지하고, SceneBar/EditTab의 펼치는 안내로 저장 범위만 설명한다.
  성공 여부를 새로 추정하지 않는다. 데이터 소유권 문서에 타임라인·Undo 원본을 추가한다.
- **3단계**: App의 표식 준비·저장확정·정착·폐기·복구 effect를 `useCanvasGenerationLinks`로 그대로 이동한다.
  5개 입력(authReady/scenes/flushScenePending/patchSceneById/setGens), 기존4개 콜백 반환.
  생성 요청 조립은 기존 `sceneGenerationInputs`/`sceneGenerationSubmission` 도우미와 App 배선을 유지한다.
  많은 화면 상태를 받는 거대한 새 훅을 만들지 않는다. 표식 저장→제출, 확정실패 정리, 결과불명 유지, 숨김/재시도 규칙을 검증한다.
- **4단계**: SceneBoard의 입력 저장 예약·확정·4개 카드 반영 모드만 `useSceneInputCommit`으로 이동한다.
  카드·연결·그룹·씬정체성·이동ref·전환/언마운트 effect와 `useSceneHistory`의 Undo 소유권은 유지한다.
  최신 flush ref의 렌더 중 갱신, 입력 먼저/파생 나중, 400ms debounce·2초 상한과 전환 틈의 쓰기 차단을 보존한다.
  실측에서 기존 즉시 새로고침 입력 유실을 재현하여 다음 단계 진행을 중단했다. 같은 Claude 설계 세션의
  보완 승인에 따라 기존 `holdUnload`를 입력 대기와 정상 저장 큐에도 적용한다. 데이터 형식은 바꾸지 않는다.
- **5단계**: 재현된 자동조회 중복2·떠난 화면의 폴링알림1·태그의 불필요집계1을 수정한다.
  자동조회 진행ref/시각은 두 경로가 공유, 태그는 목록만 갱신하되 같은 묶음의 일반 변경은 집계 필요를 OR로 보존한다.
  폴더·다른 PC 변경 안전망과 사용자 재시도는 유지한다. 새로운 이벤트 분류나 조회 큐 API를 만들지 않는다.
- **6단계**: 합성 생성물1000·카드100개 씬2·100클립의 고정 소스/자료로 전후 측정한다. 1000클립 저장 비용은 별도 조건이다.
  개발모드·변환 캐시·동시 시험의 CPU경합을 기록하고, 서로 다른 조건의 수치로 속도 개선을 주장하지 않는다.
- **7단계**: 실제 변경 경계·낡은 localStorage 주석·데이터 소유권·코드 색인을 맞추고 기존 구조/문서 검사로 확인한다.
