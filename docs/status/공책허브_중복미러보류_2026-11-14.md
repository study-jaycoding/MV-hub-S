## 설계(Claude 초안 · Codex 확정)
- 기능을 알고(`hubFeaturesKnown()`) 공책 기능(`scene_writer_v1`)이 있을 때만, '복원 보류' 수를 셀 때 **중복 보류**를 뺀다. 중복 보류 = 막힌 id X 에 대해 ① 지금 계정의 `::_none` 확정본에 씬 X 가 있고 ② originals 의 X 원본이 **모두** 그 씬과 카메라를 뺀 내용이 같다(`sameSceneContent({...a, camera: undefined}, {...b, camera: undefined})` — 기존 비교 함수, undefined 필드 무시) ③ X 가 어떤 original 의 ledger 에도 없다. original 하나는 막힌 id 중 중복이 아닌 것이 하나라도 있으면 지금처럼 센다.
- **쓰기 없음**: localStorage 미러 기록·blockedIds·originals 는 그대로. [보관본 내려받기]는 지금처럼 모든 originals 를 싣는다. 옛 허브(기능 없음 확인)·기능 모름에서는 지금과 같다(옛 허브에서 막힌 씬은 허브 복원본과 다를 수 있어 숨기면 안 된다).
- 확정 보강: 현재 계정·저장소 준비를 확인하고, 같은 ID의 원본은 세대를 가리지 않고 모두 비교한다. 본문 JSON 손상·본문 ID 불일치·실행 기록(comfyRuns·comfyCardRuns) 차이는 중복으로 보지 않는다. `sameSceneContent`는 실행 기록을 제외하므로 그 두 필드는 별도로 대조한다(키 순서 차이도 보수적으로 보류 유지). 어느 original의 ledger에라도 같은 ID가 있으면 유지한다. 기능 표식 변경 시 표시를 다시 읽는다. 보류가 모두 중복이라 경고가 사라져도 중립적인 [보관본 내려받기] 단추는 남겨 원본 접근을 유지한다.
