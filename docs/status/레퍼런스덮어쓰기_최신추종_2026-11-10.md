## 원인 (코드 확인, 실행 재현은 안 함)

1. 프로젝트 파일을 캔버스에 넣으면 참조 = `asset:<project>|<path>` + `target_project_id` + `content_sha`(`useSceneClipboardDrop.ts`).
2. 5초 주기 `syncSceneAssetReferences` 가 그 참조를 등록 → 허브가 그때 바이트를 관리 사본으로 복사·SHA 계산(`routers/asset_sync.py` `_snapshot_registration`) → 참조에 `asset_content_id` 기록(`features/canvas/assetRefs.ts`, 이미 있으면 안 바꿈). 서버 업로드가 끝나면 참조를 그때 판의 `asset-sync:` 사본으로 승격.
3. 승격 전에 덮어쓰면 카드는 버전표로 새 그림을 보이지만 생성 요청에 옛 `asset_content_id` 가 실리고(`spotlightSubmit.ts`) 허브가 `expected_asset_content_id` 로 옮겨(`usecases/gen_requests.py`) 작업자가 새 바이트와 달라 과금 전에 멈춘다(`agent_push.py`). 덮어쓴 뒤 재등록은 옛 id 를 기대값으로 보내 409 → 프런트가 조용히 삼켜 영구 고착.
4. 함께 찾은 구멍(Codex): 작업자 `execute_pending` 의 `ref_cache` 가 claim 묶음 사이에 같은 경로를 재사용 → 기대값만 빼면 진행 중 덮어쓴 뒤의 다음 요청이 옛 그림으로 조용히 생성. Comfy 는 서버 `_archive_input` 이 따로 cid 를 대조.
5. 설계 문서와 어긋남: [ASSET_LOCAL_SYNC](../ASSET_LOCAL_SYNC.md) §3 "캔버스의 논리 파일 최신 판 추종은 현행 동작으로 유지하되, 생성 시점에 실제 제출한 판을 다시 고정" · [ASSET_REGISTRY](../ASSET_REGISTRY.md) Jay 결정 "캔버스는 최신 판을 따라가고 생성 기록은 그때 판".

## 설계 (Claude v0.1 → Codex 1·2·3차 → v0.3 AGREE, Jay J1=B·J2=A)

- **live(원본 추종) 참조** = `file_path` 가 `asset:<project>|<path>` · project ∉ {`imports`, `captures`, `imp/cap`} · type `image`. 판정 기준은 저장된 원래 참조이며 화면·전송용 URL 이 아니다. 저장된 옛 `/api/assets/file?...` 형태·영상·오디오는 live 아님(기존 정책).
- D1 프런트: live 는 `/register`·resolve·승격 안 함 — `promoteAssetReference` 자체 + `syncSceneAssetReferences`(열린/닫힌 씬·Undo/Redo) + `SpotlightPrompt` 보관 동기화(트레이·인라인 칩·Library 초안). `content_sha`·대장 번호는 보존. 기존 cid 는 지우지 않는다.
- D2 허브: 새 생성에서 요청 참조와 실제 제출 경로가 **둘 다** live 면 `expected_asset_content_id` 를 넣지 않는다. 본문·멱등·placeholder 비교 그대로.
- D3 작업자: 프로젝트 원본 경로(`asset:` 이고 project ∉ 내장 3개, type 무관)는 claim 묶음마다 새로 받는다. 이전 묶음의 임시파일·매핑은 진행 중 요청을 위해 유지, 재다운로드 실패 시 옛 캐시로 돌아가지 않음, 같은 묶음 안 같은 경로는 한 번. 작업자는 live/type 을 모른다 — 기대값이 오면 그대로 대조.
- D4 Comfy: `gatherComfyMedia` 가 URL 변환 전에 원래 참조로 live 판정, live 면 입력 메타의 옛 cid 를 비운다. 서버 대조는 고정 참조에 유지.
- D5 실행 입력 지문: 일반 생성·Comfy 의 `asset_content_id || file_path` 식별에서 live 는 경로를 쓴다(`scenes.ts` 의 트레이 동기화 비교는 이미 각각 비교 — 손대지 않음).
- D6 문구: 고정 참조 불일치 → "레퍼런스(이름)가 예상한 내용과 달라 생성을 멈췄습니다 · 크레딧은 쓰지 않았습니다".
- 그대로: 재생성(당시 판 대조) · MCP(실행 전 트리 버전 검증 — 보장은 그 시점까지) · 고정 사본 대조 · 이미 `asset-sync:` 로 승격된 카드(자동 복원 안 함, 원본을 다시 넣어야 함).
- Jay 결정: J1=B 생성 기록에서 꺼낸 재료도 원본 경로로 나오면 최신(보관 위치로 투영돼 `asset-sync:` 로 나오면 그때 판) · J2=A 이번엔 이미지만.
- 잃는 것: live 원본의 생성 전 자동 보관·cid 기반 다른 PC 복구(생성 뒤엔 실제 보낸 판이 보관됨). 작업자 임시 디스크가 한 실행 안에서 같은 파일을 N 번 받으면 약 N×S(코드 구조상 산식, 미실측).
