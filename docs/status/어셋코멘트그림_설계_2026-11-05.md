## 1. 하려는 것 (한 줄)

어셋 탭에서 C(격자 칸·크게 보기 Ctrl 단추·c 키)를 누르면 생성물과 **같은 코멘트 그림 창**이 뜨고, 그린 그림이 그 파일의 코멘트에 붙는다. 이미지 = 캡쳐로 여러 장, 영상 = 프레임마다 한 장.

## 2. 지금 구조(확인한 것)

- 어셋 코멘트 = 표 `asset_comment`(프로젝트 + 파일 경로 기준). 생성물 코멘트(`generation_comment`)와 따로다.
- **공유 코멘트는 서버에 바로 쓴다**(로컬 허브가 `/api/assets/comments` 를 서버로 넘김 — `routers/assets_metadata.py`). 이 PC 에 사본이 없다.
- **비공개 코멘트는 이 PC 로컬 DB 에만** 있다(서버로 안 감).
- 그래서 생성물 때의 발행 꾸러미(v2)·되살아남 막기 표(tombstone) 같은 길이 **필요 없다** — 지우면 서버에서 바로 지워진다.

## 3. 바꾸는 것

| 자리 | 내용 |
|---|---|
| DB(서버·로컬 같은 표) | 새 표 `asset_comment_drawing` — 생성물 그림 표와 같은 칸(코멘트 id·순번·종류·크기·영상 시각·획 목록·작은 그림·내용 지문). 코멘트를 지우면 그림도 지운다 |
| 재시도 안전 | 새 표 `asset_comment_create_ledger` — 같은 요청을 두 번 보내도 코멘트가 둘 생기지 않게(생성물 comments-v2 와 같은 규칙: 같은 id·같은 내용 = 같은 결과, 다른 내용 = 409) |
| API | `POST /api/assets/comments-v2`(글 + 그림 0~12장) · `GET /api/assets/comments/{id}/drawings/{drawing_id}`(획) · `.../thumb`(작은 그림). 공유 = 서버로 넘김, 비공개 = 로컬 |
| 획 검사·지문 | 생성물 것(`services/comment_strokes.py`)을 그대로 쓴다 — 새로 만들지 않는다 |
| 서버 능력 표시 | `asset_comment_drawings: 1` — 이 표시가 없는 서버면 어셋 C 는 종전 작은 창(생성물과 같은 대체 규칙) |
| 화면 | 코멘트 그림 창이 '생성물' 대신 '어셋 파일'도 받게 넓힌다(오른쪽 지난 코멘트 = 그 파일의 공유 + 내 비공개). 어셋 칸 C·크게 보기 Ctrl 단추 C·c 키가 이 창을 연다 |
| 크기 한도 | 새 주소 5MiB(생성물 comments-v2 와 같음) |
| 계정 정리·신원 | 코멘트를 지우는 곳(`repo/account_cleanup.py` 등)이 그림도 함께 지우는지 확인·보강 |

## 4. Jay 가 정할 것

| # | 질문 | 추천 |
|---|---|---|
| A1 | 서버를 아직 안 올린 동안 어셋 C 는? | **종전 작은 창**(그림 없이 글만) — 서버 업데이트 뒤 자동으로 새 창 |
| A2 | 비공개 코멘트에도 그림? | **예** — 비공개는 이 PC 에만 저장(생성물과 같다) |
| A3 | 파일 이름을 바꾸거나 옮기면? | 지금 글 코멘트와 **같이 따라간다**(그림은 코멘트에 붙어 있어 따로 할 일 없음) — 확인만 |

## 5. 위험과 확인할 것

- **서버 업데이트 필요**(새 표·새 주소). 순서 = 서버 먼저 → 앱 릴리스. 옛 앱은 새 표를 모르니 그림만 안 보이고 글은 그대로.
- 새 표 2개 → 서버 DB 이름표·업데이트 검사 대상(지난 배포에서 "새 DB 이름표는 서버 업데이트를 막는다" 함정 — 생성물 때처럼 기준 목록에 넣지 않는 규칙을 따른다).
- 시험: 백엔드(재시도 409·지우면 그림도·비공개는 서버로 안 감·능력 표시 없을 때 거절) · 프런트(어셋 C → 새 창·대체 규칙·지난 코멘트에 어셋 그림).
