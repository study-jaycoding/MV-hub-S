# 빈 프롬프트 커서 자리 · Shift+Backspace 칸별로 되돌림 — 2026-10-22 (Jay 요청)

owner: Claude 총괄 · reviewer: Codex(독립 검토 C1~C3 반영) · status: 완료(dev 커밋 — Jay 화면 손 확인 전) · touched_paths: 아래 계약 · updated: 2026-10-22

고침: `.sl-prompt[data-empty]::before` 를 `position:absolute`(위 4·왼 6·오른 84 — 글 여백과 같다)로, `.sl-prompt` 에 `position:relative` · Shift+Backspace 를 초점 자리만으로 되돌림(`useSpotlightTray` 는 `3d832a8b` 이전과 글자까지 같음, 프롬프트 쪽은 `clearPrompt` 만).
Codex 독립 검토(읽기 전용, gpt-6-astra/high, 세션 `01a16150-9ac9-7823-bd4b-9e43bee9a83b`, 대상 `3d832a8b`·`5cc89ada`) 지적 3건, 모두 고침:
- C1 P2 프롬프트 드롭다운(open)이 열려 있으면 다른 메뉴(역할 메뉴)가 떠 있어도 Shift+Backspace 가 지웠다 → `keyGate.backgroundBlockCount()` 로 자기 한 겹만 빼고 센다.
- C2 P2 캔버스에서 프롬프트 지우개를 누르면 초점이 돌아오지 않았다(blur → focusout 이 허용 표식을 지워 focusin 이 튕김, 옛 Shift+Backspace 도 같았다) → 되돌리는 초점 앞에 `allowFocusRef` 를 세운다.
- C3 P2 넘친 레퍼런스 칸에서 sticky 비우기 단추가 썸네일 위를 덮었다 → 칸을 바깥 틀(.sl-reftray — 초점·키·놓기·아래 선)과 안쪽 스크롤 칸(.sl-reftray-scroll)으로 나누고 단추를 스크롤 밖에.
검증: 새 시험 5(칸별 Shift+Backspace · 안내 문구 규칙 · C1 · C2 · C3) · 관련 시험(seedancePromptRender·seedanceRoleMenuRender·spotlightTrayReady·keyGate) 61 통과 · 프런트 전체 413 파일·4,908 통과(종료 코드 0)·구조 lint·빌드 통과 · 격리 S 서버(dev 빌드) 실제 브라우저 4/4 — 빈 프롬프트 문구 absolute · 문구 오른쪽 빈 곳을 눌러도 커서 offset 0(맨 처음) · 치면 문구 사라지고 글이 앞에서 시작 · 레퍼런스 20개 중간 스크롤에서 스크롤 칸 끝(1375) ≤ 단추 왼쪽(1375)·복사와 같은 세로줄. 고치기 전 판에서 새 시험이 실패하는지는 돌려 보지 않았다(dev 가 Jay 의 실사용 창이라 되돌려 확인은 생략).

Jay:
1. "아무것도 입력이 안 되어 있을 때 입력하려고 누르면 문구 뒤에 커서가 붙는다. 누르면 앞쪽에 커서가 있고 문장이 보이다가 입력하면 문장이 사라지면 된다. 이런 부분들이 있는지 찾아보고 수정하자."
2. "Shift+Backspace 로 전체 지우는 건 다시 각각 나눠서 — 레퍼런스 누르고 하면 거기만, 프롬프트 누르고 누르면 거기만." (`3d832a8b` 에서 둘 다로 바꾼 것을 되돌림. 비우기 단추는 그대로)

지금(코드 확인): 프롬프트 안내 문구는 `.sl-prompt[data-empty]::before { content: attr(data-placeholder) }` — 글줄 안에 놓여 빈 칸을 누르면 커서가 문구 **뒤**에 선다. 같은 방식(::before 의 attr 안내 문구)은 앱에서 이 한 곳뿐이다(`attr(data-placeholder)`·`:empty::before` 전수 검색). 다른 입력칸은 브라우저 기본 placeholder 라 커서가 앞에 선다.
