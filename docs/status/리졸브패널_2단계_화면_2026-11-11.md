## 화면

- 머리: `MV Hub` · 프로젝트 고르기 › 시퀀스(편집 탭과 같은 규칙: 시퀀스 = 폴더 P, 컷 = 직계 하위 폴더 · 마지막 고른 것은 이 창 저장소에 기억) · 상태 줄 "리졸브 빈: MV Hub/…/C0010" ·
  한 줄 안내 "이 창이 리졸브 미디어 풀의 지금 빈을 고른 컷으로 바꿉니다" · 지금 빈이 다르면 "리졸브 지금 빈이 'C0010' 이 아닙니다 · [맞추기]"(자동으로 되돌리지 않음).
- 왼쪽: 컷 목록(자연 정렬 · 공유물 수 · ★최종/보류 개수 — 공유 & 리뷰 사이드바와 같은 개수 조회). 오른쪽: 고른 컷의 공유물 카드(편집 탭 풀과 같은 조회·거르기).
- 카드: 썸네일(`MediaThumbnail`) · 작성자 · 모델 · 길이 · 날짜 · ★최종/보류 · 상태 줄(받는 중 · 끌 수 있음 · NAS 준비 중 · 리졸브 'C0010' 빈에 있음 · 확인 못 함 [다시 확인] · 다른 빈에 있음 · 표시 충돌 · 프로젝트가 바뀜 · 실패 까닭).
- 리졸브 밖(일반 브라우저 — 끌기 다리 `window.mvhubResolve` 없음)에서 열면 목록은 보이고 끌기는 막힌 채 "리졸브의 MV Hub 창에서만 끌어 넣을 수 있습니다".
  **이때는 읽기 전용이다** — `cache`·`target`·`prepare`·`adopt`·`current-bin` 을 하나도 부르지 않는다(열린 리졸브의 지금 빈·빈 만들기·NAS 복사·로컬 캐시에 부수효과 0). 구현 뒤 확인에서 찾아 계약에 더함(2026-11-11).
- 글자 끝에 "..." 를 쓰지 않는다(Jay 규칙).

## 흐름

1. 열 때 `GET /api/resolve/panel/identity` → 문맥(instance·account·epoch)·판 범위. **1.5초마다**(앞 응답 뒤 · 끌기 허용 기준 2초보다 짧게 — 같은 2초로 두면 왕복 시간만큼 끌기가 막힘, 독립 리뷰 P3)·창 초점 때 다시 — 바뀌면 목록·준비·target·카드 상태를 모두 버리고 새로 읽는다.
   - **account 는 요청한 사람 기준**: AUTH-on 이면 그 요청의 로그인 계정(email) 해시, AUTH-off 면 허브 활성 계정 키 해시. 쓰는 요청의 문맥 검사도 같은 기준(AUTH-on 에서 다른 계정으로 로그인하면 `account_changed`). [C2-2]
   - 화면은 인증 만료·로그아웃·다른 계정 로그인 이벤트(앱의 인증 이벤트·저장소 변화)에도 상태를 모두 버리고 끌기를 막는다(로그인이 필요하면 `LoginScreen`). 그 전 요청의 늦은 응답은 버린다.
   - **창 id**: 페이지를 열 때마다 무작위 `window` id 를 만들고 seq 를 싣는 요청(cache·target)에 함께 보낸다. 백엔드는 순번을 (문맥, window) 별로 둔다 — 창을 다시 열거나 두 창을 띄워도 서로를 `stale` 로 만들지 않는다. [C2-1]
2. 컷을 고르면 순번(seq)+1 → `POST cache`(그 컷 카드, 로컬 캐시만 — **500개씩 나눠 차례로**, 빈 목록이면 안 보냄, 컷이 바뀌면 남은 묶음은 보내지 않음) · `POST target {create:false}`(빈이 있으면 지금 빈으로). `target` 이 `missing` 이면 "리졸브 빈은 첫 끌기 때 만듭니다". [C2-4]
3. 카드에 포인터를 누르면: 그 컷 빈이 아직 없으면 `target {create:true}` · 그 카드가 NAS 준비 전이면 `POST prepare`(카드 한 장). 둘이 끝나기 전의 `dragstart` 는 시작하지 않고 "준비 중 — 다 되면 다시 끌어 주세요".
4. `dragstart`: 다리 있음 · 판 호환(다리의 판이 identity 범위 안, 그리고 다리도 화면 판을 받음) · 그 카드 prepared · target ok(같은 리졸브 프로젝트) · 마지막 문맥 확인이 2초 안이고 같음 — 전부일 때만 `preventDefault` 뒤 `mvhubResolve.startDrag(path, {protocol: 1})`.
   돌려준 값이 `false` 면 끌기가 시작되지 않은 것이다 — adopt 를 부르지 않고 "리졸브 창의 판이 맞지 않습니다 — 리졸브를 다시 켜 주세요".
5. 끌기를 시작하면 앞 응답을 받은 뒤 1초 쉬고 최대 8번 `POST adopt`. 응답 상태마다 화면이 하는 일 [C2-5 · Claude 합의 검토]:

   | adopt 상태 | 화면 |
   |---|---|
   | `in_bin` | 멈춤 · "리졸브 'C0010' 빈에 있음" |
   | `conflict` · `elsewhere` · `project_changed` | 멈춤 · 사실만(두 id / 그 빈 / 프로젝트가 바뀜) · [다시 확인] |
   | `account_changed` | 흐름 1 처럼 상태 전부 버림 |
   | `not_seen` | 다음 시도(그동안 카드는 "확인 중"만 · 단추 없음) · 8번 뒤에야 "확인 못 함 — 놓지 않았거나 다른 빈" · [다시 확인] |
   | `busy` | 다음 시도(횟수에 안 셈 · 그동안 "확인 중"만 · 단추 없음) · 누적 30초 넘으면 "확인 중 — 리졸브가 바쁨" · [다시 확인] |
   | `not_prepared` | 그 카드의 준비 기록을 버리고 `prepare` 를 다시 → 성공하면 adopt 를 **한 번만** 다시 · 실패면 그 까닭 |
   | `stamp_failed` · `save_failed` · `ledger_failed` · `unknown` | 즉시 멈춤 · 그 까닭 · [다시 확인](같은 adopt) — "빈에 있음"으로 보이지 않음 |
   | `rebuild_recovery_pending` | 즉시 멈춤 · "리졸브 보내기 정렬 복구가 끝나지 않았습니다 — 복구 뒤 다시" · 끌기 막음 · [다시 확인] 없음 |
   | HTTP 오류(400 위치 불일치·503 시작/업데이트 중 등) | 즉시 멈춤 · 서버 문구 · [다시 확인] |

   | target 상태 | 화면 |
   |---|---|
   | `ok` | "리졸브 빈: …" · 그 컷 끌기 허용 조건 충족 |
   | `missing` | "리졸브 빈은 첫 끌기 때 만듭니다" |
   | `stale` | 조용히 버림(실패로 보이지 않음) |
   | `account_changed` | 상태 전부 버림 |
   | `busy` | "확인 중" — 다음 누름·컷 선택 때 다시 |
   | `rebuild_recovery_pending` | 복구 안내 · 끌기 막음 |
   | `unavailable` · HTTP 오류 | "리졸브에 연결하지 못했습니다"/서버 문구 · 끌기 막음 |
6. 패널이 보이는 동안 2초마다 `GET current-bin`(앞 응답 뒤에만) — `busy`·실패는 "확인 중", 지금 빈 id ≠ target 빈 id 일 때만 "다름" 줄.
7. AUTH-on(개발)에서 로그인 전이면 앱의 `LoginScreen` → 로그인 뒤 다시 읽음. 워크스페이스는 **공유 & 리뷰의 '전체 보기'와 같은 조회**(이 창은 앱의 워크스페이스 선택을 모름).

## 끌기 다리(3단계 플러그인이 지킬 약속 — 이번엔 화면 쪽만)

`window.mvhubResolve = { protocol: number, accepts: {min, max}, startDrag(path: string, opts: {protocol: number}): boolean }` — 화면은 `protocol` 이 identity 의 `{min,max}` 안이고 화면 판(1)이 `accepts` 안일 때만 부르고,
**화면 판을 `opts.protocol` 로 넘긴다**. 플러그인은 그 판이 자기 `accepts` 밖이면 끌지 않고 `false` 를 돌려준다(3단계 약속) — `false` 면 화면은 "리졸브 창의 판이 맞지 않습니다 — 리졸브를 다시 켜 주세요". 이번 단계는 모의 다리로 전달·거절 처리를 시험. [C2-3]

## 1단계 리뷰 P3 (같이 고침)

① 빈 이름 원천 하나: target·adopt 모두 같은 함수(프로젝트 이름 = `repo.get_project` 이름, 없으면 준비 때 생성물의 `project_name`)로 목적 빈·복구 관문 `managed_identity` 를 정한다.
② target 에 프로젝트 열람 권한 판정(일반 보내기·폴더 조회와 같은 기준) — 못 보면 거절.
③ target·adopt 경로에 문맥 전환 주입 시험(가짜 자식 안에서 인스턴스 id 를 바꿔 `account_changed`·장부 미기록 확인).
