# MV Agent 작은 것 셋 — 답 글 '>' 반복 · 붙인 자료 번호 · 옛 이름 (2026-11-12)

owner: Claude(설계·구현) · reviewer: 남은 요청 묶음 끝 독립 리뷰 · status: 검증 중(dev 커밋 · 8012 재시작·Jay 확인 전) · updated: 2026-11-12

## 1. 요청

- Jay 11-12 "모두 구현하자" — 남은 목록의 'Jay 답을 기다리는 것' 가운데 작은 셋을 추천안으로:
  1. **답 글 '>' 반복**(11-11 한 줄 묶기 때 남김) — AI 가 계획의 card_text 를 답에 인용(>)으로 다시 옮겨 써 칸이 길어진다.
  2. **붙인 자료 번호**(11-12 제안) — 칩이 여럿이면 "레퍼런스1? 이미지1?" 이 헷갈린다.
  3. **옛 이름** — AI·로그에 보이는 글에 'Ask Agent' 가 남았다.

## 2. 설계

1. 원인 = 칸 모드 어댑터가 `prepare_generation_plan` 에 일반 연결 설명("반환되면 card_text 를 별도 텍스트로 안내")을 그대로 준다. → 칸 모드 설명 `PANEL_DESCRIPTIONS["prepare_generation_plan"]` 과 `PANEL_INSTRUCTIONS` 에 "계획은 칸에 카드로 뜨니 card_text 를 답에 옮겨 쓰지 말고 한두 줄로 무엇을 계획했는지만" · 허브 GUIDE 에도 같은 한 줄. 어댑터가 바뀌었으니 `ADAPTER_VERSION` 2026.11.12.3(설치본 갱신 판정). 일반 연결(Claude 앱·Codex 등록)은 그대로.
2. 칩·내 말 위 붙인 자료에 **붙인 순서 번호(1, 2, …)** 를 단다. 허브 GUIDE 에 "붙인 자료는 붙인 순서대로 1번·2번… — 사용자가 '1번'·'두 번째'라고 하면 그 순서" 한 줄(붙인 자료 JSON 의 items 순서 = 칩 순서, 이미 그대로).
3. AI·로그에 보이는 두 문구(`mcp_v2` 409 안내 · `agent_chat_process` 실행 거절)를 'MV Agent' 로. 주석·시험 이름은 그대로.

## 3. 시험

- 어댑터: 칸 모드 prepare 설명·지침에 '옮겨 쓰지 말' 문구, 일반 연결 설명은 그대로.
- 허브: GUIDE 두 줄.
- 화면: 칩 번호·내 말 위 번호(정보 칸 '이 대화에서 만든 것'은 번호 없음).
- 칸 시험 전체 + 백엔드 agent_chat·mcp 시험 + 어댑터 시험 + 빌드·경계 검사.
