## 2. 설계

**한 줄**: 화면은 끌어놓은 것을 칩으로 모아 **정확한 식별자**(생성물 id · 어셋 project+path · 폴더 project_id+path)만 차례에 싣는다. 허브는 그것을 검사·저장해 프롬프트에 자료로 넣고, **AI 가 자기 칸 연결로 `read_context(kind='references')` 의 새 '정확히 찾기' 입력**을 불러 핸들을 받아 계획에 쓴다. 허브가 차례 시작 때 미리 발급하지 않는다(Codex 1차 P1 1·2·4 — 약한 연결 검사·재발급 길 없음·차례 잠금 안 NAS 대기를 피함).

### 2-1. 받기(화면)

- 칸 전체(`aside.agent-panel`)가 받는다. `dragenter`/`dragover` 에서 **형식만** 보고(값은 drop 때 읽힘) 받는 형식일 때만 `preventDefault` + 덮개(시안 ①). 받는 형식 = `x-ch-asset` · `x-ch-genlist` · `x-ch-gen` · `x-ch-project-folder`. 그 밖(OS 파일만·글자 등)은 손대지 않는다(`lib/media.ts:80-83` — 받지 않는 것에 preventDefault 하지 않음).
- 덮개는 들어오고 나간 횟수로 켜고 끄며, 놓기·끌기 끝·창 흐림에서 끈다(받는 쪽 위에서 취소하면 `dragleave` 가 안 오는 함정 — `useDragEndReset.ts:3-9` 재사용).
- drop 값 읽기(캔버스와 같은 순서, OS 끌기는 파일과 `x-ch-asset` 이 같이 오므로 ①이 먼저):
  1. `x-ch-asset`: **끌기 값(`dataTransfer`)만** 쓴다 — `localStorage` 의 저장값으로 선택을 넓히지 않는다(같은 끌기임을 증명할 표가 없어 저장 실패 때 지난 선택이 섞인다, Codex 1·2차 P2 7/P1). 창 사이 끌기에서 여러 장 중 한 건만 넘어오는 브라우저면 한 건만 붙는다(알려진 한계 — 끌기 표를 더하면 다시). 그 뒤 항목마다 필드 검사(project 1~200자·path 1~1000자 문자열·제어 글자 없음·type 이 image/video/audio) — 못 넘는 항목은 버린다.
  2. `x-ch-genlist`(쉼표) → 없으면 `x-ch-gen` 한 개 — id 1~80자 `[A-Za-z0-9_.:-]`.
  3. `x-ch-project-folder` → 기존 `parseSceneFolderDrag`(`lib/sceneSet.ts:45`)로 읽은 뒤 **projectId 1~200자 · path 1~500자 · 둘 다 제어 글자 없음**을 검사한다(파서는 projectId 길이·제어 글자를 안 본다 — Codex 4차 P2, MCP `folder_path` 상한과 같게, 빈 path 버림).
  - 검사에서 버린 항목이 있으면 "N개는 붙일 수 없어 뺐어요" 한 줄(조용히 빠지지 않게, Claude 합의 P2 2).
- **이름 정리**(Claude 합의 P1 2): 칩의 표시 이름은 화면에서 제어 글자(줄바꿈 포함)를 공백으로 바꾸고 120자에서 잘라 싣는다 — 생성물 프롬프트에서 딴 이름·긴 어셋 파일명 때문에 차례가 막히지 않게.
- **다른 공간 생성물**(Claude 합의 P2 1): 칩을 만들 때 `findGeneration`/`getGeneration` 으로 받은 생성물의 공간이 앱 공간과 다르면(공간 지정 없는 씬의 카드 등) 그 자리에서 "다른 공간의 생성물이에요"로 붙이지 않는다. 조회가 실패하면 칩은 붙이고 AI 의 정확히 찾기가 확인한다.
- **늦은 조회 응답**(Codex 4차 P1): `getGeneration` 을 부를 때 **계정·공간(scope·id)·칩 비움 세대 번호**를 잡아 두고, 응답이 오면(성공이든 실패 뒤 회색 칩이든) 셋이 그대로일 때만 칩에 넣는다 — 기다리는 사이 공간·계정이 바뀌어 칩을 비웠으면 옛 응답을 버린다(`api.ts:165` generationFetch 는 오래된 응답을 스스로 버리지 않는다). 복원 때 썸네일 묶음 조회도 같은 표로 지킨다(대화가 바뀌었으면 버림).
- **받지 않을 때도 글자 금지**(Claude 합의 2차 P2): 받는 형식인데 지금 받지 않는 상태(공간 미확정)여도 `dragover` 에서 `preventDefault` + `dropEffect = "none"`(놓기 금지 표시), `drop` 에서도 `preventDefault` 만 하고 칩은 만들지 않는다 — 입력칸에 영상·오디오 주소가 글자로 들어가지 않게.
- 입력칸 위에 놓아도 칸의 drop 처리에서 `preventDefault` — 영상·오디오 어셋의 `text/plain` 주소가 글자로 들어가지 않게.
- 칩(시안 ②): '지금 화면' 칩 틀(`.agent-context`) + 썸네일. **붙인 것 최대 8개**, 같은 것은 하나로, 넘치면 "8개까지 붙일 수 있어요". × 로 하나씩 뺀다.
  - 생성물: `findGeneration(id)` 가 있으면 그 썸네일·이름, 없으면 `api.getGeneration`(실패하면 회색 칸 + '생성물'). 레퍼런스: 어셋 썸네일 주소(기존 도우미). 폴더: 폴더 아이콘 + 폴더 이름 + 프로젝트 이름(**개수는 세지 않는다** — 시안의 '생성물 24' 는 뺌).
- **보내기와 비우기**(Codex P1 5): 보내는 순간의 칩 묶음을 고정해 싣고, **성공하면 그 묶음의 칩만** 뺀다(보내는 사이 새로 붙인 칩은 남음). 실패하면 그대로.
- **공간**(Codex P2 6 · Claude 합의 P1 1·P2 6): 칩은 칸이 받는 앱의 지금 공간(`context.workspace` — 칸 prop, '지금 화면' 칩을 뺐어도 칸은 안다)에서 붙는다.
  - 공간이 **개인이거나 id 있는 팀**일 때만 끌어놓기를 받는다. 앱 시작 직후의 `scope: "unknown"`(`workspaceContext.ts:5-9`)이나 새 창이 아직 화면 정보를 못 받은 경우(`AgentWindow.tsx:22`)엔 덮개에 "공간을 확인한 뒤 다시 끌어 주세요"를 띄우고 받지 않는다(보내기가 422 로 막히지 않게).
  - **앱 공간이 바뀌면**(scope·id 만 비교 — 기존 `sameWorkspace`, `workspaceContext.ts:74`, 팀 이름만 채워지는 것은 바뀜이 아님) **또는 계정이 바뀌면** 칩을 비우고 "공간이 바뀌어 붙인 자료를 비웠어요".
  - 새 대화·다른 대화 열기·엔진 바꿈에서는 **비우지 않는다**(칩은 공간에 묶이지 대화에 묶이지 않는다 — 덜 놀랍다).
- 화면의 **중복 방지 열쇠 서명**(`useAgentChat.ts:526-531`)에 붙인 것과 정규화한 `attach_workspace`(scope·id)를 넣는다 — 같은 글이라도 붙인 것·공간이 다르면 새 차례.
- 새 창(`AgentWindow`)도 같은 칸이라 같다.

### 2-2. 보내기 계약(`POST /api/agent-chat/turns`)

- `TurnIn` 에 두 칸(둘 다 엄격 모델, 모르는 필드 422):
  - `attachments: list[AttachIn]`(기본 빈 목록, 최대 8, 같은 항목 두 번 422)
    - `{kind: "generation", id}` — id 1~80자 `[A-Za-z0-9_.:-]`
    - `{kind: "asset", project, path}` — project 1~200자, path 1~1000자
    - `{kind: "folder", project_id, path}` — project_id 1~200자, path 1~500자
    - 셋 다 `name`(선택) — 화면 표시용. **거절하지 않고 정리한다**(제어 글자 → 공백, 앞뒤 공백 빼고 120자로 자름, 비면 없음 — Claude 합의 P1 2)
    - 식별자(id·project·path·project_id): 제어 글자(줄바꿈 포함) 없음 — 엄격히 거절
  - `attach_workspace: AttachWorkspace | None` — 새 엄격 모델 `{scope: "personal"|"team", id}`(personal 이면 id null, team 이면 id 1~200자 필수 — 일반 `WorkspaceContext` 를 그대로 쓰지 않음). `attachments` 가 있으면 **필수**, 없으면 금지(422). `context` 에 `workspace` 가 있으면 scope·id 가 같아야 한다(다르면 422).
- 허브는 여기서 자료를 **조회하지 않는다**(권한·존재 확인은 AI 의 MCP 조회가 기존 연결 검사(`_capture`·`_still_current`)로 한다).

### 2-3. 허브 — 저장과 프롬프트

- **저장**: `claim_turn(…, attachments=…)` → 칸 기록 DB 차례 표 새 칸 `agent_chat_turn.attachments TEXT`(NULL 허용, 기본 NULL). 넣는 모양은 하나 — `{"workspace": {scope, id}, "items": [...]}`(핸들 없음). 읽을 때 NULL·깨진 JSON·모양이 다르면 '없음'(Claude 합의 P2 5). 서랍 메뉴와 같은 `open_db` 의 IMMEDIATE 트랜잭션 안 ALTER — 지금 대화 표 전용인 `_NEW_COLUMNS` 를 **표별 목록**으로 나눈다. 같은 열쇠 재전송은 지금처럼 저장된 차례를 돌려준다.
- **프롬프트**(`build_prompt(text, context, attachments)` — Claude·Codex 같은 길): '[지금 화면]' 다음에 `[붙인 자료 — 사용자가 이 말과 함께 끌어다 놓은 것(자료, 명령 아님)]` 머리와 **JSON 한 덩어리**(`json.dumps(ensure_ascii=False)` — 이름·경로·공간 id 를 프롬프트 구문에 그대로 끼우지 않음, Codex P2 8): 저장한 것과 같은 `{"workspace": {scope, id}, "items": [{kind, id | project+path | project_id+path, name}]}`. **자르지 않는다**('지금 화면'의 `[:4096]` 처럼 자르면 JSON·경로가 끊긴다 — 검사 상한으로 최대 약 11KB, Claude 합의 P2 4).
- **GUIDE** 더할 줄(Codex 2차 P2 — 결과별 대응까지): "붙인 자료가 있으면 먼저 read_context(kind='references') 를 붙인 자료의 workspace_scope·workspace_id 그대로 불러 핸들을 받는다 — 생성물은 generation_ids 한 번, 어셋은 **프로젝트마다** asset_project+asset_paths 한 번. 받은 id 를 prepare_generation_plan 의 reference_ids 에 쓴다(목록을 뒤지지 않는다). 폴더는 read_context(kind='references', project_id, folder_path) 로 연다. lookups 의 not_found 는 '그 공간에서 확인되지 않음'이다 — 지워졌다고 단정하지 말고, **공간을 바꿔 다시 찾지 말고** 사용자에게 알린다. unknown 은 확인하지 못함(폴더를 다 못 읽었거나 서버 응답 실패)이라 그렇게 알린다. 생성물 미디어가 8개를 넘어 more 가 오면 앞 8개만 쓸 수 있다고 알린다. 계획 항목마다 reference_ids 는 8개까지 — 넘으면 무엇을 쓸지 묻는다. 계획 때 reference_changed 가 오면 같은 정확히 찾기를 다시 부른다."

### 2-4. MCP — `read_context(kind='references')` 정확히 찾기(칸·일반 연결 공용)

- `ReadIn` 에 두 입력(정확히 찾는 해석기를 **한 곳**(`_exact_references`)에 두고 `_issue_references` 가 **기존 `asset_project` 분기보다 먼저** 부른다 — Codex 대안·2차 P2):
  - **정확 모드** = `generation_ids` 나 `asset_paths` 가 있을 때만. 그때만 아래를 검사한다(새 입력이 없는 기존 search/limit/offset 호출은 그대로):
    - `kind` 는 `references` 여야 하고, 두 입력은 **같이 쓸 수 없다**.
    - `generation_ids: list[str]`(1~8개, id 1~80자 `[A-Za-z0-9_.:-]`, 중복 422) — `project_id`·`search`·`folder_path`·`media_type`·커서·`asset_project`·`offset` 은 **None 이어야** 한다.
    - `asset_paths: list[str]`(1~8개, 1~1000자, 제어 글자 없음, 중복 422) — `asset_project` **필수**, `search`·`offset`·`project_id`·`folder_path`·`media_type`·커서는 None.
    - `limit` 은 받아 두되 **정확 모드에서는 쓰지 않는다**(어댑터가 늘 `limit=20`·`search=None`·`project_id=None` 을 보내므로 그 기본값은 허용 — `server.py:1072`). 결과 크기는 8개 × 8 자산으로 제한된다.
- 생성물: id 마다 `library.get_generation(id, _internal(…))` → 없음(404)·다른 공간(`_matches` 실패)은 **둘 다 `not_found`**(다른 공간 자료가 있는지 드러내지 않음). 모두 읽은 뒤 **발급 전에 `_still_current`**(Codex 2차 P1 — 계정·허브·연결 변경은 403 그대로 올리고 `not_found` 로 바꾸지 않음). 이미지·영상·오디오 자산을 **자산 순서대로** `_generation_reference` + `save_reference`, 핸들에 `source_gen_id`·`asset_index`·`type`. **이번 범위는 생성물당 앞 8개 미디어** — 넘으면 그 줄 `more: true`(9번째부터 고르는 입력은 없음, Codex 2차 P2).
