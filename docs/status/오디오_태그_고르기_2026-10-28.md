# 오디오 — ElevenLabs v4 감정·발성 태그 고르기(A [+ Tag] 단추 · B `[` 목록)

요청 근거: Jay 2026-10-28 수정 창 세션(`local_ae7891b3…`)에서 시안(`tags_mock.png`)을 보고 **"A+B 둘 다"**, 이어서 "이 오디오 부분 작업은 agent work (audio) 세션으로 넘기자" — 그 세션이 이 세션으로 넘김(인계 메시지에 Jay 원문 인용).
진행 방식: Codex 크레딧 문제로 Claude 단독(Jay 지시 — [Codex 사후 점검 대기](Codex_사후점검_대기_2026-10-28.md)). 작은 작업(minor).
선행: [오디오 2-A](오디오_2A_TTS모델_2026-10-28.md) — v4 는 저장된 대본 한 줄을 CLI 제출 때 `dialogue[0].text` 로 바꾼다. 태그는 **대본 글자**로 들어가므로 제출·서버·에이전트는 바꾸지 않는다.

## 확인한 사실(2026-10-28)

- 힉스필드 웹(비로그인) 모델별 대사 칸: **ElevenLabs v4 만 `+ 태그` 단추**가 있고 안내 문구도 "[laughs] 같은 오디오 태그를 사용해…". v4 Turbo·v3 는 일반 스크립트 칸(태그 단추 없음) — 이 세션에서 모델을 바꿔 가며 직접 확인.
- 태그 표(웹 번들 `01bd19df-1j8TmdZbdpRrdjML.js`, 수정 창 세션 조사·이 세션 재확인): emotion 7 · vocalizations 12 · delivery 6 · character 3 · sound-effects 12 = 40개.
- 웹의 `[` 규칙(같은 번들): 커서 앞 마지막 `[` 부터 커서까지가 검색어 — 그 사이에 `]`·줄바꿈이 있거나 커서 뒤가 `…]` 로 닫혀 있으면 목록 아님 · 목록에 없는 입력은 그대로 넣는 custom 항목 · 넣을 때 앞 글자가 공백이 아니면 앞에 공백 하나, 뒤에 공백 하나(이미 공백이면 그것을 쓰고, 다음이 줄바꿈이면 생략), 값은 `[값]`.
- 모델이 태그대로 읽는지는 **유료 생성 미확인**.

## 결과

- A: `SpotlightPromptRow` 에 `onAudioTag` — 있을 때만 `[+ Tag]` 단추(비우기 왼쪽, 위 8·오른쪽 88px)와 위로 뜨는 묶음별 태그 창. 알약을 누르면 커서 자리에 넣고 창은 열린 채. Esc(`useEscapeClose` 한 겹)·이 줄 밖 누름으로 닫힘 — 글 칸을 누르는 건 커서 옮기기라 열어 둔다(여러 자리에 연달아). 단추가 있을 때 글 칸 오른쪽 여백 84→150px.
- B: `SpotlightPrompt` 의 `atagQuery` — 글이 바뀔 때(promptTick)·커서가 움직일 때 `audioTagTrigger` 로 다시 잰다(v4·글 칸에 초점·IME 조합 아님·@/# 고르기 아님일 때만). 목록 = `AudioTagList`(`.sl-mention` 모양, 묶음 머리). ↑↓·Enter·Tab 은 기존 @/# 처리와 기록 탐색(↑↓)보다 먼저. Esc 는 그 `[` 를 '닫음'으로 기억해 같은 `[` 뒤에 더 쳐도 다시 열지 않는다(다른 `[` 면 다시 연다).
- 넣기: `insertAudioTag` — 웹 띄어쓰기 규칙. [+ Tag] 창에서 넣을 때는 `[` 목록이 열려 있을 때만 `[검색어` 를 바꾼다(Esc 로 닫은 `[` 는 글자로 둔다 — 시험 중 발견해 고침).
- 화면 확인: 실제 부품·앱 CSS 를 띄운 격리 화면(저장소 밖, 백엔드 없음)에서 단추 간격 6px·높이 같음, 알약 누른 뒤 초점이 글 칸에 남고 커서 자리에 `[sighing]` 이 들어감을 확인. 앱(5173) 화면은 Jay 확인 전.
- 미확인: 모델이 태그대로 읽는지(유료 생성 안 함).
