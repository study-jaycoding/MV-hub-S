# 배포 후보 넓은 리뷰 — 복원 세대(1C-1) 카드 의도 격리 지적 2건 고침 (2026-11-15)

Jay 11-15 "배포 가능하게 검증하고 딜레이나 버그등을 모두 수정하자". 후보 `b0816844` 의 Codex 넓은 리뷰 L1(`01a1dcd0-9083`, 읽기 전용)이 1C-1 복원 세대 카드 의도 대기열에서 중간 2건을 냈다. 1C-1 계약은 [저장통합_1C_복원세대_2026-11-13.md](저장통합_1C_복원세대_2026-11-13.md) — 복원 전 조작은 새 세대 DB 에 섞이지 않는다. 이 계약은 바꾸지 않는다.

## 지적 (총괄이 코드로 확인)

- **L1-02(중간)** `frontend/src/lib/sceneCardLinks.ts` `load()`: 응답을 받자마자 `prepareGeneration()` 으로 대기열을 격리하고, 조작이 끼었는지는 그 뒤에 봤다. G1 GET 진행 → 공책 G2 채택 → G2 에서 카드 제거·되살림 → 늦은 G1 응답이 G2 의도를 '복원 전 요청'으로 격리했다.
- **L1-01(중간)** `frontend/src/lib/sceneStore.ts` `refreshFromStore()`: 분리 창이 메인 창의 저장 통지로 씬을 다시 읽을 때 `confirmedNotebookMeta = null` 로 비워, 그 틈에 생긴 카드 제거·되살림 의도가 세대 없이 기록되고 다음 조회에서 격리됐다(분리 창은 공책 토큰이 없어 메타를 스스로 못 고친다).

## 고침 (설계 Claude `fix-designs/C1-regen.md` → Codex 확정·구현 `01a1dcdb-f37e`, 작업실 `codex/fix-regen-1115`)

- L1-02: 응답의 계정·조작 순번·공책 채택 세대가 출발 때와 같을 때만 격리(`prepareGeneration`)에 쓴다. 다르면 대기열을 건드리기 전에 버리고 다시 읽는다.
- L1-01: 외부 재조회가 씬과 같은 트랜잭션에서 공책의 합류·의도·진행 기록(`nj`·`ns`·`nw` 등)도 읽어 `confirmedNotebookMeta` 를 비우지 않는다(Codex 확정안 (a) — 세대 없는 옛 의도를 승격하지 않는다).
- 시험: 늦은 옛 GET(조작 있음/없음) · 분리 창 외부 저장 뒤 제거·되살림이 현재 세대로 남음 · 진짜 복원 전 의도는 계속 격리 · 외부 재조회가 공책 합류·닫기 요청을 같은 판으로 읽음. 2차에서 시험의 모듈 분리 문제(부분 모킹이 옛 모듈 참조를 쥠)를 실제 `syncSceneNotebook()`→`adoptRestoredNotebook()` 경로로 고쳤다.
- 되돌려 확인(총괄, 샌드박스 밖): `sceneCardLinks.ts` 만 되돌리면 늦은 GET 시험 2개, `sceneStore.ts` 만 되돌리면 분리 창 시험·외부 재조회 시험이 실패. 순서를 섞은 실행(`--sequence.shuffle --sequence.seed=1115`)도 42/42.
