## 2. 지금 앱에서 일어나는 곳(코드 확인)

- 캔버스: 씬은 그 창의 `SceneBoard` 가 들고, App 이 `sceneActionRef`(`commitDocument(command)`·`sceneId`·`selection()`)로 명령한다. 명령 = `createNode{id, kind, position}` · `connectCards{pairs, role?}` · `disconnectEdges{edgeIds}` · `removeCards` · `editNodeText` — 모두 캔버스 되돌리기 기록에 들어간다.

## 3. 설계

### 3-1. 도구 하나 — `screen_action(name, args)`(칸 연결 전용)
| name | args | 하는 일 | 한도(한 차례 누적) |
|---|---|---|---|
| `canvas.read_selection` | `scene_id` | 그 씬에서 지금 고른 카드 `[{id, kind, label(40자)}]` 20개까지 | — |
| `canvas.create_nodes` | `scene_id`, `nodes:[{kind:"generation"\|"text", text?(2000자)}]`(1~5) | 빈 생성 카드·글 카드 만들기(화면 가운데부터 옆으로) — **잇지 않는다**(자동 연결 없음, 2판) | 노드 10 |
| `canvas.connect` | `scene_id`, `pairs:[[from,to]]`(1~10) | 명시한 쌍만 기존 역할 규칙(`connectCards`)대로 잇기 — 안 되는 쌍은 건너뜀 | 잇기 20 |
| `library.set_hidden` | `generation_ids`(1~50), `hidden: bool` | 숨기기(비활성) **목표 상태로**(뒤집기 아님) | 100 |

- 세 목록(어댑터 `PANEL_TOOLS`·해석기 `PANEL_TOOLS`·허브 `_PANEL_METHODS`)에 `screen_action` 하나를 더한다(같은 목록 하나에서 — 지금 시험이 대조).
- **차례 시작 때 고정**(2판, Codex 1차 P1-1·2): 옆에 붙은 칸은 마운트마다 실행 창 번호(`screen_tab` — uuid)를 만들어 차례 시작 요청(`TurnIn.screen_tab`, 선택)에 싣는다. 허브는 그 차례 실행 객체에 `screen_tab`·**그 차례 화면 정보의 공간(`context.workspace`)·열린 씬(`context.scene.id`)**을 고정한다. 새 창(`?embed=agent`)·화면 정보를 뺀 차례는 `screen_tab` 이 없다 → 화면 동작 불가("옆 칸이 열린 MV Hub 화면에서만 할 수 있어요").
- 허브 검사(실행 전): **칸 연결 + 그 연결의 진행 중 차례 + 그 차례의 `screen_tab`** · name·args 모양 · 한 차례 누적 한도(쪼개기 우회 막기, 잇기는 명시한 쌍만이라 한도가 곧 상한) · 캔버스 `scene_id` = 고정한 열린 씬(아니면 거절 — 서버는 씬 내용을 모르니 사람이 그 차례에 보고 있던 씬만) · `library.set_hidden` 의 id 는 **고정한 공간에서 이 신원의 내 생성물**인지 허브가 확인(생성물 조회 + 공간 대조 + **소유자 대조** — 조회 성공만으로 소유를 믿지 않음), 아니면 그 id 는 건너뜀 목록으로.
- **종료 경합**(Codex 1차 P1-4): 발급·한도 예약·claim 은 그 차례 실행 객체의 잠금 안에서 '아직 진행 중'을 다시 보고 한다(2-A `claim_gate` 와 같은 무늬) — 취소·끝남과 엇갈리면 발급하지 않는다.

### 3-2. 화면이 실행 — 서버가 발급한 실행 표
- 허브가 동작 기록(메모리, 그 차례 실행 객체 안) `{action_id, name, args(검사한 것), state: pending→claimed→done|failed|expired, deadline(30초)}` 을 만들고 차례 사건 **`ui_action{action_id, name, args, deadline}`** 을 낸다.
- 실행 자격 = **그 차례를 시작한 칸 마운트**: `POST /api/agent-chat/turns/{tid}/actions/{aid}/claim {screen_tab}` 의 `screen_tab` 이 차례에 고정한 값과 같을 때만, 처음 한 번만 실행 표(token)를 준다(원자적, 두 번째부터 409). 같은 계정의 다른 탭·새 창·칸을 닫았다 다시 연 마운트(새 번호)·대화 복원은 자격이 없다 — follow 로 받았는지가 아니라 번호로 정한다(Codex 1차 P1-1). 칸 안에서도 **그 마운트가 직접 보낸 차례만** 실행 목록에 두고(`send` 가 받은 turn_id), 다른 대화를 열거나 같은 대화를 다시 열면(복원) 그 목록을 비운다(같은 마운트의 복원도 실행하지 않음 — Codex 2차 P2). 이미 처리한 `action_id` 는 다시 청하지 않는다.
- 표를 받은 칸만 실행 → `POST …/result {token, ok, summary, data}`.
- **상태**(Codex 1차 P1-4): 기한 안에 claim 이 없으면 `expired_unclaimed` = 실행 안 됨(AI 에 그대로) · claim 뒤 기한까지 결과가 없으면 `unknown` = 결과 불명(AI 에 "화면에서 확인하세요", 다시 내지 않음). 허브가 다시 켜지거나 차례가 끝나 실행 객체가 없으면 claim 은 404 — 실행하지 않는다.
- **'한 일' 카드는 칸이 실행 직후 자기 영수증으로 먼저 만든다**(Codex 2차 P1-2): 실행기가 끝나면 그 칸이 바로 카드(실제 바뀐 것·되돌리기 자료)를 그리고, 결과를 허브에 보낸다. 허브는 기한 안에 받은 결과를 `ui_action_result` 사건으로 내고(기한이 지나면 상태 사건 — 3-3b, 대화 복원 때 보임 — 되돌리기 단추는 없음), 칸은 같은 `action_id` 의 사건과 합친다. 기한 뒤·차례가 끝난 뒤의 결과는 허브가 받지 않지만 칸 카드는 이미 있어 실제 변경과 되돌리기가 남는다. 차례 종료로 follow 가 끝나도 카드는 칸 상태에 남는다.
- 칸의 실행기(`agentScreenActions.ts`, 이름 → 처리 함수 표, 표에 없는 이름 거절):
  - 캔버스: `sceneActionRef.current?.sceneId === args.scene_id` 이고 계정이 그 차례의 계정일 때만 — 아니면 실패("그 씬을 캔버스에서 열어 주세요"). **실제 바뀐 것을 확인해 보고**(Codex 1차 P1-6): `commitDocument` 는 참/거짓만 주므로, `actionRef` 에 지금 카드 id·엣지 목록을 읽는 `snapshot()` 을 더해 명령 전후를 비교한다 — 만든 카드 id(칸이 `uid` 로 만든 것 중 실제로 생긴 것)·새로 생긴 엣지 id·건너뛴 쌍·거절(GPU 보기 모드 등 편집 거절이면 "보기 모드라 바꿀 수 없어요").
  - 숨기기: `addDisabledGen`/`removeDisabledGen` 로 목표 상태 → **다시 읽어** 실제로 바뀐 id 만 결과에(저장 실패를 삼키는 `saveJSON` 을 믿지 않음). 결과 글에 '이 브라우저 기준'(저장이 계정별이 아님 — Codex 1차 P2).
- MCP 호출은 결과를 최대 30초 기다려 `{ok, summary, data}` 또는 위 상태를 AI 에 돌려준다.

### 3-3. '한 일' 카드와 되돌리기
- 결과마다 칸에 '한 일' 카드(차례 사건 `ui_action_result{action_id, ok, summary, undo}` — 허브가 결과를 받을 때 낸다): "새 노드 2개 만듦 · 1개 이음 [되돌리기]" / "생성물 7개 회색(비활성)으로 바꿈 · 이 브라우저 기준 [되돌리기]".
- 되돌리기 = **그 동작이 바꾼 것만, 뒤에 손댄 것이 없을 때만**(Codex 1차 P1-5·2차 P1-1): 캔버스는 동작 직후 씬 지문(`actionRef.snapshot()` 의 카드·엣지 전체를 이은 해시)을 기록하고, **되돌릴 때 지문이 다르면 되돌리지 않는다**("그 뒤 캔버스가 바뀌어 되돌릴 수 없어요 — Ctrl+Z 를 쓰세요") — 카드의 프롬프트·모델·결과·위치·연결 무엇이 바뀌었든 사람이 한 일을 지우지 않는다. 같으면 만든 카드 `removeCards`·이은 엣지 `disconnectEdges`. 숨김은 그 뒤 **다른 숨김 변경이 없었을 때만**(숨김 저장의 바뀜 번호를 동작 때 기록 — 사람이 풀었다 다시 숨긴 것은 지금 값만으로 구별 못 하므로) 그 동작이 바꾼 id 를 되돌린다. 계정·허브가 바뀌었으면 되돌리기 거절. 한 번 되돌리면 단추가 사라진다. 대화를 다시 열면(복원) 되돌리기 단추는 없다(그 창의 일).

### 3-3b. 4판 보탬(Claude 합의 1차)
- **캔버스가 이 창에 없을 때**: App 이 지금 화면에 `scene` 을 싣는 것은 **이 창에 보드가 실제로 붙어 있고 쓸 수 있을 때만**(캔버스를 별도 창으로 띄웠거나 다른 탭이 캔버스를 쥐고 있으면 싣지 않고 `scene_unavailable: "away"`). 허브는 고정할 씬이 없으니 캔버스 동작을 거절하고, 어댑터·GUIDE 는 "캔버스가 별도 창에 떠 있으면 못 해요 — 본창으로 돌려 주세요"를 말하게 한다.
- **만들고 이은 뒤 되돌리기**: 씬 지문은 카드·엣지·**그룹**의 내용으로 만든다(객체 참조 아님 — Codex 3판 동의 P2). 지금 지문이 같은 칸에서 **뒤 동작 직후 지문**과 같으면 "아래 카드부터 되돌려 주세요"(뒤 동작을 되돌리면 앞 동작이 다시 되돌릴 수 있게 된다). 지문 확인과 되돌리기 명령 사이에 다른 편집이 끼지 않게 같은 처리 안에서 한다.
- **실패·불명도 카드로**: 기한이 지나면 허브가 그 차례 잠금 안에서 상태(`expired_unclaimed`·`unknown`)를 `ui_action_result{status}` 사건으로 낸다(결과 도착과 기한 만료는 잠금 안에서 먼저 온 쪽 하나로 정한다). 칸에 자기 결과 카드가 있으면 그것이 우선. '결과마다 카드'는 실패·불명에도 해당한다. GUIDE: "화면 동작이 성공이 아니면 그 상태를 말로 알린다".
- **말**: 앱에서 이 동작은 '숨김'이 아니라 **회색(비활성)**(d 키 — 회색 필터를 켰을 때만 목록에서 빠짐). 카드·도구 설명·GUIDE 글은 "회색(비활성)으로 바꿈 · 이 브라우저 기준".
- **글 카드는 명령 하나로**: `createNode` 가 선택 `text` 를 받게 한다(`edits.ts` — `createNode` 뒤 지연 저장 `editNodeText` 가 사람이 치던 글과 되돌리기 한 칸으로 섞이지 않게).
- **actionRef 보탬**: `snapshot()`(카드·엣지·그룹 내용) · `viewCenter()`(화면 가운데) · `canEdit()`(보기 모드 거절과 '바뀐 것 없음'을 가름) · `selectCards(ids)`(만든 노드를 골라 사람이 찾게 — 사람이 만들 때와 같게).
- **회색 바뀜 번호**: `deactivated.ts` 가 자기 저장 때와 **다른 창의 `storage` 알림 때** 모두 번호를 올린다.
- **`screen_tab` 은 허브 메모리에만**: 차례의 화면 정보 JSON·사건·복원 응답에 싣지 않는다. 같은 중복 방지 키로 다시 보낸 요청은 처음 고정한 값을 그대로 쓴다(새 마운트면 실행 안 됨으로 끝남).
- **claim 뒤 다시 확인**(Codex 3판 동의 P2): 실제 명령 직전에 마운트·직접 보낸 차례·계정·씬을 다시 보고, 다르면 실행하지 않고 실패로 보낸다. 서버 결과 전송이 실패해도 이미 반영한 동작은 성공 카드로 둔다.

### 3-4. GUIDE·어댑터
- GUIDE 의 '빈 노드 만들기·잇기 같은 화면 동작은 아직 없다'를 바꾼다: 캔버스 동작은 '지금 화면'의 scene 이 그 씬일 때만, 먼저 `canvas.read_selection` 으로 고른 카드를 확인, 숨기기는 `read_context(kind='generations')` 로 찾은 내 생성물 id 로. 동작 결과는 '한 일' 카드가 보이니 한 줄로만.
- 어댑터 `--panel` 에 `screen_action` 도구(설명 = 위 표·한도·'옆 칸이 열린 화면에서만'). 일반 연결에는 없다. `ADAPTER_VERSION` 올림.

### 3-5. 구현(11-12)
- 허브 `services/agent_chat.py` — 차례 실행 객체에 `screen_tab`·공간·열린 씬·동작 기록·누적 사용량(메모리만) · `issue_action`(emit_lock 안 지금 차례·멈춤·한도 재확인 → `ui_action` 사건) · `claim_action`(같은 번호·처음 한 번·멈춘 차례·기한 지남 거절) · `finish_action`(표 대조·기한·차례 살아 있을 때만 → `ui_action_result`) · `expire_action`(claim 없음 = expired_unclaimed, claim 뒤 답 없음 = unknown — 결과와 먼저 온 하나) · 차례 끝에 남은 동작을 `closed` 로 닫고 사건은 안 냄. GUIDE 의 '화면 동작은 아직 없다'를 screen_action 안내로.
