## 2. 설계

### 2-1. 행 메뉴(시안 ①, 포크 뺌)

- 행 = 감싸는 칸 하나에 **[대화 열기 단추] + [⋯ 단추]** 두 형제(단추 안 단추 금지). 행에 올리거나 초점이 오면 ⋯ 이 보이고, ⋯ 또는 **우클릭**으로 메뉴.
- 메뉴가 열린 동안 글자 단축키 P·U·R·A·D 는 `event.code`(한글 자판도) — 입력칸·IME 조합 중·Ctrl/Alt/Meta·반복 입력은 무시하고, 누를 때 잠금을 다시 본다. Esc 는 한 단계씩(하위 메뉴 → 행 메뉴 → 서랍) 닫고 초점을 ⋯ 로 돌린다.

| 항목 | 동작 | 허브 |
|---|---|---|
| 새 창에서 열기 | 옆 칸에서만 — **열기 요청**(계정·`identity_key`·대화 id·요청 번호 UUID·만든 시각)을 `localStorage` 요청 키에 적고 지금 [새 창으로 띄우기](`onPopOut`)를 탄다. **받는 쪽은 새 창(`?embed=agent`)만**(옆 칸은 무시). 새 창은 처음 뜰 때 **만든 지 30초 안이고 처리 안 된 요청**만 마지막 대화 복원보다 먼저 쓰고, 이미 열린 창은 저장소 알림으로 받는다. 같은 계정·신원일 때만 연다. 보내는 중·도는 중이면 **가장 최신 요청 하나를 보류**했다가 풀리면 연다. 받는 창은 요청 키를 **지우지 않고**(확인과 삭제 사이에 새 요청을 지울 수 있다, Codex 3차) 처리한 요청 번호를 **공유 `localStorage` 의 별도 '처리됨' 키**에 적는다 — `sessionStorage` 는 `window.open` 이 여는 창의 것을 복사해 주므로 창을 닫았다 다시 열면 처리 기록이 사라진다(Claude 합의 P1, `lib/popupWindows.ts:163`). 옆 칸의 지금 대화는 바꾸지 않는다 | 없음 |
| 고정 / 고정 풀기 (P) | 맨 위 '고정됨' | `PATCH pinned` |
| 읽지 않음으로 표시 / 읽음으로 표시 (U) | 라임 점(수동) | `PATCH unread` |
| 이름 바꾸기 (R) | 행 자리 입력칸, Enter 저장(앞뒤 공백 뺀 1~80자) · Esc 취소 | `PATCH title` |
| 프로젝트로 옮기기 › | 하위 메뉴 = 지금 화면 프로젝트(이름을 아는 것) · 서랍에 **이름이 보이는** 다른 프로젝트(id 별, 표시 이름으로 합치지 않음) · 프로젝트 없음. 이름 모르는 프로젝트는 고를 수 없다 | `PATCH project` |
| 보관 / 보관 풀기 (A) | 맨 아래 '보관함 N' | `PATCH archived` |
| 삭제 (D) | 확인 창 뒤 지움 — 결과(세션 파일 정리 성공·못 찾음·실패·Codex 남음)를 알린다 | `DELETE` |

- 보내는 중·지금 대화가 도는 중에는 그 대화의 바꾸는 항목을 잠근다. 다른 대화의 고정·이름·보관은 된다. 도는 대화 삭제는 허브도 409.
- 전체 프로젝트 목록은 옆 칸에 들어오지 않는다(받으려면 `App.tsx` 변경) — 이번엔 위 후보만.

### 2-2. 목록 모양(시안 ②)

- 순서: **고정됨**(최근 순) → 프로젝트 묶음 → '프로젝트 없음' → **보관함 N**(접힘, 펼치면 보관 대화).
- 목록은 신원 파일의 대화를 **최대 500개**(최근 순) 싣고 넘치면 `truncated: true` — 화면은 그때 목록 끝에 "최근 500개만 보여요" 를 적는다(오래된 고정·보관 대화가 빠질 수 있다는 뜻). 보관함 N = **보이는 목록 기준** 보관 대화 수. 전체 고정 목록 보장은 이번 범위 밖(대화가 500개를 넘을 때 다시).
- 라임 점 = `unread`. 보관은 **서랍 정리**일 뿐 AI 접근 차단이 아니다 — MCP 대화 읽기에 계속 나온다(문구로 안내).

### 2-3. 읽지 않음(자동·수동) — 경쟁 없는 규칙(Codex P1 7)

- 대화마다 **`unread_rev`**(읽지 않음이 바뀔 때마다 1씩 오르는 번호)를 둔다. 허브가 차례를 끝낼 때 **상태·끝남 사건·`unread=1`·`unread_rev+1` 을 한 트랜잭션**으로 적고, 끝남 사건(`state`)에 새 `unread_rev` 를 싣는다(`finish_turn`).
- 화면의 **자동 읽음은 언제나 조건부** `{unread:false, seen_rev:<본 번호>}` 이고 **`unread=1` 일 때만** 보낸다 — 허브는 지금 `unread_rev` 가 같을 때만 끈다(늦은 요청이 그 뒤의 차례 끝·수동 표시를 못 지움, Codex 2차 P1). ① 대화를 열 때: 복원 응답의 `unread`·`unread_rev` ② 보고 있는 대화의 끝남 사건을 받았을 때: 그 사건의 `unread_rev` — 창이 숨어 있으면 들고 있다가 다시 보일 때(`visibilitychange`) 한 번 보낸다.
- 메뉴의 수동 '읽지 않음으로 표시' = `unread=1, unread_rev+1` · 수동 '읽음으로 표시' = 조건 없이 끔(+1). 사람이 고른 것이 마지막이다.
- 허브 쓰기는 **조건부 UPDATE 한 번**: 자동 읽음 = `SET unread=0, unread_rev=unread_rev+1 WHERE id=? AND unread_rev=?`(맞지 않으면 아무것도 안 바꾸고 지금 값을 돌려줌) · 수동은 조건 없이 같은 꼴. 성공하면 rev 가 오른다.

### 2-4. 서랍 넓이 조절(Jay 추가)

- 서랍 오른쪽 끝선 손잡이(옆 칸 손잡이와 같은 방식 — 포인터 잡기·더블클릭 기본값·←→ 8px). 최소 220px, 최대 = 칸 폭 − 40px(칸 폭이 바뀌면 `ResizeObserver` 로 다시 맞춤), 기본 310px. 칸이 아주 좁아 최대가 최소보다 작으면 **최대가 이긴다**(서랍이 칸을 넘지 않게). 이 브라우저에만 기억(`STORAGE_KEYS.agentDrawerWidth`, try/catch — 읽기 실패해도 기본값).

### 2-5. 허브(칸 기록 DB — 콘텐츠 DB 와 무관)

- **표 칸 추가**(`agent_chat_conversation`): `pinned`·`archived`·`unread` INTEGER 0/1 · `unread_rev` INTEGER 0 · `project_override` TEXT(NULL = 첫 차례 화면, '' = 프로젝트 없음) · `cli_home`·`cli_cwd` TEXT(세션을 띄운 때의 Claude 자격 폴더·작업 폴더).
  - `open_db`: (지금처럼 `journal_mode=WAL`·`executescript(_SCHEMA)` 를 먼저 — `executescript` 는 열린 트랜잭션을 커밋해 버린다) → `BEGIN IMMEDIATE` → `PRAGMA table_info` → 없는 칸만 `ALTER TABLE ADD COLUMN` → 재시작 정리(2-5 finish_turn ④) → 커밋, **성공한 뒤에만** `_opened` 에 넣는다(실패 = 롤백, 다음 열기에 다시). 옛 허브 호환은 **번갈아 쓰기**에 한정(같은 파일을 두 허브가 동시에 쓰는 것은 지금도 지원하지 않음 — 처음 연 허브가 남은 차례를 끝난 것으로 바꾸는 기존 동작).
  - MCP 읽기 전용(`ro_conversations`)은 `open_db` 를 거치지 않으므로 **칸이 없는 옛 파일**이면 `project_override` 를 쓰지 않는다(표 정보로 확인).
- **차례 끝 묶기**(`finish_turn`, Codex P1 1·2차 P2): 지금 `set_status` 뒤 `append_event('state')` 가 따로라 그 틈에 지우면 사건이 되살아난다 → 상태(진행 중일 때만)·(있으면) 오류 사건·끝남 사건·unread 를 한 트랜잭션. 종료 지점 전부: ① `_run` finally ② 취소 정리 `no_runtime` ③ 라우터의 시작 실패 `start_failed`(오류 사건 포함) ④ `open_db` 의 재시작 정리 `interrupted`(차례마다 끝남 사건·unread 를 같은 트랜잭션에). `cancelling` 은 중간 상태라 대상이 아니다.
- **차례 시작 재확인**(Codex P1 1): `claim_turn` 트랜잭션 안에서 대화가 아직 있는지 본다 — 없으면 LookupError → 404(사이에 지워진 대화에 차례가 붙지 않게).
- **목록**(`GET /conversations`): 위 칸 + 실효 `project` + `truncated`.
- **고치기**(`PATCH /conversations/{id}`, Codex P2 10): **`updated_at`(목록 순서·MCP 쪽 넘김 기준)을 바꾸지 않는다**(Claude 합의 P2 — 고정·읽음·이름만 바꿔도 맨 위로 오르지 않게. 지금 `update_conversation` 은 늘 바꾸므로 따로 쓴다). 준 필드만. `title`: 문자열·앞뒤 공백 뺀 1~80자(null·다른 타입 422) · `pinned`·`archived`·`unread`: 진짜 참/거짓만(null 422) · `seen_rev`: 참거짓이 아닌 0 이상 정수, `unread:false` 와 함께일 때만(있으면 자동 읽음 = 조건부, 없으면 수동 = 조건 없음) · `project`: 문자열(1~200자, 제어 글자 없음) = 그 프로젝트, `null` = 프로젝트 없음(`''` 로 저장), 생략 = 그대로(첫 차례로 되돌리기는 없음). 빈 몸·없는 대화 404/422.
- **지우기**(`DELETE /conversations/{id}`, Codex P1 1·3): 신원 차례 잠금 안에서 `delete_conversation` 이 **한 IMMEDIATE 트랜잭션**으로 있음(404)·도는 차례(409)를 보고 사건·계획 묶음·차례·대화를 지운다. 커밋 뒤 세션 파일:
  - Claude 대화·`cli_session_id` 가 UUID 꼴·**`cli_home`·`cli_cwd` 가 저장된 대화만**(근거 없는 옛 대화는 자동으로 안 지움): `<cli_home>/projects` 아래 폴더를 하나씩 읽어 `<uuid>.jsonl` 이름 후보를 모은다(**어느 폴더든 읽기 오류가 나면 확정하지 않음**). **이름 후보가 정확히 한 개**이고, 그 파일이 보통 파일(링크 아님)·실제 경로가 projects 안·앞 50줄 안에 `sessionId == uuid` 이고 `cwd == cli_cwd`(대소문자 무시) 인 줄이 있을 때만 지운다(Codex 2·3차). 보장 범위 = "저장한 자격 폴더 안에서 같은 이름이 하나뿐이고 그 내용이 이 칸 작업 폴더의 그 세션으로 적힌 파일" — 같은 내용의 사본까지 가려내지는 못한다.
  - 응답 `session_file`: `deleted` · `not_found`(근거 없음·0개·여러 개·확인 실패 — 안 지움) · `failed`(권한 등) · `codex_kept`(Codex 기록은 Codex 폴더에 남음 — 칸이 다시 잇지 않으니 기억은 끊김) · `none`(세션 없음). 화면이 그대로 알린다(로그만 남기지 않음). 확인 창에도 Codex 는 기록이 남는다고 적는다.
  - 그 대화의 칸 MCP 설정 파일 `AGENT_CHAT_DIR/mcp/<대화 id>.json`(칸 폴더 안·대화 id 이름)도 지운다(없으면 넘어감). 만든 그림·계획(콘텐츠 DB)·칸 연결(mcp_client 행)은 그대로.
- **세션 자격 폴더 기록**(Codex 2차 P2): 차례를 띄울 때 **실제 Job 에 넘기는 환경·작업 폴더를 한 번 잡아** 거기서 자격 폴더(`CLAUDE_CONFIG_DIR` — 상대 경로면 **자식 작업 폴더 기준**(허브 위치 기준인 기존 `_credential_dir` 은 그대로 쓰지 않음) — 또는 `USERPROFILE\.claude`)를 계산해 실행 객체에 둔다. 경로 비교는 `normcase`+`normpath`. Claude 세션 사건으로 `cli_session_id` 를 적을 때 그 값을 `cli_home`·`cli_cwd` 에 같이 적는다(사건 받을 때 다시 계산하지 않음).

### 2-6. 화면 상태(Codex P1 8, P2 12·13)

- 이 창에서 지움 성공: 지운 대화가 지금 대화이거나 **지금 불러오는 중인 대화**(불러오는 대상 id 를 따로 추적, Codex 2차 P1)면 `drop`(epoch 를 올려 늦은 복원 응답을 버림), '마지막 대화' 기억은 **지운 id 와 같을 때만** 비움, 목록 새로. 다른 창에 **삭제 알림**(브라우저 저장소 키 — 계정·대화 id) → 그 창에서도 지금·불러오는 중인 대화가 같으면 같은 처리와 안내. 대화 열기·보내기·사건 받기의 404 도 그 대화만 비운다.
- 서랍을 다시 열 때마다 목록 새로(지금과 같음) — 다른 창의 변경은 그때 맞춰진다.

### 2-7. 안 하는 것
