# 리졸브 패널 — 에피소드를 고르면 컷 빈만 먼저, 들어간 빈을 따라 보기 (2026-11-12)

Jay 요청(11-12): "e020 을 누르면 그 안에 생성물이 있는 폴더만 다빈치에 먼저 생기고, 다빈치에서 내가 폴더를 들어가면 생성물들이 보이면 된다 · 내가 선택하는 폴더 안의 정보를 패널 오른쪽에 자동으로(이미지 3·4·5 모양) · MV 의 컬러·전역 태그·생성자 거르기 그대로 · 거르기 칸 옆 여백". 시안 2(편집 탭 미디어 풀을 그대로 넣은 그림)를 보고 **"이대로 만들어"**. 정할 것 3가지는 추천대로(아래 결정 1~3).

## 흐름

1. **패널 트리에서 에피소드(컷들의 부모 폴더) 이름을 누르면** — `target` 한 번(`episode_path` = 그 에피소드, `create_paths` = 생성물 있는 컷들)으로 그 컷 빈을 모두 만들고(이미 있으면 그대로), 다빈치 지금 빈을 에피소드 빈으로 둔다. 응답에 컷 경로 → 빈 ID 표(`bins`)를 받는다. 펼침 화살표(▸)만 누르면 펼치기만 한다(빈을 만들지 않음).
2. **다빈치에서 컷 빈에 들어가면** — 2초 `current-bin` 읽기의 `bin_id` 가 `bins` 의 어느 컷이면 패널이 그 컷을 고른 것으로 따라가고(트리·오른쪽 보기), 그 컷 생성물을 `stage` 한다. 이때 `stage` 에 그 `bin_id` 를 실어 **ID 로 목적 빈을 찾는다**(이름 경로로 찾지 않음 — 사람이 빈 이름을 바꿔도·같은 이름 빈이 있어도 맞게). 그 ID 의 빈이 없으면 경로로 대신하지 않고 보류(deferred). `target` 은 부르지 않는다(이미 지금 빈). 에피소드 빈으로 돌아가면 컷 선택을 풀고 타일 보기.
3. **패널에서 컷(트리의 컷 또는 오른쪽 타일)을 누르면** — 지금처럼 `target(create)` 로 그 컷을 지금 빈으로 고르고 `stage`. 같은 `target` 에 `episode_path`(그 컷의 부모)와 에피소드 컷 목록을 실어 빈 표도 받는다.
4. **오른쪽 칸** = 편집 탭 미디어 풀(`EditPool`) 그대로 — 메타데이터·썸네일·목록, 정렬·검색, 카드 = 라이브러리 카드. 보기·크기·정렬은 패널 화면 설정에 기억. 에피소드만 고른 때는 컷 폴더 타일(누르면 3). 카드는 보기 전용: 고르기·끌기·크게 보기 없음, 호버 단추(T·C·⠿·오버레이)는 숨김, S/★ 는 표시만.
5. **카드 표** — 편집 탭의 'V1 - 선택 카드' 자리(`poolMark`)에 '띄움'(stage 의 staged·present) · '쓰임 · NAS'(이번 창에서 바꿔 끼운 것, 라임).
6. **상태 줄** — 오른쪽 칸 아래 한 줄(띄움·쓰인 것·NAS로 옮김·다른 허브·확인 필요). 알림·실패·[다시]·[맞추기]·[넘겨받기]는 그 위에. `busy` 같은 영어 상태는 한국어로.
7. **거르기 칸** — 왼쪽 칸 176→200px · 옆 여백 14px · 컬러 점 22px · 제목 간격(MV 사이드바 값).

## 결정 (Jay 11-12 — 시안의 추천대로)

- **결정 1** 같은 에피소드 안에서 컷을 옮길 때는 앞 컷을 지우지 않는다(쓴 것 바꿔 끼우기만).
- **결정 2** 다른 에피소드로 옮길 때 앞 에피소드의 각 컷 빈: 쓴 것 바꿔 끼우기 → 안 쓴 내 항목 지우기(`unstage`) → **비게 된 컷 빈 지우기**(`delete_empty` — 클립·하위 빈이 하나도 없을 때만, 지우기 직전 다시 읽음). 에피소드·프로젝트 빈은 남긴다. 지울 수 있는 빈은 **서버가 이 창·이 리졸브 프로젝트에서 `target` 의 `bins` 로 받아 기억한 컷 빈 ID** 뿐이다 — 에피소드·프로젝트 빈이나 모르는 ID(서버를 다시 켜서 잊은 것 포함)는 항목 정리만 하고 빈은 남긴다.
- **결정 3** 거르기는 보기와 빈에 넣는 것 둘 다(지금 규칙).
- 빈 만들기는 계속 사람이 누른 `target` 만 한다(새 빈 보류 규칙 그대로). 에피소드에 새 컷이 생겨도 그 자리에서 빈을 만들지 않는다 — 지금 빈이 바뀌므로. 다음에 에피소드를 다시 누르면 생긴다.
- 패널을 다시 열 때 inventory 정리는 **저장된 선택의 에피소드 컷 빈은 건너뛴다**(결정 1 을 다시 열기에도). 서버는 `target` 이 돌려준 에피소드 빈 ID 들을 기억해 inventory 정리 요청을 `active_bin` 으로 거절한다. 이 기억은 창을 다시 잡을 때(claim) 지우지 않는다 — 다시 열기가 바로 그때다. 저장된 선택은 패널을 닫았다 열어도 남게 `localStorage` 에 둔다. inventory 정리는 빈을 지우지 않는다(`delete_empty` 안 씀).
- **순서** — 다른 에피소드를 누르면 새 에피소드 `target` 을 **먼저** 하고 앞 에피소드 정리는 그 뒤에 한다(사람이 다빈치에서 앞 컷 빈 안에 있으면 그 빈을 지우게 되므로 — Claude 설계 검토 11-12). 정리는 실행 직전에 그 에피소드가 다시 고른 에피소드가 아닌지 본다(A→B→A).
- **같은 에피소드 안**: 다빈치에서 컷 빈 → 에피소드 빈으로 돌아가거나 패널에서 에피소드를 다시 눌러도 정리하지 않는다. `bins` 에 없는 빈(사람 빈·다른 에피소드)에 들어가면 아무것도 하지 않는다. 따라가기 stage 는 지금 빈 ID 가 바뀔 때 한 번만(2초마다 다시 부르지 않음).
- **지우기 이중 확인** — 서버: 기억한 컷 빈 ID 만 `delete_empty` 를 실어 보낸다. 리졸브 안(자식): 그 ID 의 빈이 요청한 `folder_path` 를 이름 경로로 찾은 빈과 같은 ID 이고, 지우기 직전 다시 읽어 **지금 빈이 아니고** 클립·하위 빈이 0 일 때만 `DeleteFolders`. 읽기 실패는 '비었음'이 아니다.
- **오른쪽 칸 보기 전용** — `EditPool` 에 `viewOnly` 하나를 더해 카드 누르기·끌기·끌어 고르기 상자·더블클릭·우클릭·편집 탭 안내 글(끌기 = 타임라인에 넣기…)을 끈다. 편집 탭은 `viewOnly` 를 안 주므로 그대로.
