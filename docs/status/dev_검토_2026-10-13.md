## 4. 찾아서 고친 것

Codex 의 지적은 상대 보고다 — 코드를 읽어 확인한 뒤에 고쳤다. 자세한 까닭은 각 커밋 글과 정본 문서에 있다.

**편집 문서(브라우저에만 있고 백업이 없다)**
- 새 판을 쓰다 옛 판으로 되돌린 뒤 계정을 바꾸면 **모든 계정의 편집본이 지워졌다**(옛 판의 계정 전환 정리가 `ch.*` 를 지운다) → 키를
  `mvhub.editDoc:` 로. 옛 자리의 문서는 **옮기지 않고 읽기만** 한다 — 옮기기(복사 → 삭제)는 두 창이 엇갈리면 방금 저장한 편집을 덮었다
  (Codex 재검토 P1 두 번).
- 다른 창이 저장한 것을 알림이 오기 전에 덮던 것 → 바꾸기 직전에 저장소를 보고, 달라졌으면 받아들이고 **이번 조작은 버린다**.
  바꾸기의 결과는 셋(`done`·`none`·`stopped`).
- 저장하지 못한 편집이 있는데 앱이 스스로 새로고침하던 길: 업데이트 완료(덮개 · 설정 창의 폴 · 예약한 0.6초 사이) · 로그아웃(확인 창 ·
  응답을 기다리는 동안의 편집 · 두 번 누름 · 끝나지 않는 응답) · DB 가져오기·복원의 확인 창. 남긴 길은 [EDIT_TAB.md](../EDIT_TAB.md) §4.

**Resolve**
- 가져오는 도중 Resolve 에서 다른 프로젝트를 열면 **그 프로젝트에 쓰고 저장했다** → 쓰는 호출 바로 앞마다 프로젝트를 다시 확인한다.
  Bin 순서를 다시 짓다 멈추면 남은 임시 Bin·백업 자리를 결과와 글에 싣는다. **실제 Resolve 로는 재지 않았다**(가짜 Resolve 시험).
- 이름 규칙의 번호 배정이 저장·전송 한 번에 대상 폴더를 여러 번 훑던 것 → 한 번.

**공유 & 리뷰의 컷 카드**
- 정보판 크레딧을 카드 수만큼 묻던 것 → 화면에 든 카드만, 떠난 화면의 요청은 줄에서 뺀다 · 시간 제한 · 캐시 상한.
- 폴더를 옮길 때 묶음 조회가 두 번 나가던 것 · 옛 서버라는 기억을 영영 믿던 것(5분에 한 번 다시 묻는다) · 응답에 화면이 안 쓰는
  칸까지 실려 60컷에 3.2MB 이던 것.
- 폴더별 모양 기억이 다른 창의 값을 덮던 것 · 저장에 실패한 자리의 모양이 옛 값으로 돌아가던 것 · [대표] 단추가 키보드로 안 눌리던 것.
- 컷 카드 정보판의 줄이 카드마다 달라 보이던 것(Jay 10-13) → 날짜는 늘 두 줄, 줄 높이를 카드마다 같게.

  편집'으로 저장돼 다른 창의 저장을 덮었다 → 충돌을 알게 되면 창과 묶음을 끝낸다. **P2 여섯**: 없는 폴더가 일부만 돌아오면 인/아웃이
  다시 뒤집힘(순서를 바꿀 때 미리 맞바꾸지 않고 그릴 때·찍을 때 바로잡게 바꿈) · 1px 하한과 테두리가 좁은 컷을 넘침 · 끄는 중 휠 단추를
  떼면 놓기가 됨(카드·컷·클립 끌기 셋 다) · 멈춘 포인터 밑에서 스크롤이 바뀌어도 옛 끼움 자리로 저장 · 끄는 중 Space·Enter 가 뒤의
  단추를 누름 · 키보드만으로는 길이 조절·컷 순서를 못 함(클립 메뉴에 '길이 조절' 줄을 넣었고, 키보드 길은 한계로 적고 Jay 에게 물음).
- 3회째 **P1 하나**: 충돌을 알고 길이 조절을 다시 연 뒤 다른 창이 **또** 저장하면 '이미 충돌 중'이라며 그 새 저장을 덮었다 → 충돌을
  원문별로 안다(새 외부 저장마다 그 걸음을 버리고 창을 닫는다). **P2 둘**: 풀의 카드를 끄는 채 타임라인 클립 위에서 휠 클릭하면 길이
  조절 창이 떴다(끄는 중의 휠·우클릭을 어디서든 삼킨다) · 클립 끌기가 Esc 로 취소되지 않고 끄는 동안 뒤의 키가 먹었다.
  키보드 진입점은 Codex 가 '미해결 P2 로 보류'로 남겼다(§6).
- 4회째: 저장·충돌(B) 승인. **P2 셋**: 끌던 클립이 다른 창의 저장으로 사라지면 놓는 이벤트가 오지 않아 '끄는 중'(키·메뉴 막기)이 Esc 를
  누를 때까지 남았다 → 클립 끌기를 걷는 길을 한 곳으로 모아 창의 초점 잃음 · 문서가 갈림 · 화면에서 빠짐에 건다. 누르기만 한 채(6px 전) 휠
  클릭으로 길이 조절 창을 열면 창 뒤에서 끌기가 살아났다 → 창·메뉴를 열기 전에 대기 중인 끌기와 포인터 쥐기를 걷는다. 길이 재기의 '이미
  쟀다' 판정이 옛 요청 길이를 실측값인 양 굳힐 수 있었다(요청 길이는 동기화로 바뀔 수 있다 — 편집 세션이 `generation_sync.py` 를 읽어
  확인) → 판정을 뺐다. 영상 클립은 전처럼 열 때마다 재고, 잰 값을 0.5초 모아 한 번에 적는 것만 남겼다.
- 격리 실측(b127)에서 나온 것: 길이 조절 창에서 끝까지 줄이면 단추가 꺼지며 초점이 창 밖으로 떨어져, ←/→ 가 **듣지 않았다**(창 안을
  다시 눌러야 살아났다) → 화살표를 창 전체에서 듣는다. **정정**: 21시 보고와 커밋 `9307b599` 의 글은 '뒤의 재생헤드를 움직였다'고 했는데
  틀렸다 — 대조 실측(b132)에서 재생헤드는 움직이지 않았고 키가 죽었을 뿐이다.

## 5. 실측에서 나온 숫자

**컷 카드 화면**(격리, 헤드리스 크롬 1600×1000, 60컷·200컷 에피소드 — 건수·바이트는 회마다 같았고 시간은 1~5회)

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 정보판 크레딧 요청(첫 화면) | 카드 수만큼(60 · 200건) | 화면에 든 14건(스크롤하면 그만큼 더) |
| 떠난 화면의 크레딧 요청 | 56 · 196건이 떠난 뒤에도 나감 | 0건 |
| 묶음 조회 응답 한 건 | 60컷 3,177KB · 200컷 10,159KB | 257KB · 639KB |
| 맨 위 → 에피소드의 묶음 조회 | 4건 6.59MB | 2건 0.28MB |
| 가만히 둔 60초(60컷 · 200컷) | 17.2MB · 43.9MB | 5.7MB · 7.2MB |
| 처음 가는 에피소드(60 · 200컷) | 463ms · 652ms | 같음 |

- **정정 — 결함이 아니었다**: 처음 실측은 '모아보기에서 [폴더로] 로 컷에 들어갈 때만 목록 2건·묶음 조회 4건'이라고 했다. 호출 스택과
  인터벌 기록을 찍어 다시 재니(압축 안 한 빌드, 17세션) 둘째 묶음은 **15초 주기 조회**(`useGenerationAutoRefresh`)가 누르는 순간과 겹친
  것이었다 — 누름 자체는 20번 모두 목록 1건·묶음 조회 2건. 실측 도구의 '요청이 잠잠해질 때까지 기다리기'가 첫 주기 조회 뒤에야 풀려
  걸음들이 15초 격자에 맞춰졌다. **걸음별 요청 수를 셀 때는 인터벌이 부른 요청을 따로 가려야 한다.**
- 가만히 둘 때 15초마다 오는 목록(60컷 에피소드 화면에서 1.07MB)이 이제 가장 크다(전부터 있던 것). 묶음 보기에서는 낱장 목록이 화면에
  안 보이는데도 받는다 — 폴더 카드의 '바뀜 신호'로만 쓰인다. 줄이려면 목록 훅을 고쳐야 해 이번에는 기록만 했다.

**옛 판·새 판 섞임**
- 옛 서버 + 새 허브: 낱장 카드로 떨어지고 `folder-cards` 404 는 자리를 옮길 때만(반복 없음). 서버를 새 판으로 바꿔 끼운 뒤 새로고침하면
  에피소드 카드가 나온다. 새 허브를 쓰다 옛 허브(0836)로 되돌려도 화면 정상 — 새 판이 남긴 키를 옛 화면은 읽지 않는다.
- 못 본 것: 운영 DB 스키마에서 올라가는 길 전체(시험 사본에서 `folder_cover` 표만 빼 흉내 냄) · '5분에 한 번 다시 묻기'를 기다린 것은 아님.

**편집 탭**(b120 — 그 뒤에 고친 것이 있다)
- 편집 탭 조각(약 110KB)은 누르기 전에는 받지 않는다. 여는 데 30ms(클립 300개 100ms). 문서는 클립당 약 150글자.
- **공유 & 리뷰 탭 위에 띄워 두면 15초마다 시퀀스의 공유 목록 전체를 다시 받는다**(문서의 "폴링 없음"과 다름 — 생성물 300개면 60초에 8.7MB).
  **재생 중 프레임마다 문서 전체 스타일 재계산**(타임코드 글자를 `textContent` 로 쓰는 두 곳 — 클립 300개에서 프레임당 7ms씩).
  → 고침(`fix/edit-tab-idle-cost` — 15초 틱에는 왼쪽 폴더 숫자만 다시 받는다 · 글자 노드의 값만 고친다 · 안 보이는 소스 판은 영상을 받지
  않는다). **고친 빌드(b128)로 다시 잼**(조건마다 1회 · 같은 격리 조건):

  | | 고치기 전(b120) | 고친 뒤(b128) |
  |---|---|---|
  | 공유 & 리뷰 탭 위 편집 탭(생성물 300)의 60초 api 전송 | 45건 · 8.7MB | 37건 · 3.48MB(공유 & 리뷰 탭만 둔 것과 같다) |
  | 시퀀스 공유 목록 요청 | 15초마다 2쪽 1.24MB | 0건 |
  | 재생 15초의 메인 스레드(클립 300) | 11,270ms(75%) — 스타일 5,718ms | 3,803ms(25%) — 스타일 75ms |
  | 같은 것(클립 5) | 2,857ms(19%) | 1,170ms(7.8%) |
  | 45초 재생(클립 300)의 50ms 넘는 프레임 간격 | 20번(52.4fps) | 0번(56.2fps) |
  | 가만히 둔 30초에 편집 탭이 얹는 몫(클립 300) | +447ms | +66ms |
  | 싱글 뷰어에서 카드를 누른 뒤 숨은 소스 판 | 영상 7.1초를 통째로 받음 | 주소 없음 · 요청 0건(듀얼로 바꾸면 그때 받는다) |

  고치기 전의 첫 두 줄과 마지막 줄은 앞선 실측 보고의 숫자다(로그로 다시 확인하지 못했다). b128 뒤에 편집 탭 프런트가 더 바뀌었고
  마지막 dev 빌드로 다시 재지는 않았다. 못 잰 것: 실제 변경 알림 때 공유 목록을 다시 받는지 · 듀얼 뷰어의 재생 비용.
- 전부터 있던 것(이번에 그대로): 새로 고침 뒤 클립 300 시퀀스를 열면 길이 재기가 CDN 영상을 다시 받는다 — 처음 열기 828건 · 181.7MB,
  다시 열어도 842건 · 157.8MB. 편집 탭 위에서도 밑 탭(공유 & 리뷰)의 목록은 15초마다 712KB 씩 온다(남은 전송의 약 82%).
- 판단을 넘긴 것: 뷰어 `preload="auto"`(열기만 해도 재생헤드 자리의 영상을 통째로) · 영상 클립마다 열 때 길이를 묻는 요청(저장은 모아 한 번으로 줄였다) · '한 트랙만 보기'의
  멈춘 rAF · 새 판 직후 첫 클릭의 빈 화면 0.9~3.5초.

  실제 Resolve · 실제 NAS 지연 · 운영 적용)은 현황판의 '검증 한계' 그대로다.

  Resolve 메뉴 스크립트 `resources/resolve/MVHub_Importer.py` 에는 같은 `SaveProject` 모양이 남아 있다(설치되는 파일이라 따로 정할 일).
- 새 조작 셋은 실제 화면에서 Jay 가 아직 보지 않았다. 모의 그림에 물은 셋(뒤만 자르기 · 전부 끈 폴더는 5초 · 카드 위 끌기 = 끌어 넣기)은
  추천값으로 지었다.
- **키보드만으로는 길이 조절 창을 열 수도 컷 순서를 바꿀 수도 없다**(Codex P2 — 보류). 타임라인의 클립은 원래 초점을 받지 않아 고르기·끌기도
  마우스뿐이다. 선택 클립의 명령·컷 머리 메뉴(앞으로/뒤로)는 새로 보이는 화면이라 Jay 에게 먼저 묻는다.
- 편집 탭의 길이 재기: 영상 클립은 페이지를 열 때마다 다시 잰다(요청 수는 줄지 않았다). 저장은 값이 한꺼번에 오면 1번, 띄엄띄엄 오면(영상을
  처음 받을 때) 클립 10~20개에 4~12번이다 — 클립 수보다는 적지만 '한 번'은 아니다. 다시 열면 0번(값이 한 프레임 안으로 같다). 건너뛰려면 문서에 '쟀다'는 표시를 따로 적어야
  한다 — 문서 칸이 늘어 이번에는 하지 않았다.
- 새 조작에서 Jay 에게 그림으로 물을 표시 둘(격리 실측의 관찰 — 결함은 아니다): 축소하면 컷 칸이 10px 안팎이라 무엇을 잡았는지 줄 말고는
  안 보인다(포인터 옆 이름표) · 가장자리 자동 넘기기 중에는 끼움 줄이 화면 밖일 때가 있다(자리 계산은 맞다).
