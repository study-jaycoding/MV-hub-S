## 4. 찾아서 고친 것

Codex 의 지적은 상대 보고다 — 코드를 읽어 확인한 뒤에 고쳤다. 자세한 까닭은 각 커밋 글과 정본 문서에 있다.

**편집 문서(브라우저에만 있고 백업이 없다)**
- 새 판을 쓰다 옛 판으로 되돌린 뒤 계정을 바꾸면 **모든 계정의 편집본이 지워졌다**(옛 판의 계정 전환 정리가 `ch.*` 를 지운다) → 키를
  `mvhub.editDoc:` 로. 옛 자리의 문서는 **옮기지 않고 읽기만** 한다 — 옮기기(복사 → 삭제)는 두 창이 엇갈리면 방금 저장한 편집을 덮었다
  (Codex 재검토 P1 두 번).
- 다른 창이 저장한 것을 알림이 오기 전에 덮던 것 → 바꾸기 직전에 저장소를 보고, 달라졌으면 받아들이고 **이번 조작은 버린다**.
  바꾸기의 결과는 셋(`done`·`none`·`stopped`).
- 저장하지 못한 편집이 있는데 앱이 스스로 새로고침하던 길: 업데이트 완료(덮개 · 설정 창의 폴 · 예약한 0.6초 사이) · 로그아웃(확인 창 ·
  응답을 기다리는 동안의 편집 · 두 번 누름 · 끝나지 않는 응답) · DB 가져오기·복원의 확인 창. 남긴 길은 [EDIT_TAB.md](../EDIT_TAB.md) §4.

**Resolve**
- 가져오는 도중 Resolve 에서 다른 프로젝트를 열면 **그 프로젝트에 쓰고 저장했다** → 쓰는 호출 바로 앞마다 프로젝트를 다시 확인한다.
  Bin 순서를 다시 짓다 멈추면 남은 임시 Bin·백업 자리를 결과와 글에 싣는다. **실제 Resolve 로는 재지 않았다**(가짜 Resolve 시험).
- 이름 규칙의 번호 배정이 저장·전송 한 번에 대상 폴더를 여러 번 훑던 것 → 한 번.

**공유 & 리뷰의 컷 카드**
- 정보판 크레딧을 카드 수만큼 묻던 것 → 화면에 든 카드만, 떠난 화면의 요청은 줄에서 뺀다 · 시간 제한 · 캐시 상한.
- 폴더를 옮길 때 묶음 조회가 두 번 나가던 것 · 옛 서버라는 기억을 영영 믿던 것(5분에 한 번 다시 묻는다) · 응답에 화면이 안 쓰는
  칸까지 실려 60컷에 3.2MB 이던 것.
- 폴더별 모양 기억이 다른 창의 값을 덮던 것 · 저장에 실패한 자리의 모양이 옛 값으로 돌아가던 것 · [대표] 단추가 키보드로 안 눌리던 것.
- 컷 카드 정보판의 줄이 카드마다 달라 보이던 것(Jay 10-13) → 날짜는 늘 두 줄, 줄 높이를 카드마다 같게.

**편집 탭**
- 크게 보기·비교·폴더 창으로 넘겨도 뒤에서 재생·소리가 계속되던 것 → 두 시계를 멈춘다.
- '빈 트랙 모두 삭제'가 잠긴 빈 트랙까지 지우던 것(하나씩은 못 지운다) → 남긴다(**Jay 미확인** — 정본에 맞춘 판단).

## 5. 실측에서 나온 숫자

**컷 카드 화면**(격리, 헤드리스 크롬 1600×1000, 60컷·200컷 에피소드 — 건수·바이트는 회마다 같았고 시간은 1~5회)

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 정보판 크레딧 요청(첫 화면) | 카드 수만큼(60 · 200건) | 화면에 든 14건(스크롤하면 그만큼 더) |
| 떠난 화면의 크레딧 요청 | 56 · 196건이 떠난 뒤에도 나감 | 0건 |
| 묶음 조회 응답 한 건 | 60컷 3,177KB · 200컷 10,159KB | 257KB · 639KB |
| 맨 위 → 에피소드의 묶음 조회 | 4건 6.59MB | 2건 0.28MB |
| 가만히 둔 60초(60컷 · 200컷) | 17.2MB · 43.9MB | 5.7MB · 7.2MB |
| 처음 가는 에피소드(60 · 200컷) | 463ms · 652ms | 같음 |

- **정정 — 결함이 아니었다**: 처음 실측은 '모아보기에서 [폴더로] 로 컷에 들어갈 때만 목록 2건·묶음 조회 4건'이라고 했다. 호출 스택과
  인터벌 기록을 찍어 다시 재니(압축 안 한 빌드, 17세션) 둘째 묶음은 **15초 주기 조회**(`useGenerationAutoRefresh`)가 누르는 순간과 겹친
  것이었다 — 누름 자체는 20번 모두 목록 1건·묶음 조회 2건. 실측 도구의 '요청이 잠잠해질 때까지 기다리기'가 첫 주기 조회 뒤에야 풀려
  걸음들이 15초 격자에 맞춰졌다. **걸음별 요청 수를 셀 때는 인터벌이 부른 요청을 따로 가려야 한다.**
- 가만히 둘 때 15초마다 오는 목록(60컷 에피소드 화면에서 1.07MB)이 이제 가장 크다(전부터 있던 것). 묶음 보기에서는 낱장 목록이 화면에
  안 보이는데도 받는다 — 폴더 카드의 '바뀜 신호'로만 쓰인다. 줄이려면 목록 훅을 고쳐야 해 이번에는 기록만 했다.

**옛 판·새 판 섞임**
- 옛 서버 + 새 허브: 낱장 카드로 떨어지고 `folder-cards` 404 는 자리를 옮길 때만(반복 없음). 서버를 새 판으로 바꿔 끼운 뒤 새로고침하면
  에피소드 카드가 나온다. 새 허브를 쓰다 옛 허브(0836)로 되돌려도 화면 정상 — 새 판이 남긴 키를 옛 화면은 읽지 않는다.
- 못 본 것: 운영 DB 스키마에서 올라가는 길 전체(시험 사본에서 `folder_cover` 표만 빼 흉내 냄) · '5분에 한 번 다시 묻기'를 기다린 것은 아님.

**편집 탭**(b120 — 그 뒤에 고친 것이 있다)
- 편집 탭 조각(약 110KB)은 누르기 전에는 받지 않는다. 여는 데 30ms(클립 300개 100ms). 문서는 클립당 약 150글자.

  **재생 중 프레임마다 문서 전체 스타일 재계산**(타임코드 글자를 `textContent` 로 쓰는 두 곳 — 클립 300개에서 프레임당 7ms씩).

  않는다). **고친 빌드(b128)로 다시 잼**(조건마다 1회 · 같은 격리 조건):

  고치기 전의 첫 두 줄과 마지막 줄은 앞선 실측 보고의 숫자다(로그로 다시 확인하지 못했다). b128 뒤에 편집 탭 프런트가 더 바뀌었고
