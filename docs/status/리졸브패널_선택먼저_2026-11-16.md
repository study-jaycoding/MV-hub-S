## 원인(코드)

- 패널의 모든 리졸브 일은 한 줄짜리 대기열(`useResolvePanel.enqueue` — Promise 사슬, 들어온 차례대로)이다. 따라가기 읽기(poll)·패널 클릭(target/stage)·미리 띄우기 조각(prestage)·이름 정리 조각(rename)이 같은 줄에 선다. 리졸브 쪽도 변경 잠금 하나라 동시에 둘은 못 한다(Codex `01a1e2b8`).
- 이름 정리는 한 조각이 끝나면 바로 다음 조각을 줄 끝에 넣고(renameStep), poll 은 '앞 일이 끝난 뒤 0.7초/2초 기다렸다' 다음 읽기를 넣으므로, 이름 정리가 이어지는 동안 poll 은 조각 하나 끝날 때마다 한 번꼴로만 끼어든다.
- 패널에서 컷을 누르면 `stageCut` 이 **받기 확인(cache) → target(빈 고르기) → stage** 순서라, 빈이 바뀌는 것은 받기 확인 뒤다(Codex).

## 바꾸는 것(1판 초안 — Codex 확정 전)

1. **실행자는 하나, 줄은 둘**: 대기열을 '사람 줄'(패널 클릭의 target·stage, 따라가기 stage, [맞추기]·재시도, current-bin 읽기)과 '배경 줄'(미리 띄우기 조각·이름 정리 조각·실시간 빈 만들기 sync)로 나눈다. 돌고 있는 일은 끝까지 하고, 다음 일을 고를 때 **사람 줄이 비어 있을 때만 배경 줄**에서 꺼낸다. [NAS] 저장 흐름은 지금처럼 한 덩어리(사이에 아무것도 안 끼움).
2. **사람이 움직이면 배경 쉬기**: 패널 클릭·다빈치 빈 바뀜을 본 뒤에는 배경 줄을 잠시 멈추고, '같은 빈을 두 번 연속 정상 관측 + 사람 줄 비어 있음'이 되면 다시 꺼낸다(고정 3초 대신 — Codex). 쉬는 동안 poll 은 정상 간격.
3. **빈 고르기 먼저**: 패널에서 컷을 누르면 target(빈 고르기)을 먼저 하고, 받기 확인·stage 는 그 뒤. 이미 받은 컷은 target 직후 stage 로 바로 보임. 받지 않은 컷은 빈은 바로 바뀌고 받는 동안 진행 표시.
4. **오래된 선택은 합치기**: 사람 줄에 같은 종류의 낡은 선택(seq 가 더 새 선택에 밀린 것)이 쌓이면 마지막 것만 실행.
5. **이름 정리 조각 줄이기(검토)**: 10개 → 5개(읽기 40 → 20)로 줄여 한 조각 시간을 줄일지 — 전체 시간이 늘어나는지와 함께 Codex 판단.

## 완료 조건(초안 — 목표치, 예측 아님)

- 시험: 배경 일(이름 정리 조각)이 도는 중에 사람 선택이 들어오면, 그 조각이 끝난 **바로 다음**에 사람 선택이 실행되고 그 뒤 배경이 이어짐 · 사람이 움직인 뒤 배경은 같은 빈 두 번 관측 전엔 안 꺼냄 · 패널 컷 클릭 = target 이 cache 보다 먼저 · 낡은 선택은 실행 안 됨 · [NAS] 흐름 사이에 다른 일이 안 끼어듦 · 계약 1 의 되풀이 0·헛일 0 그대로.
- 실측('mv test', 시간 기록): 배경 없을 때 다빈치 클릭 → 패널 따라감 p95 1.5초 · 이미 찬 빈 패널 클릭 → 다빈치 빈 바뀜 p95 2초 · 이름 정리 중 따라감 p95 4초(각 20회 — Codex 확정안 2). 클릭 시각은 관찰 도구(다빈치 지금 빈 바뀜)와 허브 기록(reason=follow/select 의 요청 시작)으로 잰다.
