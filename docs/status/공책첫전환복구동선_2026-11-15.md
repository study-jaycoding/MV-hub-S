# 허브 공책 첫 전환 복구 동선 (2026-11-15)

> [공책 기본 끔 기록](배포후보_공책기본끔_2026-11-15.md) 의 "복구 동선은 다음" 을 만든다. **배포 후보 `61eba19a` 에는 넣지 않는다**(dev 의 다음 변경). Jay /goal("남은 것들도 모두 진행, 정할 것은 Codex 와")에 따라 시안(작업 폴더 `recovery-mockup\mockup.png`)의 권고안 J1~J3 으로 진행한다.

## 왜

공책을 켠 판에서 브라우저가 처음 합류할 때 로컬 씬이 허브 미러와 다르면 로컬 씬 전부를 `["nr", 계정]` 보관함에 넣고 캔버스를 미러로 바꾼다(`frontend/src/lib/sceneNotebook.ts` `adoptRestoredNotebook`). 지금 되살리는 길은 설정 → 자료 관리 → '복원 전에 남겨 둔 것' 에서 파일로 내려받아 전체 가져오기뿐이라, 사용자는 전환이 일어난 줄도 모르고 씬이 사라진 것으로 본다.

## 설계(Codex `01a1de9b` 설계 확인 DESIGN-CHANGES · 합의 1차 Codex·비참여 Claude `e1a0bae6` 지적 반영판)

- **공책 켬에서만**: 첫 전환은 공책 켬(`scene_writer_v1`)의 합류에서만 생긴다. 알림·고르기·되살리기는 허브 기능에 공책이 있을 때만 보인다. 공책 끔에서는 지금처럼 '복원 전에 남겨 둔 것' 의 [보관본 내려받기]·[전체 가져오기로 되살리기]만 둔다 — 끔의 미러 재개(`resumeImportedMirror`)는 현재 서버 지문을 기준판으로 삼아, 로컬엔 없고 서버엔 다른 내용이 있는 ID 를 되살리면 서버 내용을 바꿀 수 있어서다(Codex 차단 사유 1).
- **알림(J1)**: 본 창(`!isCanvasWindow()`)의 캔버스 탭에 캔버스가 이 창에 있을 때만 알림 줄 — "허브 공책으로 바꿨습니다. 이 브라우저에만 있던 씬 N개는 지우지 않고 보관했습니다 [보관한 씬 보기] ✕"(N = 그 묶음에서 고를 수 있는 행 수). 묶음의 `fromGeneration` 이 있으면(허브를 백업에서 되살려 세대가 바뀐 경우) 앞말을 "허브 기록이 바뀌어" 로. 대상 = 되살릴 수 있는 행이 있는 보관 묶음 가운데 **본 적 없는 것 중 가장 최근**(createdAt). 닫거나 되살리면 그 묶음 id 를 `localStorage` `mvhub.restoreNoticeSeen:<계정>` 에 적고, 적을 때 지금 남아 있는 묶음 id 만 남긴다(개수로 자르지 않아 옛 묶음이 다시 뜨지 않게). 읽기 실패·낡은 기준(`fresh=false`)·기록 없음이면 알림을 그리지 않는다('되살릴 것 없음' 으로 단정하지 않는다).
- **알림의 읽기 비용(비참여 Claude B1)**: 보관 묶음은 줄지 않으므로 알림은 **씬 저장 알림을 구독하지 않는다**. `readRestoreArchives` 를 마운트·계정·허브 기능·다른 탭의 저장소 변경·창 focus 때와, `adoptRestoredNotebook` 이 보관 묶음을 새로 적었을 때 내는 신호(`sceneNotebook.ts` 의 구독 한 쌍)에서만 읽는다. 행 상태를 견줄 지금 씬은 그 읽기 때와 대화상자를 열 때 다시 본다. 설정 화면의 `useStorageRecovery` 는 그대로(열려 있을 때만 붙는다).
- **행(고르기 대상)**: 보관 묶음의 이 계정 버킷(`<계정>::…`) 씬만, 버킷이 다르면 같은 ID 도 다른 행. 상태는 지금 확정본(`listPersistedScenes(null)`, 둘 다 `readStoredScene` 정규화)과 견준다 — 같은 ID·카메라를 뺀 같은 내용 = '이미 있음' · 이미 만든 사본 = '이미 되살림'(판정은 `mergeArchiveBucket` 과 같은 `copyKey(행 ID, sceneBodySum(정규화한 행))`) · 같은 ID 다른 내용 = '다름' · 없음 = '캔버스에 없음' · 정규화에 실패한 보관 씬 = '읽을 수 없음'. '다름'·'캔버스에 없음' 만 고를 수 있다(읽을 수 없는 씬 하나가 가져오기 글 전체를 거절시키지 않게, 내려받기는 남는다). 카메라는 비교에서 뺀다.
- **고르기(J2)**: 대화상자에 행을 묶음(만든 때)별로 — 이름·카드 수·상태. 기본 선택 = 고를 수 있는 것 전부. [파일로 내려받기](그 묶음, 기존 `downloadNotebookArchive` 형식) · [닫기] · [N개 되살리기]. 알림에서 열면 그 묶음만, 설정에서 열면 본 것까지 모든 묶음.
- **되살리기**: 실행 직전(가져오기 호출 바로 앞, 사이에 기다림 없이) 계정·공책 켬·이 창이 캔버스 쓰기를 쥐었는지(`isCanvasFloating` 의 다른 창·인계·동기화 제한, 쓰기 상태가 away·taking·giving·checking·syncing 아님)를 다시 확인한다. 고른 씬을 전체 가져오기 형식의 글로 만들어 기존 `importSceneArchiveText` 에 넣는다 — 버킷은 지금 캔버스(`<계정>::_none`), **`conflicts` 는 빈 배열**(합류 때 일부러 뺀 충돌을 '[옛 창]' 탭으로 되살리지 않게 — 비참여 Claude B2). 버킷이 다른 같은 ID 두 행을 함께 고르면 기존 규칙대로 하나는 그대로, 하나는 '[사본]'. 기존 합치기 규칙 그대로: 캔버스에 없는 ID 는 그대로 더하고(공책 켬은 같은 ID 의 허브 삭제본이면 되살림 의도, 기준판을 모르는 충돌이면 서버가 사본으로 보존 — `sceneStore.ts` 복원 의도·`scene_notebook.py` 판정), 같은 ID 다른 내용은 새 ID 의 '[사본] 이름' 탭(시안의 '[보관본]' 대신 이미 쓰는 '[사본]'). `comfyRuns`·`comfyCardRuns` 는 기존처럼 뺀다. 허브 씬을 덮지 않고 보관함은 그대로 둔다. 결과 문구는 로컬과 허브를 나눈다 — "캔버스에 N개를 되살렸습니다(사본 M개) — 허브 공책에는 이어서 올라갑니다". 실패하면 오류 문구를 그대로 보이고 묶음을 '본 것' 으로 적지 않아 다시 시도할 수 있다. 허브에서 지운 씬의 ID 를 되살리면 그 지운 판의 내용이 보관 판 내용으로 바뀐다(기존 되살림 규칙 `write_row` 와 같다 — 사용자에게는 새로 보이는 동작이라 문서에 적는다).
- **카드 소속 되살리기와 계정 전환(합의 1·2차 → 독립 리뷰 `01a1debc` 뒤 4판에서 다시 설계)**: `importSceneArchiveText` 는 로컬 저장을 기다린 뒤 계정이 바뀌었으면 던져 카드 소속 되살리기(`reviveCardGenerations`, 지금 계정에 넣는다)에 닿지 않는다. 3판의 별도 표식(`mvhub.restoreRevive`)은 독립 리뷰에서 쓰기 전 실패와 겹칠 때·열 때 계산한 행 상태와 실제 병합이 다를 때·표식 저장 실패 때 틀리거나 잃는다는 지적(높음 2·중간 1)을 받아 **없앤다**. 대신 가져오기 함수 안에서 처리한다: 저장이 **성공한 뒤**(`!out` 이면 기존처럼 바로 던지고 아무것도 넣지 않는다) 계정이 바뀌어 있고 공책 켬이면, **실제 병합에서 같은 ID 로 들어간 씬**(`restored`, 사본 제외)의 카드 소속 되살리기를 **가져오기를 시작할 때 잡은 계정과 그때 읽은 복원 세대**로 그 계정의 카드 소속 대기열(`ch.sceneCardRevives.v1.<계정>`)에 넣는다(`sceneCardLinks.ts` 의 함수 하나, 같은 소속의 제거 대기는 기존 규칙대로 상쇄). 그 계정이 다시 활성일 때 기존 대기열 전송이 보낸다(활성이 되는 순간이 아니라 기존 전송 계기 — 마운트·카메라가 아닌 저장·online — 에서. 보내기 전 `load` 가 저장소 대기열을 다시 읽는다). 모듈이 아직 그 계정을 현재로 들고 있으면(계정이 바뀐 직후 `enterScope` 전) 메모리 대기열도 같이 맞춘다. 대기열 저장은 앱의 다른 되살리기와 같은 방식(저장 실패 시 그 세션의 메모리 대기열)이다. 그다음 기존처럼 계정 전환 오류를 던진다. 계정이 그대로면 지금처럼 `reviveCardGenerations`. 공책 끔(미러) 가져오기는 바꾸지 않는다. 이 처리는 파일 가져오기에도 같이 적용된다(같은 함수).
- **알림 갱신**: 알림 쪽은 낡은 읽기 회복 알림(`subscribeSceneStoreStale` — 저장 알림이 아니다)도 받아 낡은 첫 읽기 뒤 다시 읽는다. 설정에서 되살리거나 알림을 닫아 '본 것' 이 바뀌면 같은 창 안의 알림에도 신호를 보내 바로 갱신한다(`storage` 이벤트는 같은 창에 오지 않는다).
- **여러 묶음을 한 번에**: 설정에서 여러 묶음의 행을 되살리면 고른 행이 하나라도 있던 묶음을 '본 것' 으로 적는다.
- **다시 찾기**: 설정 → 자료 관리 '복원 전에 남겨 둔 것' 칸에 [보관한 씬 고르기](공책 켬이고 고를 수 있는 행이 있을 때) — 같은 대화상자. 기존 보관 개수·내려받기는 그대로.
- **계정 전환**: 대화상자와 선택은 계정 단위 — 계정이 바뀌면 닫는다.
- **J3**: 이 동선은 공책 기본 끔을 되돌리지 않는다. 구현·검증 뒤 기본 켬을 다시 검토한다(자동 재활성화 아님).
- 범위 밖: 보관함 자료 형식·첫 전환 판정·서버, 분리 창 안의 알림, 공책 끔에서의 고르기, 영어 문구(이웃 문구와 같이 한국어만).
