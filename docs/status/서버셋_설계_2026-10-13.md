"서버와 같이"라고 적어 둔 것은 셋 중 ②뿐이었다. ①③은 로컬 허브(각 PC 의 `backend`)가 처리하는 경로라 앱 배포에 같이 나간다 — 조사에서 `_proxy.py` 의 로컬 처리 목록(`/api/assets/`·`/api/tags`·`/api/auto-tags`)으로 확인됐고, 라우트 정의는 내가 다시 봤다(아래). **단** `docs/기능설명서.md:18` 에 공유 서버에 브라우저로 직접 접속하는 운영 방식이 적혀 있다(Codex 설계 검토 — 지원 경로는 확인, 실제로 쓰는지는 미확인): 그 방식에서는 ①의 태그·전역 태그 삭제가 공유 서버 라우트를 타므로 **①은 서버도 같이 배포**해야 그 창에서 지워진다. ③의 Assets 쓰기는 로컬 접근 제한이 있어 서버와 무관하다.

호환의 전제 하나: 옛 라우트를 남기면 **옛 앱 → 새 허브**는 안전하지만, **새 앱 → 옛 허브**(③의 `/tags/ops`)는 404 다. 앱과 허브는 한 묶음으로 배포되므로 이 조합은 생기지 않는다는 조건을 둔다 — 전체 목록 PUT 으로 조용히 되돌아가는 폴백은 **넣지 않는다**(덮어쓰기 문제를 다시 연다. Codex).

## ① 이름에 `/` 가 든 태그·전역 태그·Assets 등록을 지울 수 없다

### ① 지금 구조(확인)

- 프론트는 이름을 주소 한 칸에 넣는다 — `encodeURIComponent` 라 `/` 는 `%2F` 로 간다.
  - 태그 전체 삭제 `DELETE /api/tags/{tag}` (api.ts:733) · 전역 태그 삭제 `DELETE /api/auto-tags/{name}` (api.ts:769) · Assets 등록 해제 `DELETE /api/assets/mounts/{name}` (assetsApi.ts:142).
- 백엔드 라우트(확인): `generation.py:817 @router.delete("/tags/{tag}")` · `library.py:1192 @router.delete("/auto-tags/{name}")` · `assets.py:769 @router.delete("/mounts/{name}", …_require_mount_manager)`.
- 만드는 쪽은 셋 다 JSON 본문이고 서버는 이름을 검사하지 않는다(strip·빈 값·중복만). 그래서 옛 앱이나 다른 입구로는 지금도 `/` 이름이 생길 수 있다.
- 왜 못 지우나(추정 — 실행 안 함): uvicorn 이 `%2F` 를 `/` 로 풀어 라우팅하므로 `{tag}` 한 칸과 안 맞아 404/405. `_proxy.py:607-610` 주석이 그 디코딩을 말한다.
- 저장 위치: 모두 PC 마다 로컬 허브의 계정별 DB(`data/db/acct/<slug>/content_hub.db` — `tag`·`gen_tag`·`gen_tag_overlay`·`auto_tag`)와 JSON(`asset_mounts.json`). 공유 서버 DB 가 아니다.
- 26회차 프론트 거절(`lib/nameGuard.ts`)은 `/`·`.`·`..` 만 막는다. `\`·`|` 거절은 `MountManager.tsx:63` 에만 있고(레퍼런스 표기 `asset:이름|경로` 와의 충돌) 태그에는 없다 — 조작점검 문서에 "nameGuard 가 `\|` 도 막는다"고 적은 것은 틀렸다(아래 '정정').

## ② 작업 달력이 새벽(KST 00~09시)에 만든 컷을 전날 칸에 놓는다

### ② 지금 구조(확인)

- `generation.created_at` 은 UTC(`datetime('now')`, 일부 `…T…Z` 꼴 — 둘 다 UTC).

- 서버 자동 작업기간: `manage_tasks.py:868 g["created_at"][:10]` — UTC 날짜. **DB 에 쓰지 않고 응답에만** 담는다(과거 데이터 처리 불필요). `/api/manage/*` 는 공유 서버로 중계되므로 이 계산은 공유 서버에서 돈다.
- 시간대: 앱은 `config.py` 가 `TZ=KST-9` 로 고정(서버 OS 는 UTC — 메모). 대시보드 생성기간은 이미 `datetime(created_at,'localtime')`(KST, `manage_db.py:1087`)이고 사용량 집계도 KST 자정 경계(`manage_db.py:503-518`) — **관리 화면 안에서 대시보드·집계는 KST, 작업 달력·파생 기간만 UTC** 로 어긋나 있다.
- 프론트의 UTC 문자열 읽기 선례: `lib/dateGroups.ts:21-24`(`iso.replace(" ","T")+"Z"` → 로컬 날짜), `generationDisplay.ts parseCreatedAt`.

## ③ 같은 계정의 두 창에서 같은 Assets 파일 태그를 편집하면 한쪽이 지워진다

### ③ 지금 구조(확인)

- 저장은 목록 통째: `PUT /api/assets/tags {project, path, tags}`(assetsApi.ts:430) · `PUT /api/assets/tags/batch {project, items:[{path,tags}]}`(assetsApi.ts:435, 500개씩). 백엔드 `repo/assets.py:701 set_asset_tags_batch` 가 `BEGIN IMMEDIATE` 안에서 `UPDATE asset_meta SET tags=<JSON>` 으로 덮는다(빈 목록이면 NULL).
