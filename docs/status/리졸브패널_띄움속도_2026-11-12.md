## 설계

1. **A 묶어 띄우기(`_panel_stage`)** — ① 지금처럼 원하지 않는 내 항목 지우기 ② 클립 목록·표식·경로를 **한 번** 읽어 항목마다 present·same_file_exists·conflict(기록)·기록 이어받기·새로 가져올 것을 정한다 ③ 새로 가져올 것이 있으면 기존 `_import_groups` 묶음대로(영상은 잇달아 한 묶음, 스틸은 한 건씩) **묶음마다 직전에 지금 빈 == 목적 빈을 보고**(아니면 그 묶음부터 남은 항목은 모두 deferred) **목적 빈 클립 ID 를 다시 읽어 그 묶음의 '전 ID'로 삼은 뒤** 기존 `_import_media_items` 로 가져온다(스틸 한 건씩 넣는 동안 사람이 빈을 옮겨도 그 뒤 것은 안 가져오게 — 지금 코드의 항목마다 확인과 같은 보호 · 사람이 그사이 같은 파일을 가져온 클립을 '새 클립'으로 오인하는 틈을 그 호출 하나로 줄임) ④ **이번 ImportMedia 가 돌려준 클립**(그중 그 묶음의 전 ID 집합에 없는 것)만 다룬다 — 돌려받지 않은 클립(그사이 사람이 가져온 것 등)은 짝짓기·표식·지우기 대상이 아니다. 돌려받은 클립을 **정규화한 전체 경로**로 항목과 짝짓고 **목적 빈 클립 목록에 있는지** 확인 — 하나로 짝지어지고 목적 빈 안이면 성공. 짝이 둘 이상(모호)이면 그 항목은 import_failed 이고 그 클립들은 손대지 않고 unexpected 로 센다. 돌려받았는데 목적 빈 밖이면(그사이 지금 빈이 바뀜) import_failed 이고 **지우지 않고 '소유 미확인' 복구 기록(`owned: false`)만** 남긴다(리졸브가 그 빈에 원래 있던 같은 파일의 사람 클립을 돌려줄 수 있어 — 별도 Claude P3). 이 기록은 진단용이라 **이후 띄움의 기록 이어받기에 쓰지 않는다**(그 기록만으로 표식·이름·지우기 0 — Codex P1). 이어받을 기록을 고를 때 **owned:false 를 먼저 걸러 낸 뒤** 고른다(한 생성물에 보통 기록과 owned:false 기록이 같이 있어도 보통 기록이 가려지지 않게 — 별도 Claude P3). 기록의 `bin_id` 는 실제로 들어간 빈(지금 빈 목록에 있으면 그 빈 ID, 모르면 빈 글자)이고, 이 기록은 그 클립을 정리하지 않는다(클립은 그 빈에 남는다). 다른 import 기록처럼 그 생성물이 staged·present 가 되면 지워진다. 짝 없는 돌려받은 클립은 unexpected 로 센다(손대지 않음 — 지금과 같음). **가져온 뒤 표식을 다 붙이기 전에 예외가 나면**(프로젝트 바뀜·목록 읽기 실패 등) 이번에 돌려받은 클립 중 표식이 안 붙은 것을 복구 기록으로 결과에 실어 올린다 — **짝짓기·목적 빈 확인을 끝낸 클립은 일반 기록**(성공 길에서 표식을 붙일 것과 같은 증거), **확인을 끝내지 못한 클립(목록 읽기 실패·프로젝트 바뀜 등으로 짝짓기 전)은 `owned: false`**(이어받기 제외 — Codex P1) · `_panel_stage` 안에서 예외(ResolveBridgeError 든 목록 읽기 실패 `_Unknown` 같은 일반 예외든)를 잡아 leftover(`import_records`)를 단 ResolveBridgeError 로 다시 올린다(원래 code 유지 — panel_operation 은 ResolveBridgeError 의 leftover 만 결과에 싣고, 라우터는 상태와 상관없이 저장한다. 별도 Claude P2·P3) ⑤ **표식을 모두 먼저**(그래야 이름 바꾸기 도중 끊겨도 내 항목으로 찾는다) ⑥ **이름은 맨 뒤에** 모두 바꾸고 ⑦ 이름을 한 바퀴 되읽는다. 표식·이름 실패는 지금처럼 그 클립을 지우고(사용 0 일 때만 — 그사이 사람이 썼으면 안 지움), 못 지우면 복구 기록. **stage 요청 전체에서 같은 경로는 대표(첫) 항목 하나만 가져오고(가져오기 묶음이 달라도), 둘째 항목부터는 대표의 최종 결과로 정한다** — 첫 항목이 staged 로 남으면 same_file_exists, 아니면 첫 항목과 같은 상태(deferred·import_failed). 결과 상태 이름·순서·`import_records`·`unexpected_imports`·`deferred`(= deferred 상태 항목 수 — 묶음째 보류·대표를 따른 보류 포함)·`removed` 는 지금과 같다. 클립은 가져오기 직후 다빈치 미디어 풀에 들어가고(화면 표시 시점은 미측정) 이름은 개당 ~0.1초씩 뒤따른다. 표식 뒤 이름 전에 끊기면 그 클립은 파일 이름으로 남는다 — 다음 띄움은 present 로 보고 이름을 다시 바꾸지 않는다(사람이 바꾼 이름을 덮지 않으려고).
2. **B 켜짐 확인 건너뛰기(`run_resolve_panel_isolated`) — 읽기만** — 시간 제한이 있는 읽기 작업(current-bin 8초·inventory 20초)만, 패널 자식이 리졸브 프로젝트를 읽은 결과(`resolve_project_id` 있음)를 돌려준 뒤 10초 안이면 `_resolve_is_closed()`(0.38초)를 건너뛴다. **쓰기(target·stage·unstage·adopt)는 지금처럼 늘 확인**한다(쓰기 자식은 시간 제한이 없어, 리졸브가 막 꺼진 뒤 건너뛰면 잠금을 쥔 채 오래 멈출 수 있다 — Codex P2). 그래서 띄움(stage)에는 0.38초가 그대로 남는다. 자식 실패(예외·시간 초과·결과 없음·프로젝트 ID 없는 결과)는 기억을 지워 다음 작업이 다시 확인한다. 잠금·before_start·인터프리터 선택은 그대로.
3. **C 감지 간격** — current-bin 읽기를 고른 에피소드의 빈 표가 있으면 0.7초, 아니면 지금처럼 2초 간격으로(빈 표가 없으면 따라갈 것이 없다 — 자식 프로세스를 늘 0.7초마다 띄우지 않게).
4. **D 미리 캐시** — 에피소드를 고르면(컷을 골라도 같은 에피소드면) 화면이 그 에피소드 컷들의 거르기 통과 생성물 ID 를 컷마다 넘기고(고른 컷 먼저, 컷마다 띄움과 같은 범위 = created_at·id 순 오래된 200개), 훅이 대기열 밖에서 기존 cache API 로 컷마다 받아 둔다(리졸브 호출 0). **선택의 일이 먼저**: 요청마다 그 직전에 쓰기 대기열이 빌 때까지 기다린다(선택의 cache·target·stage 가 대기열에 있으면 그 뒤) · 새 선택의 cache·target 요청은 허브에서 seq 를 올려 진행 중인 미리 받기 요청을 **파일 사이에서** 멈추게 한다(받던 파일 하나는 끝까지 — 정상 캐시). **알고 가는 비용**: 허브 받기 잠금(`_prepare_lock`)은 허브 하나뿐이라, 미리 받던 파일 하나를 다 받을 때까지 선택의 cache·stage_items 가 기다릴 수 있다(큰 원본·느린 네트워크면 길어짐 — 별도 Claude P2, 결정으로 받음). **문맥 고정**: 미리 받기 한 판은 시작할 때의 프로젝트·에피소드·계정 문맥·목록(거르기 포함)에 묶이고, 목록이나 거르기·에피소드가 바뀌면 화면이 새 판을 시작해 옛 판은 다음 확인에서 끝난다 · 매 요청의 seq 는 **지금 선택의 seq**(sequence 최댓값이 아님 — 정리용 inventory 순번이 선택의 cache·target 을 stale 로 만들지 않게)이고, 판이 같고 에피소드가 같을 때만 쓴다 · 받다 멈춘 컷은 같은 판이면 한 번 더 · **성공(cached)으로 확인된 ID 만** 다시 묻지 않는다 · 실패는 알리지 않음(들어갈 때 다시 받는다).
