## 2. 근거 (Claude 직접 확인, dev 066b1428)
- `agent_push.py:3590-3592`: `prompt == "(no text)"` 이고 `_placeholder_prompt_is_optional`(Kling 4.0·Flash image-to-video + 참조, MiniMax H3 + 참조)이면 `--prompt` 인자만 지운다. `prompt` 변수는 그대로다.
- `agent_push.py:3693-3695`: 제출 지문 `_submission_fingerprint(model, prompt, …)` 은 그 `prompt`("(no text)")의 해시를 `prompt_sha256` 으로 저장한다(`:2448-2464`).
- `agent_push.py:1484-1503` `_matches_submission_fingerprint`: 원격 작업의 `params.prompt` 가 문자열이 아니면(없으면) 바로 실패, 있으면 정규화 해시를 지문과 비교한다. 인자를 빼고 제출한 작업은 원격에 prompt 가 없거나 빈 값일 것이므로 대조가 실패한다.
- 결과: 제출 응답을 잃은 이 조합의 요청은 이미 생성된 원격 작업을 못 찾아 `no_match` 로 끝나고(`backend/app/repo/gen_requests.py:650` 부근에서 다시 실행 허용), 사용자가 다시 실행하면 같은 생성이 두 번 과금될 수 있다. 자동 재실행은 아니지만 기존 '이미 있는 작업 찾기' 보호가 무력해진다. main(693c12a9)은 "(no text)" 를 그대로 보내 대조가 맞았으므로 **main 보다 나빠진 것**(Gate 6-A 위반).
- 같은 문제를 이미 푼 선례: 업스케일은 CLI 가 prompt 를 거절해 `prompt = ""` 로 두고 제출하며(`:3499-3501`), 대조는 원격에 prompt 가 없으면 빈 값으로 본다(`:1495-1496`).

## 3. 설계
- 제출: "(no text)" 인자를 뺀 경우 `prompt` 도 `""` 로 둔다(업스케일과 같은 방식). 지문은 실제로 보낸 것(프롬프트 없음 = 빈 해시)을 담는다. 그 밖의 조합·진짜 프롬프트·미디어 없는 글 생성은 그대로.
- 대조: 원격 작업에 `prompt` 키가 없을 때 빈 값으로 보는 규칙을 **실제로 프롬프트 없이 제출하는 조합에만** 둔다 — 업스케일(지금 그대로) + 이번 자리표시 생략 조합(MiniMax H3, Kling 4.0·Flash 는 지문 params 의 `mode` 가 `image-to-video` 일 때) 이면서 지문의 `prompt_sha256` 이 빈 문자열 해시일 때. 빈 해시만으로는 '인자를 뺐다'는 증거가 아니므로(예: `"​"` 대본은 정규화 뒤 빈 해시) 모든 모델에 넓히지 않는다(합의 1차 Codex·Claude P2). 원격이 빈 문자열을 주는 경우는 지금도 맞는다. 원격 prompt 가 `null`·숫자 등 문자열이 아니면 지금처럼 거절한다. 진짜 프롬프트로 제출한 지문은 원격에 prompt 가 없으면 여전히 맞지 않는다.
- 바꾸지 않는 것: 서버 쪽 복구·재큐 규칙, 지문 형식(version 1), 다른 모델의 인자·대조 — 특히 보이스 체인지·더빙(빈 프롬프트 제출이지만 대조 동작은 지금 그대로, 넓히려면 실측 뒤 따로)·여러 화자 음성 대사(`audio_stored_params` 가 일부러 prompt 를 지워 자동 복구하지 않는 규칙 유지), 화면.
- 이미 저장된 "(no text)" 해시 지문(이 고침 전 dev 에서 begin 한 요청)은 바뀌지 않는다 — 새 제출부터 적용(main 에 배포된 적 없는 dev 전용).

## 4. 남은 위험
- 원격(Higgsfield)이 인자 없이 제출한 작업의 prompt 를 무엇으로 저장하는지(키 없음 / 빈 문자열 / 다른 기본 문구)는 유료 생성 없이 실측하지 못한다. 키 없음·빈 문자열 둘 다 맞게 하며, 다른 기본 문구를 넣는다면 그 조합은 여전히 `no_match`(지금 dev 와 같음, main 보다 나쁜 범위는 이 경우로 줄어듦) — 다음 실제 생성 때 확인할 항목으로 남긴다.
