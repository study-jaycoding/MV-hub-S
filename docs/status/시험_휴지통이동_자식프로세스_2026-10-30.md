# 휴지통 이동 시험 9건 실패 — 저장소 루트 실행 때 자식 파이썬이 `app` 을 못 찾음 — 2026-10-30

요청: 캔버스 한계 작업의 백엔드 전체 시험에서 `backend/tests/test_trash_transfer.py` 9건(`test_process_exit_recovery` 8 · `test_checkpoint_import_does_not_load_runtime_config` 1)이 실패했다. 제품 결함인지 시험 환경 문제인지 가르고, 고친다.

## 원인 (실측)

제품 결함이 아니라 **시험이 띄우는 자식 파이썬의 위치 문제**다.

- 시험 두 개가 `python -c "from app..."` 로 자식 프로세스를 띄운다. `-c` 는 **현재 폴더**만 모듈 경로에 넣는다.
- pytest 의 `-o pythonpath=…backend` 는 pytest 자신의 `sys.path` 만 바꾸고 자식에게 전해지지 않는다. 자식이 받는 것은 현재 폴더뿐이다.
- 그래서 저장소 루트에서 돌리면 자식이 `ModuleNotFoundError: No module named 'app'` 으로 곧바로 끝난다. 휴지통 코드는 실행되기도 전이다.
- `run-test`(의도 검사)는 항상 저장소 루트에서 돌기 때문에, 그 경로의 전체 시험에서 늘 같은 9건이 나왔다.

| 실행 위치 | 명령 | 결과 |
|---|---|---|
| `D:\ClaudeCode\MV-hub-S-dev` | `-c backend/pytest.ini --rootdir backend -o pythonpath=…` | 9 실패 · 27 통과 — 9건 모두 `No module named 'app'` |
| `D:\ClaudeCode\MV-hub-S-dev\backend` | 인자 없이 파일만 지정 | 36 통과 |

같은 파이썬(3.14.3)·같은 환경변수에서 위치만 달랐으므로 파이썬 3.14·환경변수·자식 프로세스 기동 자체는 원인이 아니다.

## 고침

두 `subprocess.run` 에 `cwd=config.BACKEND_DIR` 를 넘긴다. 제품 코드는 고치지 않는다. 같은 꼴이 `test_backup_admission_account_pin.py`(`cwd=str(worker_backup.BACKEND_DIR)`)에 이미 있다.
