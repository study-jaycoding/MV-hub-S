Jay:
- "영상 재생에서 우클릭을 하면 나오는 메뉴(크롬 메뉴)에서 동영상 프레임 복사·동영상 프레임을 다른 이름으로 저장 두 개만 나오게 할 수 있나? 디자인으로 보여줘" → 크롬 메뉴는 항목을 고를 수 없어 앱 메뉴로 바꾸는 안을 모의 이미지로 보임.
- "이름을 변경하고, 버튼을 누르지 않아도 영상 재생되는 곳에서 Ctrl+우클릭을 하면 캡쳐가 되게 한다. 다른 것도 () 안의 단축키로 — 동영상 프레임 복사 → **프레임 캡쳐 (Ctrl+우클릭)**, 동영상 프레임을 다른 이름으로 저장 → **프레임 저장 (Ctrl+Shift+우클릭)**. 이미지에서도 — **이미지 캡쳐 (Ctrl+우클릭)**, **이미지 저장 (Ctrl+Shift+우클릭)**. **Alt+우클릭**을 하면 원래 기본 우클릭 메뉴가 나온다."

## 결과(10-22)

- 시험: 프런트 전체 416개 파일·4,923개 통과 · 경계 검사·빌드 통과 · 새 시험 `previewMediaMenu` 9개(메뉴·단축키·Esc/바깥 누름·오디오 제외 + 클립보드·저장 함수 실물).
- 실제 크롬(격리 S 서버, dev 빌드 `index-DywFYBQL.js`, 진짜 마우스 우클릭) 5회 × 16개 확인 전부 통과: CDN 영상(854×480)·이미지(1024×1024) 각각 메뉴 이름·단축키 표시 · 메뉴 '프레임 캡쳐'와 Ctrl+우클릭 = 클립보드에 그 크기 PNG · Ctrl+Shift+우클릭 = 저장 창에 PNG(영상, 이름 끝 시각)/원본(이미지) · 저장 창 없는 환경 = 그 이름으로 PNG 내려받기 · Alt+우클릭 = 막지 않음 · Esc·바깥 누름 = 메뉴만 닫힘, 다음 Esc 에 크게 보기 닫힘. 헤드리스라 저장 창은 페이지 안 대역으로 받은 파일을 검사했다(진짜 저장 창은 미확인).
- 딜레이(3회): Ctrl+우클릭부터 클립보드까지 영상 약 0.34초 · 이미지 약 0.06초 — 같은 영상을 이미 한 번 뜬 뒤의 값. 처음 뜰 때는 CORS 사본을 다시 받는 시간이 더해진다(따로 재지 않음).
- 시험 함정: 앞 동작의 알림이 남아 있으면 알림만 보고 클립보드를 너무 일찍 읽는다(5회 중 2회 거짓 실패) → 클립보드 내용을 기다리게 고쳤다.
