# 계정 정리 영구 삭제를 켠다 — 한 번도 승인된 적 없는 계정만 (2026-11-17)

owner: Claude · reviewer: Codex · status: 구현 중 · touched_paths: 아래 계약 · updated: 2026-11-17

> 서버 관리 창 '계정 정리'의 영구 삭제는 11-03 배포 전 재검토(Codex `01a1a0d7`)에서 '삭제와 진행 중 쓰기의 경합'으로 꺼 두었다(`backend/app/routers/account_cleanup.py` `DELETE_ENABLED = False`, [수용 항목 재검토 수정](배포전_수용항목_재검토수정_2026-11-03.md)). Jay(2026-11-17): "계정 정리에서도 삭제가 가능해야 한다 … 잘못 만들어진 계정의 경우 생성물이 없다. 지워도 상관없다."

## Codex 결정 자문 (`01a1e6ef`, gpt-6.1-sol·high·read-only) — RECOMMEND-ENABLE-WITH

- 상수만 켜면 남는 틈: 요청이 승인 상태로 미들웨어를 통과(`main.py` 가 요청 초기에 계정을 담음) → 관리자가 차단 → 삭제 완료 → 앞 요청이 저장. 사람 댓글(`generation.py`·`assets.py` 가 작성자 계정이 살아 있는지 안 봄, 댓글 표에 작성자 외래 키 없음 — Codex 가 메모리 SQLite 로 삭제된 이메일 작성자 댓글 저장을 재현)·계정 상태 보고(`/ingest/account-report` → `hf_status:<email>`)가 그 예. 숨김이지만 승인된 계정은 이미 '먼저 차단'이라 안전.
- **한 번도 승인되지 않은 계정은 승인 전 토큰이 발급되지 않아**(`routers/auth.py`) 그 틈이 생기기 어렵다 — 코드 근거 추정. `approved_at` 은 첫 승인 때 채워지고 차단해도 지워지지 않는다(`repo/accounts.py` `set_account_status`: `approved_at=COALESCE(approved_at, datetime('now'))`).
- 권고 최소 안전장치: 삭제 잠금 안의 같은 판정에 **`approved_at IS NULL`** 을 더한다(DB 변경 없음·작고 되돌리기 쉬움). 한 번 승인됐던 계정까지 안전하게 지우려면 모든 쓰기 경로의 잠금 안 재확인이 필요해 크다 — 이번엔 안 한다.
- 반영: 공유 서버 기능이라 앱 릴리스 없이 main → 서버 [Git 업데이트]. 관리 창은 GET 의 `delete_enabled`·`verdict` 로 단추를 켜므로 [관리 도구 갱신]은 필수가 아니다.

## 바꾸는 것

- `backend/app/repo/account_cleanup.py`: 목록·잠금 안 판정이 함께 쓰는 `_judge` 에 '승인된 적 있는 계정'(→ `blocked`)을 더하고 조회 칸에 `approved_at`. 이미 있는 규칙(승인 상태 = 먼저 차단, 이력·보호 조건, 잠금 안에서 확인 창 값 그대로)은 그대로. 가입 대기(승인 전)+숨김 계정은 승인된 적이 없어 계속 대상이다.
- `backend/app/routers/account_cleanup.py`: `DELETE_ENABLED = True`.
- 시험: 승인됐다가 차단된 계정은 목록 '삭제 불가'·삭제 거절 · 꺼짐 시험은 상수를 False 로 고정해 그 길을 계속 지킨다.
- `docs/SERVER.md` 계정 삭제 줄: 꺼짐 → 대상 조건.
- 시험 고침 1: '승인 → 차단 → 삭제 → 재가입' 뒤 옛 토큰·늦은 요청이 돌아오지 않는지 보는 시험 4개(`test_account_cleanup_auth.py` `wipe`)는 이제 판정이 승인됐던 계정을 막아 실패했다 → 지우기 전 `approved_at` 을 비워 '옛 DB·수동 변경처럼 승인 기록이 비었는데 토큰이 있던 계정'을 흉내 내 그 이중 안전장치를 계속 지킨다.
- 독립 리뷰 Codex `01a1e6fe`(새 세션, gpt-6.1-sol·read-only): CHANGES 중간 1 — 관리 창이 승인 상태 계정에 "[차단]으로 로그인을 막은 뒤 지울 수 있습니다"라고 안내했다(이제 불가능한 동선) → `tools/server_console/account_rows.py` 판정 글자 '먼저 차단' → '차단만', 페이지·선택 안내를 '승인된 적 있는 계정은 차단·숨김까지만'으로, 시험 추가(승인·승인됐던 계정에 '지울 수' 약속 없음). ①목록·잠금 안 같은 규칙 ②승인 전 토큰 없음 ③`wipe` 흉내는 이중 안전장치로만 유효 ④삭제 단추는 `delete_enabled`+`deletable` 둘 다 — 지적 없음. 관리 창 글자가 바뀌었으므로 서버 반영 때 [관리 도구 갱신]도 한다.
- 확인: 계정 정리·인증 시험 통과(시험 기록 `62449d2f`), 관리 창 계정 정리 시험 14 통과(`7cc1e948`).

## 남는 위험

- 승인된 적 있는 계정(한 번 승인 뒤 생성물 없이 차단)은 지울 수 없다 — 차단·숨김까지만. 필요하면 쓰기 경로 재확인 작업(큰 일)을 따로.
- 바깥 사용량 원장(힉스필드 조직 사용량)에 같은 이메일이 나중에 나오는 경우는 이 조건으로도 막지 못한다(계정 행을 다시 만들지는 않음).
