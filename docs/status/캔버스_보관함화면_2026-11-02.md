# 캔버스 보관함 화면 개선·설명 칸 (2026-11-02, Jay 시안 확정)

owner: Codex(구현)·Claude(설계·총괄) · reviewer: 구현·합의와 분리된 Claude 세션 · status: 완료 · touched_paths: 아래 계약 · updated: 2026-11-02

Jay 가 시안으로 정한 것:

- 카드 이름 앞에 워크스페이스 마크. 글자를 밝게.
- 위쪽의 [+ 새 탭으로 열기]·휴지통 단추를 없애고, 그리드·리스트 전환을 오른쪽 위로.
- 카드 우클릭 메뉴 [열기]·[삭제]. 기본 회색, 호버하면 열기는 라임, 삭제는 빨강.
- 보관 창에 자유 글 설명 칸. 그 설명을 보관함 카드에서 볼 수 있다.
- 카드의 설명을 누르면 창이 뜨고 글 전체를 볼 수 있다.

더블클릭 열기는 요청에 없어 넣지 않는다. 앞선 계약 `scene-keep-20261102` 의 `keep-ui` 중 "칸은 이름·프로젝트뿐"과 "+ 새 탭으로 열기·휴지통 단추"는 이 계약이 대체한다.

## 설계

**저장.** `scene_keep` 에 `description TEXT NOT NULL DEFAULT ''` 칸을 더한다. `schema.sql` 과 `db_migrations.py` 의 `CREATE TABLE` 을 둘 다 고쳐 `description` 을 `data` **앞**에 둔다(`data` 가 마지막 칸이라는 시험을 지키고, 목록이 큰 `data` 뒤를 읽지 않게). 표가 이미 있는 DB 는 `PRAGMA table_info` 확인 뒤 `ALTER TABLE`(다른 칸과 같은 방식)이고 이때만 칸이 `data` 뒤에 붙는다. 그런 DB 는 dev 뿐이라 허용한다. DB 이름표(baseline)는 건드리지 않는다. 기본값이 있어 되돌린 옛 코드의 INSERT 도 그대로 돈다.

보관 기능은 아직 main 에 없다(2026-11-02 확인: `origin/main` 에 `repo/scene_keeps.py` 없음). 그래서 설명을 모르는 옛 보관 서버는 현장에 없고, `KeepIn` 의 `extra='forbid'` 는 그대로 둔다.

**서버.** `KeepIn.description`(기본 빈 글자, 최대 2,000자). `validate_metadata` 가 NFC 로만 바꾸고 앞뒤 공백·줄바꿈은 그대로 둔다. 설명을 `metadata` 에 넣어 해시·INSERT·UPDATE 가 함께 움직인다 — 설명만 바꿔 덮어써도 revision 이 오른다. `list_keeps` 가 설명을 돌려주고, `save_keep` 의 `exists` 응답도 설명을 돌려준다. 로컬 허브는 기존처럼 `body.model_dump` 로 그대로 넘긴다.

**보관 창(`SceneKeepDialog`).** 프로젝트 아래 `설명` 글칸(`textarea.settings-input`, `maxLength` 2000). 회색 안내 글은 넣지 않는다.

덮어쓰기에서 설명이 조용히 지워지거나 옛 글로 돌아가면 안 되므로 같은 이름 보관본의 설명을 따른다:

- 창을 열 때 `sceneKeepApi.list` 를 한 번 부른다. 실패해도 보관은 막지 않는다.
- `typed: string | null`. 사용자가 손대기 전(`null`)에는 지금 프로젝트·이름과 같은 행의 설명을 보여 준다. 이름은 서버처럼 NFC·trim 뒤 비교하되 빈 이름에서 예외를 던지는 `normalizeSceneKeepName` 은 쓰지 않는다. 손대면 그 값을 쓴다. 비우면 빈 설명으로 저장된다.
- **규칙 하나: `typed === null` 이면 `exists` 든 `conflict` 든 서버가 준 최신 설명을 payload·`overwrite.payload`·`retryPayload` 에 넣고, 창이 보여 줄 값도 같이 바꾼다.** 목록이 성공했어도 낡았을 수 있다. `conflict` 는 다시 읽은 `latest.description` 을 쓰고, `latest` 가 없으면(지워짐) payload 를 그대로 둔다. `typed !== null` 이면(빈 글자 포함) 어느 경로에서도 사용자가 쓴 값을 바꾸지 않는다.
- `retryPayload` 는 이름·프로젝트처럼 설명이 바뀌면 지운다.
- `capture` 는 설명을 모른다(`App.tsx` 는 범위 밖). 반환 타입을 `Omit<SceneKeepPayload, "description">` 으로 두고 Dialog 가 설명을 붙인다.

**보관함(`SceneKeepWindow`).**

- 도구 줄에는 보기 전환만 오른쪽에 둔다. `chosen`, [+ 새 탭으로 열기], 휴지통 단추를 뺀다.
- 카드는 설명 단추를 안에 담아야 해서 `<button>` 대신 `<div role="listitem" tabIndex={0}>` 로 바꾼다(단추 안 단추 금지). 묶음은 `role="list"`. 왼쪽 클릭은 지금처럼 선택 표시만 한다.
- 카드 안은 미리보기 · `.scene-keep-item-text`(`.scene-keep-item-title` = 마크 + 이름, 설명) · `.scene-keep-item-meta`(시각·노드 수).
- 우클릭(키보드 메뉴 키 포함)은 그 카드를 선택하고 메뉴를 연다. 구조는 `MediaPreview` 우클릭 메뉴와 같다 — `createPortal` 로 body 에 그리고(`.admin-window` 가 transform 이라), `.preview-menu-catcher`·`.preview-menu`, `useEscapeClose(…, !!menu, true, true)`·`useModalFocus(menuRef, !!menu)`, 위아래 화살표. 바깥 누름·Esc·항목 선택으로 닫는다. 포털은 카드 JSX 가 아니라 창의 조각 바로 아래에 둔다(React 이벤트가 카드로 올라가지 않게).
- [열기]는 지금 단추와 같은 `perform(() => onOpen(row.id))`, [삭제]는 지금 확인 창(`HostConfirm`)을 연다. `busy` 면 두 항목 모두 막는다.
- 설명은 카드 안 `<button type="button" class="scene-keep-item-desc"><span>글</span></button>`. 누르면 `stopPropagation` 하고 읽기 창을 연다. 카드 선택은 바뀌지 않는다. 설명이 없으면 그리지 않는다.
- 2줄을 넘을 때만 끝을 흐린다. `span` 의 `scrollHeight > clientHeight + 1` 을 `ResizeObserver` 콜백에서 재서 `.more` 를 붙인다(줄 수는 카드 폭에 달렸고, 정수 반올림에 1px 여유를 둔다). 시험 환경처럼 `ResizeObserver` 가 없으면 처음 한 번만 잰다(`CutInfoPopup` 과 같은 분기). 화면 글자 끝에 "..." 를 쓰지 않으므로 `line-clamp` 는 쓰지 않는다.
- 읽기 창은 같은 파일의 작은 컴포넌트. `.admin-window` 바깥에 `.admin-confirm-backdrop` + `.admin-confirm.scene-keep-desc-window`. 머리 = 마크·이름·✕, 본문 = 글 전체(`pre-wrap`, 길면 창 안 스크롤). `useModalFocus`·`useEscapeClose` 를 쓰고, 뒤 창의 `useModalFocus` 는 읽기 창이 뜬 동안 끈다. 글은 React 글자로만 그린다.
