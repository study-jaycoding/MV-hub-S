# MV Agent 모델 칩·깊이 칩·사용량·설정 (2026-11-12)

owner: Claude(설계·구현) · reviewer: 남은 요청 묶음 끝 독립 리뷰 · status: 검증 중(dev 커밋 · 8012 재시작·Jay 확인 전) · updated: 2026-11-12

## 1. 요청

- Jay 11-12(리졸브 세션으로 보냄): Claude 앱처럼 모델 칩에 올리면 회사별로 고르고, 속도 부분을 누르면 깊이를 고르고, 설정 창에서 모델·Claude/Codex 연결을, 속도 옆에 사용량을 → 시안 `mvagent-aside/model-settings.png` → **"모두 구현하자. 설계부터 확정하고 바로 구현"**.
- 11-11 '모델·깊이 한 단추' 결정을 이 요청이 바꾼다(호버 하위 메뉴·속도 따로 누르기 = Jay 11-12 의 새 말).

## 2. 설계

- **입력칸 아래** = 왼쪽 [모델 칩][깊이 칩][사용량 원] · 오른쪽 [보내기]. 칩은 평소 글자만, 올리면 바탕과 ⌄.
- **모델 칩 메뉴**: 모델 찾기 · 회사 줄(Claude = 구독 이름, ChatGPT = 잠금 까닭) — 줄에 올리거나 누르면(→ 키도) 옆에 그 회사 모델 하위 메뉴 · 구분선 · 설정. 찾기에 글을 쓰면 회사 줄 대신 맞는 모델이 바로 나온다. 다른 회사 모델 = 새 대화(지금과 같음).
- **깊이 칩 메뉴**: 생각 깊이 Low~Max(엔진이 아는 것) · 옵션 '빠른 모드'(스위치, Opus 에서만 — 추가 크레딧, 칸을 열 때마다 꺼짐: 지금 규칙 그대로).
- **사용량 원**: 지금 대화가 찬 정도(마지막 답의 입력+캐시+출력 토큰 ÷ 문맥 창). 누르면 작은 창 — 대화 찬 정도 · Claude 주간 남은 양(100 − utilization)과 초기화 시각 · '마지막 답 기준'. 값이 없으면 '답을 한 번 받으면 보여요'.
  - 허브: Claude 해석기가 `rate_limit_event.rate_limit_info.unifiedWindows.seven_day`(utilization 0~1·resetsAt 초) → `usage{weekly}` 사건, 마지막 assistant 줄 `message.usage` 합 + result `modelUsage[*].contextWindow` 최대 → result 앞에 `usage{context:{used,window}}` 사건(0단계 원본 실측 모양). Codex 는 사용량 사건 없음(토큰 수만 줘서 한도를 모름).
  - 화면: 대화 찬 정도는 그 대화의 마지막 usage 사건(복원 포함), 주간은 계정별로 이 브라우저에 남긴다(`STORAGE_KEYS.agentUsage` {account, weekly, at}).
- **설정 쪽**(모델 메뉴 '설정' → 칸 안을 덮는 한 쪽, ← 로 돌아감·Esc):
  - 연결: Claude(구독 이름·판·연결됨 / 안 됐으면 [연결] = 지금의 연결 흐름) · ChatGPT(Codex)(판·잠금 까닭 / [연결] 은 잠금이 풀린 뒤).
  - 기본값: 새 대화 모델(마지막에 쓴 모델 | 모델 하나) · 새 대화 생각 깊이(마지막 | 단계) — 새 대화를 시작할 때만 적용. 먼저 쓸 생성 모델(없음 | 앱 모델 카탈로그의 그림·영상 모델) — 차례마다 `gen_model`(코드, `^[A-Za-z0-9_.:-]{1,100}$`)로 싣고 허브는 프롬프트에 '모델을 말하지 않으면 이걸로 계획(read_context models 로 확인)' 한 줄. 이 브라우저에 남김(`STORAGE_KEYS.agentDefaults`).
  - 사용량: Claude 주간 · 이 대화 찬 정도 · ChatGPT 는 'Codex 는 한도를 알려 주지 않아요'.
- 새 파일 `AgentSettings.tsx`(설정 쪽·사용량 창) — CODE_MAP 에 적는다.
