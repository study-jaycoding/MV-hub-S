## 결과 (2026-10-29)

- 새 `lib/textNodeTokens.ts`: 토큰 판정(보기 알약·편집칸 공용 — 전엔 TextCard 안에 정규식이 따로 있었다) · `wrapTextTokens`(이어진 번호만, 알약 안 원래 글자 그대로, 캐럿이 걸친 토큰은 글자) · `editorText`(그림 자리 표시는 빼고 `<br>` 은 줄바꿈, 다 지운 뒤 크롬이 남기는 `<br>` 하나는 빈 글) · 캐럿 글자 위치 왕복 · `caretMention`(@ 앞이 단어 글자면 아님).
- `TextCard`: textarea → contentEditable 편집칸(`scene-textnode scene-textedit`, 보기 모드와 같은 줄 간격 1.7). 열 때 저장 글을 넣고 이어진 번호를 알약으로, 칠 때마다 감싸기·저장·캐럿 기억, 알약을 누르면 글자로 풀림, 칸을 떠나면 남은 토큰도 알약. Enter = 줄바꿈 글자, 붙여넣기 = 서식 없는 글, 한글 조합 중엔 감싸지 않음. @ 목록은 화면에 그려진 @ 글자 자리를 재서(카드 배율로 나눠) 그 바로 위에. 글이 밖에서 바뀌면(되돌리기 등) 칸을 다시 채운다 — 카드 글은 `editNodeText` 가 바로 바꾸고 저장만 늦추므로 친 글을 덮지 않는다.
- 생성창 도우미(`promptEditor.wrapRefTokens`)를 쓰지 않은 까닭: `<<<image1>>>` 을 `@image1` 로 바꾸고 없는 번호를 빨간 경고 알약으로 만든다 — 텍스트 노드 글은 Comfy 로도 가므로 친 그대로여야 한다.
- 시험: 새 `textNodeTokens.test.ts` 5개 · `textCardMention` 를 새 칸으로 8개(편집칸 알약·치는 중 글자·@ 목록·넣기·Esc·Enter·알약 풀기) · 기존 `sceneUndoScope`·`sceneInputPersist`·`sceneRefServerStatus` 는 글 넣는 방식만 새 칸으로(지키는 내용 그대로) · 관련 9파일 시험 기록 `d4886aac…` · 빌드 `77343e58…`(처음엔 타입 오류 2 — 안쪽 함수가 채우는 변수의 타입 좁히기, 상자 객체로 고침) · `lint:architecture` `e6996f1b…` · 프런트 전체 469파일 5497개 통과(타입 고침 전, 고친 뒤 관련 시험 다시 통과) · `check_code_map` 빠짐 0.

## 고침 — 편집을 끝내면 글이 두 번 보이던 것 (2026-10-29, Jay 화면)

- 원인: 보기 칸과 편집칸이 같은 자리의 같은 `div` 라 React 가 편집을 끝낼 때 요소를 새로 만들지 않고 다시 썼다. 편집칸 글·알약은 React 밖에서 넣은 것이라 지워지지 않고, 그 뒤에 보기 내용이 덧붙었다(저장된 글은 한 번 — 보기 화면만 겹침).
- 고침: 두 칸에 `key`("edit"/"view") — 서로 다른 요소로 새로 만든다.
- 고치기 전 실패 확인: 새 시험(편집 → Esc → 보기에 글 한 번·알약 하나)을 key 를 잠깐 뺀 코드로 돌려 `'@image1 과 시합@image1 과 시합'` 로 실패(화면 증상과 같음) → 되돌린 뒤 통과. 시험 기록 `d2b8dede…` · 빌드 `bec4b444…` · `lint:architecture` `932dadf1…`.
- 앞 결과의 시험이 이것을 못 잡은 까닭: 편집 중·보기 중을 따로 띄웠고 한 칸에서 오가며 보기 내용을 본 시험이 없었다.
