## 1A — 오래 안 쓴 창이 씬 백업을 옛 내용으로 덮지 않게

### 지금(확인)

- 씬의 정답은 브라우저의 IndexedDB(`sceneStore`, `scenes.ts:3·278`)이고, 허브 DB `scene_backup` 은 단방향 미러다. `scenes_backup.py` 머리 주석의
  'localStorage' 는 옛 말이다 [C1 사실 정정].
- 미러는 이 탭의 기억만 쓴다: `lastPushed`·`serverHash` 는 모듈 변수라 창을 새로 열면 비어 있다(`sceneBackup.ts:72-73`).
- 그래서 며칠 안 쓴 프로필 B 를 열면 첫 미러에서 B 의 씬 X(7장)와 서버 지문(A 가 올린 12장)이 달라 올리고(`sceneBackup.ts:255-263`),
  허브는 묻지 않고 덮는다(`scenes_backup.py:101-107`).

### 규칙

씬마다 **맞춘 판** = 이 프로필의 그 씬 내용이 서버와 같았던 마지막 지문. 탭이 범위(계정)에 들어갈 때 **한 번** 읽고, 그 뒤로는 이 탭이 직접 본
것(같음 확인·올리기 성공·복구·가져오기)으로만 바꾼다 — 다른 탭이 그사이 장부를 바꿔도 이 탭의 판은 바뀌지 않는다. 다른 탭의 최신 판을 빌려 와
이 탭의 옛 내용을 '허가된 덮어쓰기'로 보내는 길을 막는다 [C1].

씬 X 의 지금 지문 h, 서버 지문 s, 맞춘 판 b 로:

| 경우 | 동작 |
| --- | --- |
| 서버에 X 가 없다 | 올린다(넣기) — 서버 백업이 사라졌으면 다시 만든다 [C2] |
| s == h | 같다 — b := h |
| h == b, s ≠ b | **옛 창이고 바뀐 것 없음 → 올리지 않는다.** 이 탭의 `lastPushed` 에도 넣지 않는다(이 탭에서 X 를 지워도 남의 새것을 안 지움) |
| h ≠ b, s == b | 내가 고쳤고 서버는 그대로 → 올린다(`base_hash = b`) |
| h ≠ b, s ≠ b, 또는 b 없음 | 둘 다 바뀌었거나 모름 → `base_hash = b ?? ""` 로 올린다 → 허브가 **사본**으로 받는다 |

### 허브(`scenes_backup.py`·`routers/scenes.py`)

- `SceneUpsertIn.base_hash: Optional[str] = None`. **칸이 없으면(옛 앱) 지금처럼 덮는다.** 새 앱은 늘 칸을 보낸다 — 지문을 못 구했으면 `""`(모름) [C5].
- 한 트랜잭션(`BEGIN IMMEDIATE`) 안에서 upsert 마다 판정하고 **결과를 씬마다 돌려준다** [C3]: `results: [{id, status, target_id, hash}]`
  - 행 없음 → 넣음 `saved`. 행 지문 == 들어온 지문 → `same`. 행 지문 == base → 덮음 `saved`.
  - 그 밖 → 원래 행은 그대로, **사본 행** `copied`: `target_id = <id>_c<들어온 지문 앞 10자>` — 같은 내용을 다시 보내면 같은 사본으로 모인다(응답을 잃고 다시
    보내도 사본이 늘지 않는다) [C3]. data 는 JSON 의 `id`·`name`(`<이름> (옛 창 사본)`)을 바꾸고 **카드마다 `pendingGenerationAttempts` 를 뺀다** —
    새 id 에서는 생성 복구가 씬 id 불일치로 결과를 카드에서 지운다(`canvasGenerationRecovery.ts:156-168` **확인**). 결과 id(`genIds`)는 남긴다 [C4].
    `hash` = 사본의 실제 지문.
  - 사본이 크기 상한을 넘으면 `status: "too_big"`(행 없음).
- 삭제: `delete_bases: {id: hash}` 를 주면 행 지문이 그 판과 같을 때만 지운다. 다르면 남기고 `kept: [id]`. 판은 **이 탭이 실제로 본 판**(b)만 쓴다 [C1].
  칸이 없으면(옛 앱) 지금처럼 지운다.

### 화면(`sceneBackup.ts`)

- 장부: localStorage `mvhub.sceneBackupLedger:<계정 ns>` = `{ [sceneId]: { b, fork?: { id, b } } }` — 씬마다 **한 항목**(맞춘 판 + 갈래) [C3].
  `enterScope` 때 한 번 읽어 메모리에 둔다. 쓰기는 이 탭이 판을 바꾼 항목만, 쓰는 순간의 저장값 위에 그 항목만 얹어(다른 탭이 쓴 다른 씬 항목을 지우지
  않게) **응답 처리 뒤 범위(ns)를 다시 확인하고** 쓴다 [C3]. 쓰기 실패(용량)는 삼킨다 — 판이 없으면 '모름'(사본 쪽)으로 가지 덮어쓰기 쪽으로 새지 않는다.
- 지문을 못 구하면(insecure context·예외) 서버에 이미 있는 씬은 **올리지 않고 보류**, 새 씬만 넣는다. 보류가 생기면 한 번 알린다 [C5].
- 응답 처리: `saved`/`same` → b := hash, `lastPushed` 에 적음. `copied` → 그 씬에 갈래 `{id: target_id, b: hash}` 를 적고 알림 한 번
  ("캔버스 'X': 다른 창에서 더 새로 저장된 백업이 있어 덮지 않았습니다 — 이 창의 것은 백업에 '(옛 창 사본)'으로 따로 남깁니다"). `too_big` → 7A 표시 집합에 넣고
  `lastPushed` 에 **넣지 않는다**(다음에 다시 본다) [C3]. `kept` → 그 씬의 `lastPushed`·b 를 지운다(남의 새것이 남았다).
- 갈래가 있는 씬: 그 뒤 편집은 글자의 `id`·`name` 을 바꿔 갈래 id 로 올린다(`base_hash` = 갈래의 b). 이 탭에서 그 씬을 지우면 갈래 행을 지운다.
  로컬 X 의 지문이 서버 X 와 같아지면 갈래를 끝낸다.
- 복구(`ensureInit`)·가져오기(`runImport`): 더한 씬의 b = 받은 글자의 지문. 이 탭 장부의 **갈래 행은 가져오지 않는다**(개수에서도 뺀다) — 두 로컬 씬이 같은
  행을 미러하지 않게 [C3]. 새 프로필(장부 없음)의 첫 복구는 사본 행도 따로 된 씬으로 가져온다(지금 동작).
- 처음 업데이트 직후엔 장부가 비어 있다 → 서버와 다른 씬은 '모름' → 사본. 덮지는 않으니 잃지 않는다(대신 '가져오기' 대상이 하나 보일 수 있다).

### 시험

- 허브: base 일치 → 덮음 · 불일치 → 원래 행 그대로 + 사본(id·name 바뀜, `pendingGenerationAttempts` 없음, `genIds` 그대로) · 같은 내용 다시 → 같은 사본 하나 ·
  같은 지문 → `same` · base 칸 없음 → 덮음 · `delete_bases` 불일치 → 남김 + `kept` · 사본 상한 초과 → `too_big`.
- 화면: 옛 창(h == b, s ≠ b) → PUT 없음 · 서버에 행 없음 → 넣음 · 다른 탭이 장부를 바꿔도 이 탭은 처음 읽은 b 로 보냄 · `copied` → 다음 편집은 갈래 id 로 ·
  갈래 씬 삭제 → 갈래 행 삭제 · 가져오기가 갈래 행을 건너뜀 · 지문 못 구함 → 있는 씬 보류 · `too_big` → `lastPushed` 안 채움.

### 지금(상대 보고, 표시한 것은 확인)

  돌려준다(`repo.reserve_idempotent_gen_request`, 시험 `test_gen_request_idempotency.py`). 캔버스는 `canvas_link.attempt_id` 가 같은 일을 한다.
- 빈 곳: '답이 없을 때 같은 요청을 한 번 더'. 부분 수정만 재시도하고 오류 종류를 안 가린다. 스포트라이트·캔버스 일괄·재생성은 재시도가 없다.
- **Comfy [실행]은 요청표가 없다**: `comfyApi.run` 이 raw fetch(`comfyApi.ts:168-187` **확인**), 허브 `_start_run` 은 요청마다 새 job_id

### 화면 — 생성·재생성: 재시도는 `http.ts` 의 전송 층에서 [C6]

- `jsonFetch` 에 선택 인자 `{ retryNoResponse: true }`. 켜면 **`fetch()` 와 응답 본문 읽기(`res.json()`)만** 최대 2번 — `fetch` 가 TypeError 로 실패했거나(AbortError 제외)
  본문을 다 못 읽었을 때 1초 뒤 **같은 헤더·같은 본문**(요청표·변경 id 그대로)으로 다시 보낸다. HTTP 오류(4xx·5xx)는 재시도하지 않는다.
  그 뒤의 데이터 보정(`normalizeGenerationPromptCompatibility` 등)·화면 처리는 재시도 밖이다 — 보정 중 TypeError 를 '답 없음'으로 오인하지 않는다.
- 이 인자는 **요청표가 있는 생성 POST 에만** 켠다(`createGeneration`·`regenerateGeneration` — 키 또는 `canvas_link` 가 있을 때). 호출 자리는 바꾸지 않는다.
  부분 수정의 기존 재시도는 그대로 둔다(같은 키라 해가 없다).
- 두 번 다 답이 없으면 오류 글을 "답을 받지 못했습니다 — 들어갔을 수 있으니 목록을 확인한 뒤 다시 누르세요"로. 캔버스 일괄 요약도 이 경우를 '접수 여부 모름'으로 센다 [C6].

### Comfy [실행] — 화면 + 허브

- 허브: `run(... run_key: str = Form(""))`.
  - **접수 장부**를 따로 둔다 [C7]: 미해결 실행 기록(journal)은 성공·정리 때 지워지므로 중복 방지 장부가 될 수 없다. 작은 파일 장부(journal 과 같은 잠금·원자 쓰기 방식)
    `{owner, run_key, fingerprint, job_id, at}`, **24시간 보존**, 상한 1,000(넘으면 오래된 것부터).
  - `_start_run` 순서: 키 형식(UUID) 확인 → 업로드를 임시로 받으며 **바이트 지문**을 같이 계산 → `fingerprint = sha256(content · param_values · media_meta · 파일마다 (순서·이름·바이트 지문))` [C8]
    → **키 잠금** 안에서 조회·예약·등록을 한 번에: 있으면 지문이 같을 때 그 job_id 를 돌려주고(임시 파일 정리), 다르면 409. 없으면 job 을 만들고 장부에 적은 뒤 잠금을 푼다.
    잠금 순서는 **키 잠금 → 잡 잠금** 한 방향만. 잡 정리(sweep)는 키 장부를 건드리지 않는다(보존 기간으로만 지운다) [C7].
  - 장부에는 있는데 메모리 잡이 없으면(허브가 다시 켜짐) 409 "같은 실행이 이미 접수돼 다시 실행하지 않았습니다" — 완료된 것일 수도 있으니 '미해결 실행에서 확인'이라고는
    쓰지 않는다 [C7].
  - 키가 없으면(옛 앱) 지금과 같다.
- 화면 `comfyApi.run`: 실행마다 `run_key`(UUID). **허브가 요청표를 받는다고 알릴 때만** 첫 POST 를 같은 방식(전송 층 재시도)으로 한 번 더 보낸다 —
  허브가 기능 표식(`features` 에 `comfy_run_key`)을 주지 않으면 지금처럼 한 번만 보낸다(새 화면 + 옛 허브에서 자동 이중 실행 방지) [C9].
  기능 표식을 어디에 둘지(기존 상태 조회 응답에 칸 하나)는 구현에서 기존 것을 찾아 쓴다.

### 시험

- 화면: 전송 TypeError 한 번 → 같은 키·같은 변경 id 로 두 번째 1회 · 본문 읽기 실패 → 다시 보냄 · 4xx/5xx → 재시도 없음 · 보정 중 TypeError → 재시도 없음 ·

## 3A — 최종본의 프로젝트 귀속을 바꾸는 길에 양쪽 검수자

  공간 변경(`/api/generations/workspace/batch` → `set_generation_workspace_batch`, 본인 카드만 · 전용 관리자 예외 있음) ·
  공유 번들 재발행(`/api/share/publish-bundle` → `import_bundle_item`, **항목별 트랜잭션**, 작성자 == 발행자만) · 프로젝트 삭제(전역 PM). 세 쓰기 함수는 이미 `BEGIN IMMEDIATE`.
  확인한 범위에서 다른 귀속 병합 길은 없다(Codex).
- 우회: 미분류로 빼기 → 본인이 최종 → 다시 프로젝트로. 반대로 남이 정한 최종을 미분류로 빼낼 수도 있다.

### 규칙

**최종본**의 project_id 가 실제로 바뀔 때만(같은 프로젝트 안 폴더 이동은 제외): 전역 admin 이면 통과. 아니면 **출발이 프로젝트면 그 검수자, 도착이 프로젝트면 그 검수자**.
최종 아닌 것은 지금 그대로. 판정 대상은 요청 입력이 아니라 **병합 뒤 실제 귀속 변화**다 [C13].

### 공유 서버

- helper `_check_final_moves(conn, actor_uid, changes)` — 각 쓰기 함수의 **같은 트랜잭션 안에서** 대상 행의 `is_final`·현재 project_id 와 `project_member` 를 읽어 판정.
  걸리면 403 "최종본은 두 프로젝트의 검수자(또는 관리자)만 옮길 수 있습니다 — <이름>".
  - `assign_to_project`(팀 탭) — 하나라도 걸리면 아무것도 안 바꿈.
  - `set_generation_workspace_batch` — 프로젝트가 바뀌는 행만 판정.
  - `import_bundle_item` — **서버 수신 경로에서만** 실제 actor 를 넘겨 판정하고, 걸린 항목은 **통째로 `blocked`**(기존 `blocked_ids`) 처리, 다른 항목은 계속 받는다 [C12].
    같은 함수를 쓰는 로컬 반영 경로(`routers/share.py:984`, 신뢰된 서버 자료)에는 판정을 걸지 않는다 — 인자로 구분한다 [C13].
  - 프로젝트 삭제는 **예외**(PM 의 정리 — 최종은 미분류가 되고, 다시 넣으려면 위 규칙).
- **최종 지정 쪽도 같은 트랜잭션에서** [C10]: finalize·unfinalize·final_review 의 권한 판정(지금 귀속 기준)을 실제 쓰기(`repo/share.py:149` 부근)와 같은 트랜잭션 안으로 옮긴다.
  그래야 '권한 확인 → (그사이 비최종 상태로 이동) → 새 프로젝트에서 최종 확정'이 안 된다.

### 로컬 허브·화면

- 내 작업 탭 이동(`assign_project` 의 my 갈래): **공유된 항목은 로컬 최종 표식과 상관없이 서버 먼저** — 403 이면 로컬도 바꾸지 않는다 [C11]. 로컬 미러의 `is_final` 은
  늦거나 틀릴 수 있다. 공간 변경이 이미 쓰는 '서버 먼저' 순서를 그대로 빌린다. 공유 안 된 항목은 지금 순서.
- 화면: 403 을 '서버 미연결'과 다른 글로(`useGenerationProjectActions.ts:82`).
- **배포**: 공유 서버가 새 판이어야 막힌다. 옛 서버 + 새 앱은 지금처럼 통과. 서버 배포는 따로 여쭌다.

### 시험(백엔드)

- 팀원: 미분류 최종 → 본편 403(행 그대로) · 본편 최종 → 미분류 403 · 도착만 검수자 → 출발이 다른 프로젝트면 403, 미분류에서 오면 통과 · 양쪽 검수자 통과 · admin 통과 ·
  최종 아님 → 지금대로 · 같은 프로젝트 폴더 이동 통과 · 공간 변경으로 프로젝트가 바뀌는 최종 403 · 번들: 걸린 항목 blocked + 나머지 반영 · 로컬 반영 경로는 판정 없음 ·
  finalize 와 이동이 겹칠 때(이동 먼저 커밋) 새 프로젝트 기준으로 거절 · 프로젝트 삭제 통과.

## 4B — 로그아웃하면 같은 브라우저의 다른 탭도 정리

### 지금(상대 보고, 표시한 것은 확인)

- 공유 서버 브라우저(로그인 있음): 로그아웃 = `api.logout()` → `setAuthToken(null)` → `setAccount(null)`. **로그인 화면은 앱을 덮는 것이 아니라 하위 화면을 내린다**
  (`App.tsx:2326`) — DOM 에 있던 코멘트 글·부분 수정 그림은 사라진다 [C14 사실 정정]. 토큰은 탭마다 메모리(`http.ts:15` **확인**)라 다른 탭은 옛 토큰을 계속 쓴다.
- 메인 화면은 `ch.auth.token` 의 storage 이벤트를 듣지 않는다(App 의 리스너는 다른 키 — `App.tsx:236` **확인**).
- 401 이 오면 요청 당시 토큰과 견주지 않고 지금 토큰을 지운다(`http.ts:108-112` **확인**) — 늦게 온 401 이 새 로그인을 지울 수 있다 [C16].
- 로컬 허브 방식: 로그아웃하면 허브의 활성 계정이 풀리고, 그 뒤 쓰기는 기본 DB 로 간다(`publish.py:562`·`db_paths.py:20`). 다른 탭은 이를 스스로 알아채지 않는다
  (주기 조회로 정리되는 구조가 아니다) [C15 사실 정정].

### 바꾸는 것(화면만)

- **공유 서버 방식** — 다른 탭이 `ch.auth.token` 을 지웠고(`newValue === null` 또는 `key === null`) 이 탭이 토큰을 쥐고 있으면:
  - 지킬 것이 없으면(`unloadHeld()` 거짓) → 기존 '밖에서 로그아웃됨' 길(`setAuthToken(null)` + `authRequired`) → 로그인 화면. 로그인 화면에 "다른 탭에서 로그아웃했습니다".
  - **지킬 것이 있으면** → 화면을 내리지 않는다. 위에 띠: "다른 탭에서 로그아웃했습니다 — 저장 못 한 편집(<곳>)이 있습니다. 옮겨 적거나 마친 뒤 [로그아웃]을 누르세요."
    이 동안 이 탭의 토큰은 그대로 둔다(지금 동작과 같다 — 4B 는 서버 토큰을 끊지 않는다). 띠의 [로그아웃]은 이 탭의 기존 로그아웃(묻기 포함)을 부른다 [C14].
- **로컬 허브 방식** — 로그아웃한 탭이 `mvhub.hubLogoutAt` 에 시각을 쓴다. 다른 탭은 듣고 **곧바로 '쉼' 상태**: 씬 백업·카드 소속 미러의 자동 동기를 멈춘다(활성 계정이
  풀린 허브의 기본 DB 로 새지 않게) [C15]. 지킬 것이 없으면 새로 고침(`reloadNow`). 있으면 위와 같은 띠 + [새로 고침]. 사람이 누르는 쓰기는 막지 않는다 — 띠가 알린다.
  같은 계정 재로그인은 지금처럼 새로 고친다.
- **늦은 401** [C16]: 요청을 보낼 때의 토큰을 기억해, 401 이 왔을 때 **지금 토큰이 그 토큰과 같을 때만** 지운다(다른 탭에서 새로 로그인했으면 건드리지 않음).

### 시험

- 공유 서버 방식: 다른 탭 토큰 삭제 이벤트 → 지킬 것 없음 = 로그인 화면 · 있음(코멘트 글) = 화면 그대로 + 띠 + 토큰 유지 · 띠 [로그아웃] → 기존 로그아웃 ·
  스스로 지운 경우(이벤트 없음)는 지금대로 · 토큰 없던 탭은 아무 일 없음 · 늦은 401(그사이 새 토큰) → 새 토큰 유지.
- 로컬 허브 방식: 시각 키 이벤트 → 씬 백업 sync 안 돎 · 지킬 것 없음 = 새로 고침 · 있음 = 띠.

## 5B — 라이브러리 프롬프트 초안 저절로 담기

### 지금(상대 보고, 표시한 것은 확인)

- 글·인라인 칩은 편집기 DOM 에 있고 `serializeParts`/`restoreParts` 로 꺼내고 되살린다.
- 씬에 들어갈 때 라이브러리 글을 **메모리에만** 담아 두고 나올 때 되살린다(`SpotlightPrompt.tsx:445-494` **확인**). 이 effect 는 **처음 실행에서도** `prev === null` 이라
  캔버스 탭으로 켜지면 빈 편집기를 라이브러리 초안으로 적는다 [C17].
- 트레이는 라이브러리용 `localTrayRefs` 와 씬 카드용이 따로고, `setTrayRefs` 는 씬 모드에서 씬 쪽을 가리킨다(`useSpotlightTray.ts:52-56` **확인**) [C17].
- 칩은 문자열 참조라 새로 고친 뒤에도 되살릴 수 있다(blob URL 없음).

### 바꾸는 것

- 키 `mvhub.libraryPromptDraft:<계정 ns>` — `ch.` 접두가 아니라 계정 전환 때 지워지지 않고, 계정마다 따로라 섞이지 않는다.
- 담기: 라이브러리 모드에서 글(tick)·라이브러리 트레이가 바뀌면 **그 순간의 키와 `{parts, trayRefs(uid 뺌)}` 를 고정해** 0.5초 뒤 쓴다. 씬 진입·창 닫기(pagehide)·언마운트
  때는 기다리던 것을 **바로 확정**한다(예약을 버리지 않는다 — 마지막 글을 잃지 않게). 예약 콜백은 그때의 DOM 을 다시 읽지 않는다(씬 글이 섞이지 않게) [C18].
- 보내기 성공 뒤 편집기를 비우는 길은 초안 글을 **즉시** 지운다(트레이는 지금처럼 남긴다) [C18].
- 되살리기: 마운트 때 한 번, 처음 실행과 실제 라이브러리 → 씬 전환을 구분한다 [C17].
  - 라이브러리 모드로 켜짐 → 편집기에 `restoreParts` + 라이브러리 트레이 직접 설정.
  - 캔버스 탭으로 켜짐 → `libraryDraftRef` 를 저장된 글로 채우고(빈 편집기로 덮지 않음), 라이브러리 트레이는 `setLocalTrayRefs` 로 직접 채운다.
  - 새 uid 는 되살릴 때 한 번만 붙인다. 되살렸으면 한 번 알린다 "지난번 쓰던 글을 되살렸습니다".
  - `useSpotlightTray` 에 라이브러리 트레이를 직접 놓는 함수 하나를 더한다.
- 담지 않는 것: 모델·설정·배치 수·공간(Codex 동의).

### 시험

- 글·칩·트레이 → 다시 마운트 → 셋 다 · 보낸 뒤 → 다시 마운트 → 글 없음, 트레이는 남음 · 계정 ns 다르면 안 읽음 · 손상 JSON 무시 · 캔버스 탭으로 켬 → 씬에서 나오면 되살아남
  (빈 글로 덮이지 않음) · 씬 안 글은 안 담김 · 0.5초 안에 씬 진입 → 마지막 라이브러리 글이 담김.

## 7A — DB 백업에서 빠진 씬 탭에 계속 보이는 표시

### 지금(확인 + 상대 보고)

- 5MB 를 넘는 씬은 미러에서 빼고 새로 생길 때만 이름으로 알린다(2.5초 알림). `oversized` 는 밖에서 못 읽는다.
- 이 집합은 업로드 성공 여부가 아니라 **전송 전 크기 검사 결과**이고, sync 가 `retry`·`blocked`·메타 실패로 일찍 끝나면 갱신되지 않는다(`sceneBackup.ts:225-236`) [C19].
- 씬 탭 줄은 `components/scene/SceneBar.tsx`. 탭마다 붙는 표시는 워크스페이스 표식뿐.

### 바꾸는 것

- `sceneBackup.ts`: 크기 집합 계산을 **네트워크와 떼어** 확정본이 바뀔 때마다(`subscribeScenesPersisted`)·범위 전환·씬 삭제 때 다시 센다(확정본 글자 길이만 보면 되고,
  큰 씬만 바이트를 센다). sync 는 같은 집합을 쓴다. `getSceneBackupOversized()`(씬 id) + `subscribeSceneBackupOversized(fn)`(바뀔 때마다) — 처음 구독 때 지금 집합을
  바로 읽게 한다. 기존 '새로 생길 때' 알림은 그대로. 1A 의 `too_big`(사본이 상한 초과)도 이 집합에 넣는다 [C19].
- `useSceneCoordination` → App → `SceneBar` 에 `backupSkippedIds`. 그 탭 이름 뒤 작은 호박색 `백업 안 됨`(좁으면 `⚠`), 누르는 동작 없음. title:
  "5MB 를 넘어 이 PC 의 DB 백업에 올라가지 않습니다 — 카드를 줄이면 다음 백업 때 다시 올라갑니다. 설정의 [전체 내보내기]로 따로 받아 두세요."
  표시가 사라지는 것은 '크기 제한 해소'이지 '백업 성공'이 아니다 — 글도 그렇게 쓴다 [C19].

### 시험

- 큰 씬 → 그 탭만 표시 · 작아지면 사라짐(네트워크 실패 중에도) · 오프라인에서 커짐 → 표시 · 지운 씬 → 빠짐 · 계정 전환 → 비움 · 같은 이름 두 씬 중 큰 것만 ·
