## 지금(코드에서 확인한 사실)

- 편집 키는 `EditTab.onKey`(1240~1318줄) 한 함수다. 입구 순서: `keysActive` → 위에 뜬 창·키 주인 → 입력 요소(모든 `INPUT`) → 물리 `KeyA`+Ctrl/⌘(Alt 없음, Shift 허용)면 '전체 선택' 예외 →
  `defaultPrevented` 면 그 예외만 통과 → 발생 요소가 body·편집 영역·상단바의 `button, a` 인지 → Ctrl/⌘ 와 Alt 가 같이 눌리면 아무것도 안 함 → 수식키 분기 → 동작.
- 키 판정: 글자·`Space`·`Slash` 는 물리 키 `event.code`, 방향키·`Home`·`End`·`Delete`·`Backspace`·`Escape`·`=`/`+`/`-` 는 `event.key`(숫자패드 `+`·`-` 와 NumLock 꺼진 숫자패드도 같은 동작).
  Ctrl/⌘+Shift+= 는 `key:"+"` 라 확대, Shift+- (`_`)는 축소가 아니다. [C1]
- Shift 의 뜻이 키마다 다르고, '실행'과 '키를 먹음'이 다르며, 조건이 맞지 않으면 다른 키로 넘어가지 않고 끝난다(예: 고른 것 없는 Alt+↑ 는 일반 ↑ 로 가지 않는다) — 아래 표가 그 정본이다. [C1·C2]
- Space: Tab 으로 간 `button, a, [role=button]` 초점이면 양보. Esc: 입구를 다 지난 뒤 속도 막대 → 고르기 풀기(`markKeyHandled`), 둘 다 없으면 안 먹는다.
  클린 피드 창의 키(Esc 제외)는 `key/code/수식키/repeat` 를 복사해 부모 body 에 다시 보낸다(`EditCleanFeed.tsx:243`, `isComposing` 은 안 실린다). [C1]
- 휠(`EditTimeline.tsx:216-234`, `passive:false`): 우선순위 Alt → Shift → Ctrl · Ctrl 은 `ctrlKey` 만 · 방향 = `deltaY || deltaX` · 좌우 넘기기는 크기도 쓴다 · 수식키 없는 휠은 브라우저 스크롤.
  배율: 확대/축소 단추·키 ×1.25 / ×0.8, Alt+휠 ×1.15 / ÷1.15 · 트랙 높이 Shift+휠 ×1.12 / ÷1.12. [C1]
- 앱 단축키 저장소 `lib/shortcuts.ts` 는 글자(`key`) 기준 + 한 칸 + 고정 목록이고 입력기 상태는 `keyGate` 가 보정한다 — 편집 키와 규칙이 달라 그대로 못 쓴다. [C1]

## 기본 동작 표(정본 — 지금 `onKey`·wheel 을 옮긴 것) [C2]

## 설계

1. **동작 목록 한 곳**(새 `lib/editShortcuts.ts`, 순수): 위 표를 그대로 `{id, 묶음, 이름, 기본 칸, shift, once, input: "key"|"wheel"|"both"}` 로. 처리는 `EditTab` 의 `{owns(ctx), run(ctx, via)}` 표(`via` = 키/휠 — 배율용).
   공용 `shortcuts.ts` 는 넓히지 않는다(라이브러리·보드 회귀를 막는다). 저장 도우미·창 모양·초점 관리는 재사용. [C1]
2. **칸**: 동작마다 **길이 2 고정 배열 `[칸|null, 칸|null]`**(빈 칸 = `null` — 칸 번호가 흔들리지 않게). 칸 = 키 하나 또는 휠 하나(휠은 `input` 이 wheel·both 인 동작만). [C2]
   키 표기 = 수식키(`mod`·`alt`·`shift`) + 키 이름. 키 이름 = 글자·숫자·기호·`Space` 는 `code`(`KeyI`·`Digit1`·`Slash`·`Equal`·`Minus`…), 이름 있는 키는 `key`(`ArrowLeft`·`Home`·`End`·`Delete`·`Backspace`).
   **같은 입력으로 보는 것**(지금과 같게): `NumpadAdd`→`Equal`, `NumpadSubtract`→`Minus` 이고 **이 두 별칭은 Shift 를 뗀다**(숫자패드 `+`·`-` 는 Shift 로 글자가 안 바뀐다 —
   지금 코드는 `key` 만 봐서 Ctrl+Shift+숫자패드 `-` 도 축소다. 일반 자판의 Ctrl+Shift+- 는 `_` 라 축소가 아니다 — 그대로). NumLock 꺼진 숫자패드는 `key` 로 이미 같다.
   숫자패드를 따로 지정하지는 않는다. 받기·실행·겹침 검사가 **같은 정규화 함수 하나**를 쓴다. [C3]
3. **키 처리 순서**(지금 동작을 그대로 옮기는 정본) [C1·C2]:
   1. 입구 거르기는 지금 순서·조건 그대로(모든 `INPUT` 제외 — `isTypingTarget` 으로 바꾸지 않는다).
   2. **Ctrl/⌘+A 예외**: 물리 `KeyA` · Ctrl 또는 ⌘ · **Alt 없음** 인 실제 이벤트를 아래 6의 찾기 함수로 조회해 **동작이 찾아지면**(정확 또는 Shift same) `defaultPrevented` 여도 통과.
      통과가 실행을 강제하지는 않는다 — 뒤의 발생 영역·양보·소유 검사는 그대로(공용 지킴이가 Ctrl/⌘+A 기본 동작을 먼저 막는 지금 구조에 맞춘 것).
   3. 발생 요소 검사(지금 그대로).
   4. Ctrl/⌘ 와 Alt 가 같이 눌리면 넘김(AltGr 배열).
   4-1. **Esc 는 여기서** 지금 그대로 처리하고 끝: Ctrl/⌘·Alt 가 붙은 Esc 는 넘김, `isKeyHandled` 면 넘김, 속도 막대가 있으면 `markKeyHandled` 후 막대만 닫기, 아니고 고른 것이 있으면
        `markKeyHandled` 후 고르기 풀기, 둘 다 없으면 넘김(Shift+Esc 도 지금처럼 닿는다). Esc 는 표에 없고 아래 5 의 예약 검사에도 닿지 않는다. [C3]
   5. **예약 입력이면 넘김** — 실제 입력(별칭·수식키 정규화 뒤)이 아래 '지정할 수 없는 것'에 들면 찾지도 않는다(예: Ctrl+Shift+R 이 Shift same 로 Ctrl+R 동작에 닿지 않는다).
   6. **찾기는 한 번**: 정확히 맞는 칸 → 없고 Shift 가 눌렸으면 Shift 를 뺀 칸 중 `shift: same` 동작 → 없으면 넘김.
   7. **Space 양보**: 실제 입력이 Space 이고 Tab 으로 간 `button, a, [role=button]` 초점이면 넘김(어느 동작에 지정됐든 — **처리 함수보다 앞**).
   8. 찾은 동작의 `owns(ctx)` 가 거짓이면 **넘김으로 끝**(다른 칸을 다시 찾지 않는다). 참이면 키를 먹고, `once` 이고 반복 keydown 이면 실행만 거른다, 아니면 `run`.
   9. 클린 피드에서 다시 보낸 키도 같은 길을 탄다(`isTrusted`·부모 `activeElement` 로 거르지 않는다).
   10. 확대·축소·트랙 높이의 계산은 **지금 함수를 그대로** 부른다(반올림 `Math.round` · `LANE_MIN/MAX` · `ZOOM_MIN/MAX` 를 새로 쓰지 않는다 — 배율만 `via` 로 고른다). [C3]
4. **휠**: 칸의 수식키는 **하나만**(alt·shift·ctrl). 찾을 때는 지금 우선순위 **Alt → Shift → Ctrl** 중 눌린 가장 높은 하나로(Alt+Ctrl 휠 = Alt 칸). Ctrl 은 `ctrlKey` 만.
   방향 = `deltaY || deltaX` 의 부호(0 무시), `scrollX` 는 크기를 쓴다. 방향 없는 `X+wheel` 은 `X+wheelup`·`X+wheeldown` 둘 다와 겹친다고 센다.
   **타임라인 안의 Ctrl+휠은 지정이 없어도 막는다**(브라우저 확대가 되살아나지 않게 — 지금과 같다). 수식키 없는 휠은 지정 불가. [C1]
5. **겹침**(편집 탭 안에서만, 실제 입력 기준): 같은 표기 · 방향 없는 휠과 방향 휠 · 한 동작 안의 같은 칸 둘. Shift same 동작의 '빈 Shift'(예: M 동작이 있을 때 Shift+M)는 다른 동작에 지정할 수 있다 —
   그때는 정확한 쪽이 먼저 받는다(겹침이 아니라 우선순위, 창에 'Shift+M 은 ○○가 먼저 받음' 한 줄).
   **지정할 수 없는 것**: Esc · Tab · Shift+Tab · **Enter**(단추 누르기·입력기 조합과 겹친다 — 클린 피드는 `isComposing` 을 안 싣는다 [C2]) · 수식키만 · Ctrl/⌘+Alt 동시 ·
   브라우저·OS 가 가져가는 것(Ctrl+W·T·N·L·Shift+T·Shift+N · Ctrl+Tab·Ctrl+Shift+Tab · Ctrl+1~9 · Alt+←·→ · Ctrl+Shift+R · 모든 F1~F12) · 수식키 없는 휠 · `scrollX` 에 키.
   **Ctrl+R(Shift 없음)은 허용**(속도 막대 기본값). 창에는 '앱이 고정'과 '브라우저가 가져감'을 나눠 적는다.
6. **저장** = 새 `localStorage` 키(`ch.editShortcuts`, `storageKeys.ts`) — 기본값과 다른 동작만 `{id: [칸|null, 칸|null]}`. **이 브라우저 프로필의 설정**(계정별·PC 사이 동기화 아님). [C1]
   - **읽을 때 고치기**: 알려진 id · 길이 2 배열 · 칸 형식 · 지정 불가 · **동작의 입력 종류에 맞는 칸인가**(`input: key` 동작의 휠 칸 · `scrollX` 의 키 칸은 틀림) · 동작 안 중복을 검사해
     틀린 동작은 그 동작 전체를 기본값으로. 그다음 겹침은 **칸 단위**로: 그 칸이 그 동작의 기본 칸과 같으면 '기본', 아니면 '사용자'. **기본이 먼저**, 사용자끼리는 **표 순서가 앞인 동작의 칸이 남고**
     뒤쪽 동작의 그 동작 지정 전체를 기본값으로 → 겹치지 않을 때까지 반복(매번 지정이 하나 이상 줄어 끝난다). 지운 것은 사유(형식·지정 불가·입력 종류·겹침)별로 창을 열 때 알린다. [C2·C3]
   - **사용자가 칸 하나를 바꿀 때·행의 ↺**: 저장값을 **다시 읽고**, 그 동작의 **그 칸 하나만**(↺ 는 그 동작의 두 칸) 바꾼 결과를 검사해 겹치면 **쓰지 않고 거절** — 지금 설정 그대로, '○○에 사용 중' 안내.
     다른 탭이 바꾼 다른 칸·다른 동작을 덮지 않는다(localStorage 라 동시에 쓰는 순간까지 막지는 못한다). '전체 기본값 복원' = 저장값을 비운다. 쓰기 실패는 안내. [C2]
   - 같은 창 알림(이벤트) + 다른 탭 `storage` 로 따른다. 키·휠 처리는 **지금 지도를 ref 로 읽는다**(그릴 때 잡은 값을 쓰지 않는다).
7. **창**(새 `components/timeline/EditShortcutsWindow.tsx`): 모양은 `ShortcutsWindow` 그대로, 두 단, 찾기 칸. 행마다 칸 둘 — 칸을 누르면 그 칸을 받는다(빈 칸은 '＋'), 칸마다 **×(비우기)**
   (Backspace 는 받는 중에도 보통 키로 받는다 — `remove` 에 지정할 수 있어야 한다), 행의 '↺', '전체 기본값 복원'. 칸이 모두 비면 '없음'. [C1]
   **창이 열린 동안 내내 키 주인**(편집 키가 쉰다). Esc = 받는 중이면 받기 취소, 아니면 창 닫기(누름 하나에 하나).
