## 2. 흐름

1. 알약을 누르면 칸이 열리고(알약 라임) 본문은 왼쪽으로 좁아진다(겹치지 않음).
2. 입력하면 프런트가 **지금 화면 정보**(탭·프로젝트/폴더·선택 카드 id·공간)와 **중복 방지 키**를 붙여 차례(turn)를 연다.
3. 허브가 차례를 시작할 때 **신원을 고정**한다: 허브 id·DB 경로·로그인 계정·패널 연결 id·대화 id. 저장·사건 전달·계획 실행 직전에 다시 대조하고 다르면 그 차례를 버린다.
4. 허브가 CLI 를 **차례마다 한 번** 띄운다(이어 가면 허브가 소유를 확인한 정확한 세션 id 로 resume — `--last`·`--continue` 안 씀). 프롬프트는 UTF-8 바이트로 stdin 에 넣고 닫는다(명령줄 길이 한계 — WinError 206).
5. CLI 의 JSON 줄을 **엔진별 해석기**가 사건으로 바꾼다: 글(조각 또는 통째) · 도구 사용 한 줄 · 계획 카드 · 끝 · 오류(로그인 만료·CLI 계정 바뀜 포함). 사건은 **차례별 순번**을 달아 보관한다.
6. 프런트는 `after=순번` 긴 기다림으로 사건을 받는다. 깨우기만 기존 `agent_signals` 방식을 쓰고, 사건 이력은 새 보관소에 둔다(`agent_signals` 는 깨운 쪽이 소비·재시작 때 사라짐 — `agent_signals.py` 28·52·119).
7. 계획 카드의 **[실행] 은 사람만** → 앱 전용 입구가 그 계획을 다시 읽어 확인한 뒤 공통 제출 로직을 부른다 → 결과는 지금처럼 라이브러리에 들어온다.

## 3. 백엔드 (로컬 허브만)

### 3-1. 경로와 지킴

새 서비스 `services/agent_chat.py`(가칭: CLI 실행·트리 관리·차례 상태) · 순수 해석기 `services/agent_chat_parse.py`(가칭, 엔진별) · 새 라우터 `routers/agent_chat.py`(가칭).

| 경로 | 하는 일 |
|---|---|
| `POST /api/agent-chat/session` | 칸을 열 때 **패널 비밀값** 발급 — 비밀값 대조의 유일한 예외. 발급 조건은 아래 '권한' |
| `GET /api/agent-chat/status` | 쓸 수 있는 엔진(설치·판·인증 방식)과 모델 목록 |
| `POST /api/agent-chat/turns` | `{idempotency_key, conversation_id?, engine, model, effort, text, context}` → `turn_id`. 같은 키면 같은 차례를 돌려준다 · 계정당 진행 1차례를 원자적으로 선점(두 번째는 409) |
| `GET /api/agent-chat/turns/{id}/events?after=n` | 새 사건을 최대 25초 기다림 |
| `POST /api/agent-chat/turns/{id}/cancel` | 상태 `취소 중` → 트리 회수 확인 뒤 `취소됨`. 회수 전에는 다음 차례를 열지 않는다 |
| `GET /api/agent-chat/conversations`, `GET …/{id}` | '새 대화 ⌄' 목록·내용 |
| `POST /api/agent-chat/plans/{plan_id}/execute` | [실행] — 3-3 |

- **지킴**: 모든 경로에 `require_loopback_browser_request`(루프백 + Host·Origin 루프백 — DNS 리바인딩·CSRF) + 로그인 신원 + **패널 비밀값 대조**(`/session` 만 예외). 헤더 형식만 보는 `mcp.app_headers` 를 그대로 쓰지 않는다(`mcp.py` 44·85). 기능 꺼짐이면 404. 공유 서버 모드에서는 라우터를 붙이지 않는다.
- **권한 = 로그인 신원(계정 + 허브 + DB), 탭이 아니다.** 신원은 **패널 전용 판정**으로 구한다: 활성 계정 고정 범위 안에서 정규화한 계정 키(로그인 이메일 소문자) + 허브 id + 정규화한 DB 절대경로. 기존 `_identity`(`mcp.py` 78)를 그대로 쓰지 않는다 — AUTH off 에서 `me` 로 귀결될 수 있고(`deps.py` 109), DB 경로가 고정 설정이면 계정을 바꿔도 같다(`db_paths.py` 22). **로그인한 계정이 없으면 거절**한다.
  - `/session` 발급 조건 = 루프백 브라우저 검사 통과 + 위 신원이 있음. 탭이 보낸 식별값은 받지 않는다 — 허브가 비밀값을 새로 만들어 그 신원에 묶는다.
  - 패널의 모든 요청은 기대 계정 헤더(`X-MVHub-Expect-Account`)를 **반드시** 싣는다 — 없으면 400(기존 검사는 헤더가 없으면 건너뛴다, `deps.py` 96).
  - 비밀값은 **다른 웹페이지의 위조 요청을 막는 표**다. 같은 신원이면 다른 탭·새로 고친 탭도 `/session` 으로 새 표를 받아 그 신원의 대화·차례·계획을 보고, 취소하고, 실행할 수 있다(같은 사람의 같은 계정 — MV Hub 의 다른 화면과 같은 규칙). 다른 신원(다른 계정·다른 DB)의 것은 볼 수도, 취소·실행할 수도 없다.
  - 허브가 재시작되면 메모리의 비밀값은 모두 사라진다 → 프런트가 401 을 받으면 `/session` 으로 새 표를 받는다. **새 표의 신원을 그 요청이 시작될 때 고정한 신원과 비교**해서, 같을 때만 다시 보낸다. 다르면(그사이 계정이 바뀜) 자동으로 다시 보내지 않고 이전 요청을 버린 뒤 "계정이 바뀌었어요"를 보인다. 신원 판정에 세션 토큰 교체는 들어가지 않는다(다시 로그인해도 같은 계정이면 같은 신원).
  - 시험: 고정 DB 경로에서 계정 A→B 전환 · A 요청 대기 중 B 전환 + 허브 재시작 · 다른 신원의 새 표로 취소·실행 시도 → 모두 거절.

### 3-2. 패널 전용 MCP 연결

- 기존 `local_setup.configure_client` 는 `codex`·`claude`·`claude_desktop`·`other` 만 받고 **사용자 전역 설정 파일을 고친다**(`local_setup.py` 262 이하) → 쓰지 않는다.
- 허브가 **패널 전용 연결 등록·프로필**을 따로 발급한다: 등록은 기존 v2 연결 표를 쓰되 **실행 허용 끔을 영구 고정**, 프로필은 `%LOCALAPPDATA%\MVHub\agent_chat\` 아래, CLI 에는 그 자리에서 만든 MCP 설정을 넘긴다. 전역 `~/.claude.json`·`~/.codex/config.toml` 은 건드리지 않는다.
- 노출 도구는 **허용 목록**: 연결 확인·조회(`read_context`)·참고 그림 찾기·계획 저장·계획 보기·견적. `execute_generation_plan`·`request_execution`·`add_to_canvas` 는 빼고, 허브의 실행 거절(403 `execution_not_allowed`, `mcp_v2.py` 1157)은 그대로 둔다 — 두 겹.
- 기존 MCP 지침은 "요청하면 실행"을 권하므로(`server.py` 960·984) 패널 차례에는 **패널 전용 안내**(계획까지만, 실행은 사용자가 칸의 단추로)를 덧붙인다.

### 3-3. [실행] 앱 입구

- 기존 `_execute` 는 연결의 실행 허용을 보므로 그대로 부르면 403 이다. 연결 허용을 켜면 에이전트에도 실행권이 생기니 켜지 않는다.
- 대신 **앱 전용 입구**: 패널 비밀값 + 허브가 저장한 `허브·계정·연결 id·대화 id·차례 id·계획 id` 대응을 확인 → 서버의 계획 내용을 다시 읽고 → 권한 검사 아래의 **공통 제출 로직**을 부른다. 공통 제출 로직은 기존 실행 경로의 장치를 그대로 포함한다: 계획 원자적 선점(`claim_plan`, `repo/mcp_v2.py` 177 · `routers/mcp_v2.py` 1166) · 항목별 중복 방지 키 · 취소와 불명확 접수 복구. 그래서 두 번 동시에 눌러도, 응답을 잃고 다시 보내도 한 번만 나간다. 계획 id 를 CLI 글에서 뽑아 믿지 않는다 — 계획 저장 도구 결과를 허브가 MCP 응답에서 직접 받은 것만 대응표에 넣는다. 기존 연결별 계획 조회 조건(`repo/mcp_v2.py` 123·177)은 보존한다.

### 3-4. CLI 실행 (구현 0단계에서 실측으로 고정)

- 작업 폴더 = `%LOCALAPPDATA%\MVHub\agent_chat\work`(빈 폴더, **저장소 밖** — dev 의 `DATA_DIR` 는 저장소 안이라 상위 지침을 찾을 수 있다, `config.py` 28).
- 자식 환경에서 **API 키·제공자 전환 변수를 뺀다**(`ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`·`ANTHROPIC_BASE_URL`·`CLAUDE_CODE_USE_*`·`OPENAI_API_KEY`·`OPENAI_BASE_URL` 등) — 구독이 아닌 요금 경로로 새지 않게. 인증 방식은 비밀값을 출력하지 않는 상태 확인으로만 본다.
- 실행 파일은 검증한 경로와 인자 배열로 부른다(`.cmd` 래퍼·빈 문자열 인자 `--tools ""` 함정 실측). stdout·stderr 를 동시에 비우고 출력 한도를 둔다.
- Claude(후보): `claude -p --output-format stream-json --verbose --include-partial-messages --model <m> --effort <e> --tools "" --strict-mcp-config --mcp-config <패널 설정> --allowedTools <허용 목록> --permission-mode dontAsk --setting-sources <실측으로 정함> [--resume <sid>]`. `--bare` 는 구독 로그인을 안 읽어 못 쓴다.
- Codex(후보): `codex exec --json --skip-git-repo-check --ignore-user-config --ignore-rules -m <m> -c model_reasoning_effort=<e> -c features.shell_tool=false -c mcp_servers.<패널>.…` + 도구 허용/금지 목록(`enabled_tools`·`disabled_tools`) — 처음과 `exec resume <id>` 의 옵션 배치를 따로 고정하고 이어 갈 때도 제한을 다시 건다.
- 시간 제한 10분. **차례마다 Windows Job Object** 에 CLI 와 그 자식(MCP 어댑터 포함)을 넣어 취소·시간 초과·허브 종료 때 함께 회수한다.
  순서는 기존 런처와 같다(`run_agent_session.py` 190·1164): **멈춘 채 생성 → Job 배정 → 재개**. 배정에 실패하면 실행하지 않고 오류로 끝낸다. 차례 Job 은 탈출(breakaway)을 허용하지 않고 닫히면 안의 프로세스를 모두 끈다.

### 3-5. 차례 상태와 재시작

- 칸 닫기 ≠ 취소: 차례는 계속 돌고, 칸을 다시 열거나 새로 고치면 `after` 로 다시 붙는다. 앱 창 닫힘·브라우저 종료 알림으로 정리를 기대하지 않는다.
- 허브 종료 = Job 으로 자식 회수. 다음 기동 때 남은 `진행 중` 차례는 **`중단됨`으로 바꾸고 자동 재실행하지 않는다**.
- 계정이 바뀌면 진행 중 차례는 버리고, 프런트도 이전 계정의 요청·사건을 폐기한다(기존 `X-MVHub-Expect-Account` 방식).

### 3-6. 기록

- `%LOCALAPPDATA%\MVHub\agent_chat\<허브 id>-<DB 경로 해시>-<계정 키>.db`(SQLite, 콘텐츠 DB 와 별개·백업 대상 아님). **DB 경로 해시 = 정규화한 DB 절대경로의 해시**(내용 해시가 아님 — 데이터가 바뀌어도 그대로). DB 를 옮기거나 다른 DB 로 바꾸면 새 기록으로 갈라진다(복원도 경로가 같으면 이어진다). 표: 대화(id·엔진·모델·CLI 세션 id·제목·시각) · 차례(id·중복 방지 키·상태·고정 신원) · 사건(차례·순번·종류·내용) · 계획 대응(차례·계획 id·연결 id).
- 계정 키는 로그인 신원으로 정한다(AUTH 켠 격리 시험에서 `account_key()` 가 늘 None 이던 함정).
- **엔진을 바꾸면 새 대화**. CLI 원본 기록이 만료(Claude 기본 30일)되면 대화는 그대로 보이되 이어 가기만 막고 안내한다. 끊긴 계획의 [실행] 은 3-3 확인을 그대로 거친다(대응표가 있으면 실행 가능).

| 새로 고침·재시작 뒤 권한 이어받기 | 받음 — 권한 = 로그인 신원, 비밀값은 위조 방지 표, 다른 신원은 불가(3-1 권한) |
| 동시 두 번 실행 | 받음 — `claim_plan` 선점·항목 중복 방지 키·불명확 접수 복구 포함(3-3) |
| Job 배정 전 자식 누출 | 받음 — 멈춘 채 생성 → 배정 → 재개, 배정 실패 = 실행 거부, 탈출 금지(3-4) |
| 0단계 통과 증거 부족 | 받음 — 처음·이어 가기 각각, 증거 항목 명시(6절) |
| DB 지문 미정의 | 받음 — 정규화한 DB 경로 해시(3-6) |

| 지적 | 처리 |
|---|---|

| 401 재발급이 계정 변경을 재시작으로 오인 | 받음 — 새 표 신원과 고정 신원 비교, 다르면 폐기, 기대 계정 헤더 필수(3-1 권한) |
