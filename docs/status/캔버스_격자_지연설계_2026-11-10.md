### 2단계 B — 1단계로 부족할 때만, 좁힌 그림판 시험

- 카드 **몸통만** 바꾼다. 그룹·SVG 연결선(적중 영역)·바깥 틀·테두리·포트·손잡이·범위 선택·임시선은 DOM 그대로
  (그룹 잡기·이름·접기, 연결선 클릭·올림·가위, 회색 숨김 우회선·접힌 그룹 브릿지·무선 화살표, 범위 선택 미리보기 보존).
- P1 = 레퍼런스·리스트·글·생성 완료 결과만. 나머지 종류는 기존 DOM 그대로(생략·대체 없음).
- 겹침 순서: (a) 카드마다 몸통 자리 작은 canvas / (b) 보드 한 장 canvas + 예외 카드 가림 — 실측으로 고른다.
  초안의 '보드 canvas 를 DOM 아래 두기'는 버림(예외 카드가 위에 보이는데 클릭은 앞 카드의 투명 틀이 받는 경우가 생김 — Codex).
- 예외(지금처럼 전체 DOM 몸통): 마우스 올림·편집·끄는 중·Comfy 대기·높이 미측정·영상 재생. **선택은 테두리 표시만**(Ctrl+A 때 최적화 유지).
  몸통 안 조작(썸네일별 더블·휠클릭, 몸통 컴포넌트 안 포트·손잡이)은 올림 때 DOM 으로 돌아와 동작 — 올리지 않은 상태의 경로를 목록으로 확인.
  keepIds(컬링 제외) ≠ 몸통 예외 목록(미측정 폭·높이, 재측정, 씬별 캐시는 따로).
- 상태 계약: has-node·missingHere(missing/held/incomplete/'이 PC 에만')·리스트가 모은 참조 상태·glow·생성 상태·코멘트 수·Comfy 실행을
  그리기 목록 순수 함수에서 DOM 과 같은 규칙으로(`scene.css` 1244, `SceneBoard.tsx` 3426).
- 다시 그리기 예약 = 카메라·내용·상태·그림 준비·선택 미리보기, 한 프레임에 한 번.
- 화면보다 넓게(여유 영역) 그린 canvas 를 DOM 과 같은 카메라로 합성기 이동, 여유를 벗어날 때만 다시 그림. 줌·F 250ms 전환도 같은 변환(`useSceneViewport.ts` 214·320).
- 그림 캐시는 한 곳(keptThumbs 는 HTMLImageElement 300장 쥐기 — 두 벌 쥐지 않게). OffscreenCanvas 는 worker 가 아니면 메인 스레드 일.
  메모리(그림판 약 14MB·DPR2 57MB, 카드 사진·디코드 캐시)는 예산 후보 — 줌 단계·DPR·영상 포함 최대값과 씬 왕복 뒤 회수를 잰다.
- 켜고 끄기: 줌 ≤30% 켬·≥36% 끔, 쉬었을 때 바꿈. 'DOM 에서 처음 축소'와 '그림판 모드에서 줌'을 따로 잰다. 설정 스위치(기본 꺼짐).
- 2단계 성공 기준: 1단계 기준 + 최초 모드 진입 프레임 · Ctrl+A · 겹친 카드 클릭이 보이는 카드에 감 · 팬·줌 중 생성 완료 반영 · 모드 왕복 뒤 메모리 회수.

  2. 그림·목록 대기 — 첫 실행에 다음 쪽 요청이 그림 요청 뒤 2.5초(원인이 동시 연결 6개라는 건 가설 — 대기 기록·프로토콜 확인 뒤) ·
     격자는 keptThumbs 를 안 씀 · 포스터 없는 영상 `preload=metadata`.
  3. 실제 다시 그리기·새로고침 — ThumbnailGrid 는 콜백을 안정 함수로 바꾸고(345) GenerationCard 는 memo, selectedCount 는 다중 선택 카드에만(430):
     부모 실행 비용과 카드 몸통 다시 그리기를 나눠 잰다. 목록 맞추기는 길이가 다르면 새 배열이지만 항목 객체가 새것인지가 관건(`stateReconciliation.ts` 65).
     생성 중 3초는 처리 중 카드 확인이 먼저, 목록은 바뀌거나 15초 안전망일 때(`useGenerationAutoRefresh.ts` 86) — 실제 reload 경로 비용을 잰다.
  4. 따로 — 어셋 범위 선택이 마우스 움직일 때마다 레이아웃 읽기(`AssetsView.tsx` 490) · 늘 붙은 투명 버튼 덮개·clip-path·container-type 은 비용이 확인될 때만.
