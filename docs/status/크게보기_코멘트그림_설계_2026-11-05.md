## 3. 설계

### 3.1 화면

1. **C 단추**: `cur.genId` 가 있을 때만(1단계는 생성물만). 상태 = `POST /api/generations/comment-counts` 로 그 장 하나. 누르거나 `c` → 코멘트 모드.
2. **코멘트 모드 창**(새 `CommentDrawModal`): 왼쪽 무대·도구·아래 판(붙는 그림 · 입력 · 🔒 비공개로 쓰기 · [코멘트 달기]), 오른쪽 340px 지난 코멘트. 크게 보기 위에 뜨고, **떠 있는 동안 크게 보기의 키·재생은 쉰다**(방향키·Space 가 아래로 새지 않게). 닫을 때 쓰던 것이 있으면 "버릴까요?".
3. **영상**: 책갈피 = 그린 프레임. 같은 프레임 판정은 24fps 가상 눈금의 같은 칸(편집 창과 같은 눈금)이면 같은 책갈피. 붙는 그림 칸을 누르면 그 프레임으로. `[ ]` 는 지금처럼 **굵기**(시안의 '앞뒤 책갈피' 키는 뺀다). 표시는 시각(타임코드) — 원본 FPS 를 모르므로 원본 프레임 번호로 쓰지 않는다.
4. **그림 보기**: 코멘트의 그림을 누르면 크게 보기에서 원본 위에 겹침(영상은 그 시각으로 옮기고 멈춤), 띠 "💬 작성자 · 시각 · [끄기]". 코멘트 창 겹 순서는 그대로.

### 3.2 그림 저장 — 형태와 위치(Jay 질문 반영)

**용량은 '어디에 두느냐'가 아니라 '무엇으로 두느냐'가 정한다.** 같은 그림이면 본 DB 표·코멘트 전용 DB·폴더 어디에 두어도 차지하는 크기는 같다. 줄이는 길은 그림을 가볍게 만드는 것이다.

형태 — 두 안 중 **나. 획 목록으로 확정**(Jay 11-05):

| | 가. 투명 PNG(v0.1) | **나. 획 목록(추천)** |
|---|---|---|
| 담는 것 | 원본 크기 투명 그림 | 그린 선의 점·도형·글자 좌표(수정 창이 이미 들고 있는 `DrawItem` 그대로) |
| 크기(예시 1장 실측, Pillow 압축 — 앱은 브라우저 저장이라 다를 수 있음) | 1080p 15KB · 4K 45KB | 3.0KB(사각형·화살표·글자·펜 점 120개, 해상도 무관) |
| 볼 때 | 그림을 그대로 겹침 | 같은 그리기 코드로 다시 그려 겹침(어느 크기로도 선명) |
| 단점 | 해상도만큼 커짐 | 글자는 그 PC 글꼴로 그려 PC 마다 조금 다를 수 있음 · 받은 좌표 목록을 검사해야 함 |
| 덤 | — | 나중에 '그림 고치기'를 따로 저장 없이 할 수 있음 |

- 용량 감(실측 기준): 이미지 코멘트 그림 1장 ≈ 3KB, 영상 그림 1장 ≈ 3KB + thumb 11KB(320×180 JPEG 품질 80, 품질 70 이면 9KB). 비교: 지금 dev 실사용 로컬 DB(`backend/data_test/db/content_hub.db`) 66MB. 서버에는 공유 코멘트만 간다. 생성물 목록·검색 쿼리는 그림 표를 읽지 않는다(비용은 코멘트 스레드·그림을 열 때만). 늘어나는 비용은 주로 DB·백업 크기다. 줄이는 장치: 그림·점 수 상한(§3.6), 펜 점 간략화(보이는 모양 유지, 줄어드는 양 미측정), thumb 품질.
- 미리보기 그림(thumb, JPEG 긴 변 320px)은 **영상만** 둔다 — 목록에서 그 프레임을 다시 뜨지 않으려고. 이미지는 생성물의 기존 썸네일 위에 획을 그려 보여 준다(따로 저장 안 함). thumb 은 축소 원본이 들어가므로 '원본 재저장 안 함'의 유일한 예외다.

위치 — **본 DB 의 전용 표**(코멘트 전용 DB 는 만들지 않는다, J2):
- 전용 DB 파일을 따로 두면 크기는 같고, 백업·DB 옮기기·서버 업데이트·복원이 지금은 DB 하나를 기준으로 움직이므로 그 길을 모두 고쳐야 한다(실패 시 코멘트와 그림이 따로 놀 위험).
- 본 DB 의 표는 코멘트와 한 트랜잭션·외래키로 묶여 같이 지워지고 같이 백업된다.

```text
generation_comment_drawing(
  id TEXT PRIMARY KEY,          -- 클라 uuid(식별자)
  comment_id TEXT NOT NULL REFERENCES generation_comment(id) ON DELETE CASCADE,
  idx INTEGER NOT NULL,         -- 붙는 순서, UNIQUE(comment_id, idx)
  kind TEXT NOT NULL,           -- 'image' | 'video'
  width INTEGER NOT NULL, height INTEGER NOT NULL,  -- 그린 좌표계 = 원본 크기
  time_sec REAL,                -- 영상만, 실제 표시 시각
  strokes_json TEXT NOT NULL,   -- 획 목록(Jay 확정) {"v":1,"items":[...]} — 수정 창 DrawItem 과 같은 꼴, 좌표 = 원본 픽셀
  thumb_jpg BLOB,               -- 영상만
  content_hash TEXT NOT NULL,   -- strokes+thumb 해시(재전송 대조)
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
)
```
- 외래키 연쇄 삭제는 SQLite 의 `PRAGMA foreign_keys` 가 켜져 있어야 동작한다 — 연결 설정을 구현 때 확인하고, 꺼져 있으면 저장소 함수가 명시적으로 지운다(미확인). 생성물 외래키는 걸지 않는다(로컬 행이 없는 팀 항목의 비공개 코멘트가 있다 — Codex).

### 3.3 저장·전달 경로

| 경우 | 글 | 그림 |
|---|---|---|
| 미발행 로컬 | 로컬 DB | 로컬 표, 글과 한 트랜잭션 |
| 공유·팀 항목(허브 위임 중) | 서버 위임 | **그림 전용 새 경로**로 글과 함께 서버에 |
| 비공개 | 늘 로컬 | 늘 로컬 — 위임·발행·서버 조회 없음 |
| 발행 | 묶음에 글 | 묶음 코멘트에 그림(획 + 영상 thumb base64) |
| 서버 직결 화면 | 서버 DB | 서버 표(비공개 입력 숨김, 서버 거절 유지) |

### 3.4 API — 옛 길은 그대로, 그림은 새 판 경로

- 작성: **`POST /api/generations/{id}/comments-v2`**(로컬 예외 `/api/generations` 아래라 핸들러가 나눈다). 본문 = 지금 칸 + `id`(클라 uuid) + `drawings[]`. 옛 서버에는 이 경로가 없어 **404 → 허브가 409 "팀 서버 업데이트 뒤 그림을 붙일 수 있습니다"** 로 돌려주고 화면은 쓰던 글·그림을 지킨다. 옛 경로에 그림을 실어 보내지 않으므로 '글만 남는' 일이 생기지 않는다(Codex P1-2, 사전 기능 확인만으로는 못 막음).
- 같은 요청 다시 보내기: 코멘트 id 를 클라가 정하므로 같은 id·같은 내용 = 같은 결과, 같은 id·다른 내용 = 409. 응답 = `{id, drawings:[{id, content_hash}]}` — 허브·화면이 보낸 것과 대조해 다르면 실패로 보고 초안을 지킨다.
- 목록: `GET /api/generations/{id}/comments` 에 각 코멘트 `drawings` **메타만**(§10 C5). 획은 그림마다 `GET /api/generation-comments/{comment_id}/drawings/{drawing_id}`, 영상 thumb 은 `…/{drawing_id}/thumb`(둘 다 로컬 예외 아래). 비공개·미발행 = 로컬만, 공유 = 서버 권위(로컬 사본 있어도 서버 답을 따름, 서버 403·404 면 로컬로 대체하지 않음), 응답 `Cache-Control: private, no-store`. 서버에서 받는 것은 상한 있는 바이트 중계(기존 `_forward_stream` 규칙 재사용, 성공·오류 본문 모두 상한).
- 권한: 그림은 **이미 권한 검사를 통과한 코멘트 id** 에서만 꺼낸다. 계정 고정은 기존 `_personal_meta_account_scope`.

### 3.5 발행·재전송·삭제

- 그림 달린 발행은 **새 판 발행 경로**로 보내고(§10 C3), 그 앞에 서버가 그림을 아는지 확인(발행과 같은 고정 문맥 — 미들웨어 중계 아님). **모르면 그림 달린 코멘트가 있는 항목의 발행을 막고** "팀 서버 업데이트 필요"를 알린다(J4, Codex 권고 — 조용한 유실 방지). 서버를 먼저 올리는 배포 순서라 막히는 기간은 옮기는 사이뿐.
- 받는 쪽 합치기: 그림은 그 코멘트가 **같은 생성물·같은 작성자·공개**일 때만 붙인다. 같은 그림 id 는 부모·해시가 같아야 하고 다르면 거절. 영수증에 그림 확인을 넣고, 옛 영수증(그림 확인 없음)이면 보완 절차(다시 보내기)를 둔다.
- **지운 코멘트가 다시 살아나는 문제**(기존 글에도 있음 — 발행 재전송이 서버에서 지운 코멘트를 `INSERT OR IGNORE` 로 다시 넣음): 서버에 삭제 기록 표(`generation_comment_tombstone`)를 두고 합치기가 그 id 를 건너뛴다(J5 — 기존 동작도 바뀐다).
- 코멘트 삭제: 실제로 지워지는 코멘트 행의 그림이 연쇄 삭제. 다른 PC·서버 직결에서 부모가 지워져도 내 비공개 답글·그림은 남고 '원글 삭제됨'으로 보인다(기존 트리 규칙 `lib/commentTree.ts:29`).
- 휴지통: 생성물 휴지통 이동 때 코멘트와 함께 그림 행도 모으고, 복원 때 함께 되살린다.

### 3.6 한도·검증(받는 모든 곳 같은 검증기 — 세부 규격은 §10 C4·C5 가 정본)

- 코멘트 하나 그림 ≤ 12장, 그림 하나 획 항목 ≤ 500·점 ≤ 20,000·글자 ≤ 200자(나안), width·height 는 원본 크기와 같고 총 픽셀 ≤ 12MP(수정 창 상한과 같게), time_sec 유한·0 이상, idx 0..11 겹침 없음.
- thumb: 엄격한 base64 해독, 실제 JPEG 해독·크기 확인, ≤ 64KiB.
- 본문 상한은 **파싱 전**(`services/upload_limits.py` 의 경로 규칙)에 새 작성 경로·발행 경로를 넣는다. 발행은 bundle 과 commands 에 겹쳐 실리는 것까지 합쳐 계산. 넘으면 보내기 전에 알리고 일부만 버리지 않는다.
- 검증 실패 = 글까지 통째로 취소(원자적).

### 3.7 프런트 구조(D4 — 단계적으로)

## 10. 계약(Codex 2차 '합의에 필요한 최소 목록' 반영)

### C1 작성 재시도

- 새 장부 표 `generation_comment_request(id PK, fingerprint, gen_key, created_at)` — comments-v2 로 만든 코멘트마다 한 줄, **바뀌지 않는다**(글 수정은 코멘트 행만 바꾼다). 로컬 비공개 작성도 로컬 장부에 같이 남고 서버로 안 간다.
- `fingerprint` = 서버가 계산하는 SHA-256: 인증 신원(본문의 author 는 안 씀) · 정규화한 생성물 키(서버 = job_id 앵커) · 공개/비공개 · parent_id · 작성 때 글 · 그림들의 **순서 있는 `{drawing_id, content_hash}` 목록**(C4 해시에는 id 를 넣지 않는다 — Codex 3차).
- **처리 장소가 바뀐 재시도**(Codex 3차): 허브는 comments-v2 를 받으면 **로컬 장부를 먼저** 본다 — 그 id 가 로컬 장부에 있으면 지금 공유 여부와 상관없이 로컬의 처음 결과를 돌려준다(그 사이 발행됐어도 서버로 다시 보내지 않는다). 로컬 장부에 없을 때만 지금의 공유 분기를 탄다.
- **코멘트는 있는데 장부가 없는 경우**(발행 합치기로 들어온 코멘트에 같은 id 재시도가 닿음): 새로 만들지도 덮지도 않는다. 기존 행의 작성자·생성물·공개 여부·부모·**정규화한 글**과 그림 `{id, hash}` 가 요청과 모두 같으면 `{"result":"present"}` 로 그 결과를 돌려주고, 하나라도 다르면 409(보낸 글이 저장 안 됐는데 성공으로 처리하지 않게 — Codex 4차). 처음 장부가 있는 경우의 '수정 전 요청 재시도 허용'은 그대로.
- comments-v2 처리 순서(한 트랜잭션):
  1. 삭제 기록(C2)에 그 id 가 있으면 → 만들지 않고 종료 응답 `{"result":"deleted","id":…}`(HTTP 410).
  2. 장부에 그 id 가 있고 지문이 같으면 → 처음 결과를 그대로 돌려줌(그 뒤 글을 고쳤어도 정상 재시도로 본다).
  3. 장부에 있고 지문이 다르면 → 409 충돌.
  4. 없으면 코멘트 + 그림 + 장부를 함께 쓴다. 검증 실패면 통째로 취소.
- 부모(parent_id)가 삭제 기록에 있으면 → 409 "원글이 삭제됨"(새 답글을 받지 않는다).
- 화면: 응답이 불확실한 동안 같은 id·같은 본문을 유지한다. 사용자가 글·그림을 고치면 새 id(새 작성 의도).
- 허브가 서버의 404 를 '업데이트 필요'로 바꾸는 것은 **경로 없음** 404 일 때만(FastAPI 기본 `{"detail":"Not Found"}` — 프런트 `lib/http.ts` 의 `isRouteMissing` 과 같은 기준, Codex 확인). 생성물 없음·권한 숨김 404 는 그대로 전한다.

### C2 삭제 기록

- 표 `generation_comment_tombstone(id PK, gen_key, deleted_at)` — 로컬·서버 모두.
- **기록하는 때**: 사용자가 코멘트를 지울 때(로컬·서버, 수정·삭제 API) 그 트랜잭션에서 **실제로 지워지는 모든 id**(지금 규칙 = 부모와 직접 답글)를 기록.
- **기록하지 않는 때**: 생성물 휴지통 이동·중복 정리(`generation_delete`) — 되살릴 수 있어야 하므로.
- **복원**: 휴지통 복원은 코멘트·그림을 다시 넣되 **삭제 기록이 있는 id 는 건너뛴다**(휴지통에 넣기 전에 따로 지운 코멘트가 돌아오지 않게). 복원이 삭제 기록을 지우지 않는다.
- **보존**: 영구(행이 작다 — id·키·시각). 생성물을 영구 삭제해도 남긴다(낡은 묶음이 되살리지 못하게).
- **합치기(발행 받기)**: 삭제 기록 id 는 넣지 않고, 부모가 삭제 기록에 있는 답글도 넣지 않는다. 영수증에 `skipped_deleted: [id…]` 로 따로 적어 보내는 쪽이 다시 보내지 않게 한다.
- **비공개 답글**: 서버의 공개 부모 삭제는 내 로컬 비공개 답글을 지우지 않는다. 화면은 삭제가 **확인된** 경우(서버 410/삭제 기록)만 "원글이 삭제됨", 조회 실패·권한 문제는 "원글을 불러오지 못함"으로 구분.
- 삭제 기록은 일반 목록 응답에 싣지 않는다.

### C3 발행

- 그림 유무는 **명령(항목) 단위**로 판정한다: 그 항목의 코멘트에 그림이 있으면 **새 판 발행 경로** `POST /api/share/publish-bundle-v2`(옛 서버엔 없음 → 404 경로 없음 → 막고 "팀 서버 업데이트 필요"), 없으면 지금 경로. 그림 있는 항목과 없는 항목이 한 번에 발행되면 **최초 전송부터 두 묶음으로 나눠** 보낸다(Codex 합의 요청 지적 — 명령이 항목별로 만들어진다 `share_commands.py:115`).
- 동결된 재전송(`share_commands` 의 다시 보내기)도 같은 판정(동결 명령의 `parameters.item` 코멘트에 그림이 있는가)으로 경로를 고르므로 최초 전송과 **늘 같은 경로**다. 원장·명령에 칸을 더하지 않는다. 혼합 발행(그림 있는 항목 + 없는 항목)의 최초·재전송 경로 일치를 시험한다.
- 그림 확인이 없는 옛 영수증(그림 기능 전 발행)은 보완을 **새 명령 id** 로 한다 — 대상은 서버에 지금 살아 있는 코멘트의 그림만, 글·삭제를 덮지 않는다(서버는 삭제 기록 id 를 거절).
- 사전 확인(J4)은 발행 함수와 **같은 고정 문맥**에서 한다 — 기존 발행이 계정·DB 세대·URL·토큰을 잡는 곳(`routers/publish.py:1032`)과 `_proxy.pinned_connection`(`_proxy.py:64`)을 재사용(Codex 확인). 결과 분류: 지원 없음·경로 없음 = 업데이트 필요 / 401 = 로그인 / 403 = 권한 / 시간 초과·5xx = 확인 불가(막고 나중에). 어느 실패도 '지원함'으로 보지 않는다. 사전 확인은 안내용이고 실제로 막는 장치는 새 판 경로다.

### C4 획 v1 규격

- 문서: `{"v":1,"items":[…]}`. items 1~500개. 종류별 허용 칸만(그 밖의 칸 = 거절):
  - `pen`: `erase` 참/거짓 · `color`(수정 창 팔레트 8색 중) · `size` · `points` **1~5,000개**(클릭 한 번 = 1점 획 — 지금 도구 출력, `PartialEditModal.tsx:159`), 각 `{x,y}` 유한수.
  - `shape`: `shape` ∈ {line, arrow, rect, ellipse} · color · size · `from`·`to`.
  - `text`: `text` 1~200자(제어 문자 금지) · color · `size`(좌표계 px 글자 높이 — 지금 도구는 굵기 × 1.5, 최대 180 작업 px `PartialEditModal.tsx:147`) · `at`.
  - `size`(세 종류 모두) = **1 ~ max(180, 좌표계 긴 변의 1/4)**. 좌표계가 원본 크기라 작업 캔버스를 줄인 만큼 저장값이 커질 수 있고(작업 px × 원본/작업 비율 — 큰 원본은 긴 변/4 가 받는다), 작은 원본은 줄이지 않으므로 도구 최대값 180 이 받는다(256px 그림의 굵기 120·글자 180 도 통과 — Codex 4차). 지금 도구가 만드는 값(굵기 4~120, 글자 6~180 작업 px)을 늘 받아들이고, 공유 도구의 동작은 바꾸지 않는다.
  - 모든 좌표는 0~width, 0~height 안(그릴 때 잘라 넣는다). 그림 하나의 점 합계 ≤ 20,000.
- 정규화: 숫자 소수 1자리, 칸 순서 고정, 공백 없는 JSON — 서버가 정규화본을 저장.
- 해시(서버 계산, SHA-256): 정규화 획 · v · kind · width · height · time_sec(ms 반올림, 이미지는 null) · idx · thumb 의 SHA-256(없으면 null). 클라가 보낸 기대 해시와 다르면 거절.
- 미지원 판(`v` ≠ 1): 쓰기 거절(400). 읽기는 원문 그대로 두고 화면에 "이 그림은 새 판에서 볼 수 있습니다".
- 좌표계와 그리는 캔버스 분리: width·height = 주석 좌표계 = 원본 크기(가로·세로 각 ≤ 16,384). **그리는 캔버스만** 12MP 안으로 줄이고 좌표·굵기·글자 크기를 같은 비율로 바꾼다(수정 창의 12MP 작업 상한과 같은 방식).
- 층: **원본 아래층 + 투명 주석 위층**. 지우개(`destination-out`)는 주석 층에만 작용(수정 창과 같다).
- v1 그리기 규칙(선 끝 둥글게·화살촉 모양·사각형 모서리·타원)은 떼어 낸 그리기 모듈에 고정하고 시험으로 지킨다 — 뒤에 수정 창 그림이 바뀌어도 v1 렌더는 그대로.
- 글꼴: 수정 창 글꼴 목록(`TEXT_FONT`). 글꼴을 다 불러온 뒤(또는 불러오면 다시) 그린다. 줄바꿈·글자 축소를 하지 않는다. PC 마다 글자 모양이 조금 다른 것은 허용(Jay 확인 — 비교 그림).

### C5 전달·보호 한도

- 바이트 상한(파싱 전, `services/upload_limits.py` 경로 규칙): 획 JSON 그림당 ≤ 256KiB · thumb ≤ 64KiB · 그림 ≤ 12장 · comments-v2 요청 ≤ 5MiB · publish-bundle-v2 요청 ≤ 32MiB(bundle·commands 겹쳐 실림 포함). 넘으면 보내기 전에 알리고 일부만 버리지 않는다.
- 목록 응답은 그림 **메타만**(id·idx·kind·width·height·time_sec·has_thumb·content_hash·v). 획·thumb 는 그림마다 따로 받고 둘 다 `Cache-Control: private, no-store`. 비공개·미발행 = 로컬만, 공유 = 서버 권위(로컬 대체 없음).
- 프런트: 획·thumb 는 **영구 캐시에 두지 않는다**(열린 창 메모리만). 요청 시작 때 계정·서버·생성물·코멘트를 고정하고, 다른 문맥의 늦은 응답은 버린다. 401·403·404·410 이 오면 그 그림을 화면에서 걷는다(옛 표시 유지 금지). 기존 코멘트 목록 캐시(`api.ts:307-309`, 계정별)에는 메타만 들어간다.
- 한 스레드에서 한 번에 받는 그림은 화면에 보이는 것만(지연 로딩).

### C6 영상

- 책갈피의 **기준 시각** = 그 프레임에 처음 그릴 때의 실제 `video.currentTime`(탐색이 끝난 값). 한 번 정하면 바뀌지 않는다. 책갈피를 다시 열면 그 시각으로 옮긴 뒤 획을 보인다.
- 같은 24fps 칸으로 옮겨 오면 새 책갈피를 만들지 않고 그 책갈피의 기준 시각으로 맞춘다(기준 시각·thumb 를 덮어쓰지 않는다).
- thumb 은 기준 시각에서 뜬다. 캡처 시작 때 생성물·미디어 주소·기준 시각·그림 판(수정 횟수)을 고정하고, 늦게 끝난 결과는 버린다. **thumb=null 은 정상 계약** — 뜨지 못하면 없이 저장하고 화면은 어두운 바탕 위 획으로 보인다(해시에도 null 반영).
- 이미지 그림은 thumb 이 없다 — 목록 미리보기 = 생성물 썸네일 + 획(별도 층). 생성물 썸네일이 없거나 만료돼도 획과 글은 보인다.
