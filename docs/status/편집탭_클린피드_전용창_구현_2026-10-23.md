## 구현에서 정한 것(합의 대상)

1. **미디어 중계**(설계 D·3차 6·P2-1): 앱이 장면에 넣는 같은 출처 상대 주소 중 **`/media/…` 와 `/api/media-thumb?src=/media/…&w=N`(src 가 `/media/…` 인 것만)** 에 세션 번호를 준다
   (`/api/media-picture` 는 피드가 쓰지 않아 뺀다 · 절대 주소 — CDN `https://…` — 는 번호 없이 그대로, 피드가 직접 연다).
   `GET/HEAD /api/clean-feed/media/<세션>/<번호>?key=` → ① 그 파일이 이 PC 에 있으면(`_proxy._local_media_target`) `/media` 는 `FileResponse`(Range 그대로) · 썸네일은
   `library.media_thumb(src, w)` 를 불러 그 응답 · ② 없고 open 때 위임 모드였으면 **세션의 계정 고정값(pin) 으로 `pinned_account_scope(pin)` 에 들어가 그 안에서
   `_proxy.base_url()`·`_proxy.token()` 을 요청마다 다시 읽어**(토큰 값을 세션에 두지 않는다 — 같은 계정의 재로그인으로 토큰만 바뀌어도 맞다) **원래 경로**(`/media/…` 또는
   `/api/media-thumb?src=…&w=`)를 스트리밍(`_proxy._open`, Range·If-Range·조건부 헤더 전달, `Accept-Encoding: identity`, 연결 30초·읽기 60초 시한, 1 MiB 청크) — 상태 코드
   (200·206·304·416·오류)와 Content-Length·Content-Range·Accept-Ranges·ETag·Last-Modified·Content-Type 을 그대로, HEAD 는 본문 없이 · ③ 아니면 404. 모든 응답
   `Cache-Control: no-store`. 세션마다 동시 중계 4개(넘으면 503). **세션이 끝나면 그 세션의 진행 중 스트림을 끊고 소켓을 닫는다**(새 요청 거절과 따로). 자기 자신에게 다시 요청하지 않는다.
2. **계정 고정과 세션 종료**: 식별값 = **계정 세대값** `active_account.account_epoch()`(이 프로세스의 정수, 포인터 파일 형식은 그대로) + 로컬 허브(인증 끔)
   `capture_account_pin()` · 인증 켬(dev) `(request.state.account 의 email, sha256(Bearer 토큰))`. **세대값 +1 자리**(`active_account.bump_account_epoch()`):
   `set_active` · `clear_active` · `/api/auth/login`·`/api/auth/access`·`/api/auth/register` 의 **토큰을 발급한 성공 경로**(같은 계정의 재로그인도 — 새 토큰이다) ·
   `/api/auth/logout` · `_activate_local_agent` 에서 **짝 계정이 실제로 바뀐 때만**(`/me` 반복·같은 계정은 안 올림) · `db_transfer._strict_clear_active` 와 복원 실패 때의 포인터 되돌림.
   **올리지 않는 곳**: `ingest` 의 `/api/agent/local-pair-token`(로컬 에이전트가 브라우저 세션을 이어받는 토큰 — 올리면 짝을 맺을 때마다 피드가 꺼진다) · `/me`(짝 계정이 그대로).
   한계(의도): 세대값은 허브 전체에 하나 — 같은 허브에 다른 클라이언트가 로그인해도(에이전트 재로그인 등) 피드가 끝난다(안전한 쪽).
   **토큰 바뀜**(같은 계정의 토큰 교체 — 'authKey'(이메일·uid·서버 주소)에는 안 보인다): 앱이 1초 점검마다 `getAuthToken()` 을 open 때 값과 견줘 다르면 close · 허브는 인증 켬에서
   main WS 가 (다시) 붙을 때 `ch_session` 쿠키 토큰의 sha256 을 세션 지문과 견줘 다르면 종료.
   세션은 다음에서 **영구히 끝난다**(키는 다시 안 통함, 창 닫음, 사유를 남김): close · 새 open(taken) · 사람이 창을 닫음 · **세대값이나 식별값이 open 때와 다름**(미디어 요청·
   WS 글·1초 점검마다 비교 — 점검 사이 A→로그아웃→A 도 세대값이 바뀌어 잡힘) · 인증 켬에서 저장한 토큰 지문의 토큰이 더는 유효하지 않음(미디어 요청마다 verify_token·승인·
   비밀번호 표식 — 미들웨어와 같은 판정) · main 연결이 3초 넘게 없음(연결 유실 정리 — 로그아웃 판정은 세대값이 한다) · 허브 종료. 앱은 로그인 토큰(authKey)이 바뀌거나 지워지면
   close(다른 탭 로그아웃). Bearer 토큰은 지문(sha256)만 세션에 두고 미디어 요청 때 검증은 그 지문과 같은 토큰을 open 때의 메모리 사본으로 한다 — 사본·고정값은 메모리에만(로그·응답·디스크 없음).

5. **시계·송신·재동기**(3차 8~10·P2-3·P2-4):
   - 앱(main): 표본 `{rev,t,at,playing,moving,rate,limit}` 을 재생 중 rAF 마다(단 1초 60개까지 — 앞 표본에서 16ms 안이면 건너뜀) + 이동·재생·멈춤·배속·반복 경계·장면 바뀜 즉시.
     **`ws.bufferedAmount` > 64 KB 면 보내지 않고 최신 하나만 들고 있다가** 줄면 보냄 · 2초 넘게 64 KB 위면 연결을 닫고 다시 붙음(허브가 최신 장면·표본으로 다시 맞춤).
   - 허브: 연결마다 보내기 1초 시한(넘으면 그 연결을 닫음) · scene·clock·active 최신만 · key 순서 대기.
   - 피드: 추종기에 주는 playing = `표본.playing && 표본.moving && (지금 − 표본.at ≤ 0.1초) && 재동기됨` — **moving=false 도 즉시 멈춤**(3차 P2-3) · 외삽은 그때만 `at` 기준
     타임라인 0.05초까지·`limit` 안 · 표본의 `at` 이 지금보다 0.1초 넘게 옛것이면 지금 상태로 쓰지 않음(멈춘 시각으로만).
   - 숨김 → 보임: 허브가 보임으로 바뀌는 순간 **재동기 번호 n**(세션마다 +1)을 정해 피드에 `visible{sync:n}` + 들고 있던 최신 장면 → 표본, main 에 `resync{sync:n}`
     (앱은 바로 표본 하나 + rev 가 바뀌었으면 장면, 그 뒤 표본에 `sync:n` 을 싣는다) · 피드는 숨김 때 재동기됨=false, **`sync ≥ n` 인 표본**을 받으면 true(도착 순서·`at` 비교에
     기대지 않음 — main 의 표본이 피드의 visible 처리보다 먼저 와도 맞다) — 그 전에는 재생하지 않고 마지막 그림(멈춘 시각). 멈춘 상태여도 resync 응답 표본이 오므로 기다림이 끝난다.
     피드의 상태 규칙: `visibleSync`(받은 visible 의 최대 번호)와 `best`(받은 표본 중 (sync, rev, at) 이 가장 큰 것 — 낮은 번호·옛 표본이 늦게 와도 덮지 않음)를 따로 기억하고,
     두 사건마다 `재동기됨 = 보임 && best.sync ≥ visibleSync` 를 다시 계산 · 숨김 중 받은 표본은 best 에 넣되 재생을 시작하지 않음.
     허브는 세션의 현재 n 을 들고 있다가 **새 main 연결마다 먼저 resync{n}** 을 보낸다(재동기 순간 main 이 다시 붙던 중이어도 놓치지 않게).
   - 다시 붙기는 즉시(지연 없이 한 번 → 실패하면 0.5초 간격) — 송신 2초 보류로 다시 붙어도 3초 안에 끝난다.

8. **재시작·일시 단절·소유권 상실 가르기**(Codex P1-2): 허브는 실행마다 **인스턴스 id**(난수)를 두고 open·status 가 돌려준다. 끝난 세션은 (id → 사유) 를 이 실행 동안 최근 32개 기억.
   `GET /api/clean-feed/status?session=<id>` → `{supported, reason, instance, session: live|ended|unknown, ended_reason}`. 앱의 main WS 가 끊기면 즉시 다시 붙고, 실패하면 status 로
   묻는다: ① 같은 인스턴스·live → 계속 다시 붙음 ② 같은 인스턴스·ended(taken·closed·logout·account·user-closed) → **다시 열지 않고 끔**(사유를 알림) ③ 같은 인스턴스·ended(main-gone — 3초 넘김)
   또는 다른 인스턴스(허브 재시작)·unknown → 모니터를 고른 상태면 **`takeover:false` 로 open** — 허브는 다른 live 세션이 있으면 409(밀어내지 않음, 앱은 끔) · 사람이 메뉴에서 고른 open 만
   `takeover:true`(앞 세션 taken). status 자체가 실패하면(허브가 다시 뜨는 중) 0.5초 간격으로 10초까지 다시 묻고, 그래도 안 되면 끄고 알림.
   **같은 인스턴스인데 unknown**(끝난 기록 32개가 밀려남) = 재시작으로 보지 않고 끔(알림) — 다시 열기는 다른 인스턴스일 때와 main-gone 일 때만.
   open 본문에 **`client`(탭 id — 페이지를 열 때마다 난수)·`seq`(그 탭의 open 순번, 늘기만)** — 허브는 탭마다 본 최대 seq 를 기억하고 **더 낮은 seq 의 open 은 409(stale — 밀어내지 않음)**
   (요청이 끊기거나 시한을 넘겨 서버 처리가 늦게 이어져도 옛 선택이 새 선택을 못 이긴다). 다른 탭의 open 은 seq 와 무관(그 탭의 사람 선택 = takeover).
9. **앱 쪽 작업 번호**(Codex P1-2): `useCleanFeed` 는 작업 번호를 두고 **모니터 고르기·끄기·인증 바뀜(authKey·토큰)·언마운트** 때 +1. 모든 비동기 결과(status·open·WS 사건·다시 열기)는
   시작 때의 번호를 들고, 지금 번호와 다르면 상태를 바꾸지 않는다 — 늦게 **성공한** 옛 open 은 그 응답의 세션만 close(session·key) 하고 버린다 · 늦은 409·실패는 무시.
   **open 은 한 번에 하나만**: 진행 중에 새로 고르면 마지막 선택만 들고 있다가, 앞 open 의 응답·정리가 끝난 뒤 **보내기 직전에 작업 번호를 다시 보고** 보낸다(끄기면 안 보냄).
