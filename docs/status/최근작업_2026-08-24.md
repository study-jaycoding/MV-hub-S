## 2. Resolve 전송 큐 v3 — 구현·실기기 검증 완료

> [!NOTE]
> 시점 기록이다. 이 큐는 2026-08-25 `aa0985b9` 로 걷어내고 직접 전송으로 되돌렸다(릴리스 0847 부터). 현행은 [docs/ARCHITECTURE.md](../ARCHITECTURE.md) §7.6.

Jay 요구는 "누를 때마다 전부, 앞 작업을 기다리지 않고"였다. Resolve API 구조상 **진짜 병렬 반입은
불가**(미디어 풀 커서가 전역이라 동시 쓰기는 클립 오배치를 만든다)라는 것을 먼저 확인하고, 대신
**즉시 접수(202) + 영속 대기열 + 전담 워커 + 준비만 3병렬** 구조를 택했다.

- 설계 명세: [DESIGN_RESOLVE_QUEUE_V3_2026-08-24.md](../DESIGN_RESOLVE_QUEUE_V3_2026-08-24.md)
- 1단계(접수·큐·워커) → 적대 리뷰 P1 6건 수정 → 2단계(취소·워치독·큐 UI·복구 흐름)
- 라이브 테스트에서 릴리스 차단 2건 발견·수정: 같은 초에 접수된 항목의 순서 뒤바뀜(단조 키로 교정),
  이미 죽은 프로세스를 살아 있다고 오판(프로세스 종료 시각 판정으로 교정)
- 실기기 실반입 검증 통과: 클립 3개 반입, 같은 요청 6회 반복 접수에도 중복 0, 검증 뒤 프로젝트 원상 복원
- 큐가 막힌 상태에서 올바른 프로젝트를 다시 열면 즉시 재개되도록 폴링 보강

## 3. 공유 서버 이사 공지 — 구현·실환경 검증 완료

서버 PC·IP가 바뀌면 작업자 허브가 옛 주소를 계속 보다가 로그인 화면에 갇히는 문제를 해결했다.

- 로그인 화면에 주소 변경 패널(막혔을 때의 탈출구)
- 관리자 창의 **[팀에 공지]** 버튼이 릴리스 폴더에 공지를 발행 → 작업자 알림 → **한 번 눌러 전환**
- 전환 시 옛 서버 토큰 삭제, 위조 공지 거부, 로컬 전용 라우트에 loopback·Host 가드
- 운영 절차: [SERVER_RELOCATION.md](../SERVER_RELOCATION.md)
