## 합의한 설계와 구현

1. **빌드 때 JS/CSS 사전 gzip**: Vite 최종 출력 단계(`generateBundle order: post`)에서 1 KiB 이상이고 압축이 더 작은 파일에만 `.gz`를 만든다. 원본을 보존하고 별도 패키지는 추가하지 않는다.
2. **HTTP 협상**: `/assets`의 JS/CSS GET·HEAD에만 적용. gzip 허용 여부·q=0을 판별하고 원본과 압축 파일 모두 정상 파일일 때 선택한다. Range는 원본, 누락·조회 실패도 원본으로 돌아간다. MIME은 원본 형식, ETag는 선택한 표현, Vary는 Accept-Encoding. 기존 immutable 정책과 index 재검증 정책을 유지한다.
3. **필요할 때 캔버스·편집 CSS 로딩**: SceneBoard를 별도 청크로 받고, 지역 ErrorBoundary로 실패를 캔버스 안에 가둔다. 실패 시 수동 새로고침 안내, 바깥 탭·도구 막대는 유지한다. edit-tab.css는 EditTab이 요청한다. 공유 `.lin-*` 때문에 history.css는 전역에 유지한다.
4. **릴리스 설치 재현성**: 기존 node_modules 존재와 관계없이 잠금 파일을 요구하고 `npm ci --include=dev --no-audit --no-fund` 후 빌드한다. 실패하면 즉시 중단한다. ZIP 검사에서 JS/CSS 부재와 원본 없는 gzip을 거부한다.

동일한 SceneBoard 입력·선택 신호·actionRef 계약을 유지한다. 트랜스파일링·최소화·트리셰이킹은 기존 Vite 프로덕션 파이프라인을 그대로 사용한다. 청크 경고 한도는 높이지 않았다.

## 검증과 제한

- 정적 파일·목록 gzip·릴리스 빌드/ZIP 계약 시험: **56 통과**. npm은 가짜 함수, ZIP은 임시 파일로 검증했다. 릴리스 스크립트 본문은 실행하지 않았다.
- 처음 전체 프런트 시험에서 5건 실패: 기존 시험이 캔버스 지연 로딩 완료 전에 다음 선택 신호를 보냈다. 실제 모듈 완료와 캔버스 DOM 마운트를 기다리도록 fixture를 고쳤다. 고정 대기 증액·기존 결과 단언 완화는 없다.
- 로딩 중 최초 Resolve 선택이 실제 SceneBoard에 반영되는 시험을 추가했다. 관련 **72 통과**를 두 번 확인했고, 전체 프런트 회귀 재검증은 **346파일 3,739 통과**했다. 기존 React `act` 경고는 남는다.
- 타입 검사 포함 프로덕션 빌드는 저장소 밖 임시 출력으로 성공했다. 해당 assets가 앞서 실측한 after/assets와 모두 바이트 일치했다. 실제 배포 ZIP 제작·설치까지 검증한 것은 아니다.
- 초기 전송 감소는 **캔버스를 바로 열지 않는 시작 화면 기준**이다. 캔버스부터 열면 해당 청크도 받는다. 실제 로딩 시간·LCP·장시간 운용 개선율은 측정하지 않았다.
- App은 아직 약 512 KB라 Vite의 500 KB 경고가 남는다. 캔버스 파일의 stat 이후 open 사이 경합은 기존 FileResponse와 동일한 제한이다.
- 격리 브라우저에서 로그인 전 401·차단한 모델 카탈로그 502는 전후 각각 17건 관측됐다. 제품 화면 검증을 콘솔 오류 0으로 보고하지 않는다. 실제 미디어 편집·Resolve·NAS 지연은 미검증이다.
- 구조 린트·문서 린트·생성 목록 최신성 검사·`git diff --check` 통과, 수정 문서 updated는 2026-10-14. graft build/check는 in sync. CODE_MAP 기본 검사는 새 미추적 Boundary 파일 1개를 미존재로 표시하므로, **실제 인덱스는 보존하고 임시 인덱스에 해당 경로만 등록해** 재검사했다: 미존재 0·문서 누락 0. 체크 도구는 수정하지 않았다.
