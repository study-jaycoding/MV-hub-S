# 조작·단축키 전반 점검 (2026-10-10)

Jay 요청: "모든 조작과 단축키를 Codex 와 같이 실시간으로 검토하고, 버그·딜레이·작동 이상을 모아 설계한 뒤 고친다."
이 문서는 그 결과다 — 무엇이 나왔고, 어떤 규칙으로 고쳤고, 무엇이 남았는지. 코드의 세부는 각 파일 주석이 정본이다.

## 1. 방법

- **Codex 정적 검토** 4구역(라이브러리·캔버스·프롬프트와 창들·편집 탭) → 설계 검토 1회 → 코드 리뷰 6회(커밋마다) → 남은 위험 상의 2회(무엇을 지금 고치고 무엇을 둘지 · 그룹 소실과 대량 끌기 지연) → 남겨 뒀던 셋(6회차)의 설계 검토 1회 + 코드 리뷰 10여 회
  → **7회차**: '남은 것' 표 47항목을 하나씩 다시 가름(고친다 / 결함 아님 / 실측 먼저 / 위험이 더 큼) → 모달 초점의 설계 검토 1회 → 묶음별 코드 리뷰(dev 아홉 묶음 + 편집 탭,
  묶음마다 1~8회. 리뷰가 잡은 큰 것 둘: `App` 의 훅이 이른 반환 아래에 놓여 로그인이 끝나는 순간 앱이 죽는 것 · 실측 도구가 원본 자료를 지우는 것)
  → **8회차**: 7회차 전체를 한 덩이로 다시 읽는 통합 검토 1회(묶음 사이의 맞물림·키 리스너 전수·끌기 구현 전수) → 설계 검토 1회 → 코드 리뷰 8회
  (리뷰가 씬 섞임 수정에서 같은 부류의 길을 여섯 번 더 짚었다 — 아래 3 의 '8회차')
  → **9회차**: 8회차에서 넘긴 셋의 설계 검토 2회(일괄 '마지막 걸음 다시 넣기'를 끌기별 명시 등록으로 바꿨다) → 코드 리뷰
  → **10회차**: 9회차에 드러난 부류("입력은 타이머·응답보다 먼저 온다")를 구조로 전수 검토 1회(아홉 건) → 코드 리뷰 4회
  → **11회차**: 부류 하나 더("길게 누른 키의 반복 keydown")를 키 리스너 전수로 검토 1회(열 건) → 코드 리뷰 3회(넷을 더 짚음)
  → **12회차**: 부류 둘("처리 중 재진입" · "뗀 것을 놓치면 남는 상태")을 전수 검토 1회(일곱 건 + 후보 셋) → 설계 검토 1회 → 코드 리뷰 4회
  → **13회차**: "늦게 온 조회 응답이 지금 화면을 덮는다"를 전수 검토 1회(일곱 건) → 코드 리뷰 2회.
- **격리 브라우저 실측** 5구역(작업 공간·공유 & 리뷰·캔버스·프롬프트와 창들·편집 탭). 실사용 DB 의 읽기 전용 사본으로 격리 서버를 띄우고
  헤드리스 Chrome 에 실제 키·마우스 입력을 넣어 화면·초점·콘솔·걸린 시간을 봤다. 수정 뒤 같은 구역을 여섯 번 더 쟀다(1차 수정 뒤, 최종 빌드, 마지막 묶음, 남은 위험, Jay 결정 반영, 남겨 뒀던 셋).
  7회차에는 고치기 전에 한 번(재현·프로파일 — '실측 먼저'로 가른 것들), 고친 뒤에 두 번 쟀다. 고친 것은 **옛 빌드로 되돌려 같은 스크립트가 실패하는지**도 같이 봤다.
  8회차에는 Codex 가 코드로만 짚은 것을 **고치기 전에 전부 재현부터** 하고(재현 안 되면 고치지 않는다), 고친 빌드에서 같은 스크립트를 다시 돌렸다.
- **실기 확인** 1회(Jay 허락) — 창 있는 격리 크롬에 진짜 키·마우스 입력(OS 입력)을 넣어 한글 입력기와 끌어 놓기를 봤다.
- 자동 시험은 옛 방식으로 되돌려(되돌려 확인) **시험 이름으로** 잡히는지 봤다 — 350종 전부 잡힌다(8회차의 68종·9회차의 38종·10회차의 26종·11회차의 25종·12회차의 82종·13회차의 27종도 — 9회차에는 내가 넣은 한 줄이
  되돌려도 안 잡혀, 필요 없는 수정임을 알고 뺀 것이 하나 있다).
- 느린 조작: 화면만 바꾸는 조작 300ms·서버 왕복 1500ms 를 넘은 것은 한 곳뿐이다(캔버스에서 카드 412장을 한꺼번에 끌 때 최악 프레임 343ms,
  158장은 49ms). 규칙 13 으로 절반쯤, 규칙 17 로 화면 갱신을 초당 52~55번까지 올렸다(아래 6회 — 전부 고른 끌기만. 일부만 고른 큰 끌기는 그대로다, 아래 5).

## 2. 규칙 — 새로 생긴 약속

코드를 고칠 때 이 약속을 깨면 같은 문제가 돌아온다.

1. **떠 있는 것이 키의 주인이다** (`lib/keyGate.ts`). Esc 로 닫히는 겹(창·메뉴·확인 창 = `useEscapeClose` 를 켠 것)이 하나라도 떠 있으면
   뒤 화면의 단축키는 쉰다. 뒤 화면의 키 처리(라이브러리 색·비활성·격자 키, 캔버스, 계보 보드, 프롬프트 표시/숨김, Assets, 편집 탭)는
   첫 줄에서 `backgroundKeysBlocked()` 를 본다. Esc 가 없는 덮개(업데이트 진행·로그인 화면·지연 로딩 창이 도착하기 전)는 `useKeyOwner`.
   - 겹으로 올리지 않는 것: 폴더 창·캔버스 '생성 결과' 창(라이브러리 격자를 품은 창 — 그 격자의 키가 살아야 한다), 코멘트 패널.
   - **늘 마운트돼 있는 컴포넌트는 `enabled` 에 열림(그리고 보임) 상태를 넘긴다.** 켜진 채 남은 겹은 보이지 않아도 키를 전부 막는다
     (프롬프트 도크의 드롭다운·편집 탭의 숨긴 뷰어 메뉴가 그 꼴이었다 — 숨기면 닫는다).
2. **Esc 는 한 번에 맨 위 한 겹** (`lib/useEscapeClose.ts`). 겹의 위아래는 켜지는 렌더의 순서(나중에 연 것·안쪽 것이 위). 맨 위 겹이 받은 Esc 는
   '쓴 것'으로 표시한다(`lib/keyHandled.ts`). 뒤 화면의 Esc(선택 해제·폴더 창 닫기)는 겹이 아니라 `useBackgroundEscape` — 위에 무엇이든 떠 있거나
   이미 쓴 Esc 면 손대지 않는다. Esc 를 직접 듣는 React 핸들러(격자·폴더 창)도 같은 표시를 본다.
3. **초점 잃은 키는 보이는 격자가 받는다** (`useLooseKeys`). 초점이 BODY 이거나, 막 연 폴더 창 자체이거나, 상단바·툴바·선택 막대의 단추에 남아 있을 때.
   격자가 실제로 쓴 키일 때만 초점을 데려온다. 받지 않는 것: Tab·Alt 조합·Esc, 단추의 Enter/Space, 캔버스의 보드 위(초점 없는 키는 보드의 것 — 창 안 격자는 규칙 10), 가려진(inert) 격자.
4. **누르는 순간 위에 뭔가 떠 있었으면 그 누름은 그것의 몫이다** (`pressStartedCovered`). 메뉴·확인 덮개를 닫는 누름이 뒤의 선택을 풀거나 바꾸지 않는다 —
   격자 밖·격자 안·캔버스 빈 곳 모두. 판정은 pointerdown 의 캡처에서 적어 둔다(닫기는 누름의 앞쪽에서 일어나, mousedown 에서 보면 이미 닫혀 있다).
5. **입력칸 밖의 Ctrl+A 는 화면 글자를 긁지 않는다**, **조합 중의 Enter 는 앱의 키 처리에 보내지 않는다** (`usePageSelectAllGuard` — 뿌리마다 한 번 건다: App, 그리고 App 없이 따로 뜨는 분리 창 둘 `ManageWindow`·`AssetsWindow`. 관리 화면은 분리 창에만 있다 —
   빠져 있던 동안 작업표의 입력칸들은 이 지킴이 밖이었다).
   글자 입력 대상의 판정은 `isTypingTarget` 하나로(체크박스·슬라이더는 글자 입력이 아니다).
6. **목록 재조회는 그사이 칠한 색을 덮지 않는다** (`lib/generationColorState.ts` 의 색 편집 장부). 조회 출발 뒤에 칠했거나 저장이 대기 중인 카드는
   화면의 색을 지킨다. 캔버스의 색 장부(`lib/useSceneGenData.ts`)와 같은 규칙이다.
   - **카드를 응답으로 갈아 끼우는 길은 전부 이 장부를 지난다**(7회): 목록 조회뿐 아니라 위치 조회(`useResolveLibraryFollow`·`revealLocated`)와
     생성 완료 뒤의 상세 조회(`useGenerationProgress`)도 요청이 **떠나는 순간** 도장(`colorLedger.stamp()`)을 찍고, 받은 카드를 넣을 때 그 뒤에 칠한 색을 지킨다.
7. **단축키 등록부** (`lib/shortcuts.ts`): 고정 키는 지정할 수 없다 · Shift 는 Ctrl·Alt 와 함께일 때만 센다 · 충돌은 같이 켜지는 화면끼리만(`scope`).
   저장돼 있던 고정 키·깨진 값은 읽을 때 거른다(막기 전에 저장한 Enter 가 계속 듣지 않게).
   - (7회) **읽을 때 겹침도 정리하고 알린다**: 걸러진 항목이 기본값으로 돌아가며 다른 항목의 지정과 겹치면 뒤의 것을 기본값으로 돌리고,
     단축키 창이 무엇이 바뀌었는지 한 번 보여 준다(`droppedOnLoad`). **기호 키는 Shift 를 따로 세지 않는다**(`shiftInKey` — Ctrl+Shift+1 은 key 가 이미
     `!` 다. 세면 옛 저장값 `mod+!` 가 죽는다). 값은 `splitBinding` 하나로 쪼갠다(`+` 키를 지정해도 창이 죽지 않게 — 전에는 앱 전체가 빈 화면이 됐다).
     수식키가 붙은 입력기 키(`mod+process`)는 지정을 받지 않는다.
8. **단추에 남은 초점은 Tab 으로 온 것만 '키보드 초점'이다** (`focusCameByTab`). 카드 안 단추의 Enter·Space 를 그 단추에 양보하는 것은 Tab 으로
   옮겨 온 초점일 때만이다. `:focus-visible` 로 보면 안 된다 — 마우스로 누른 단추도 그 뒤 아무 키(Esc)나 누르면 켜진다.
9. **보이지 않는 자리에는 키가 듣지 않는다.** 밖에서 선택이 풀리면 격자의 초점 카드도 지운다(격자의 Space·Ctrl+클릭으로 마지막 카드를 뺀 자리만 남는다).
   지운 자리는 **방향키·Shift 클릭의 기준으로만** 기억한다 — 툴바 단추·슬라이더를 누른 뒤의 방향키가 목록 맨 위로 튀지 않게.
   컷 카드의 Enter 는 골라져 있거나 초점이 놓인 카드만 연다.
   - (7회) 선택이 이미 빈 채 밖을 눌러도 초점 카드를 지운다(`useGenerationSelection` 의 `onPressCapture` — 누름을 캡처에서 알린다. '생성 결과' 창은
     mousedown 의 전파를 막아 버블에서는 못 듣는다). **Shift 클릭의 기준 자리는 선택이 다른 길로 바뀌면 잊는다**(`rangeAnchorRef` — 선택 칸을 켰다 끈 뒤의
     Shift 클릭이 옛 기준에서 이어지지 않게).
10. **창이 가린 보드는 키를 받지 않는다.** 캔버스에서 폴더 창이 떠 있는 동안 보드의 키 처리는 통째로 쉰다(`lib/useSceneKeyboardShortcuts.ts` —
    창의 막이 화면 전체를 덮어 보드는 누를 수도 없다). 폴더 창·'생성 결과' 창이 떠 있으면 붙여넣기도 보드에 붙지 않는다
    (`lib/useSceneClipboardDrop.ts`). 그동안 초점 없는 키는 **창 안 격자**가 받는다(규칙 3 의 캔버스 예외 — `takesLooseKey`), 폴더 창에서는
    BODY 의 r·g·b·d 도 창 안 선택에 먹는다. 초점을 창으로 끌어오는 장치는 두지 않는다(한 번 넣었다가 뺐다 — 매 프레임 감시가 필요했고
    창 밖 단추에 남은 초점은 못 막았다).
11. **한글 입력 상태의 글자 키는 물리 키로 읽는다** (`lib/keyGate.ts` `letterFromPhysicalKey`). `e.key` 가 "Process"(윈도 입력기)나 자모(맥·리눅스
    한글 자판)로 온 글자 키만, 입력칸 밖에서만, keydown 에서만 그 글자로 덮는다. 라틴 글자가 온 키(영문 상태·다른 자판)는 손대지 않는다.
    keyup 에서 글자를 보는 곳(가위 Y)은 `e.code` 를 같이 본다. **실기 확인(이 PC 의 크롬·MS 한글 입력기)**: 한글 상태여도 입력칸 밖의
    글자 키는 `key="r"`(keyCode 82)로 온다 — 윈도에서는 이 코드가 돌지 않는다(입력칸 안에서는 `key="Process"`·229). 다른 환경용 보험이다.

    그 뒤의 방향키는 조작부의 미세 이동이 아니라 **창의 키**다 — 크게 보기는 ←/→ = 앞·뒤 장(창이 약속한 키가 조작부를 만진 뒤 죽는 것이 결함이었다).
    방향키를 쓰지 않는 창(정보 창·컷 정보 창)에서는 영상 자체에 초점이 있어도 크롬이 ←/→ = 탐색, ↑/↓ = 음량을 한다. 탐색은 **시작(`seeking`)에도** 건다 — 영상을 덜 받았으면
    끝(`seeked`)이 수십 초 뒤에 온다. **도는 중의 반복 되감기**(`loop`·재생 중·0.25초 안의 탐색)는 건너뛴다 — 그때 옮기면 조작부에서 연 메뉴가 닫힌다.
    속도(`ratechange`)에는 걸지 않는다(메뉴에서 고르면 초점이 스스로 풀린다). 마지막으로 본 초점 이동이 Tab 이면(키보드로 조작부를 쓰는 중) 건드리지 않는다.
    모달 안 매체에 `tabIndex=-1` 을 주지 않는다 — 조작부가 Tab 에서 통째로 빠지고 마우스 길은 그대로 남는다.
30. **고른 카드 여러 장의 끌기는, 조건이 맞을 때만 카드의 바깥 틀만 옮긴다** (`SceneBoard.tsx` `moveOrigins`·`moveLayerScreenOk`·`moveLayerTargets`·`sameCardButPlace`).
    켜는 조건(첫 실제 이동에서 한 번): 살아 있는 끄는 카드가 **40장 이상이고 전부 골라져 있고**, 화면 배율이 **30% 이상**(툴바에 보이는 반올림 값 — 목표와 지금 보이는 배율 둘 다)이고,
    모니터 배율(devicePixelRatio)이 1. 그룹 머리 끌기·고르지 않은 카드가 섞인 끌기·한 장·판 밀기(규칙 17)는 전의 길이다. 켜지면 좌표는 전처럼 걸음마다 넣되, 끄는 카드의
    바깥 틀을 `left/top = 끌기 전 자리` + `translate = 이동량` + `data-layer-move`(규칙 17 과 같은 값 0 애니메이션)로 그리고, 카드 속에는 '자리만 다른 카드'를 다시 넘기지 않는다
    (x·y 를 뺀 모든 필드의 얕은 비교 — 필드를 골라 비교하지 않는다. 내용이 바뀌면 그 자리에서 새 카드). **조건을 잃으면 그 갱신에서 끄고, 그 끌기에서는 다시 켜지 않는다** —
    끄는 중 Esc 의 선택 해제, 줌이 30% 아래로(휠·툴바·F — 줌은 React 상태가 아니라 `lib/sceneZoomStore` 로 듣는다), 모니터 배율 변경(`matchMedia`). settle 이 없다(좌표가 살아 있다 —
    규칙 17 의 '읽기 전 settle' 과 다르다). 끄는 동안 그 카드의 `style.left/top` 은 끌기 전 자리다 — 보이는 자리는 `getBoundingClientRect` 로 읽는다.
    **문턱은 전부 실측에서 나왔다 — 낮추거나 조건을 넓히기 전에 그림을 다시 잴 것**: 배율 25% 아래에서는 따로 층이 된 카드가 흐려진다(캔버스의 `will-change: transform` 아래에서
    새 층이 다른 배율로 래스터된다 — 끄는 카드 안의 픽셀 21~70% 가 달라졌다. 끄는 동안만 그 귀띔을 떼는 것은 화면 전체의 결을 바꾸고 판 밀기를 53 → 14 로 떨어뜨렸다) ·
    고르지 않은 채 끄는 카드는 쌓임 맥락이 되어 배지·포트가 겹친 이웃 아래로 내려간다 · 20장 아래는 이득 없이 레이어만 는다 · 모니터 배율 1.25·1.75 는 끄는 동안 반 픽셀
    어긋남이 남는다(격자 22px × 배율이 정수가 아니다).
31. **Enter·Space 는 Tab 으로 찾아간 단추의 것이다** (`lib/keyGate.ts` `activationKeyOwned`). 화면의 키 처리(격자·재생 창)가 Enter·Space 를 쓰기 전에 이 함수로 묻는다 —
    체크박스 같은 입력은 언제나, 단추·링크는 **Tab 으로 옮겨 온 초점일 때만** 그 요소의 키다. 마우스로 눌러 초점이 남은 단추에서는 화면이 받는다([반복]을 누른 뒤의
    Space 는 여전히 재생/정지). 막대(range)는 양보 대상이 아니다 — Enter·Space 로 하는 일이 없다(음량을 만진 뒤의 Space 도 재생/정지).
    크게 보기(`MediaPreview`)는 창 안 단추에 늘 양보하는 제 규칙을 둔다.
32. **씬을 바꾸는 틈에는 보드가 아무것도 받지 않는다** (`SceneBoard.tsx` `cardsSceneId`·`switchingRef`·`useUnlessSwitching`, `lib/useSceneHistory.ts` `frozenRef`).
    탭 누름은 동기 렌더고, 씬 동기화 effect 가 넣는 '새 씬의 카드로 바꾸기'는 그 뒤의 낮은 우선순위 렌더다(React 18). 그 사이 — 새 씬(prop)은 왔고
    카드는 아직 떠난 씬의 것 — 가 **틈**이다. 짧지만 밀려 있던 키·클릭은 이때 들어온다(탭 연타, 탭을 누르고 곧바로 누른 키).
    - 씬이 바뀐 effect 는 `ref` 와 견주지 않고 **늘** 카드·연결·그룹을 넣는다. 견줘서 건너뛰면 앞 전환이 밀어 둔 갱신이 뒤늦게 새 씬 화면에 그려진다
      (전: X → Y → X 연타에 Y 가 X 의 카드로 덮여 저장됐다).
    - 카드의 주인 씬(`cardsSceneId`)은 **state** 다 — 카드와 같은 갱신으로 바뀐다. `sceneIdRef` 로 읽으면 effect 는 돌았고 카드는 아직인 렌더에서 이름과 내용이 어긋난다.
    - 틈(`cardsSceneId !== scene.id`)에 막는 것: 보드의 누름·휠(`inert`) · 키(`useSceneKeyboardShortcuts` 의 `isFrozen`) · 붙여넣기의 **시작**(`useSceneClipboardDrop` 의
      `frozenRef` — 끝날 때의 '씬이 그대로인가' 검사로는 못 거른다) · 편집용 설정자(`setCards`·`setEdges`·`setGroups` — 씬 동기화 effect 만 `…Now` 를 쓴다) ·
      저장·되돌리기·과거 스냅샷 고치기(`frozenRef`) · `flushPending` · 카메라 저장 · 툴바 맞춤/확대 · 보드 밖에서 시작하는 범위 선택. 틈에 한 조작은 버려진다.
    - **보드에 새 쓰기 길을 낼 때는 이 틈을 지나는지 볼 것** — 편집용 설정자와 `persist` 를 지나면 막힌다. 다른 길(직접 `onChange`, App 의 `patchActiveScene`)은 따로 막아야 한다.
33. **보드 위의 새 누름은 남은 끌기를 먼저 끝낸다** (`lib/sceneDragSession.ts` `settle`, `SceneBoard.tsx` `settleDrag`). 끌기 세션은 보드에 하나뿐이라 새 끌기의 `beginDrag` 가
    앞 끌기를 끝내 주지만, 그때는 새 조작이 **시작 좌표를 이미 읽은 뒤**다. 누름의 첫머리(`onBoardMouseDownCapture` · 보드 밖 누름의 콜백)에서 먼저 끝낸다.
    끄는 중 다른 단추를 누르면 그 자리에서 끝난다(전: 그 단추를 뗄 때). 짝이 되는 약속 둘: 끌기가 끝날 때 그룹 값을 **ref 에도 바로** 넣는다(`groupsRef.current = …` —
    같은 누름의 새 조작이 다음 렌더 전에 읽는다) · 새 조작의 기준 틀은 렌더가 잡아 둔 값이 아니라 **누르는 순간에** `cardsRef`·`groupsRef` 로 다시 잰다(`currentGroupFrames`).
34. **프롬프트에 묶인 카드는 그 씬과 함께 든다** (`lib/useSceneCoordination.ts` `boundCard`·`sceneBinding`, `lib/useSpotlightTray.ts` `trayReady`). 묶임(`{ sceneId, cardId, refs }`)은
    그 씬이 활성일 때만 있는 것으로 본다 — 씬을 바꾼 직후 '새 씬 + 떠난 씬의 카드 id' 로 묶인 렌더가 없다(두 씬에 같은 id 의 카드가 있으면 — 가져온 씬 — 그 틈의
    입력·생성이 새 씬의 카드로 갔다). 씬을 바꿀 때 값을 비우지는 않는다(곧바로 돌아오면 보드의 선택은 그대로인데 묶임만 사라진다).
    묶임이 바뀐 렌더에는 트레이가 아직 **앞 카드의 레퍼런스**다 — 제출은 `trayReady`(트레이가 지금의 묶임에 맞춰졌는가)가 참일 때만 나간다.
35. **끄는 중에 밖에서 값이 갈리면, 끌기가 쥔 값을 받은 값 위에 다시 얹는다** (`lib/sceneDragSession.ts` `rebase`·`onRebase`, `SceneBoard.tsx` 씬 동기화의 `replaced`).
    끄는 동안의 좌표·크기·네모는 저장 전이라 부모의 씬에는 없다. 같은 씬에 밖의 갱신(생성 결과 도착 등)이 오면 씬 동기화가 그 값으로 갈아 끼우므로,
    그 직후 ref 를 받은 값으로 맞추고 도는 끌기의 `onRebase` 를 부른다 — 끌기는 **받은 카드에 좌표·크기만** 다시 넣는다(밖에서 온 내용은 남는다).
    - `onRebase` 를 거는 것은 값을 끄는 중에 바꾸는 넷뿐이다: 카드 끌기(일부 = 마지막 걸음, 판 밀기 = 좌표에 확정해 둔 만큼)·그룹 머리 끌기·카드 크기 조절·그룹 크기 조절.
      범위 선택·화면 이동·연결선·자르기·순서 끌기에는 걸지 않는다.
    - **`move` 를 한 번 더 부르는 것으로 대신하지 않는다** — `move` 는 속도 표본(그룹 이탈 판정)·마우스 밑 찾기(자르기)까지 한다(Codex 설계 검토).
      다시 얹는 값은 **마지막으로 넣은 결과**다 — 다시 계산하면 그사이 줌이 바뀐 크기 조절이 다른 값을 낸다. 기준 카드만 보고 건너뛰지 않고 쥔 카드·네모 전부를 놓는다.
    - 좌표를 끌기가 쥐는 것은 **밖에서 갈렸을 때뿐**이다 — 놓을 때의 '이미 넣었으면 다시 계산하지 않는다'(규칙 17)는 그대로다.
    - **누르기만 하고 아직 안 움직였으면 쥔 것이 없다** — 아무것도 얹지 않는다. 크기 손잡이(카드·그룹)는 그때 받은 크기를 **새 출발점**으로 삼는다
      (누른 순간의 값을 쥐고 있으면 밖에서 커진 카드가 첫 걸음에 줄고, 그룹은 끌지 않고 놓을 때 옛 테두리가 저장된다).
    - 끄는 사이 대상이 밖에서 지워졌으면 되살리지 않는다. 그룹 크기 조절은 놓을 때 대상 그룹이 없으면 아무것도 저장하지 않는다.
      기준 카드(잡은 카드)만 지워졌으면 남은 카드·네모는 계속 같이 간다 — 이동량을 기준 카드에서 다시 재지 않는다.
36. **끈 뒤에 삼키는 click 은 그 끌기에 딸린 한 번이다 — 타이머만 믿지 않는다** (`lib/useSceneCardMove.ts` `swallowDropClick`, `SceneBar.tsx` `suppressClickRef`·`suppressTimerRef`,
    `common/FolderTreeView.tsx` `folderDraggingRef`·`dragReleaseRef`, 편집 탭 `timeline/EditPool.tsx` `draggedRef`). 끌어 놓으면 브라우저가 같은 작업 안에서 click 을 하나
    더 보내므로 그것을 삼키고 `setTimeout(0)` 으로 거둔다 — 그런데 **입력은 타이머보다 먼저 처리된다**. 놓은 직후 화면을 다시 그리느라 바쁜 사이(카드가 많은 씬)에
    누른 것은 타이머가 돌기 전에 도착해 전부 삼켜졌다. 세 가지를 같이 지킨다:
    - 삼켰으면 **그 자리에서** 거둔다(한 번).
    - **새 누름(mousedown·pointerdown)이 오면** 거둔다 — 그 뒤의 click 은 놓기의 것이 아니다. click 이 딸려 오지 않은 끌기(뗀 자리가 다른 요소)도 이것으로 닫힌다.
    - 해제를 타이머로 예약했으면 **새 누름이 그 예약도 거둔다** — 남겨 두면 곧바로 시작한 다음 끌기의 억제(끄는 중 Esc 로 취소한 것 등)를 앞 끌기의 타이머가 푼다.
    깃발을 끌기가 **끝날 때** 세우고 딸린 click 이 같은 작업에 오는 자리(`EditPool`·Resolve 목록)는 앞 타이머가 끼어들 틈이 없다 — 예약을 따로 들 필요가 없다.
37. **미뤄서 하는 일은 그사이의 입력을 본다.** 타이머·다음 프레임·응답을 기다린 뒤에 하는 초점 이동·넣기·닫기·저장은, 기다리는 사이 사용자가 한 일을 덮지 않는다
    (입력은 타이머보다 먼저 처리되고, 응답은 몇 초 뒤에도 온다).
    - **초점**: 미뤄서 주는 초점은 갈 곳을 잃었을 때(BODY)만 준다 — 다른 입력칸으로 옮긴 초점은 둔다. Assets 의 태그 입력 종료(`AssetsView` `cellOnTagCancel`) ·
      제출 성공 뒤(`useSpotlightSubmit` — BODY·프롬프트 입력칸·생성 단추일 때만. 패널 안이라도 옵션 입력은 둔다) · Shift+Backspace 로 비운 뒤(`SpotlightPrompt`) ·
      생성물 격자의 편집 종료(`ThumbnailGrid` — 전부터). 새 입력칸에 주는 초점은 타이머가 아니라 **그 칸이 그려지는 커밋에서**(편집 탭 `EditPool` 의 검색칸).
    - **넣기**: 응답을 기다린 뒤에 레퍼런스·프롬프트를 넣는 길(`SpotlightPrompt` — 외부 파일 가져오기·'레퍼런스로 사용'·프롬프트 재사용)은 기다리는 사이 고른 카드가
      바뀌었으면 넣지 않는다. **더하는** 것은 묶임이 같은지만(`bindingKeyRef` — 다녀왔으면 그 카드에 넣는 것이 맞다), **갈아 치우는** 것은 한 번도 안 바뀌었는지
      (`bindingTurnRef`)와 요청 순번(`reuseSeqRef` — 나중에 누른 것이 이긴다)까지 본다. 가져온 파일은 Assets 에 남기고 알린다.
    - **닫기**: 늦게 끝난 요청이 창을 닫을 때는 그 창이 같은 대상을 보이고 있을 때만(`InfoPopup` `shownGenRef` — 창은 App 에 하나뿐이다).
    - **뜻을 타이머로 정하는 입력**(단일/더블클릭 — `lib/useClickSeparation`): 훅 하나를 여러 대상이 같이 쓰면 대상을 가린다(`onClick(single, key)`) —
      다른 대상의 클릭은 앞 예약을 거두고 새로 건다.
    - **예약해 둔 저장·검색**: 대상이 바뀌기 전에 적거나(계보 보드의 카메라 — `HistoryBoard` `shownFocusRef`) 밖에서 초기화되면 버린다(`SearchBox` — 내가 보낸 검색의
      메아리와 바깥 변경을 `sentRef` 로 가르고, 값이 안 바뀌는 초기화는 신호로 받는다: 탭 누름은 `TopBar` 의 key, 자동 따라가기는 `resetKey`.
      **사용자가 아무것도 안 해도 오는 초기화에 key 를 쓰지 말 것** — 입력칸이 다시 올라가며 치던 사람의 초점이 사라진다).
    - 에셋 끌기의 페이로드(`lib/spotlightAssetRefs`): dragstart 가 그 순간의 선택으로 만든 값을, 늦게 적히는 저장된 선택으로 다시 넓히지 않는다.
38. **길게 누른 키의 반복 keydown 은 기본 동작만 막고, 일은 다시 하지 않는다.** 키를 누르고 있으면 브라우저가 keydown 을 계속 다시 보낸다(`event.repeat` — 간격은 OS 설정, 보통 초당 수십 번).
    한 번만 일어나야 하는 키 — **토글**(색·비활성·고르기·재생/정지·여닫기), **열기·보내기**(히스토리·붙여넣기·저장), **찍기**(편집 탭의 I·O·M·D), **셔틀**(L·J) — 는
    첫 keydown 에만 한다. 반복마다 다시 하면 짝수 번에 '안 먹은' 것처럼 보이고, 놓는 순간에 따라 결과가 달라지며, 요청이 겹쳐 나간다.
    - **기본 동작은 반복에도 막는다** — Space 의 스크롤, Ctrl+K·Ctrl+V 의 브라우저 동작, Tab 의 초점 이동. 막지 않으면 일은 한 번만 해도 화면이 밀리거나 초점이 흘러간다.
    - **반복이 뜻인 키는 그대로**: 방향키(카드·프레임·편집점 이동), 되돌리기·다시 하기, 확대·축소, 트랙 옮기기, 정렬 반복.
    - 첫 누름을 **누가 썼는지에 따라** 반복을 막을지 정해야 하는 키(캔버스의 Tab — 캔버스가 쓰면 노드 선택기, 아니면 평소의 초점 이동)는 그 누름에 표식을 단다
      (`useSceneKeyboardShortcuts` `pickerTabHeld`). 표식은 **그 키의 새 누름·keyup·창 blur** 에 지운다 — 양보하며 돌아가는 길보다 먼저. 다른 키의 누름에는 지우지 않는다.
    - 줄(role="button")이 키를 막을 때는 **줄 자신이 받은 키만** 본다(`e.target === e.currentTarget`) — 안의 단추에서 올라온 Enter·Space 를 막으면 그 단추가 안 눌린다.
    - 시험은 반복을 **홀수 번** 보낸다 — 토글은 짝수 번 뒤집히면 처음과 같아 되돌려도 안 잡힌다.
39. **처리 중인 일은 다시 받지 않는다 — 그리고 누르고 있다는 표식은 뗀 것을 놓쳐도 내린다.** 응답을 기다리는 동안 같은 단추·키를 한 번 더 누르면
    (더블클릭, 조급한 다시 누름) 같은 일이 겹쳐 실행된다. 겹치면 탈이 나는 일은 처리 중임을 **동기 값(ref)** 으로 들고 다시 누른 것을 받지 않는다.
    - **유료 요청**: 재생성은 누름마다 요청 키가 새로 만들어져 서버의 중복 제거로도 합쳐지지 않는다(`useGenerationCardActions` `regenInFlightRef` —
      생성물별). 풀기는 **제출 응답 직후** — 목록 갱신까지 잡고 있으면 '큐에 등록'을 보고 일부러 한 번 더 누른 것이 말없이 버려진다. 캔버스는 pending 연결을
      만들기 **전에** 막는다(`App` `sceneRegenInFlightRef` — 연결 준비가 느리면 뒤 누름이 앞 요청의 응답 뒤에 닿는다). 막은 누름이 만든 연결은 버린다.
    - **응답마다 새것을 만드는 일**: 히스토리 열기(응답마다 씬 탭) · 다운로드(같은 파일의 사본) · Assets 반입(서버가 이름을 `_2` 로 피한다).
      다운로드는 **받던 것을 같이 기다린다**(`lib/download` `inFlight` — 단건·일괄이 한 경계를 지나므로 일괄이 도는 중의 단건도 걸린다). 일괄은 한 번에 하나.
      반입은 올리는 중인 같은 파일(자리·이름·크기·수정 시각)만 거른다 — 다른 파일의 겹친 반입은 받고, '가져오는 중' 표시는 **횟수**로 든다.
    - **전체를 덮어쓰는 저장**(역할 목록 PATCH — 화면의 값으로 만든 요청은 화면이 낡았으면 그사이 저장된 것을 지운다): **잠금으로 막지 않고 구조로 막는다**
      (`lib/saveQueue`). ① 저장을 **한 줄로** 세운다 — 줄은 모듈 값이라 화면(창·탭·패널)이 사라졌다 다시 떠도 이어진다. ② 차례가 오면 서버의 **지금 값을 읽어**
      화면에서 **바꾼 것만** 얹는다(`rebaseRoles(지금 값, 누른 순간의 화면 값, 누른 뒤의 값)`) — 달라질 때만 보낸다. ③ 쓰기 직전에 **계정이 그대로인지** 본다
      (`accountAtRequest` — 읽는 사이 다른 탭에서 계정이 바뀌면 새 계정의 이름으로 나간다). 지금 목록에 **없는 멤버는 '역할 없는 멤버'가 아니다** — 저장하면 되살아난다.
      화면의 `disabled`(줄이 도는 동안 모든 멤버의 칩)는 그 위의 안내일 뿐이다. 잠금만으로는 닫히지 않았다 — 누른 멤버만 잠그면 다른 멤버를 누를 때 옮겨 가고,
      패널의 state 면 탭을 다녀올 때 풀리고, 다시 읽기가 끝나기 전의 틈이 남고, 열 때 먼저 보이는 캐시가 있다(Codex 코드 리뷰가 그 길을 차례로 짚었다).
      단추를 `disabled` 로 잠근 자리의 핸들러 가드는 넣지 않는다 — React 는 disabled 단추의 click 을 부르지 않아 닿지 않는 줄이다.
    - **늦게 끝난 앞 요청이 나중 것을 덮는 일**(Comfy 워크플로 불러오기 — 파싱은 Comfy 서버를 조회해 수십 초가 걸릴 수 있다): 받되 **순번**으로 가린다.
      순번은 일의 맨 앞(파일을 **읽기 전**)에 잡고, **이미 반영된 것보다 앞선 것만** 버린다 — '가장 나중에 시작한 것만 받는다'로 하면 나중 것이 읽기·파싱에
      실패했을 때 아직 돌던 앞의 것까지 버려진다. 반영된 순번은 **씬과 카드**로 적는다(같은 씬 파일을 두 번 가져오면 카드 id 가 같다). 다른 길로 확정한 것
      (워크플로 창의 저장)도 '반영된 것'이다. '불러오는 중'은 돌고 있는 **수**로 든다. 받아들일 때 딸린 것(내용·후보·노출 선택)을 **같이** 바꾸고, 실패하면 앞의 묶음을 둔다.
    - **'누르고 있다' 표식**(순서 손잡이 ⠿ 는 누르는 동안만 줄을 draggable 로 만든다): 끄는 길이 손잡이의 mouseup·끌기의 dragend 뿐이면, 끌기가 시작되기 전에
      손잡이 밖에서 떼거나 누른 채 창을 떠났을 때 남는다 — 그 뒤로는 줄 본문을 끌어도 순서가 바뀌어 저장됐다. 켜져 있는 동안 창의 mouseup·blur·숨김을 듣는다
      (`lib/useDragEndReset` `useHandleRelease` — 세 곳). 호버로 트는 소리(Assets 오디오 타일)도 같다 — 올려 둔 동안만 듣고, 벗어나거나 셀이 사라지면 뗀다.
40. **늦게 온 조회 응답은 지금 대상의 것일 때만 화면에 넣는다 — 성공·실패·로딩 모두.** 대상을 바꾸는 조작(프로젝트·팀·필터·여는 창의 대상)이 조회를 새로 보내면
    앞 조회의 응답은 뒤늦게 올 수 있다. 조회를 보낼 때 **순번이나 대상의 키**를 잡고, 응답이 왔을 때 그것이 지금도 최신인지 본다.
    - **대상의 키는 화면이 구분하는 전부다.** Assets 코멘트는 경로만 견줘서, 프로젝트를 바꿔 같은 상대경로의 파일을 열면 앞 프로젝트의 코멘트가 섞였다
      (`useAssetCommentActions` — 프로젝트 + 경로). 다시 쓰이는 칸도 같다: Assets 타일은 key 가 상대경로라 프로젝트를 바꾸면 같은 칸이 다른 파일을 보인다 —
      그 칸에 늦게 심는 것(복사용 그림)은 **지금 파일의 것**일 때만, 그리고 파일이 바뀌면 걷는다(`AssetCell` `urlRef`).
    - **실패도, 로딩 표시도** 같은 가드를 지난다 — 늦은 실패가 지금 목록을 비우거나 오류 글을 띄우지 않는다. 반대로 **응답을 버리는 길에서는 로딩을 끌 것이
      없다**: 대상이 '없음'이 되는 경우(폴더가 하나도 없는 팀)에는 그 자리에서 화면과 로딩을 비운다(`useAssetProjectData` — 화면의 소속 표시를 먼저 비워야
      빈 값이 앞 대상의 캐시에 적히지 않는다).
    - **창을 여는 조회**: 늦은 응답이 그사이 연 다른 창을 갈아 끼우지 않는다(`ProjectManagerPanel` `settingsOpenSeqRef` — 다른 프로젝트의 ✎·'+ 새 프로젝트').
    - **무엇을 물었는지는 보낼 때가 아니라 '지금'의 값으로**: 저장이 끝난 뒤의 재조회가 누른 순간의 필터·팀·콜백을 쓰면 그사이 바뀐 화면과 어긋난다
      (`AdminWindow` `showHiddenRef` · `MountManager` `latestRef`).
    - **변경 요청의 응답이 조회와 같은 범위라고 믿지 않는다**: 폴더 등록·해제의 응답은 팀으로 좁히지 않은 전체였다 — 그대로 넣으면 다른 팀의 폴더가 보인다.
      끝나면 지금의 범위로 다시 묻는다.
    - **응답마다 화면을 가져가는 일**(히스토리 열기 = 새 씬 탭으로 이동)을 여럿 잇달아 하면 **누른 순서대로** 한다(`useGenerationUtilityActions`
      `historyChainRef` — 앞의 조회가 끝난 뒤에 다음 것을 보낸다). 한꺼번에 보내면 먼저 누른 것이 나중에 와서 화면을 가져간다.
    - 대상이 바뀌면 그 대상에 딸린 패널은 닫는다 — 열어 두면 거기서 하는 일이 새 대상에 간다(Assets 코멘트 패널: 새 코멘트가 새 프로젝트의 같은 경로에 달렸다).

### 8회차 — 통합 검토가 짚은 것, 그리고 씬 섞임

7회차를 끝낸 뒤 Codex 에게 7회차 전체를 한 덩이로 다시 읽혔다(묶음 사이의 맞물림·키 리스너 전수·끌기 구현 전수). 새 P1 은 없었고 P2 열·P3 둘이 나왔다.
전부 **고치기 전에 격리 브라우저에서 재현**했고(전부 재현됐다), 그 실측이 대조로 넣은 두 곳에서 기존 결함 둘을 더 찾았다.

- **★ 씬 탭을 빠르게 오가면 한 씬이 다른 씬의 카드로 덮여 저장되던 것**(기존 결함 — 8회차의 수정이 만든 것이 아니다. 규칙 32). 직접 확인 스크립트의
  '씬 탭 연타'가 실패해 추적했다: 고치기 전 빌드(dev `50d38c6b`)에서 8회 실행 중 3~4회, 측정이 같이 돌아 부하가 걸렸을 때 잘 났다. X(카드 1장)·Y(빈 씬)를
  X → Y → X 로 누르면 **Y 에 X 의 카드가 저장**된다(새로 고침 뒤에도 남는다). 10-10 에 같은 증상을 한 번 고쳤는데(저장 확정의 방어) 다른 길이 남아 있었다 —
  X 로 간 effect 의 '카드 바꾸기'가 밀려 있는 사이 Y 로 돌아오면 Y 의 effect 가 "같은 객체"라며 아무것도 넣지 않아, 밀린 X 의 카드가 Y 화면에 뒤늦게 그려지고
  다음 저장 확정이 그것을 Y 에 썼다. 고친 뒤 Codex 리뷰가 같은 부류를 여섯 번 더 짚었다(전부 닫음): 다른 동기 렌더가 끼면 카드의 이름만 새 씬으로 바뀜 →
  주인 씬을 state 로 · 틈의 실제 편집이 밀린 갱신 뒤에 다시 적용됨 → 편집용 설정자 · 틈에 시작한 끌기·화면 맞춤·Comfy 실행 → 보드 `inert`·키·카메라 ·
  틈에 예약된 붙여넣기 · 기록 전파 · 프롬프트 도크의 묶임(규칙 34) · 묶임이 바뀐 직후의 제출(앞 카드의 레퍼런스로 생성이 나갈 수 있었다).
- **캔버스 밖 끌기의 놓친 mouseup**(규칙 21 을 넓힘): 생성물·컷 카드·Assets·Resolve 목록의 마퀴, 태그·코멘트 패널, 정보 창·크게 보기·컷 정보 창의 머리,
  버전 비교 창의 이동·크기 조절, 모아보기와 View 재생 창의 재생헤드, 미니맵(뗀 마우스를 보드 위로 옮기면 캔버스가 화면 밖으로 날아갔다), 레퍼런스 순서 끌기
  (나중의 무관한 누름에 순서가 바뀌었다) — 전부 단추를 뗀 마우스를 따라왔다. 절반은 창을 떠날 때(blur)도 그랬다. 태그·코멘트 패널은 **떠돈 자리가 저장**됐다.
  누른 채(안 움직이고) 놓친 것이 클릭으로 확정되던 것도 같이(격자·Assets·Resolve·계보 보드).

  `lostpointercapture` 로 끝낸 끌기를 바로 뒤의 `pointermove` 가 다시 켰다.
- **단추에 초점이 있을 때의 Enter·Space**(규칙 31): Assets 카드의 S·T·C(Enter = 크게 보기가 열림, Space = 선택이 풀림 — 단추는 안 눌림), 모아보기와
  View 재생 창의 닫기·반복·음소거(Space = 재생/정지가 바뀜 — 단추는 안 눌림).
- **레퍼런스 역할 메뉴가 뜬 채 Ctrl+K** 가 메뉴 뒤에서 프롬프트를 숨기던 것(같은 도크의 모델 목록은 쉬었다 — 이 메뉴만 겹이 아니었다) · 그 메뉴가 뜬 채
  트레이의 Shift+Backspace 가 레퍼런스를 전부 지우던 것.
- **Resolve 목록**: 카드 크기 막대를 만진 뒤 r·g·b·d·Ctrl+A·Esc 가 전부 안 먹던 것(막대에 초점이 남는다).
- **폴더 줄의 d**: 길게 누르면 반복마다 뒤집히던 것(키다운 11번 = 토글 11번) · 폴더 메뉴가 떠 있는데 Tab 으로 닿은 뒤 폴더 줄에서 먹던 것.
- **캔버스 — 남은 끌기와 새 누름**(규칙 33): 앞 끌기의 걸음이 프레임을 기다리는 사이 같은 카드(나 같이 고른 카드)를 다시 누르면 앞 끌기의 이동이 통째로
  사라지던 것 · 가운데 단추로 판을 밀다 카드를 잡으면 밀린 화면 이동이 카드 이동량에 섞이던 것 · 그룹을 끌다 곧바로 다른 조작을 시작하면 한 걸음 전의
  그룹 틀·네모를 읽던 것(옮겨 간 그룹의 옛 자리에 놓은 카드가 편입됨, 자동 그룹의 옛 틀이 수동 네모로 저장됨).

### 9회차 — 8회차에서 넘긴 셋

8회차가 "별도 설계·후속"으로 넘긴 셋을 Codex 와 다시 봤다(설계 검토 2회). 하나는 고쳤고, 하나는 고칠 것이 없다는 결론이고, 하나는 영향이 있는 한 곳만 고쳤다.

- **끄는 중에 밖에서 씬이 갱신되면 끌던 것이 되돌아가던 것**(규칙 35 — 8회 실측의 덤으로 본 것): 생성 결과가 도착하는 등 같은 씬이 밖에서 갱신되면 끌던 카드가
  끌기 전 자리로 돌아가 보였고(다음 움직임에 다시 왔다), **더 움직이지 않고 놓으면 그 값이 저장**됐다 — 카드 끌기·카드 크기 조절은 한 일이 사라지고,
  그룹 머리 끌기는 **네모만 가고 멤버는 끌기 전 자리에 남은 채** 저장됐다(틀이 늘어난다). 판 밀기는 좌표에 확정해 둔 이동이 사라졌다.
  같이 고친 것(Codex 검토가 짚음): 그룹 크기를 조절하는 사이 그 그룹이 밖에서 지워지면, 놓을 때 마지막 테두리 안의 카드를 다른 그룹에서 빼고 비게 된 그룹을 지워
  저장하던 것 · 크기 손잡이를 누르기만 한 사이 밖에서 크기가 바뀌면 옛 크기에서 늘어나거나(카드 — 220 → 밖 440 → +22 가 242 로 저장) 놓을 때 옛 테두리가
  저장되던 것(그룹) · 끄는 사이 기준 카드가 밖에서 지워지면 남은 카드가 놓을 때까지 끌기 전 자리로 보이거나(판 밀기) 네모만 멈춰 엇갈린 채 저장되던 것(그룹째 끌기).
- **보드의 저장이 '지금 활성 씬'에 쓰이는 구조**: 고치지 않는다 — 보드가 부모에 쓰는 길은 `useSceneHistory` 의 세 자리(`persist`·`commitDerivedState`·`restoreState`)뿐이고
  셋 다 규칙 32 의 틈에서 막힌다. `onChange` 는 그 렌더의 활성 씬을 쥐고 있어, 막히지 않은 쓰기에서는 카드의 주인 = 쓰는 씬이다. 주인 씬 id 를 실어 보내도
  지금의 길에서는 달라지는 동작이 없다(Codex 동의 — "현재 경로에 한정"). 새 쓰기 길을 낼 때의 주의는 규칙 32 의 마지막 줄 그대로다.
- **끄는 중에 사라진 화면의 남은 리스너**: 계보 보드만 고쳤다 — 가운데 단추로 화면을 미는 중에 보드가 내려가면, 그 뒤에 민 만큼이 단추를 뗄 때 그 카드의 카메라로
  저장됐다(다시 열면 엉뚱한 자리). 정보 창·크게 보기·Assets·계보 보드의 노드 끌기는 그대로 둔다 — 남은 리스너는 사라진 화면의 state 만 건드려 아무 일도 하지 않고
  다음 뗌에 스스로 떼어진다(Codex 동의).

8회차를 고친 뒤의 재실측(캔버스·편집 탭)이 두 빌드에 똑같이 있던 것을 셋 더 찾았다:

- **카드를 끌어 놓은 직후의 클릭이 안 먹던 것**(규칙 36): 놓자마자 누른 씬 탭 세 번이 전부 무시됐다(고치기 전 20/20). 끌어 놓은 뒤의 click 하나를 삼키는 장치가
  타이머가 돌 때까지 남아 그 사이의 click 을 전부 삼켰다. 같은 모양을 전수로 찾아 같이 고쳤다(Codex 가 둘을 더 짚음): 씬 탭 순서 끌기(탭 밖에서 놓은 바로 뒤의 탭 누름 ·
  곧바로 다시 끌다 Esc 로 취소하고 놓으면 씬이 열리던 것) · 사이드바 폴더 줄(끌어 놓은 바로 뒤에 그 폴더를 눌러도 안 골라짐) · 편집 탭 미디어 풀(끌어서 고른 바로 뒤의 카드 누름).
  Resolve 목록은 끌기가 끝날 때마다 깃발을 다시 써서 해당 없음(넣었던 한 줄이 되돌려 확인에 안 잡혀 뺐다).
- **편집 탭 — 타임라인 클립을 끌다 놓는 이벤트를 놓치면 클립이 어긋난 채 남던 것**: 끌던 만큼 `translateY` 를 단 채 남아 그 클립을 다시 눌러야 풀렸다(단추 없는 움직임 3/3 ·
  창을 떠난 뒤 3/3). 브라우저는 그때 포인터 쥐기만 거둔다 — `lostpointercapture` 를 취소로 듣는다(끝점이 없으니 옮기지 않는다).

### 10회차 — 뒤따르는 입력이 타이머·응답보다 먼저 올 때

9회차의 '끈 뒤의 click'이 "입력은 타이머보다 먼저 처리된다"는 한 문장으로 설명됐다. 같은 전제를 잊은 자리를 Codex 에게 **모양으로**(이름이 아니라 구조로) 전수로
찾게 했다 — 미뤄서 푸는 깃발 · 미뤄서 하는 초점·선택 · 디바운스된 저장 · 타이머로 뜻을 정하는 입력 · 늦게 도는 응답. 아홉 건이 나왔고 전부 코드로 읽어 맞다고
확인한 뒤 고쳤다(규칙 37). 손으로 닿는 것 여섯, '간격 0' 입력에서만 나는 것 셋.

- **프롬프트에 놓은 외부 파일이 다른 카드의 레퍼런스로 저장되던 것**: 카드 A 를 고른 채 파일을 놓고, 올라가는 사이(큰 영상은 몇 초) B 를 고르면 그 파일이 B 에 붙었다 —
  트레이는 이미 B 의 것이라 거기에 더해지고, 트레이의 변경 통지가 B 에 썼다. '레퍼런스로 사용'(@)·프롬프트 재사용도 같은 길이었다(받아 오는 수십~수백 ms).
  재사용은 A → B → A 로 다녀와 새로 친 글을 옛 응답이 덮거나, 잇달아 둘을 누르면 늦게 온 첫 응답이 이기기도 했다(Codex 코드 리뷰).
- **Assets: 태그 입력 뒤 검색칸을 누르면 초점을 빼앗기던 것**: 다음 프레임에 격자가 초점을 가져가, 검색칸에 치려던 글자가 격자의 단축키로 갔다 — r·g·b 는 **고른 파일의 색을 바꾼다**.
- **생성 제출 뒤 검색칸에 치던 글자가 프롬프트에 들어가던 것**: 응답이 오면 프롬프트로 초점을 돌려주는데, 그사이 옮긴 초점까지 가져갔다.
- **캔버스·계보 보드에서 S 를 두 카드에 연달아 누르면 뒤 카드가 무시되던 것**: 단일/더블클릭을 가르는 220ms 대기를 보드의 모든 카드가 같이 써서, 앞 카드의 대기 중에
  누른 다른 카드의 S 가 '둘째 클릭'으로 버려지고 앞 카드의 확인만 뒤늦게 떴다.
- **검색어를 친 직후의 초기화가 되살아나던 것**: 0.3초 뒤로 예약된 검색이, 그사이의 필터 초기화(켜진 탭을 다시 누름 · Resolve 자동 따라가기) 뒤에 다시 걸렸다 —
  따라가기가 찾아간 자리에 옛 검색이 걸리면 찾은 카드가 가려진다. 덤으로 고쳐진 것: 검색어 끝에 친 빈칸이 0.3초 뒤 사라지던 것(부모에서 돌아온 값이 입력을 덮었다).
- **늦게 끝난 '다시 실행'이 다른 카드의 정보 창을 닫던 것**: 정보 창은 App 에 하나뿐이라, 닫고 다른 카드를 열어도 옛 요청이 끝나며 지금 창을 닫았다.
- ('간격 0'에서만) 계보 보드에서 휠로 줌한 직후(0.25초 안) 다른 계보로 넘어가면 떠난 카드의 마지막 줌이 저장되지 않던 것 · Shift+Backspace 직후의 한 프레임에
  다른 칸을 누르면 프롬프트가 초점을 되가져가던 것 · 에셋을 고르기에서 뺀 직후(0.15초 안)에 한 장만 끌어 놓으면 뺀 파일이 같이 붙던 것 ·
  (편집 탭) 검색 단추를 누른 직후의 카드 누름보다 늦게 검색칸이 초점을 가져가던 것.

### 11회차 — 길게 누른 키의 반복

8회차의 '폴더 줄 d'가 "길게 누르면 반복마다 뒤집힌다"였다. 같은 모양(반복 keydown 을 거르지 않는 토글·열기·찍기)을 Codex 에게 키 리스너 전수로 찾게 했다 —
열 건이 나왔고 전부 코드로 읽어 확인한 뒤 고쳤다(규칙 38). 코드 리뷰가 넷을 더 짚었다(아래 ★).

- **격자의 색·비활성·고르기가 반복마다 뒤집히던 것**: r·g·b·d(작업 공간·공유 격자, Resolve 프로젝트 창), Space 고르기(격자·폴더 묶음 카드), Assets 격자의 글자 키 전부.
  키를 조금 길게 누르면 여러 번 뒤집혀, 떼는 순간에 따라 켜지거나 꺼졌다 — 색은 반복마다 저장 요청도 나갔다.
- **재생/정지 Space 가 반복마다 뒤집히던 것**: 컷 릴·타임라인 보기(View)·크게 보기.
- **프롬프트 도크(Ctrl+K)** 가 반복마다 열렸다 닫히던 것 · **캔버스 Tab(노드 선택기)** 이 반복마다 열렸다 닫히던 것.
- **캔버스 Ctrl+V 를 길게 누르면 붙여넣기가 반복되던 것**: 반복은 브라우저의 붙여넣기만 막는다.
- **내 계정 창의 Enter**: 반복과 처리 중의 재입력으로 비밀번호 변경 요청이 겹쳐 나가, 성공해 칸이 비워진 뒤의 Enter 가 "현재 비밀번호를 입력하세요"로 성공 안내를 덮었다.
- **프로젝트 줄의 Enter·Space**: 고르기가 토글이라 반복마다 지정·해제가 뒤집혔다.
- ★ **히스토리 키(h)**: 응답이 늦는 동안 반복마다 요청이 나가고, 응답마다 가계 씬 탭이 하나씩 새로 생겼다.
- ★ **프로젝트 줄의 Space 에 목록이 스크롤되던 것** — 막으면서 드러난 것 하나: 줄 안의 접기 단추에서 Enter 를 누르면 접히면서 프로젝트 고르기까지 뒤집혔다
  (click 은 줄로 안 올라가게 막혀 있었지만 keydown 은 올라왔다). 줄은 자신이 받은 키만 본다.
- ★ **캔버스 Tab 의 표식이 남던 것**(고치면서 만든 것): 첫 누름을 캔버스가 썼다는 표식이 다음 Tab 누름까지 남아, 선택기를 닫고 입력 칸에서 Tab 을 길게 누르면
  초점 이동이 한 칸 가고 멎었다. 표식을 '아무 키의 새 누름'에 지우게 했더니 이번엔 Tab 을 누른 채 Shift 만 눌러도 지워졌다 → 새 Tab 누름·Tab keyup·blur 에만.
- ★ (편집 탭) **Alt+M(북마크 지우기)**: 재생 중에 길게 누르면 재생헤드가 지나가는 북마크가 줄줄이 지워졌다.
- (편집 탭) 재생/정지·구간 반복·비활성(D)이 반복마다 뒤집히고, 재생 중의 I·O·M 은 지나가는 프레임마다 찍히며, L·J 는 배속이 순식간에 끝까지 오르던 것.

### 12회차 — 응답 전에 한 번 더 누른 것, 그리고 뗀 것을 놓친 표식

11회차의 '내 계정 창'(처리 중 재입력)이 한 부류의 머리였다. Codex 에게 두 모양을 전수로 찾게 했다 — ① 처리 중임을 막지 않는 비동기 핸들러 ② keydown·mousedown 에
켜고 keyup·mouseup 에 끄는데 blur·숨김·사라짐에는 안 꺼지는 상태. 일곱 건 + 후보 셋이 나왔고, 전부 코드로 읽어 맞다고 확인한 뒤 고쳤다(규칙 39).

- **재생성(↻)을 응답 전에 한 번 더 누르면 유료 생성이 둘 나가던 것**: 누름마다 요청 키를 새로 만들어 서버의 중복 제거가 합치지 못했다. 목록·계보 보드·
  '생성 결과' 창·캔버스가 같은 길이다. 캔버스는 누름마다 pending 연결도 하나씩 만들었다.
- **히스토리 열기(h·단추)를 조회 중에 다시 누르면 같은 씬 탭이 여러 개 생기던 것**(11회차는 '길게 누름'만 막았다 — 따로 두 번 누른 것은 지나갔다).
- **역할을 연달아 주면 먼저 준 역할이 사라지던 것** — 두 곳. 관리자 창의 전역 역할은 저장 중인 멤버만 잠가서, 다른 멤버를 누르면 잠금이 옮겨 가고 앞 멤버가
  풀렸다(그때 누른 것은 낡은 목록에 그것만 더해 보냈다). 프로젝트 멤버 칸의 역할은 잠금이 아예 없었다. 처음에는 잠금을 넓혀 막으려 했으나 코드 리뷰가 새는 길을

  바꿨다. 같이 닫힌 것: 그사이 프로젝트에서 빠진 멤버를 낡은 역할 칩이 되살리던 것 · '+ 추가'가 그사이 다른 곳에서 먼저 넣고 역할을 고친 멤버를 기본 역할로 덮던 것.

### 13회차 — 늦게 온 조회 응답이 지금 화면을 덮을 때

12회차의 Comfy("늦게 끝난 앞 것이 나중 것을 덮는다")와 같은 모양을 **조회** 쪽에서 Codex 에게 전수로 찾게 했다 — `await 조회` 뒤에 화면에 넣으면서 그사이

  고치거나 지우면 앞 프로젝트의 코멘트 id 로 요청이 나간다. 읽다가 하나 더: **프로젝트를 바꿔도 코멘트 패널이 열린 채 남아**, 거기에 쓴 새 코멘트가

### 편집 탭(`feature/edit-tab`)
- **계정을 바꾸면 편집 문서가 지워지던 것**(개인 설정 정리가 `ch.editTimeline:` 까지 지움 — 로컬에만 있고 백업이 없다). 문서·보관본·마지막으로 연 시퀀스는 남긴다.
- 편집 키가 규칙 1 을 본다(풀·뷰어 메뉴가 뜬 채 Delete·Space 가 뒤에 먹음). 입력칸에 초점이 남은 채 타임라인을 누르면 키를 돌려받는다. 숨긴 뷰어의 메뉴는 닫는다.
- 상단바 단추에 초점이 남은 채의 편집 키: 관리자 창·알림·계정 메뉴를 Esc 로 닫으면 ←·→·L 이 안 먹고 Space 가 방금 닫은 창을 다시 열었다 → 상단바 단추의
  초점은 '다른 창'이 아니다(규칙 3 과 같게), 마우스로 눌러 남은 초점이면 Space 는 재생(규칙 8).
- 7회차: **실제 길이가 문서의 길이보다 짧은 영상에서 재생이 실제 끝 뒤를 끝없이 탐색하던 것**(실측 2.5초에 탐색 약 26,000번 — 화면은 멈춘 듯 보인다) →
  탐색 자리의 상한을 영상의 실제 길이로 두고, 끝에 선 영상은 아래 것으로 넘긴다. 그러면 **틀 것이 하나도 없는 구간의 반복**이 남는데, 그 '빈 바퀴'는
  돌아간 자리에서 멈춘다 — 판정은 처음부터 끝까지 돈 바퀴에만, 세는 시간은 걸음이 지난 구간에서(정본 `docs/EDIT_TAB.md` §6. Codex 리뷰 8회).
  그 밖에: 숨은 탭에서 따라가는 영상이 안 멈추던 것 · 멈춘 뒤 남던 배속 글자 · 북마크 색·목록 단추가 다시 눌러도 안 닫히던 것 · 우클릭 메뉴가 누른 자리를
  덮어 떼는 순간 첫 항목이 눌릴 수 있던 것(2px 띄우고, 자리가 없으면 위·왼쪽으로) · 영상을 넘기는 프레임의 깜빡임.

### 5-2. 수용한 제한 — 고칠 수는 있지만 얻는 것보다 거는 것이 크다

| 항목 | 왜 |
|---|---|
| 전부 고른 끌기의 첫 걸음은 약 0.1초 (R2) | 시작·끝의 스타일 재계산(40~55ms)은 규칙 22 로 없앴다. 남은 것은 첫 걸음에 층을 만드는 비용인데, 표시(`data-layer-move`)를 **늘 켜 두면** 약 4ms 가 된다. 헤드리스 실측으로는 늘 켜도 쉬는 비용이 없었지만(가만히 둔 10초에 프레임 0 — 값이 변하는 대조는 600) **실제 창에서는 재지 못했고**, '끝없는 애니메이션 금지'(쉬는 화면의 CPU — `tests/idleCssAnimations.test.ts`)와 부딪힌다 — 넣지 않았다 |
| 작업표 설명 칸에 '저장 안 됨' 표시가 붙으면 창 1000px 에서 가로 넘침이 37px 는다 (R3) | 줄바꿈을 허용해 봤으나 표시가 "저장 안 / 됨" 두 줄로 깨졌다(그림으로 확인 — 되돌림, `composition-manage.css` 주석). 실패했을 때만, 좁은 창에서만 |
| 편집 탭: 판정하지 않는 빈 바퀴(뒤에서 시작·도중에 자리 옮김·범위가 달라짐)는 한 바퀴 더 돌고 멈춘다 | 멀쩡한 반복을 멈추는 쪽이 더 나쁘다 — 판정은 '온전한 바퀴'에만(`docs/EDIT_TAB.md` §6) |
| 편집 탭: 틀 것 없는 구간의 반복이 멈추는 순간 빈 무대가 한 프레임 스친다(실측 5/6) · 다이나믹 트림 반복 중 '비활성 숨기기'를 켜면 전체 반복이 된다 | 앞의 것은 틀 것이 없는 구간에서만, 한 프레임 — 그 뒤는 영상이 보인다. 뒤의 것은 그 편집점이 배치에서 사라져서다(전과 같음) |

| 폴더 창이 뜬 채 연 태그 패널은 길면 프롬프트를 덮을 수 있다 | 패널을 body 로 올린 결과(규칙 27 — 코멘트 패널 앞으로 오게). 밖을 누르면 닫힌다 |
| 계보 보드 검색칸의 Esc 는 아무 일도 하지 않는다 | 닫을 겹이 없는 입력칸이다(글은 남는다) — 전부터 |
| 영상 조작부에서 Esc·방향키가 앱에 오지 않는 경우가 셋 남는다 — ① Tab 으로 조작부 안에 들어가 있는 동안 ② Tab 을 누른 뒤 마우스로 조작부를 누른 경우 ③ 매체 이벤트가 하나도 안 나는 누름(0초에 멈춘 영상의 시간 줄 맨 앞처럼 값이 안 바뀌는 누름, 영상을 아직 하나도 못 받아 탐색이 안 일어나는 누름) | 크롬이 조작부 안의 키·누름을 페이지로 보내지 않는다(규칙 29 — 전부터 있던 것). '조작부를 썼다'는 것은 매체 이벤트로만 알 수 있어, 이벤트가 안 나는 누름은 알 길이 없고 키보드로 쓰는 중에는 초점을 빼면 안 된다. 재생 단추·시간 줄·음량·음소거를 마우스로 만진 보통의 경우는 고쳤다. 영상을 한 번 누르거나 Tab 으로 조작부를 벗어나면 풀린다 |
| 크게 보기에서 조작부 끝 칸의 Tab 은 BODY 로 한 칸 떨어졌다가 다음 Tab 에 창 안으로 돌아온다 | 그 Tab 이 페이지에 오지 않아 되돌릴 수 없다(규칙 29). BODY 에서도 Esc 는 듣고, 뒤 화면으로 새지는 않는다 |
| (8회차) 보드가 포인터를 쥔 뒤(4px 넘게 끈 뒤)에 mouseup 을 놓친 끌기에서, 마우스를 **한 번도 움직이지 않고** 다시 누르면 그 누름은 카드가 아니라 보드로 가 범위 선택이 된다(실측 15/15) | 포인터 캡처가 새 누름의 대상을 보드로 돌린다. 앞 끌기는 그 누름에 제대로 끝난다(규칙 33 — 유실 없음). 마우스가 한 번이라도 움직이면 규칙 21 이 먼저 끝내므로 손으로는 닿기 어렵다. 카드로 다시 보내려면 대상 판정을 따로 지어야 한다 |
| (8회차) 끄던 창·보드가 끄는 중에 사라지면(Esc 로 닫음) window 에 걸린 끌기 리스너가 남는다 — 정보 창·크게 보기·Assets·계보 보드의 노드 끌기 | 남은 리스너는 사라진 화면의 state 만 건드려 아무 일도 하지 않고, 다음 '단추 없는 움직임'·mouseup 에서 스스로 떼어진다(규칙 21 의 도우미 — 코드로 확인, Codex 동의). 저장으로 이어지던 하나(계보 보드의 화면 밀기 → 카메라 저장)는 9회차에 고쳤다 |

### 5-3. 별도 설계가 필요하다 — 조작 규칙이나 구조를 바꾸는 일

| 항목 | 왜 |
|---|---|
| 화면에 다 맞춘 큰 씬(배율 25% 아래)의 부분 끌기 (R1 의 남은 부분) | 고른 카드 40장 이상의 끌기는 배율 30% 이상에서 1.1~1.5배가 됐다(규칙 30 — `3de5de9b`). **그 아래 배율은 그대로다**: 412장 씬을 화면에 다 맞추면 배율이 8% 라, 158장을 끌 때 초당 12(걸음 80ms = 합성 갱신 32 + React 18 + 그리기 22). 빠른 길을 그 배율에서 켜면 초당 18 이 되지만 **끄는 카드와 그 뒤 차례의 이웃 카드가 끄는 동안 흐려진다**(끄는 카드 안의 픽셀 53~70% 가 달라짐 — 캔버스의 `will-change: transform` 아래에서 새로 층이 된 카드가 다른 배율로 래스터된다. 문턱은 줌 0.232 와 0.255 사이). 그 귀띔을 끄는 동안만 떼면 화면 전체의 결이 바뀌고 판 밀기가 53 → 14 가 되고, 늘 떼면 평소 화면의 27~51% 가 달라진다 — 셋 다 재 보고 버렸다. 연결선이 따라오는 비용도 남는다(브라우저 쪽 한계가 맞춤 28~30 — 런타임 실험). 이 배율의 큰 묶음 끌기를 매끄럽게 하려면 캔버스를 그리는 방식(층 구성)부터 다시 봐야 한다 — 고르지 않은 카드·그룹 머리·40장 미만의 끌기도 같은 까닭으로 전의 길이다(쌓임이 달라지거나 이득이 없다) |
| 끄는 사이 **다른 창**이 같은 카드의 자리를 바꾸면 되돌리기가 그 변경까지 끌기 전으로 감는다 (R31) · (9회차) 카드·그룹 머리를 **누르기만 한 뒤** 밖에서 그 카드의 자리가 바뀌면, 그 뒤의 첫 걸음은 누른 순간의 자리에서 잰다(밖에서 옮긴 자리가 아니다 — 크기 손잡이는 받은 크기에서 잰다) · (9회차) 끄는 중에 저장이 한 번 낀 끌기(화면 맞춤 F 등) 뒤에 밖 갱신이 오고 놓으면, Ctrl+Z 가 그 **밖 갱신의 내용까지** 끌기 전으로 되돌린다 | 좌표만 고치면 더 위험하다 — 변경의 출처·충돌·되돌리기 정책이 먼저다(Codex). 가운데 것은 누른 순간에 잡는 것(시작 자리·같이 갈 그룹·재배정의 기준 틀·판 밀기 여부)을 통째로 다시 잡아야 해서 같은 설계에 묶는다(같은 좌표를 두 곳에서 동시에 고칠 때만 — Codex P3). 뒤의 것은 스냅샷으로 되돌리는 방식의 일반 성질이다(끌기가 아니어도 편집 → 밖 갱신 → Ctrl+Z 두 번이면 같다. 생성 결과의 소속만 따로 살린다). 끌기 묶음의 기록을 밖 갱신 때 다시 만들면 끄는 중 지운 카드를 되돌리기가 못 살린다 — 3자 병합이 필요하다(Codex 동의). 끄는 중에 저장이 끼지 않은 보통 끌기는 Ctrl+Z 가 끌기만 되돌리고 밖 갱신은 남는다(시험) |

    - 캔버스·계보 보드에서 S 를 두 카드에 연달아 누르면 **나중 카드의 확인**이 뜬다(전: 앞 카드의 확인이 뜨고 뒤 카드는 무시).
    - 검색어 끝에 친 빈칸이 0.3초 뒤 사라지지 않는다 · 켜진 탭을 다시 누르거나 Resolve 따라가기가 오면 치던 검색어(아직 적용 전)는 버려진다.
19. **11회차에 달라진 동작**(싫으면 아래 7 의 11회차 커밋을 되돌린다):
    - **키를 길게 눌러도 한 번만 된다** — 색(r·g·b)·비활성(d)·Space 고르기·재생/정지·Ctrl+K·캔버스 Tab·히스토리(h)·Ctrl+V, 편집 탭의 Space·D·I·O·M·L·J·Alt+M.
      전에는 누르고 있는 동안 계속 뒤집히거나 다시 실행됐다. 방향키·되돌리기·확대/축소·프레임 이동은 전처럼 누르고 있으면 계속 간다.
      **L·J 를 누르고 있어도 배속이 오르지 않는다** — 배속을 올리려면 한 번씩 다시 누른다. 길게 눌러 올리는 쪽이 좋으면 알려 달라.
    - 사이드바 프로젝트 줄의 접기 단추(▸)에 초점을 두고 Enter 를 누르면 **접기만** 된다(전: 접히면서 그 프로젝트가 골라지거나 풀렸다).
20. **12회차에 달라진 동작**(싫으면 아래 7 의 12회차 커밋을 되돌린다):
    - **재생성(↻)을 빠르게 두 번 누르면 한 번만 나간다** — "재생성 처리 중입니다 — 완료 후 다시 누르세요."라고 알린다. '큐에 등록했습니다'가 뜬 뒤에 다시 누르면 전처럼 하나 더 나간다.
      일부러 연타해 여러 장을 뽑던 쓰임이 있었다면, 안내가 뜬 뒤에 누르거나 알려 달라 — 연타를 그대로 받게 되돌릴 수 있다(그러면 더블클릭 실수도 두 장이다).
    - 히스토리(h)를 조회 중에 다시 눌러도 씬 탭은 하나만 열린다 · 받는 중인 파일의 다운로드를 다시 누르면 "이미 받는 중입니다" · 일괄 다운로드가 도는 중에는
      다른 일괄을 받지 않는다("다운로드가 진행 중입니다") · Assets 에 올리는 중인 같은 파일을 다시 놓으면 "이미 가져오는 중인 파일입니다".
    - 관리자 창: 역할 하나를 저장하는 동안(서버 응답이 올 때까지) **모든 멤버의 역할 칩이 잠긴다**(전: 누른 멤버만). 프로젝트 멤버 칸도 저장 중에는 역할 칩·✕·+ 추가가 잠긴다.
      역할을 누르면 **저장 전에 목록을 한 번 더 읽는다**(요청이 하나 는다) — 그사이 다른 곳에서 바뀐 역할은 그대로 두고 누른 것만 바꾼다.
      그사이 프로젝트에서 빠진 멤버의 역할 칩을 누르면 저장하지 않고 "이미 프로젝트에서 빠진 멤버입니다. 다시 넣으려면 '+ 추가'를 쓰세요."라고 알린다
      (전: 그 멤버가 다시 들어왔다). '+ 추가'는 그사이 이미 들어와 있는 멤버를 건너뛴다(전: 기본 역할로 덮었다).
      공유 서버 이름·주소는 저장 중에 칸이 잠기고 단추가 "저장 중…"이 된다.
    - Comfy 카드·창에 워크플로를 잇달아 넣으면 **나중에 넣은 것**이 남는다(전: 늦게 끝난 쪽). 창에 잘못된 파일을 놓아도 앞 워크플로의 파라미터 설정이 그대로다.
      창에 .json 을 놓을 때 뜨던 "씬 불러오기 실패" 류의 안내가 더는 뜨지 않는다.
    - Assets 오디오 타일에 마우스를 올린 채 다른 창으로 가면 소리가 멈춘다. 돌아와서 마우스를 움직이면 다시 난다.
21. **13회차에 달라진 동작**(싫으면 아래 7 의 13회차 커밋을 되돌린다):
    - Assets 에서 **프로젝트를 바꾸면 열려 있던 코멘트 패널이 닫힌다**(전: 앞 프로젝트 파일의 코멘트가 보이는 채로 남았다).
    - 히스토리(h)를 두 카드에 잇달아 열면 **누른 순서대로** 열린다 — 둘째는 첫째의 조회가 끝난 뒤에 열린다(전: 응답이 온 순서대로).
    - 폴더 등록 창: 등록·해제 뒤 목록을 지금 팀으로 다시 읽는다(요청이 하나 는다 — 다른 팀의 프로젝트 폴더가 섞여 보이지 않는다).
    - 그 밖은 손에 닿는 변화가 없다 — 빠르게 바꿀 때 옛 것이 뒤늦게 덮어쓰던 것이 사라진다.
