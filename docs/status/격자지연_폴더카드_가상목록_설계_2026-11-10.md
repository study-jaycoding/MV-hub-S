## 왜 (실측 근거)

- 폴더 300개짜리 폴더로 들어갈 때(어셋 창 안 두 번 누름, 4배 CPU) 가장 긴 프레임 652~1,600ms 의 거의 전부가 **두 번 누름 처리 안의 스크립트** — React 가 카드 300장(요소 약 6,400·그림 1,200)을 만드는 시간(1,433~1,531ms). 화면 밖 건너뛰기(`4ef081e9`)는 레이아웃·강제 레이아웃만 줄였다(192→64ms · 228→77ms).
- 가상 목록은 **화면에 들 줄(과 앞뒤 여유)만 만든다** — 1680×1000 창·크기 1 에서 한 줄 4장 × 약 5줄 = 20장 안팎(추정). 만드는 카드 수가 약 15분의 1이라 들어갈 때 스크립트도 그만큼 줄 것으로 본다(추정 — 구현 뒤 같은 장면으로 잰다).
- 같은 창의 파일 격자(`AssetsView` 의 Virtualizer)와 워크스페이스 격자(`ThumbnailGrid`)가 이미 virtua 로 같은 일을 한다 — 새 의존성 없음.

## 범위

- 바꾼다: `AssetFolderGrid` 의 **그리드·목록 보기**(카드 `<article>`).
- 안 바꾼다: 표 보기 `AssetFolderTable`(줄이 가볍고 `<table>` 구조 — 따로 잴 일), 공유·워크스페이스의 컷 카드 격자 `FolderCardGrid`(폴더 수가 적었다 — 범위 밖), 카드 하나의 모양·버튼·동작.
- 걷어낸다: `4ef081e9` 의 화면 밖 건너뛰기 — `assets.css` 의 `content-visibility` 두 줄과 `AssetFolderGrid` 의 `--folder-card-h` 재기(가상 목록이면 화면 밖 카드가 아예 없어 필요 없다). 몇 줄짜리라 같은 변경에서 지운다.

## 설계

### 줄 모델

- 항목 = 지금의 `items`(하위 폴더 카드 다음 직접 파일 카드) 그대로.
- 열 수: 그리드 = `computeGridColumns(격자, round(EPISODE_CARD_WIDTH × scale), 12)` — 지금 CSS `repeat(auto-fill, minmax(min(100%, W×scale), 1fr))` 와 같은 공식(`lib/gridVirtualRows`, 파일 격자가 쓰는 것). 격자 폭이 바뀌면 ResizeObserver 로 다시. 목록 = 1.
- 줄 = 항목을 열 수만큼 끊은 배열. 경로 → 줄 번호 표(`rowOfPath`)를 같이 만든다(키·되돌아오기용).

### 그리기

- 스크롤 상자는 지금과 같은 요소(`scrollRef`·`onScroll` 그대로 — 스크롤 저장·복원·`useLooseKeys` 가 이 요소에 붙어 있다). 클래스에 `assets-folder-virtual` 를 더해 새 CSS 범위를 묶는다(표 보기도 `.assets-folder-grid` 를 쓰므로).
- 안: 위 여백 → `<Virtualizer scrollRef data={rows} itemSize={추정} bufferSize={400}>` → 아래 여백. 줄마다 `<div className="assets-folder-row" style={{ gridTemplateColumns: repeat(열, minmax(0, 1fr)) }}>` 안에 지금의 카드 그대로.
- CSS(`.assets-folder-grid.assets-folder-virtual` 로만 — 표 보기로 새지 않게): 상자 `display: block; padding: 0 22px; overflow-anchor: none`(격자 스크롤 고침 때처럼 바닥 여백이 스크롤 기준점이 되지 않게). 줄 `display: grid; gap: 12px; padding-bottom: 12px; align-items: start`(줄 사이 간격은 margin 이 아니라 padding — virtua 는 margin 을 줄 높이로 재지 않는다). 위 여백 22px = 위 여백 상자와 `startMargin`. 아래는 마지막 줄의 12px 가 이미 있으므로 아래 여백 상자를 10px 로 해 지금의 22px 과 맞춘다(1차 P3). 카드에 걸린 기존 선택자(`.assets-folder-grid.list .assets-folder-card` 등)는 자손 선택자라 그대로 맞는다(Codex 확인).
- `itemSize`(아직 재지 않은 줄의 높이 짐작): 없으면 virtua 가 작게 짐작해 처음에 줄을 훨씬 많이 만들었다 지운다(ThumbnailGrid 주석 — 약 80ms). 이 창에서 마지막으로 잰 줄 높이를 보기·크기·맞춤별로 모듈에 기억해 쓰고, 처음엔 열 폭으로 셈한 값(표지 16:9 + 띠 + 테두리 + 줄 간격)을 쓴다. 잰 줄은 잰 높이를 쓴다.

### 키·초점 (지금 동작 유지) — v2(Codex 1차 P1·P2 반영)

- 위·아래 걸음 = `columnsOf(격자)`(DOM 의 offsetTop) 대신 위 열 수.
- **출발 카드** = 기다리는 초점 목표(`pendingFocus`) → 실제 초점이 놓인 카드 → 고른 것 순. 화면 밖 카드로 가는 동안 다시 누르거나 Enter 를 눌러도 옛 카드가 아니라 최신 목표에서 출발·열기한다(1차 P1 반례: A 에 초점이 남은 채 B 로 가는 중 Enter 가 A 를 열었다).
- 옮길 카드가 그려져 있으면 지금처럼 초점 + `scrollIntoView({ block: "nearest" })`. 아니면 `pendingFocus = 경로` 를 두고 `scrollToIndex(그 줄, { align: "nearest" })`.
- **초점 완료는 카드의 표지 단추 ref 콜백**에서 한다 — 그 경로의 단추가 붙는 순간 `focus({ preventScroll: true })` 하고 `pendingFocus` 를 비운다. virtua 는 자기 상태로 줄을 다시 그려 부모의 레이아웃 효과가 다시 돌지 않을 수 있으므로(1차 P1) 부모 효과에 기대지 않는다.
- **취소**: Esc · 카드·빈 곳 클릭 · 폴더(격자 key)·보기·크기 변경 · 언마운트 때 `pendingFocus` 를 비운다.
- **초점 줄은 남겨 둔다**: 격자의 `focusin`/`focusout` 으로 실제 초점이 놓인 카드 경로를 기억하고, 그 경로의 줄을 Virtualizer `keepMounted` 로 둔다(1차 P2 — 사라지면 초점이 BODY 로 떨어져 Esc 가 끊기고(`useLooseKeys` 는 Esc 를 받지 않는다 · `keyGate.ts:155`) Tab 으로 옮긴 초점의 출발점을 잃는다). 줄 번호는 렌더마다 경로에서 다시 셈해 열 수가 바뀌어도 맞는다. 고른 카드의 줄은 남기지 않는다(선택은 경로 상태라 다시 그려지면 표시된다).
- 고른 것·두 번 누름·미들클릭·미리보기·최근 본 표시는 카드 안 코드라 그대로.
- **빈 곳 클릭 선택 풀기**: 지금 `event.target === event.currentTarget`(격자 자신)인데 줄 상자가 생기면 카드 사이·줄 아래·마지막 줄 빈 칸을 눌러도 대상이 줄·virtua 상자다(1차 P2) → `!(target).closest(".assets-folder-card")` 로 바꾼다.

### 스크롤 복원과 Backspace 되돌아오기 — v2(Codex 1차 P1·P2 반영)

- 지금은 `AssetsView` 의 한 효과가 `el.scrollTop = 저장 픽셀` 로 복원한 **뒤** DOM 에서 돌아온 카드를 찾아 `scrollIntoView` 한다. 가상 목록에서는 ① 첫 렌더의 열 수가 1이라(열은 상태로 잰다) 경로 → 줄 번호가 틀리고 ② virtua 의 스크롤 상자 연결이 마이크로태스크로 늦으며 `nearest` 는 DOM 이 아니라 자기 위치를 본다(`virtua/index.js:286·555`) ③ 짐작 높이 하나로는 위쪽 줄 높이가 달라(띠 없는 폴더·직접 파일·폭) 같은 픽셀이 다른 카드를 가리킨다(1차 P2). 또 virtua 는 `itemSize` 를 처음 만들 때만 읽는다(`virtua/index.js:526`).
- 바꿈 — **폴더 격자가 자기 스크롤 복원과 되돌아오기를 맡는다**(표 보기·파일 격자는 지금 경로 그대로):
  - `AssetFolderGrid` 가 `handleRef` 로 `{ anchor(), restore(state), reveal(path) }` 를 내준다.
  - 저장: `AssetsView` 의 스크롤 저장(150ms 타이머)이 폴더 격자일 때 `{ key, top, anchor }` 를 적는다. `anchor` = 화면 맨 위에 걸친 첫 카드의 경로 + 그 줄 위끝에서 화면 위끝까지의 거리.
  - 복원: `AssetsView` 의 같은 자리에서 `el.scrollTop =` 대신 `handle.restore({ top, anchor })`, 이어서 돌아온 카드가 있으면 `handle.reveal(경로)`. 격자는 둘을 **요청으로 보관**하고, 열 수를 잰 뒤(측정 완료 표시) 다음 프레임에(virtua 연결 뒤) 실행한다 — `anchor` 경로가 목록에 있으면 그 줄로 `scrollToIndex(줄, { align: "start" })` + 거리만큼 보정, 없으면 `top` 픽셀. 그다음 `reveal` 은 그려져 있으면 `scrollIntoView({ block: "nearest" })`, 아니면 `scrollToIndex(줄, { align: "nearest" })`. 실행 전에 열 수가 바뀌면 경로에서 줄을 다시 센다. 실행하기 전에는 요청을 버리지 않는다(부모가 `backTo` 를 비워도 격자가 쥐고 있다).
  - `itemSize` 는 Virtualizer 를 만들 때만 읽히므로 Virtualizer 의 key 에 보기·크기·맞춤·열 수를 넣어, 바뀌면 새 짐작으로 다시 만든다(스크롤 상자는 바깥 요소라 위치는 남는다).

## v3 설계 — 카드는 그대로, 먼 카드의 썸네일만 가까워질 때 붙인다 (가상 목록 v1·v2 는 보류)

### v3.1 — Codex 3차(REVISE, 'v3 방향은 타당', P2 4개) 반영

- **카드별 켜짐 + 구독자 집합**: 관찰 등록부는 카드 요소마다 `{ 켜짐, 구독자들 }` 을 든다. 카드가 들어오면 켜짐 = 참, 구독자 모두에게 알리고 그 카드 관찰을 푼다. **이미 켜진 카드에 새로 붙는 `NearThumb`(검색·트리 갱신으로 띠 썸네일이 바뀜)는 즉시 보인다** — 교차 상태가 그대로면 새 알림이 오지 않기 때문(3차 P2). 썸네일 하나가 떨어질 때는 자기 구독만 빼고, 구독자가 0 이 된 카드만 관찰을 푼다.
- **문턱 경계**: 개수 = 지금 그리는 `groups.length + directFiles.length`. 문턱 이하가 되면 모든 `NearThumb` 를 켠다(49→48 의 빈 자리를 채운다). 다시 문턱을 넘어도 **같은 마운트에서 한 번 켜진 것은 끄지 않는다**(`NearThumb` 의 보임 상태는 참으로만 바뀐다 — `MediaThumbnail` 과 `NearThumb` 를 문턱으로 바꿔 끼우지 않으므로 48→49 에서 그림이 다시 붙지 않는다).
- **관찰자 준비·미지원·정리**: 등록부는 렌더 중에(효과가 아니라 ref 초기화로) 만들어 두어, 부모의 효과가 관찰자를 만들기 전에 자식이 등록해도 보관된다. 관찰자는 스크롤 상자가 생긴 뒤 만들고, 그때 보관된 카드를 모두 관찰한다. **미지원 판정은 `typeof IntersectionObserver === "undefined"` 로만** 하고(준비 전 `null` 을 미지원으로 보지 않는다 — 그러면 1,200개를 즉시 만든다), 미지원이면 등록 즉시 켠다. 스크롤 상자가 바뀌면(그리드 → 표 → 그리드, 보기 전환) 옛 관찰자를 `disconnect` 하고 새 상자로 다시 만들어 남은 등록을 다시 관찰한다. 언마운트 때 `disconnect`·등록부 비우기, 늦게 온 옛 관찰자 알림은 무시(세대 번호). React StrictMode 의 효과 두 번 실행에도 같은 결과.
- **모양·조작 보존**: 그림 크기·맞춤 CSS 는 단추의 **직계 자식** `img`/`video` 에 걸린다(`episode-board.css:19·38`) → `NearThumb` 는 보인 뒤 **감싸는 요소 없이 `MediaThumbnail` 그대로**를 돌려준다. 보이기 전 빈 자리도 같은 자리의 직계 자식 `span.assets-folder-placeholder` 하나. 표지·띠 칸의 크기는 단추의 비율(16:9·1:1)이 정하므로 바뀌기 전후 카드 높이가 같다. 미들클릭은 단추·`data-ep-action` 조상이 받고 그림은 `draggable={false}` 라 빈 자리·그림 어느 쪽을 눌러도 같다. 초점은 같은 단추 요소에 남는다.
