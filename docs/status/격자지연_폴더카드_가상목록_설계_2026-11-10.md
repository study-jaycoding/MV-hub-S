# 어셋 폴더 카드 격자 — 가상 목록 설계 (2026-11-10)

owner: Claude(설계) · reviewer: 미정(Jay 판단 — 바로 만들기 또는 Codex 설계 검토) · status: 설계 중 · touched_paths: 이 문서 · updated: 2026-11-10
위 속성의 `active`는 이 작업의 진행 기록이라는 문서 위상이며, 구현 완료·검토 완료·배포 승인을 뜻하지 않는다. 코드 변경 없음(구현은 Jay "만들어" 뒤).

## 요청

Jay(2026-11-10): [폴더 카드 화면 밖 건너뛰기](격자지연_폴더카드_2026-11-10.md) 뒤 "열 때 멈춤도 가상 목록으로 줄일까요?"에 "가상 목록 설계부터".

## 왜 (실측 근거)

- 폴더 300개짜리 폴더로 들어갈 때(어셋 창 안 두 번 누름, 4배 CPU) 가장 긴 프레임 652~1,600ms 의 거의 전부가 **두 번 누름 처리 안의 스크립트** — React 가 카드 300장(요소 약 6,400·그림 1,200)을 만드는 시간(1,433~1,531ms). 화면 밖 건너뛰기(`4ef081e9`)는 레이아웃·강제 레이아웃만 줄였다(192→64ms · 228→77ms).
- 가상 목록은 **화면에 들 줄(과 앞뒤 여유)만 만든다** — 1680×1000 창·크기 1 에서 한 줄 4장 × 약 5줄 = 20장 안팎(추정). 만드는 카드 수가 약 15분의 1이라 들어갈 때 스크립트도 그만큼 줄 것으로 본다(추정 — 구현 뒤 같은 장면으로 잰다).
- 같은 창의 파일 격자(`AssetsView` 의 Virtualizer)와 워크스페이스 격자(`ThumbnailGrid`)가 이미 virtua 로 같은 일을 한다 — 새 의존성 없음.

## 범위

- 바꾼다: `AssetFolderGrid` 의 **그리드·목록 보기**(카드 `<article>`).
- 안 바꾼다: 표 보기 `AssetFolderTable`(줄이 가볍고 `<table>` 구조 — 따로 잴 일), 공유·워크스페이스의 컷 카드 격자 `FolderCardGrid`(폴더 수가 적었다 — 범위 밖), 카드 하나의 모양·버튼·동작.
- 걷어낸다: `4ef081e9` 의 화면 밖 건너뛰기 — `assets.css` 의 `content-visibility` 두 줄과 `AssetFolderGrid` 의 `--folder-card-h` 재기(가상 목록이면 화면 밖 카드가 아예 없어 필요 없다). 몇 줄짜리라 같은 변경에서 지운다.

## 설계

### 줄 모델

- 항목 = 지금의 `items`(하위 폴더 카드 다음 직접 파일 카드) 그대로.
- 열 수: 그리드 = `computeGridColumns(격자, round(EPISODE_CARD_WIDTH × scale), 12)` — 지금 CSS `repeat(auto-fill, minmax(min(100%, W×scale), 1fr))` 와 같은 공식(`lib/gridVirtualRows`, 파일 격자가 쓰는 것). 격자 폭이 바뀌면 ResizeObserver 로 다시. 목록 = 1.
- 줄 = 항목을 열 수만큼 끊은 배열. 경로 → 줄 번호 표(`rowOfPath`)를 같이 만든다(키·되돌아오기용).

### 그리기

- 스크롤 상자는 지금과 같은 요소(`scrollRef`·`onScroll` 그대로 — 스크롤 저장·복원·`useLooseKeys` 가 이 요소에 붙어 있다). 클래스에 `assets-folder-virtual` 를 더해 새 CSS 범위를 묶는다(표 보기도 `.assets-folder-grid` 를 쓰므로).
- 안: 위 여백 → `<Virtualizer scrollRef data={rows} itemSize={추정} bufferSize={400}>` → 아래 여백. 줄마다 `<div className="assets-folder-row" style={{ gridTemplateColumns: repeat(열, minmax(0, 1fr)) }}>` 안에 지금의 카드 그대로.
- CSS: 상자 `display: block; padding: 0 22px; overflow-anchor: none`(격자 스크롤 고침 때처럼 바닥 여백이 스크롤 기준점이 되지 않게). 줄 `display: grid; gap: 12px; padding-bottom: 12px; align-items: start`(줄 사이 간격은 margin 이 아니라 padding — virtua 는 margin 을 줄 높이로 재지 않는다). 위 여백 22px 은 `startMargin` 과 맞춘다. 카드에 걸린 기존 선택자(`.assets-folder-grid.list .assets-folder-card` 등)는 자손 선택자라 그대로 맞는다.
- `itemSize`(아직 재지 않은 줄의 높이 짐작): 없으면 virtua 가 작게 짐작해 처음에 줄을 훨씬 많이 만들었다 지운다(ThumbnailGrid 주석 — 약 80ms). 이 창에서 마지막으로 잰 줄 높이를 보기·크기·맞춤별로 모듈에 기억해 쓰고, 처음엔 열 폭으로 셈한 값(표지 16:9 + 띠 + 테두리 + 줄 간격)을 쓴다. 잰 줄은 잰 높이를 쓴다.

### 키·초점 (지금 동작 유지)

- 위·아래 걸음 = `columnsOf(격자)`(DOM 의 offsetTop) 대신 위 열 수.
- 옮길 카드가 그려져 있으면 지금처럼 초점 + `scrollIntoView({ block: "nearest" })`. 그려져 있지 않으면(화면 밖) `scrollToIndex(그 줄, { align: "nearest" })` 하고 '초점 줄 카드'를 기억했다가, 그 카드가 그려진 렌더 뒤(레이아웃 효과)에 `focus({ preventScroll: true })`.
- 초점이 놓인 카드가 스크롤로 사라지면 초점은 BODY 로 떨어진다 — 키는 지금도 BODY 에서 받고(useLooseKeys) 출발 카드는 고른 것(`selected`)이라 이어진다.
- 고른 것·Enter·Esc·두 번 누름·미들클릭·미리보기·최근 본 표시는 카드 안 코드라 그대로.

### Backspace 로 돌아온 카드 보이기

- 지금은 `AssetsView` 가 스크롤을 복원한 **뒤** DOM 에서 그 카드를 찾아 `scrollIntoView` 한다 — 화면 밖이면 카드가 없어 무효가 된다.
- 바꿈: `AssetFolderGrid` 가 `revealRef`(경로를 받아 보이게 하는 함수)를 채워 주고, `AssetsView` 는 같은 자리(복원 뒤)에서 그 함수를 부른다. 함수 = 카드가 그려져 있으면 `scrollIntoView({ block: "nearest" })`(지금과 같음), 아니면 `scrollToIndex(줄, { align: "nearest" })`. 순서(복원 → 보이기)는 그대로.

### 스크롤 복원

- `AssetsView` 의 복원(`el.scrollTop = 저장값`)은 그대로 둔다 — virtua 는 스크롤 이벤트를 따라간다. 화면 위쪽 줄은 아직 안 재서 짐작 높이로 자리를 잡으므로, 짐작이 실제와 다르면 같은 픽셀 위치가 다른 줄을 가리킬 수 있다. 폴더 카드는 한 보기 안에서 높이가 거의 같고 짐작을 마지막 잰 값으로 주므로 차이는 작다고 본다(추정 — 구현 뒤 '돌아와 같은 카드가 보이나'로 잰다). 워크스페이스 격자도 같은 방식이다.

## 시험·확인 계획

- 기존 `assetFolderTabs.test.tsx`(virtua 를 '전부 그리기'로 바꿔 둔 시험 — 방향키·Enter·Esc·Backspace 되돌아오기·미들클릭·정렬·목록 보기)가 그대로 통과해야 한다. Backspace 시험은 카드가 그려진 경우라 `scrollIntoView` 경로를 그대로 탄다.
- 새 시험: ① 줄 끊기·`rowOfPath`(열 1·3·4, 직접 파일 섞임) ② virtua 가짜가 앞 몇 줄만 그릴 때 — 화면 밖 카드로 방향키를 누르면 그 줄로 `scrollToIndex` 하고 그려진 뒤 초점이 간다 ③ 화면 밖 카드로 Backspace 되돌아오기 — `scrollToIndex` 로 보인다.
- 격리 실측(고정 사본·설치본 빌드·4배 CPU, 폴더 300개): 들어가기 3회의 가장 긴 프레임·스크립트 · 스크롤 60걸음 끊긴 프레임 · 만들어진 카드 수 · 첫 화면 카드 위치가 지금 빌드와 같은지 · 크기 1·1.6·목록 · 화면 밖 카드로 방향키 · 화면 밖 카드로 Backspace 되돌아오기 · 다른 폴더 다녀와 스크롤 복원.

## 완료 조건 (구현 때 계약으로 옮긴다)

- 프런트 빌드·경계 검사·관련 시험 통과.
- 폴더 300개 들어가기(4배 CPU 3회) 가장 긴 프레임 평균이 지금(652~1,600ms, 평균 약 1,000ms)의 3분의 1 이하, 스크롤 끊긴 프레임이 지금(37~74)보다 많지 않다.
- 첫 화면 카드 위치·크기가 지금 빌드와 같다(그리드 크기 1·1.6, 목록). 방향키·Backspace 로 화면 밖 카드에 가면 그 카드가 보이고 초점·선택이 간다. 스크롤 복원 후 보이던 카드가 같은 줄에 있다.

## 위험·열린 질문

- **스크롤 복원 오차**: 짐작 높이와 실제가 다르면 돌아왔을 때 줄이 조금 어긋날 수 있다(위 '스크롤 복원'). 실측으로 확인 — 크면 경로 기준 복원(보던 첫 카드 경로를 저장해 그 줄로 `scrollToIndex`)을 더한다.
- **찾기(Ctrl+F)**: 화면 밖 카드는 DOM 에 없어 브라우저 찾기에 안 걸린다(파일 격자·워크스페이스 격자와 같은 한계). 지금 폴더 카드에서 Ctrl+F 를 쓰는지 Jay 확인이 필요하면 묻는다.
- **카드 수가 적을 때**: 몇 장뿐이면 이득이 없고 줄 상자만 하나 더 생긴다 — 동작·모양이 같은지 시험으로만 본다.
- 표 보기는 범위 밖이라, 폴더가 많은 폴더를 표로 보면 여전히 전부 만든다(따로 잴 일).
