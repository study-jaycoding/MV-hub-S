# 로컬 허브 중계 인증의 계정 자동 연결 보호

owner·touched_paths: 아래 vibe-intent 참조 · reviewer: 별도 Claude Fable 5.2 독립 리뷰 통과(아래 근거) · status: 완료(dev 코드·격리 검증, 실사용 반영 별도) · updated: 2026-11-13

[진행 인계](Codex인계_진행중작업_2026-11-12.md)의 다른 계정 로그인 문제다. [개발 실행기](로컬허브_개발실행기_2026-11-02.md)의 미해결 제품 동작만 다루며 그 실행기 전체 검증을 완료 처리하지 않는다. 사용자는 11-13 Claude와 Codex가 검토·합의해 작업을 선택하고 진행하도록 위임했다. dev 전용 커밋, 사용자 main 병합·push, 실사용 서버·DB·설치본 보호는 유지한다.

## 확인한 경로와 범위

- 별도 Codex `priority_db_design_review`(요청 GPT-6 Astra/high, 실제 모델 메타데이터 미확인)가 호출자와 수신자를 읽었고 총괄도 구현 관련 소스를 읽었다. `shared_server_login → _http_json → _proxy.raw_request → auth.login → _activate_local_agent`; 화면 `/auth/me → _proxy._forward → auth.me → _activate_local_agent`; 401 재확인 `_probe_token_state`와 MCP `_upstream_me`도 `raw_request`를 사용한다.
- 수신 측은 접속 IP가 loopback인지 확인하므로 같은 PC 허브의 중계와 직접 개발 화면 요청을 구분하지 못한다. `_activate_local_agent`는 `mcp_active_account` 설정과 로컬 에이전트 pair 계정을 바꿀 수 있다. 실제 계정 로그인·대기 작업 제출은 실행하지 않았다.
- Codex 추천 A안: 두 공통 송신 지점에서 중계 표식을 직접 붙이고, 수신 `_activate_local_agent`에서 자동 연결만 생략한다. 로그인 호출 한 곳만 고치거나 모든 자동 연결을 끄는 안은 각각 `/me` 누락·직접 개발 로그인 회귀가 있다.
- 전역 `bump_account_epoch()`는 로그인·가입 등에서 자동 연결 밖에서도 실행된다. 이번 최소안 뒤에도 중계 로그인으로 클린 피드/씬 lease 등 기존 세대값 검사가 영향을 받을 수 있다. 모든 화면/실행의 완전한 독립을 약속하지 않는다. 기존 무효화 정책은 별도 검토 없이 제거하지 않는다.
- 표식은 인증 증명이 아니다. 클라이언트가 같은 헤더를 직접 넣어도 자동 연결만 생략하며 권한·토큰·승인·pair 비밀키 검증을 우회하지 않아야 한다. 일반 허브 로그아웃은 `shared_server_logout`의 로컬 처리이며, 직접 `/auth/logout`의 기존 무효화 정책은 이 계약에서 바꾸지 않는다.

## 설계 확인·진행

- Claude `mvhub-design` 새 세션 `0cc280fd-79d3-4e81-ab32-d02f4c9452f3`, 요청 Fable/high, 실제 `claude-fable-5-2`가 두 차례 고정 원문을 검토해 계약 변경 없이 동의했다. 도구 없는 검토이며 총괄은 첫 호출 전후 5파일 SHA256 동일함을 확인했다. 역할은 지정됐고 ponytail 본문은 훅 주입으로 적용했다는 상대 보고다. 직접 파일/시험 실행으로 확대하지 않는다.
- 총괄은 `backend/app`의 `_activate_local_agent`·`local_agent_pair.activate`·`mcp_active_account` 쓰기를 검색했다. 자동 연결 밖 MCP 쓰기는 `issue_panel_client`·`/app/configure`의 명시적 설정이다. `/api/mcp/`는 허브 로컬 소유라 중계 인증이 그 쓰기에 닿지 않는다. Claude도 추가 발췌로 이 구분을 확인했다.
- `useHubAuth.ts`의 AUTH-off 로그아웃은 `hubLogout()` 뒤 반환하며 AUTH-on만 `api.logout()`을 사용한다. `dev_hub.py`는 에이전트를 띄우지 않아 이번에 없앨 8012 pair 자동연결에 의존하지 않는다. `_STREAM_PREFIX`는 `/api/manage/save-finals/content/`이며 미디어 분기는 `/media/`라 `/api/auth/me`가 스트리밍 중계로 빠지지 않는다.
- 원시 `_open`은 파일/미디어에도 쓰므로 합의한 두 공통 인증 송신 지점만 수정한다. 복원 검증 도구의 직접 임시 서버 로그인은 이번 허브 중계 경로가 아니다. graft 래퍼 `callers _activate_local_agent`의 후보를 실제 login/access/me 소스와 대조했고 총괄은 ponytail·ponytail-review를 적용한다.
- 구판 허브·구판 수신 중 하나라도 남으면 기존 문제가 남는다. 효과를 보려면 두 프로세스가 신판이어야 하며 직접 개발 로그인/상태 조회가 8012의 pair·MCP 계정을 선택한다. 자동 재시작은 하지 않는다. 개발 실행기의 옛 경고는 구판 조합에 유효하고 신판 두 프로세스에는 이번 기록의 조건을 적용한다.
- 시험 담당 `backend_failure_triage`는 계약의 시험 2파일만 소유하고 총괄은 제품 3파일을 소유한다. 먼저 제품 수정 전 재현 시험을 만들고 실패 근거를 확인한 뒤 제품을 수정한다. 실사용 데이터/서버/계정/CLI는 시험하지 않는다.

## 구현·검증 (11-13)

- 제품 3파일은 위 합의대로 공통 헤더 상수, 두 송신 지점의 표식 추가, 자동 연결의 조기 반환만 바꿨다. 로그인·토큰·쿠키·승인·전역 epoch·직접 로그아웃 코드는 유지한다. 시험 담당의 2파일 소유권은 종료 후 총괄로 회수했다.
- 수정 전 재현은 별도 Codex 실행 보고: **13실패·28통과, 10.05초, exit 1**. 중계 login/access/me와 첫 access의 자동 연결 4건, 실제 송신 표식 9건이 실패했다(명령 `482884`, 최종 출력 `9396b8`). 초기 시험 준비 중 잘못된 토큰의 password stamp로 발생한 401은 시험 준비 오류를 고친 뒤 위 수치에서 제외했다.

- 모든 시험은 공통 conftest가 실사용 환경변수를 제거한 임시 자료와 가짜/loopback HTTP를 사용했다. 직접 C 계정 전환, 정확하지 않은 표식, 비밀번호 오류·승인 대기·첫 자동 승인·쿠키 복원·pair 비밀키·직접 logout 및 기존 epoch도 확인했다. 실사용 계정·공유 서버·CLI·설치본에는 실행하지 않았다.
- 총괄 자기 검토는 실제 auth 호출자와 수신 helper, pair-token 발급, 중계 생성 요청 및 인증 거부 경계를 대조했다. `ponytail`·`ponytail-review` 본문 적용. graft `build/check`는 wiring in sync, `blast`는 작업 트리 대비 HEAD를 사용했다. 다른 세션 지침/문서 변경이 목록에 섞이고 자동 연결 시험 연결을 0/3으로 잡았으므로 실행 커버리지로 쓰지 않는다. 실제 호출 소스·위 HTTP 시험으로 보완했다. code-map 참조 1,223개 누락0/대상 코드 994개 미등재0, inventory check와 diff check 통과.

- 리뷰어는 역할의 시스템 주입, ponytail 훅 주입, 전달된 ponytail-review 본문 사용을 보고했다. 실제 추론 수준은 미확인이다. 도구로 직접 검색·시험·해시 계산·쓰기 차단 시험을 수행한 리뷰가 아니며 총괄이 제공 원문·대상 해시·시험 기록을 대조했다. `_proxy.py` 411–609의 파일 다운로드/바이트 helper 호출은 리뷰어가 원문 대신 인증 경로 검색으로 확인한 한계도 남긴다.
