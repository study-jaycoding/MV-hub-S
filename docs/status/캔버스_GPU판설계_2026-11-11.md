'줌 도중 내용 변화 0' 이 아니면 DOM 안에서 못 없앤다(그 길은 느린 PC 비용으로 기준 실패, Codex 도 지금대로 권함). Figma 는 판을 자체 엔진으로 GPU 에 직접 그린다(WebGL → WebGPU, [공식 블로그](https://www.figma.com/blog/figma-rendering-powered-by-webgpu/)).

## 목표와 완료 조건(초안)

- 줌·화면 이동(가운데 버튼)·카드 끌기·범위 선택 **도중** 33ms 넘는 프레임: 이 PC 0, CPU 4배 흉내도 지금 dev 이하(실제 씬 412장 + 2000장 합성 씬).
- 보이는 모습은 지금 카드와 같은 정보(정확한 픽셀 같음은 목표 아님 — 글자 그리기가 달라진다). 조작·단축키·되돌리기·저장은 그대로.
- GPU 가 안 되는 PC 는 지금 DOM 판으로 자동으로 돌아간다.

## 방식 — GPU 판 + 최소 DOM 덧판(초안)

1. **그리기는 WebGL 판 하나**(WebGPU 는 2단계 후보): 점 격자·그룹 틀·연결선(인스턴스 선)·카드 사각형(텍스처)·선택 테두리·포트(인스턴스 원). 카메라는 셰이더 행렬 하나라
   줌·이동이 DOM·스타일·칠하기·크롬 굽기를 전혀 건드리지 않는다 — 이것이 끊김을 없애는 핵심.
2. **카드 모습 = 카드별 텍스처**: 카드를 Canvas2D 로 그려(지난 [그림판 실험](캔버스_보드그림판_2026-11-10.md)의 `boardCanvasDraw` — 12종 중 5종은 이미 있음) 텍스처 아틀라스에 올린다.
   카드 내용이 바뀔 때만 그 카드를 다시 굽는다. 배율 단계 2~3개(멀리·중간·가까이)를 두고 보이는 카드만 메모리에 둔다.
3. **조작은 JS 판정**: 공간 색인(사각 나무)으로 카드·포트·선·그룹 머리를 찾아 끌기·범위 선택·연결·자르기·크기 조절을 상태만 바꿔 GPU 로 다시 그린다.
   — 그림판 실험이 진 이유('조작 시작마다 전부 DOM 으로 되돌림', 실측 +35~337%)를 피하는 자리. **조작 중에도 GPU 판이 그린다.**
4. **DOM 덧판은 최대 몇 장**: 마우스를 올린 카드(단추·썸네일 미리보기)·편집 중인 카드(글 입력)·Comfy 값 칸 같은 입력이 있는 카드만 그 자리에 DOM 으로 얹는다.
   팝업·메뉴·창은 지금 그대로(이미 덧판).
5. **되돌아가기 장치**: 표식 하나로 DOM 판(지금)과 GPU 판을 바꾼다. WebGL 실패·GPU 블록리스트·카드 종류 미지원이면 DOM 판.

지키는 재제안 금지: 판 한 장 Canvas2D 그림판(조작 시작 비용 해법 없이) · 카드마다 canvas(층 폭증) · 멀리 볼 때 줄인 몸통(Jay 접음) — 이 설계는 셋 다 아니다(조작 중에도 GPU 판, 캔버스 하나, 모습은 지금 카드와 같은 정보).

## 위험

- **글자**: Canvas2D 글자는 DOM 과 줄바꿈·자간·한글 조합이 다르다 — 줄바꿈을 직접 구현해야 한다. 정확한 같음은 포기하고 '같은 정보'로 대조한다.
- **기능 동등**: 카드 12종의 상태 표시(생성 중·실패·서버에 없음·방금 생성 빛·폴더 이름표·결과 수 …)를 모두 다시 그려야 한다. 빠지면 조용히 정보가 사라진다 — 종류별 대조표가 관문.
- **시험**: 카드 DOM(`.scene-card`)을 찾는 시험이 37개 파일·150곳이다. GPU 판에선 카드가 DOM 이 아니므로 시험이 판정 함수·상태를 보도록 바뀌어야 한다(두 판을 다 돌리는 동안은 DOM 판 시험 유지).
- **접근성**: WebGL 판은 화면 낭독기가 못 읽는다 — 숨은 목록이나 DOM 판 되돌아가기가 필요하다.
- **메모리**: 카드 텍스처(예: 300×200 × 배율 단계 × 4바이트)가 카드 수에 비례 — 보이는 카드만 두는 관리가 필요하다.
- **두 판 유지비**: 되돌아가기를 남기는 동안 카드 모습을 두 곳에서 고쳐야 한다.
- **팀원 PC**: GPU 가 약하거나 블록리스트면 DOM 판 — 그 PC 는 지금 수준.

## 1단계 계약(2차안 — Codex 지적 반영)

- **범위 = 보기 모드**: GPU 판은 줌·화면 이동·마우스 올린 카드 읽기(덧판)만 한다. 편집·생성·삭제·끌기·연결·자르기·범위 선택과 그 단축키는 GPU 모드에서 막고,
  한 단추·한 단축키로 지금 DOM 판(편집 모드)으로 돌아가 한다. 모드 안내를 보이고, 돌아갈 때 카메라·선택·초점을 그대로 넘긴다. 조작을 GPU 로 옮기는 것은 2단계.
- **상태 출처**: 씬·카메라·선택·되돌리기·저장은 지금 그대로(SceneBoard·세션)가 원본이다. GPU 판은 그 값을 읽기만 하는 표시 계층이다. 모드를 바꿔도 저장·되돌리기·씬 수신을 다시 시작하지 않는다.
  GPU 모드의 덧판에는 변경 콜백을 넘기지 않는다(읽기 전용 속성으로 그린다) — 시험으로 막는다.
- **카드 그림 다시 굽기**: 카드의 표시 내용(글·제목·참조 목록·결과·상태·서버 보유 표시·폴더 이름표·연결 표시)·크기·썸네일 도착/어셋 버전·글꼴/테마가 바뀔 때만 그 카드를 굽는다.
  위치·카메라·선택 테두리·마우스 올림은 굽기와 떼어 셰이더 값으로. 배율 단계 교체는 프레임마다 나눠 하고 새 그림이 준비될 때까지 옛 그림을 그린다. 씬마다 세대 번호를 두어 늦게 온 이미지 결과는 버린다.
- **크기·좌표·판정**: 카드 크기는 DOM 모드가 잰 높이(지금 heightsRef)를 쓰고, 한 번도 재지 않은 자동 높이 카드는 GPU 모드에 들어가기 전에 나눠 잰다(전체를 한 번에 붙이지 않는다).
  그림·덧판·판정은 같은 최신 카메라·같은 카드 크기·같은 겹침 순서를 쓴다(화면 좌표와 기기 배율을 구분, 숨김·접힘 반영).
- **덧판**: 최대 1장(마우스 아래 맨 앞 카드). 덧판 DOM 이 준비된 프레임에 그 카드의 GPU 그림을 감춘다(같은 프레임 교체). 그 카드보다 앞에 있는 GPU 카드와 겹치면 덧판을 띄우지 않는다.
  덧판 위의 첫 클릭·휠이 사라지지 않게, 덧판이 뜨기 전 입력은 GPU 판정이 받아 같은 일을 한다(읽기 동작만).
- **전환·실패**: 개발 표식 기본 끔. 켜면 텍스처 준비가 끝난 뒤 바꾼다. 입력 중에는 전환을 미룬다. 미지원 카드 종류가 보이는 씬이면 들어가지 않는다(1단계 지원 = 레퍼런스·리스트·글·모델·생성 + 제목).
  WebGL 컨텍스트 상실·생성 실패·메모리 초과면 DOM 판으로 돌아가고 그 세션에서는 다시 들어가지 않는다(오가기 반복 금지).
- **메모리 상한**: 텍스처 합계(아틀라스 빈칸·밉맵·교체 중 옛/새 그림 포함) **128MB** 이하. 넘으면 ① 화면 밖 카드의 큰 배율 그림부터 버리고 ② 맞춤 같은 낮은 배율은 카드를 1/4 해상도로 굽는다
  (2,000장 × 약 75×55px). 다시 보이면 낮은 해상도부터 다시 굽는다. CPU 쪽 그리기용 이미지는 굽고 나면 놓는다.
- **완료 조건(Codex 제안 채택)**: 고정 빌드·격리 사본에서 ① 5종 + 제목의 실제 썸네일·상태·자동 높이·겹침·덧판을 DOM 판과 대조, 보기 모드 조작으로 씬 데이터·되돌리기 기록이 바뀌지 않음
  ② 412장·2,000장, 같은 카메라로 데운 뒤 번갈아 5쌍: 줌·이동 중 33ms 초과 이 PC 매회 0, CPU 4배 흉내는 미리 정한 집계로 DOM 판 이하 ③ 첫 진입·빠른 마우스 올림 왕복·배율 단계 경계·이미지 도착·입력 끝난 뒤 1초를
  따로 재고 최대 프레임을 공개(멈춤을 준비·종료 구간으로 옮긴 결과를 걸러냄) ④ 메모리 최고점이 상한 이내이고 씬·모드 반복 전환 뒤 누적 증가 없음, GPU 실패·키보드 복귀·표식 끔 회귀 시험 통과.
  CPU 4배 흉내는 약한 GPU 를 재현하지 않으므로, 팀원 저사양 GPU 에서 켜지거나 안전하게 DOM 으로 돌아가는지도 확인한다(실측 방법은 1단계 계획에서).

## Codex 설계 검토 2차 (같은 thread 이어서) → 3차안

2차 판정 '수정 후 진행' — ① 해소 · ② 부분(낡은 높이·진입 뒤 미지원 카드) · ③ 부분(CPU 이미지 최고 메모리·프레임당 굽기/올리기 양·덧판 놓을 때 GPU 그림 복원) · ④ 부분(켜졌지만 느린 GPU 판정).
숫자: 128MB 는 실험 상한으로 무리 없지만 MiB·계산 범위를 고정 · 1/4 해상도 2,000장 ≈ 31.5MiB(원시 RGBA) — 고정 픽셀이 아니라 화면상 크기 기준·글자 읽힘 관문 · 덧판 1장은 타당, 가려진 카드 읽기 대체 길·초점/팝업 남았을 때 처리 ·
첫 진입·마우스 올림·입력 뒤는 '최대값 공개'가 아니라 미리 정한 실패 기준 · 단계표 충돌·'제목 = head' 명시. 아래 3차안이 이를 반영한다(위 1단계 계약에 더한다 — 겹치면 3차안이 이긴다).

## 1단계 계약 보완(3차안)

- **지원 카드**: 레퍼런스·리스트·글(text)·모델·생성·제목(`head`). 그 밖의 종류(set·view·output·input·render·comfy)가 보이는 씬에는 들어가지 않고, 들어간 뒤 그런 카드가 생기거나 화면에 들어오면
  그 자리에서 DOM 모드로 돌아가 안내한다(그 씬에서는 사용자가 다시 켤 때까지 DOM).
- **높이 낡음**: GPU 모드에서 카드의 높이에 영향을 주는 값(지금 SceneBoard 의 측정 열쇠 structSig·refKeySig 와 같은 것 — 글·글꼴 크기·참조 목록·폭·제목 글)이 바뀌면, 그 카드만 화면 밖 숨은 측정 칸에 DOM 으로 한 장씩
  붙여 재고(프레임당 최대 4장) 그 높이로 다시 굽는다. 재는 동안은 옛 그림을 옛 높이로 그린다. 썸네일이 도착해 자동 높이가 바뀌는 레퍼런스도 같은 길.
- **덧판 수명**: 띄움 = 마우스 아래 맨 앞 지원 카드가 120ms 머물 때(빠른 지나감에는 안 띄움). 놓음 = 마우스가 카드 밖 + 덧판 안에 초점 없음 + 덧판에서 연 팝업 없음 — 셋 다일 때, 놓는 같은 프레임에 GPU 그림을 되살린다.
  초점·팝업이 남아 있으면 마우스가 떠나도 둔다(다른 카드에 올려도 새 덧판을 띄우지 않음). 일부가 가려진 카드는 덧판 없이 더블클릭 → 지금의 크게 보기 창(이미 떠 있는 덧판)으로 읽는다.
- **예산(측정 전 고정)**: GPU 텍스처 합계 ≤ **128 MiB**(할당한 모든 아틀라스 장 × 밉맵 포함 크기 × 교체 중 옛/새 동시 — 바이트로 셈) · CPU 쪽 굽기 버퍼 ≤ **64 MiB**(아틀라스 한 장 굽고 올린 뒤 놓는다 — 이미지 디코드 캐시는 브라우저 몫) ·
  프레임당 굽기 ≤ **4 ms**(메인, performance.now 로 끊음)·올리기 ≤ 한 장의 부분 영역 1번. 해상도 단계 = 카드의 화면상 크기 × 기기 배율에 맞는 {1/4, 1/2, 1} 중 그보다 크거나 같은 것(1.25배 넘게 늘려 그리지 않음 = 글자 읽힘 관문).
- **느린 GPU**: 켤 때 화면 밖 1초 시험 그리기(지금 씬·지금 카메라, 30프레임)에서 프레임 중앙값 > 20ms 또는 하나라도 > 50ms 면 켜지 않고 안내. 켠 뒤 10초 안에 조작 중 50ms 넘는 프레임이 3번이면 DOM 모드로 돌아가고 그 세션은 다시 켜지 않음.
- **전환 구간 실패 기준(측정 전 고정, 이 PC 1배)**: 켜기(DOM → GPU) 동안 100ms 넘는 프레임 0·총 막힘 ≤ 300ms · 덧판 띄우기/놓기마다 33ms 넘는 프레임 0 · 입력 끝난 뒤 1초 안 50ms 넘는 프레임 0 ·
  CPU 4배 흉내는 같은 구간의 최대 프레임이 DOM 판의 같은 구간 이하.

## Codex 설계 검토 3차 → 4차안

3차 판정 '수정 후 진행' — 높이 무효화·미지원 처리·덧판 수명 해소. 남은 필수: 최대 해상도(화면 배율 × 기기 배율 > 1.25 일 때 '1.25배 넘게 늘리지 않음'과 모순) · 디코드 동시량과 카드 한 장 굽기·올리기 크기 ·
성능 측정 정의(화면 밖 시험 방법·'DOM 의 같은 구간'·'총 막힘')와 지속 감시 · 단계표 head(고침). 구현 중 정해도 됨: 아틀라스 배치·퇴출 순서·안내 문구.

## 1단계 계약 보완(4차안 — 3차안에 더한다, 겹치면 4차안이 이긴다)

- **배율 상한**: 해상도 단계 {1/4, 1/2, 1, 2}(CSS 크기 기준). GPU 모드는 **화면 배율 × 기기 배율 ≤ 2.5** 에서만 쓴다(2 단계 × 1.25). 그보다 크게 확대하면 줌이 150ms 쉰 뒤 DOM 판으로 바꾸고(보이는 카드가 적어 DOM 이 가볍다),
  2.2 아래로 줄어 150ms 쉬면 GPU 로 돌아온다(사이 띠로 오가기 막음). 줌 도중에는 바꾸지 않는다.
- **디코드·굽기·올리기 크기**: 썸네일은 `createImageBitmap(…, {resizeWidth: 굽는 크기})` 로 굽는 크기에 맞춰 디코드, 동시 최대 6장, 디코드된 비트맵도 CPU 64 MiB 예산에 넣고 굽자마자 닫는다.
  굽기 단위 = 카드 한 장(그 안을 쪼개지 않음) — 프레임 예산 4ms 는 카드 사이에서 확인하고, 한 프레임에 예산을 넘기는 카드는 최대 1장. 시험 씬(412·2,000장)에서 카드 한 장 굽기 최대 ≤ **8 ms**(1배)를 관문으로 잰다.
  올리기 = 프레임당 카드 한 장 영역의 `texSubImage2D` 1번(최대 2 단계 기준 카드 크기, 그보다 큰 카드는 1 단계까지만).
- **느린 GPU 판정**: ① 켤 때 = 판 그리기 전체를 30번 연속 그려(화면에 보이는 GPU 판에서, 켜기 직후 첫 1초 — 그동안 DOM 판을 아래에 둠) GPU 시간(`EXT_disjoint_timer_query_webgl2`, 없으면 `gl.finish()` 벽시계)의 중앙값 > 12ms 면
  DOM 판 그대로·안내 ② 계속 감시 = 조작 중 rAF 간격으로 최근 10초 창에 50ms 넘는 프레임이 3번이면 DOM 판으로 돌아가고 그 세션은 다시 켜지 않음(켠 뒤 10초만이 아니라 늘).
- **측정 정의**: '총 막힘' = 켜기 시작 ~ 첫 GPU 프레임 사이 메인 스레드 작업 중 50ms 넘는 몫의 합(Long Animation Frame 의 blockingDuration 합). 전환 구간 기준은 'DOM 의 같은 구간' 대신 절대값으로 —
  이 PC 1배: 위 3차안 그대로 / CPU 4배 흉내: 켜기 100ms 넘는 프레임 ≤ 2·총 막힘 ≤ 1200ms · 덧판 띄우기/놓기마다 33ms 넘는 프레임 ≤ 1 · 입력 끝난 뒤 1초 안 100ms 넘는 프레임 0.

## Codex 설계 검토 4차 → 5차안

4차 판정 '수정 후 진행' — 단계표 head 해소. 남은 것: 큰 카드를 1 단계로 묶으면 배율 1.25~2.5 에서 늘려 그리기 제한과 다시 충돌·'큰 카드'와 최대 올리기 크기 없음 · 총 막힘을 첫 GPU 프레임까지만 세면 30번 검사 비용이 빠짐 ·
배율에 따른 자동 GPU 복귀가 사용자 DOM 선택·미지원 카드·실패 뒤 재진입 금지를 무시하지 않게 우선 조건. 구현 중 정해도 됨: 아틀라스 배치·퇴출 순서·30번 검사 나누기.

## 1단계 계약 보완(5차안 — 4차안에 더한다, 겹치면 5차안이 이긴다)

- **큰 카드**: 해상도 단계를 카드 크기로 묶지 않는다(4차안의 '그보다 큰 카드는 1 단계까지만'을 뺀다). 한 단계의 그림이 **4 Mpx(16 MiB)** 를 넘는 카드는 가로 띠로 나눠(띠마다 ≤ 4 Mpx) 프레임마다 띠 하나씩 굽고 올린다
  (그동안 옛 그림을 그린다). 굽기 단위 = 카드 한 장 또는 큰 카드의 띠 하나 — 그 하나의 굽기 최대 ≤ 8ms 관문, 프레임당 올리기 ≤ 4 Mpx.
- **총 막힘**: 켜기 시작 ~ 켤 때 성능 검사(30번 그리기)가 끝나고 첫 안정 프레임(그 뒤 33ms 넘지 않은 프레임)까지의, 메인 스레드 50ms 넘는 몫의 합(LoAF blockingDuration 합). 3·4차안의 기준값은 이 구간에 적용한다.
- **모드 우선순위**(위가 이긴다): ① 실패·느린 GPU 로 돌아감 → 그 세션 GPU 잠금 ② 사용자가 고른 DOM 모드 → 사용자가 다시 켤 때까지 DOM ③ 미지원 카드가 보이거나 있음 → DOM(그 씬에서 사용자가 다시 켤 때까지)
  ④ 배율 상한(화면 배율 × 기기 배율 > 2.5) → DOM, 2.2 아래로 줄어 150ms 쉬면 GPU. **자동 GPU 복귀는 ④ 로 DOM 이 된 경우에만**, 그리고 그때 ①~③ 이 모두 아닐 때만 한다.

## Codex 설계 검토 5차 — 합의

5차 판정 **'이대로 1단계 진행 가능'**(같은 thread `01a1c786-c017-78e2-9133-586cd5948dac`, read-only `gpt-6-astra`·high): 큰 카드 띠 굽기·성능 검사 끝까지 세는 총 막힘·모드 우선순위 모두 해소, 새 모순 없음.
구현 중 정해도 됨: 픽셀·바이트 단위 통일 · GPU 최대 변 길이 처리 · 띠 완성 뒤 카드 교체 방식 · 안정 프레임 대기 제한시간. 단서: 문서 검토 판정이며 메모리·8ms·전환 성능은 구현 뒤 약속한 실측 관문으로 확인.
1단계 계약 = 2차안 + 3·4·5차 보완(겹치면 뒤 판이 이긴다). 구현에 들어가면 이 계약을 `vibe-intent`(major)로 옮겨 양측 합의 근거와 함께 bind 한다.

### 자료 흐름

SceneBoard 상태(원본 — 카드·연결선·그룹·높이·선택·숨김/접힘·생성 정보…) → `gpuScene`(순수) → ① 모습 열쇠가 바뀐 카드 → `cardAtlas` 굽기 대기열 ② 위치·크기·선택·숨김 → 인스턴스 버퍼 → `gpuRenderer.draw(카메라)`.
카메라는 지금 useSceneViewport 의 zoomRef/panRef 그대로 — 카메라를 바꾸는 모든 길(휠·가운데 버튼·화면 맞춤·씬 전환)이 GPU 판에 '그려 달라'를 한 번 알린다. GPU 판은 카메라를 쓰지 않는다(읽기만).

### SceneBoard 에 끼우는 자리(변경 최소)

- 표식 `mvhub.canvas.gpuBoard`(storageKeys, 기본 끔) + `gpuMode` 결과로 `gpuView` 를 정한다.
- `gpuView` 이면 `.scene-canvas` 안의 카드 목록·연결선 SVG·그룹 틀·끝 점을 그리지 않고 보드에 `<GpuBoard>` 하나를 둔다(보드 크기 canvas — 카메라 층 밖). 카메라 층은 덧판 칸만 담는다. DOM 모드로 돌아가면 GpuBoard 를 내리고 카드 DOM 을 지금 컬링대로 다시 붙인다.
