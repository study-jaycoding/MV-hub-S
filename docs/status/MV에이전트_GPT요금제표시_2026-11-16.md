## 확인한 것

- 지금 Codex 확인은 `codex login status` 뿐(`agent_chat_process.py:185-190`) — 출력은 'Logged in using ChatGPT' 한 줄(이 PC 실측), 요금제 없음. Claude 는 `auth status` 의 subscriptionType(`agent_chat_claude.py:108`).
- 공식 Codex app-server 프로토콜 `codex-rs/app-server-protocol/src/protocol/v2/account.rs:22-35` — `Account::Chatgpt { email, plan_type }`, 종류 목록 `codex-rs/protocol/src/account.rs` `PlanType`(free·go·plus·pro·prolite·promax·team·business·enterprise·edu 등).
- 이 PC 실측(요금제만 출력): `codex app-server` 에 initialize → account/read = type chatgpt·planType promax. stdin 을 닫고 한꺼번에 보내면 응답 전에 끝남(3줄, 0.9초) → 응답을 받을 때까지 stdin 을 열어 둔다.

## 구현·검증

- `agent_chat_codex.plan_name` — 전용 빈 폴더 `plan-probe` 에서 JobProcess 로 `app-server` 를 띄워 account/read 의 planType 만 이름으로(15초 제한, 끝나면 Job 회수). `agent_chat.engines()` 만 Codex 가 쓸 수 있을 때 불러 행의 subscription 에 담음(대화 보낼 때의 `engine_problem`·`state()` 는 안 부름, 목록 60초 캐시). 가짜 CLI 에 app-server 흉내(FAKE_CODEX_PLAN, 기본 free).
- 설계 중 바꾼 것: 처음 계약은 `state()` 안에서 조회 → `engine_problem` 이 대화마다 `state()` 를 불러(`agent_chat.py:93`) 보낼 때마다 Codex 를 한 번 더 띄우게 되므로 목록(`engines()`)으로 옮김(계약 2판).
- 인벤토리: `plan_name` 의 시간 제한 타이머가 `docs/inventory/background_jobs.md` 에 한 줄로 잡혀 다시 생성(계약 3판에 경로 추가). 다시 받은 시험 기록: plan `57538d2e`(45) · regression `b29258da`(108)·`572e39bc`(inventory --check) — 모두 통과.
- 첫 시험 기록(인벤토리 전): plan `5cb5e86d`(45 통과 — promax·plus·대문자·free·모르는 값·apikey·응답 없이 끝남·멈춤 1초 제한·Job 못 만듦·쓸 수 없을 때 조회 안 함·engine_problem 조회 안 함) · regression `12ea7aa9`(api·connect·runtime 108 통과). 이 PC 실제 Codex(0.162.0-alpha.17.2)로 임시 폴더에서 `plan_name` = 'Pro Max', 0.82초.
- 화면: 프런트는 이미 subscription 을 'N 구독' 으로 보임(`AgentPanel.tsx` 회사 줄) → 'ChatGPT · Pro Max 구독'. 허브(8012)를 다시 켜야 새 백엔드가 적용됨 — Jay 확인 남음.
