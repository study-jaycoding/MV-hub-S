## 1. 증상

캔버스 "생성 결과 N개" 팝업·라이브러리 그리드에서 **7월에 만든 시댄스 영상**의 썸네일이 결과가 아니라
**레퍼런스(캐릭터 시트) 이미지**로 뜬다. 재생하면 실제 프레임이 보이므로 "한 번 재생하면 정상"으로 보인다.
8월 결과물은 정상.

## 2. 원인 (실측)

| 경로 | 같은 잡의 영상 썸네일 | 허브에서 쓰는 곳 |
|---|---|---|
| CLI `generate get/list` (1.1.23) | `hf_…_<job_id>_thumbnail.webp` — 진짜 포스터 (문제 잡 3건·정상 잡 1건 모두) | 주기 동기화(최신 100건), 에이전트 완료 보고 |

- `mcp_item_to_cli` 가 "실샘플 미확보 best-effort" 로 `results.thumbnailUrl` 을 포스터로 넘겼고,
  `_upsert_synced` 가 영상이면 그대로 `asset.thumbnail_path` 에 저장했다.
- 08-20 도입된 기동 시 이력 자동 보충(`ad78206b`)이 **08-24 13:20** 에 264개 잡을 다시 써서 영상 63건이 오염
  (asset 행 재삽입 흔적·`history_import_audit` 시각 일치). 주기 동기화는 CLI 로 최신 100건만 다시 쓰므로
  8월 잡은 20초 뒤 진짜 포스터로 돌아갔고, **7월 잡은 창 밖이라 남았다**. `same_asset` 이 값이 다르면 행을
  DELETE+INSERT 하므로 CLI 가 넣어둔 webp 도 이력 보충이 덮었다(08-21 사본 대비 2건 실측).
- 실사용 DB(읽기 전용 조회): 영상 asset 75 중 63 이 레퍼런스 UUID 와 일치. 한 레퍼런스 URL 이 34개 영상의 썸네일.

## 3. 처방 (코덱스 설계 리뷰 2회 반영)

1. **MCP 변환 차단** — 영상 항목의 `thumbnailUrl` 은 무조건 버리고(진짜 포스터는 CLI 가 준다), 이미지도 입력
   미디어와 같은 `thumbnailUrl`/`minUrl` 은 버린다. `type` 을 `result_media_type` 으로 `parse_job` 까지 전달해
   확장자 없는 영상 URL 이 image 로 오분류되지 않게 한다. `minUrl` 을 결과 URL 로 폴백하는 것도 영상·입력이면 금지.
2. **기존 포스터 보존** — 포스터 없이 들어온 재동기화는 '같은 결과물'(타입 동일 + `source_url or file_path` 동일,
   행 1개)일 때만 기존 포스터를 승계한다. asset 만 바뀌어도 `updated` 로 올려 WS 갱신 신호를 낸다.
3. **로컬 재조정** `services/thumbnail_repair.py` — 로컬 허브 기동 20초 뒤 1회. 게이트는 이력 보충과 동일
   (공유 서버 AUTH on·pairing 없음, 복원 드릴에선 실행 안 함), CLI 로그인 이메일 == 로컬 계정 키, 계정 DB 스코프
   캡처→override. 후보(포스터가 입력 URL 과 같은 영상 asset)마다 CLI `generate get` 1회 → 잡 id·asset·영상·결과
   URL 동일 검증 → 진짜 포스터면 CAS 교체, 없거나 또 입력이면 CAS NULL(첫 프레임 폴백), 확인불가면 무변경.
   예산 120초·개별 15초·순차, 남은 후보는 다음 기동. 처리>0 이면 `synced` broadcast.

코덱스 1차(v1) **재설계** — `PeriodicSync` 는 공유 서버 전용이라 로컬에선 안 돎, 무조건 UPDATE 경합, 승계 조건
과대, `minUrl` 결과 폴백 오염. 2차(v2) **수정 후 승인** — `result_media_type` 전달, 영상 minUrl 폐기, host+path
비교, 승계는 행 1개, 검증식 `parsed.generation.id == job_id`, monotonic 예산. 3차(diff) **수정 후 승인** — 부분 성공
후 예외·취소 시 broadcast 누락, 계정 스코프·기동 훅 회귀 테스트 부재 → 반영(try/finally broadcast, 후보별 예외 격리,
scope/배선 테스트). 4차 **승인**(남은 지적 = 이 문서의 수치 자리표시자 → 갱신 완료).

## 5. 잔여 위험 / 남은 것

- `same_media_url` 은 힉스필드 CDN 경로 규칙에 의존 — 서명 query 만 다른 경우는 잡지만, 호스트가 바뀐 복사본은
  다른 미디어로 본다(누락은 안전 방향).
- 재조정은 CLI 가 있는 로컬 허브에서만 실효. 공유 서버 DB 에 이미 퍼진 오염값은 작업자 로컬이 고쳐진 뒤
  다음 공유/동기화가 덮는다(별도 처리 없음).
- MCP 가 나중에 진짜 포스터를 주더라도 영상 항목은 버린다(의도: CLI 가 권위).
