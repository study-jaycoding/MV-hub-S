## 설계(①안 · Jay 10-29 A안 '단순하게' — Codex 1~8차 검토 반영)

1. **판별 = 로컬 정책(보장 아님)** — MP4/MOV 머리만 읽는다(ffmpeg 없이). 결과는 셋: **변환 생략 후보**(`avc1`·`avc3` + avcC profile_idc ∈ {66,77,88,100} + 짧은 변 720~2160) · **변환 대상**(그 밖, 그중 해상도를 읽었고 범위 밖이면 '범위 밖' 표시) · **판별 불가**. profile 로 8비트 4:2:0 을 미루어 보는 것은 **휴리스틱**이다(SPS 의 색차·비트 깊이는 읽지 않는다 — High profile 은 규격상 8비트 4:2:0 이지만 실제 SPS 를 검증하지 않음). '변환 생략 후보'도 Kling 이 받는다는 보장이 아니다.
   - 파서 경계(Python·TS 같게): 상자 크기·확장 크기(64비트)·크기 0(끝까지)을 부모 범위 안에서만 · 한 단계 상자 수 512 · 깊이 고정(moov→trak→mdia→minf→stbl→stsd) · 한 번에 읽는 머리 바이트 상한(상자 머리 8 — 확장 크기일 때만 8 더, 표본 항목 86, avcC/hvcC 32) · `mdat` 등 내용은 한 바이트도 읽지 않고 크기로 건너뜀(moov 가 파일 끝이어도) · **영상 trak 이 정확히 하나·stsd 항목 수 1 일 때만** 판정(둘 이상이면 판별 불가 — ffmpeg `0:v:0` 와 어긋나지 않게) · 범위를 벗어나는 크기·잘린 상자·표본 항목 안 상자 깨짐·**어느 trak 이든(소리 trak 이라도) mdia·hdlr 을 못 읽음** = 판별 불가.
2. **에이전트(권위, 과금 전 마지막 관문)** — `_submit_one` 에서 모델이 `kling_video_edit`·`kling4_0` 일 때:
   - **우회 입력 거절**: `params` 에 미디어 키(`video`·`video_references`·`image_references`·`image`·`start_image`·`end_image`·`input_video`·`medias`)가 있으면 create 전에 실패("Kling 영상 수정의 영상·이미지는 레퍼런스로만 받습니다"). 다른 모델의 공용 인자 처리는 그대로.
   - `--video` 로 나갈 레퍼런스 영상마다(레퍼런스 고리 안, **제출 허가 `_begin_submission` 전**): 판별 → '변환 생략 후보'면 지금과 똑같은 인자. 해석값이 **업로드 ID(UUID)** 면 로컬 파일이 아니라 판별·변환하지 않고 지금처럼 그대로 보낸다(ffmpeg 유무와 무관 — 독립 리뷰 2차 P2).
   - 그 밖이면 H.264 인코더(`ffmpeg -encoders` 에 libx264)가 있는 ffmpeg(CONTENT_HUB_FFMPEG → PATH)로 **요청마다 새 임시 파일**(`mvhub-kling-*.mp4`, 핸들을 닫은 뒤 실행)에 변환: `-nostdin -y -i 원본 -map 0:v:0 -map 0:a:0?`(첫 오디오만, 무음 입력엔 오디오를 새로 만들지 않음) · 짧은 변을 720~2160 안으로(짝수·비율 유지 — 854×480 → 1282×720) · `libx264 -preset veryfast -crf 18 -pix_fmt yuv420p -profile:v high` · 오디오 AAC 192k · `+faststart` · 길이·fps 옵션 없음(CFR 입력 기준 — VFR 의 프레임 시각 보존은 보장 안 함) · 300초 제한(초과 시 ffmpeg 종료·회수 뒤 사본 삭제). 출력이 비었거나 **200MB 를 넘으면** 실패(자르지 않음). 변환본을 `--video` 로 보내고 **`ref_cache`·원본 임시 파일·원본 sha256 지문·로컬 보관·예상 내용 검사는 원본 그대로**. 제출 자료에 `transcoded: "h264"`(서버는 버림).
   - **변환 동시 수 2**(프로세스 전역 세마포어, 차례 대기 상한 없음) — 같은 원본이라도 요청마다 따로 변환(공유 캐시에 섞지 않음). '판별 불가'도 ffmpeg 가 있으면 변환을 시도한다(실패하면 create 전 실패).
   - **서버 점유 기한과의 관계(Jay 10-29 A안 — 준비 기한·회수 기억 장치를 두지 않음)**: 서버의 요청 점유 기한은 30분(`repo/gen_requests.py` 1731행)이고 에이전트는 점유한 배치의 레퍼런스를 모두 받은 뒤 `_submit_one` 을 돌린다. 다운로드·변환 차례 대기·변환이 길어 제출 허가 전에 점유가 만료되면 **기존 흐름 그대로** 제출 허가가 거절돼 그 시도는 create 를 하지 않고(그 시도의 과금 없음) 기존 API 로 점유 반환을 **시도**한다 — 반환 성공·자동 재대기까지 보장하는 것은 아니며, 다시 받으면 다시 변환하므로 시간이 더 든다(Codex 9차 P3 문구). 변환 실패는 다른 생성 전 실패(지문 불일치·로컬 보관 실패 등)와 같은 `_fail`. 3~8차에서 다듬던 준비 기한(점유 + 20분)·초과 때 서버에 쓰지 않기·회수 기억(점유 + 31분) 장치는 **빼었다** — 드문 경우를 막으려다 새 경합(늦은 실패·반환 회차·회수 계기·계정 전환)이 이어졌기 때문.
   - **알려진 한계(후속 작업)**: 점유가 만료된 뒤 늦게 보낸 `_fail` 은 서버 실패 API·DB 갱신이 점유자를 비교하지 않아 다른 실행자가 다시 점유한 요청을 실패로 바꿀 수 있다(Codex 3·4차). 이것은 **기존의 모든 생성 전 실패가 이미 가진 문제**이고 이번 변환은 그 앞 단계 시간(변환 차례 대기·최대 300초 변환)을 늘릴 뿐이다 → 서버의 실패·반환 API 가 점유자·점유 회차를 확인하게 하는 일은 아래 「후속 작업」으로 따로(이번 범위 밖).
   - ffmpeg(H.264) 가 없을 때: 로컬 정책상 '범위 밖'이면 create 전에 실패 — 사유 "앱의 변환 정책상 Kling 영상 수정에는 짧은 변 720~2160px 영상을 보냅니다(이 영상 854×480 · hvc1). 이 PC 에 H.264 변환용 ffmpeg 가 없어 바꿔 올리지 못해 생성하지 않았습니다 — Seedance 2.5 편집을 쓰거나 ffmpeg 를 설치하세요(과금 없음)". '판별 불가'·'범위 안이지만 변환 대상'(코덱 등)은 **호환성을 위해 원본 그대로** 보낸다(받을 수도 있는 영상을 막지 않기 — 성공·환불을 보장하는 근거로 쓰지 않음) + 콘솔 한 줄.
   - **실패 경계**: ffmpeg 탐색·인코더 확인·판별·임시 파일 생성·변환·출력 검사는 모두 제출 허가 전 — 여기서 난 모든 오류(임시 파일 생성·디스크 부족·실행 실패·300초 변환 제한 초과·예상 밖 예외)는 그 단계 안에서 잡아 create 전 `_fail`("Kling 용 영상 변환에 실패해 생성하지 않았습니다(…) — Seedance 2.5 편집을 쓰세요(과금 없음)"). 넓은 except 는 **이 변환 단계에만** 두고 제출 허가 이후 경로에는 넣지 않는다(이후 예외는 지금처럼 '제출 확인 필요'). ffmpeg 출력은 바이트로 받아 UTF-8 `errors="replace"` 로 읽고 `_sanitize_diagnostic` 으로 정리해 300자까지.
   - **사본 정리**: `_submit_one` 을 감싸 그 요청이 만든 사본을 끝날 때(성공·명령줄 초과·지문 불일치·로컬 보관 실패·워크스페이스 실패·제출 허가 거절·CLI 실패 모두) 지운다. 정리 오류는 무시해 결과·원래 사유를 덮지 않는다. 프로세스가 강제 종료되면 OS 임시 폴더에 `mvhub-kling-*` 가 남을 수 있다(정상 종료만 보장).
3. **보고(② 결정용 숫자 — 안내·통계만)** — `_collect_account_status` 가 `acct["ffmpeg_h264"] = True/False`. ffmpeg 확인은 결과를 10분 기억(설치 뒤 다음 보고·제출에 반영). 서버 `hf_status:{email}` 에 쌓여 `identity.list_account_statuses()` 로 **보고한 계정 중 몇이 True 인지** 센다(PC 수가 아니라 보고 계정 수). `/api/account/hf` 는 실제 bool 일 때만 `ffmpeg_h264` 를 돌려주고 아니면 `null`(미보고와 false 구분).
4. **화면(보조 — 미리 알림만, 막지 않음)** — 수정 창이 이미 받아 둔 원본 Blob 머리를 같은 정책으로 읽고(`lib/videoFormat.ts`), **Kling 모델을 고른 동안만** 한 줄 안내: '변환 대상'이면 "이 영상(854×480 · hvc1)은 Kling 이 받지 못할 수 있어 최신 작업자 프로그램이 보낼 때 H.264 로 바꿔 올립니다(ffmpeg 필요 · 원본은 그대로)", 계정 보고가 false 면 "이 계정의 마지막 보고에는 H.264 변환용 ffmpeg 가 없습니다 — 실제로 실행하는 PC·프로그램 버전에 따라 자동 변환·사전 중지 여부가 다릅니다. 확실하게 하려면 Seedance 2.5 편집을 쓰세요", 보고가 null 이면 "자동 변환 지원 여부를 확인할 수 없습니다". **어느 경우에도 '생성 전에 멈춘다'고 단정하지 않는다**(보고는 이메일별 마지막 값이라 다른 PC·오래된 보고·옛 에이전트일 수 있다 — Codex 2차 P2). 생성 단추는 막지 않는다(실제 판단은 새 에이전트). '변환 생략 후보'·판별 불가·Seedance·이미지에는 안내 없음.
5. Seedance 2.5 편집·이미지 수정·다른 모델·다른 화면의 제출 인자와 흐름은 그대로.
