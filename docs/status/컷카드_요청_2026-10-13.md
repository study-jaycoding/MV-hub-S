원인은 아침의 설계대로였다: 뒤로·앞으로 가기는 **보는 자리만** 되살리고 다음 생성 위치(`generationScope`)·무장 폴더(`armedFolder` — 사이드바의 분홍 표시 = 실제 생성 목적지)를
두었다. 앞으로 가는 조작(사이드바·에피소드 카드·[폴더로])은 모두 무장까지 옮기므로 뒤로 가기만 어긋났다. 컷 카드 세션(아침에 만든 쪽)과 상의해 뒤집었다 —
'보기만'으로 묶은 까닭은 공유 탭 기억 되살림(Jay 가 고른 자리가 아니다)이었고, 뒤로 가기에는 지킬 독립된 까닭이 없었다.

- **규칙**: 브라우저 뒤로·앞으로 가기로 **자리가 실제로 바뀌면** 그 자리를 눌러 들어간 것과 같다 — 보는 자리 + 다음 생성 위치 + 무장 폴더(폴더까지 고른 자리만, 프로젝트만 고른 자리는 없음)를 함께 옮긴다.
- **그대로인 것**: 공유 탭을 직접 눌러 돌아올 때의 '마지막 자리 기억' = 보기만 · 같은 자리의 기록(미리보기 겹·탭 기록은 그때 자리의 사본을 싣는다 — 닫는 것만으로 생성 위치가 바뀌면 안 된다) · 휴지통 기록(생성 목적지가 아니다) · 다른 문맥(공간·계정)의 기록은 안 되살림 · 선택 비움·`manualRevision`(늦은 Resolve 응답 폐기).
- **구현**: `lib/useLibraryFilters.restoreLocation(location, adopt)` — adopt 이고 휴지통이 아니면 `commitGenerationScope` + `setArmedFolder`(같은 값이면 객체를 갈지 않는다 — 저장을 다시 하지 않는다), 그 **뒤에** `restoredLocationRef` 를 켠다('낡은 프로젝트' 효과가 목록에 없는 프로젝트의 기록을 지우지 않게 — Codex 3차 P2 의 경우가 이제 이 길로 난다). `lib/useAppNavigation.applyView(view, fromHistory)` — popstate 만 adopt 로 부른다(탭·겹을 여는 `navigate` 는 아니다). 무장 저장은 localStorage 뿐이다(허브의 `PATCH …/selection` 은 사이드바 클릭이 보낸다 — 뒤로 가기는 보내지 않는다).
