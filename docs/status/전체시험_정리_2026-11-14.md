# 전체 시험에서 나온 dev 정리 2건 (2026-11-14)

Jay 11-14 "할수있는것들 순서대로 진행" 의 SQLite 3.54.1 후보 전체 시험(고정 사본 `ad9ed419`)에서 나온 것 가운데, SQLite 와 무관하게 dev 를 고쳐야 하는 두 가지다.

## 1. 1C-1 이 만든 import 순환

`test_architecture_boundaries.py::test_backend_internal_import_graph_has_no_cycles` 가 실패한다(어제 `07263f68` 사본에서는 통과, Claude 직접 확인). 1C-1(`dde729bb`)이 `scene_notebook.py` 에 `from .share_commands import database_generation, require_restore_generation` 를 더해 `identity → scene_notebook → share_commands → share → … → identity` 가 닫혔다(이 검사는 함수 안 import 도 센다 — `identity.py:844`).

- 고침: 세 이름(`database_generation`·`RestoreGenerationConflict`·`require_restore_generation`)은 `share` 에 기대지 않으므로 새 잎 모듈 `backend/app/repo/restore_generation.py` 로 옮긴다(내용 그대로). `share_commands.py` 는 그 모듈에서 다시 내보내 기존 `commands.database_generation` 호출자(usecases/share·routers/share)와 시험의 import 를 그대로 둔다. 1C 의 다섯 사용처(`scene_notebook`·`scenes_backup`·`scene_cards`·`edit_docs`·`routers/scenes`)는 잎 모듈에서 가져온다.
- 같은 시험의 다른 순환 `agent_chat_codex ↔ agent_chat_process` 는 GPT 잠금 풀기(`6b2a9414`) 쪽이라 그 작업 세션에 알렸다(이 기록 범위 밖).

## 2. 시험이 파이썬 CRT 시간대 기억에 기대던 것

`test_task_due_local_date.py::test_archive_due_dates_follow_team_local_date` 가 SQLite 3.54.1 후보에서만 매번 실패한다(지금 3.50.4 는 통과). 원인(직접 재현): `conftest.py:70` 이 `CONTENT_HUB_*` 를 모두 버려 자식 프로세스에서 `config.py:20` 이 `TZ` 를 `KST-9` 로 되돌린다. 3.50.4(파이썬 동봉 DLL)는 파이썬과 CRT 시간대 기억을 같이 써서 시작 때의 `AAA±12` 를 계속 보고, 3.54.1(sqlite.org 공식 DLL)은 자기 첫 사용 때의 `TZ`(KST-9)를 따로 읽는다. 한낮엔 KST 날짜 = UTC 날짜라 자식이 '날짜 경계'로 건너뛰고 부모가 실패한다. 제품 경로는 `config.py` 가 시작 때 `TZ` 를 정한 뒤 SQLite 를 쓰므로 두 DLL 모두 팀 시간대를 따른다(앱 DB 연결로 직접 확인).

- 고침: 부모가 시간대를 `MVHUB_DUE_TZ_CHILD` 값으로 넘기고, 자식 모듈이 첫 SQLite 사용 전에 `TZ` 를 그 값으로 다시 맞춘다. 고정 사본에서 두 Python 모두 세 번씩 통과.
