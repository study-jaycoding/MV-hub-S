## 설계 3판 (Codex 2차 반영 — 이 절이 2판·1판보다 우선) [C2-n]

2차에서 남은 결함(계정 문맥·arm 귀속·NAS 장부 공유·정렬과 저장 충돌)은 대부분 **'놓인 클립을 나중에 찾아 옮기는 것'과 '별도 로그인 짝'** 에서 나왔다. 3판은 둘을 없앤다.

### 1. 로그인·계정 — 짝짓기 없음 [C2-1·C2-2·C2-3·C2-10]

- 패널 화면(`?embed=resolve-panel`)은 **앱 창과 똑같이 일반 API 를 부른다** — 목록·컷 수·★/보류·썸네일(`<img src="/media/…">`)·워크스페이스 목록 모두 편집 탭이 쓰는 같은 프런트 함수(`useEditSequence` 의 조회·`sharedWorkspaceFilter`)로.
  그러면 공유 & 리뷰·편집 탭과 **같은 코드 길이라 같은 결과**다(패널 전용 읽기 경로·공개 접두어·키·`session.json` 은 없앤다).
- AUTH-off(릴리스 기본 — 로컬 허브가 저장된 서버 토큰으로 위임): 앱 창처럼 로그인 없이 허브의 활성 계정으로 보인다. AUTH-on(개발 `test_dev`): 패널 창 안에서 앱과 같은 로그인 화면(별도 프로필이라 한 번 로그인).
  embed 화면은 401 이면 로그인 화면을 보인다(지금 embed 창은 메인 창의 로그인을 전제 — 패널만 로그인 화면을 품는다).
- 쓰는 요청(prepare·target·adopt)은 일반 인증을 지나고, 그 위에 **시작 때 받은 계정 세대**를 싣는다: 화면이 열릴 때 `GET /api/resolve/panel/identity` → `{epoch, who}`.
  쓰는 요청마다 `epoch` 을 보내고, 허브는 `active_account.account_epoch()` 과 다르면 거절(`account_changed` → 화면 새로고침). 작업은 `capture_account_pin()` 으로 접수 계정을 고정해
  `pinned_account_scope(pin)`(+ 위임이면 `_proxy.pinned_connection`, `routers/agent_chat.py:69` 와 같은 짝) 안에서 한다 — 잠금 대기 뒤·응답 전에도 epoch 를 다시 본다.
- `_require_local_resolve` 는 loopback 전용이 아니라 **이 PC 의 로컬 주소**를 허용한다(`request_guards.py:215`) — 다른 리졸브 경로와 같은 범위 그대로 쓴다(문서 1·2판의 'loopback' 표현 정정).
- 판 호환: 플러그인은 `PANEL_PROTOCOL`(정수)을, 화면은 받아들이는 범위 `[min, max]` 를 갖는다 — 화면이 플러그인 판을 범위로 검사하고, 플러그인도 화면이 알려 주는 판을 자기 범위로 검사한다. 어느 쪽이든 밖이면 끌기를 막고 까닭을 보인다.

### 2. 플러그인 — 창과 끌기만 [C2-4 일부]

- 주소: 기본 `http://127.0.0.1:8010/?embed=resolve-panel`. 허브가 시작 때 `%LOCALAPPDATA%\MVHub\resolve-panel\hub.json`(**주소·판만, 비밀 없음**)을 쓰면 그 주소를 쓴다(개발 포트용).
- `startDrag` IPC 는 **보낸 창·최상위 프레임·출처(= 연 주소의 출처)** 를 확인한다. 경로는 화면이 허브에서 받은 것(서버 확정 경로)을 넘기고, main 은 추가로 **파일이 실제로 있고·일반 파일이고·영상/그림 확장자**인지만 본다.
  신뢰 범위(명시): 허브 출처의 최상위 화면은 앱 창과 같은 신뢰다 — 그 화면이 넘긴 경로를 끈다. 다른 출처로 이동한 화면·하위 프레임·다른 창의 요청은 거절.

### 3. 미리 받기 — 파일만 [C2-5]

- `POST /api/resolve/panel/prepare {epoch, project_id, folder_path, gen_ids}` → `transfer_generations` 의 **복사 단계만** 떼어 낸 함수(`prepare_generation_files` — 이름 규칙·render 폴더·재사용 그대로,
  `transfer_generations` 도 이 함수를 쓰게 바꿔 동작은 같게)로 복사하고, **장부를 쓰지 않는다**. 응답 = 생성물별 경로·상태. 같은 요청 합치기·허브 전체 동시 1개·컷을 바꾸면 미착수 항목 건너뛰기(2판 그대로).
- 공유 NAS 장부는 3단계(아래 4)에서 **실제로 리졸브에 표시를 찍었을 때만** 보통 보내기와 같은 모양(새 transfer_id 1건)으로 쓴다 → 여러 PC 가 한 파일을 고쳐 쓰는 일이 없다.
- **Jay 결정(2026-11-11 "리졸브 보내기를 할 때처럼 파일을 받아 두면 되지 않나" → 아래 안 → "구현")**: 리졸브 보내기의 받기 두 단계를 나눈다 —
  ① **컷을 열면** 원본을 **이 PC 캐시에만** 미리 받는다(`_cached_source` — 로컬 `/media` 또는 `media_cache.cache_url`, NAS 에 쓰지 않음, 이름 장부도 안 건드림).
  ② **카드를 누르면** 그 카드 하나만 보내기와 같은 복사(이름 배정·별칭·render(NAS) 복사·완료 표식 — 위의 `prepare_generation_files` 한 항목)를 하고, 끝나면 끌기가 된다.
  그래서 NAS 에는 **실제로 끌어 넣으려 누른 것만** 남는다(보내기로 하나씩 보낸 것과 같음). 누른 뒤 기다림은 LAN 복사뿐(작은 영상 1~2초 안쪽 — 추정, 실측으로 확인).
  ①은 장부·NAS 쓰기가 없어 관문은 일반 인증·로컬 주소·문맥만. ②는 위 관문 표의 prepare 줄 그대로.

### 4. 컷 빈 맞추기 → 리졸브가 처음부터 그 빈에 넣음 → 표시만 [C2-4·C2-6·C2-7·C2-9]

- **target**: 패널에서 컷을 고르면 `POST /api/resolve/panel/target {epoch, project_id, folder_path}` — 허브가 리졸브 자식으로 ① 지금 리졸브 프로젝트 id·이름을 적고
  ② 목적 빈(`MV Hub/<프로젝트>/<폴더 경로>`, 보내기와 같은 `_destination_folder`)이 **있으면** 그 빈을 '지금 빈'(`SetCurrentFolder`)으로, **없으면** 아직 만들지 않는다 —
  카드에 처음 포인터를 누르는 순간 `target {create:true}` 로 만들고 지금 빈으로(빈 컷 빈이 쌓이지 않게. 그 컷의 첫 끌기만 '리졸브 빈 준비 중'을 잠깐 보임).
  ③ `GetCurrentFolder` 를 되읽어 그 빈 id 인지 확인. 응답 = `{resolve_project_id, bin_path, bin_id}` → 화면 위에 "리졸브 빈: MV Hub/…/C0010".
- **끌기**: 그 컷의 target 이 확인됐고(같은 리졸브 프로젝트) 파일이 준비된 카드만 끌기를 시작한다. 리졸브는 놓은 파일을 **지금 빈**에 넣는다(실측 필요 — 아래 '구현 첫 단계').
- **adopt**: 놓은 뒤 앞 응답을 받고 1초 쉬고 최대 8번 `POST /api/resolve/panel/adopt {epoch, resolve_project_id, project_id, folder_path, gen_id}` — 허브가 자식으로:
  ① 지금 프로젝트 id ≠ 받은 id → `project_changed`(쓰지 않음). ② **목적 빈 안에서만** 그 경로의 모든 항목을 모은다(경로별 전 항목 함수 — `_clips_by_path` 는 첫 항목만이라 쓰지 않음).
  ③ 항목이 있으면 **표시가 없거나 다른 생성물 표시인 항목에만** `stamp_and_verify`(dict 먼저·되읽기 — 기존 반입의 표시 함수도 이것으로 바꿈, C1-8 닫힘 그대로).
  **옮기기는 하지 않는다** — 목적 빈에 그 생성물의 파일이 있는 것이 사실이므로 표시는 이번 끌기에서 왔든 예전 보내기에서 왔든 맞다(멱등). 그래서 '이번 끌기의 증거'가 필요 없다.
  ④ 목적 빈에 없고 다른 빈에서 같은 경로가 보이면 **아무것도 바꾸지 않고** 사실만 알린다("같은 파일이 '빈 X'에 있습니다 — 옮기지 않았습니다"). 빈 정리 단추는 이번 범위 밖.
  ⑤ 표시를 새로 쓴 것이 있으면 guard → `SaveProject` → 결과 확인(보통 반입 끝과 같은 순서 — `resolve_bridge.py:1921-1924`) → 보통 보내기와 같은 장부 1건(origin `panel`·이 PC id·그 항목·`resolve_import` 결과).
- 상태(관측 사실만): `in_bin`(목적 빈에 있음·표시 확인·저장 확인) · `in_bin_unsaved`(표시는 됐으나 저장 확인 실패) · `elsewhere`(다른 빈에서 봄) · `not_seen`(8번 동안 목적 빈에서 못 봄 — "놓지 않았거나 다른 빈" · [다시 확인]) ·
  `project_changed` · `busy`(잠금 대기 30초 넘음 — 재시도 횟수에 안 셈) · `unknown`(자식이 결과 없이 끝남). 카드 문구는 "방금 들어갔다"가 아니라 **"리졸브 'C0010' 빈에 있음"**.
- 정렬: target 이 새로 만든 빈은 보내기의 자연 정렬 복구를 돌리지 않는다(기존 항목 이동·백업 저장이 따라오므로 — 2차 C2-6). **새 빈은 형제들 끝에 붙을 수 있고, 다음 리졸브 보내기의 정렬 복구가 맞춘다**(보장 축소 — 계약에 적음).

### 6. 구현 첫 단계 — 실측(시험 프로젝트에서)

1. 타임라인에 진짜 파일을 놓으면 리졸브가 미디어 풀의 **지금 빈**에 넣는가(아니면 다른 규칙인가) — 아니면 4 의 target 은 쓸모가 없고 설계를 다시 연다.
2. 지금 빈에 같은 파일이 이미 있을 때 놓으면 새 항목을 만드는가·재사용하는가(중복 안내 문구를 정한다).
3. 파이썬 `SetThirdPartyMetadata` 의 dict·두 인자 형식 중 무엇이 되는가(21.1).

### 7. 3판 보완 (Codex 3차 반영) [C3-n]

- **문맥 = (허브 실행 인스턴스 id, 계정 키, epoch)** [C3-1]: 허브가 시작할 때 무작위 인스턴스 id 를 만든다(epoch 는 재시작 때 0 부터라 그것만으론 못 가름). `GET /api/resolve/panel/identity` 가 셋을 주고,
  화면은 2초마다·창 초점 때 다시 묻는다. 바뀌면 목록·준비 결과·target 을 **모두 버리고** 끌기를 막은 채 새로 읽는다. 쓰는 요청은 셋을 싣고, 허브는 **검사 → `capture_account_pin` → 다시 검사 → 작업 시작** 순서로(그 사이 전환이면 부수효과 전에 거절).
  끌기 시작 전에도 화면이 '마지막 문맥 확인이 2초 안이고 같음'일 때만 `startDrag` 를 부른다. AUTH-off 의 로컬 허브 신뢰는 기존 모델 그대로이며 epoch·인스턴스 id 는 인증 수단이 아니라 **낡은 화면 거르기**다.
- **target 유효성** [C3-2]: target 요청에 화면의 선택 순번을 싣고, 허브는 잠금을 잡은 뒤 **그 화면의 더 새 순번이 이미 처리됐으면 버린다**. 화면은 패널이 보이는 동안 2초마다 가벼운 읽기
  `GET /api/resolve/panel/current-bin`(지금 프로젝트 id·지금 빈 id — 리졸브 읽기만)으로 지금 빈이 target 과 같은지 보이고, 다르면 **자동으로 되돌리지 않고** "리졸브 지금 빈이 'C0010' 이 아닙니다 · [맞추기]"를 띄운다
  (끌기는 막지 않는다 — 놓는 빈은 리졸브가 놓는 순간 정하므로 원자적으로 묶을 수 없고, 다른 빈에 들어가면 adopt 가 `elsewhere` 로 사실만 알린다. 옮기지 않으므로 해는 없다).
  화면 위에 늘 "이 창이 리졸브 미디어 풀의 지금 빈을 고른 컷으로 바꿉니다" 한 줄. 첫 빈 만들기가 끝나기 전의 `dragstart` 는 시작하지 않고 카드에 "리졸브 빈 준비 중 — 다 되면 다시 끌어 주세요".
- **단계별 확인·재시도** [C3-3]: adopt 는 목적 빈에 그 파일이 있으면 매번 ① 표시(없을 때만 쓰고 되읽기) ② guard → `SaveProject` 확인 ③ 장부 기록 확인을 **새 표시 여부와 상관없이** 모두 한다(멱등).
  장부 transfer_id 는 **결정적**(`panel-<sha1(이 PC id, 리졸브 프로젝트 id, 생성물 id, 경로)[:20]>`) — 다시 하면 같은 파일을 같은 내용으로 다시 쓴다(PC 마다 다른 이름이라 PC 끼리 안 부딪힘).
  상태에 `stamp_failed`·`save_failed`·`ledger_failed` 를 더하고, 셋 다 확인된 때만 `in_bin`. [다시 확인]은 같은 adopt 를 다시 부른다.
- **다른 생성물 표시는 덮지 않는다** [C3-4 · C4-1]: 목적 빈의 항목에 **다른 생성물 id 의 유효한 표시**가 있으면 — job_id 별칭이어도 — 이번 판에서는 쓰지 않고 장부도 쓰지 않고 `conflict`(두 id 를 보여 줌).
  별칭을 성공으로 인정하려면 표시·장부·선택 감시(`resolve_selection_monitor.py:245·324` — 경로 충돌 제외·표시와 장부의 정확 일치)가 같은 id 를 쓰도록 기존 장부까지 아우르는 별칭 해석이 필요해 **이번 범위 밖**. adopt 의 경로는 화면이 보낸 값을 쓰지 않고 **허브가 그 문맥에서 준비해 둔 기록**(메모리: 문맥·생성물 → 경로)에서 찾는다 — 없으면 `not_prepared`(화면이 prepare 를 다시 부름).
- **기존 정렬 복구 기록 확인** [C3-5]: target·adopt 의 **첫 쓰기 전에** 일반 보내기가 쓰는 복구 기록 관문(`resolve_bridge.py:1145` 대 — 미완·판독 실패면 멈추고 그 안내를 돌려줌)을 그대로 지난다. 패널 자체 복구 장부는 만들지 않는다.
- **복사 분리 범위** [C3-6]: 공통으로 떼어 내는 것은 **항목 하나의 준비**(원본 확보·이름 배정·별칭 연결·복사·완료 표식)뿐이다. 일반 보내기의 manifest 초기 기록·체크포인트·부분 실패·catalog 갱신·취소 보호는 지금 호출부에 그대로 남는다.
  패널만 manifest·catalog 를 만들지 않고, '컷을 바꾸면 미착수 건너뛰기'는 패널 호출에만. 완료 조건 = 기존 `test_resolve_transfer.py`(재사용·중간 실패·체크포인트 포함)가 손대지 않고 통과.
- 구현 첫 실측에 더함: target 뒤 사용자가 다른 빈을 고르고 놓기 · 컷 빠르게 왕복 · 첫 빈 만들기 도중 끌기.

## 설계 2판 (Codex 1차 반영 — 3판이 우선, 기록)

### 0. 경로·모드 [C1-1]

- 새 API 는 **`/api/resolve/panel/*`** 아래에 둔다 — 이미 로컬 처리 목록(`_proxy.py:632` `"/api/resolve/"`)에 있어 위임 모드에서도 공유 서버로 가지 않는다. 라우터마다 `_require_local_resolve`(loopback) 를 건다.
- 인증 미들웨어(`main.py:952`) 예외는 두지 않는다 — 패널의 요청은 **패널 세션 키**(아래 B)로 라우터에서 검증하고, 미들웨어의 일반 세션 검사를 지나도록 클린 피드와 같은 공개 접두어(`/api/resolve/panel/s/`)만 예외로 등록한다(그 밑의 모든 경로는 세션 키 필수).
- 세 모드의 '계정': AUTH-on = 세션을 연 앱 토큰의 email(토큰 sha·비번 도장까지 — `clean_feed_session.identity_ok` 와 같은 판정) · AUTH-off 단독/위임 = `active_account.capture_account_pin()` ·
  공통 = `active_account.account_epoch()`. 셋 중 하나라도 바뀌면 그 패널 세션은 끝(`account_changed`).

### B. 로그인 넘기기 — 클린 피드 세션 모델 재사용 [C1-2·C1-3]

- 패널 세션은 **앱 창(로그인된 계정)이 연다**: 앱이 켜지고 리졸브 연결이 가능하면 `POST /api/resolve/panel/session`(일반 인증 필요) → 허브가 세션 id + 무작위 키(32바이트)를 만들고
  `identity`(epoch·pin/토큰 sha·email)를 묶는다(`clean_feed_session.Session` 과 같은 모양 — 그 모듈의 identity 부분을 공용 함수로 꺼내 둘이 같이 쓴다).
- 허브가 `%LOCALAPPDATA%\MVHub\resolve-panel\session.json`(주소·세션 id·키·허브 인스턴스 id·프로토콜 판) 을 원자적으로 쓴다. 플러그인은 그것을 읽어 `/?embed=resolve-panel&session=…&key=…` 를 연다.
  허브가 세션을 다시 열면(계정 전환·허브 재시작) 파일이 바뀌고, 플러그인은 2초마다 파일 시각을 보다 바뀌면 다시 연다. 앱이 꺼져 있거나 로그인 전이면 파일이 없음 → 창에 "MV 앱을 켜고 로그인해 주세요".
- **신뢰 범위(명시)**: 키는 같은 Windows 사용자 프로필의 파일에 있다 — 같은 사용자로 도는 다른 프로세스는 읽을 수 있다(로컬 허브 loopback·클린 피드 키와 같은 범위). 다른 사용자·다른 PC 는 못 읽는다.
  로그아웃하면 허브가 그 계정의 패널 세션을 끝내고 파일을 지운다. 키는 세션마다 새로, 세션은 허브 재시작에 살아남지 않는다(메모리).
- 패널 화면의 모든 요청은 `/api/resolve/panel/s/<세션>/…` + 머리글 `X-Panel-Key` — 허브가 매 요청 `identity_ok` 를 본다. 데이터 읽기(시퀀스·컷 목록·공유물·썸네일)는 **패널 전용 읽기 경로**가
  그 세션의 계정으로 같은 조회를 해 준다(일반 `/api/generations` 를 패널 프로필에서 부르지 않는다 — 그 프로필엔 토큰이 없고, 위임 모드의 '지금 저장된 토큰'으로 새는 것을 막는다).
  썸네일도 같은 접두어로 내준다(클린 피드의 공개 미디어 정규식처럼 세션 키 필수).

### A. 플러그인 `com.mvhub.resolve` (저장소 `integrations/resolve-panel/`) — 2판 고친 점

- 웹 화면은 `session.json` 의 주소에서만 연다. preload 의 `mvhubResolve.startDrag(prepId)` 는 **경로가 아니라 준비 식별자**를 받는다 [C1-3].
- main 은 IPC 를 받을 때 ① 보낸 창이 플러그인 창 하나뿐인지(`event.sender === win.webContents`) ② 최상위 프레임인지(`event.senderFrame === webContents.mainFrame`) ③ 그 프레임 주소의 출처가 `session.json` 의 허브 출처와 정확히 같은지 확인하고,
  ④ 허브에 `GET /api/resolve/panel/s/<세션>/drag/<prepId>`(키 머리글 — main 이 파일에서 읽은 키) 로 경로를 받아(허브가 세션·계정·생성물·준비 상태를 검사하고 **서버가 확정한 경로**만 줌)
  ⑤ 그 사이 창 주소·세션이 바뀌지 않았는지 다시 보고 `startDrag`. 어느 하나라도 아니면 끌지 않고 화면에 까닭을 돌려준다.
- 플러그인은 자기 판(`PANEL_PROTOCOL`)을 preload 로 알려 준다. 화면이 요구하는 판보다 낮으면 끌기를 막고 "리졸브 창이 옛 판입니다 — 리졸브를 다시 켜 주세요" [C1-12].

### D. 미리 받기 — 2판 [C1-4·C1-10]

- 장부는 **시퀀스의 컷마다 하나**(`transfer_id = panel-<sha1(project_id, 컷 경로)[:16]>`)를 계속 고쳐 쓴다 — 컷을 다시 열어도 새 장부를 만들지 않는다(색인 5천 장부 한도·catalog 덮어쓰기 누적을 막는다).
  `transfer_generations` 에 `origin="panel"`·기존 transfer_id 재사용·기존 항목 병합을 받는 인자를 더한다. **origin 은 처음 쓸 때부터** 장부에 있다.
- 최상위 `status`·`resolve_import` 의 뜻은 그대로(파일 준비 결과 / 반입 결과). 패널 상태는 **항목마다** `item.panel = {state, prep_id, resolve_project_id?, resolve_item_ids?, error?, at}` 로 따로 둔다:
  `prepared`(파일 있음) · `adopted`(새 항목을 목적 빈에 넣고 표시까지 확인) · `adopted_partial`(넣었으나 표시·저장 확인 실패 — 까닭) · `review`(새 항목을 확정 못 함·중복 — 사람이 보라) · `project_changed` · `unknown`(결과 모름).
- `list_pending_manifests` 는 `origin == "panel"` 을 거른다(패널 장부의 다시 하기는 패널 화면의 [다시 확인]). `manifest_generation_entries`(경로→생성물 색인)는 패널 장부도 읽는다 — 리졸브에 들어간 클립의 표시가 실패해도 선택 감시가 경로로 찾게.
- 요청 합치기: 같은 세션·같은 컷의 준비가 도는 중이면 새 요청은 그 결과를 같이 기다린다. 허브 전체 동시 준비 1개. 다른 컷으로 바꾸면 아직 시작 안 한 항목은 건너뛴다(도는 복사 한 건은 끝까지).
- 장부 쓰기 = 장부별 잠금 안에서 **다시 읽고 → 항목 병합 → 원자 저장**(카드 두 장의 결과가 서로를 지우지 않게) [C1-7].
- **Jay 확인 필요(1판 그대로)**: render(NAS)에 미리 복사 = 끌지 않은 카드도 파일이 생김. 대안(이 PC 임시 칸 + ReplaceClip)은 ReplaceClip 이 메타데이터까지 바꾸고(pyi `ReplaceClip`) 복구 경로가 늘어 **이번 판에서 택하지 않는다** [C1-10].

### F. 놓은 뒤 정리 — 2판 [C1-5·C1-6·C1-7·C1-8·C1-9·C1-11]

- **끌기 직전 사진**: 카드에 포인터를 누르는 순간 화면이 `POST …/s/<세션>/arm {prep_id}` → 허브가 리졸브 자식으로 **지금 프로젝트 id·이름 + 지금 미디어 풀 빈 id + 그 파일 경로를 가진 모든 미디어 풀 항목 id·빈**을 적어 `arm_id` 를 돌려준다.
  `arm` 이 끝나기 전에는 끌기를 시작하지 않는다(카드에 짧은 '준비' 표시 — 보통 1초 안, 길면 실측으로 조정). 사진은 그 프로젝트 id 를 고정한다 [C1-6].
- 놓은 뒤 `POST …/s/<세션>/adopt {arm_id}` 를 **앞 응답을 받은 뒤** 1초 쉬고 다시(최대 8번 · 매번 세션 identity 재검사). 허브는 `resolve_mutation_slot`(반입·타임라인 보내기와 같은 변경 잠금) 안의 자식 프로세스로:
  1. 지금 프로젝트 id ≠ 사진의 id → `project_changed`(쓰지 않음). 리졸브가 둘 이상이거나 연결이 불명확하면 쓰지 않음(`unknown`).
  2. 그 경로를 가진 **모든** 항목을 다시 모은다(`_clips_by_path` 는 첫 항목만 남겨 쓰지 않는다 — 새 함수가 경로별 전부·빈 위치를 준다).
  3. **새 항목 = 사진에 없던 id**. 새 항목이 없으면 `not_dropped_yet`(다음 재시도) — 8번 뒤엔 `unknown`("들어갔는지 확인하지 못했습니다 · [다시 확인]"). 사진에 있던 항목은 **절대 옮기지 않는다**(사용자가 정리해 둔 것 보호).
     리졸브가 이미 있던 항목을 재사용해 새 항목이 안 생긴 경우도 `unknown` 이 아니라 `reused`(옮길 것 없음 — 그 항목이 이미 목적 빈·표시면 끝) 로 가르려면 타임라인 사용 수가 필요하다 → **이번 판에서는 가르지 않고 `unknown` 으로 정직하게** 남긴다(구현 첫 단계 실측으로 리졸브가 재사용하는지 확인한 뒤 정한다).
  4. 새 항목이 **하나**이고 사진 때의 '지금 빈'에 있으면 → 목적 빈으로 옮긴다. 목적 빈을 만드는 길은 **기존 반입과 같은 함수 묶음**(빈 만들기 + 자연 정렬 복구 + 복구 기록 — `resolve_bridge.py:1735` 대 흐름)을 '가져오기 대신 옮기기' 갈래로 부른다(같은 빈 결과 보장) [C1-11].
     새 항목이 둘 이상이거나 사진 때와 다른 빈에 있으면 옮기지 않고 `review`.
  5. 목적 빈에 같은 경로의 옛 항목이 이미 있으면(예전에 보낸 것) 새 항목은 **옮기지 않고** 표시만 찍고 `review`("같은 파일이 두 번 들어감 — 타임라인은 새 항목을 씀"). 타임라인 Resolve 보내기는 지금처럼 목적 빈의 첫 경로 항목을 쓴다(계약에 적는다).
  6. 표시 = 새 함수 `stamp_and_verify`: `SetThirdPartyMetadata(dict)`(21.1 정의) 를 먼저, 안 되면 `(key, value)` — 그리고 **되읽어** `already`·`written`·`failed` 를 가른다. 기존 반입의 `_stamp_mvhub_metadata` 도 이 함수로 바꾼다(모의 시험에 dict 형도 더함) [C1-8].
  7. 옮기기(`MoveClips` 반환 + 되읽은 빈 위치) · 표시(되읽기) · 장부 저장까지 **확인된 것만** `adopted`. 하나라도 확인 못 하면 `adopted_partial`(무엇이 안 됐는지). 프로젝트 저장은 하지 않는다(리졸브 자동 저장에 맡김 — 기존 반입과 같은지 구현 때 대조).
  8. 자식이 결과 없이 죽거나 시간 초과 = `unknown`(만들었는지 모름 — 다시 확인 권함). 잠금이 바쁘면 `busy`(재시도 횟수에 안 셈, 최대 30초).
- 화면: 카드 상태 줄에 결과(들어감 · 확인 필요 · 프로젝트가 바뀜 · 확인 못 함 [다시 확인]). 창을 닫아도 허브의 adopt 는 끝까지 하고 장부에 남긴다 — 다시 열면 그 상태가 보인다 [C1-9].

### G. 설치·갱신 — 2판 [C1-12]

- 설치기는 메뉴 스크립트 설치기와 같은 보호: 기존 폴더를 `.bak-<시각>` 으로 보존 → 새 폴더를 임시 이름에 쓰고 **내용 검증**(파일 목록·sha256) → 이름 바꾸기 → 실패하면 보존본을 되돌림. 같은 판이라도 sha 가 다르면(손상) 다시 깐다. 낮은 판으로는 내리지 않는다(롤백은 MV 롤백이 플러그인 판도 같이 되돌릴 때만).
- 권한 거부·파일 잠김(창이 열려 있음) → 상태 `deferred`(다음 허브 시작 때 다시) · 설정 칸에 까닭. 화면/플러그인 판 불일치는 A 의 프로토콜 확인이 끌기를 막는다.
- **실행 조건**: 릴리스 설치본의 허브가 시작할 때만 자동 설치한다(dev·`test_dev`·임시 작업실 실행은 공용 ProgramData 플러그인을 자동으로 바꾸지 않는다 — 개발은 설정 칸의 수동 [설치] 또는 시험판 폴더로).
- 릴리스: `integrations/resolve-panel/` 를 릴리스 허용 목록·패키지·업데이트·롤백 검사에 넣는다 — **배포 단계 변경이라 Jay 확인 뒤 별도 묶음**.

## 설계 1판(기록 — 위 2판이 우선)

### A. 플러그인 `com.mvhub.resolve` (저장소 `integrations/resolve-panel/`)

- 블랙매직 예제 구조(Electron, `manifest.xml`·`package.json`·`main.js`·`preload.js`·`WorkflowIntegration.node` — 예제의 것을 함께 배포, README 가 권함).
- 메뉴 `Workspace → Workflow Integrations → MV Hub` → 창 하나(맨 위 고정 · 자리·크기 기억). 창은 **MV 로컬 허브의 웹 화면**을 띄운다:
  `http://127.0.0.1:<허브 포트>/?embed=resolve-panel`. 화면 코드는 MV 프런트에 있고 플러그인은 껍데기 — 업데이트는 MV 업데이트로 화면까지 바뀐다.
- 플러그인이 하는 일은 둘뿐: ① 창 띄우기 ② **진짜 파일 끌기**(`webContents.startDrag({file, icon})`). 리졸브 API 호출은 하지 않는다 — 빈 정리·표시는 허브의 기존 파이썬 길(직렬화·guard·장부)을 그대로 쓴다.
- preload 가 웹 화면에 내주는 것은 `mvhubResolve.startDrag(path)` 하나. **허브 출처(127.0.0.1:<포트>)에서만**, main 은 그 경로를 허브에 되물어(`GET /api/resolve-panel/drag-check?path=`)
  '이번에 준비한 파일'일 때만 끈다(임의 파일 끌기 차단).
- 허브 주소·포트: 허브가 시작할 때 `%LOCALAPPDATA%\MVHub\resolve-panel\hub.json`(주소 · 일회성 짝 키)을 쓴다 → 플러그인이 읽어 연다. 허브가 꺼져 있으면 창에 "MV 앱을 켜 주세요".

### B. 로그인 넘기기

- 플러그인 창은 브라우저 프로필이 따로라 로그인이 없다. `hub.json` 의 일회성 짝 키로 `POST /api/resolve-panel/pair` → 허브가 **지금 로그인한 앱 계정**의 세션 쿠키를 그 창에 준다
  (loopback 만 · 키는 한 번 쓰면 버림 · 허브 재시작마다 새 키 · 같은 OS 사용자 프로필 안의 파일이라 신뢰 범위는 로컬 허브와 같다). 앱에 로그인한 계정이 없으면 "MV 앱에서 먼저 로그인".
- 짝이 실패하면 앱과 같은 로그인 화면을 창 안에서 보인다(예비).

### C. 창 화면(`?embed=resolve-panel`)

- 머리: 프로젝트 › 시퀀스(편집 탭과 같은 규칙: 시퀀스 = 폴더 P, 컷 = 직계 하위 폴더 · 마지막 고른 것 기억).
- 왼쪽: 컷 목록(자연 정렬 · 공유물 수 · ★/보류/+N — 공유 & 리뷰 사이드바와 같은 원천). 오른쪽: 고른 컷의 공유물(편집 탭 풀과 같은 조회·같은 거르기).
- 카드: 썸네일 · 작성자 · 모델 · 날짜 · 길이 · ★최종/보류 · 받기 상태(받는 중 · 끌 수 있음 · 실패 까닭). **V1·V2 넣기 단추 없음**(Jay).
- 한계: 편집 탭의 'V1 - 선택 카드' 표는 편집 문서가 앱 창 브라우저(localStorage)에 있어 이 창에서는 못 본다(편집 공유 '서버에 저장'을 쓴 시퀀스만 가능 — 이번 범위 밖).

### D. 미리 받기 — 컷을 고르면

- `POST /api/resolve-panel/prepare {gen_ids}` → 허브가 `transfer_generations` 로 복사(보내기와 같은 이름 규칙·같은 render 폴더·같은 재사용 규칙). 장부에 `origin: "panel"`, 상태 **`prepared`**
  (리졸브에 아직 안 들어감 — `list_pending_manifests` 가 '보내지 못한 것'으로 보이지 않게 거른다).
- 응답 = 생성물별 파일 경로·상태. 컷을 바꾸면 그 컷만. 같은 컷을 다시 열면 이미 받은 것은 건너뛴다(기존 skipped 규칙).
- **Jay 확인 필요**: 이 길이면 끌지 않은 카드도 NAS render 폴더에 파일이 생긴다. 대안 = 이 PC 임시 칸에 받고 놓은 뒤에 render 로 옮겨 `ReplaceClip` 으로 바꿔 잇기(API 있음 · 미실측 · 단계가 늘어남). 기본안은 render(지금 보내기와 같음).

### E. 끌기

- 카드 `dragstart` → `preventDefault` → `mvhubResolve.startDrag(path)`. 놓는 자리·트랙·끼워넣기/덮어쓰기는 **리졸브 자체 동작** 그대로(다빈치 조작 = 우리 조작).
- 받기 전 카드는 끌기를 시작하지 않고 "받는 중"을 보인다.

### F. 놓은 뒤 정리 — 리졸브 보내기와 같은 결과로

- 끌기를 시작하면 화면이 1초 간격 최대 8번 `POST /api/resolve-panel/adopt {transfer_id, gen_id}` 를 부른다(찾으면 멈춤).
- 허브(직렬화 · 선택 감시 멈춤 · 업데이트 관문 · guard)가 자식 프로세스로: 미디어 풀에서 **그 파일 경로의 클립**을 찾는다(지금 빈 → 목적 빈 → `MV Hub` 아래) →
  목적 빈(`_destination_folder` — 보내기와 같은 빈·정렬 규칙)이 아니면 `MoveClips` → 표시 도장 → 장부를 보내기와 같은 완료 기록으로(`resolve_import` 결과 · 상태 `done`).
  그러면 선택 감시·다시 보내기 재사용·타임라인 보내기가 지금처럼 이 클립을 안다.
- 못 찾으면 `not_found`(놓지 않음·취소 — 8번 뒤 조용히 끝, 장부는 `prepared` 그대로). 목적 빈에 같은 경로가 **이미 있고** 새 항목이 하나 더 생겼으면 옮기지 않고 둘 다 표시만 찍고 알린다(타임라인이 쓰는 항목은 지우지 않는다).

### G. 설치·갱신

- `services/resolve_panel_installer.py`(메뉴 스크립트 설치기와 같은 방식 — manifest `Version` 비교 · 임시 폴더에 쓰고 이름 바꾸기 · 관리 표식). 자리 = `%PROGRAMDATA%\Blackmagic Design\DaVinci Resolve\Support\Workflow Integration Plugins\com.mvhub.resolve\`.
- MV 로컬 허브 시작 때 리졸브가 설치돼 있으면 설치/갱신(무료판은 메뉴가 안 생길 뿐 해가 없어 판별하지 않는다). 쓰는 중(창이 열림)이라 바꾸지 못하면 다음 시작 때 다시.
  설정의 리졸브 칸에 상태 한 줄(설치됨 · 리졸브 다시 켜야 보임 · 실패 까닭). 처음 설치 뒤엔 리졸브를 다시 켜야 메뉴에 보인다.
- 릴리스 묶음에 `integrations/resolve-panel/` 포함(배포 단계 — Jay 확인 뒤).
