## 합의안 (동작·저장 내용·허브 공책 규칙 그대로)

1. **R1 공책 결과에 `visibleChanged` 를 따로 둔다** — 기존 `changed` 반환 동작은 보존. 판정은 각 트랜잭션 안에서 pending 재생 뒤 **공책 step 이 바꾼 씬·순서**로, 성공 뒤에만 누적
   (앞뒤 스냅샷 비교 금지 — 중간 사용자 편집을 복구로 오인).

   | 경로 | 판정 |
   |---|---|
   | 최종 확정(받기·추가·삭제·충돌 사본·업로드 실패 사본·순서) | `sceneNotebook.ts` 690 `!equal(all[bucket] ?? [], next)` 를 상수로 보존(709·713 메타 변경은 안 섞음) → 반환 `value` → 718 `applied.ok` 뒤 누적 |
   | 첫 합류 | 172 합류 트랜잭션 안에서 표시 버킷 vs 교체 후 목록(537 호출 전 스냅샷 금지, 합류 성공 = 무조건 true 아님) |
   | 작아진 업로드 실패 사본의 표식 제거 | 473 반환 `modified` 를 `result.ok` 일 때 누적 |
   | 동시 편집 기준 승계·사본 대상 소실 재시도(653~680)·진행 기록·영수증·기준·의도 정리 | false(앞 누적 true 유지) |

   모든 반환 경로(조기 ready·첫 합류·local_only·재시도 한도·catch)에 누적값. disabled·토큰 없음 false. 소비처: `sceneBackup.ts` 451 → `visibleChanged` · 825 는 `changed` 유지 · `sceneWriter.ts` 161 초기 결과·시험 객체에 필드.
2. **R2 바깥 변화 알림(externalSubs)은 씬·순서 차이가 있을 때** — `sceneStore.ts` 671 의 `stepOut.changed` 를 메타 합치기 전 `diffScenes`(619) 의 `puts + deletes > 0` 과 함께 본다
   (순서 키·빈 버킷 생성/삭제 포함 — 337·350·354). `touched` 는 안 씀. `external`·`hadConfirmedOnly`·`dropped`·`notify`·`persisted`·`announceWrite`·`changed` 자체는 그대로.
   보완: 첫 합류(172~180)가 충돌 목록을 바꿀 때 `sceneNotebookTransaction` 이 `notify` 를 전달(723).
3. **R3 같은 글자 정본은 객체를 바꾸지 않음** — 공책 교체(114)에서 115 `sameState`·삭제/되살림 검사를 통과한 뒤 `expected.text === JSON.stringify(scene)` 이면 기존 객체 보존, 117 기준 갱신은 함.
   금지: 글자 같다고 삭제·되살림 의도 확인 생략 · 동시 편집 분기(653) 기준 승계 생략 · `sameSceneContent`(Comfy 실행 정보 제외)로 동등 판정 · 계정·토큰·세대 guard 생략.
4. **R4 지문 기억** — `fingerprint(text)` 를 정확한 전체 문자열 키로 기억, 상한 = 항목 수 + 보유 문자열 총 길이(문자 수), 큰 글자 미기억, 계정 전환 때 비움, 직접 계산한 값만(459 의 `row.base.hash` 대조 유지), 비보안 문맥 JS SHA 경로도.
5. **R5 `applyExternal` 싼 길** — 합친 목록이 길이·순서·객체가 같으면 `prev`(`following` 분기도), `latestActive === myActive` 면 `sameSceneContent` 건너뜀. `recoverConflicts()`·안내는 그대로.
6. **R6 카메라만 쓰기는 카메라만 보내고 화면 객체를 갈아 끼우지 않는다**(구현 중 추가, 아래 '구현 중 발견') — `features/canvas/session.ts` 의 공통 쓰기 길이 `recordCamera` 에도
   저장소 사본(`listScenes` = 씬 객체마다 JSON 으로 만든 사본)의 `cards·edges·groups·mcpAttachmentReceipts` 를 패치에 실어 보낸다. 그 사본은 저장소 씬 객체가 바뀔 때마다(카메라 쓰기 포함) 새로 만들어져,
   다음 카메라 쓰기 때 `patchSceneById` → `mergePatchedSceneList(…, 활성 씬)` 이 활성 씬을 그 사본으로 바꾸고 판이 카드 배열을 새로 받아 카드 전부를 다시 그린다.
   고침: `recordCamera` 패치 = `{ camera }` 만(저장 내용 같음 — 카드는 그 명령이 바꾸지 않는다) · `patchSceneById` 가 카메라 하나만 든 패치면 활성 씬은 화면 객체(`withComfyState` 포함, 실행 정보 반영은 지금 규칙)를 두고
   카메라만 바꾸며(쓰기 성공 때), 다른 씬은 지금처럼 최신 목록. 쓰기 어댑터 타입은 부분 패치를 받게 넓힌다. `write` 가 없는 어댑터(`updateScenesWith` 길)·다른 명령은 그대로.

보류: 출처 추적으로 '자기 창 확정' 판별(허브 받기도 이 창 트랜잭션이라 안내를 놓칠 수 있음 — Codex) · 카메라를 허브 공책에 바로 올리지 않는 정책(브라우저 공통 카메라 동작이 바뀜 — Jay 결정 거리) · 메타 확정 뒤 백업 재예약 제거(별도 설계).
