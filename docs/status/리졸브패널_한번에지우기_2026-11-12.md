# 리졸브 패널 — 앞 에피소드 컷 빈 한 번에 지우기 (2026-11-12)

owner: Claude(설계·구현, 세션 `85e432e7`) · reviewer: Codex(설계 검토·독립 리뷰, 명령줄) · status: 완료 · touched_paths: 아래 계약 · updated: 2026-11-12

## 지금 동작(코드로 확인)

다른 에피소드로 옮기면 `useResolvePanel.ts` `settleEpisode` 가 앞 에피소드의 컷 빈마다 차례로:
`currentBin`(자식 프로세스 1) → 쓴 것 `adopt`(항목마다) → `unstage`(자식 프로세스 1, `delete_empty`).
작업마다 자식 프로세스 띄우기(~0.17초)·쓰기 확인·리졸브 연결이 붙고, 지우기·되읽기가 컷마다 번갈아 돌아(미디어 풀이 바뀐 뒤 첫 읽기 0.1~0.2초) 컷 빈이 하나씩 사라진다. 컷 20개면 수십 초(추정 — 컷당 1~1.5초 × 컷 수, 실측 아님).

## 설계

1. **새 패널 작업 `settle`(자식 프로세스 하나)** — 앞 에피소드 컷 빈 전부를 받는다. 자리는 `unstage` 와 같다(`manifest_root` 필수 검사·`_settle_recovery_record` 를 지난 뒤, `expect_project` 대조 목록 두 곳에 넣음).
   - 시작에 `guard()` 뒤 다빈치 지금 빈 ID 를 읽는다 — **못 읽으면(None·읽기 실패) 아무것도 안 지우고 멈춘다**. `MV Hub` 아래 빈 ID 표를 한 번 만든다.
   - 빈마다 건너뛰기: ID 가 없으면 `not_seen` · 이름 경로로 찾은 빈의 ID 가 다르면(이름이 바뀜) `renamed` · 다빈치 지금 빈이면 `current` · 그 빈을 읽다 실패하면 `unreadable`(그 빈만 손대지 않고 나머지는 계속).
   - 빈마다 지울 후보 = 지금 `unstage` 와 같은 규칙(**이 MV 프로젝트 표식 · 내 항목(`_panel_owned`) · 사용 0**). 쓰인 것·사용 값을 못 읽은 것·사람 클립·다른 허브 표식은 그대로. 쓰인 내 항목의 생성물 ID 는 빈마다 돌려준다(최대 200).
   - 비싼 판정(표식·소유·파일 확인)을 다 끝낸 뒤 `guard()` → **지금 빈을 다시 읽고**(못 읽으면 멈춤, 지금 빈이 된 빈은 뺌) → 빈마다 **기존 `_panel_delete_many` 그대로**: 20개 묶음마다 `guard()` → 그 묶음의 사용 값을 바로 전에 다시 읽어 0 인 것만 `DeleteClips` → 목록 되읽어 사라진 것만 셈. 묶음마다 미디어 풀이 바뀐 뒤 첫 읽기(0.1~0.2초)가 붙지만, 컷마다 자식 프로세스 두 개를 띄우던 지금보다 훨씬 짧다(추정 — 실측으로 확인). 지우는 중 읽기 실패면 그 빈은 `unverified`(빈 안 지움)·나머지 계속.
   - 남는 위험(지금 `unstage` 와 같음): 한 묶음 안에서 앞 클립의 사용 값을 확인한 뒤 같은 묶음의 뒤 클립을 읽는 사이(묶음당 ms 단위)에 앞 클립이 타임라인에 들어가면 그 클립은 지우기 요청에 들어간다. 11-12 실측으로 리졸브는 쓰는 중인 클립의 `DeleteClips` 도 막지 않는다 — 이 틈에 걸리면 **쓰인 클립이 미디어 풀에서 지워질 수 있다**(타임라인 항목은 남음).
   - 지운 뒤 빈마다 목록을 다시 읽어, 후보였는데 남은 클립 중 **사용 값이 확인된 양수인 것**(고른 뒤 타임라인에 들어감)도 `used` 에 더한다(그 뒤 adopt 대상). 사용 값을 못 읽은 것은 남기기만 하고 `used` 에 넣지 않는다(지금 `current-bin` 규칙과 같음).
   - 빈마다 감싸는 예외는 읽기 실패(`_Unknown`)만 — 프로젝트 바뀜(`guard` 의 오류)은 삼키지 않고 그 자리에서 멈춘다.
   - **건너뛴 빈(`not_seen`·`renamed`·`current`·`unreadable`)은 `used` 를 돌려주지 않는다** — 지금처럼 그 빈은 adopt 도 안 한다(사람이 들어가 있는 빈의 클립을 옮기지 않음).
   - 비게 된 빈은 **빈마다 바로 전에** 이름 경로 그대로·클립 0·하위 빈 0(엄격히 읽음, 읽기 실패는 '비었음' 아님) → `guard()` 와 지금 빈 읽기(그 빈이 지금 빈이면 안 지움) → **그 빈 하나만 `DeleteFolders`**. **빈 지우기 단계 시작 때 읽은 지금 빈(끝에 되돌릴 빈)은 단계 내내 어떤 경우에도 안 지운다** — 앞 빈을 지우면 리졸브가 지금 빈을 부모로 옮겨, 단계 시작 때 사람이 들어가 있던 빈이 뒤 순서의 '지금 빈' 검사를 통과해 버리기 때문(Codex·별도 Claude 6차 P2). `DeleteFolders` 는 든 것까지 지우므로 여러 빈을 확인한 뒤 한 번에 지우면 앞 빈 확인 뒤 사람이 넣은 클립까지 지울 수 있다(독립 리뷰 1·2차 P1) — 빈마다 확인 직후 지우는 지금 `unstage delete_empty` 와 같은 보호. 대가 = 빈마다 지운 뒤 첫 읽기(0.1~0.2초). 끝나고 트리를 한 번 훑어 사라진 빈만 `bin_deleted`(훑기 실패면 모두 false — 기억을 남기는 쪽).
   - **빈을 지운 뒤 다빈치 지금 빈을 처음 자리로 되돌린다(끝에 한 번)** — 11-12 mv test 실측: `DeleteFolders` 는 사람이 다른 빈(형제)에 있어도 지금 빈을 **지운 빈의 부모로 옮긴다**(`DeleteClips` 는 안 옮김). 그대로 두면 새 에피소드 컷 빈에 있던 사람이 앞 에피소드 빈으로 끌려간다(지금 `unstage delete_empty` 길도 같은 문제 — 옛 길 실측에서 다빈치가 들어가 있던 빈까지 지워졌다). 빈을 하나씩 지우는 동안 지금 빈은 앞 에피소드 빈(지운 빈의 부모)으로 옮겨 가 있지만, 사람이 그사이 지울 빈에 들어가면 지금 빈 = 그 빈이라 걸러진다. 빈 지우기 전에 읽은 지금 빈 객체로 `SetCurrentFolder` 뒤 되읽어 확인, 못 되돌리면 `restore_failed`(빈별 결과·지운 수는 그대로) — 화면은 알리고 쓴 것 옮기기는 이어 간다.
   - 지운 클립은 ID 를 못 읽는다(11-12 실측) — 후보의 ID 는 지우기 전에 적어 둔 값으로 센다.
   - 에피소드 빈은 지우지 않는다(지금과 같음).
   - 프로젝트가 바뀌면(`guard`) 그 자리에서 멈추고 오류로 끝난다. 그 전에 지운 클립은 지워진 채다(쓰인 것·사람 것은 애초에 후보가 아님).
2. **HTTP `POST /api/resolve/panel/settle`** — 이 창이 target 으로 받은 그 컷의 빈만 넘긴다(`panel.cut_bin`, 모르는 ID 는 `not_seen` 으로 빼고 자식에 안 넘김) · **같은 빈 ID 는 한 번만** · 에피소드 빈으로 기억한 ID(`_episode_roots`)와 지금 에피소드의 컷 빈(`_episode_bins` — `remember_episode` 가 target 마다 비우고 새로 채우는 '지금 에피소드'만, 코드로 확인)은 빼고 `episode`/`current_episode` 로 돌려줌 — 이 빼기는 **쓰기 잠금 안(`before_write`, 자식 띄우기 직전)에서 한 번 더** 한다(그사이 잠금을 먼저 잡은 target 이 막 기억한 빈을 지우지 않게) · `expect_project` · 쓰기 잠금·`mutation_scope` 는 다른 쓰기와 같음 · 지운 빈은 `panel.forget_bin`.
3. **화면** — `settleEpisode` 는 컷마다 돌던 `currentBin`+`unstage` 대신 `settle` 한 번. 그 뒤 쓰인 것만 항목마다 `adopt`(NAS 로) — 실패는 알림에 모으고 다음 항목으로. 부르기 전과 adopt 사이마다 A→B→A(그 에피소드를 다시 골랐는지)를 본다. 빈 표가 없는 한 컷 정리(`settle` 함수)는 그대로.
   - **진행 중인 settle 하나(자식 1개, 짧음)는 끝까지 돈다.** 그 사이 A 를 다시 고르면, A 의 리졸브 쪽 작업(target·미리 띄우기)은 화면 대기열에서 settle 이 끝난 뒤 돈다 — 지워진 A 의 빈은 target 이 다시 만들고 미리 띄우기가 이 PC 캐시에서 다시 채운다. 쓰인 것·사람 것은 어떤 순서로도 안 지워지므로 이 틈은 '다시 채우는 시간'만 든다.

## 결정

- **빈을 클립째 지우지 않고(Del 키) 클립을 먼저 지운 뒤 빈 빈만 하나씩.** `DeleteFolders` 는 클립이 든 빈도 통째로 지워 사용 확인을 건너뛴다(기존 함정 노트). 안 쓴 클립은 한 번에 사라지지만 **빈 빈은 빈마다 확인 직후 하나씩** 지워 짧은 간격으로 차례로 사라진다(6차 — 빈당 시간은 실측으로, Jay 확인 몫). 한 번에 지우는 B안은 앞 빈 확인 뒤 사람이 넣은 클립까지 지울 수 있어(독립 리뷰 P1) 기본으로 두지 않는다.
- **쓴 것 NAS 옮기기를 지우기 뒤로.** 쓰인 클립은 어느 순서든 안 지워진다. 옮기기 실패가 그 컷의 안 쓴 클립 정리를 막지 않는다(전에는 막았음) — 이 PC 경로로 남은 쓰인 클립은 [저장]의 마지막 검사가 잡아 저장을 막는다.
