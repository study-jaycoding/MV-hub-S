## 고칠 안(Claude 설계 v3 — Codex 사전 검토 `01a1b4dc` 1차 P1 2·P2 1, Claude 합의 검토 `71b73a6a` P2 2 반영)

**2-12 — 안쪽 문맥은 자기가 열지 않은 트랜잭션을 끝내지 않는다(공용 `db.py`).** `_get_connection_sqlite` 에서 풀 연결을 받은 직후 `owns = not (pooled and conn.in_transaction)` 을 기억한다. 정상 종료의 COMMIT 은 `owns` 일 때만. 예외 때 `owns` 가 아니면 ROLLBACK·풀 연결 폐기를 하지 않고 그대로 올린다(트랜잭션과 연결의 주인은 바깥 문맥 — 바깥이 예외를 받으면 지금처럼 ROLLBACK·폐기). 1회용 연결(명시 경로·풀 끔)은 늘 새 연결이라 지금과 같다. 안쪽이 스스로 연 트랜잭션(바깥이 autocommit 상태)은 지금처럼 안쪽이 끝낸다. 호출부(asset_backfill·asset_sync)는 고치지 않는다 — 바깥 `BEGIN IMMEDIATE` 가 끝까지 유지된다.
- 확인: 전체 백엔드 시험을 임시 추적(작업실에만, 커밋 안 함)으로 돌려 '바깥 트랜잭션 안의 안쪽 문맥'이 생기는 호출 지점을 모두 모은다 → 각 지점이 잠금 안에서 느린 IO(네트워크·큰 파일)를 하지 않는지 본다(지금은 안쪽 커밋 때문에 잠금이 일찍 풀리던 곳 — 고친 뒤엔 바깥 끝까지 쥔다). 결과는 아래 '추적 결과'에 적는다.

**2-5 — 활동 대조 스냅샷을 조회자 사이에서 나눠 쓴다.** `manage_tasks` 에 `_activity_snapshot(conn, project_ids)` 를 두고 두 호출 지점(작업 목록·과거 모드 프로젝트 목록)이 쓴다. 키 = (DB 경로, 프로젝트 id 튜플). 값 = (작업 표 캐시와 같은 `_task_cache_stamp()` 표식, 만료 시각, 스냅샷). 표식이 같고 10초 안이면 재사용, 아니면 계산하고 **계산 뒤 표식이 계산 전과 같을 때만** 저장(작업 표 캐시와 같은 규칙). 같은 키의 동시 계산은 기존 `_task_flight_lock` 으로 한 번만. 칸은 넣을 때 만료분을 지우고 최대 8칸. 조회자별 투영(`project_cuts`·`visible_activity_projects`)은 그대로라 응답은 지금과 같다.

**2-6 — `_forward` 가 조건부·압축 머리글을 오간다.** 요청에 브라우저의 `If-None-Match`·`Accept-Encoding` 을 그대로 싣는다. 응답(성공·HTTPError 모두, 304 포함)의 `ETag`·`Cache-Control`·`Vary`·`Content-Encoding` 을 되돌린다. 본문은 지금처럼 바이트 그대로라 압축 본문 + `Content-Encoding` 이 그대로 브라우저에 간다(허브는 풀지 않는다). `_forward_stream`(미디어·Range, identity 고정)은 그대로. 팀 목록(`/api/generations`)은 `_forward` 가 아니라 덧씌우는 경로라 영향 없음.

**2-9 — 알림 종의 건강 검사 결과를 짧게 기억한다.** `get_status` 의 두 건강 검사(1167·1244행)와 후보 판정(1230행)만 `_installation_health_cached` 를 쓴다. 키 = (설치 폴더, 기대 CLI 판, 설치 파일 표식) — 필수 파일·내장 python.exe/pythonw.exe·python*.dll·CLI 핀·package.json·node.exe·CLI 진입점·`runtime/python`·`Lib/site-packages` 폴더의 (경로, mtime_ns, 크기). **건강할 때만** 30분 기억하고, 미완료 설치 저널(`_unfinished_install`)은 매번 먼저 본다. 업데이트 시작(`start_update`)의 검사는 늘 새로 한다.

**2-10 — 활성화 판정을 파일 표식으로 기억한다(v2 — Codex 사전 검토 P1 2건 반영).** 표식 = 그 경로의 `os.lstat` (st_ino, st_dev, st_mtime_ns, st_size, st_mode, st_file_attributes). 사슬 표식 = 제어 파일에서 활성화 루트까지(포함) 각 경로의 표식, activated 면 저널에서 루트까지도. ① 전체 검사 **전에** 사슬 표식을 재고, 전체 검사가 normal·activated 를 내면 **다시 재서 전과 같을 때만** (환경값 3개, 사슬 표식들, 결과)를 기억한다 — 검사 중 활성화 도구가 파일을 바꾸면 기억하지 않는다(Codex P1: 읽은 직후 draining 으로 교체되면 새 표식에 옛 normal 이 붙는다). ② 다음 호출은 환경값이 같고 **사슬의 모든 경로**의 lstat 표식이 기억과 같을 때만 그 결과를 쓴다 — 조상 폴더를 옮기고 그 자리에 연결점을 만들면 그 조상의 lstat(파일 번호·재분석 지점 속성)이 달라져 전체 검사로 간다(Codex P1: 말단 파일 표식만으로는 못 본다). 다르거나 lstat 실패면 지금 전체 검사. **blocked 는 기억하지 않는다**(매번 전체 검사 — 풀림이 바로 보이게). 제어 파일은 루트 바로 아래라 적중 때 lstat 은 사슬 길이만큼(제어 2 + 저널 2~3)이고 resolve·JSON 읽기는 없다.

**2-13 — 중계·실시간 브리지의 설정 읽기를 스레드로.** `_forward`·`_forward_stream` 은 `await asyncio.to_thread(lambda: (base_url(), token()))`. `remote_realtime` 의 비동기 경로(`_run`·`_wait_until_config_change`·`_wait_or_config_change`·`_consume`)는 `await asyncio.to_thread(self._read_config)` 로 부른다(`_read_config` 자체는 그대로 — 시험·동기 호출 호환).

**2-14 — 허브의 필터 훑기 페이지를 키운다(v3 — Claude 합의 검토 P2 반영).** `_team_local_filtered_for_account` 의 서버 페이지를 첫 200 에서 시작해 이어 받을 때마다 두 배(200·400·800, **상한 800**)로. 상한을 2000 이 아니라 800 으로 둔 것은 공유 서버가 목록 응답을 압축하는 동안 이벤트 루프를 잡기 때문이다(`list_gzip.py` 머리말 실측: 200행 6.86MB·레벨 2 중앙 26.5ms → 800행 약 0.1초, 2000행이면 약 0.27초로 추정 — Claude P2). 종료 조건 '서버 소진'은 **그 회차에 요청한 크기**와 비교한다(지금 상수 200 비교를 그대로 두면 큰 페이지에서 일찍 멈추지 않는다). 결과(`matches[:limit]`)·커서 전진·안전 상한(`MAX_FETCHES`)·옛 서버 503 은 그대로. 촘촘한 필터는 첫 200에서 끝나 지금과 같고, 희소한 필터만 왕복 수가 준다(팀 6천 행이면 30 → 9).

**2-15 — Comfy 결과 저장이 스스로 라이브러리 신호를 낸다.** `ws.manager` 에 `bind_loop`/`unbind_loop`(lifespan 에서 `agent_signals` 와 같은 자리)와 `notify_mutation_threadsafe(account_uid)`(묶인 루프에 `call_soon_threadsafe`, 루프 없으면 생략)를 둔다. `_save_canvas_run` 이 이번 호출에서 새로 저장한 출력 수를 세고, 기존 `finally` 안에서 settle 한 **뒤 그 수가 1 이상이면** 계정 범위(`acct:<owner>`, AUTH off 는 None — `realtime_scope` 와 같은 규칙)로 보낸다 — 출력 1을 저장하고 출력 2에서 예외가 나 `_mark_run_failure` 가 삼키는 부분 저장도 신호가 나간다(v3 — Claude 합의 검토 P2: try/finally 밖에 두면 이 경우가 빠지고, 지금은 ack 가 메우던 경우다). HTTP 경로(`/save`)에서 불려도 같은 알림이 디바운스로 합쳐진다. 그러면 `canvas-runs/ack` 의 synced 는 중복이라 '라이브러리 안 바꿈' 경로에 넣는다(묶음 1 결정의 다시 볼 조건 "Comfy 결과 저장이 스스로 라이브러리 신호를 낼 때" 충족).

**2-4 — 바뀐 것이 없는 계정 보고는 synced 를 내지 않는다(처리는 매번 그대로, v2 — Codex 사전 검토 P2 반영).** `record_account_status` 가 '보이는 변화'를 돌려준다. 같은 `BEGIN IMMEDIATE` 트랜잭션 안에서 쓰기 **전후**의 (a) hf_status 원문, (b) 보고에 든 워크스페이스들의 등록부 행(id·name·plan_type·credits), (c) 이 계정의 워크스페이스 멤버 행 전부(workspace_id·creator_uid·user_role·is_selected·is_available)를 비교해 하나라도 다르거나 (d) 자동 편입이 행을 하나라도 넣으면 참. 등록부는 여러 계정이 같이 쓰는 값이라 원문이 같아도 다른 계정의 보고가 그 사이 바꿔 놓은 값을 이번 보고가 되돌릴 수 있다(Codex P2: A 100 → B 80 → A 100 재보고). last_seen_at·그날 잔액 표는 비교하지 않는다(라이브러리 화면 값이 아님). 옛·불완전 보고(workspaces 가 list 아님)는 원문 비교만. `_ingest_core` 는 라우터가 넘긴 notes 에 (첫 신원 연결을 했는가, 상태 보고가 바뀌었는가)를 적는다. account-report 라우트는 둘 다 아니면 `request.state.library_unchanged = True`(묶음 2-A 장치). 원문 비교라 잔액이 바뀐 보고도 지금처럼 신호한다 — 똑같은 보고가 반복될 때만 조용해진다. 편입·잔액 기록·워크스페이스 갱신은 매번 그대로(11-07 기각안 '같은 보고 건너뛰기'와 다르다 — 처리는 하고 알림만 뺀다).

## 남는 위험·확인할 것

- 2-12: 지금 안쪽 커밋으로 잠금이 일찍 풀리던 곳은 고친 뒤 바깥 끝까지 쓰기 잠금을 쥔다 — 추적 결과로 잠금 안의 느린 IO 가 없는지 확인한다. 안쪽 예외를 바깥이 잡고 계속 쓰는 코드는 이제 같은 트랜잭션 안에서 계속된다(지금은 안쪽이 롤백·연결 폐기 — 바깥이 닫힌 연결을 쓰게 되던 상태).

- 2-6: 브라우저 HTTP 캐시가 작업 표를 개인 캐시에 둔다(서버가 이미 `private, no-cache` 로 보냄 — 허브 경유도 같아진다).

## 추적 결과(2-12)

- 방법: 작업실 기준 사본(프런트·문서 제외)의 `db.py` 에만 임시 추적을 넣어 백엔드 전체 시험을 돌렸다(커밋 안 함). 시험은 연결 풀을 끄므로(`conftest.py` `CONTENT_HUB_DB_POOL=0`) 풀 연결 비교 대신 **스레드마다 열린 연결 사슬**에서 트랜잭션이 열린 채 새 문맥이 들어오는 순간을 기록했다(첫 추적은 풀 조건으로 잡아 0건이었다 — 시험 환경 함정). 8,673 통과(실패·오류 24 = 빠진 문서·프런트 파일 때문, 이번 추적과 무관).

- 잠금 시간: 세 바깥 경로의 `BEGIN IMMEDIATE` 안에는 DB 문장·설정 읽기·같은 볼륨 파일 이름 바꾸기(`_settle` 의 `os.replace`)·파일 존재 확인뿐이고 네트워크·큰 파일 복사는 없다(복사·해시는 트랜잭션 전). 고친 뒤 쓰기 잠금을 바깥 끝까지 쥐어도 느린 IO 를 잡지 않는다. ②도 같은 버그였다 — 안쪽이 `asset_location` 쓰기를 먼저 커밋하고 outbox 쓰기는 문장마다 커밋됐다.
- 원래 버그 재현: 새 시험 `test_db_nested_transaction.py` 5개 중 4개가 고치기 전 코드에서 실패(자산 보충 `_queue` 의 잠금 풀림 포함), 고친 뒤 5개 통과.
