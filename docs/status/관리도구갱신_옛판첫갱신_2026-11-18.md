## 설계안 (추천 A)

**A. 새 관리 창이 `server_tls` 없이도 한 번은 뜨게(첫 갱신용), 두 번째 갱신부터 정상.** 고치는 곳은 `tools/server_console/` 안만.

1. `install.py`·`server_api.py`·`status.py`·`ui.py`: `import server_tls` 를 `try/except ModuleNotFoundError` 로 — 없으면 `None`.
2. 모듈이 없을 때의 보수적 판정 함수 하나(`server_console` 안): 같은 폴더 규칙(`MVHUB_SERVER_TLS_DIR` 또는 `%PROGRAMDATA%\MVHub\server-tls`)에서 `server.pem`·`server.key` 는 `stat`, `promote.pending` 은 `lstat` — **셋 다 '없음'(FileNotFoundError)으로 확인될 때만** 'off'. 하나라도 있거나, 폴더를 못 정하거나, 확인 중 다른 오류(PermissionError 등)면 'error'(로그인·켜기/끄기 등 TLS 를 타는 동작은 "관리 도구를 한 번 더 갱신하세요"로 거절). HTTPS 를 HTTP 로 잘못 보는 길은 없고, 정상 TLS 를 잠깐 막는 쪽으로만 틀린다. 지금 운영 서버는 HTTPS 꺼짐이 배포 전 확인 항목이라 대부분 'off' 길.
3. `status.read_ready`·`server_api` 요청: **요청할 때마다** 위 판정을 다시 한다(지금 server_tls.read_config 를 요청마다 부르는 것과 같은 시점). 'off' 면 http 경로 — 지금처럼 프록시 없음·리다이렉트 거절(`server_tls.opener` 의 HTTP 쪽과 같은 처리), 'error' 면 지금처럼 `tls_config_error`.
4. `ui.py` 인증서 만료 표시: 모듈 없으면 표시하지 않음.
5. `console.py`: APP_MODULES 에서 `server_tls` 를 필수에서 빼고 '있으면 code_root 의 것이어야 함' 검사로(없으면 통과, 다른 위치면 기존처럼 3). `console_run.py` 이사 도구 쪽은 원래 루트 도구 경로를 쓰므로 그대로 두되 모듈 없음에 안전한지 확인.
6. 표시 둘을 나눈다: (가) 모듈 없음 — 관리 창 머리에 "HTTPS 도구가 아직 없습니다 — 다음 main 판으로 [관리 도구 갱신]을 한 번 더 하세요"(TLS 꺼짐이어도 늘 보임) (나) TLS 오류 — 지금 `tls_config_error` 문구 그대로.
7. 시험(`backend/tests/test_server_console.py` 쪽): ① **옛 PATHS 로 첫 stage 생성 → 게시 → 그 stage 의 새 관리 창으로 다음 SHA 갱신 → 그 stage 에 `tools/server_tls.py` 가 실제로 들어 있음**(최우선, Codex) ② 옛 PATHS stage(server_tls.py 없음)에서 `console.py --install-root … --check` 가 0 ③ 모듈 없음 + TLS 파일 하나라도 있음 / 접근 거부 / 끊어진 `promote.pending` 링크 → error·로그인 거절 ④ 요청 직전 설정 변경(창을 연 뒤 인증서가 생김) → 다음 요청이 error ⑤ 'off' HTTP 경로의 프록시 없음·리다이렉트 거절 ⑥ server_tls 가 code_root 밖에서 로드되면 여전히 3 ⑦ 두 selfcheck 도우미 그대로 통과 ⑧ 새 PATHS stage 는 지금과 같음.
8. 반영: 관리 창 갱신은 **origin/main 을 직접** 꺼내므로 앱 릴리스는 필요 없다. A 판이 main 에 들어간 뒤(커밋 X) 서버에서 [관리 도구 갱신] → 새 관리 창(모듈 없음 표시) → **그다음 main 커밋 Y(기록 문서 한 줄 병합이라도)** 뒤 [관리 도구 갱신] 한 번 더 → server_tls 포함 32개. 같은 SHA 로 두 번 누르면 31개 stage 를 재사용하므로 소용없다.

**B(기각 후보). server_tls 를 server_console 패키지 안으로 옮기고 tools/server_tls.py 를 얇은 껍데기로** — 지문 목록에 든 파일 내용이 바뀌어 서버 업데이트 검사 위험, 루트 도구 import 경로 영향.

**C(기각 후보). 관리 창 패키지에 TLS 읽기 사본** — 같은 규칙 두 벌, 어긋날 위험. A 의 2번은 '파일 있음/없음'만 보는 보수적 판정이라 사본이 아니다.
