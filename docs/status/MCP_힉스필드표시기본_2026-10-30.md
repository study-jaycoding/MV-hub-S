## 설계 (어댑터 `server.py` 만 — 백엔드·허브 변경 없음, native 에만 적용)

1. **표시 계획을 어댑터가 계산한다(`higgsfield_display`)** — native 의 `wait_results`·`get_result`·`get_generation` 응답에 붙인다. 항목마다:
   - **위젯 대상**: `generation_status == "done"` 이고 `display_context.origin_job_id` 가 UUID 이며 `display_context.status` 가 `asset_missing`·`unavailable`·
     `not_ready`·`origin_missing` 이 아님(영상·여러 장 `media_not_verified` 포함 — 위젯은 작업 전체를 보이므로 `asset_index` 는 무시).
   - **MV 대신 보이기 대상**: done 이고 위젯 대상이 아니며 `asset_missing` 도 아님 — `origin_missing`·`unavailable`(옛·가져온 기록처럼 만든 이 정보가 비어
     허브가 원본 번호를 안 주는 경우)·`display_context` 없음(구형 허브)·origin 이 UUID 아님. 지금 MV 그림으로 보이던 완료 결과가 안 보이게 되지 않도록.
   - **글만**: done 이 아님(실패·취소·진행·미확인) 또는 `asset_missing`(그릴 미디어가 없음).
   - **wait_results**: `{"tool": "show_generation_by_ids", "jobs": [{index: item_index, job_id}...], "fallback": {"tool": "show_results",
     "item_indexes": [...]}, "card_only_item_indexes": [...]}`.
   - **get_result(plan_id, item_index)·get_generation**: 위젯 대상이고 `mv_preview=false` 일 때만 붙인다 — `jobs=[{index: get_result 는 그 item_index ·
     get_generation 은 0, job_id}]`, `fallback={"tool": 같은 도구, "arguments": 같은 조회 인자(get_result 는 plan_id·item_index·asset_index,
     get_generation 은 generation_id·workspace_scope·workspace_id·asset_index) + "mv_preview": true}` — **wait_seconds 는 넣지 않는다**.
     `mv_preview=true` 이거나 위젯 대상이 아니면 표시 계획을 붙이지 않는다(실행할 위젯 지시가 MV 그림과 함께 가지 않게).
   - native 응답의 `display_context` 에서 옛 지시 `tool`·`arguments`·`note`·`access` 를 지운다. conversation 응답은 그대로.
   - **실제로 위젯 계획에 들어간 항목에만**(wait_results 의 jobs 항목 · get_result·get_generation 은 위젯 대상이고 `mv_preview=false`) 맨 위 `note`(허브의
     "show_results로 결과를 확인하세요")를 "힉스필드 위젯(show_generation_by_ids)으로 표시하세요." 로 바꾸고, card_text 끝에 한 줄
     "그림이 안 보이면 'MV 미리보기로 보여줘'라고 말씀해 주세요." 를 붙인다. `mv_preview=true` 응답은 기존 MV 미리보기 안내 그대로.
2. **지침(native)**: 결과 표시는 기본 힉스필드 위젯이다.
   - 계획은 모든 항목이 끝날 때까지 wait_results 로 기다린 뒤, 그 계획의 `higgsfield_display.jobs` 를 모두 모아 `show_generation_by_ids` 를 **한 번** 부른다
     (계획 최대 20 ≤ 도구 상한 60). 그 항목들엔 show_results 를 부르지 않는다.
   - 응답 `jobs` 에서 `status == "lookup_failed"` 인 항목만 대신 보인다(계획 → `show_results(그 item_indexes)`, get_result·get_generation → `fallback` 호출).
     찾은 항목(완료·실패 상태 포함)은 대신 보이지 않는다.
   - 힉스필드 도구가 도구 목록에 없으면 도구 검색으로 불러온 뒤 판단하고, 그래도 없거나 호출 전체가 오류면 위젯 대상 전부를 대신 보인다(안내 포함).
   - `fallback.item_indexes` 는 처음부터 show_results 로, `card_only_item_indexes` 는 card_text 만.
   - **show_results 는 한 번에 8개까지** — 계획의 대신 보이기 대상이 8개를 넘으면 8개씩 나눠 부른다(위젯 호출은 계획당 한 번 그대로).
   - 같은 대화에서 이미 위젯으로 보인 job 은 단순 재조회·재연결로 다시 부르지 않는다. 사용자가 다시 보여 달라고 하면 다시 부른다.
   - 한 결과에 힉스필드 위젯과 MV 그림을 함께 내지 않는다 · MV 의 MCP Apps 화면은 열지 않는다 · MV ID·폴더를 힉스필드 ID 로 쓰지 않는다.
   - 삭제: "사용자가 힉스필드 표시를 명시적으로 고른 경우에만" · "외부 연결 계정·워크스페이스·공유 폴더 권한을 먼저 확인"(→ 위젯 응답으로 판단).
3. **`get_generation`·`get_result`(native)**: 새 인자 `mv_preview: bool = False`(native 에만 등록). 위젯 대상이고 `mv_preview=false` 면 MV 그림(ImageContent)을
   넣지 않고 `higgsfield_display` 와 card_text 만. `mv_preview=true` 이거나 위젯 대상이 아니면 그림 표시는 지금과 같다(유효한 미리보기가 있으면 그림, 없으면
   상태 안내 — 표시 계획은 붙이지 않음).
4. **`show_results`(native)** = MV 미리보기 경로: 대신 보이기 또는 사용자가 MV 미리보기를 원할 때. 동작은 그대로, 설명만 native 용으로.
5. **도구 설명은 모드별로 등록**(`server.tool(description=...)`) — 공통 지침 본문의 "선택 때만" 문장도 모드별 분기로 옮긴다.
   **conversation(Codex) 연결은 서버 지침·도구 목록(이름·설명·입력 형식·주석)이 바뀌기 전과 같다** — 바뀌기 전 코드로 잰 지문을 시험에 고정한다.
6. `ADAPTER_VERSION` → `2026.10.30.1`. 이 기록은 기능 정본 `docs/MCP_INTEGRATION.md` 에서 링크한다(`docs/README.md`·`CURRENT_STATUS.md` 는 다른 세션의
   미커밋 변경이 있어 건드리지 않는다 — 앞 작업과 같은 방식).

## 제외

- 백엔드·허브(`_display_context` 등) 변경 · Codex(conversation) 표시 변경 · MV 자체 MCP Apps 결과 카드 되살리기 ·
  힉스필드 커넥터 설치·로그인 자동화 · 설치본·팀 배포(MCP 단독 업데이트는 별도 지시 때) · `docs/README.md`·`CURRENT_STATUS.md` 수정.

## 위험

- 지침은 LLM 이 따르는 글이라 호출 순서를 코드로 강제하지 못한다(계산은 어댑터가 하지만 부르는 것은 LLM) → 실사용 확인 조건.
- 힉스필드 커넥터 계정·공간이 MV 생성 계정과 다르면 `lookup_failed` → 그 항목만 MV 그림(실측한 응답 모양 기준).
- 위젯 호출이 성공해도 화면 표시는 보장되지 않는다(휴대폰 Claude 앱 미확인) → card_text 끝의 "MV 미리보기로 보여줘" 안내로 사람이 되돌릴 길을 둔다.
- 영상·여러 장 결과의 위젯 표시는 실측 전(이 DB 에 표본이 있으면 확인, 없으면 미확인으로 남긴다).
