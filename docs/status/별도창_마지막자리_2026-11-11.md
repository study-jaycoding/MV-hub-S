# 별도 창은 마지막으로 닫은 자리에서 다시 뜬다 (2026-11-11)

owner: Claude · reviewer: 없음(화면 자리만 바꾸는 작은 변경 — 빠른 수정) · status: 검증 중 · updated: 2026-11-11

- 할 것: 별도 창(Assets·관리·캔버스·Agent)이 닫힐 때(`pagehide`) 자기 자리(`screenX/Y`)와 바깥 크기(`outerWidth/Height`)를 브라우저 저장소에 적고, 다음에 열 때 그 값으로 연다. 적은 값이 없거나 이상하면(최소화된 창의 -32000 등) 지금 자리.

## 실측 (11-11, 숨은 데스크톱 · 진짜 앱처럼 `--app` 만, 크롬 157.0.8103.38 · 엣지 157.0.4341.42)

스크립트는 세션 스크래치 `winpos\probe_popup_rect.py`(저장소 밖). 창을 CDP 로 각 모니터에 옮겨 놓고(사용자가 끌어 놓은 것 흉내) 읽은 값으로 닫았다가 다시 연다.

- **크기는 바깥 크기다**: `window.open` 의 `width=540,height=880` → 바깥 540×880(안쪽 524×841). 안쪽 크기를 적으면 다시 열 때마다 16×39 씩 줄었다(3차). 바깥 크기로 적으면 그대로(4차).
- **같은 모니터는 그대로**, **옆 모니터는 끌려온다**: 오른쪽 2800 → 1940(주 모니터 오른쪽 끝), 왼쪽 -1200 → 0. 크롬·엣지 같다. 둘 다 `window-management` 권한 상태 = `prompt`.
- **'여러 화면 창 배치' 허락이 있으면 세 모니터 모두 그대로**(크롬, CDP 로 허락). 끌려온 채 연 뒤 허락되면 연 창이 `moveTo` 로 정확히 옮겨진다(크롬·엣지 모두, 오른쪽·왼쪽).
- **진짜 X 와 같은 `WM_CLOSE` 로 닫아도 `pagehide` 가 자리·바깥 크기를 정확히 적는다**(크롬·엣지, 오른쪽 2800·왼쪽 -1200).
- 1·2차는 실측 스크립트 탓으로 무효: 1차 = 다시 연 창 대신 메인 창을 읽음, 2차 = `--window-position/--window-size` 를 주면 모든 새 창이 그 자리·크기로 가서 `window.open` 값을 무시한다(진짜 앱 `_spawn_app_window` 는 이 옵션을 쓰지 않는다).
- 그래서: 적은 자리가 메인 창이 있는 모니터 밖이면 창을 열기 **직전에**(누른 흔적이 남아 있을 때) `getScreenDetails()` 로 허락을 묻는다. 창은 끌려온 자리로 먼저 뜨고, 허락되면 그 자리로 옮긴다. 한 번 허락하면 다음부터는 바로 그 자리에 뜬다. 막으면 브라우저가 다시 묻지 않고 끌려온 자리 그대로(같은 모니터는 그래도 마지막 자리).
- 미확인: 브라우저가 묻는 창이 실제 앱 창에서 잘 보이는지(CDP 허락은 묻는 창을 건너뛴다) — Jay 5173 확인. 배율이 다른 모니터(이 PC 는 주 모니터 배율 1)의 크기 환산.
