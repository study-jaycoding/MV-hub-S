# Slack 알림 — 서버 복구 문서에 복원 순서와 사본 띄우기 주의를 넣는다 (2026-11-06)

Slack 코멘트 알림 dev 통합 기록([Slack알림_2026-11-05.md](Slack알림_2026-11-05.md) §20 '남은 일')의 문서 후속. Jay 11-06 "Slack 넣고 다시 점검"으로 이번 배포 후보에 Slack 이 들어가, 배포 전에 넣는다.

넣는 것(`docs/SERVER_RECOVERY.md` 한 곳, 예비 PC 복구 절차 끝의 주의 상자 다음):

1. **J8 — 손으로 DB 파일을 덮거나 `server_move_import.bat --install`(파일 설치라 DB 세대값이 백업 값 그대로 — `tools/server_move.py` 에 세대 갱신 없음, grep 확인)로 같은 서버 PC 에 되돌릴 때의 순서**: 관리 창 Slack [일시 멈춤] → 서버 끄고 복원 → 켠 뒤 [다시 켜기]. 다시 켜기는 '이 시각 전 코멘트는 안 보냄' 기준을 지금으로 옮기고 미발송 줄을 닫는다. 지키지 않으면 최근 30분 안 코멘트 알림이 한 번 더 갈 수 있다 — Jay 11-05 J8 "추천대로"(받아들인 위험 + 문서 한 줄). 앱의 가져오기·복원 길(`_install_db`)은 DB 세대값이 바뀌어 자동으로 닫히므로 이 순서가 필요 없다.
2. **사본 띄우기 주의**: 배달부는 `CONTENT_HUB_READ_ONLY=1` 일 때만 꺼진다(`backend/app/main.py` 시작 단계). 서버 PC 에서 백업 사본을 읽기 전용 없이 띄우면 그 사본이 봇 토큰을 풀어 DM 을 보낼 수 있다. 공식 드릴(`tools/verify_backup_restore.py` → `restore_runtime_verify`)과 쉬운 이전 도구의 검증 서버는 이미 `READ_ONLY=1` 이다. 토큰은 서버 PC 기계 범위로 암호화돼 다른 PC(예비 PC)에서는 안 풀린다 — 예비 PC 로 복구하면 배달부는 돌지 않고, 관리 창에서 토큰을 다시 등록해야 알림이 다시 간다. 이것을 코드로 막는 것은 따로 합의할 일이다(Slack 기록 §20 Claude 합의 세션 지적 ②).

확인한 코드(읽기만): `main.py` 의 `if not READ_ONLY: slack_notifier.start()` · `config.py` `READ_ONLY = CONTENT_HUB_READ_ONLY` · `services/restore_runtime_verify.py`·`services/isolated_env.py`·`tools/server_move_easy.py` 의 `CONTENT_HUB_READ_ONLY: "1"` · `services/slack_client.py` 가 `comfy_team_key.protect/unprotect`(machine scope DPAPI)를 쓰고 못 풀면 `undecryptable`(배달부 무동작) · 관리 창 단추 이름 `tools/server_console/slack.py`(등록 / 교체 · 토큰 지우기 · 일시 멈춤 · 다시 켜기).
