## 3. 설계

**한 줄**: 화면은 끌어온 파일·붙인 캡처를 프롬프트와 같은 업로드로 올려 **지금 레퍼런스 칩**(`imp/cap`)으로 넣는다. 보낼 때 **그림 칩의 1024px 썸네일**을 받아 차례에 함께 싣고, 허브는 검사만 해서 저장하지 않고 CLI 에 그림으로 넘긴다(Claude = stream-json 그림 블록, Codex = `--image`). 레퍼런스로 생성에 쓰는 길은 지금 그대로(AI 의 정확히 찾기 → 핸들).

### 3-1. 화면(Claude 구현)

- **파일 끌어오기**: `acceptsDrag` 에 OS 파일(`dataTransferHasFiles`)을 더한다. 놓을 때 순서는 지금 형식이 먼저(어셋 탭의 OS 끌기는 파일 + `x-ch-asset` 이 같이 오므로 어셋 칩) → 지금 형식이 없고 파일만 있으면 `filesFromDataTransfer` → `referenceDropTypeFromFile` 로 거른 뒤 남은 칸 수(8 − 지금 칩)만큼만 `api.uploadReferenceFiles(files, 목적지)`. 거른 것·넘친 것은 지금 안내 줄("N개는 붙일 수 없어 뺐어요"·"8개까지").
- **Ctrl+V**: 입력칸 `onPaste` — 클립보드에 그림이 있으면 기본 동작을 막고 `api.uploadCapture(blob, 목적지)`(captures). 글자 붙여넣기는 그대로. 프롬프트처럼 **길게 누른 Ctrl+V 의 반복은 막는다**(입력칸 keydown 에서 `repeat` + Ctrl/⌘+V 를 그림 붙여넣기 뒤 키를 뗄 때까지 무시, 창 흐림에서도 풂).
- **목적지**(Claude 합의 1차 P2-2): 프롬프트(`SpotlightPrompt.tsx:231-232`)처럼 `{target_project_id: 지금 화면의 project(=앱 필터의 프로젝트 id, 있을 때), target_workspace_id: 팀 공간이면 그 id}` 를 넘긴다 — 허브가 이 값으로 서버 보관을 예약한다(`assets.py:1316-1325`). 올린 뒤 프롬프트처럼 `notifySpotlightAssetsChanged` 로 어셋 창에 알린다.
- **올리는 동안**: 놓거나 붙이는 즉시 회색 칩(도는 점, 둘째 줄 "올리는 중")을 넣어 8개 상한에 든다. 성공하면 그 칩을 `{kind: "asset", project: "imp/cap", path: "captures|imports/<path>", name}` 칩으로 바꾸고(같은 자료가 이미 있으면 회색 칩만 뺌), 실패하면 회색 칩을 빼고 "그림을 올리지 못했어요" 한 줄. 업로드 결과 project 가 내장 두 폴더가 아니면 받은 그대로 쓴다.
- **늦은 업로드 답**: 시작 때 계정·공간·칩 비움 세대(지금 `resolveGeneration` 과 같은 표)를 잡고, 셋이 그대로일 때만 칩에 넣는다(파일은 이미 imports·captures 에 있음 — 프롬프트와 같음).
- **공간 미확정**: 끌기는 지금처럼 덮개 "공간을 확인한 뒤 다시 끌어 주세요"(파일도 같은 규칙), 붙여넣기는 그 문장 안내만 하고 올리지 않는다.
- **칩 둘째 줄**(시안 A): 이미지 어셋 = "레퍼런스 · AI 가 봄" · 이미지 생성물 = "생성물 · AI 가 봄" · 영상 = "영상 · 자료로만" · 오디오 = "오디오 · 자료로만" · 폴더 = 지금 그대로 · 조회 전 생성물 = "생성물 · 확인 중" · 올리는 중 = "올리는 중". 칩에 `media`(image/video/audio)를 둔다 — 어셋은 끌기 값·업로드 응답의 type, 생성물은 조회한 `assets[0].type`. **`media` 는 칩에만 두고 보내는 `item` 에는 넣지 않는다**(허브의 엄격 모델이 모르는 필드를 422 로 막음 — Claude 합의 1차 P3-6).
- **보내기**: 올리는 중인 칩이 있으면 보내지 않고 "올리는 중인 그림이 끝나면 보낼 수 있어요". 보내는 순간의 칩 묶음에서 `media === "image"` 인 칩마다 1024px 썸네일(어셋 `assetThumbUrl(project, path, 1024)`, 생성물 `thumbOf(gen, 1024)` = 첫 장)을 받아 base64 로 싣는다 — **줄인 썸네일 주소(`/api/assets/thumb`·`/api/media-thumb`)일 때만**(관리 어셋처럼 원본 주소가 오면 받지 않음 — 허브의 크기 검사에 걸려 차례 전체가 막히지 않게, P3-8), 응답이 image/jpeg·png·webp·gif, 한 장 1,500,000 바이트·**붙인 순서대로 합쳐 6,000,000 바이트까지**(허브와 같은 숫자 — 넘친 그림부터 뺌, Codex 1차 P2-4), 모두 합쳐 10초 안. `media_type` 은 **응답의 형식(Content-Type)** 으로 정한다(어셋 썸네일은 늘 JPEG, 파일 이름은 .png 일 수 있음 — P3-7). **조회 중이라 종류를 모르는 생성물 칩**도 그림을 못 실은 것으로 센다(Codex 1차 P2-6). 못 실은 그림은 빼고 보낸 뒤 "N번 그림은 불러오지 못해 AI 가 보지 못했어요"(칩·식별자는 그대로 감 — AI 는 자료로는 안다). 그림을 받는 동안 다시 보내기를 막는다.
- **받는 사이 바뀜**(Codex 1차 P2-5): 그림을 받기 시작할 때 계정·공간·칩 비움 세대·대화 id 를 잡아 두고, 보내기(`chat.send`) 바로 전에 다시 본다. 하나라도 바뀌었으면 보내지 않는다(입력칸 글·남은 칩은 건드리지 않음).
- 중복 방지 서명(`useAgentChat.ts:733`)은 그대로 — 그림은 칩(식별자)에서 나오므로 같은 칩이면 같은 요청이다.

### 3-2. 보내기 계약(`POST /api/agent-chat/turns`) — Codex 구현

- 요청 몸에 `images: [{index, media_type, data}]`(기본 없음, 최대 8): `index` 0~7(`attachments` 의 몇 번째 칩의 그림인지), `media_type` 은 "image/jpeg"·"image/png"·"image/webp"·"image/gif", `data` 는 base64.
- **읽는 순서**(Codex 1차 P1-1·P2-2): 이 엔드포인트만 몸을 직접 읽는다 — ① 실제로 받은 바이트를 세며 **8,400,000 바이트에서 끊고 413**(Content-Length 가 없거나 거짓이어도, 몸을 되돌리지 않음) ② JSON 해석 ③ `images` 를 떼어 낸 나머지로 `TurnIn.model_validate` — 실패하면 기본 모양 그대로 `{"detail": [{loc, msg, type}]}` 인 422(**`input`·`ctx` 없음** — 기본 422 는 입력 전체를 되돌려 그림 base64 가 응답에 실린다) ④ 그림 검사(Pillow 는 `asyncio.to_thread` 로 — 이벤트 루프를 막지 않게, `verify()` 뒤엔 다시 열어 크기·형식을 읽음). 그 뒤는 지금 순서(모델·깊이·화면 정보 검사 → 차례 잠금 → 같은 열쇠 확인). 바뀌는 점: 인증(`_panel`)이 몸 읽기보다 먼저라 깨진 JSON 에도 인증 실패가 먼저 나온다(Claude 합의 3차 P3).
- 그림 검사(422 "N번 그림을 보낼 수 없어요" — 짧은 글만): 목록·항목 모양(엄격 — 모르는 필드 없음) · 그림이 있으면 `attachments` 도 있어야 함 · `index` < 붙인 자료 수·중복 없음·그 자료가 폴더가 아님 · 글자 수 2,000,004 이하 · `base64.b64decode(validate=True)` · 풀면 한 장 1,500,000 바이트·합쳐 6,000,000 바이트 이하 · 머리 바이트가 `media_type` 과 맞음(JPEG `FF D8 FF` · PNG `89 50 4E 47 0D 0A 1A 0A` · GIF `GIF87a`/`GIF89a` · WebP `RIFF????WEBP`) · **Pillow 로 열어 `verify()` 가 통과하고 실제 형식이 `media_type` 과 같으며 가로·세로 각 2,048 이하**(Codex 1차 P2-3 — 서명 뒤 쓰레기·큰 해상도를 막음. 화면이 보내는 것은 한 변 1,024 이하로 줄인 썸네일 — `thumbs.py:122` `thumbnail((w, w))`).
- **허브는 저장하지 않는다** — 허브 DB·사건·칸 기록·로그에 그림 바이트가 남지 않는다(`stored_attachments()` 그대로). 같은 열쇠 재전송은 지금처럼 저장된 차례를 돌려주고 그림은 버린다. 복원 기록·대화 기록 MCP 읽기에도 그림 없음.
- **CLI 자기 세션 기록에는 남는다**(Codex 1차 P2-8, 실측: Claude 세션 파일에 그림 블록 1개, Codex rollout 에 `data:image/png;base64` 2줄) — 대화를 이어 가려면 앞 차례 그림이 그 세션에 있어야 하므로 받아들인다. 칸에서 대화를 지우면 지금 정책대로 Claude 세션 파일은 지워지고 Codex 기록은 남는다(서랍 메뉴 설계 — 바꾸지 않음).

### 3-3. 허브 — CLI 에 넘기기(Codex 구현)

- `service.start_turn(…, images=[(index, media_type, bytes), …])`. `build_prompt` 는 붙인 자료 JSON 다음에 한 덩어리: "[함께 보낸 그림] 붙인 자료 N번(…)의 그림을 이 말과 함께 보냅니다 — 직접 보고 판단합니다. 그림이 없는 붙인 자료는 자료로만 받습니다. 생성 레퍼런스로 쓰려면 지금처럼 read_context 정확히 찾기로 핸들을 받습니다." 번호는 1부터(칩 번호와 같게).
- **Claude**: 그림이 있는 차례만 명령에 `--input-format stream-json` 을 더하고 stdin = 한 줄 `{"type":"user","message":{"role":"user","content":[{"type":"text","text":<프롬프트>}, {"type":"text","text":"붙인 자료 N번 그림"}, {"type":"image","source":{"type":"base64","media_type":…,"data":…}}, …]}}` + `\n`. 그림 없는 차례는 지금 그대로(글자 stdin). 이어 가기(`--resume`)와 같이 쓰는 것은 실측 2로 확인, 포크(`--resume X --fork-session`)는 구현 뒤 가짜 CLI 시험으로 확인한다(Codex 2차 P3-1).
- **Codex**: 그림이 있는 차례만 `config.AGENT_CHAT_DIR / "images" / <turn_id> / <N>.<jpg|png|webp|gif>` 에 쓰고 — 새 대화는 `--image <경로>` 를 `-C` 앞 옵션에, 이어 가기는 `resume --image <경로> … -- <id> -`(실측 4). 그 폴더는 차례가 끝날 때(성공·실패·중단·시간 초과·시작 실패 모두) 지운다 — 폴더를 만든 직후부터 실행 스레드가 맡기 전까지의 예외(부분 쓰기 실패 포함)도 그 자리에서 지운다. **보장 범위 = 정상 끝은 즉시 삭제, 허브가 죽으면 다음 실행에서 회수**(Codex 1차 P2-7): 허브 시작 때와 **그림 차례를 시작할 때마다** **1시간보다 오래된** `images/*` 만 지우고, **허브 시작 때 한 번 더 정리를 예약**한다(65분 뒤 한 번 도는 daemon 타이머 — 시작 때 1시간이 안 돼 건너뛴 폴더도 그 뒤 그림 차례가 없어도 회수, 허브 종료 때 취소, Codex 2차 P2-7). 시작 정리·예약은 서비스 생성자가 아니라 `main.py` lifespan 시작에서 부르는 메서드로(모듈을 불러오는 시험·도구 프로세스가 돌리지 않게 — Claude 합의 4차 P3), 다시 부르면 앞 타이머를 먼저 취소한다(시험이 lifespan 을 여러 번 돌림) — 설치본(8010)·dev(8012) 허브가 `AGENT_CHAT_DIR` 를 같이 쓰므로(`config.py:123-124`) 다른 허브가 막 시작한 차례의 그림을 지우지 않게(Claude 합의 1차 P2-1, 차례 최대 10분 `agent_chat.py:35`). 프롬프트에 "첨부 그림 순서 = 붙인 자료 N번…".
- **출력 해석기**: Codex 해석기는 모르는 항목 종류를 위반으로 판정한다(`agent_chat_parse.py:170-171`) — 그림 차례에 새 종류가 나오지 않는지 구현 뒤 실측에서 `--json` 사건 종류를 확인한다. Claude 해석기는 모르는 종류를 무시하고 입력을 되돌려 보여 주는 옵션도 쓰지 않는다.
- 그림 바이트·base64 를 로그·예외 글에 넣지 않는다.
