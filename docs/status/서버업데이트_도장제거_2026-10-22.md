# 서버 업데이트에서 검사 도장(source receipt) 확인을 뺀다 — 2026-10-22

owner: Claude 총괄(설계·구현) · reviewer: Codex(사전 검토·독립 리뷰, 읽기 전용) · status: 승인(독립 리뷰 통과·dev 커밋, main·서버 반입은 게이트 뒤 Jay) · touched_paths: 아래 계약 · updated: 2026-10-22

## 왜

Jay(10-22 21시대): "그냥 업데이트깃하면 바뀌게해라 왜 절차를 더만든거야?" → "검사돌려서 이상 없는것만 배포하면 되자나. 굳이 도장을 안만들어도 되자나." → (확인서 유지 + NAS 계정 한 번 저장 / 확인서 빼기 두 갈래와 비용을 설명한 뒤) **"빼라. 그러면 그냥 업데이트 되는거지?"**

지금 서버 `update_git.bat` 은 선택 커밋의 배포 전 게이트 source-only 기록(도장)을 NAS 에서 가져와야만 진행한다. 서버 관리자 창은 NAS 자격 증명이 없어 그 기록을 못 읽는다(Jay 서버에서 `Test-Path` False). 검사 통과 판만 main 에 올리는 것은 배포 절차(릴리스 PC 게이트 → 통과한 SHA 만 main)로 지키고, 서버는 도장 없이 main 을 받는다.

## 설계

1. `tools/run_update_git.ps1` — 서버 역할에서 도장 반입을 없앤다: `-SourceReceipt` 인자·`MVHUB_SERVER_SOURCE_RECEIPT`·`logs\server-update.local.json`·`Get-SelectedCommit`·`Import-ServerReceipt`·`Read-UpdateBytes`·`Get-BytesSha256`·`Write-RemoteChangeNote` 제거. coordinator 호출은 `--root`·`--verification-python` 만. UAC 자기 재실행·검증 Python 자동 준비(`-VerificationPython`/환경변수 우선)는 그대로.
2. `tools/server_release_update.py` — `--source-receipt` 인자와 도장 읽기·검증(`validate_source_receipt` 호출 3곳, 준비 중 도장 변경 검사) 제거. stage 설명서(`server-stage.json`)에서 `source_receipt_sha256` 제거. 자격 기록에서 `source_receipt_sha256`·`source_receipt_raw`·`checks.source_validation` 제거, profile 을 `server-source-v2` 로 올린다. 깨끗한 트리·선택 커밋 호환 선언·stage 격리 빌드·소스 입력 불변 검사·격리 기동 검사(fresh data)·CLI 확인·설명서 지문은 그대로.
3. `tools/server_activation.py`(상주 supervisor) — `verify_qualification` 에서 도장 대조(168·172–174·179행) 제거, `SOURCE_PROFILE = 'server-source-v2'`(v1 기록은 거부 — 서버에는 아직 stage 가 없어 영향 없음), 호출자가 없어지는 `validate_source_receipt`·`SOURCE_STEPS` 삭제. 도장 검증 안에만 있던 **필수 소스 입력 검사(`stage_source_inputs_missing`)는 따로 떼어** prepare(빌드 전)와 `verify_qualification` 에서 계속 부른다(Codex 지적). stage 소스 불변 대조(175–178행)·도구 지문·CLI·런타임 증명·rollback_decision·legacy 호환 기록은 그대로.
4. `tools/publish_server_receipt.py` 삭제(쓰는 곳 없음). 그 시험도 삭제. NAS `server-receipts` 폴더는 남겨 두되 쓰지 않는다.
5. 문서 `docs/SERVER.md` 정기 업데이트: 릴리스 PC 게이트 → 통과한 SHA 만 main → 서버 `update_git.bat` 더블클릭(UAC 예). `docs/CODE_MAP.md` 항목 갱신.

**잃는 것**: 서버가 스스로 '이 커밋이 전체 시험을 통과했다'를 확인하지 않는다(통과 판만 main 에 올리는 절차가 대신). **남는 안전장치**: 별도 stage 에 만들고 격리 기동으로 확인한 뒤 supervisor 가 바꿔 끼우고, 실패하면 DB 호환 판단으로 자동 복귀.

**서버 반입**: supervisor 코드가 바뀌므로 이번 한 번은 서버에서 수동 반입(fetch·SHA 확인·`merge --ff-only`·프런트 빌드·`restart_server_task.bat` — Jay 운영 단계, 에이전트가 검증용으로 실행하지 않음) 뒤 더블클릭 실측. 반입 직전에 서버에 `logs\server-current.json` 이 **없는지** 확인한다(있으면 v1 stage 를 가리킬 수 있어 새 supervisor 가 거부 — 멈추고 판단, Claude 합의 세션 지적).

**구현 메모** — 필수 소스 입력(`REQUIRED_SOURCE_INPUTS`)에서 `tools/predeploy_gate.ps1`·`tools/validation_result.ps1` 은 뺐다: 도장 게이트용이던 파일이라 서버 실행에 필요 없고, 남기면 그 두 파일을 옮기거나 지울 때 서버 업데이트가 멈춘다(Claude 합의 세션 지적). 남은 7개 = `backend/app/main.py`·`backend/serve.py`·`backend/schema.sql`·`backend/requirements.lock.txt`·`frontend/package.json`·`frontend/package-lock.json`·`hf_cli_version.txt`. 도장 전용이던 시험(도장 내용·변조·줄바꿈 대조·선언 묶음·다른 커밋 도장·자동 반입·원격 변경 안내)은 지우고, 인자 인용 시험은 `-VerificationPython` 으로 옮겼다.

**검증·독립 리뷰** — 시험 기록 9개 전부 종료 0(지문 `2ae796f2…`): 진입 12 · 준비 40 · supervisor 36(+1 skip) · v2 재시작/이전 v2 복귀·v1 거부 2 · 기존 묶음 78 + 238(+1 skip) · lint_docs·check_code_map(빠짐 0)·gen_inventory --check. Codex 독립 리뷰(새 세션 `01a163b0-63df-7d01-93fa-22d6ad48694c`, 도구 0회) **통과** — 결함 없음, 단서: 실제 서버의 포인터 부재·UAC·전환은 반입 때 확인. `guard check --stage integrate` 통과.
