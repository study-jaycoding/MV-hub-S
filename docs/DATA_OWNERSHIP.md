# 데이터 소유권과 실행 모드 기준

> 리아키텍처 중 데이터를 잘못된 저장소로 보내지 않기 위한 기준 문서다.
> API·저장·동기화 코드를 바꾸기 전에 이 문서와 `신원과_모드_가이드.md`를 함께 확인한다.
>
> 최종 확인: 2026-08-05. 근거: `backend/app/routers/_proxy.py`, `backend/app/db.py`,
> `backend/app/active_account.py`, `backend/app/deps.py`, `backend/tests/test_proxy_ownership.py`.

---

## 1. 핵심 원칙

MV Hub는 브라우저와 서버 하나로 끝나는 일반 웹앱이 아니다. 사용자의 PC가 **로컬 허브**로서
파일·CLI·개인 작업을 소유하고, **공유 서버**는 계정·권한·팀 데이터를 소유한다.

```text
브라우저
  └─ 로컬 FastAPI 허브
       ├─ 로컬 소유: 개인 DB·파일·CLI·Comfy·씬·실행 큐
       └─ 서버 소유: 계정·권한·팀 공유·PM 데이터 → 공유 서버로 위임
```

소유권은 "어디서 API 요청을 받는가"가 아니라 **어디의 데이터가 최종 정답인가**로 판단한다.
로컬 라우터가 요청을 받은 뒤 팀 항목만 공유 서버로 다시 위임하는 하이브리드 경로도 있다.

---

## 2. 실행 모드

| 모드 | 판정 | 데이터 처리 |
|---|---|---|
| 로컬 단독 | `CONTENT_HUB_AUTH=0`, 공유 토큰 없음 | API와 개인 데이터를 현재 PC에서 처리 |
| 로컬 프록시 | `CONTENT_HUB_AUTH=0`, 공유 토큰 있음 | 로컬 전용 경로는 현재 PC, 나머지는 공유 서버로 위임 |
| 공유 서버 | `CONTENT_HUB_AUTH=1` | 다계정 SQLite와 RBAC를 서버가 직접 처리 |
| 격리 테스트 | `CONTENT_HUB_NO_PROXY=1` | 저장된 공유 토큰이 있어도 외부 서버 위임 차단 |

`_proxy.is_local_path()`는 로컬 프록시 모드에서만 의미가 있다. `_LOCAL_PREFIXES`와
`_LOCAL_EXACT`에 없는 `/api/*` 요청은 기본적으로 공유 서버로 전달된다.

## 3. 데이터 소유권 표

| 데이터·기능 | 최종 정답 | 설명 |
|---|---|---|
| 로그인 계정·승인 상태·전역 역할 | 공유 서버 DB | `/api/auth/*`, `/api/members/*`의 팀 계정 정보 |
| 팀 프로젝트 정의·프로젝트 역할 | 공유 서버 DB | 프로젝트 이름·보관·멤버·역할은 팀 공통 |
| 내 비공개 생성물·히스토리·개인 메타 | 계정별 로컬 SQLite | `data/db/acct/<계정>/content_hub.db` |
| 팀에 발행된 생성물·공유 댓글 | 공유 서버 DB | 로컬 허브가 팀 항목을 조회·수정할 때 서버로 재분기 |
| 색·태그·자동 태그 | 계정별 로컬 SQLite | 내 카드 메타와 남의 팀 카드에 대한 개인 overlay 모두 로컬 |
| 생성 요청·에이전트 상태·실행 큐 | 로컬 허브 DB/메모리 | 실제 Higgsfield CLI가 있는 PC에서만 처리 |
| CLI 모델·비용·계정·워크스페이스 | 로컬 PC의 CLI | 공유 서버로 위임하지 않음 |
| Comfy 설정·실행·결과 저장 | 로컬 PC | 이 PC의 Comfy/Cloud 연결과 디스크를 사용 |
| 에셋 원본·마운트·트리·썸네일 | 로컬 파일 시스템 | 파일 I/O를 공유 서버에 위임하지 않음 |
| 에셋 댓글 등 팀 메타 | 공유 서버 또는 로컬 | `assets` 라우터가 항목 성격에 따라 명시적으로 재분기 |
| 씬 원본 | 브라우저 `localStorage` | 현재 편집본의 정답 |
| 씬 백업 | 계정별 로컬 SQLite | 캐시 소실 복구용 미러이며 공유 서버로 보내지 않음 |
| 미디어 캐시·다운로드·병합 | 로컬 파일 시스템 | 원격 바이트를 이 PC에 저장·가공 |
| ComfyUI 연결·실행 (`/api/comfy`) | 로컬 | 이 PC 의 로컬/Cloud Comfy 자원 — 서버 위임 금지 |
| DaVinci Resolve 전송 (`/api/resolve/`) | 로컬 | Render 원본 저장·Resolve 제어 — 이 PC 디스크/앱 대상 |
| 릴리스 업데이트 (`/api/release-update/`) | 로컬 | 이 PC 의 설치본·프로세스를 교체 |
| PM 작업·일정·팀 통계·크레딧 | 공유 서버 manage DB | 팀 공통 관리 데이터 |
| PM 프로젝트 폴더 연결 | 로컬 허브 DB | 각 PC의 렌더 경로와 연결되는 로컬 정보 |
| 완료본 판정·원본 바이트 | 공유 서버 | 팀이 판정한 최종본과 원본 조회 권위 |
| 완료본 실제 파일 저장 | 로컬 파일 시스템 | NAS·렌더 폴더에 쓰는 작업은 현재 PC에서 실행 |
| 로컬 DB 내보내기·가져오기 | 계정별 로컬 SQLite | 서버 DB를 통째로 교체하는 경로가 아님 |
| 작업자 DB 백업 세트 | 로컬 원본 + 공유 서버 계정별 복제본 | 로컬 `content + trash`를 세트로 전송한다. 서버 저장 계정은 요청 이메일이 아니라 검증한 세션으로 정하며, 공유 `manage` DB는 작업자 세트에 포함하지 않음 |

프로젝트 목록과 생성물 목록처럼 **하이브리드 응답**도 있다. 예를 들어 프로젝트 정의는 서버에서
받지만, "내 로컬 생성물 개수"는 로컬 DB에서 계산해 합칠 수 있다. 이 경우 usecase가 두 출처의
결합 규칙을 소유하고 router나 repo 한쪽에 숨기지 않는다.

## 4. 생성물 식별자 경계

| 값 | 용도 | 금지 사항 |
|---|---|---|
| `generation.id` | 한 DB 안의 정식 행 ID·FK·로컬 API 식별자 | 외부 Higgsfield job ID라고 가정하지 말 것 |
| `generation.job_id` | Higgsfield 멱등 키·로컬/서버 간 같은 결과물 상관관계·팀 확인 키 | 로컬 DB의 FK나 행 ID로 직접 쓰지 말 것 |
| `creator_uid` | 생성물 작성자·소유권 | `worker_id`와 혼용하지 말 것 |
| `worker_id` | 작업 PC/워크스테이션 | 사람 작성자 판정에 쓰지 말 것 |
| `email` | 로그인 계정과 계정별 DB 폴더 키 | 생성물 작성자 ID로 직접 쓰지 말 것 |

현재는 레거시 호환 때문에 로컬 DB와 공유 서버에서 같은 생성물이 서로 다른 `generation.id`를 가질
수 있다. 이때 양쪽에 보존되는 `job_id`를 경계 상관관계와 `ack_key`로 사용한다. 단, 한 DB 안의
조회·FK·수정은 항상 `generation.id`로 수행하고 경계 변환은 `repo/id_resolve.py`에 모은다.

반드시 지킬 규칙:

1. `id == job_id`를 가정하지 않는다.
2. `job_id`가 없는 Comfy·로컬 생성물의 폴백 동작을 유지한다.
3. 로컬 ID와 서버 ID를 직접 바꾸지 않고 기존 resolve helper를 사용한다.
4. ID 통합 마이그레이션은 `DESIGN_id_unification.md`의 호환 단계와 백업 검증 없이 진행하지 않는다.

신원 헬퍼의 상세 선택 규칙은 `신원과_모드_가이드.md`를 따른다.

## 5. 변경 체크리스트

API·저장·동기화 코드를 바꿀 때 아래를 모두 확인한다.

1. 이 데이터의 최종 정답이 로컬인지 공유 서버인지 적었다.
2. 새 API가 로컬 전용이면 `_LOCAL_PREFIXES`/`_LOCAL_EXACT` 분류를 확인했다.
3. 하이브리드 경로라면 router가 아니라 usecase에 결합 순서를 두었다.
4. 로컬 파일·CLI·Comfy 작업이 공유 서버로 프록시되지 않는다.
5. 테스트에서는 임시 DB와 `CONTENT_HUB_NO_PROXY=1`을 사용한다.
6. `generation.id`와 `job_id`를 같은 값으로 가정하지 않는다.
7. 프록시 소유권이 바뀌면 `test_proxy_ownership.py`의 골든 목록을 의도적으로 갱신한다.
