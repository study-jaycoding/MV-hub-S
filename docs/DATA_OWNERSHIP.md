# 데이터 소유권과 실행 모드 기준

> 리아키텍처 중 데이터를 잘못된 저장소로 보내지 않기 위한 기준 문서다.
> API·저장·동기화 코드를 바꾸기 전에 이 문서와 `신원과_모드_가이드.md`를 함께 확인한다.
>
> 근거: `backend/app/routers/_proxy.py`, `backend/app/db.py`,
> `backend/app/active_account.py`, `backend/app/deps.py`, `backend/tests/test_proxy_ownership.py`.

## 1. 핵심 원칙

저장 통합 1C-1은 기존 `app_setting.share_db_generation`을 복원 세대로 재사용한다. 공책 시작·동기화·닫기, 옛 씬 미러, 카드 소속, 편집 백업·복원은 해당 DB 쓰기 트랜잭션 안에서 세대를 먼저 검사한다. 누락은 `restore_generation_required`, 불일치는 `restore_generation_changed`(409)이며 업무 행·영수증을 바꾸지 않는다. 읽기 응답의 본문·기준판·세대는 같은 읽기 트랜잭션에서 얻는다.

복원 세대가 달라도 편집 문서와 옛 미러의 원본 소유권은 브라우저에 있다. 원문·제어 자료를 복구 후보로 남기고 자동 전송을 멈춘다. 출처 대응은 SHA-256 지문이며, 편집 복구 원문은 보류 시점·전송 중 원문만 남기고 후속 편집을 누적하지 않는다. 공책은 브라우저 상태를 원자적으로 보관한 뒤 허브 상태를 채택한다. 다만 세대 기록 없는 깨끗한 기준판은 문서별로 현재 세대를 채택하고 이후 새 편집만 저장한다. 공책의 깨끗한 채택은 보관본을 만들지 않으며 다른 저장 경로의 대기열을 재개하지 않는다. 이는 1C-1 구현 계약이며, `[되돌리기]`·로컬 세트 복원 입구(1C-2)와 1-C 전체 완료를 뜻하지 않는다. [합의 기록](status/저장통합_1C_복원세대_2026-11-13.md)을 따른다.

MV Hub는 브라우저와 서버 하나로 끝나는 일반 웹앱이 아니다. 사용자의 PC가 **로컬 허브**로서
파일·CLI·개인 작업을 소유하고, **공유 서버**는 계정·권한·팀 데이터를 소유한다.

```text
브라우저
  └─ 로컬 FastAPI 허브
       ├─ 로컬 소유: 개인 DB·파일·CLI·Comfy·씬·실행 큐
       └─ 서버 소유: 계정·권한·팀 공유·PM 데이터 → 공유 서버로 위임
```

소유권은 "어디서 API 요청을 받는가"가 아니라 **어디의 데이터가 최종 정답인가**로 판단한다.
로컬 라우터가 요청을 받은 뒤 팀 항목만 공유 서버로 다시 위임하는 하이브리드 경로도 있다.

## 2. 실행 모드

| 모드 | 판정 | 데이터 처리 |
|---|---|---|
| 로컬 단독 | `CONTENT_HUB_AUTH=0`, 공유 토큰 없음 | API와 개인 데이터를 현재 PC에서 처리 |
| 로컬 프록시 | `CONTENT_HUB_AUTH=0`, 공유 토큰 있음 | 로컬 전용 경로는 현재 PC, 나머지는 공유 서버로 위임 |
| 공유 서버 | `CONTENT_HUB_AUTH=1` | 다계정 SQLite와 RBAC를 서버가 직접 처리 |
| 격리 테스트 | `CONTENT_HUB_NO_PROXY=1` | 저장된 공유 토큰이 있어도 외부 서버 위임 차단 |
| 격리 개발(`test_dev.bat`) | `CONTENT_HUB_AUTH=1` + `CONTENT_HUB_NO_PROXY=1` | 다계정이지만 '공유 팀 서버'가 **아니다**(`is_shared_team_server()=False`, `routers/_proxy.py`) — 비공개 코멘트 저장 허용 |

`_proxy.is_local_path()`는 로컬 프록시 모드에서만 의미가 있다. `_LOCAL_PREFIXES`와
`_LOCAL_EXACT`에 없는 `/api/*` 요청은 기본적으로 공유 서버로 전달된다.

## 3. 데이터 소유권 표

| 데이터·기능 | 최종 정답 | 설명 |
|---|---|---|
| 로그인 계정·승인 상태·전역 역할 | 공유 서버 DB | `/api/auth/*`, `/api/members/*`의 팀 계정 정보 |
| 팀 프로젝트 정의·프로젝트 역할 | 공유 서버 DB | 프로젝트 이름·보관·멤버·역할은 팀 공통 |
| 내 비공개 생성물·히스토리·개인 메타 | 계정별 로컬 SQLite | `data/db/acct/<계정>/content_hub.db` |
| 팀에 발행된 생성물·공유 댓글 | 공유 서버 DB | 로컬 허브가 팀 항목을 조회·수정할 때 서버로 재분기 |
| 공유 명령의 복원 세대 | 대상 content DB의 `app_setting.share_db_generation` | 초기화 시 기존 값을 보존하고 API 복원마다 회전한다. 새 명령은 받은 `db_generation`을 동결하며 서버는 적용 트랜잭션 안에서 대조한다. 이미 남은 receipt 재생은 허용한다. 필드 없는 구명령과 수동 파일 복원은 이 보호 범위 밖이다 |
| 비공개 코멘트(`is_private`) | 작성자 로컬 SQLite | 서버·번들로 나가지 않는다. 공유 팀 서버는 비공개 저장 요청을 거절(`routers/generation.py`·`assets_metadata.py`) |
| 슈퍼 관리자 세션 · 10분 elev 토큰 | 서버 DB(`super_admin_session`) · 로컬 `app_setting`(`shared_server_elev_token`) | 토큰은 로그아웃·계정 전환 시 삭제 |
| 업데이트 공지 후보·고정·읽음 | 공유 서버 DB(`release_update_notice*`) | 관리 쓰기는 서버 `Admin` 만 |
| 서버 이사 공지 수락 · 서버 표시명 | 로컬 `app_setting` | `services/shared_connection.py` |
| 감사 이벤트(`audit_event`) | 공유 서버 DB | 슈퍼 관리자 변경 등 |
| 색·태그·자동 태그 | 계정별 로컬 SQLite | 내 카드 메타와 남의 팀 카드에 대한 개인 overlay 모두 로컬 |
| 생성 요청·에이전트 상태·실행 큐 | 로컬 허브 DB/메모리 | 실제 Higgsfield CLI가 있는 PC에서만 처리 |
| CLI 모델·비용·계정 상태·현재 워크스페이스 선택 | 로컬 PC의 CLI | `/api/models`·`/api/cost`·`/api/account`·`/api/workspaces` — 공유 서버로 위임하지 않음 |
| 워크스페이스 등록부·멤버·해석·계정 보고 | 공유 서버 DB | `workspace_registry`·`workspace_member`(`repo/identity.py` `record_account_status`). `/api/workspaces/resolve`·`/api/account/hf` 는 프록시 모드에서 서버 위임 |
| Comfy 설정·실행·결과 저장 | 로컬 PC | 이 PC의 Comfy/Cloud 연결과 디스크를 사용 |
| 에셋 원본·마운트·트리·썸네일 | 로컬 파일 시스템 | 파일 I/O를 공유 서버에 위임하지 않음 |
| 자료 내용 ID·로컬 사본·업로드 대기열 | 반입 계정의 로컬 SQLite·파일 | 전체 SHA 기반 `asset_content_id`, `asset_blob`·`asset_location`·`asset_sync_outbox`. 로컬 즉시 사용, 목적 프로젝트/계정/연결을 고정한 영속 재시도. 별도 레퍼런스 DB를 만들지 않음 |
| 프로젝트 imp_cap 보관본·서버 위치 | 공유 서버 DB·명시 Assets 루트 | 서버가 바이트·권한을 확인한 뒤 `imp_cap/표시이름`에 확정. 같은 owner/project/root에서 중복 방지. 서버 원본은 권한 있는 전용 스트리밍 API로 읽고, 로컬 사본은 계정별 캐시. 기존 파일 API의 로컬 소유권을 전역 변경하지 않음 |
| 자료의 정식 위치 전환 | 서버 ready receipt → 기존 문서 포트 | 내용 ID·역할·생성 당시 입력은 고정하고 위치만 전환. 계정/프로젝트/서버/루트 문맥과 이전 위치를 대조. 씬·Undo는 공개 canvas 포트, 생성 정보·재생성·공유는 읽기 투영을 사용. 이미 접수한 실행 payload는 불변 |
| 에셋 댓글 등 팀 메타 | 공유 서버 또는 로컬 | `assets` 라우터가 항목 성격에 따라 명시적으로 재분기 |
| 씬 원본 | 브라우저 IndexedDB | 씬별 확정 저장본. 화면에 남은 미확정 편집과 구분한다([씬 저장 계약](CANVAS_SCENE_STORAGE.md)). ⚠️ 앱 창은 브라우저·설치 경로별 **전용 프로필**로 뜨므로(`run_agent_session.py` `_app_profile_dir`) 한 PC 에도 씬 원본이 여러 벌 존재할 수 있다. 로컬 허브에서는 **허브 공책**(쓰기 임대 `services/scene_writer.py`, 기본 켬·`CONTENT_HUB_SCENE_WRITER=0` 이면 끔)이 이 PC 브라우저들이 맞춰 보는 기준 사본을 계정 DB 에 둔다 |
| 씬 백업·허브 공책 | 계정별 로컬 SQLite | 본문 `scene_backup` + 공책 머리말·시작 작업·순서·보관본·요청 영수증 `scene_notebook*`. 공유 서버로 보내지 않음. 5MB 넘는 씬은 허브 사본이 안 된다(`sceneBackup.ts`). 삭제 미러는 **이 세션에서 로컬에 있던 씬**만 지운다 — 서버에만 있는 id 는 다른 프로필 것일 수 있어 건드리지 않는다 |
| 편집 타임라인 문서 | 현재 브라우저의 계정별 localStorage | 프로젝트·시퀀스별 편집 원본. 계정 DB 의 `edit_doc_head`·`edit_doc_copy` 에 2초 묶어 자동 보존·충돌 사본(1MB 넘는 문서는 보내지 않고 화면에 경고, `editDocBackup.ts`). DB 백업에 이 표가 포함되지만 미전송 편집·원본 미디어·Undo는 포함되지 않는다. 파일 보관·복원은 [EDIT_TAB](EDIT_TAB.md) 참조 |
| 편집 타임라인 Undo | 페이지 실행 중 메모리 | 새로고침하면 지워진다. 문서 파일 복원과 Undo 기록 복원은 다르다 |
| 미디어 캐시·다운로드·병합 | 로컬 파일 시스템 | 원격 바이트를 이 PC에 저장·가공 |
| ComfyUI 연결·실행 (`/api/comfy`) | 로컬 | 이 PC 의 로컬/Cloud Comfy 자원 — 서버 위임 금지 |
| DaVinci Resolve 전송 (`/api/resolve/`) | 로컬 | Render 원본 저장·Resolve 제어 — 이 PC 디스크/앱 대상 |
| 릴리스 업데이트 (`/api/release-update/`) | 로컬 | 이 PC 의 설치본·프로세스를 교체 |
| PM 작업·일정·팀 통계·크레딧 | 공유 서버 manage DB | 팀 공통 관리 데이터 |
| PM 미공유 생성 활동 | 기존 서버 `team_generation_fact` | 작업 행·상태·건수에 활용. 본인 또는 `read_all` 범위의 메타만 조회하며 원본·프롬프트 전송은 추가하지 않음 |
| PM 배치 활동 시각 | 실제 배치 변경을 처리한 콘텐츠 DB → 기존 관리 팩트/공유 번들 | nullable `task_activity_at`. 원래 생성일과 구분하며 조회·동기화 수신 시각으로 대체하지 않음. 명시 복원 외 과거 보관 유지 |
| PM 본인 미공유 미리보기 | 계정별 로컬 SQLite | `/api/manage/local-task-previews`는 로컬 전용. 본인·팀 공간·프로젝트·폴더 재검증, 서버 폴백/다운로드/변경 알림 없음 |
| PM 프로젝트 폴더 연결 | 로컬 허브 DB | 각 PC의 렌더 경로와 연결되는 로컬 정보 |

자료 보관 기능의 구현·검증·미확인 범위는 [ASSET_LOCAL_SYNC](ASSET_LOCAL_SYNC.md) §12가 기준이다.
DB 백업에는 새 표가 포함되지만 실제 미디어 바이트는 포함되지 않는다. 만료 가능한 업로드 허가는 내보내기 사본에서 제거한다.
`content_asset_sync.v1` 이관 기록을 모르는 구버전은 해당 DB를 열지 못한다. 구버전 롤백은 이관 전 DB 사본으로 해야 한다.
| 완료본 판정·원본 바이트 | 공유 서버 | 팀이 판정한 최종본과 원본 조회 권위 |
| 완료본 실제 파일 저장 | 로컬 파일 시스템 | NAS·렌더 폴더에 쓰는 작업은 현재 PC에서 실행 |
| 로컬 DB 내보내기·가져오기 | 계정별 로컬 SQLite | 서버 DB를 통째로 교체하는 경로가 아님 |
| 작업자 DB 백업 세트 | 로컬 원본 + 공유 서버 계정별 복제본 | 로컬 `content + trash`를 세트로 전송한다. 서버 저장 계정은 요청 이메일이 아니라 검증한 세션으로 정하며, 공유 `manage` DB는 작업자 세트에 포함하지 않음 |

프로젝트 목록과 생성물 목록처럼 **하이브리드 응답**도 있다. 예를 들어 프로젝트 정의는 서버에서
받지만, "내 로컬 생성물 개수"는 로컬 DB에서 계산해 합칠 수 있다. 이 경우 usecase가 두 출처의
결합 규칙을 소유하고 router나 repo 한쪽에 숨기지 않는다.

작업 목록의 새 미공유 활동 병합은 **실제 공유 팀 서버**에서 적용한다. 단독 로컬·격리 dev는
루프백 브라우저 검사 후 기존 콘텐츠 기반 개인/팀 미디어 표시를 보존한다. 이 경로는 이미
그 PC의 계정 DB에 있는 내용이며 원격에서 private 원본을 추가 수집하지 않는다. 서버 위임이
실패했다고 이 로컬 경로로 폴백하지 않는다. [작업 표시 계약](TASK_ACTIVITY_FACTS.md) 참조.

## 4. 생성물 식별자 경계

| 값 | 용도 | 금지 사항 |
|---|---|---|
| `generation.id` | 한 DB 안의 정식 행 ID·FK·로컬 API 식별자 | 외부 Higgsfield job ID라고 가정하지 말 것 |
| `generation.job_id` | Higgsfield 멱등 키·로컬/서버 간 같은 결과물 상관관계·팀 확인 키 | 로컬 DB의 FK나 행 ID로 직접 쓰지 말 것 |
| `creator_uid` | 생성물 작성자·소유권 | `worker_id`와 혼용하지 말 것 |
| `worker_id` | 작업 PC/워크스테이션 | 사람 작성자 판정에 쓰지 말 것 |
| `email` | 로그인 계정과 계정별 DB 폴더 키 | 생성물 작성자 ID로 직접 쓰지 말 것 |
| `fact:<관리행 UUID>` | PM 미공유 작업 메타의 표시 식별자 | 콘텐츠 변경·수동 연결·로컬 비활성 API에 사용 금지. 확인된 `local_gen_id`만 로컬 작업에 사용 |

현재는 레거시 호환 때문에 로컬 DB와 공유 서버에서 같은 생성물이 서로 다른 `generation.id`를 가질
수 있다. 이때 양쪽에 보존되는 `job_id`를 경계 상관관계와 `ack_key`로 사용한다. 단, 한 DB 안의
조회·FK·수정은 항상 `generation.id`로 수행하고 경계 변환은 `repo/id_resolve.py`에 모은다.

반드시 지킬 규칙:

1. `id == job_id`를 가정하지 않는다.
2. `job_id`가 없는 Comfy·로컬 생성물의 폴백 동작을 유지한다.
3. 로컬 ID와 서버 ID를 직접 바꾸지 않고 기존 resolve helper를 사용한다.
4. ID 통합 마이그레이션은 `DESIGN_id_unification.md`의 호환 단계와 백업 검증 없이 진행하지 않는다.

신원 헬퍼의 상세 선택 규칙은 `신원과_모드_가이드.md`를 따른다.

## 5. 변경 체크리스트

API·저장·동기화 코드를 바꿀 때 아래를 모두 확인한다.

1. 이 데이터의 최종 정답이 로컬인지 공유 서버인지 적었다.
2. 새 API가 로컬 전용이면 `_LOCAL_PREFIXES`/`_LOCAL_EXACT` 분류를 확인했다.
3. 하이브리드 경로라면 router가 아니라 usecase에 결합 순서를 두었다.
4. 로컬 파일·CLI·Comfy 작업이 공유 서버로 프록시되지 않는다.
5. 테스트에서는 임시 DB와 `CONTENT_HUB_NO_PROXY=1`을 사용한다.
6. `generation.id`와 `job_id`를 같은 값으로 가정하지 않는다.
7. 프록시 소유권이 바뀌면 `test_proxy_ownership.py`의 골든 목록을 의도적으로 갱신한다.
8. 사용자가 만든 것을 저장하는 새 자리라면 아래 §6 저장 지도의 분류·소유 범위에 넣고, 백업에 들어가는지 적었다.

## 6. 작업물 저장 지도 (2026-11-12 저장 통합)

§3 은 "로컬이냐 공유 서버냐"를, 이 절은 **로컬 안에서 어디에 두고 어떻게 지키나**를 정한다.
설계·근거·단계는 [저장 통합 설계](status/저장통합_설계_2026-11-12.md)(Claude·Codex 합의 4판)가 정본이다. 아래 "지금"은 11-12 코드 기준이고, "목표"는 그 설계의 단계가 끝난 뒤다.

### 6-1. 분류 — 무엇인가

| 분류 | 뜻 | 들어가는 것 | 목표 원본 | 백업 |
|---|---|---|---|---|
| 가. 작업물 | 잃으면 일이 사라짐 | 캔버스 씬 · 편집 문서 · 코멘트·그림 · MV Agent 대화 · 폴더 등록 · 회색(비활성) 표시 | 이 PC 허브 DB(또는 허브 폴더 파일) | 세트에 포함 |
| 라. 제어 자료 | 잃으면 옛 자료 재흡수·중복 요청·덮어쓰기 방지 붕괴 | 이관 완료 표식 · 기준판·요청 ID·삭제 의도 · 미전송 대기열 · 카드 제거·되살리기 대기열 · 충돌·업로드 실패 사본 · 공책 참여 전 보관본 | 작업물과 같은 계정 공간 | 작업물과 함께 |
| 나. 개인 설정 | 잃으면 불편함 | 테마·언어 · 창 위치·폭 · 필터·보기 · 단축키 · 리졸브 패널 선택 | 브라우저 | 없음 |
| 다. 임시 | 잃어도 됨 | 창 넘김 값 · 트리·썸네일 캐시 · 쓰기 임대 토큰 · 캔버스 되돌리기 기록 | 브라우저·메모리 | 없음 |

- 명시 보관·공유(`scene_keep`·`edit_share`)는 자동 원본·충돌 사본과 목적이 다르다. 자동 정리 규칙이 함께 지우지 않는다.
- 쓰다 만 초안(수정 창·코멘트·라이브러리 프롬프트 `libraryPromptDraft`)은 이번 범위 밖이다.

### 6-2. 소유 범위 — 누구 것인가 (백업 구성원·복원 대상의 기준)

| 범위 | 들어가는 것 | 계정 복원 때 |
|---|---|---|
| 계정 자료 | 콘텐츠·휴지통 DB(`data/db/acct/<계정>/`) · 그 계정 Agent 대화 DB · 그 계정 `asset_mounts.json` | 덮어씀(복원 전 보존본 먼저) |
| PC 공용 자료 | `manage_hub.db`(계정과 무관한 고정 경로, `manage_db.MANAGE_DB_PATH`) | 덮지 않음. 로컬 세트에 사본만 |
| 전송 제외 운영 상태 | 작업자 전송 상태 DB 등(`services/worker_backup.py` 머리말) | 세트에 넣지 않음 |

### 6-3. 작업물마다 지금 자리

| 작업물 | 지금 원본 | 사본·백업 | 걸리는 점 |
|---|---|---|---|
| 캔버스 씬 | 브라우저 IndexedDB `mvhub-scenes` | 허브 공책(`scene_backup`+`scene_notebook*`) → 로컬 백업 세트 | 5MB 넘는 씬은 허브 사본 없음 |
| 편집 문서 | 브라우저 localStorage `mvhub.editDoc:*` | `edit_doc_head`/`edit_doc_copy` → 세트 | 1MB 넘으면 안 보냄 · Undo 는 메모리 |
| 코멘트·그림 | 계정 DB(팀 것은 공유 서버) | 세트 | 쓰다 만 초안은 저장 안 됨 |
| MV Agent 대화 | `%LOCALAPPDATA%\MVHub\agent_chat\<허브>-<지문>-<계정>.db`(`config.AGENT_CHAT_DIR`) | **없음** | 저장 통합 1-B 에서 세트에 넣음 |
| 폴더 등록 | 계정 폴더 `asset_mounts.json` | **없음** | 1-B 에서 세트에 넣음 |
| 회색 표시 | 메인 앱 브라우저 localStorage(`deactivated.ts`, `ch.*` 키) | **없음** | 리졸브 패널에서 안 보임 · 계정 바꾸면 지워짐 → 5단계에서 내 PC 허브로(Jay J2) |
| 리졸브 패널 선택 | 패널 브라우저 localStorage | 없음 | 나. 개인 설정 |

로컬 백업 세트 = 콘텐츠·휴지통(한 시점 짝)·`manage_hub.db`·봉인 파일(manifest), 계정별 폴더 `backups/<계정>/`(`services/backup.py`). 공유 서버는 그중 콘텐츠·휴지통만 계정당 10세트 받는다(`routers/db_backup.py`). 보관 규칙·삭제 안전 계약은 설계 §4-3 이 정본이다.

### 6-4. 브라우저 키 이름 규칙 (새 키부터)

- `mvhub.<분류>.<기능>.<이름>`, 계정 범위는 끝에 `:<계정>` 하나로. 예: `mvhub.settings.library.view:<계정>`.
- 지금 접두사는 4종(`ch.` · `ch_` · `mvhub.` · 없음)이고, `ch.*` 는 계정을 바꿀 때 지워지는 숨은 규칙이 있다(`lib/personalSettings.ts`). 새 키는 위 규칙을 따르고, 계정 바꿀 때 지우는 대상은 "나. 개인 설정" 목록으로 명시한다 — 작업물·제어 자료는 지우지 않는다.
- 옛 키를 옮길 때 순서: 시작 표식(적혔는지 확인) → 옛 쓰기 차단 → 마지막 자료 포착 → 새 자리에 한 트랜잭션으로 확정 → 완료 표식(캔버스 흡수 `sceneStore.ts` 와 같은 방식).
