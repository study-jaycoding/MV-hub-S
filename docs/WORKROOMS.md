# 기능 작업실과 통합 시험실

<!-- BEGIN MVHUB POLICY workrooms 2026-10-15-r14 -->
## 공통 작업실 운영

1. 요청을 받으면 저장소 루트·브랜치·Git 상태와 관련 작업 기록의 담당자·경로를 확인한다. 기능의 기존 작업실을 우선 재사용하고, 없으면 승인 범위에서 만든다.
2. 새 작업실은 확인한 dev 기준 커밋에서 나눈다. 기존 기능 브랜치를 잇는 이유와 기준을 기록하고, dev 미커밋 변경을 일괄 복사하거나 몰래 커밋하지 않는다.
3. 담당 폴더·브랜치·수정 경로·확인 화면을 알리고, 담당자·관련 경로·기준 커밋·상태·확인 주소를 작업 기록에 남긴다. 기록으로 소유권을 확인할 수 없으면 해당 변경을 멈추고 충돌 범위를 보고한다. 다른 담당자의 경로와 겹치면 조율한다. 기존 세션·프로세스를 중단하거나 이동하지 않는다.
4. 작은 문서 수정은 충돌 없는 현재 폴더에서 처리할 수 있다. 읽기 전용 리뷰마다 새 작업실을 만들지는 않는다.

### 구현·통합·배포

- 작업실은 배포 선택 단위다. 기능별 소스·브랜치·포트·시험 데이터·브라우저 프로필을 분리한다. 브랜치 분리만으로 독립 배포가 보장되지는 않는다.
- 평소 수정은 논리적인 묶음별 구현·자기 검토·관련 시험을 한다. 위험 변경은 구현 전 설계 합의와 실사용 통합 전 독립 리뷰·필요 검증을 마친다.
  검토 범위·실패 처리·재검증은 [AGENT_WORKFLOW](AGENT_WORKFLOW.md)를 따른다. 검증 횟수를 이유로 실패를 통과시키지 않는다.
- 관련 확인을 통과한 커밋은 그 차례의 담당자가 통합 시험실 `codex/mvhub-integration`로 일반 병합한다.
  병합·검증·재시작은 한 번에 한 담당자만 한다. 소유권·진행 중 병합·미커밋 변경을 확인하며 불명확하거나 충돌하면 멈추고 조율한다. 기록은 기술적 잠금이 아니다.
- 통합 화면에는 병합한 소스가 반영된다. 미커밋 편집은 해당 작업실 화면에만 보인다. 실제 새 코드를 주는지 확인한 뒤 반영 완료라고 보고한다.
- 백엔드는 진행 중 생성·저장이 없음을 확인한 뒤 해당 프로세스만 수동 재시작한다. 불명확하거나 작업이 남으면 '백엔드 반영 대기'로 보고한다. `uvicorn --reload`는 쓰지 않는다.
  스키마·저장 형식 변경은 서버 시작 전에 대상 DB·자료의 최신 복구용 사본과 복구 범위를 확인한다. 옛 사본만 믿거나 원본 DB를 수동 초기화·임의 마이그레이션하지 않는다.
  새 화면과 기존 백엔드가 호환되지 않으면 함께 전환할 때까지 병합·활성화를 미룬다. 이미 반영됐다면 해당 기능 사용을 중지하도록 알리고 강제 종료·임의 롤백하지 않는다.
- 통합 문제는 원인 작업실에서 수정해 다시 병합한다. 통합 브랜치에서 제품 코드를 직접 고치지 않으며 통합 브랜치는 배포 원천이 아니다.
- 배포는 Jay가 고른 변경과 승인된 선행 의존성만 대상으로 한다. 후보 SHA와 원격 main을 고정하고 `origin/main..<후보SHA>`의 전체 포함 커밋을 확인한다.
  선택하지 않은 변경이 섞이면 임의 rebase/cherry-pick으로 떼지 않고 구성안을 보고한다. 여러 기능의 통합 시험으로 일부만 선택한 후보 검증을 대신하지 않는다.
  실제 후보의 깨끗한 작업 폴더에서 [Gate 6-A](RISK_REDUCTION_PLAN_2026-08-15.md)를 통과하고, 명시적인 병합·배포 권한을 따른다. 통합 성공은 자동 배포 승인이 아니다.

### 데이터·실행 경계

- 승인된 통합 실사용 모드만 기존 dev의 `backend/data_test`와 포트를 공유한다. 이는 사용자 데이터이며 폐기 가능한 격리 사본이 아니다.
  사용자 앱 실행·구체적인 요청에 따른 실제 생성은 허용한다. 에이전트의 임의 유료 시험·반복 대량 생성, 운영 공유 서버 쓰기는 허용하지 않는다.
- 자동 회귀·계약 검증은 별도 격리 사본에서 비용 없이 한다. 사본 차단 장치는 OS 샌드박스가 아니며 공유 서버·계정·전역 MCP 설정은 기존 안전선을 따른다.
- 이 PC의 통합 실사용 실행기는 통합 작업실의 `test_integration.bat`이며 dev와 한 번에 하나만 실행한다. 포트 검사는 원자적이지 않으므로 동시에 실행하지 않는다.
  격리 실행기는 파일이 실제 존재하는 작업실의 `test_workroom.bat`다. 정책 파일을 받았다는 이유만으로 실행기·의존성·자료가 준비됐다고 판단하지 않는다.
- 자료가 안 보이면 DB 사본과 미디어 준비 상태를 나눠 확인한다. 원본 DB 초기화·운영 폴더 전체 덮어쓰기 대신 승인된 준비 절차로 필요한 사본만 보완한다.
- 지침 파일 갱신은 실행 중 세션의 재로딩이 아니다. 다음 작업 전에 최신 지침과 버전을 다시 확인한다. 이 공통 정책과 아래 구현 당시 기록이 다르면 운영 판단은 이 정책을 따른다.

### 기존 통합 자료 복구 범위

통합 전 주 DB 사본 `data_test/db/content_hub.before-integration-20261015.db`는 주 DB 복구용이며 미디어·브라우저 저장소·전역 설정은 복구하지 않는다. MCP가 붙인 캔버스의 파일 복원은 MCP 처리 기록을 아는 통합실에서 한다. 이후 변경에는 새 사본이 필요하다.
