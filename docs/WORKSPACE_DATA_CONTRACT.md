# 워크스페이스 데이터 규격

## 목적

Higgsfield 생성 결과에는 워크스페이스 ID가 들어오지 않는다. MV-Hub는 생성 요청 또는 검증된
동기화 묶음이 알고 있는 워크스페이스를 별도 메타데이터로 저장한다. 기존 결과는 현재 선택값으로
추측하지 않으며 `unknown`으로 보존한다.

## 공통 컨텍스트

API 요청에서는 다음 객체를 사용한다.

```json
{
  "scope": "team",
  "id": "workspace-uuid",
  "name": "MILLIONVOLT"
}
```

- `team`: `id` 필수, `name`은 현재 귀속의 표시 이름 스냅샷
- `personal`: `id` 없음. CLI workspace unset 컨텍스트
- `unknown`: `id`, `name` 없음. 레거시 또는 검증되지 않은 데이터

DB와 조회 응답에서는 인덱싱하기 쉬운 평면 컬럼을 사용한다.

- `workspace_scope`
- `workspace_id`
- `workspace_name`

## 저장 위치

- `generation`: 현재 귀속 워크스페이스. 생성 요청값으로 시작하며, 사용자가 `##` 명령으로
  자기 카드의 잘못된 귀속을 명시적으로 보정할 수 있다.
- `gen_request.payload.workspace`: 대기 중 화면/CLI 전환과 무관하게 요청 당시 값을 보존한다.
- `project`: 프로젝트에 지정한 워크스페이스.
- `team_generation_fact`: 워크스페이스별 프로젝트·멤버·모델·기간 집계 차원.
- 공유 번들·휴지통: 위 세 필드를 그대로 보존한다.

## 멤버 등록부

CLI 1.1.23에는 조직 전체 멤버 조회 명령이 없다. 각 인증 계정의 에이전트가 보고한
`workspace list`를 합쳐 다음 테이블을 유지한다.

- `workspace_registry`: 워크스페이스의 마지막 이름·플랜·잔액 보고
- `workspace_member`: 계정별 접근 여부·역할·선택 상태·마지막 확인 시각

이 등록부는 “MV-Hub에서 확인된 멤버”이며 Higgsfield 조직 전체 명단과 동일하다고 가정하지 않는다.

등록부는 id 기준 upsert 만 하고 행을 지우지 않는다. 힉스필드에서 워크스페이스를
지웠다 다시 만들면 id 가 바뀌어 “이름은 같고 멤버 0명”인 유령 행이 남아 프로젝트
설정 드롭다운에 같은 이름이 2개로 보인다. 정리는 전용 스크립트로 한다(서버 PC,
저장소 루트에서):

```powershell
.\run_py.bat tools\cleanup_workspace_registry.py           # 미리보기(유지/유령 표)
.\run_py.bat tools\cleanup_workspace_registry.py --apply   # 실제 삭제
```

가용 멤버가 1명이라도 있거나 workspace_id 컬럼을 가진 어떤 테이블에서든 참조되는
행은 자동으로 보호된다(동적 스키마 스캔). 다른 DB 는 `--db <경로>`.

## 정합성 규칙

1. 불완전한 `team` 컨텍스트(`id` 없음)는 `unknown`으로 저장한다.
2. `personal`, `unknown`은 `workspace_id`를 가질 수 없다.
3. 기존의 확인된 워크스페이스는 구버전 클라이언트가 보낸 `unknown`으로 덮어쓰지 않는다.
4. 동기화가 기존 생성물과 다른 워크스페이스를 보고해도 조용히 바꾸지 않는다.
5. 레거시 생성물·프로젝트·관리 팩트는 무손실로 유지하고 워크스페이스만 `unknown`으로 추가한다.
6. 계정의 과거 `hf_status:<email>` 보고는 등록부가 비어 있는 항목만 1회 보강한다. 재부팅으로
   `last_seen_at`을 현재 시각으로 갱신하지 않는다.
7. `#+`/`#-`는 `##` 전역 모드에서 워크스페이스 적용/제거 목록을 여는 선택 명령이다. 사용자가
   워크스페이스 이름을 직접 입력하거나 Enter로 제출하는 경로는 제공하지 않으며, 일반 태그와
   전역 태그 테이블에도 어떤 행도 만들지 않는다.
8. `#+`는 라임색 적용 칩, `#-`는 빨간색 제거 칩으로 현재 계정이 접근 가능한 등록부 목록을
   보여준다. 칩을 선택하면 표시명이 아니라 등록부의 정확한 UUID를 변경 API에 전달한다. 같은
   표시명이 여러 UUID에 있으면 화면에 ID 뒷자리를 붙여 구분하며, 서버가 선택한 UUID와 다른
   결과를 돌려주면 변경을 시작하지 않는다. 이름만 보내는 구버전 요청은 고유한 이름만 허용한다.
9. 일괄 변경은 최대 500개이며, 없는 카드·남의 카드가 하나라도 있으면 전부 변경하지 않는다.
   프로젝트 소속은 거부하지 않고 **함께 옮긴다**(`repo/workspace_assignments.py`, 2026-08-21 `e53c8497`):
   `#+` 지정은 대상 워크스페이스의 활성 프로젝트가 정확히 1개면 그 프로젝트로 이동하고(`folder_path`
   초기화), 0개·여러 개면 다른 워크스페이스의 프로젝트 소속만 해제한다. `#-` 제거는 팀 프로젝트
   소속도 함께 해제한다(`folder_path` 초기화). 개인 프로젝트 소속은 건드리지 않는다.
   예외: 서버 본체에서 10분 슈퍼 관리자 권한(`X-MVHub-Super-Session`)이 검증되면 남의 카드도
   변경한다 — `creator_uid` 유지, 감사 기록([AUTH_FAILURE_SEMANTICS.md](AUTH_FAILURE_SEMANTICS.md) §5).
10. 명시적인 제거는 `unknown`이 아니라 `personal`로 저장한다. `unknown`은 동기화가 보강할 수
    있는 레거시 상태이므로 제거에 사용하면 다음 동기화에서 팀 귀속이 되살아날 수 있다.
11. 공유된 내 카드는 서버 복사본을 먼저 갱신한다. 서버 변경이 실패하면 로컬 변경을 시작하지
    않으며, 변경된 로컬 생성물은 관리 텔레메트리 재전송 대상으로 표시한다.

## 워크스페이스 필드를 하나 추가할 때 고칠 곳

이 문서(계약)를 먼저 고치고, 소유권이 바뀌면 [DATA_OWNERSHIP.md](DATA_OWNERSHIP.md) 도 함께 고친다.
그다음 코드는 아래 순서로 따라간다 — 하나라도 빠지면 값이 중간에서 조용히 사라진다.

| 층 | 파일 | 무엇을 |
|---|---|---|
| API 모델 | `backend/app/models.py` | 요청·응답 필드 |
| 정규화 단일 출처 | `backend/app/workspace_context.py` | 값 정규화·`unknown` 판정 |
| 코어 DB | `backend/schema.sql` + `backend/app/db_migrations.py` | 컬럼 + 기존 DB 마이그레이션 |
| 관리 DB | `backend/app/manage_db.py` | 관리 허브 쪽 스키마 |
| 읽기·쓰기 | `backend/app/repo/generations.py` · `backend/app/repo/generation_sync.py` | SELECT 목록·INSERT/UPDATE |
| 조회 응답 | `backend/app/repo/generation_rows.py` · `backend/app/repo/generations_query.py` | 카드 행 조립 · 메인 목록 SELECT |
| 소스 목록 | `backend/app/repo/sources.py` | 소스 패널 SELECT |
| 프로젝트 | `backend/app/repo/projects.py` | 프로젝트 범위 질의 |
| 공유·휴지통 | `backend/app/repo/share.py` · `backend/app/repo/trash.py` | 발행 번들·휴지통 복원 |
| 생성 요청 | `backend/app/repo/gen_requests.py` | 요청 큐 payload |
| 프런트 타입 | `frontend/src/types.ts` · `frontend/src/lib/workspaceContext.ts` | 타입 + 컨텍스트 조립 |
| 팀 집계 | `backend/app/repo/manage_telemetry.py` | `build_telemetry_facts` 의 **명시적 SELECT 컬럼 목록** — 여기 안 넣으면 팀 집계에서만 값이 사라진다 |
| 에이전트 | `agent_push.py` | 보고 payload |

> [!IMPORTANT]
> 이 표는 **자주 빠뜨리는 층**을 모은 것이지 전부가 아니다. 이 필드를 실제로 다루는 파일은
> 테스트·문서를 빼고도 **37개**다(2026-08-26). 작업 전에 파일 목록으로 전수 확인한다.
>
> ```powershell
> git grep -l "workspace_scope" -- backend/app backend/schema.sql frontend/src tools agent_push.py
> ```
>
> 이 명령은 표의 `frontend/src/lib/workspaceContext.ts`(`scope`·`id`·`name` 키만 사용)와
> `agent_push.py`(`workspace` 객체로 전송)를 **잡지 못한다**. 두 파일은 수동으로 확인한다.
>
> `backend/schema.sql` 과 `tools/` 를 범위에 넣어야 한다 — `backend/app` 만 지정하면
> **스키마 파일을 놓쳐 컬럼 자체를 안 만들게 된다.**
>
> 줄 단위로 보면 350줄이 넘어 훑기 어렵다. 파일을 먼저 좁히고 그 안에서 확인한다.

> [!WARNING]
> 마이그레이션 없이 `schema.sql` 만 고치면 **새 설치에서만 동작하고 기존 사용자 DB 에서는 없는 컬럼**이
> 된다. `backend/data` 는 사용자 데이터이므로 직접 초기화해서 해결하지 않는다.

## 격리 테스트 집계

- `CONTENT_HUB_NO_PROXY=1`인 `test_dev`, `test_dev_server`는 운영 서버로 관리 통계를 보내지
  않는다. 복사된 `content_hub.db`의 대기열을 같은 `backend\data_test\db\manage_hub.db`에
  반영해 서버와 같은 대시보드 집계를 로컬에서 확인한다.
- 프로젝트 또는 워크스페이스 귀속을 바꾸면 해당 생성물의 집계를 같은 요청에서 갱신한다.
  과거 버전에서 남은 대기열은 대시보드를 조회할 때 한 번 더 복구한다.
- 생성자 UID와 승인 계정 이메일이 고유하게 연결된 팩트만 집계한다. 연결이 없거나 중복이면
  다른 사람으로 추측하지 않고 대기열에 남긴다.
- `CONTENT_HUB_NO_PROXY`가 꺼진 운영·일반 클라이언트에서는 로컬 집계 저장소에 쓰지 않고
  기존 인증 서버 전송 계약을 그대로 사용한다.

## UI 의미(현행 구현)

- 상단 워크스페이스 선택은 **생성·크레딧·프로젝트·관리 컨텍스트**다. 2026-09-17부터
  **공유&리뷰만** 이 컨텍스트를 기본 조회 범위로 자동 적용한다. 작업 공간·캔버스의 기존
  수동 워크스페이스 필터와 생성 목적지·무장 태그는 바꾸지 않는다.
- 공유&리뷰 툴바의 `W R&D · 자동` 메뉴에서 `현재 워크스페이스 따라가기` / `전체 보기`를
  고른다. 자동 상태에는 X가 없다. 전체 보기는 현재 화면의 임시 선택이며, 공간 변경·앱 재시작
  후 자동으로 돌아간다. 단순 이름 갱신은 공간 변경으로 보지 않는다.
- 팀 자동 조회는 정확한 워크스페이스 ID로 좁힌다. 개인 자동 조회는 **현재 조회 권한이 있는
  모든 개인 워크스페이스 공유물**(`workspace_scope=personal`)이다. 내 생성물로만 제한하지 않는다.
  기존 공유·프로젝트 멤버 권한과 AND로 적용하는 보기 필터이며 새로운 접근 권한이 아니다.
- 현재 공간이 미확인이면 확인 안내를 표시하고 목록 조회를 보류한다. 사용자가 명시적으로
  전체 보기를 고를 수 있지만 자동으로 전체 범위를 열지는 않는다. 팀 ID가 있으면 이름이
  아직 없어도 조회한다. 소속이 `unknown`인 과거 생성물은 자동 조회에 포함하지 않으며 전체
  보기에서 확인한다. 현재 선택값으로 과거 기록을 추측·보정하거나 DB를 변경하지 않는다.
- 공유&리뷰에서는 전역 태그 영역의 수동 W 칩을 숨기고 툴바만 범위를 제어한다. 기존 W 칩과
  선택은 보존하므로 작업 공간으로 돌아가면 그대로 사용한다. 일반 전역 태그는 유지한다.
- 공간·자동/전체 범위 전환 시 이전 폴더·생성자 선택·카드 선택·미리보기·미리보기 뒤로가기 기록을 무효화하고,
  이전 조회/추가 페이지/다빈치 응답은 폐기한다. 다빈치가 다른 공간의 생성물을 가리키면
  공유&리뷰는 이동하지 않는다. 복수 선택은 현재 범위 안의 생성물만 위치 선택에 사용한다.
- 생성자 이름·건수도 공유 목록의 **유효 워크스페이스 + 프로젝트** 범위를 따른다. 로딩한 카드
  일부가 아니라 서버에서 조회 권한이 있는 공유물 전체를 집계한다. 미분류는 프로젝트 미지정만,
  기본 라이브러리는 보관 프로젝트를 제외하며 직접 보관 프로젝트를 선택하면 그 안을 센다.
  해당 범위에 공유물이 없는 생성자는 숨긴다. 생성자 자신의 선택 조건·검색·색·태그·폴더·휴지통
  조건으로는 집계를 좁히지 않는다. 따라서 이 추가 조건 사용 시 현재 그리드 건수와 다를 수 있다.
  공간/계정 전환 직후 옛 행을 숨기고, 늦은 응답과 같은 범위의 역순 응답을 폐기한다.
  공유/이동/삭제의 기존 변경 알림으로 다시 집계하고, 성공한 집계에서 사라진 생성자 선택만 해제한다.
  조회 실패 시 옛 건수를 유지하지 않고 재시도 안내를 표시한다. 내 작업의 기존 생성자 집계는 유지한다.
  공유 휴지통에서는 일반 공유물 집계를 조회/표시하지 않고 기존 생성자 선택을 자동 해제하지 않는다.
  선택 중이라면 `생성자 필터 해제` 버튼을 제공해 숨겨진 필터에 갇히지 않도록 한다.
- 휴지통은 원본 수신 건수로 다음 offset을 계산하고 탭 캐시에도 함께 저장한다. 공간 밖 항목이
  전부 숨겨진 페이지도 앞으로 진행한다. 빈 그리드는 회색 필터가 꺼져 있어도 최대 10번 자동
  조회하고, 이후 남은 페이지는 `더 보기`로 이어간다. 범위 필터가 있는 휴지통의 추가 조회가
  실패하면 자동 당김을 멈추고 명시적 새로고침을 안내해 같은 페이지의 반복 요청을 막는다.
- 개인 컨텍스트에서 실제 생성된 결과는 내부적으로 `workspace_scope=personal`로 유지
- 관리창은 처음에는 공통 워크스페이스 컨텍스트를 따르지만, 관리창에서 직접 워크스페이스를 고른
  뒤에는 그 창의 범위를 독립적으로 유지한다.
- 작업 화면의 폴더 행은 사용자 PC 디스크를 실시간 검사한 값이 아니라 공유 서버의
  `generation.folder_path`에서 파생된 기록이다. 화면에 `공유 서버 작업 기록`으로 출처를 표시한다.
- 생성에서 파생된 작업은 마지막 관측 뒤 프로젝트 설정 기간(기본 30일)과 계획 마감일이 모두
  지난 경우 삭제하지 않고 `과거 기록`으로 전환한다. 새 생성이 들어오면 다시 활성화한다.

## 공유 조회 API 호환성 (2026-09-17)

- `GET /api/generations`: 기존 `workspace_id` / `workspace_ids`에 선택적인
  `workspace_scope=personal`을 추가한다. 팀 ID와 personal을 동시에 주면 AND 조건이므로 0건이다.
  명시한 ID는 공백 제거·중복 제거 후 사용하고, 빈 ID·200자 초과·200개 초과 목록은 422로
  거부한다. 구서버 프록시에도 정규화한 값을 보내며 단수 별칭은 선택이 하나일 때만 보존한다.
- `POST /api/generations/locate`: `workspace_ids` / `workspace_scope=personal`을 지원한다.
  필터를 적용한 뒤 결과 폴더를 고르고, 적용된 응답에는 `workspace_filter_applied: true`를 넣는다.
  필터 없는 기존 요청에는 이 필드를 생략해 옛 응답 형태를 유지한다.
- `GET /api/creators?tab=team`: 같은 `workspace_ids` / `workspace_scope=personal`을 지원하며
  ID 정규화·길이/개수 검증도 같다. 범위 지정 응답은 `{items: [...], workspace_filter_applied: true}`,
  미지정/내 작업 응답은 기존 배열이다. 구서버가 범위를 무시한 배열이나 확인값 없는 응답을 보내면
  409와 공유 서버 업데이트 안내를 반환한다. 카드 페이지 수집이나 전체 집계로의 자동 대체는 하지 않는다.
  요청 동안 계정 key/UID를 함께 고정하고 성공/오류 모두 복원한다.
- 로컬 허브는 공유 서버의 적용 확인값을 검사한다. 구서버가 조건을 무시하면 409로 안내하고,
  적용을 확인한 응답에 다른 공간 행이 섞이면 502로 거부한다. 필터 해제나 로컬 성공으로
  자동 대체하지 않는다. UI는 같은 조건의 409를 한 번 안내하며 임시 전체 보기를 제안한다.
- 개인 목록은 구서버 호환을 위해 허브가 페이지별로 재검증한다. 원본 페이지 커서를 사용하고
  계정 key/uid를 고정한다. 60페이지(약 12,000행)를 확인해도 필요한 결과/끝을 확정하지 못하면
  503과 서버 업데이트 안내를 반환한다. 따라서 **공유 서버와 클라이언트 모두 업데이트 권장**.
  기존 수동 복수 워크스페이스 필터의 같은 상한에서 조용히 잘리는 한계는 이번 변경 밖이다.
- DB 스키마·마이그레이션·저장 소유권·과금·미디어 다운로드 정책 변경 없음. 프로젝트/폴더 행의
  사이드바 집계를 현재 자동 범위에 맞춰 다시 집계하는 기능은 포함하지 않는다(생성자 집계는 포함).

## 후속 단계

1. **구현 완료** — 에이전트는 제출 직전에 요청 워크스페이스로 CLI 를 전환하고 결과를 다시
   검증한다. 다만 워크스페이스별 독립 큐가 아니라, 하나뿐인 CLI 전역 선택 상태를 보호하는
   **전체 제출 공용 락**으로 직렬화한다(`agent_push.py` 의 `workspace_lock`).
2. **미구현** — 운영 DB에서 workspace별 프로젝트 합계와 하위 에피소드·시퀀스 합계 정합성 지속 감시.
3. **미구현** — 워크스페이스 재배정 이력을 과금 스냅샷과 분리해 append-only 로 보존.
   현재 감사 기록은 슈퍼 관리자가 다른 소유자의 카드를 바꾼 특수 경로만 포함한다.
