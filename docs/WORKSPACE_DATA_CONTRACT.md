# 워크스페이스 데이터 규격

## 목적

Higgsfield 생성 결과에는 워크스페이스 ID가 들어오지 않는다. MV-Hub는 생성 요청 또는 검증된
동기화 묶음이 알고 있는 워크스페이스를 별도 메타데이터로 저장한다. 기존 결과는 현재 선택값으로
추측하지 않으며 `unknown`으로 보존한다.

## 공통 컨텍스트

API 요청에서는 다음 객체를 사용한다.

```json
{
  "scope": "team",
  "id": "workspace-uuid",
  "name": "MILLIONVOLT"
}
```

- `team`: `id` 필수, `name`은 현재 귀속의 표시 이름 스냅샷
- `personal`: `id` 없음. CLI workspace unset 컨텍스트
- `unknown`: `id`, `name` 없음. 레거시 또는 검증되지 않은 데이터

DB와 조회 응답에서는 인덱싱하기 쉬운 평면 컬럼을 사용한다.

- `workspace_scope`
- `workspace_id`
- `workspace_name`

## 저장 위치

- `generation`: 현재 귀속 워크스페이스. 생성 요청값으로 시작하며, 사용자가 `##` 명령으로
  자기 카드의 잘못된 귀속을 명시적으로 보정할 수 있다.
- `gen_request.payload.workspace`: 대기 중 화면/CLI 전환과 무관하게 요청 당시 값을 보존한다.
- `project`: 프로젝트에 지정한 워크스페이스.
- `team_generation_fact`: 워크스페이스별 프로젝트·멤버·모델·기간 집계 차원.
- 공유 번들·휴지통: 위 세 필드를 그대로 보존한다.

## 멤버 등록부

CLI 1.1.23에는 조직 전체 멤버 조회 명령이 없다. 각 인증 계정의 에이전트가 보고한
`workspace list`를 합쳐 다음 테이블을 유지한다.

- `workspace_registry`: 워크스페이스의 마지막 이름·플랜·잔액 보고
- `workspace_member`: 계정별 접근 여부·역할·선택 상태·마지막 확인 시각

이 등록부는 “MV-Hub에서 확인된 멤버”이며 Higgsfield 조직 전체 명단과 동일하다고 가정하지 않는다.

등록부는 id 기준 upsert 만 하고 행을 지우지 않는다. 힉스필드에서 워크스페이스를
지웠다 다시 만들면 id 가 바뀌어 “이름은 같고 멤버 0명”인 유령 행이 남아 프로젝트
설정 드롭다운에 같은 이름이 2개로 보인다. 정리는 전용 스크립트로 한다(서버 PC,
저장소 루트에서):

```powershell
.\run_py.bat tools\cleanup_workspace_registry.py           # 미리보기(유지/유령 표)
.\run_py.bat tools\cleanup_workspace_registry.py --apply   # 실제 삭제
```

가용 멤버가 1명이라도 있거나 workspace_id 컬럼을 가진 어떤 테이블에서든 참조되는
행은 자동으로 보호된다(동적 스키마 스캔). 다른 DB 는 `--db <경로>`.

## 정합성 규칙

1. 불완전한 `team` 컨텍스트(`id` 없음)는 `unknown`으로 저장한다.
2. `personal`, `unknown`은 `workspace_id`를 가질 수 없다.
3. 기존의 확인된 워크스페이스는 구버전 클라이언트가 보낸 `unknown`으로 덮어쓰지 않는다.
4. 동기화가 기존 생성물과 다른 워크스페이스를 보고해도 조용히 바꾸지 않는다.
5. 레거시 생성물·프로젝트·관리 팩트는 무손실로 유지하고 워크스페이스만 `unknown`으로 추가한다.
6. 계정의 과거 `hf_status:<email>` 보고는 등록부가 비어 있는 항목만 1회 보강한다. 재부팅으로
   `last_seen_at`을 현재 시각으로 갱신하지 않는다.
7. `#+`/`#-`는 `##` 전역 모드에서 워크스페이스 적용/제거 목록을 여는 선택 명령이다. 사용자가
   워크스페이스 이름을 직접 입력하거나 Enter로 제출하는 경로는 제공하지 않으며, 일반 태그와
   전역 태그 테이블에도 어떤 행도 만들지 않는다.
8. `#+`는 라임색 적용 칩, `#-`는 빨간색 제거 칩으로 현재 계정이 접근 가능한 등록부 목록을
   보여준다. 칩을 선택하면 표시명이 아니라 등록부의 정확한 UUID를 변경 API에 전달한다. 같은
   표시명이 여러 UUID에 있으면 화면에 ID 뒷자리를 붙여 구분하며, 서버가 선택한 UUID와 다른
   결과를 돌려주면 변경을 시작하지 않는다. 이름만 보내는 구버전 요청은 고유한 이름만 허용한다.
9. 일괄 변경은 최대 500개이며, 없는 카드·남의 카드·프로젝트 충돌이 하나라도 있으면 전부
   변경하지 않는다. 팀 프로젝트 카드는 프로젝트와 같은 워크스페이스만 허용하고, 프로젝트에
   있는 동안 워크스페이스 제거를 허용하지 않는다.
10. 명시적인 제거는 `unknown`이 아니라 `personal`로 저장한다. `unknown`은 동기화가 보강할 수
    있는 레거시 상태이므로 제거에 사용하면 다음 동기화에서 팀 귀속이 되살아날 수 있다.
11. 공유된 내 카드는 서버 복사본을 먼저 갱신한다. 서버 변경이 실패하면 로컬 변경을 시작하지
    않으며, 변경된 로컬 생성물은 관리 텔레메트리 재전송 대상으로 표시한다.

## 격리 테스트 집계

- `CONTENT_HUB_NO_PROXY=1`인 `test_dev`, `test_dev_server`는 운영 서버로 관리 통계를 보내지
  않는다. 복사된 `content_hub.db`의 대기열을 같은 `backend\data_test\db\manage_hub.db`에
  반영해 서버와 같은 대시보드 집계를 로컬에서 확인한다.
- 프로젝트 또는 워크스페이스 귀속을 바꾸면 해당 생성물의 집계를 같은 요청에서 갱신한다.
  과거 버전에서 남은 대기열은 대시보드를 조회할 때 한 번 더 복구한다.
- 생성자 UID와 승인 계정 이메일이 고유하게 연결된 팩트만 집계한다. 연결이 없거나 중복이면
  다른 사람으로 추측하지 않고 대기열에 남긴다.
- `CONTENT_HUB_NO_PROXY`가 꺼진 운영·일반 클라이언트에서는 로컬 집계 저장소에 쓰지 않고
  기존 인증 서버 전송 계약을 그대로 사용한다.

## UI 의미(현행 구현)

- 상단 워크스페이스 선택은 **생성·크레딧·프로젝트·관리 컨텍스트**이며, 라이브러리 생성물
  가시성을 자동으로 제한하지 않는다(`frontend/src/lib/workspaceContext.ts`).
- 라이브러리를 특정 워크스페이스로 좁히려면 `#+` 로 등록한 **워크스페이스 필터 칩을 사용자가
  직접 켜야** 한다. 칩을 켜지 않으면 개인·팀 어느 컨텍스트에서도 모든 워크스페이스 생성물이 보인다.
- 개인 컨텍스트에서 실제 생성된 결과는 내부적으로 `workspace_scope=personal`로 유지
- 관리창은 처음에는 공통 워크스페이스 컨텍스트를 따르지만, 관리창에서 직접 워크스페이스를 고른
  뒤에는 그 창의 범위를 독립적으로 유지한다.
- 작업 화면의 폴더 행은 사용자 PC 디스크를 실시간 검사한 값이 아니라 공유 서버의
  `generation.folder_path`에서 파생된 기록이다. 화면에 `공유 서버 작업 기록`으로 출처를 표시한다.
- 생성에서 파생된 작업은 마지막 관측 뒤 프로젝트 설정 기간(기본 30일)과 계획 마감일이 모두
  지난 경우 삭제하지 않고 `과거 기록`으로 전환한다. 새 생성이 들어오면 다시 활성화한다.

## 후속 단계

1. **구현 완료** — 에이전트는 제출 직전에 요청 워크스페이스로 CLI 를 전환하고 결과를 다시
   검증한다. 다만 워크스페이스별 독립 큐가 아니라, 하나뿐인 CLI 전역 선택 상태를 보호하는
   **전체 제출 공용 락**으로 직렬화한다(`agent_push.py` 의 `workspace_lock`).
2. **미구현** — 운영 DB에서 workspace별 프로젝트 합계와 하위 에피소드·시퀀스 합계 정합성 지속 감시.
3. **미구현** — 워크스페이스 재배정 이력을 과금 스냅샷과 분리해 append-only 로 보존.
   현재 감사 기록은 슈퍼 관리자가 다른 소유자의 카드를 바꾼 특수 경로만 포함한다.
