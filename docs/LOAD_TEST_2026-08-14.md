# 100명 저사양 TLS 8시간 지속 시험 결과

> **시점 고정 검증 기록**: 이 문서는 2026-08-14 당시 코드와 시험 환경의 결과를 보존한다.
> 현재 배포 가능 여부와 최신 테스트 숫자는 [CURRENT_STATUS.md](CURRENT_STATUS.md)를 따른다.
> 코드·CLI·운영 환경이 바뀐 뒤 이 결과를 새 배포의 자동 보증으로 사용하지 않는다.

## 결론

2026-08-13 22:28:24부터 2026-08-14 06:28:49까지 8시간 24초 동안 시험했다.
정한 16개 합격 조건을 모두 통과했다. 업무 요청 5,606,739건은 전부 HTTP 200이었고,
SQLite 잠금, 전송 오류, WebSocket 오류, 에이전트 롱폴 오류, 서버 표준 오류 출력은 모두 0건이었다.

이 결과는 **100명이 동시에 목록 조회·상세 조회·필터 조회·색상 쓰기·미디어 읽기와
실시간 연결을 사용하는 조건**에 대한 강한 안정성 증거다. 외부 생성 서비스, 실제 사내망과 NAS,
운영 리버스 프록시까지 포함한 절대적인 무장애 보증은 아니다.

실행에 사용한 핵심 조건은 다음과 같다.

```powershell
python tools\load_test_100.py --users 100 --duration 14400 --cycles 2 `
  --generations-per-user 20 --server-cpu-cores 4 `
  --server-priority below-normal --sample-interval 30 `
  --max-rss-mb 512 --max-p95-ms 500 `
  --max-login-p95-ms 10000 --max-memory-growth-percent 20 `
  --tls-certfile <cert.pem> --tls-keyfile <key.pem> --tls-ca-file <cert.pem> `
  --output <result.json> --quiet
```

## 이번에 보완한 위험

- 장기 시험의 지연시간 표본을 고정 크기로 제한해 시험 도구 자체의 메모리 누적을 막았다.
- 전체 요청 수와 상태 코드는 표본이 아니라 정확한 값으로 유지한다.
- 30초마다 서버 RSS·CPU·WebSocket·에이전트 연결을 기록해 순간적인 저하를 잡는다.
- 결과와 진행 파일을 임시 파일에서 원자적으로 교체해 중간 JSON 손상을 막는다.
- 저사양 조건의 CPU 개수와 프로세스 우선순위가 실제로 적용됐는지 결과에 남긴다.
- 메모리 절대 상한, 로그인 지연, 모든 사이클의 상태를 자동 합격 조건에 포함했다.
- 롱폴의 순간 대기자 감소를 접속 해제로 오판하지 않고, 실제 연결 계정으로 안정성을 판정한다.

## 아직 남는 범위

- 512MB는 서버 프로세스 RSS의 합격 상한이며 Windows 전체 메모리를 512MB로 강제한 시험은 아니다.
- 같은 PC의 루프백 통신이므로 실제 사내망 지연, 패킷 손실, NAS 속도는 포함하지 않았다.
- 시험용 인증서를 신뢰하도록 설정한 TLS 시험이며 운영 인증서·리버스 프록시는 별도 점검 대상이다.
- 실제 Higgsfield/HF 생성 호출, 대용량 업로드, 운영 DB 복제와 백업 동시 실행은 포함하지 않았다.
- 8시간 통과는 현재 요청 구성의 안정성 근거이지 모든 장애에 대한 절대 보장은 아니다.

배포 전에는 운영과 같은 스테이징 장비에서 실제 인증서·프록시·NAS를 연결한 짧은 확인 시험과
백업 복원 점검을 추가한다. 배포 후 첫 근무일에는 `/api/admin/runtime`과 운영 로그에서
RSS, SQLite 잠금, 5xx, 에이전트 연결, 생성 상태 지연을 집중 관찰한다.
