# 최적화·구조 개선 라운드 설계 v2 (2026-08-21, 코덱스 서베이 → 클로드 설계 → 코덱스 검토 반영 확정)

v1→v2 (코덱스 설계 검토 4건 반영): ①1-C를 웨이브 2로 상향(연결정보 동시 변경 위험)
②2-B를 두 커밋으로 분리(helper 이동→manage 교체, manage는 PK 전용 유지 — job_id 해석을
암묵 허용하면 안 됨) ③3-B에 timestamp 형식 게이트 선행(실데이터 created_at이 단일 형식임을
증명 못 하면 백로그 강등) + 반개구간 규격(로컬 시작일 00:00과 종료일 다음날 00:00을 각각
UTC 변환, start+24h 금지, naive→OS 로컬 해석→aware UTC, TZ 캐시 금지·OS TZ 변경 시 서버
재시작을 운영 조건으로 명시) ④항목별 검증 케이스 보강(아래 각 항목에 반영).

전제(절대 원칙): **배포 버전 기능 전부 보존.** API 응답 필드·권한 의미·DB 스키마 의미 불변.
매 항목: 계약 테스트 먼저 고정 → 변경 → 전 회귀(백엔드 1187·프론트 608) → 실측 비교.

기준 실측(2026-08-21, 실데이터 사본 256건): 핵심 쿼리 0.4~11ms · 콜드 임포트 796ms ·
번들 gzip ~300KB · 빌드 2.2s. **현 규모 병목 없음** — 본 라운드는 데이터 증가 대비 스케일링
결함(N+1·루프 블로킹)과 드리프트 위험(중복 정의) 제거가 목적이다.

근거: 코덱스 read-only 서베이(2f00bb99 기준, 성능-01~09·구조-01~06·P2 25건 재평가·금지 9건).
전문은 세션 산출물 — 각 항목 요지는 아래에 재기록.

## 웨이브 1 — 저위험·즉효 (각각 독립 커밋)

1-A. **관리 summary to_thread 격리** (성능-04) — routers/manage.py:566 `async def` 라우트가
  dashboard_summary() SQLite 집계를 이벤트 루프에서 직접 실행 → `asyncio.to_thread` 한 줄 격리.
  검증: 기존 JSON 동등성(test_manage_workspace_scope·test_project_budget_period) + DB 호출을
  인위 지연시킨 상태에서 다른 async 요청이 진행되는지(루프 비블로킹) 확인.

1-B. **CLI pin reader 통합** (구조-02) — hf_cli_version.txt 를 3곳이 제각각 읽음(ingest 만
  utf-8, 나머지 utf-8-sig) → 기존 `read_first_line()` 공통 helper 로 통일. BOM 계약 회귀 차단.
  검증: BOM/무BOM/빈/공백/부재 + 다중 행·디코딩 오류·읽기 불가 + 호출부별 ""/None 폴백 고정
  + 기존 sparse-checkout 테스트.

1-D. **WorkspaceUsageDashboard 모델 Map 인덱스** (성능-07) — 행마다 worker_models/project_models
  전체 filter() 2회 → useMemo 로 UID/PID→rows Map 1회 구축. 완료된 reconcile 최적화는 불변.
  검증: null UID/PID·중복 키·빈 문자열 비병합·Map 내부 행 순서·overview 갱신 시 재계산
  순수함수 테스트 + 기존 608 통과.

## 웨이브 2 — 배치화·연결정보 (계약 테스트 선행)

2-A. **워크스페이스 배치 응답 N+1 제거** (성능-01) — generation.py:476/570 이 항목마다
  get_generation() 재호출 → 기존 `get_generations_with_materials()` 배치 경로로 응답 재구성
  (requested_id 순서 보존, 필드 불변). 검증: PK/job_id 별칭·같은 행 혼합 입력·중복/없는
  ID·휴지통·changed/unchanged 혼합에서 updates 의 requested_id·순서 전후 완전 동등 비교 +
  SQL trace 로 쿼리 수가 입력 크기와 무관함 확인(전/후 실측 기록).

2-B. **생성물 가시성 배치 helper 공용화** (성능-02+구조-04) — ★두 커밋 분리(코덱스 요구):
  ①library 의 "조회된 행 가시성 판정+멤버십 1회 조회"만 `services/generation_access.py` 로
  이동(프록시·ID 해석·materials·missing 조립은 이동 금지), library 출력 동등성 고정
  ②manage.py:1020 에 **PK 전용** 배치 조회 적용(단건 반복만 교체) — job_id 해석을 암묵
  허용하지 않음, 숨김=404·부재/휴지통=연결 단계 409 라는 기존 실패 계약·부분 연결 없음 보존.
  검증: read_all/소유자/공유 멤버/비멤버/AUTH-off/없는 ID/중복 ID + 엔드포인트별 실패 계약.

2-C. **공유 서버 URL/token 단일 소유자** (구조-01, 웨이브 2로 상향) — 연결정보 계약을 먼저
  고정: import 시점 env 확정·계정 DB 전환 후 재조회·빈/공백/후행 슬래시 의미·NO_PROXY·백업
  401 처리. 그 다음 `services/shared_connection.py` 신설 후 _proxy·publish·worker_backup 위임.

## 웨이브 3 — 중위험 (전용 동등성 테스트 선행)

3-A. **/cache-all 배치 UPSERT + to_thread** (성능-03) — 전체 규모 비례 N+1과 루프 정지 동시
  제거. 선행 고정: queued 의미(=request_media_preservation True 반환 수)·running/complete/
  failed 기존 행·force 재등록·reason 우선순위(final>manual>admin>shared)·running 불변·
  timestamp/error 초기화·트랜잭션 롤백.

3-B. **사용량 날짜 필터 인덱스 활성화** (성능-05) — ✅게이트 측정 후 **백로그 강등 확정**
  (2026-08-21 실측). 근거: ①형식 측정 — 서버 스냅샷 3,895행은 단일 'YYYY-MM-DD HH:MM:SS'
  이지만, upsert_facts 가 payload created_at 을 **무정규화 그대로 저장**해 코드 차원 보증이
  없음(dev 로컬엔 테스트 시드 date-only 행 실존, 코드 주석은 T…Z 를 언급 — 미래 혼재 위험)
  ②비용 실측 — 실서버 스냅샷(3,895행)에서 team_overview 전체 20.4ms·기간 필터 33.8ms로
  현 규모 실익 없음. 재개 전제: 쓰기 시점 created_at 정규화 설계(+기존 행 마이그레이션)
  선행, 또는 overview 실측 200ms 초과 시 재평가. (성능-06 10집계 단일화도 같은 실측
  근거로 함께 백로그 유지.) 반개구간·시간대 규격(v2 명세)은 재개 시 그대로 적용.
