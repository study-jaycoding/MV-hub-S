# 최적화 라운드 5 설계 v2 (2026-08-22, 코덱스 서베이4 → 클로드 선별 → 코덱스 검토 반영)

코덱스 설계 검토 판정: 웨이브 1 전항목 동의(추가 계약 아래 반영)·웨이브 2 는 2-C 게이트
경계/2-D flush 계약 확정 후 착수. ★검토 중 실버그 추가 발견: `_allowed_param_names` 가
빈 폴백 스키마를 `_PARAM_NAMES_CACHE[model]=set()` 로 프로세스 수명 박제 가능 → 2-C1 에
포함해 수정.

전제 동일: 배포 기능 불변·계약 테스트 선행·독립 커밋·웨이브 리뷰. 범위=서베이4
(서비스 계층 8모듈: resolve_bridge·asset_watcher·cli_bridge·share_state_reconciler·
comfy_client·resolve_transfer·release_update·operational_health) 21후보 중 선별.

## 웨이브 1 — 저위험 소형 (각 독립 커밋, 코덱스 전항목 동의)

추가 확정 계약: 1-A=renew False 시 원격 호출·로컬 transition·process 전부 금지+
composite partial unpublish 0회 테스트 · 1-B=/start 응답의 _with_activity 도 offload
(업데이트 직전 재검사는 updater 작업 안 유지) · 1-C=빈 DB·NULL·비활성 overdue 제외
동등성 테스트 · 1-D=중도 취소 시 디스크 manifest 최대 checkpoint-1건 지연은 기존
계약(변화 없음) · 1-E=신뢰 root 만 1회 resolve, manifest 기록 비신뢰 경로는 매번
resolve·검증 유지 · 1-F=returned_all 인정 조건 불변·예외/부분 반환은 재스캔 ·
1-H=해시 불가 대역 None 보수 처리 · 1-I=형식 깨진 응답도 미캐시(정상 workspaces
응답의 tier 부재만 None 캐시).

1-A. **reconciler-2 lease 갱신 실패 즉시 중단** — renew 반환 False 면 cas_lost 집계
  후 _process_claimed_intent 미진입(stale worker 의 원격 unpublish 방지, 실버그급).
1-B. **ops-1 async 라우트 SQL offload** — release_update 라우트의 _with_activity 를
  to_thread 안으로(이벤트 루프 블로킹 제거).
1-C. **ops-2 큐 snapshot SQL 6→2** — 첫 GROUP BY 에 overdue·check failure 조건 합계
  포함, active/recovery 는 파이썬 합산, unanchored(JOIN 필요)만 별도.
1-D. **transfer-1 요약 재집계 checkpoint 시점만** — 초기·checkpoint 직전·최종만 전체
  집계(항목당 3회 전체 순회 O(N²) 제거). checkpoint 저장 정확도 동일.
1-E. **transfer-3 pending 목록 stat 1회화** — is_file+stat → stat 1회, resolved roots
  프로젝트당 1회 계산.
1-F. **bridge-1 성공 배치 Bin 재스캔 생략** — returned_all=True 면 _existing_paths()
  생략(스캔 결과가 판정에 안 쓰임). RefreshFolders 유지, 부분 반환은 종전 재스캔.
1-G. **bridge-2 원본 검사 stat 1회화** — 준비·실행 두 단계 각각 is_file+stat →
  stat 1회(두 단계 재검증 자체는 유지, symlink 의미 동일).
1-H. **watcher-2 emitter snapshot 재사용** — health cycle 시작 시 emitters 1회
  snapshot → handle별 조회 맵(O(W²)→O(W)). 조회 실패는 종전대로 None 보수 처리.
1-I. **comfy-1 예외 None 비캐시** — /workspaces 예외로 만든 tier=None 은 캐시하지
  않음(정상 응답의 tier 부재만 캐시). R3 계정 스냅샷과 동일 교훈.

## 웨이브 2 — 중위험 (전용 테스트 선행, 코덱스 검토 계약 반영)

2-A. **reconciler-1 origin 조건 claim** — claim_due_share_state_intents 에 선택적
  server_origin 조건(현 권위 서버 행만 claim). ★후보 SELECT 와 최종 claimed SELECT
  양쪽에 정규화된 origin 조건. 다른 서버 행은 보존(전환 시 재개). 외부 origin due 가
  limit 초과여도 현재 origin 행이 claim 되는 starvation 테스트 필수.
2-B. **transfer-2 목적지별 lock** — 락 범위=존재 확인→전체 byte 비교→고유 .part→
  os.replace 전체. 같은 목적지·같은 원본=후발 skipped, 다른 원본=오류. 프로세스 내부
  동시성만 막는 한계와 락 레지스트리 회수 계약 명시.
2-C1. **cli_bridge-1 TTL single-flight** — list_models·get_model_params·
  get_account_status 키별 이벤트 루프별 in-flight 공유(동시 miss M회→1회). 실패·빈
  결과 비캐시 유지. ★함께: `_allowed_param_names` 의 빈 폴백 스키마
  `_PARAM_NAMES_CACHE[model]=set()` 박제 수정(빈 결과는 이 캐시에도 넣지 않음 —
  RL-24 백오프 경로만 사용). parse_job 의 workspace_context import 상단 이동(leaf
  확인됨), _UID_RE 는 현 위치 유지(repo 역의존 방지).
2-C2. **cli_bridge-2 비용 single-flight + 게이트 경계(코덱스 확정 흐름)** —
  ①비용 캐시 1회 로드(load-once 동기화) ②파라미터 스키마가 이미 메모리에 있어 CLI
  불필요할 때만 _param_args 를 게이트 밖 실행 ③스키마 miss 가능성이 있으면 게이트
  안에서 실행 ④key 생성 후 fresh 캐시는 게이트 전 반환 ⑤miss 는 _cost_key
  single-flight 합류 ⑥leader 만 세마포어 취득 후 double-check → generate cost.
  계약 문구: "스키마가 CLI 없이 확정된 비용 캐시 히트"만 semaphore-free.
2-D. **cli_bridge-3 비용 캐시 쓰기 debounce** — 확정 계약: debounce 시간·지속 burst
  최대 미저장 시간 명시, 쓰기 실패 시 dirty 유지, shutdown flush 호출 위치·대기 상한
  명시, _write_cost_cache 가 성공 여부 반환(revision 마감 조건). 원자 저장·TTL·만료
  폴백 불변.
2-E. **comfy-2 object_info single-flight** — use_cache=True 만 합류(False 는 항상
  독립 호출). leader 실패·취소 시 전체 waiter 해제+in-flight 삭제 보장. 빈 dict 도
  비캐시. API 키별 격리 유지.
2-F. **comfy-3 출력 다운로드 streaming** — download_view 전용(view_bytes 는 소형
  텍스트용으로 유지). 실패 시 기존 dst 보존·같은 폴더 고유 .part·모든 예외에서 정리·
  성공 시에만 os.replace. ★SSRF 검사·외부 호스트 인증 헤더 제거·연쇄 redirect 차단·
  600s timeout 전부 보존.
2-G. **watcher-1 락 밖 NAS 확인** — 락 안 placeholder 세대 예약→락 밖 identity 확인→
  재진입 후 observer·등록·세대·handle 상태 재검증. 확인한 identity 를 schedule 에
  전달해 중복 stat 회피. 이전 세대 무시·grace/backoff 불변.
2-H. **watcher 건강 시 identity stat 완화(코덱스 수정 수용)** — 건강한 alive=True
  상태만 monotonic 기준 5초 cadence 로 identity stat. emitter snapshot·is_alive 는
  1초 유지(watcher-2 후 저렴). ★alive=False·recovery 중·root-lost 신호는 즉시 stat
  (감지 지연=이벤트 영구 누락 위험이라 완화 금지).
