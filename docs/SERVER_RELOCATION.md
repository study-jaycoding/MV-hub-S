# 공유 서버 주소 이사 공지 (관리자용)

공유 서버를 새 PC·새 IP로 옮기면, 작업자 PC의 허브는 옛 주소를 계속 바라본다. 그대로 두면
공유·발행이 실패하고 결국 로그인 화면에 갇힌다(주소를 바꿀 관리자 화면은 로그인해야 열린다).

**관리자 창에서 [팀에 공지]를 누르면** 작업 중인 사람에게 알림이 뜨고, 그 알림을 **한 번 누르면
바로 새 주소로 전환**된다. 이 문서는 그 절차와, 버튼을 쓸 수 없을 때의 수동 방법이다.

---

## 1. 이사 절차 (버튼 — 권장)

1. 새 PC에서 공유 서버를 띄우고, `http://<새주소>/api/health`가 응답하는지 확인한다.
2. **관리자 창 → 공유 서버 탭**에서 **서버 이름과 새 주소**를 넣고 **[저장]**.
3. 같은 자리의 **[팀에 공지]** → 확인창("팀 전체에 서버 전환 안내가 발송됩니다") → **[공지 발송]**.
4. 작업자 PC는 **앱을 켜 둔 채로 최대 1분 안에** 알림을 받는다(기동 시 1회 + 1분 주기).
5. 작업자는 오른쪽 위 알림(종 아이콘)의
   **"'MV 팀 서버' 서버가 새 위치로 이동했습니다. 누르면 전환되고 다시 로그인합니다."**
   를 **누르기만 하면** 전환된다 → 로그아웃되고 새 주소 기준 로그인 화면이 열린다.
6. 다시 로그인하면 끝이다.

> **확인창은 없다.** 알림 본문이 "누르면 전환되고 다시 로그인합니다"라고 이미 말하고 있고,
> 옛 주소로 남아 있으면 어차피 공유가 안 된다. 대신 백엔드가 누를 때마다 **공지를 다시 읽어
> 재검증**하고, **새 주소가 진짜 MV Hub 서버인지 확인**한 뒤에만 바꾼다(닿지 않으면 전환하지
> 않고 알림 자리에 실패 사유가 뜬다).

### [팀에 공지]가 하는 일

버튼은 작업자 설치본의 원본인 **릴리스 폴더**(`INSTALL_SOURCE.txt`가 가리키는 곳)에
`server-location.json` 파일을 **원자적으로** 기록한다. 번호(`server_revision`)는 **기존 파일의
번호와 이 PC가 마지막으로 발행한 번호 중 큰 쪽 +1**(둘 다 없으면 1) — 관리자가 번호를 기억할
필요가 없고, 공지 파일을 지운 뒤에 눌러도 번호가 1로 되감기지 않는다(§6).

- 발행에 쓰이는 값은 **저장된** 이름·주소다. 입력창만 고치고 저장하지 않았으면 확인창이 그
  사실을 경고하고, 나가는 값은 저장된 값이다. **[저장] 먼저, [팀에 공지] 다음.**
- 기존 파일을 **읽지 못하면 발행하지 않는다**(NAS 응답 없음·손으로 고치다 깨진 파일 등).
  번호를 확인 못 한 채 1로 덮어쓰면 이미 옮긴 PC와 아직 안 옮긴 PC 중 어느 쪽이 맞는지
  판단할 근거가 사라지기 때문이다. 이때는 아래 §3 수동 방법으로 처리한다.
- 발행한 관리자 PC 자신에게는 알림이 뜨지 않는다(자기가 낸 공지다).

### 안 될 때

| 메시지 | 뜻 |
| --- | --- |
| 릴리스 폴더에 **쓰기 권한이 없습니다** — 관리자 PC에서 실행하세요 | 그 PC는 릴리스 폴더에 읽기 권한만 있다(정상). 릴리스 폴더에 쓸 수 있는 관리자 PC에서 누른다. |
| **릴리스 설치본에서만** 공지를 발행할 수 있습니다 | 개발용 Git 실행본·공유 서버 본체에는 `INSTALL_SOURCE.txt`가 없어 릴리스 폴더를 알 수 없다. 작업자와 같은 설치본(관리자 PC)에서 누른다. |
| 릴리스 폴더를 찾을 수 없습니다 / 연결할 수 없습니다 | NAS가 꺼져 있거나 경로가 틀렸다. `INSTALL_SOURCE.txt`를 확인한다. |
| 기존 `server-location.json`을 해석할 수 없습니다 | 파일이 깨졌다. 그 파일을 고치거나 지우고 다시 누른다. |

## 2. 알림이 안 뜰 때 확인할 것

| 증상 | 원인 |
| --- | --- |
| 아무 PC에도 안 뜬다 | 릴리스 폴더가 다르다. `INSTALL_SOURCE.txt`가 가리키는 폴더에 `server-location.json`이 생겼는지 확인(발행 성공 문구에 그 경로가 나온다). |
| 특정 PC만 안 뜬다 | 그 PC가 **릴리스 설치본이 아니다**(개발용 Git 실행본·공유 서버 본체는 대상이 아니다). 또는 이미 그 주소를 쓰고 있다. |
| 파일은 맞는데 안 뜬다 | ① 번호를 안 올렸다(수동 편집한 경우). ② 새 주소가 아직 응답하지 않는다 — **응답하는 MV Hub 서버로 확인될 때만** 알림이 뜬다(닿지도 않는 주소로 옮기면 로그아웃만 되고 더 갇히기 때문). 서버를 먼저 띄우고 다시 확인한다. |

## 3. 수동 파일 작성 (비상용)

버튼을 쓸 수 없을 때(관리자 PC가 릴리스 설치본이 아님, 기존 파일이 깨져 발행이 거부됨 등)만
쓴다. 평소에는 §1 버튼을 쓴다 — 번호를 손으로 올리다 실수하면 팀 전체가 영향을 받는다.

### 3-1. 파일 놓을 위치

작업자 설치본의 `INSTALL_SOURCE.txt`가 가리키는 **릴리스 폴더** — `latest.json`,
`MVHub_Install.bat`이 있는 그 폴더다. 거기에 `server-location.json`을 만든다.

```text
\\NAS\releases\MVHub\
    latest.json                ← 앱 버전 (건드리지 않는다)
    MVHub_v1.4.2.zip
    MVHub_Install.bat
    server-location.json       ← 이 파일
```

> **왜 latest.json에 안 넣나**
> 릴리스 스크립트(`release/make_release.ps1`, `release/select_release.ps1`)가 latest.json을
> 정해진 필드 목록으로 **통째로 다시 쓴다**. 거기에 주소를 적어 두면 다음 릴리스를 만드는
> 순간 지워진다. 또 앱 버전을 롤백하면 주소 공지까지 함께 되감기는데, 서버 주소와 앱 버전은
> 서로 다른 사건이다. 그래서 파일을 분리한다.

### 3-2. 파일 내용

```json
{
  "shared_server_url": "http://192.168.1.50:8010",
  "server_revision": 3,
  "server_name": "MV 팀 서버",
  "announced_at": "2026-08-23T10:00:00+09:00"
}
```

| 필드 | 규칙 |
| --- | --- |
| `shared_server_url` | 새 공유 서버 주소. **`http://` 또는 `https://`로 시작**해야 한다. 후행 슬래시는 있어도 되고 무시된다. 계정정보(`user:pw@`)·물음표 뒤 쿼리는 넣을 수 없다. |
| `server_revision` | **1 이상의 정수.** 주소를 바꿀 때마다 **반드시 1씩 올린다.** |
| `server_name` | 작업자 화면에 주소 대신 보일 **서버 이름**(선택). 64자 이내 한 줄. 비우거나 빼면 작업자에게 주소가 그대로 보이고, 이미 그 PC에 등록된 이름이 있으면 그 이름을 계속 쓴다. |
| `announced_at` | 알림에 보일 시각(문자열). 없어도 동작한다. |

메모장으로 저장해도 된다(UTF-8 BOM 허용).

> `server_name`에 숫자·배열을 넣거나 줄바꿈이 섞이면 **공지 전체가 무시된다**(이름만 반쯤
> 적용돼 PC마다 다른 표기를 보는 상태를 만들지 않기 위해서다). 이름은 따옴표로 감싼 한 줄
> 문자열이어야 한다.

### 3-3. `server_revision` 규칙 — 가장 중요한 한 가지

- 주소를 바꿀 때마다 **번호를 올린다.** 3 → 4 → 5. ([팀에 공지] 버튼은 이걸 자동으로 한다.)
- **번호를 올리지 않고 주소만 고쳐 쓰지 마라.** 이미 3번 공지를 받아들여 옮긴 PC와 아직
  안 옮긴 PC 중 어느 쪽이 맞는지 판단할 근거가 사라진다. 이 경우 허브는 **공지를 무시하고
  오류 로그만 남긴다**(사고를 조용히 퍼뜨리는 대신 멈춘다).
- 번호를 **낮추면** 아무 일도 일어나지 않는다. 이미 더 높은 번호를 받아들인 PC는 옛 주소로
  자동으로 되돌아가지 않는다. 되돌리려면 번호를 **더 높여서** 옛 주소를 다시 공지한다.
  (예: 3번=새 주소로 옮겼다가 취소하고 싶으면, 4번=옛 주소로 공지한다.)

## 4. 권한 — 작업자에게 쓰기 권한을 주지 마라

이 파일은 **작업자 허브가 무조건 신뢰하는 값**이다. 여기 적힌 주소로 옮길지 사용자에게 묻고,
수락하면 그 주소가 이 PC의 공유 서버가 된다.

- 릴리스 폴더와 **같은 ACL**을 쓴다: 관리자만 쓰기, 작업자는 **읽기 전용**.
- 작업자가 쓸 수 있으면 팀 전체의 서버 주소를 임의로 바꿀 수 있다.
- [팀에 공지] 버튼의 권한도 이 ACL 하나가 결정한다 — 쓰기 권한이 없는 PC에서 누르면
  "관리자 PC에서 실행하세요"로 끝난다(앱이 따로 관리자 여부를 판별하지 않는다).

## 5. 서버 이름 — 작업자에겐 이름만 보인다

작업자에게 IP·포트를 외우게 하지 않는다. 관리자만 주소를 다루고, 작업자 화면에는 이름이 뜬다.

- **등록:** 관리자 창 → **공유 서버** 탭 → "서버 이름"과 "주소"를 함께 저장한다.
  (이사 공지의 `server_name`은 옮겨 갈 때 이 값을 대신 갱신해 준다.)
- **보이는 곳:** 로그인 화면 안내문("MV 팀 서버에 연결"), 이사 알림 문구.
- **안 보이는 곳:** 로그인 화면의 **'서버 주소 변경'** 패널은 그대로 주소를 보여준다 —
  서버가 죽어 갇혔을 때 쓰는 탈출구라 실제 주소가 필요하다.
- 이름을 비우면 예전처럼 주소가 그대로 보인다. 언제든 바꿔도 되고, 서버 동작에는 영향이 없다.
- 이름은 **주소마다 따로** 기억된다. 옛 주소로 되돌아가 로그인하면 그때 쓰던 이름이 되살아난다.
- 로그아웃해도 서버 이름은 남는다(로그인 화면에서 필요하다). 로그인한 **사람**의 표시 이름과는
  별개의 값이다.

## 6. 알아 둘 것

- **전환하면 그 PC는 로그아웃된다.** 토큰은 서버마다 다르므로 새 주소에서 다시 로그인해야
  한다. 옛 주소는 로그인 화면의 '최근 주소'에 남아 되돌아갈 수 있다.
- **전환을 미뤄도(알림을 안 눌러도) 다음에 앱을 켜면 다시 알림이 뜬다.** 옛 주소로 남아
  있으면 공유가 안 되므로, 결국 옮기는 것이 맞다.
- **옛 서버에 남은 미완료 작업은 옮겨 가지 않는다.** 위임 모드에서 옛 서버에 걸려 있던
  공유 상태는 그 서버에 그대로 얼어붙는다(마이그레이션은 이 기능의 범위가 아니다).
  필요하면 옛 서버를 잠시 더 띄워 두고 정리한 뒤 내린다.
- **로컬 작업 데이터는 각자 PC에 있다.** 서버 이사는 '공유·발행을 어디로 보내나'만 바꾼다.
- **NAS가 꺼져 있어도 앱은 멀쩡하다.** 공지 읽기·발행 모두 별도 프로세스로 격리돼 있어,
  응답이 없으면 몇 초 안에 포기한다(읽기는 조용히 넘어가고, 발행은 실패 안내로 끝난다).
- **공지를 다 돌린 뒤 파일을 지워도 번호는 이어진다.** [팀에 공지]를 누른 PC는 자기가 마지막에
  발행한 번호를 로컬에 기억해 두고, 다음 발행 때 **파일의 번호와 그 기억 중 큰 쪽 +1**을 쓴다.
  그래서 파일이 사라져도 1로 되감기지 않는다(되감기면 이미 더 높은 번호를 받아들인 PC들이
  새 공지를 조용히 무시한다). 다만 **지운 뒤에는 아직 안 옮긴 PC가 알림을 못 받으므로**,
  전환이 다 끝난 게 확인된 뒤에만 지운다.
  - 이 기억은 **[팀에 공지]를 누른 그 PC**에만 있다. 다른 PC에서 처음 발행하면 그 PC에는
    기억이 없으므로 파일의 번호를 따른다 — 파일까지 없으면 1부터 시작한다. 발행은 늘 같은
    관리자 PC에서 하는 것이 안전하다.

## 7. 사용자가 직접 주소를 바꾸는 길(공지 없이)

이미 로그인 화면에 갇힌 PC는 로그인 화면의 **'서버 주소 변경'** 패널에서 주소를 직접 넣고
'연결 테스트' 후 로그인하면 된다. 공지 파일과 무관하게 동작하는 수동 탈출구다.
