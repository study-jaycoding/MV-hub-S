# 공유 서버 주소 이사 공지 (관리자용)

공유 서버를 새 PC·새 IP로 옮기면, 작업자 PC의 허브는 옛 주소를 계속 바라본다. 그대로 두면
공유·발행이 실패하고 결국 로그인 화면에 갇힌다(주소를 바꿀 관리자 화면은 로그인해야 열린다).

**릴리스 폴더에 공지 파일 하나를 두면** 작업 중인 사람에게 알림이 뜨고, 확인 한 번으로
새 주소로 전환된다. 이 문서는 그 공지 파일을 쓰는 방법이다.

---

## 1. 공지 파일 놓을 위치

작업자 설치본의 `INSTALL_SOURCE.txt`가 가리키는 **릴리스 폴더** — `latest.json`,
`MVHub_Install.bat`이 있는 그 폴더다. 거기에 `server-location.json`을 만든다.

```text
\\NAS\releases\MVHub\
    latest.json                ← 앱 버전 (건드리지 않는다)
    MVHub_v1.4.2.zip
    MVHub_Install.bat
    server-location.json       ← 이 파일을 새로 만든다
```

> **왜 latest.json에 안 넣나**
> 릴리스 스크립트(`release/make_release.ps1`, `release/select_release.ps1`)가 latest.json을
> 정해진 필드 목록으로 **통째로 다시 쓴다**. 거기에 주소를 적어 두면 다음 릴리스를 만드는
> 순간 지워진다. 또 앱 버전을 롤백하면 주소 공지까지 함께 되감기는데, 서버 주소와 앱 버전은
> 서로 다른 사건이다. 그래서 파일을 분리한다.

## 2. 파일 내용

```json
{
  "shared_server_url": "http://192.168.1.50:8010",
  "server_revision": 3,
  "server_name": "MV 팀 서버",
  "announced_at": "2026-08-23T10:00:00+09:00"
}
```

| 필드 | 규칙 |
| --- | --- |
| `shared_server_url` | 새 공유 서버 주소. **`http://` 또는 `https://`로 시작**해야 한다. 후행 슬래시는 있어도 되고 무시된다. 계정정보(`user:pw@`)·물음표 뒤 쿼리는 넣을 수 없다. |
| `server_revision` | **1 이상의 정수.** 주소를 바꿀 때마다 **반드시 1씩 올린다.** |
| `server_name` | 작업자 화면에 주소 대신 보일 **서버 이름**(선택). 64자 이내 한 줄. 비우거나 빼면 작업자에게 주소가 그대로 보이고, 이미 그 PC에 등록된 이름이 있으면 그 이름을 계속 쓴다. |
| `announced_at` | 알림에 보일 시각(문자열). 없어도 동작한다. |

메모장으로 저장해도 된다(UTF-8 BOM 허용).

> `server_name`에 숫자·배열을 넣거나 줄바꿈이 섞이면 **공지 전체가 무시된다**(이름만 반쯤
> 적용돼 PC마다 다른 표기를 보는 상태를 만들지 않기 위해서다). 이름은 따옴표로 감싼 한 줄
> 문자열이어야 한다.

### `server_revision` 규칙 — 가장 중요한 한 가지

- 주소를 바꿀 때마다 **번호를 올린다.** 3 → 4 → 5.
- **번호를 올리지 않고 주소만 고쳐 쓰지 마라.** 이미 3번 공지를 받아들여 옮긴 PC와 아직
  안 옮긴 PC 중 어느 쪽이 맞는지 판단할 근거가 사라진다. 이 경우 허브는 **공지를 무시하고
  오류 로그만 남긴다**(사고를 조용히 퍼뜨리는 대신 멈춘다).
- 번호를 **낮추면** 아무 일도 일어나지 않는다. 이미 더 높은 번호를 받아들인 PC는 옛 주소로
  자동으로 되돌아가지 않는다. 되돌리려면 번호를 **더 높여서** 옛 주소를 다시 공지한다.
  (예: 3번=새 주소로 옮겼다가 취소하고 싶으면, 4번=옛 주소로 공지한다.)

## 3. 권한 — 작업자에게 쓰기 권한을 주지 마라

이 파일은 **작업자 허브가 무조건 신뢰하는 값**이다. 여기 적힌 주소로 옮길지 사용자에게 묻고,
수락하면 그 주소가 이 PC의 공유 서버가 된다.

- 릴리스 폴더와 **같은 ACL**을 쓴다: 관리자만 쓰기, 작업자는 **읽기 전용**.
- 작업자가 쓸 수 있으면 팀 전체의 서버 주소를 임의로 바꿀 수 있다.

## 4. 이사 절차

1. 새 PC에서 공유 서버를 띄우고, 새 주소로 `http://<새주소>/api/health`가 응답하는지 확인한다.
2. 릴리스 폴더의 `server-location.json`을 새 주소 + **올린 번호**로 저장한다.
3. 작업자 PC는 **앱을 켜 둔 채로 최대 1분 안에** 공지를 확인한다(기동 시 1회 + 1분 주기).
4. 작업자 화면 오른쪽 위 알림(종 아이콘)에 **"'MV 팀 서버' 서버가 새 위치로 이동했습니다"**가
   뜬다(이름을 안 넣었으면 주소가 보인다). 클릭하면 확인창이 새 주소를 보여주고,
   "예, 전환" → 로그아웃되고 새 주소 기준 로그인 화면이 열린다.
5. 다시 로그인하면 끝이다.

전환을 미뤄도(닫아도) 다음에 앱을 켜면 다시 알림이 뜬다. 옛 주소로 남아 있으면 공유가
안 되므로, 결국 옮기는 것이 맞다.

### 알림이 안 뜰 때 확인할 것

| 증상 | 원인 |
| --- | --- |
| 아무 PC에도 안 뜬다 | 파일명·위치가 틀렸다. 릴리스 폴더에 `server-location.json`이 맞는지, `INSTALL_SOURCE.txt`가 그 폴더를 가리키는지 확인. |
| 특정 PC만 안 뜬다 | 그 PC가 **릴리스 설치본이 아니다**(개발용 Git 실행본·공유 서버 본체는 대상이 아니다). 또는 이미 그 주소를 쓰고 있다. |
| 파일은 맞는데 안 뜬다 | ① `server_revision`을 안 올렸다. ② 새 주소가 아직 응답하지 않는다 — **응답하는 MV Hub 서버로 확인될 때만** 알림이 뜬다(닿지도 않는 주소로 옮기면 로그아웃만 되고 더 갇히기 때문). 서버를 먼저 띄우고 다시 확인한다. |

## 5. 서버 이름 — 작업자에겐 이름만 보인다

작업자에게 IP·포트를 외우게 하지 않는다. 관리자만 주소를 다루고, 작업자 화면에는 이름이 뜬다.

- **등록:** 관리자 창 → **공유 서버** 탭 → "서버 이름"과 "주소"를 함께 저장한다.
  (이사 공지의 `server_name`은 옮겨 갈 때 이 값을 대신 갱신해 준다.)
- **보이는 곳:** 로그인 화면 안내문("MV 팀 서버에 연결"), 이사 알림 문구.
- **안 보이는 곳:** 로그인 화면의 **'서버 주소 변경'** 패널은 그대로 주소를 보여준다 —
  서버가 죽어 갇혔을 때 쓰는 탈출구라 실제 주소가 필요하다.
- 이름을 비우면 예전처럼 주소가 그대로 보인다. 언제든 바꿔도 되고, 서버 동작에는 영향이 없다.
- 이름은 **주소마다 따로** 기억된다. 옛 주소로 되돌아가 로그인하면 그때 쓰던 이름이 되살아난다.
- 로그아웃해도 서버 이름은 남는다(로그인 화면에서 필요하다). 로그인한 **사람**의 표시 이름과는
  별개의 값이다.

## 6. 알아 둘 것

- **전환하면 그 PC는 로그아웃된다.** 토큰은 서버마다 다르므로 새 주소에서 다시 로그인해야
  한다. 옛 주소는 로그인 화면의 '최근 주소'에 남아 되돌아갈 수 있다.
- **옛 서버에 남은 미완료 작업은 옮겨 가지 않는다.** 위임 모드에서 옛 서버에 걸려 있던
  공유 상태는 그 서버에 그대로 얼어붙는다(마이그레이션은 이 기능의 범위가 아니다).
  필요하면 옛 서버를 잠시 더 띄워 두고 정리한 뒤 내린다.
- **로컬 작업 데이터는 각자 PC에 있다.** 서버 이사는 '공유·발행을 어디로 보내나'만 바꾼다.
- **NAS가 꺼져 있어도 앱은 멀쩡하다.** 공지 읽기는 별도 프로세스로 격리돼 있어, 응답이
  없으면 몇 초 안에 포기하고 조용히 넘어간다.
- 공지를 다 돌린 뒤 파일을 지워도 된다. 이미 옮긴 PC는 그대로고, 아직 안 옮긴 PC는 알림을
  못 받으니 급하지 않을 때만 지운다.

## 7. 사용자가 직접 주소를 바꾸는 길(공지 없이)

이미 로그인 화면에 갇힌 PC는 로그인 화면의 **'서버 주소 변경'** 패널에서 주소를 직접 넣고
'연결 테스트' 후 로그인하면 된다. 공지 파일과 무관하게 동작하는 수동 탈출구다.
