# 결과물 훑기 — NAS 결과 파일과 생성물 잇기의 토대

작성일: 2026-10-03 · 설계: Claude · 검토: Codex(설계 3회 → 승인, 코드 리뷰 반영) · 결정: Jay("화면·분석 방식은 아직. 토대만")

## 1. 목적과 범위

NAS 프로젝트 폴더의 결과 파일마다 "어느 생성물(job)인가"를 판정할 **재료와 판정 함수**를 만든다. 작업자 생성 분석의 토대다.

- **이번에 만든 것:** 결과물 훑기(스냅샷 저장)와 판정 함수 `services/nas_results.link_project`.
- **일부러 안 만든 것:** 화면, 분석 방식, 결과를 내보내는 API, 공개 범위 규칙. 쓰는 기능이 생길 때 정한다.
- **계약:** 판정은 **관측된 일치**다. 생성물·팩트의 프로젝트·폴더 같은 데이터를 고치지 않는다.
  `assets/` 같은 레퍼런스 폴더에서 이어진 것은 "그 폴더에 있다"일 뿐, 최종 사용·선택의 증거가 아니다.

## 2. 왜 에셋 대장과 따로 두나

에셋 대장([ASSET_REGISTRY.md](ASSET_REGISTRY.md))은 레퍼런스의 정체(이동·판)를 전체 sha256 으로 추적한다. 여기에 render 를
넣으면 큰 파일·작성 중 파일의 미판정이 **같은 루트의 레퍼런스 이동·없어짐 판정까지 막는다**(Codex). 그래서 대장은 그대로 두고
(render 제외 결정 유지), 결과물은 가벼운 **스냅샷**으로 따로 훑는다.

## 3. 훑기

- **언제·어디서:** 대장 훑기가 프로젝트 하나를 끝낸 직후, **같은 자리**(서버 훑기, 또는 도우미 PC 의 서버 자리 lease 안)에서
  같은 루트를 이어서 훑는다(`AssetRegistryController._results_project`). 대장 결과와 무관하게 돌고, 실패해도 대장에 영향이 없다.
  서버가 종료 중이면 건너뛴다.
- **자식:** `asset_registry_scan.py` 의 결과물 모드(`job["results"]`). 대장과 같은 목록 규칙(숨김·링크 폴더·미디어 확장자·
  폴더 속도 상한·부모 감시)이되 **render 포함**. 파일마다:
  - `stat` → 앞 64KiB 읽기 → (PNG 면) 번호 찾기 → `stat`. 크기·시각이 바뀌었으면 undetermined(값 없음).
  - `head_sha` = 앞 min(64KiB, 크기) sha256 — [RESULT_FINGERPRINT.md](RESULT_FINGERPRINT.md) 의 장부 쌍과 같은 정의.
  - PNG 번호: **시작부터** 청크 머리(길이·타입)를 따라 걷는다. 큰 청크(IDAT 등)는 seek 로 건너뛰고 `tEXt`·`iTXt` 본문만
    4KiB 상한으로 읽는다. 키 `hf-job-id`(힉스필드)·`mvhub.job_id`·`mvhub.gen_id`(이 앱 각인), 값은 UUID 꼴만.
    번호로 쓰는 텍스트 청크는 **CRC 가 맞아야** 하고, iTXt 는 압축 표시·압축 방식이 모두 0 일 때만 쓴다. 길이가 파일 끝을 넘거나
    타입이 4글자 영문이 아니면 거기서 멈추고, 못 본 번호는 **미관측(null)**. 끝부분을 '찾아 내는' 검색은 하지 않는다(이미지 데이터를
    번호로 오인하지 않게). **같은 키에 다른 번호**가 있으면(앱 각인은 기존 청크를 두고 더한다) 고르지 않고 `id_conflict=1`.
  - 파일 하나 30초, 프로젝트 하나 15분 상한. 시간이 모자라면 남은 파일은 pending(값 없음)으로 적고 목록은 끝까지 읽는다.
    30초는 **읽기와 읽기 사이에** 재는 상한이다 — NAS 읽기 한 번이 멈추면 끊지 못하고, 부모가 15분+30초(`KILL_GRACE_S`) 뒤
    자식을 끝낼 때 풀린다(그동안 그 자리를 붙잡는다 — 병합 전 검토 Codex, 실제 SMB 멈춤 실측은 아직).
    **이어 읽기는 없다** — 매번 처음부터 읽으므로 폴더가 아주 크면 뒤쪽 파일이 계속 pending 일 수 있다(실측 규모에서는 15분 안에 끝남).
- **비용(실측 10-03):** MUDX `10_ai` 1,948 파일 299초(NAS 왕복이 대부분), 산해학원 526 파일 22초.
- MP4 의 앱 각인·C2PA 는 읽지 않는다(한계).

## 4. 저장 — 서버 content DB

| 표 | 내용 |
|---|---|
| `nas_result_scan` | 프로젝트마다 최신 완주 스냅샷 하나: scan_id · **훑기 시작 때의 루트** · server/helper · 파일 수 · 시각 |
| `nas_result_file` | (프로젝트, 상대 경로) 마다 크기·mtime·head_sha·hf_job_id·mv_job_id·mv_gen_id·id_conflict·status(ok/undetermined/pending) |

- **완주한 훑기만** 그 프로젝트의 스냅샷을 통째로 바꾼다(`services/asset_registry.apply_results_snapshot`). 파일이 바뀌면 다음 완주가
  새 값으로 덮으므로 옛 번호가 남지 않는다.
- 루트는 `root_key`(공유 주소로 풀리면 UNC, 아니면 서버가 읽는 경로, 소문자)로 적고 견준다. **지금 루트가 시작 루트와 같은지
  다시 보는 것과 교체를 한 트랜잭션에서** 한다. 다르면 버린다. 조회도 지금 루트로 만든 스냅샷만 쓴다(루트가 바뀌면 다음 완주까지 없음).
- **도우미:** 관리자 PC 가 훑은 결과를 `POST /api/asset-registry/helper/results` 로 올린다. 대장 결과와 같은 자리·순번 규칙
  (같은 순번·같은 내용 재전송은 저장한 답). 본문은 파싱 전에 32MiB 로 막는다(`upload_limits`). 서버는 자리의 공유 주소를
  시작 루트로 쓰고(scan_id 는 반영 때 서버가 만든다), 줄마다 엄격히 검사한다(상대 경로·숨김·
  미디어·중복, ok 면 64자 지문·UUID 꼴 번호, ok 가 아니면 값 없음 — render 는 허용). 옛 서버(라우트 없음)·연결 실패면 도우미는
  올리기를 건너뛰고 대장 훑기를 계속한다.

## 5. 판정 — `services/nas_results.py`

단서마다 **후보 job 집합**을 만들고, 비어 있지 않은 집합들의 **교집합**으로 판정한다.

| 단서 | 세기 | 후보 |
|---|---|---|
| 파일 속 `hf-job-id` · 앱 각인 `mvhub.job_id` · 이름 `hf_…_<uuid>` | 강 | 장부에 있으면 {J}. 강 단서끼리 다르면 **충돌**. 장부에 없으면 **장부에 없음(J)** 으로 끝 — 약한 단서로 내려가지 않는다 |
| 앱 각인 `mvhub.gen_id` | 보조 | 장부 local_gen_id 가 같은 job 들. 풀리지 않으면: 위 job 단서가 있으면 무시(서버 카드 id 일 수 있다), 없으면 **장부에 없음**으로 보류 — 약한 단서로 내려가지 않는다 |
| 사이트 받기 이름 `<…>-<job 앞 8hex>` | 중 | 앞자리가 맞는 job 전부 |
| (크기, 앞 64KiB sha256) | 약 | 쌍이 같은 job 전부 |

PNG `id_conflict` 면 바로 `conflict`.
결과: 교집합 하나 → `linked` · 비면 → `conflict` · 여럿 → `candidates` · 단서 없음 → `unmatched` (+ `absent`). 같은 job 의 장부 행이
여러 계정이면 `owner_ambiguous`. 유일성은 **전체 장부**로 판정한다 — 공개 범위로 먼저 거르면 거짓 '유일'이 생긴다(공개 필터는
쓰는 기능이 정한다). 판정은 저장하지 않고 부를 때 계산한다.

실측(10-03, 서버 장부 사본 — 지문 쌍은 아직 없음): MUDX linked 97(파일 속 번호 80 · 이름 17) · unmatched 1,851 /
산해학원 linked 8 · absent 359 · unmatched 159.

## 6. 쓰는 법(토대)

서버에서 `services.nas_results.link_project(project_id)` → 스냅샷 파일마다 판정이 붙은 목록. 장부 표를 여러 프로젝트에 쓰려면
`build_index(ledger_rows())` 를 한 번 만들어 `index=` 로 넘긴다. 분석은 파일 사본 수와 고유 job 수·크레딧을 따로 센다.
