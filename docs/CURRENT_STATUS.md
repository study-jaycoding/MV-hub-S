## 방금 완료한 작업

- **RL-20 — 워치독 busy·maintenance·사망 판정 분리**

  `/api/ready`는 DB 유지보수 중 연결을 기다리지 않고 즉시 `503 maintenance`와 `Retry-After: 5`를
  반환한다. 워치독은 정상·busy·maintenance·dead를 별도 상태로 센다. busy와 maintenance는 경보만
  남기고 서버를 끄지 않으며, 시작 유예가 끝났거나 한 번 정상화된 뒤 연속 dead가 임계치에 도달한
  경우만 정확한 서버 PID를 찾아 개입한다. 격리 Windows 실측에서 ready→busy→maintenance→ready는
  무개입 복구됐고, 실제 포트 소유 프로세스의 hang은 정확한 PID만 개입 대상으로 판정했다.

  백엔드 전체 845개·21 subtests, 프론트 76개 파일·535개, 프로덕션 빌드·아키텍처 검사를 통과했다.
  2코어·below-normal 100명 단기 부하는 로그인 100건과 작업 요청 3,706건 모두 성공했고, 작업 p95
  64.69ms, WS·장기 폴링 오류와 SQLite lock 0건, 최대 RSS 198,799,360바이트였다.

## 갱신 규칙

- 위험 상태는 Gate 0 표에서 먼저 바꾼 뒤 이 문서의 요약을 맞춘다.
