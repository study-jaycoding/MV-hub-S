# 견적 CLI 동시 실행·취소 수명주기 계약

기준일: 2026-08-16

대상 위험: `RL-08`

구현 기준: `dev`의 `28f49cc6`

## 목적

여러 사용자와 브라우저 탭이 동시에 생성 비용을 조회해도 Higgsfield 견적 CLI 프로세스가 무제한으로
늘지 않게 한다. 요청 취소·타임아웃·서버 종료 때 실행 중인 CLI 부모와 자식 프로세스를 남기지 않는다.
견적은 부가 통계이므로 이 보호 장치가 실제 생성 요청 응답을 기다리게 해서는 안 된다.

## 실행 계약

1. 견적 CLI 동시 실행 기본값은 2개다.
2. `CONTENT_HUB_ESTIMATE_CONCURRENCY`로 조절할 수 있지만 1~8 범위로 제한한다.
3. 상한을 넘는 견적은 새 프로세스를 만들지 않고 이벤트 루프에서 비동기로 기다린다.
4. 같은 모델·옵션의 유효한 비용 캐시는 CLI 없이 즉시 반환한다.
5. 서로 다른 견적이 동시에 완료돼도 비용 캐시 파일 쓰기는 순서대로 처리해 최신 항목을 잃지 않는다.
6. 생성 요청은 placeholder와 pending 기록을 먼저 반환하고 견적은 백그라운드에서 갱신한다.

## 취소·종료 계약

| 상황 | 처리 |
|---|---|
| CLI 시간 초과 | Windows `taskkill /T /F`로 부모·자식 트리 종료 후 부모 process wait |
| HTTP/백그라운드 task 취소 | 같은 종료·회수 절차 후 `CancelledError`를 그대로 전달 |
| `taskkill` 실행 불가 | 부모 process kill·wait로 최소 회수 |
| 서버 정상 종료 | 등록된 모든 백그라운드 견적 task를 취소하고 gather 완료까지 대기 |
| 정상 CLI 종료 | 기존 stdout·stderr·return code 계약 유지 |

이 계약은 비용 견적뿐 아니라 `cli_bridge._run`과 `_run_capture`를 사용하는 CLI 호출의 타임아웃·취소에도
적용된다. 실제 유료 생성은 작업자 에이전트의 별도 제출 계약을 따른다.

## 검증 기록

| 검증 | 결과 |
|---|---|
| 100명 동시 조회 가정(100개 견적 요청) | CLI 실행 구간 최대 2개 |
| 병렬 비용 캐시 | 마지막 스냅샷에 100개 모두 보존 |
| Windows 실제 자식 트리 취소 | 테스트 부모·손자 종료, 2초 뒤 생존 마커 없음 |
| 타임아웃 | 종료·회수 함수 호출 후 `CLIError` |
| 서버 종료 | 남은 견적 task 취소·대기, 등록 집합 0개 |
| RL-08 대상 백엔드 | 24개 통과 |
| 백엔드 전체 | 746개 통과 |
| 프론트 전체·구조·빌드 | 522개·통과·통과(프론트 변경 없음) |

실측은 Python 테스트 자식 프로세스와 가짜 비용 응답을 사용해 실제 크레딧을 소비하지 않았다. 실제
Higgsfield CLI 응답 지연·네트워크 장애는 Gate 6의 외부 통합 실측에서 별도로 확인한다.
