## 1. 무엇인가

캔버스 옆 네 번째 탭. 위에 미디어 풀과 뷰어(싱글/듀얼), 아래에 트랙(레이어) 타임라인이 있고, **폴더 순서대로 컷 자리가 자동으로 잡힌다.**
그 자리에 내가 고른 공유 생성물이 들어가고, 재생하면 컷 순서대로 이어서 본다.

**Jay 가 정한 것**

- 다빈치와 같은 조작감.
- 같은 컷에 여러 개를 쌓아도 흐리게 하지 않는다. **위 트랙이 우선 보인다.**
- **고르지 않은 컷은 비워 둔다**(자동 채우기 없음).
- 편집은 **나만 본다**(팀 공유 아님).

**1차 범위**: 보기·고르기·쌓기·트랙 옮기기·빼기·끄기·재생·확대.
**일부러 안 만든 것**: 자르기(클립을 둘로)·앞 자르기·시간 방향 이동·파형·팀 공유.
(내보내기는 2026-10-13 에 **타임라인 Resolve 보내기**로 들어왔다 — §7. 파일로 내보내기(XML·EDL·영상 렌더)는 없다.)
(2026-10-13 Jay: **클립 길이 줄이기**(뒤를 자른다 — `trim`)와 **컷(폴더) 순서 바꾸기**(`cutOrder`)가 들어왔다 — 문서 칸·계산은 §4·§5.)

> [!NOTE]
> **클립은 자기 컷(폴더) 자리 안에 있다**(A안). 클립은 자기 컷 자리 안에서 트랙만 옮기고, 컷 길이가 바뀌면 뒤 컷이
> 밀린다. 시간 방향으로 자유롭게 옮기는 것(B안)은 자동 자리와 어긋나고 데이터 모델이 달라져 후속으로 미뤘다.
> Jay 가 이 선택에 직접 답한 것은 아니다 — Claude 권고·Codex 동의로 진행했다. 바꾸려면 여기부터 다시 연다.
> 컷끼리의 순서는 2026-10-13 부터 내가 바꿀 수 있다(§3) — 컷 하나를 통째로 옮기는 것이라 A안 그대로다.

## 2. 진입 — `Filters["tab"]` 의 값이 아니다

`tab ===` 비교가 프런트에 100곳이 넘어, 네 번째 값을 넣으면 "내 작업으로 떨어지는" 분기가 조용히 생긴다.
그래서 편집은 내비 기록의 별도 '보기'다.

- `useAppNavigation` 의 `NavView.edit`. `openEdit()` 로 들어가고, `navTab()`·`enterBoard()` 는 편집에서 나온다.
  위에 뜬 창(관리자 등)을 닫으면 편집으로 돌아온다. 편집 칸이 없는 옛 기록은 편집이 아니다.
- `App.tsx` 의 `editOpen` 이 켜지면 `.body` 안을 `EditTab` 하나로 바꾼다. 밑의 탭 상태(filters·목록 훅)는 건드리지 않는다.

편집이 떠 있는 동안 `App.tsx` 가 맞춰 주는 것:

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| 들어오기 전에 떠 있던 폴더 보기 창 두 종류 | `listPeekCtx` 에 `editOpen` · `folderPeek` 닫기 | 창은 `.body` 밖에 그려지고 `.body` 를 inert 로 만든다. 편집 탭이 스스로 여는 폴더 창은 §7 |
| 캔버스 완료 감시 | `sceneBoardCoveredIds` 에 `!editOpen` | SceneBoard 가 없으면 그 id 를 App 감시가 맡아야 한다 |
| 다빈치 선택 따라가기 | 라이브러리 `enabled && !editOpen` · 이벤트 처리부 맨 앞에서 반환 | 숨은 목록의 위치·활성 씬을 바꾸지 않게 |
| 라이브러리·프롬프트 단축키 | 두 훅의 `inactiveRef` — 라이브러리 쪽은 편집 탭이 연 폴더 창이 떠 있을 때만 듣는다 | Esc·D·Ctrl+K 가 편집 키와 겹친다 |
| 프롬프트 도크·선택 막대 | 숨김(상태줄은 남는다) | 편집 탭에는 생성 입력이 없다 |
| 밑의 목록 선택 | 들어올 때 비움 | 안 보이는 카드에 일괄 작업이 걸리지 않게 |

**멈추지 않는 것(의도적)**: 밑의 탭의 목록 새로고침(타이머·focus·WS). 그 탭에 앉아 있을 때와 같은 동작이다.
멈추려면 `dev` 와 같이 쓰는 훅 여러 곳을 건드려야 한다. 그 조용한 갱신이 실패하면 전역 알림이 뜰 수 있다(기존 동작).

  - 목록에 없는 컷(순서를 정한 뒤에 생긴 폴더)은 **이름순으로 자기 바로 앞인 컷의 뒤**에 선다(앞선 컷이 없으면 맨 앞). 같은 자리에
    여럿이 끼어도 그들끼리는 이름순이라, 같은 입력이면 언제나 같은 순서다.
  - 목록에만 있고 지금 없는 컷(폴더가 사라짐·목록을 아직 못 받음)은 건너뛰되 **목록에는 남긴다** — 돌아오면 제자리에 선다. 순서를
    바꿀 때도 그 자리를 지우지 않는다(`moveCut` 은 옮긴 결과 전체를 적는다 — Codex 설계 검토).
  - 옮긴 결과가 이름순과 같아지면 `cutOrder` 를 지운다(없음 = 이름순). `resetCutOrder` 는 이름순으로 되돌린다.
  - **지금 순서에서 제자리인 놓기는 아무것도 바꾸지 않는다** — 적어 둔 전체 목록으로만 견주면, 바로 뒤 컷 앞에 놓은 것이 그 사이의
    '지금 없는 폴더'를 넘어간 것으로 적혀 그 폴더의 돌아올 자리가 바뀐다(Codex 코드 리뷰 2026-10-13).

    바로잡는다(§5 의 `straightMarks`). 처음엔 옮기는 순간에 둘을 맞바꿨다: 없는 폴더 가운데 일부만 돌아오면 그때 예측한 자리와
    달라져 다시 뒤집혔다(Codex 코드 리뷰 2회째).
- 고른 폴더에 하위 폴더가 있으면 그 폴더가 시퀀스. 없으면 부모가 시퀀스고 그 컷으로 간다 — 단 **트리를 온전히 받았을 때만**
  (디스크 트리 실패·잘림이면 '하위 없음'을 믿지 않는다). P 바로 아래에 놓인 생성물은 컷이 아니다.
- 사이드바는 `ProjectSection` 을 쓰지 않는다. 그쪽은 폴더 클릭이 **생성 목적지를 서버에 저장**한다(`setProjectFolderSelection`).

**공유 생성물** = '공유 & 리뷰' 탭이 *자동 범위(지금 워크스페이스)에서 필터 없이* 그 폴더에 보여 주는 것.

  일반 공유·보류·최종을 모두 받고 카드에 ★/보류만 표시한다. 검색·작성자·타입·색·태그는 적용하지 않는다. 권한은 서버 계약 그대로.

  (이번 공간에서만, 저장하지 않는다).
- 쓸 수 있는 것 = 완료 + 결과 파일 있음 + 영상/이미지(오디오 제외).

- 여는 순간·시퀀스를 바꿀 때·[새로 고침]에서만 묻는다(폴링 없음). 문맥(계정·서버·워크스페이스·프로젝트·P)이 바뀌면
  받던 응답을 버리고 다음 쪽도 묻지 않는다. 실패하면 같은 문맥의 마지막 성공 결과를 그대로 둔다.
  - **밑의 탭의 폴링 틱은 변경이 아니다**(2026-10-13): 편집 탭은 밑의 탭 위에 떠 있고, 밑이 공유 & 리뷰면 그 목록의 15초 유휴
    폴링이 끝날 때마다 `libraryChanged` 가 온다(사이드바 숫자를 깨우려는 것 — `useGenerationAutoRefresh`). 그 알림에는 표식
    (`LIBRARY_POLL_TICK`)이 달려 있고, 편집 탭은 그것에는 **왼쪽의 숫자만** 다시 받는다(`reloadCounts`). 표식 없는 알림(이 창의
    공유 해제·삭제·담기)에만 공유 목록을 다시 받는다. 그 전에는 틱마다 목록 전체를 다시 받고 화면을 다시 그렸다(격리 실측 —
    60초에 8.7MB, 밑이 작업 공간이면 0.5MB. 고친 뒤의 수치는 재지 않았다). 밑의 목록 자신의 15초 폴링은 그대로 돈다.
- '끝까지 받음'은 **이번 조회가 끝까지 성공했을 때만**이다. 다시 받는 동안과 실패한 뒤에는 옛 결과가 화면에 남아 있어도
  끝까지 받은 것이 아니다.
- 폴더 연결 조회에 실패하면 '연결 없음'으로 치지 않는다 — 트리는 '온전하지 않음'으로 남는다.

클립의 미디어 상태는 셋이다.

| 상태 | 뜻 | 화면 |
|---|---|---|
| `ok` | 그 컷의 공유 목록에 있다 | 썸네일 |
| `missing` | 목록을 **끝까지** 받았는데 없다 | 붉은 줄무늬 '미디어 없음' |
| `unknown` | 실패·상한·조회 전 | 회색 줄무늬 '확인 못 함' |

`unknown` 을 '없음'으로 그리지 않는다. 클립은 어떤 상태에서도 자동으로 지우지 않는다.

## 4. 편집 문서 — localStorage

키 `mvhub.editDoc:<계정 네임스페이스>:<project_id>:<P>` — 시퀀스마다 문서 하나.

- **키가 `ch.` 로 시작하지 않는다**(2026-10-13 배포 전 점검, Codex P1 — main 코드로 확인): 편집 탭이 없던 옛 판(`main` `a83afe20` 까지)의 계정 전환
  정리(`clearPersonalSettings`)는 보존 목록 밖의 `ch.*` 를 전부 지운다. 새 판을 쓰다 옛 판으로 되돌린 뒤 계정을 바꾸면 모든 계정의 편집본이
  사라졌다(브라우저에만 있고 백업이 없다). 처음엔 `ch.editTimeline:<계정>:…` 였다. 화면 설정(`ch.editTimeline.ui`)·마지막으로 연 시퀀스
  (`ch.editTimeline.last:<계정>`)는 잃어도 되는 값이라 그대로 `ch.` 아래에 둔다.
- **옛 자리의 문서는 옮기지 않는다 — 새 자리에 없으면 옛 자리의 것을 읽고(`readEditRaw`), 쓸 때는 새 자리에만 쓴다. 옛 자리는 지우지도
  고치지도 않는다.** 처음엔 실릴 때 한 번에 옮겼다(복사 → 옛것 삭제). 두 창이 엇갈려 옮기면 한 창의 늦은 복사가 다른 창이 방금 저장한
  편집을 덮고, 옛 자리만 아는 빌드가 그 뒤에 저장한 것을 지울 수 있었다(Codex 재검토 P1 두 번) — 복사와 삭제가 없으면 그 경쟁도 없다.
  옛 자리에 문서가 있는 곳은 이 판 전의 개발 화면뿐이다(배포판에는 편집 탭이 없었다). 그 문서는 처음 저장할 때 새 자리에 생기고 옛 자리의
  것은 그때의 내용으로 남는다 — 옛 자리만 아는 빌드로 돌아가면 그 옛 내용이 보인다(새 자리의 편집이 지워진 것이 아니다). 한 번도 저장하지
  않은 옛 자리의 문서는 위의 '되돌리기 + 계정 전환'에 여전히 지워질 수 있지만, 그 조합(옛 자리의 문서 + 편집 탭이 없는 판)은 같은
  브라우저에서 만나지 않는다(개발 화면과 설치된 앱은 주소가 달라 저장소가 따로다).

```ts
interface EditClip { cut: string; gen: string; job?: string | null; track: number; off?: boolean; dur?: number; kind?: "video" | "image";
  trim?: number }                                             // 내가 줄인 길이(초) — 뒤를 자른다(§5)
interface EditDoc { v: 1; clips: EditClip[]; tracksOff: number[]; tracksLocked: number[]; muted?: boolean;
  cutsOn?: string[]; cutsOff?: string[]; hideOff?: boolean; // 컷(폴더) 비활성 — 기본값과 다르게 정한 것만(§7)
  tracks?: number; trackColors?: Record<number, string>;     // 트랙 줄 수·트랙 색(§7 트랙 머리 메뉴)
  markIn?: EditPos; markOut?: EditPos; markers?: EditMarker[]; // 마크 인/아웃·북마크(§7) — EditPos = { cut, local }
  cutOrder?: string[] }                                      // 내가 정한 컷 순서(§3) — 없으면 이름순
interface EditMarker { cut: string; local: number; color?: string; name?: string }
```

- `tracks`·`trackColors`·`markIn`·`markOut`·`markers`·`trim`·`cutOrder` 는 전부 선택 필드다 — 옛 문서는 그대로 읽힌다(없으면 트랙 3줄·색
  없음·표시 없음·원본 길이·이름순). 색은 `#rrggbb` 만, 북마크는 (컷, 프레임)에 하나만 받는다(어긋나면 문서 전체를 못 읽은 것으로
  본다 — 아래 `.bad`).
- **`v` 는 1 그대로다**(`trim`·`cutOrder` 를 더하면서 올리지 않았다). 올리면 이 칸을 모르는 빌드가 문서 전체를 '읽지 못함'으로 본다.
  그 대신 **이 칸을 모르는 빌드가 그 문서를 저장하면 두 칸이 사라진다**(`parseEditDoc` 은 아는 칸만 남긴다) — 길이는 원본으로, 순서는
  이름순으로 돌아간다. 클립·트랙·표시는 그대로다. 그런 빌드는 지금 개발 화면의 옛 판뿐이다(배포판에는 편집 탭이 아직 없다).

- `gen` = 팀 카드 id(서버 UUID). `job` = job_id — id 로 못 찾을 때 **그 컷에서 하나만 맞으면** 다시 잇는다.
- `dur` = 넣는 순간 배치에 쓴 길이(실측 → `params.duration` → 5초, 이미지 5초). 실측값이 오면 고쳐 적는다(되돌리기 단계 아님).
  목록·메타데이터를 못 받아도 배치가 변하지 않게 하려는 것이다.
  - **영상 클립은 페이지를 열 때마다 다시 잰다**(클립마다 메타데이터 요청 — 같은 페이지에서는 `lib/videoDuration` 이 기억한 값이
    바로 온다). 적힌 길이만 보고 '이미 쟀다'고 건너뛰지 **않는다**. 2026-10-13 에 "적힌 길이가 요청 길이·기본 5초와 한 프레임 넘게
    다르면 잰 값"으로 보고 건너뛰게 넣었다가 같은 날 뺐다(Codex 코드 리뷰 4회째): `dur` 에는 요청 길이와 실측값이 구분 없이
    적히고, 요청 길이(`params.duration`)는 불변이 아니다 — 동기화가 저장된 params 위에 새 값을 덮는다
    (`backend/app/repo/generation_sync.py` 의 `_merged_params`). 요청 8초로 넣어 8 이 적힌 채 재지 못한 클립은, 요청 길이가 10초로
    바뀌면 '지금 요청과 다르니 잰 값'으로 보여 8초로 굳는다(컷 길이·trim 상한·Resolve 계획까지). **다시 재기를 건너뛰려면 문서에
    '쟀다'는 사실(과 그 소스를 가리키는 근거)을 따로 적어야 한다** — 하지 않았다(문서 칸이 하나 는다).
  - **잰 값은 모아서 한 번에 적는다**(2026-10-13 격리 실측 ⑤) — 첫 값이 온 뒤 0.5초(`MEASURE_SAVE_MS`) 동안 온 것을 한 번의
    저장으로(전에는 클립마다 저장·다시 그리기). 모으는 중에 문서가 바뀌거나(다른 편집) 탭을 떠나면 그 자리에서 적는다. 시퀀스를
    바꾸면 버려진다(rev 가 다르다) — 돌아오면 다시 잰다.
- 불변식: (컷, 트랙)에 클립 하나 · 같은 (컷, 생성물)은 한 번만.
- **서버 주소는 키에 넣지 않는다.** 서버 이사는 DB 를 통째로 옮겨 id 가 유지된다. DB 복제본 서버도 같은 프로젝트·생성물 id 를
  가지므로 같은 편집 문서가 이어진다(의도한 동작).
- 읽을 때 버전·모양·불변식을 검증한다. 읽지 못한 문서는 **빈 문서로 덮지 않는다** — 화면에 알리고, 처음 저장할 때 원문을
  `<키>.bad` 로 옮긴 것을 확인한 뒤에만 덮는다.
- 바뀔 때마다 저장한다. 실패하면 '저장 안 됨'이 남고 다음 변경 때 다시 시도한다. **저장하지 못한 문서는 다른 시퀀스나
  탭에 다녀와도 버리지 않고**(메모리), 돌아오면 한 번 더 저장해 본다. 새로고침하면 사라진다.
- 다른 창의 `storage` 이벤트는 '바뀌었다'는 알림으로만 쓴다. 저장소를 다시 읽어, 이 창의 마지막 저장과 같으면 무시하고
  다르면 받아들인다(되돌리기는 비운다). 그 전에 시작한 지연 콜백(끌기 확정·길이 기록)은 `rev` 가 달라 버려진다.
- **이 창이 문서를 바꾸기 직전에도 같은 것을 본다**(`useEditDoc` 의 `pull` — 편집·되돌리기·자동 길이 기록 모두. 2026-10-13 배포 전 점검,
  Codex P2): 알림은 늦게 온다(비동기). 그 전에 이 창이 저장하면 이 창의 낡은 문서 전체가 저장돼 다른 창의 편집이 사라졌다. 이제 다른 창의
  문서를 받아들이고 **이번 조작은 버린다** — 그 조작은 옛 화면을 보고 고른 것이다(비어 있던 트랙에 넣기로 했는데 그사이 다른 창이 그 트랙에
  넣은 클립을 밀어내는 식, Codex 재검토). 화면이 새 문서로 바뀌고 "…방금 한 조작은 적용하지 않았습니다 — 다시 해 주세요"가 뜬다.
  원문이 같으면 문서를 풀어 읽지 않는다. 남는 틈은 읽고 쓰는 사이뿐이다(두 창이 같은 순간에 저장 — 잠금을 두지 않았다).
  저장 못 한 편집이 있는데 다른 창의 저장을 **그 순간에야 알았으면** 그 조작도 멈추고 알리기만 한다(알림이 뜨기도 전에 덮지 않게).
  알고 난 뒤의 편집은 전처럼 저장한다(아래 충돌 규칙).
- **저장하지 못한 편집이 있는 동안에는 창을 닫거나 새로고침할 때 브라우저가 한 번 묻는다**(`lib/unloadGuard` 의 `beforeunload`. 저장되면 묻지
  않는다). 이 문지기는 **사용자가 직접** 닫거나 새로고침할 때의 것이다. 앱이 스스로 하는 새로고침은 따로 다룬다(Codex 재검토 — 묻는
  창에서 머무르기를 고르면 서버·계정은 이미 바뀌었는데 화면만 옛 상태로 남는다):
  · **업데이트 완료** — 저장하지 못한 편집이 있으면 스스로 새로고침하지 않고 "업데이트가 끝났습니다 — 저장하지 못한 변경이 있어…"를
    띄운다([지금 새로고침] · [닫기]). 전에는 말없이 새로고침해 메모리에만 남은 편집이 사라졌다(Codex P2). 판정은 **새로고침하는 그
    순간에** 한다(`reloadIfFree` — 예약한 0.6초 사이에 '저장 안 됨'이 생길 수 있다). 설정 창의 업데이트 폴도 같은 판정을 쓴다 — 전에는
    따로 0.5초 뒤 묻지 않고 새로고침해 덮개가 묻기도 전에 편집이 사라졌다(Codex 재검토 3회째).
  · **로그아웃** — 누르는 순간, 계정·서버의 상태를 바꾸기 **전에** 묻는다(`useHubAuth.logout` 의 확인 창). 계속하면 묻지 않고 새로고침한다.
    요청을 보내고 응답을 기다리는 동안은 **떠나는 중**이라 편집·되돌리기·자동 길이 기록을 받지 않는다(`setLeaving` → `useEditDoc` 이
    `stopped` 로 답하고, 사용자의 조작이면 "로그아웃하는 중입니다 — 지금 한 조작은 적용하지 않았습니다"를 띄운다) — 확인 뒤에 새로
    생긴 '저장 안 됨'은 묻지 못한 채 사라지기 때문이다. 요청이 실패하면 풀린다.
    **로그아웃 요청은 하나뿐이다** — 진행 중에 다시 누르면 그 요청의 결과를 같이 기다린다(둘이 따로 돌면 하나의 실패가 잠금을 풀고,
    기다리던 다른 하나의 성공이 그사이의 편집을 지운다). **응답이 10초 안에 끝나지 않으면 끊고, 로그아웃이 됐는지를 허브에 물어 정한다**
    (됐으면 새로고침, 아니면 풀고 "로그아웃하지 못했습니다…". 묻지도 못하면 안 된 것으로 본다 — 실제로는 됐다면 다음 요청의 401 이
    로그인 화면으로 보낸다). 끝나지 않는 요청이 편집을 영영 잠그지 않게 하려는 것이다(Codex 재검토 4회째).
  · **DB 가져오기 · 서버 백업 복원** — 원래 있던 확인 창에 "편집 탭에 저장하지 못한 변경이 있습니다 — 이 작업이 끝나면 화면이
    새로고침되어…" 한 줄을 붙인다(`unsavedNote` — 있을 때만). 시작한 뒤에는 묻지 않고 새로고침한다(`reloadNow`).
  · 그 밖(계정 범위가 바뀐 뒤 · 서버 주소 전환 · 세션이 끊긴 뒤 다시 로그인)은 묻지 않고 진행한다(`reloadNow` — 전부터 새로고침하던
    길이고, 여기서 멈추면 화면이 어긋난다). 그 길에서는 저장하지 못한 편집이 사라진다(전과 같다 — 서버 주소 전환은 확인 창 없이
    바로 바꾸는 것이 Jay 의 결정이라 물을 자리가 없다).
- **바꾸기의 결과는 셋이다**(`EditOutcome` — `done` 바꿨다 · `none` 바꿀 것이 없었다 · `stopped` 다른 창의 저장 때문에 버렸다). 부르는 쪽은
  `none` 에만 "바꾸지 못했습니다 — 잠긴 트랙…" 같은 안내를 띄운다 — 알림 칸이 하나라, `stopped` 에 같은 안내를 띄우면 "다른 창에서 바꾼
  편집을 불러왔습니다…"를 덮는다(Codex 재검토 P2).
- 자리를 비운 사이(다른 시퀀스·다른 탭) 다른 창이 저장했으면, 다시 열 때 그 문서의 되돌리기를 비운다 — 옛 되돌리기가
  남의 저장을 덮지 않게.
- 저장 못 한 편집과 다른 창의 저장이 겹치면(충돌) **알리기만 하고 알아서 덮지 않는다.** 몇 번을 오가도, 자동 길이 기록이 와도
  저장하지 않는다 — 사용자가 편집을 이어 갈 때만 저장한다. 충돌은 저장 못 한 문서에 묶어 둔 '그때 알던 원문'과 지금 저장소를
  비교해 가리므로, 다시 열 때마다 같은 답이 나온다.
- 되돌리기/다시 하기 = 문서별 메모리 스택(100단계). 탭을 오가도 남고 새로고침하면 사라진다. 확정된 길이(`dur`)는
  되돌리기 대상이 아니다 — 옛 문서를 되살려도 길이는 지금 것을 따른다.

> [!WARNING]
> **백업이 없다.** 캔버스 씬은 로컬 DB 백업이 있지만 편집 문서는 localStorage 뿐이다. 브라우저 프로필을 지우거나
> 다른 PC·다른 프로필에서 열면 편집이 없다. 팀 공유·백업이 필요해지면 DB 로 옮긴다.

## 5. 배치와 위치 (`lib/editTimeline.ts`, 순수)

- 클립 길이(`clipLen`) = `dur`, 내가 줄였으면 `trim`(2026-10-13 Jay — 뒤를 자른다). 줄이기 전의 길이는 `clipFull`(= `dur`)이고 배치의
  클립은 둘을 다 든다(`SlotClip.len`·`full` — 타임라인의 클립에 `3.0s / 5.0s` 로 보인다).
  - **영상만** 줄인다. 그림은 줄이지 않는다(`kind:"image"` 의 `trim` 은 무시) — Resolve 가 스틸을 준 길이와 무관하게 5초로 놓아, 줄이면
    보낸 타임라인에서 다음 컷과 겹친다. `kind` 가 없는 옛 클립은 영상으로 본다.
  - 원본보다 길게는 안 된다 — `trim` 이 더 크면 쓰는 길이는 원본이다. 그래도 **적어 둔 값은 지우지 않는다**(`setClipTrim`): 넣는 순간의
    `dur` 은 추정값일 수 있어(실측 전), '원본 이상'이라고 지우면 실측이 온 뒤 내가 정한 길이가 원본 길이로 늘어난다(Codex 설계 검토).
  - `dur` 과 따로 둔 까닭: `dur` 은 실측이 오면 고쳐 적히고 되돌리기 대상이 아니다. `trim` 은 편집이라 되돌리기 대상이다.
  - 값은 프레임(24fps)에 맞춘다(`snapTrim` — 최소 1프레임, 원본을 넘지 않는 가장 긴 프레임까지. 상한은 내림: 3.02초 영상을 73프레임
    (3.0417초)으로 올리지 않는다). 잠긴 트랙의 클립은 거부한다.
- **컷 길이 = 그 컷의 켜진 클립 중 가장 긴 것**(2026-10-13 Jay: "v1 이 5초 v2 가 3초면 3초 보여주다가 남은 v1 이 더 보인다. 하지만
  v1 트랙이 꺼져 있다면 그 폴더는 3초만 재생된다"). 클립을 껐거나 그 트랙을 껐으면 세지 않는다(`clipIsOn` — 보이는 것과 같은 기준).
  켜진 클립이 없으면(빈 컷, 또는 넣은 것을 전부 껐다) 5초다.
  - 처음엔 꺼진 것까지 셌다("끌 때 길이가 출렁이지 않게"). 그러면 위 트랙이 끝난 뒤 꺼진 아래 트랙의 길이만큼 빈 화면이 나왔다.
  - 그래서 **꺼진 클립은 컷보다 길 수 있다**(`clip.len > slot.len`). 타임라인은 컷의 끝에서 잘라 그리고(다음 컷을 덮지 않게 — 잡기
    쉬운 최소 폭 6px 보다 컷의 경계가 먼저다: 한 프레임짜리 컷에서는 클립도 그 폭만큼만 그린다. 폭의 하한도 없고, 6px 보다 좁은
    클립은 테두리 없이 그린다 `.ed-thin` — 테두리 2px(고른 것 4px)는 폭을 줄여도 남아 다음 컷 자리를 덮는다),
    Resolve 계획도 컷의 끝에서 자른다(`buildTimelineExport` — 안 자르면 다음 컷의 같은 트랙 클립과 겹쳐 받는 쪽이 계획을 거부한다).
  - **한 프레임도 안 되는 컷**(켜진 클립이 반 프레임 미만 — 깨진 영상의 실측 길이 등)이 있으면 타임라인을 보내지 않는다
    (`TimelineExport.zeroCuts` — 확인 창이 "한 프레임보다 짧은 컷이 N개…"로 막는다). 클립은 최소 한 프레임이라 그 컷의 클립이 다음
    컷의 같은 트랙과 겹친다. 전에는 꺼진 긴 클립이 컷 길이를 잡아 주어 생기지 않던 입력이다(Codex 코드 리뷰).
  - 알고 남긴 것: 꺼 둔 **그림**이 컷보다 길면(켜진 영상이 5초보다 짧은 컷) 계획에는 잘린 길이로 적히지만 Resolve 는 스틸을 5초로
    놓는다 — 다음 컷과 겹쳐 '자리가 다른 클립'으로 보고된다(조용히 넘어가지는 않는다).
  - 트랙·클립을 켜고 끄면 컷 길이가 바뀔 수 있고, 재생헤드가 그 컷의 새 끝 뒤에 있었으면 컷 끝 직전으로 옮겨진다(아래).
- 보이는 클립 = 꺼지지 않은 것(클립·트랙) 중 아직 안 끝난 **가장 높은 트랙**. 위 클립이 짧으면(줄였으면) 끝난 뒤 아래가 비친다.
  잠금은 보이기와 무관하다.
- **위치의 원천은 (컷 경로, 컷 안 시각)** 이다. 앞에 컷이 끼어들거나 앞 컷 길이가 바뀌거나 컷 순서를 바꿔도 보던 자리가 유지된다.
  보던 컷이 배치에서 빠지면(숨김·폴더가 사라짐) **컷 순서에서** 그다음 컷 처음으로, 보던 컷이 짧아지면 컷 끝 직전으로 옮기고 재생을
  멈춘다(`settlePos`). '그다음'은 숨긴 컷까지 든 전체 순서(`cutPaths`)에서 찾는다 — 내가 순서를 정했으면 그 순서다. 폴더가 사라져 그
  순서에도 없는 컷은, 정한 순서에 적혀 있으면 그 자리에서, 아니면 새 컷이 서는 규칙(§3)으로 자리를 다시 찾는다.
- 넣을 트랙 = 그 컷의 가장 높은 클립보다 위에서 **켜져 있고 안 잠긴 가장 낮은 트랙**(넣자마자 보이게).
- 잠긴 트랙의 클립은 빼기·끄기·옮기기 모두 거부하고, 옮길 때는 도착 트랙의 잠금도 본다. 여러 개 옮기기는 전부 될 때만.
- 그리는 트랙 줄 수(`trackCount`) = 적어 둔 줄 수(`tracks`, 없으면 3)와 클립이 있는 가장 높은 트랙 중 큰 쪽. 상한은 없다.
- 마크 인/아웃·북마크의 자리도 **(컷 경로, 컷 안 시각)** 이다. 화면의 시각은 `markTime` 이 지금 배치로 바꾼다 — 그 컷이 배치에
  없거나(숨김·사라짐) 컷이 그 자리보다 짧아졌으면 **문서에는 남기고 화면에서만 뺀다**(끝으로 자르지 않는다 — 자르면 서로 다른
  표시가 한 자리에 겹치고, 길이가 돌아와도 제자리로 못 간다).
- 인/아웃 구간(`markRange` — 띠·구간 반복)은 **찍어 둔 표시가 다 보일 때만**이다(2026-10-13). 한쪽만 찍었으면 전처럼 전체의 처음/끝까지다.
  찍어 둔 표시가 안 보이는데 그쪽을 전체의 처음/끝으로 치면 구간이 말없이 넓어진다 — 아웃이 있는 컷이 트랙을 꺼서 짧아지는 순간 구간
  반복이 전체 끝까지 돈다(컷 길이가 켜고 끄기·길이 줄이기로 바뀌게 되면서 흔해질 일이라 고쳤다 — Codex 설계 검토). 표시는 문서에
  남아 있어 다시 보이면 구간도 돌아온다. 구간이 사라지면 구간 반복은 꺼진다(§7).
- **두 표시가 다 보이는데 인이 아웃보다 뒤면 맞바꿔 본다**(`straightMarks` — 2026-10-13). 컷 순서를 바꾸거나, 숨겼던 컷·사라졌던 폴더가
  돌아오면 문서의 인/아웃이 뒤집혀 있을 수 있다. **그리는 쪽(`marksOf`·`markRange`)과 찍는 쪽(`setMark`)이 같은 눈으로 본다** — 화면의
  '인'이 문서의 `markOut` 인 채로 인 지우기(Alt+I)를 누르면 엉뚱한 쪽이 지워진다. 문서는 다음에 표시를 찍거나 지울 때 바로잡힌 모양으로
  저장된다. 전에는 뒤집힌 구간이 말없이 사라졌다(길이가 음수라 구간이 아니었다).
- 넣을 자리의 판정(`placeState` — 빈 자리·교체·이미 여기·잠김)은 한 곳이다. 카드 휠 클릭 메뉴의 줄이 쓰고, 끌어 넣기의 강조도 같은
  것을 쓴다(둘이 어긋나지 않게 — `placeClip` 의 거부 조건과 같다).

## 6. 재생 (`lib/useEditPlayback.ts`)

영상 요소 둘을 하나처럼 다루며 이어 튼다(`lib/editVideoPair.ts` — 아래 '넘어가기'). 미리 받아 둔 것이 없으면 앞의 것에 주소를
갈아 끼운다.

- 시계 주인은 항상 하나. 보이는 클립이 영상이고 정방향 재생이면 **영상이 시계**(받는 중·버퍼링이면 시간도 선다),
  빈 자리·이미지·역방향·재생 못 하는 영상은 rAF + `performance.now()`.
- **'보이는 소스가 바뀜'은 컷이 바뀌는 것과 별개 사건**이다. 같은 컷에서 위 클립이 끝나 아래가 드러날 때도 일어나고,
  그때 아래 영상은 0초가 아니라 보던 시각에서 시작한다.
- 소스를 갈 때 순서: 정지 → 번호 올림 → 주소 교체 → `loadedmetadata` → 목표 시각으로 탐색 → `seeked` → 재생. 미리 받아 둔
  영상이면 주소 교체 대신 앞뒤를 바꾸고, 이미 그 자리에 있으면 탐색을 건너뛴다(가는 중이면 `seeked` 를 기다린다). 이미 도착한
  소스의 `loadedmetadata` 가 또 오면 무시한다.
- 위치를 옮길 때마다(훑기·재생 시작) 번호를 올린다. **마지막에 놓은 자리에 닿기 전에는 영상에 시계를 넘기지 않는다** —
  진행 중이던 옛 탐색이 끝나면 최신 자리로 한 번 더 보낸 뒤에 도착으로 친다.
- 배치가 바뀌어 위치를 보정하고 멈출 때는 영상의 옛 시각을 위치로 되받지 않는다.
- **멈추면 멈춘 자리를 그린다**(`stop` 의 끝에서 `paint`). 영상이 시계였으면 멈춘 그 프레임을 위치로 받는데, 그것이 마지막
  tick 이 그린 자리와 다를 수 있다(그 사이 편집점을 넘었으면 보이는 클립도 바뀐다). 안 그리면 재생헤드·시각 표시와 다이나믹
  트림 모드의 두 칸이 한 박자 낡은 채 선다(Codex 코드 리뷰).
- 재생 못 하는 영상은 정지화면으로 두고 길이만큼 지나간다. 적어 둔 길이보다 영상이 먼저 끝나면 그 클립의 끝으로 넘긴다.
- **실제 끝 뒤의 자리**(2026-10-11, 조작 점검): 적어 둔 길이가 실제 영상보다 길 수 있다 — 길이를 재기 전이거나 재지 못한 영상,
  그리고 차이가 한 프레임 미만이라 고쳐 적지 않는 영상. 브라우저는 실제 끝을 넘는 `currentTime` 을 끝으로 자르므로 **영상을 보낼
  자리는 `min(컷 안 시각, 영상의 실제 길이)`** 다(`aim` · `videoEnd` = `video.duration`. 모르는 것은 `NaN`(메타데이터 전)과
  `Infinity`(스트림)뿐이고 그때는 상한이 없다 — **0초도 길이다**: 모른다고 치면 0초로 잘린 자리를 계속 다시 보낸다). 재생헤드는
  놓은 자리 그대로고 영상은 끝 프레임에 선다. 자르지 않은 시각과 견주면 영영 '어긋남'이라 `seeked` 마다 같은 자리로 다시 보내고,
  도착하지 못해 그 자리의 재생이 '재생 중인데 시간이 선' 채가 된다. 그 자리에서 재생하거나 재생 중에 그리로 훑으면, 재생 중에
  먼저 끝난 것(`ended`)과 같게 **그 클립의 끝으로 넘긴다**(`passClip`). 길이 교정을 기다리지 않는다.
  - 넘기는 조건(`over`)은 둘 중 하나다 — **재생헤드가 실제 끝 뒤**거나 **영상이 그 끝에 서 있다**. 뒤의 것만 보면, 영상이 끝 바로
    앞(탐색 허용 오차 0.04초 안)에 있을 때 '도착'으로 치고 시계를 맡겨 재생헤드가 그 영상의 시각으로 되돌아간다. 앞의 것만 보면,
    끝에 선 영상에 `play()` 를 걸어 브라우저가 처음부터 다시 튼다. 이미 돌고 있는 영상에도 같은 조건을 본다(Codex 코드 리뷰).
  - **끝에 선 영상은, 자리가 그 끝보다 앞이면 허용 오차 안이어도 '도착'이 아니다**(`astray`) — 그 자리로 되감은 뒤 튼다. 오차
    안이라고 도착으로 치면 끝에 선 영상을 넘기게 되어, 틀 수 있는 마지막 조각을 건너뛴다: 실제 끝 직전에서 시작하는 구간 반복
    (실제 2.02초·구간 2~3초)이 '빈 바퀴'로 멈췄다(Codex 재검토). 되감기는 자리를 옮길 때(`sync`)와 영상이 넘어올 때(`onMeta`)만
    한다. 탐색이 끝난 자리(`onSeeked`)에서는 허용 오차만 본다 — 거기서도 되감으면, 되감아도 끝을 못 벗어나는 영상에서 `seeked`
    마다 다시 보내 끝이 없다. 그렇게 끝에 선 채 도착한 영상은 위의 `over` 가 넘긴다.

    | 재생헤드(컷 안 시각 P, 실제 끝 E) | 영상이 끝에 서 있다 | 서 있지 않다 |
    |---|---|---|
    | P < E − 0.04 | P 로 보낸 뒤 튼다 | 0.04초 안이면 그대로, 밖이면 P 로 보낸 뒤 튼다(평소) |
    | E − 0.04 ≤ P < E | **P 로 되감은 뒤 튼다** | 0.04초 안이면 그대로, 밖이면 P 로 보낸 뒤 튼다(평소) |
    | P ≥ E | 넘긴다(보내지도 틀지도 않는다) | 끝과 0.04초 안이면 그대로, 밖이면 끝으로 보낸 뒤 — 넘긴다(영상에 시계를 맡기지 않는다) |

  - **넘긴 자리는 그리지 않는다**: 프레임(tick) 안에서 넘겼으면 그 프레임이 한 번 더 본다(지난 시간 0) — 넘긴 자리가 구간의
    아웃·반복하는 끝을 지났으면 곧바로 되돌아가고, 아니면 다음 것(아래 클립·다음 컷)으로 가며, 넘어갈 다음이 없으면 전체 끝에서
    멈춘다. 넘긴 자리를 그리고 나서 다음 프레임에 되돌아가면, 구간 반복 중 재생헤드가 한 프레임 동안 아웃 너머(그 클립의 끝)를
    가리키고 판의 영상이 가려졌다(영상이 실제 끝에 닿은 것을 `ended` 보다 프레임이 먼저 본 때 — 2026-10-11 격리 실측). 넘길 때마다
    위치가 앞으로만 가므로 끝이 있고, **한 프레임에 넘기는 수는 넷까지다**(`PASS_MAX` 4 — 넷째를 넘겼으면 그 자리를 그리고 다음
    프레임이 잇는다. 재생을 누른 순간이나 영상 이벤트에서 넘긴 것은 프레임 밖의 일이라 세지 않는다). 브라우저에서는 보통 둘을
    넘지 않는다: 지금 것과 미리 받아 둔 다음 것 — 넘긴 뒤에 받기 시작한 영상은 같은 프레임에 준비되지 않는다.
  - **빈 바퀴는 돌지 않는다**: 반복·구간 반복·편집점 앞뒤 반복이 되돌아갈 때(`loopBack`), 방금 돈 바퀴가 **온전한 바퀴인데
    흐른 시간이 0** 이면 멈춘다 — 틀 것이 하나도 없어 넘기기만 한 바퀴다(구간 전체가 실제 끝 뒤 · 0초 영상뿐인 컷들. 컷이
    몇이든). 그냥 두면 프레임마다 넘기고 돌아오기만 되풀이해 '재생 중'인 채 화면의 시간이 선다. 엔진이 드는 것은 둘뿐이다 —
    바퀴를 열 때 적어 두는 `lap`(범위와 '온전한가')과 그 바퀴에 흐른 시간의 합 `flowed`. 일어난 일마다 깃발을 켜고 끄지 않는다:
    그렇게 하면 범위를 바꾸는 길과 시간을 흘리는 길을 전부 열거해야 해서, 빠진 길이 거듭 나왔다(Codex 재검토).
    - **판정하지 않는 바퀴**(온전하지 않은 바퀴 — 한 바퀴 더 돈 뒤에 판정한다): ① 바퀴의 처음보다 뒤에서 시작했다(재생을
      중간에서 눌렀다) ② 도중에 자리를 옮겼다(훑기·눈금자 클릭·컷/북마크/인·아웃/편집점 이동 — 모두 `seek` 한 곳을 지난다)
      ③ **되돌아가는 순간의 범위가 바퀴를 열 때의 범위와 다르다.** ③은 판정하는 순간에 견줄 뿐, 범위가 왜 달라졌는지는 묻지
      않는다 — 구간 반복을 끔 · 인/아웃을 옮김 · 편집점 앞뒤 반복의 그 컷이 배치에서 빠짐(비활성 숨기기) · 전체 길이가 달라짐이
      모두 같은 비교에 걸린다. 지나가지 않은 부분에 틀 것이 있는지 모르는 바퀴들이다.
    - **세는 시간**(무엇이 그 시간을 흘렸는지로, **프레임 한 걸음이 지난 구간에서** 센다 — 걸음의 출발 자리가 아니다):
      - 먼저 그 구간 [출발 자리, 닿은 자리]를 **바퀴의 끝에서 자른다**(지금 범위의 끝 — 구간 반복이면 아웃). 넘긴 자리가 아웃
        뒤일 수 있고, 거기서 흐른 시간은 이 바퀴의 것이 아니다: 세면 구간 안에 틀 것이 없는데도 아웃 뒤의 그림·영상 때문에 계속
        돈다. 아웃을 넘었는지는 되돌아가기 판정과 같은 타임라인 시각(컷의 시작 + 컷 안 시각)으로 본다 — 컷 안 시각으로 빼면
        아웃이 클립의 끝과 같은 자리일 때 끝자리 오차만큼 샌다.
      - 영상이 시계일 때는 그 구간에서 **영상의 시각이 앞으로 간 만큼**(도착 전·받는 중이면 0. 한 프레임보다 짧게 돌고 `ended` 로
        끝난 것도 그만큼 더한다 — 시계로 돌던 영상이 끝났다는 것은 끝까지 돌았다는 것이라 0 으로 치지 않는다. 다만 아웃 뒤에서
        돌다 끝난 것은 더하지 않는다 — 위와 같은 자름이다).
      - rAF 시계일 때는 그 구간을 **보이는 것이 바뀌는 경계(클립의 끝)로 쪼개, 틀 영상이 보이지 않는 조각(빈 자리·이미지·못 트는
        클립)의 길이만** 더한다(`idleFlow`). 틀 영상이 보이는 조각에서 rAF 로 버틴 시간(그 영상이 아직 도착하지 않았다: 앞의 것을
        넘겨 막 드러난 영상 등)은 세지 않는다. 걸음이 크면(배속·늦게 온 프레임) 그 안에서 보이는 것이 바뀐다 — 출발 자리만 보고
        걸음을 통째로 세거나 버리면, 뒤에 나타난 그림을 놓쳐 정상 반복이 멈추거나 영상 조각까지 센다. 조각은 그 컷 안에만 있어
        컷의 끝을 넘은 몫은 저절로 빠진다.
      - 그래서 0초 영상뿐인 컷들은 0 이고, 넘긴 뒤 드러난 그림은 한 걸음에 지나가도(큰 걸음의 중간이어도) 흐른 시간이며, 아웃
        뒤의 것은 무엇이든 바퀴를 살리지 못한다.
    - 돌아간 자리의 영상을 곧바로 넘겨 이미 바퀴의 끝을 지났으면(방금 연 바퀴가 흐른 시간 없이 끝난 것이다) 넘긴 자리를 그리지
      않고 거기서 멈춘다. **멈추는 자리는 돌아간 자리**다(구간 반복이면 인, 전체 반복이면 맨 처음 — 한 번만 트는 편집점 앞뒤
      재생이 그 편집점으로 돌아가 멈추는 것과 같다). 넘긴 클립의 끝에 서면 구간 반복이 켜진 채 재생헤드가 구간 밖에 남는다.
- **반복**(`loop`): 정방향으로 전체 끝에 닿으면 처음으로 돌아가 이어 튼다(역방향은 처음에서 멈춘다).
- **구간 반복**(`range` — 뷰어의 구간 반복 재생 단추가 켜져 있을 때만 엔진에 준다. 전체 반복과는 따로다): 아웃을 넘으면 인으로
  돌아간다. 돌아가는 것은 위치를 옮긴 것과 같게 다룬다(영상이 그 자리에 닿을 때까지 시간이 선다). '아웃을 넘었다'는 tick 앞뒤
  시각의 비교만으로 보지 않고 **아웃 앞에 있었는지를 적어 둔다**(`armed` — 재생 시작·위치 이동·되돌아간 직후에 다시 잡는다):
  영상의 `ended` 가 위치를 먼저 아웃으로 옮긴 때와, 한 프레임에 구간을 통째로 지나간 때를 놓치지 않으려는 것이다. 아웃 뒤에서
  시작했거나 아웃 뒤로 훑었으면 되돌아가지 않고 끝까지 간 뒤 구간 처음으로 들어온다. 켜는 순간은 `playRange` 가 맡는다 —
  **구간을 엔진에 먼저 넣고** 그 처음으로 가서 정방향(고른 배속)으로 튼다(상태가 반영되기를 기다렸다 틀면 그 사이 영상이 끝난 때를
  놓치고, 역재생 중이면 역방향이 이어진다).
- **편집점 앞뒤 재생**(`playAround(at, span, once)` — 다이나믹 트림 모드의 Space): 그 편집점의 `span` 초 앞으로 가서 정방향(고른 배속)으로
  `span` 초 뒤까지 튼다. `once` 면 끝에서 그 편집점으로 돌아가 멈추고(`wrap`), 아니면 그 구간을 되풀이한다. 구간 반복과 같은
  기계(`armed`·끝 판정)를 쓰되 **구간은 엔진이 쥔다**(`around` — 재생 중에만 있다): `stop` 과 모든 재생 명령(재생·J/L·
  `playRange`)이 지운다. 화면 상태로 두면 그 사이에 켠 구간 반복 재생을 옛 구간이 덮는다. 편집점은 **컷 좌표**로 쥐고 매 tick
  구간을 다시 계산한다 — 트는 동안 길이 보정으로 앞 컷이 늘어나도 그 편집점의 앞뒤를 지킨다(그 컷이 배치에서 사라지면 보통
  재생이 된다)(Codex 설계 검토).
- 탭이 가려지면 멈춘다(한 트랙만 보는 판도 그 즉시 선다 — §7 뷰어 판). 떠날 때 rAF·이벤트·주소를 정리한다.
- 프레임마다 ref 로 고치는 것은 재생헤드·타임코드뿐이다. 보이는 클립·재생 상태는 바뀔 때만 React 에 알린다.
- 타임코드는 24fps 눈금이다(원본 프레임 단위 정확도 보장 아님).

> [!NOTE]
> 미리 받는 것은 **바로 다음 하나**뿐이다(정방향 재생 중에만). 역방향(J)·훑기·한 트랙만 보기와, 다 받기 전에 경계에 닿은 때는
> 받는 시간만큼 선다(그동안 썸네일을 깐다).

### 넘어가기 — 미리 받기 · 맞바꾸기 · 미리 굴리기 (2026-10-08, Jay)

Jay: "영상에서 영상으로 넘어갈 때 딜레이가 생긴다 — 해결하자." 영상 요소 하나에 주소만 갈면 컷이 넘어갈 때마다 새 영상을 받고
재생을 시작하는 시간만큼 화면이 선다. 그래서 판(타임라인·소스)마다 **영상 요소를 둘** 두고 하나처럼 다룬다(`lib/editVideoPair.ts`).

- **앞의 것**이 보이고, **뒤의 것**은 가려 둔다(`data-spare` — `visibility: hidden`. `display: none` 이 아니다: 자리를 차지하고
  있어야 디코딩한 프레임이 바로 나온다). 엔진은 여전히 영상 하나를 다루듯 쓴다 — 읽기·쓰기·이벤트는 모두 앞의 것의 것이다
  (뒤의 것이 받는 중에 내는 `loadedmetadata`·`seeked`·`error` 는 엔진에 전하지 않는다).
- **미리 받기**(`prepare(url, time)`): 엔진은 sync 마다 '지금 보이는 것이 끝난 뒤 보일 자리'(`upcoming` — 같은 컷의 아래 클립이면
  그 시각, 다음 컷이면 0, 구간의 끝·반복하는 전체 끝이면 구간 처음)를 구해, 그것이 영상이고 지금 것과 다르면 뒤의 것에 올려 그
  시각에 세워 둔다. **정방향 재생 중에만** 한다(멈춘 채 훑을 때마다 받으면 요청이 두 배가 된다). 구간의 끝이 클립 경계와 같은
  자리면 되돌아갈 자리가 먼저다(tick 이 넘기는 순서 그대로). 한 번만 트는 편집점 앞뒤 재생은 끝에서 멈추므로 받지 않는다.
- **맞바꾸기**(`swap(url)`): 보이는 소스가 바뀌는 순간, 뒤의 것이 그 주소를 들고 있으면 **받지 않고 앞뒤만 바꾼다**. 메타데이터를
  이미 받았으면 엔진이 그 자리에서 평소 흐름(`onMeta`)을 잇고, 아직이면 진짜 `loadedmetadata` 를 기다린다(어댑터는 이벤트를
  지어내지 않는다). 받지 못한 것(`error`)은 내놓지 않는다 — 평소 길로 다시 받는다. 앞으로 나간 요소의 '세워 둔 시각' 기록은
  버린다(같은 주소·시각을 다시 청해도 그 시각으로 다시 보낸다 — A→B→A 로 되돌아오는 편집점 앞뒤 반복).
- **미리 굴리기**(`roll(on)`): 다 받아 둔 영상도 `play()` 뒤 화면이 움직이기까지 시간이 든다(격리 실측 약 0.05초 — 그동안 첫
  프레임에 서 있다). 그래서 넘어가기 `ROLL_LEAD`(0.08초, 실제 시간) 전부터 뒤의 것을 **소리 없이**(volume 0 — `muted` 는 화면의
  것이라 건드리지 않는다) 미리 굴리고, 넘어온 영상이 이미 돌고 있으면 목표를 조금 지나 있어도(`ROLL_SLOP` 0.3초 × 배속)
  되감지 않고 그대로 시계를 맡긴다. **대가: 뒤 영상의 첫 한두 프레임을 건너뛸 수 있다**(컷이 바뀌는 자리다. 멈춘 채로는 언제나
  정확한 프레임이다). 멈추거나 자리를 옮기면 세워 제자리로 돌린다. 앞 영상이 받느라 서 있어 넘어가는 순간이 오지 않으면 뒤의
  것이 혼자 멀리 가지 않게 0.25초(× 배속)에서 제자리로 돌려 세운다. 멈춘 자리가 경계를 넘어 굴리던 영상이 앞으로 나오면
  세운다(엔진이 영상에 시계를 맡기는 때가 아니면 — Codex 코드 리뷰). **실제 끝에 세워 둔 것은 굴리지 않는다**(2026-10-11 —
  세울 시각이 그 영상의 실제 길이보다 뒤라 끝으로 잘린 것: 끝난 영상에 `play()` 를 걸면 처음부터 다시 돌아, 넘어온 순간 엉뚱한
  시각의 영상이 시계를 받는다).
- 영상 요소가 하나뿐인 곳(한 트랙만 보기 — `useEditFollow`, 시험의 가짜 video)은 옛 길 그대로다: `prepare`·`swap`·`roll` 은
  있을 때만 부른다.

### 배속 (2026-10-08, Jay)

Jay: "재생 단추 줄에서 영상 배속을 올리는 것도 만들자." 반복 단추 옆의 글자 단추 — 누를 때마다 **1x → 1.5x → 2x → 4x → 1x**
(`EDIT_SPEEDS`). 1x 가 아니면 라임이다. 두 뷰어가 같이 쓰고 이 브라우저에 남는다(`EditUi.speed` — 목록에 없는 값은 1x).

- 정방향 재생은 그 배속으로 **시작**한다: 재생 단추·Space·L(멈춘 채·방향을 바꿀 때)·구간 반복 재생·편집점 앞뒤 재생.
- L 을 거듭 누르면 **지금의 2배씩**(최대 8배), J 는 그대로 1배부터다. 역방향에는 배속을 걸지 않는다.
- 재생 중(정방향)에 바꾸면 바로 따른다(걸려 있던 구간·편집점 앞뒤 재생은 그대로 이어진다). 배속이 바뀔 때만 적용한다 —
  L 로 올려 둔 속도를 다른 렌더가 되돌리지 않는다.
- 영상은 `playbackRate`, 빈 자리·이미지는 rAF 시계가 같은 배속으로 간다. 1배 미만은 없다. 위 줄의 배속 글자(`2x`·`◀ 4x`)는
  지금 실제로 도는 속도다(L·J 포함) — 도는 동안에만 보이고 멈추면 사라진다(고른 배속은 단추에 남아, 다시 틀면 그 배속으로 간다).
- ponytail: rAF 시계(빈 자리·이미지)는 배속을 바꾼 프레임 하나를 새 배속으로 센다(한 프레임치 — Codex 가 P3 로 보류에 동의).

## 7. 조작

글자 키는 **물리 키**(`event.code`)로 본다 — 한/영 상태와 무관하다. 편집 키는 고정이고 단축키 설정 창에 없다.

| 키 | 동작 |
|---|---|
| Space | 재생/정지 — 재생 키(이 줄부터 Home·End 까지)는 보이는 판의 시계로 간다(아래 '뷰어 판'). 다이나믹 트림 모드에서는 보는 편집점의 앞뒤 2초 |
| L · K · J | 정방향(고른 배속에서 시작 — 다시 누르면 그 2배씩, 최대 8배) · 정지 · 역방향(1배부터 — 끊길 수 있음) |
| ← → | 한 프레임 · Shift 는 1초 |
| ↑ ↓ | 앞·뒤 편집점(컷 경계·컷 안에서 끝나는 클립의 끝) — 다이나믹 트림 모드에서는 재생헤드가 아니라 보는 편집점에서 |
| Home · End | 처음 · 끝 |
| Delete · Backspace | 고른 클립 빼기 |
| D | 고른 클립 켜기/끄기 · 고른 것이 없으면 재생헤드가 있는 컷(폴더) 켜기/끄기 |

| Ctrl+Z · Ctrl+Shift+Z | 되돌리기 · 다시 하기 |
| Ctrl+= · Ctrl+- · Shift+Z | 확대 · 축소 · 전체 보기 |
| Ctrl+A · Esc | 클립 모두 고르기 · 고르기 풀기 |
| I · O | 재생헤드 자리에 마크 인 · 마크 아웃(다빈치) |

| W | 다이나믹 트림 모드 켜기/끄기(막대의 단추와 같다 — 아래 '다이나믹 트림 모드') |

소리 끄기는 A1 머리의 [M] 단추다(2026-10-08 — M 키는 다빈치처럼 북마크로 옮겼다). 마크·북마크 키는 편집 키라 언제나
타임라인 것이다(소스 판이 재생 키를 받고 있어도).

마우스: 눈금자 클릭·끌기 = 재생헤드 · 컷 이름 = 그 컷 처음으로(클립 고르기는 풀린다) ·
클립 클릭 = 고르기(Ctrl·Shift 여러 개) + 재생헤드가 다른 컷에 있으면 그 컷으로 ·
클립 위아래 끌기 = 트랙 옮기기 · Alt+휠 = 확대(커서 기준) · Ctrl/Shift+휠 = 좌우 · 트랙 머리의 잠금/켜기 ·

고르고, 우클릭하면 그 컷의 폴더 창이 열린다**(아래 — 2026-10-13). 뺄 때는 타임라인에서 클립을 고르고 Delete.

  도우미 `lib/marquee` 그대로). 상자는 **풀의 빈 곳에서 끌거나, Ctrl·Shift 를 누른 채 끌 때**(카드 위에서도)다 — 카드 위에서 그냥
  끌면 그 카드를 타임라인으로 끌어 넣는다(2026-10-13, 아래 '카드 끌어 넣기'. 그 전에는 카드 위에서 시작해도 상자였다). 마지막에

  붙는다(썸네일은 아래 변, 메타데이터·목록은 글). **우클릭 = 이 컷의 폴더 창**(컷 더블클릭과 같은 창 — 누른 카드가 보이게 연다).
- **폭**은 프로젝트 칸처럼 끌어서 바꾼다(`ResizableSidebar` 를 그대로 쓴다 — 저장 키 `ch.editTimeline.poolWidth`, 240~720px,

- 고른 것이 있으면 풀 아래에 막대가 뜬다: **[비교]**(2장부터) · **[Resolve 보내기]**(Jay 2026-10-08 — 앱의 보내기 줄
  `useResolveTransferActions` 를 그대로 쓴다. 고른 생성물을 넘기기만 하면 되고 탭·선택 상태에 묶여 있지 않다. 처리 중이면
  대기열에 더한다고 알린다).

  묶여 있어(폴더 창은 그래서 `teamPeek` 로 탭을 통째로 빌린다) 풀의 목록에 그대로 붙이면 다른 탭의 규칙으로 팀 생성물을
  지우거나 옮기게 된다. 지금은 컷 더블클릭으로 여는 폴더 창에서 한다. 풀에 넣으려면 풀을 폴더 창처럼 앱의 격자·선택 상태로
  그려야 한다(구조 변경 — 미정).
- 보기 방식·크기·정렬·싱글/듀얼은 **이 브라우저의 화면 설정**이다(`ch.editTimeline.ui` — 계정·시퀀스와 무관하게 하나, 편집 문서가
  아니라 되돌리기 대상도 아니다). 검색어는 남기지 않는다.

  풀의 다른 곳을 누르면 초점을 떼어 Space·J·K·L 이 다시 편집 화면으로 간다.

  어느 카드인지 모른다) 넣지 않고 알린다. 그때 넣으면 같은 생성물이 두 트랙에 들어가거나 교체하면서 그 클립의 꺼짐이 사라진다.

### 뷰어 판 — 무엇을 볼지 고르기 · 타임바 · 반복 (2026-10-08, Jay)

뷰어는 다빈치의 뷰어 모양이다(`EditViewer` — Jay 가 시안 `_shots/edit-viewer-mock.png` 를 보고 정했다).

| 자리 | 있는 것 |
|---|---|
| 위 줄 | 지금 시각 · **무엇을 볼지 고르기** · 전체 길이 · 싱글/듀얼 단추(맨 오른쪽 판에만) |
| 아래 줄 | **타임바**(누르거나 끌어서 훑기) · 처음·역재생·정지·재생·끝·**반복**·**배속**(§6) · 오른쪽에 **구간 반복 재생·마크 인·마크 아웃** |

- **타임바는 다빈치의 재생바다**(2026-10-08, Jay): 빨강 = 지금 자리, **위의 색 꼬리표 = 북마크**, 밝은 선과 **아래의 회색 꼬리표 =
  마크 인/아웃**. 컷 경계 점은 없다(처음에는 컷마다 파란 점을 찍었는데, Jay 가 다빈치에서 그 점은 북마크라고 바로잡았다).
  얇은 줄은 소스 테이프의 클립 경계다.
- **오른쪽 아래의 단추 셋**(다빈치의 뷰어 — 처음에는 앞/뒤 편집점이었다. ↑·↓ 키는 그대로): 구간 반복 재생 · 마크 인 · 마크 아웃.
  타임라인의 시계를 쓰는 판(타임라인·한 트랙만)에만 있다 — 소스 판에는 인/아웃이 없다. 판이 좁아지면 마크 인/아웃 단추부터
  숨고(I·O 키), 더 좁아지면 구간 반복 단추도 숨는다(Alt+/).
- **무엇을 볼지**: 타임라인(위 트랙이 보인다) · 소스 클립(풀에서 고른 것) · 소스 테이프(이 컷의 풀 목록을 이어서) · 한 트랙만
  (V1·V2·V3…). 판마다 따로 고르고, 싱글이어도 소스나 한 트랙만 볼 수 있다. **두 판은 늘 서로 다른 것을 본다** — 다른 판이 보고
  있는 것을 고르면 서로 자리를 바꾼다(같은 것을 두 판에 띄우는 경우를 만들지 않는다). 소스 클립과 소스 테이프는 **같은 판(소스
  엔진 하나)의 두 방식**이라 같은 것으로 친다(`isSourceView`). 기본은 듀얼 = [소스 클립 | 타임라인], 싱글 = 오른쪽 판의 것.
  다이나믹 트림 모드가 켜져 있는 동안에는 판이 타임라인 하나다(아래 절).
- **시계는 둘뿐이다** — 타임라인(기존 엔진)과 소스(같은 엔진의 두 번째 것). 타임라인 엔진은 판이 무엇을 보든 언제나 '위 트랙
  우선'을 튼다. 그래서 재생헤드·편집점·풀의 "지금 보이는 것" 표는 판이 무엇을 보든 달라지지 않는다(엔진에 트랙만 거른 배치를
  주면 다른 판과 아래 타임라인의 편집점이 바뀐다 — Codex 설계 검토).
- **한 트랙만 보기**는 타임라인의 시계를 따라가는 보기다(`useEditFollow` · `EditSoloViewer`). 위 트랙에 가려져 있어도, 꺼 둔
  클립·트랙이어도 그 트랙의 것을 보인다(`trackClip`). 멈춤·훑기·프레임 이동·역재생에는 그 자리에 정확히 맞추고(0.04초), 타임라인이
  정방향으로 '실제로 가는' 동안만 스스로 재생하며 0.2초 넘게 어긋날 때만 맞춘다. 타임라인이 받느라 서 있으면(시각이 0.15초 넘게
  안 움직임) 같이 선다. 탐색 중에는 새 탐색을 걸지 않는다. 시계에는 영향을 주지 않는다. **탭이 가려지면 바로 선다**
  (`visibilitychange` 에서 직접 세운다 — 숨은 탭에서는 rAF 가 서서 프레임 안의 정지가 돌지 않는다). 가려진 동안에는 틀지 않고,
  다시 보여도 스스로 틀지 않는다(타임라인이 가려질 때 멈췄고, 이 판은 그 시계를 따라갈 뿐이다). 영상을 보낼 자리는 엔진처럼
  실제 끝에서 자른다(§6) — 그 뒤에서는 끝 프레임에 서 있고(프레임마다 다시 보내지 않는다), 실제 끝에 선 영상은 틀지 않는다.
- **소스**는 생성물마다 컷 하나·클립 하나짜리 가상 시퀀스(`@src/<생성물 id>`)를 같은 엔진으로 튼다 — 조작·훑기·반복이 타임라인과
  같다(브라우저 기본 재생 막대가 아니다). 편집 문서에는 쓰지 않는다. 방식은 둘이다(다빈치 컷 페이지의 Source Clip · Source Tape):
  - **소스 클립** — 풀에서 고른 생성물 하나. 컷을 옮겨도 남는다(그 시퀀스의 공유 목록에 있는 동안).
  - **소스 테이프** — 재생헤드가 있는 컷의 풀 목록 전체를 풀의 정렬 순서대로 이은 것(검색어는 따지지 않는다). 컷을 옮기면 그
    컷의 목록으로 바뀐다. **풀에서 카드를 고르면 테이프가 그 카드의 처음으로 간다.** ↑·↓ = 앞·뒤 클립 경계. 위 줄 아래에
    `컷 · 3/18` 로 지금 몇 번째인지 보인다.
  - 길이는 실측값이 오면 고친다(타임라인에 안 넣은 영상은 적어 둔 길이가 없다 — 안 고치면 기본 5초에서 끝난다). **하나씩 차례로
    잰다** — 길이 재기의 큐는 앱 전체가 같이 쓰고 동시에 4개라, 테이프의 영상을 한꺼번에 줄 세우면 타임라인 클립이나 방금 고른
    소스의 길이 재기가 그 뒤로 밀린다. 목록·방식이 바뀌면 더 신청하지 않는다. 테이프 목록은 풀의 '지금 보이는 것' 표와 따로
    만든다(`cutItems` — 그 표는 재생헤드가 클립을 넘을 때마다 바뀐다).
- **타임라인과 소스는 같이 틀지 않는다** — 한쪽을 틀면 다른 쪽은 멈춘다(소리가 겹치지 않고 K 가 멈출 것이 하나다). 소스 판을
  내리면 소스도 멈춘다.
- **소스 판이 안 보이면 소스는 비어 있다**(2026-10-13) — 싱글 뷰어(기본)에서 풀의 영상 카드를 누를 때마다 안 보이는 판이 그
  영상을 끝까지 받던 것을 없앴다. 판을 올리면 그때 고른 것을 올린다. 판을 내릴 때 엔진의 범위가 바뀌어(`src-off`) 보던 자리를
  적어 두므로, 다시 올리면 그 자리다.
- **프레임마다 고치는 글자(막대·뷰어의 타임코드)는 글자 노드의 값만 바꾼다**(`writeText` — 2026-10-13). `textContent` 로 쓰면
  글자 노드를 갈아 끼우는 일이라 브라우저가 문서 전체의 스타일을 다시 계산한다(격리 실측: 프레임당 약 7ms 씩 두 곳, 클립 300 ·
  같은 글자를 `nodeValue` 로 쓰면 0ms). 새로 프레임마다 글자를 고칠 곳이 생기면 이 함수로 쓴다.
- **크게 보기·비교·폴더 창으로 넘기면 두 시계를 다 멈춘다**(`stopBoth` — 풀 카드 더블클릭 · 풀의 [비교] · 컷 더블클릭/풀 카드
  우클릭, 2026-10-13). 그 창이 떠 있는 동안 편집 키는 막혀 있어 뒤에서 도는 재생을 멈출 길이 없고 크게 보기의 소리와 겹친다.
  그 전에는 크게 보기·비교는 아무것도 멈추지 않았고, 폴더 창은 타임라인만 멈췄다.
- **반복**(`loop`·`loopSrc` — 시계마다 따로): 정방향으로 끝에 닿으면 처음부터 이어 튼다(위치를 옮긴 것과 같게 다룬다 — 영상이
  그 자리에 닿을 때까지 시간이 선다). 역방향은 반복하지 않고 처음에서 멈춘다.
- **재생 키(Space·J·K·L·←→·↑↓·Home·End)는 보이는 판의 시계로 간다.** 한 종류만 보이면 그 시계(소스만 보이면 소스 — 안 보이는
  타임라인을 틀지 않는다), 두 종류가 같이 보이면 **마지막에 누른 쪽**(다빈치 — 판을 누르거나, 메뉴에서 고르거나, 그 판의 단추를
  실행하면 그 판. 아래 타임라인을 누르면 타임라인. 초점이 들어온 것만으로는 바꾸지 않는다 — 우클릭 메뉴가 닫히며 초점을 돌려줄
  때 재생 대상이 엉뚱하게 바뀐다). 그 판의 위 줄에 라임 줄이 선다. 편집 키(Delete·D·Ctrl+Z·M…)는 언제나
  타임라인 것이다. Jay 가 직접 정한 것은 아니다(시안의 물음에 "이미지대로"만 답했다) — 다빈치 방식으로 골랐다.
- **영상 요소는 떼지 않는다**: 타임라인 판·소스 판은 안 보일 때도 붙어 있다(`hidden` + CSS `order` 로 자리만 바꾼다 — 떼면
  엔진이 걸어 둔 이벤트와 주소가 사라진다). 안 보이는 타임라인의 영상은 소리를 끈다. 타임라인 판이 없으면 한 트랙만 보는 첫
  판이 소리를 낸다. 지금 시각·타임바 머리는 판이 걸어 둔 그리기 함수를 시계가 프레임마다 부른다(React 를 거치지 않는다).
- 화면 설정(`ch.editTimeline.ui`)에 `views`([왼쪽, 오른쪽] — 값은 `"timeline"`·`"source"`·`"tape"`·트랙 번호)·`loop`·`loopSrc`·
  `markerColor`(새 북마크의 색)가 더해졌다. 소스 클립과 소스 테이프를 두 판에 같이 둔 값은 받지 않는다(기본 화면으로).

한계: 타임라인이 영상을 틀고 있는데 싱글에서 한 트랙만 보면 영상 둘을 받는다(안 보이는 타임라인의 것 + 보이는 것). 한 트랙만
보는 판은 프레임마다 배치를 읽는다(판 하나에 조회 한 번). 소스의 In/Out·끌어다 넣기는 없다 — 넣기는 풀의 우클릭 메뉴.
영상이 아주 많은 컷의 소스 테이프는 길이를 다 재는 데 오래 걸린다(그동안 안 잰 것은 적힌 길이·기본 5초로 지나간다).

### 왼쪽 폴더 옆 표시 (2026-10-08, Jay)

  없으면 키보드로는 트랙에 넣지 못한다(Codex 코드 리뷰). 마우스 우클릭과는 `contextmenu` 의 `button` 으로 가른다: 마우스 = 2,
  키보드 = 2 가 아님.
- 폴더 창의 목록 보기에서 선택 칸(체크박스) 위의 휠 클릭도 같은 메뉴다. 글자를 넣는 칸(태그·이름 편집) 위만 건드리지 않는다.

  [원본 길이로]. 값은 24fps 프레임 단위, 최소 1프레임, 원본을 넘지 않는 가장 긴 프레임까지다. **끝까지 늘리면 [원본 길이로]와 같다**
  (줄임 `trim` 을 지운다). 큰 화면은 공유 목록에서 찾은 영상일 때만 있다(못 찾은 클립은 숫자만). 영상을 못 받으면 까닭을 적고 ▶ 를
  끈다(길이는 그대로 조절된다). 띠는 쓰는 구간이 라임, 잘라 낸 구간이 옅은 회색이다(`--fill` — 10-13 밤의 첫 판은 이 값을 넣는 식이 빠져 띠가 통째로 안 그려졌다. 10-14 재실측이 찾아 고쳤고 시험이 값을 본다).
- **떠 있는 채 다른 영상 클립을 휠 클릭하면 창이 그 클립으로 바뀐다**(창은 하나 · 자리는 그대로). 숫자 칸에 치다 만 값은 **새 클립에는 가지 않는다** — 실제 마우스에서는 휠 단추를 누르는 순간 칸이 blur 돼 **앞 클립에 적용된다**(칸을 떠나는 것 = 적용 규칙 그대로. 격리 실측 3/3). 누름 없이 대상만 바뀌는 길에서는 앞 클립의
  것이라 버린다 — 초점이 창으로 옮겨지며 칸이 blur 되는데, 그때 적용하면 새 클립에 들어간다(치던 값에 그 클립의 표를 붙여 둔다).
- **걸음마다 바로 문서에 적고 저장한다.** 이어진 걸음들은 **되돌리기 한 단계**다(`useEditDoc` 의 `EditOptions.group` — 같은 이름으로
  잇달아 한 편집은 한 단계. 그사이 다른 편집·되돌리기가 끼면 새 단계고, 자동 길이 기록(`undo:false`)은 묶음을 끊지 않는다. 묶음의
  이름은 창을 열 때·다른 클립으로 바뀔 때 새로 받는다). `undo:false` 로 묶지 않는다 — 그것은 '사용자의 편집이 아니다'라는 뜻이라
  충돌 중에 저장되지 않는다(Codex 설계 검토).
- **안 되는 것**: 그림(Resolve 가 스틸을 5초로 놓는다 — §5) · 잠긴 트랙의 클립. 창을 띄우기 전에 까닭을 알린다(떠 있던 창은 그대로다).
  그림인지는 이어진 생성물로 먼저 본다(`kind` 가 안 적힌 옛 클립은 문서만으로는 영상으로 보인다).
- **스스로 닫히는 때**: 그 클립이 타임라인에서 빠짐(지움·교체·숨긴 컷) · 그 트랙이 잠김(`trimGone`) · 다른 창이 이 편집을 바꿈(`rev`) ·
  저장 충돌을 알게 됨 · 버린 걸음(`stopped`). 여는 순간 두 재생을 멈춘다(초점이 창으로 가 Space 가 창 안의 재생이 되므로).
  스스로 닫힐 때도 초점을 편집 화면으로 돌린다 — 초점이 창 안에 있었을 때만(창과 함께 사라져 body 로 떨어진 초점). 풀·폴더 창에 둔
  초점은 건드리지 않는다(2026-10-14 두 창 실측에서 찾음 — 전에는 ✕·Esc·버린 걸음으로 닫을 때만 돌렸다).
- **저장 충돌을 알게 되면 닫는다**(Codex 코드 리뷰 2회째 P1): 슬라이더를 끄는 도중 저장이 실패하고 다른 창이 저장하면, 첫 걸음은
  버려지지만 같은 끌기의 다음 걸음이 '알고 이어 가는 편집'(§4)으로 저장돼 알림을 읽기도 전에 다른 창의 저장을 덮었다. 걸음이
  `stopped` 로 돌아오거나 `useEditDoc` 의 `conflict` 가 켜지면 창과 묶음을 끝낸다. 다시 열어 조절하면 그때는 알고 하는 편집이다.
  **'안다'는 것은 그때 본 저장에 대해서다**(3회째 P1): `conflict` 는 번호고, 다른 창이 **또** 저장하면(새 원문) 새 번호가 된다 —
  알고 다시 연 조절 도중이어도 그 걸음은 버리고 창을 닫는다(전에는 '이미 충돌 중'이라며 새 저장을 덮었다).
- **클립 우클릭 메뉴에도 '길이 조절' 줄**이 있다(클립 하나를 눌렀을 때) — 휠 단추가 없는 마우스·트랙패드의 길이다. 같은 창이 뜬다.
  키보드만으로는 열 수 없다(타임라인의 클립은 초점을 받지 않는다 — 클립 고르기·끌기도 마우스뿐인 것과 같은 한계).
- **타임라인의 표시**: 줄인 클립은 글자가 `3.0s / 5.0s`(쓰는 길이 / 원본)가 되고, 그 컷 안에 남는 '원본의 나머지'가 빗금
  (`.ed-clip-rest`)으로 보인다 — 아래 트랙이 드러나는 구간이다. 빗금은 누를 수 없다.
- **길이를 바꾸면 타임라인의 타임코드가 같이 움직일 수 있다** — 재생헤드는 같은 컷의 같은 자리에 머문다(§5): 그 클립보다 앞이면 그대로,
  뒤면 줄인 만큼 당겨지고, 그 컷 안에서 새 끝보다 뒤에 있었으면 그 컷의 마지막 프레임으로 온다. 창 안의 재생은 재생헤드를 건드리지 않는다.
- **격리 브라우저 실측(2026-10-13 밤, 빌드 `a8f32834` · 1584×905)**: 위 계약의 줄마다 3/3 — 어긋난 것 0. 뜨기까지 16~20ms · 창 안 재생은
  끝 기대보다 2~3ms 뒤에 멈추고 마지막 프레임으로 · 슬라이더 8걸음 = 저장 8번 = 되돌리기 한 단계 · 숫자 칸(`2`→48f · `30`→1.25초 ·
  `abc`·`0`·`-5`→그대로 · `999`→원본 · `1,5`→36f) · 창이 뜬 채 클립 트랙 옮기기·카드 끌어 넣기·컷 순서·재생 · 우클릭 메뉴는 창 위에 ·
  편집 탭을 떠나면 창이 사라지고 돌아와도 다시 뜨지 않는다(자리 기억과 줄인 값은 남는다). **그 뒤에 넣은 것은 다시 재지 않았다**(창 안
  키의 전파 차단 · 영상 정보 전 재생 · 치던 값 묶기 · 낮은 창 · Esc 취소 · 처음 자리 · 띠·눈금·테두리 · 영상 실패 안내 — 시험과 정적
  화면으로만 확인). 못 잰 것: 저장 실패가 겹친 충돌 · 배율 100% 가 아닌 화면 · 폴더 창이 뜬 채의 앞뒤.

  글과 띠 중점의 차이 0px) · 초점 테두리 · 영상 실패 안내 · 영상 정보 전 재생(0 근처에서 시작) · **폴더 창이 떠 있을 때 창 안의 R·D 가 고른 카드에
  안 걸림**(색 저장 0건 — 고치기 전 빌드는 걸렸다) 모두 3/3. 폴더 창(z 151)보다 길이 조절 창(z 155)이 위다. **어긋난 것 하나 = 띠가 안 보임(위 — 고침)**.

### 카드 끌어 넣기 · 폴더 순서 끌기 (2026-10-13, Jay)

Jay: "위에 카드를 끌고 와서 타임라인에 넣을 수 있는 기능과 타임라인 부분의 폴더 순서를 내가 바꿀 수 있게." 순서의 규칙(문서의
`cutOrder`·새 폴더가 서는 자리)은 §3, 계산은 `lib/editTimeline.ts`(`moveCut`·`resetCutOrder`·`placeState`)다. 여기는 조작이다.

**풀의 카드를 끌어 트랙 줄에 놓기** (`EditPool` 이 몸짓을 알리고 `EditTab.onCardDrag` 가 정한다)

- 카드 위에서 누르고 5px 넘게 움직이면 끌기다. 그 밑은 누르기(고르기) 그대로고, Ctrl·Shift 를 누른 채면 상자 고르기다(위).
- 끄는 동안 카드의 **유령**이 포인터를 따라오고(자리는 ref 로 옮긴다 — 움직일 때마다 다시 그리지 않는다), 포인터가 **영상 트랙 줄**
  위에 오면 그 카드의 컷 칸이 강조되며 무엇이 될지 적힌다: `V2 에 넣기` · `V2 교체` · `지금 여기` · `잠김 — 놓을 수 없음`
  (휠 클릭 메뉴의 줄과 같은 판정 `placeState`). 가로 위치는 보지 않는다 — 들어갈 곳은 언제나 **그 카드의 컷**이다. 그 칸이 화면
  밖이어도 유령에 같은 글이 있다.
- 놓으면 휠 클릭 메뉴와 **같은 길**(`placeCard` — 지금의 공유 목록에서 카드를 다시 찾고, '확인 못 한 클립일 수 있음'이면 막고,
  `placeClip`)로 들어간다. 찬 칸은 교체다(타임라인 안에서 클립을 끌 때의 '맞바꿈'과 다르다 — 메뉴와 같게). `지금 여기`·`잠김`에
  놓으면 아무 일도 없다(되돌리기 단계·실패 알림 없음). 줄 밖(소리 줄·눈금자·컷 머리·다른 창 위·화면 밖)에 놓아도 아무 일도 없다
  — 놓을 곳은 포인터 바로 밑에 실제로 보이는 줄뿐이다(`document.elementFromPoint`).
- 끌기가 시작되는 순간 **{컷, 카드 id, 문서의 rev}** 를 잡아 두고 **재생을 멈춘다**(타임라인·소스 둘 다). 넣을 컷은 그때의 컷이다
  (풀은 재생헤드가 있는 컷을 보여 주므로 놓는 순간의 컷으로 보면 다른 컷일 수 있다). 끄는 동안 재생·편집 키는 쉰다(Esc 겹).
- 버리는 경우: **Esc** · 창이 초점을 잃음 · 단추가 떼어진 채 온 움직임(놓는 이벤트를 놓침) · 그사이 문서가 갈림(다른 창의 저장을
  받아들여 rev 가 바뀜) · 풀의 컷이 바뀜 · 그 카드가 공유 목록에서 사라짐. 버린 뒤의 놓기는 아무것도 넣지 않는다.
- **놓기는 끌기를 시작한 왼쪽 단추를 뗄 때뿐이다.** 끄는 중에 다른 단추(휠)를 눌렀다 떼도 카드는 놓이지 않고 끌기가 이어진다 —
  그 휠 클릭은 '넣을 트랙' 메뉴도 열지 않는다(전에는 어느 단추의 mouseup 이든 놓기였다 — Codex 코드 리뷰 2회째).
- 끄는 동안 **Space·Enter 의 기본 동작을 막는다**(`lib/keyGate` 의 `useDragKeyHold` — 컷 끌기도 같다). 끌기의 누름은 초점을 옮기지
  않아 그 전에 초점이 있던 단추(재생·트랙 눈)에 그대로 남고, 편집 키 처리는 쉬어도 **브라우저가 그 단추를 누르는 것**은 남기
  때문이다(같은 리뷰). 실제 크롬에서 단추가 안 눌리는지는 격리 실측 몫이다(jsdom 은 키로 단추를 누르지 않는다 — 시험은 기본
  동작을 막았는지만 본다).
- 여러 장을 골라 둔 상태여도 끈 한 장만 넣는다. 고른 것은 바꾸지 않는다(끌기에 딸려 온 click 은 누르기가 아니다).
- 폴더 창의 카드는 끌 수 없다(창이 떠 있는 동안 뒤가 inert — 그 창에서는 휠 클릭 메뉴로 넣는다).
- 마우스로만 한다(풀의 끌기는 상자 고르기와 같은 마우스 이벤트 `lib/windowDrag` 다 — 터치·펜은 상자 고르기도 없다).

**컷 머리 칸을 끌어 폴더 순서 바꾸기** (`EditTimeline` 의 컷 줄 — `onMoveCut`)

- 컷 머리 칸(컷 이름)을 좌우로 6px 넘게 끌면 순서 끌기다. 그 밑은 누르기(그 컷으로 이동), 더블클릭은 폴더 창 그대로다.
- 끄는 칸은 흐려지고, **끼워질 자리에 세로 줄**이 선다 — 포인터가 가운데를 넘지 않은 첫 컷의 앞(없으면 맨 뒤). 제자리(자기 앞·
  바로 다음 컷의 앞)면 줄이 없고 놓아도 아무 일도 없다.
- 놓으면 `moveCut(문서, 전체 순서, 그 컷, 끼울 자리의 컷)` — 되돌리기 한 단계다. 화면에는 보이는 컷만 있으므로 끼울 자리는
  **놓은 자리의 바로 뒤에 보이는 컷**이고, 숨긴(비활성) 컷은 전체 순서에서 제자리에 남는다. 재생헤드는 보던 컷에 그대로다.
- 끄는 중 타임라인 가장자리(48px)에 오면 그쪽으로 저절로 넘어간다.
- 끼울 자리는 **지금의 화면**으로 잰다 — 끄는 동안 프레임마다 다시 잡고(포인터가 멈춰 있어도 밑의 컷은 바뀐다: 가장자리에서
  저절로 넘기기 · 휠로 넘기기 · 확대 · 실측 길이가 와서 배치가 밀림), **놓는 순간에도 다시 잰다**(마지막으로 움직였을 때 적어 둔
  자리를 쓰지 않는다 — 전에는 포인터를 멈춘 채 휠로 넘긴 뒤 놓으면 옛 자리에 끼웠다. Codex 코드 리뷰 2회째).
- 버리는 경우: **Esc** · 창이 초점을 잃음 · 왼쪽 단추가 떼어진 채 온 움직임(다른 단추가 눌려 있어도) · 왼쪽이 아닌 단추의 놓기 ·
  포인터 쥐기를 잃음 · 그사이 문서가 갈림(rev) · 끌던 컷이 사라짐. 끄는 동안 재생·편집 키는 쉬고 Space·Enter 는 뒤의 단추를
  누르지 않는다(위 `useDragKeyHold`).
- 끈 뒤에 딸려 오는 **click 한 번**은 누르기가 아니다(그 컷으로 가지 않는다). 끈 직후 0.5초 안의 **더블클릭**(끌기 + 한 번
  누르기를 브라우저가 두 번 누름으로 센 것)은 폴더 창을 열지 않는다. 그 밖의 더블클릭은 그대로 연다.
- 순서를 바꿔 둔 동안 막대에 **`폴더 순서: 내 순서 ↺`** 알약이 뜬다 — 누르면 이름순으로 돌아간다(`resetCutOrder`, 되돌리기 한
  단계). 왼쪽 폴더 목록은 언제나 이름순이다.
- 끌기·메뉴를 시작한 뒤 문서가 갈려 낡은 rev 로 온 조작은 **말없이 버린다**(`act`) — 전에는 "잠긴 트랙이 있거나 옮길 자리가
  없습니다"가 떴다(클립을 끄는 사이 다른 창이 저장했을 때. Codex 검토).
- **타임라인의 클립을 끌어 트랙을 옮기는 것도 같은 규칙이다**(2026-10-13 — 같은 종류라 같이 고쳤다): 놓기는 왼쪽 단추의 놓기뿐, 왼쪽이
  떼어진 채 온 움직임에서 버린다(휠을 같이 누른 채 왼쪽만 떼면 pointerup 은 마지막 단추가 떼일 때에야 와서, 나중에 휠을 떼는 것이
  놓기가 됐다). **Esc 는 끌기를 버린다**(제자리로 — 전에는 고른 것만 풀리고 놓으면 그대로 옮겨졌다) · 끄는 동안 재생·편집 키는 쉬고
  Space·Enter 는 뒤의 단추를 누르지 않는다(끄는 중이라는 것을 상태 `clipDragging` 으로도 든다 — Codex 코드 리뷰 3회째).
  걷는 길은 한 곳이다(`cancelClipDrag` — ref·요소의 스타일·포인터 쥐기·상태): 놓기 · Esc · **창이 초점을 잃음** · **그사이 문서가 갈림(rev)** ·
  **끌던 클립이 화면에서 사라짐**(다른 창이 지움·그 컷 폴더가 없어짐 — 쥐던 요소가 없어지면 놓는 이벤트가 오지 않아 키·메뉴 막기가 Esc 를
  누를 때까지 남았다) · **누르기만 한 채(6px 전) 휠 클릭·우클릭으로 창을 엶**(쥐기가 남아, 창이 뜬 뒤 더 움직이면 창 뒤에서 끌기가 살아났다.
  Codex 코드 리뷰 4회째).
- **세 끌기(카드·컷·클립) 모두: 끄는 중의 다른 단추(휠·오른쪽)는 어느 요소 위에서든 메뉴·창을 열지 않는다.** `useDragKeyHold` 가 끄는 동안
  `auxclick`·`contextmenu` 를 잡는 단계에서 통째로 삼킨다 — 풀의 카드를 끄는 채 타임라인의 클립 위에서 휠 클릭하면 그 클립의 길이 조절
  창이 떴다(풀 쪽 가드는 풀의 카드만 봤다. Codex 코드 리뷰 3회째). 끌기가 끝나면 풀린다.

### 트랙 머리 우클릭 = 트랙 추가·삭제·옮기기·색 (2026-10-08, Jay)

다빈치의 트랙 머리 메뉴(Add Track · Move Track Up/Down · Delete Track · Delete Empty Tracks · Change Track Color)다
(`EditTrackHeadMenu`). 전부 되돌리기(Ctrl+Z) 한 단계다.

- **이 위에 트랙 추가**: 그 트랙 바로 위에 빈 줄 하나. 그 위의 트랙들은 한 줄씩 올라간다.
- **트랙 위로/아래로 옮기기**: 옆 트랙과 통째로 자리를 바꾼다 — 클립·끔·잠금·색이 트랙을 따라간다. 줄 수는 그대로다.
- **트랙 삭제**: 그 트랙의 클립도 같이 빠지고(메뉴에 `클립 N개`로 보인다) 위의 트랙들이 내려온다. 확인 창은 없다 — 되돌리기로 살린다.
- **빈 트랙 모두 삭제**: 클립이 하나도 없는 트랙을 모두 뺀다(숨긴 컷의 클립도 있는 것으로 센다). 한 줄은 남는다.
  **잠긴 트랙은 비어 있어도 남긴다**(2026-10-13 — 그 전에는 하나씩은 못 지우는 잠긴 빈 트랙이 여기서는 지워졌다). 남은 빈 줄이
  잠긴 것뿐이면 메뉴가 흐려진다.
- **트랙 색**: 견본 8색(씬 그룹과 같은 팔레트 `GROUP_COLORS`) + 없음. 머리 왼쪽 띠와 그 트랙 클립의 위쪽 띠로 보인다.
- 잠긴 트랙은 지우지 못하고, 잠긴 트랙이 걸리면 옮기지 못한다(클립이 옮겨지는 일이다). 마지막 한 줄은 지우지 못한다.
- 번호를 다시 매기는 길은 하나(`renumberTracks`) — 클립·`tracksOff`·`tracksLocked`·`trackColors` 가 같이 움직인다.
  뷰어 판의 'V3 만 보기'는 **번호로 보는 것**이라 옮기지 않는다(트랙이 사라지면 빈 화면에 'V3' 로 남는다 — 다시 고른다).
- 넣지 않은 것: Add Tracks…(개수·자리 대화상자 — 여러 번 누르면 된다) · 자막 트랙 · 소리 트랙 추가(A1 은 보이는 영상의 소리 한 줄).

### 마크 인/아웃 · 북마크 (2026-10-08, Jay)

- **마크 인/아웃**: I·O 로 재생헤드 자리에 찍는다(**뷰어 오른쪽 아래의 마크 인·마크 아웃 단추**도 같다 — 다빈치의 자리). 인을
  보이는 아웃과 같거나 뒤에 찍으면 아웃이 지워지고, 아웃을 인과 같거나 앞에 찍으면 인이 지워진다(다빈치). 눈금자 아래쪽의 구간
  막대와 양 끝의 둥근 점·줄 전체의 옅은 음영, 뷰어 타임바의 밝은 선과 아래의 회색 꼬리표로 보인다(타임라인의 시계를 쓰는 판만 —
  소스 판에는 없다). 막대의 구간 길이(`00:00:02:00 ×`)를 누르면 둘 다 지운다.
- **구간** = [인(없으면 처음), 아웃(없으면 끝)] — 하나라도 보이고 **두 프레임 이상**일 때만(`markRange`). 그보다 짧으면 표시만
  남고 구간 막대·구간 반복은 없다.
- **구간 반복 재생**(뷰어 오른쪽 아래의 단추 · Alt+/): 켜는 순간 구간 처음으로 가서 정방향으로 튼다(구간 밖에 있었어도, 역재생
  중이었어도). 켜져 있는 동안 타임라인은 그 구간을 되풀이한다(§6). 끄면 재생은 그대로 두고 구간만 풀린다. 전체 반복(⟲)과는
  따로다. 구간이 없으면 단추가 흐리고, 구간이 사라지면 같이 꺼진다(새로 찍은 구간이 말없이 돌지 않게). 저장하지 않는다.
- **북마크**(다빈치의 마커): M 으로 재생헤드 자리에 넣는다(막대의 단추도 같다 — 옆 숫자는 보이는 북마크 수). 눈금자 위쪽의 색
  꼬리표를 누르면 그 자리로 가고, 더블클릭·우클릭하면 편집 창(`EditMarkerMenu` — 이름·색 16개·지우기)이 뜬다. 북마크가 있는
  자리에서 M 을 한 번 더 누르면 그 편집 창이다. 이름은 Enter·바깥 누르기에 저장하고 Esc·Tab 은 버린다(한글 조합 중의 Enter 는
  글자 확정). 색은 누르는 즉시 바뀐다. 뷰어 타임바 위에도 같은 색 꼬리표로 보인다.
- **북마크 색 메뉴**(막대의 북마크 단추 옆 ▾ — 다빈치의 마커 색 메뉴, `EditMarkerColorMenu`): `모두 지우기` + 16색(파랑·청록·
  초록·노랑·빨강·분홍·보라·자홍·장미·라벤더·하늘·민트·레몬·모래·코코아·크림 — `MARKER_COLORS`). 고른 색이 **새 북마크의 색**이
  된다(이 브라우저의 취향 `markerColor` — 편집 문서가 아니다). 북마크 단추가 그 색으로 보인다. `모두 지우기`는 이 시퀀스의
  북마크를 전부(안 보이는 것까지) 지운다 — 되돌리기 한 단계. 아래에 자리가 모자라면 메뉴가 단추 위로 뜬다(단추를 덮으면 두 번
  누를 때 엉뚱한 색이 골라진다 — 격리 실측에서 찾았다). 메뉴가 뜬 채 ▾ 를 다시 누르면 닫힌다.
- 북마크는 (컷, 프레임)에 하나다. **고치고 지울 때는 문서의 원래 열쇠만 쓴다**(`markerKey`). '재생헤드 자리의 북마크'는
  `markerAt` 하나로 찾는다 — 같은 열쇠를 먼저, 없으면 보이는 시각이 반 프레임 안인 것(컷 경계: 앞 컷의 끝에 찍은 것과 다음 컷의
  처음은 같은 시각인데 열쇠가 다르다). M·Alt+M 이 같은 함수를 쓴다.
- 인/아웃·북마크는 편집 문서에 적고 되돌리기 대상이다. 숨긴 컷에 있는 것·컷이 그 자리보다 짧아진 것은 문서에 남고 화면에서만
  빠진다(§5).
- 메뉴 네 가지(카드 휠 클릭·트랙 머리·북마크 편집 창·북마크 색 메뉴)는 껍데기 하나(`EditMenu` — 자리·바깥 누르기·Esc/Tab·↑↓·뒤
  화면 키 차단)를 같이 쓴다. 트랙 머리 메뉴·북마크 편집 창·북마크 색 메뉴는 **여는 순간의 `rev` 를 잡아 두고** 저장을 그 `rev` 로
  한다 — 떠 있는 사이 다른 창이 이 편집을 바꾸면 닫히고, 옛 화면을 보고 고른 것이 새 문서를 덮지 않는다.
- **단추로 여는 메뉴**(막대의 ▾·목록 단추)는 그 단추를 껍데기에 넘긴다(`EditMenu` 의 `trigger`): 껍데기는 그 단추의 누름을 바깥
  누름으로 치지 않고, 닫는 것은 단추의 click 이 한다(2026-10-11 — 바깥 누름으로 치면 누르는 순간 닫히고 뒤따르는 click 이 다시
  열어, 다시 눌러도 닫히지 않았다). 그 단추를 오른쪽·가운데 단추로 누른 것은 click 이 오지 않으므로 전처럼 바로 닫는다.
- **우클릭으로 뜨는 메뉴는 누른 자리를 덮지 않는다**(2026-10-11): 누른 자리의 오른쪽 아래에 2px 띄워 놓고, 아래·오른쪽에 자리가
  없으면 화면 안으로 밀어 넣지 않고 위·왼쪽으로 뒤집는다(`beside`). 밀어 넣으면 메뉴가 누른 자리 위에 깔려, 연 자리를 다시
  눌러도 그 누름이 '메뉴 안'이라 닫히지 않는다 — 화면 아래쪽에 있는 트랙 머리의 메뉴가 늘 그랬다(격리 실측). 단추로 여는 메뉴는
  부르는 쪽이 단추에 맞춰 준 자리 그대로다.
- 넣지 않은 것: 북마크 목록 · 북마크·인/아웃을 끌어 옮기기 · 소스 뷰어의 인/아웃 · 메모·길이 있는 북마크.

### 다이나믹 트림 모드 — 나뉜 뷰어가 한 창 (2026-10-08, Jay)

다빈치의 Dynamic Trim Mode(W)다. **보기만** 한다 — 트림(클립 앞뒤를 잘라 길이를 바꾸기)은 넣지 않았고(Jay 가 시안
`_shots/edit-trim-2up-mock.png` 의 두 안 중 "(가) 보기만"을 골랐다. 트림은 클립에 '소스의 어디부터 어디까지'를 적는 문서 변경이
필요하다), 편집 문서에는 아무것도 쓰지 않는다.

같은 날 먼저 **타임라인 판 안의 '편집점 보기'**(판의 한 방식 `ViewMode "edit"` · 멈춰 있을 때만 두 칸 · 재생 중에는 덮개를 숨기고 한
화면)로 만들었다가, Jay 가 다빈치 화면으로 바로잡았다 — "이 편집점이 아니고 … 누르면 나눠져 있던 창이 **한 플레이**로 볼 수
있어야 한다. 다이나믹 모드여야 한다." 그 방식·이름·단추 그림은 없앴다(다시 만들지 않는다).

- **모드는 판의 방식이 아니라 뷰어 자리 전체의 상태다**(`EditTab` 의 `trim` — 저장하지 않는다). 켜져 있는 동안 보이는 판은
  타임라인 판 하나다(`slots = ["timeline"]`): 나뉘어 있던 소스 판·한 트랙만 판이 내려가고 **한 창**이 된다. 화면 설정(`views`·
  `dual`)은 건드리지 않으므로 **끄면 보던 대로 돌아온다**. 소스 판이 내려가면 소스 재생은 멈춘다(기존 규칙).
- **켜고 끄기**: 막대의 단추(다빈치의 Dynamic Trim 그림 `[‹|›]` — 북마크 왼쪽) · **W** · 무대 왼쪽 위의 **⊗**. 그 창의 위 줄
  글자는 `다이나믹 트림 모드`고, 판을 고르는 메뉴는 한 줄뿐이며 싱글/듀얼 단추는 없다.
- **두 칸**(`EditTrimView` — `EditViewer` 의 `over`): 왼쪽 = 편집점 **바로 앞**에 보이던 것, 오른쪽 = **바로 뒤**에 보이는 것.
  '보이는 것'은 타임라인 뷰어와 같은 규칙이다(`visibleClip` — 위 트랙 우선·끔 반영). 그래서 컷 경계뿐 아니라 컷 안에서 위
  클립이 끝나 아래가 드러나는 편집점도 본다. 칸 오른쪽 위의 꼬리표는 `C0010 · V1` | `C0040 · V1`. 클립이 없으면 `비어 있음`,
  타임라인의 처음에는 앞이, 끝에는 뒤가 없다.
- **한 번의 재생**: 재생헤드가 있는 쪽 칸에 **엔진의 화면이 올라온다**. 앞 컷이 왼쪽에서 재생되다가 편집점을 넘으면 뒤 컷이
  오른쪽에서 이어진다 — 영상 요소도 시계도 하나 그대로다(엔진의 `.ed-media` 를 CSS 로 그 반쪽에 놓는다: `.ed-stage:has(>
  .ed-split[data-side="r"]) > .ed-media`). 반대쪽 칸은 그 편집점의 프레임(앞 = 마지막 프레임, 뒤 = 첫 프레임)으로 서 있다 —
  엔진과 무관한, 재생하지 않는 `<video>` 다(주소마다 새 요소, 같은 영상에서 편집점만 바뀌면 다시 보내기만 한다). 훑기·프레임
  이동도 재생헤드 쪽 칸에서 보인다.
- **어느 편집점인가**: 재생헤드에서 **가장 가까운** 편집점(`nearestPoint` — ↑·↓ 가 쓰는 `editPoints` 그대로, 처음·끝 포함).
  재생헤드의 시각은 React 밖에 있어서, 덮개가 시계의 그리기 함수로 받는다 — 가장 가까운 점이 바뀔 때만 다시 그리고(재생
  중에도 따라간다 — 이어 틀면 `[앞 | 뒤]` 가 편집점마다 넘어간다), 재생헤드가 편집점의 어느 쪽인지는 React 를 거치지 않고
  `data-side` 에 적는다. 그래서 **엔진은 멈출 때도 멈춘 자리를 그린다**(§6).
- **표본 시각**(`shotsAt`): 편집점에서 1/4 프레임 떨어진 곳이되 **이웃 편집점과의 한가운데를 넘지 않는다** — 부동소수 오차로
  방금 끝난 클립이 다시 잡히지 않고, 0.005초만 비치는 클립을 건너뛰지도 않는다(Codex 설계 검토). 편집점 사이의 구간에서는

  **Resolve 가 받지 않은 북마크**·저장 미확인 가운데 하나라도 있으면) · `failed`·`unavailable`(만들지 않았다).

  반 프레임 경계에서 한 프레임이 사라졌다. 소리의 소스 시작은 초로 적힌 `offset` 이 아니라 **그 영상 클립이 놓인 프레임에서 센

### 컷 더블클릭 · 풀 카드 우클릭 = 공유 & 리뷰의 '폴더 보기' 창 (2026-10-08, Jay · 풀 카드 우클릭은 2026-10-13)

타임라인에 넣은 카드에 위의 "V1 - 선택 카드"가 붙고(`cardMarks`), 창은 지금 보이는 카드로 내려가서 열린다.
**미디어 풀의 카드를 우클릭해도 같은 창**이 그 컷(재생헤드가 있는 컷)으로 열린다 — 이때는 지금 보이는 카드가 아니라 **누른 카드**로
내려가서 열린다(`openCut(path, focusId)`). 다른 탭의 '컷 우클릭 = 폴더 창'과 같은 손놀림이다.
창 안의 클릭은 라이브러리의 '고르기'다 — 타임라인에 넣는 것은 카드 휠 클릭(위), 빼는 것은 미디어 풀(더블클릭)이나 타임라인(Delete)에서 한다.

그 창은 앱의 하나뿐인 목록 조회를 빌려 그리고 카드·액션의 동작이 `filters.tab` 에 묶여 있다. 그래서 창이 떠 있는 동안
**목록·카드·액션만 공유 & 리뷰로 본다**(`App` 의 `teamPeek` → `useLibraryFilters` 의 세 번째 인자).

- 밖에 내주는 `filters`·조회·공간 범위만 `tab: "team"` 이 되고(휴지통 보기도 끈다 — 목록 훅이 휴지통 API 를 고르는 열쇠다),
  **저장된 filters 는 그대로**다. 탭 저장·뒤로가기 기록(`useAppNavigation` 은 `storedTab` 을 쓴다)·다음 생성 위치를 건드리지 않는다.
  탭을 실제로 바꿨다 되돌리면 기록과 저장에 임시 상태가 샌다(Codex 설계 검토).
- 창의 문맥 = 계정·워크스페이스뿐이다(`editPeekCtx`). 창 안에서 W(자동/전체)를 바꾸는 것은 문맥 변경이 아니라 창이 유지된다.
  편집을 떠나면 그 렌더부터 `teamPeek && editOpen` 이 거짓이라 떠난 탭이 한순간도 공유 & 리뷰로 그려지지 않는다.
- 떠 있는 동안 편집 키는 쉬고(`keysActive`) 라이브러리 키가 듣는다(`libraryKeysOffRef = editOpen && !listPeek`). `.body` 는 inert.
- 닫으면 밑의 탭 목록을 비우고 원래 조회로 돌아가며, 편집 탭은 공유 목록을 다시 받는다(`reloadSignal`). 닫은 뒤에 끝난 변경
  (공유 해제·삭제)은 `libraryChanged` 알림으로 한 번 더 받는다(0.4초 몰아서).
- 문맥이 바뀌어 무효가 된 창은 목록을 비우지 않는다 — 바뀐 문맥의 조회가 이미 떠났고, 비우면 그 응답까지 버린다.

한계: 지금 보이는 카드가 첫 쪽(200장) 밖이거나 툴바 필터에 가려지면 그 카드로 내려가지 않는다. 공유 & 리뷰의 W 가 '전체 보기'면
창도 전체를 보여, 미디어 풀(자동 범위)과 목록이 다를 수 있다. 밑의 탭이 공유 & 리뷰일 때 창에서 W 를 바꾸면 그 탭에서 바꾼 것과
같아 그 탭의 보던 위치가 풀린다(다른 탭이면 건드리지 않는다). 목록 보기에서는 표가 카드 아래 변이 아니라 모델 이름 옆의 글이다.
창이 떠 있는 동안 도착한 '방금 만든 생성물'은 목록에 끼워 넣지 않는다(`usePromptCreatedActions` — 로컬 카드가 팀 목록에 섞이면
로컬 id 로 팀 요청이 나간다).

  확인된 것**(검수 골드 `is_final` — 여럿이면 그중 최신), **그다음 그 컷의 최신**(공유 목록은 최신 먼저 온다 — 풀의 '최신순' 맨
  위와 같다). 넣는 자리는 넣기와 같다(그 컷에서 켜져 있고 안 잠긴 가장 낮은 트랙 — 보통 V1). **꺼 둔 컷(비활성)과 이미 클립이
  있는 컷은 건드리지 않는다.** 한 번이 되돌리기 한 단계고, 끝나면 몇 곳을 채웠는지(`최종 n개 · 최신 m개`) 알린다. 메뉴의 옆
  숫자는 채울 수 있는 빈 컷 수다(0 이면 흐리다). 한 번 실행하는 것이지 켜 두는 것이 아니다 — 나중에 공유된 것으로 저절로
  채우지 않는다. 보류(R)로 표시된 것도 최신이면 들어간다(Jay 가 정한 순서에 보류는 없다 — 빼지 않았다). 공유 목록이
  2,000건에서 잘린 시퀀스에서는 받은 것 안에서만 고른다. **공유 목록을 다시 받는 중·받지 못한 뒤에는 채우지 않는다**(줄이
  흐리다) — 그동안 든 목록은 옛 것이라 방금 공유를 푼 카드를 넣거나 새로 최종이 된 것을 놓친다. 고른 것은 그 렌더의 문서로
  만든 것이라 저장은 그 `rev` 로 한다 — 그 사이 다른 창이 문서를 바꿨으면 넣지 않는다(Codex 코드 리뷰).

키가 듣는 조건: 편집 탭이 떠 있고 · 위에 다른 창이 없고(`keysActive`) · 입력칸이 아니고 · 키가 body 나 편집 화면에서 났을 때.
실제로 쓴 키만 기본 동작을 막는다(Ctrl+=/- 의 페이지 확대 포함). 초점이 있는 단추의 Space 는 그 단추 것이라, 편집 화면의
단추들은 mousedown 에서 초점을 가져가지 않는다. 휠은 타임라인 안에서만 가로챈다.
