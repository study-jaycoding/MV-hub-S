## 1. 무엇인가

캔버스 옆 네 번째 탭. 위에 미디어 풀과 뷰어(싱글/듀얼), 아래에 트랙(레이어) 타임라인이 있고, **폴더 순서대로 컷 자리가 자동으로 잡힌다.**
그 자리에 내가 고른 공유 생성물이 들어가고, 재생하면 컷 순서대로 이어서 본다.

**Jay 가 정한 것**

- 다빈치와 같은 조작감.
- 같은 컷에 여러 개를 쌓아도 흐리게 하지 않는다. **위 트랙이 우선 보인다.**
- **고르지 않은 컷은 비워 둔다**(자동 채우기 없음).
- 편집은 **나만 본다**(팀 공유 아님).

**1차 범위**: 보기·고르기·쌓기·트랙 옮기기·빼기·끄기·재생·확대.
**일부러 안 만든 것**: 클립 길이 줄이기(트림)·자르기·시간 방향 이동·내보내기·파형·팀 공유.

> [!NOTE]
> **컷 자리는 폴더 순서로 고정**이다(A안). 클립은 자기 컷 자리 안에서 트랙만 옮기고, 컷 길이가 바뀌면 뒤 컷이
> 밀린다. 시간 방향으로 자유롭게 옮기는 것(B안)은 자동 자리와 어긋나고 데이터 모델이 달라져 후속으로 미뤘다.
> Jay 가 이 선택에 직접 답한 것은 아니다 — Claude 권고·Codex 동의로 진행했다. 바꾸려면 여기부터 다시 연다.

## 2. 진입 — `Filters["tab"]` 의 값이 아니다

`tab ===` 비교가 프런트에 100곳이 넘어, 네 번째 값을 넣으면 "내 작업으로 떨어지는" 분기가 조용히 생긴다.
그래서 편집은 내비 기록의 별도 '보기'다.

- `useAppNavigation` 의 `NavView.edit`. `openEdit()` 로 들어가고, `navTab()`·`enterBoard()` 는 편집에서 나온다.
  위에 뜬 창(관리자 등)을 닫으면 편집으로 돌아온다. 편집 칸이 없는 옛 기록은 편집이 아니다.
- `App.tsx` 의 `editOpen` 이 켜지면 `.body` 안을 `EditTab` 하나로 바꾼다. 밑의 탭 상태(filters·목록 훅)는 건드리지 않는다.

편집이 떠 있는 동안 `App.tsx` 가 맞춰 주는 것:

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| 들어오기 전에 떠 있던 폴더 보기 창 두 종류 | `listPeekCtx` 에 `editOpen` · `folderPeek` 닫기 | 창은 `.body` 밖에 그려지고 `.body` 를 inert 로 만든다. 편집 탭이 스스로 여는 폴더 창은 §7 |
| 캔버스 완료 감시 | `sceneBoardCoveredIds` 에 `!editOpen` | SceneBoard 가 없으면 그 id 를 App 감시가 맡아야 한다 |
| 다빈치 선택 따라가기 | 라이브러리 `enabled && !editOpen` · 이벤트 처리부 맨 앞에서 반환 | 숨은 목록의 위치·활성 씬을 바꾸지 않게 |
| 라이브러리·프롬프트 단축키 | 두 훅의 `inactiveRef` — 라이브러리 쪽은 편집 탭이 연 폴더 창이 떠 있을 때만 듣는다 | Esc·D·Ctrl+K 가 편집 키와 겹친다 |
| 프롬프트 도크·선택 막대 | 숨김(상태줄은 남는다) | 편집 탭에는 생성 입력이 없다 |
| 밑의 목록 선택 | 들어올 때 비움 | 안 보이는 카드에 일괄 작업이 걸리지 않게 |

**멈추지 않는 것(의도적)**: 밑의 탭의 목록 새로고침(타이머·focus·WS). 그 탭에 앉아 있을 때와 같은 동작이다.
멈추려면 `dev` 와 같이 쓰는 훅 여러 곳을 건드려야 한다. 그 조용한 갱신이 실패하면 전역 알림이 뜰 수 있다(기존 동작).

## 3. 데이터 — 백엔드 변경 없음

**시퀀스** = (프로젝트, 폴더 P). **컷** = P 의 직계 하위 폴더.

- 컷 순서 = **이름 자연 정렬**(숫자 인식·대소문자 무시). 대상 = 디스크 트리 ∪ 팀 개수에서 나온 폴더 ∪ 받은 목록의 폴더 ∪
  문서에 남은 클립의 컷. 마지막 공유물이 사라져도 클립이 남아 있으면 컷 자리가 남는다.
- 고른 폴더에 하위 폴더가 있으면 그 폴더가 시퀀스. 없으면 부모가 시퀀스고 그 컷으로 간다 — 단 **트리를 온전히 받았을 때만**
  (디스크 트리 실패·잘림이면 '하위 없음'을 믿지 않는다). P 바로 아래에 놓인 생성물은 컷이 아니다.
- 사이드바는 `ProjectSection` 을 쓰지 않는다. 그쪽은 폴더 클릭이 **생성 목적지를 서버에 저장**한다(`setProjectFolderSelection`).

**공유 생성물** = '공유 & 리뷰' 탭이 *자동 범위(지금 워크스페이스)에서 필터 없이* 그 폴더에 보여 주는 것.

- 조회 `{tab:"team", ...sharedWorkspaceFilter(워크스페이스), project_id, folder_path:P}`. `review_filter` 없음 —
  일반 공유·보류·최종을 모두 받고 카드에 ★/보류만 표시한다. 검색·작성자·타입·색·태그는 적용하지 않는다. 권한은 서버 계약 그대로.
- 워크스페이스를 모르면 묻지 않는다. 안내 옆 **[전체 보기]** 가 그 탭의 전체 보기처럼 워크스페이스 조건 없이 묻는다
  (이번 공간에서만, 저장하지 않는다).
- 쓸 수 있는 것 = 완료 + 결과 파일 있음 + 영상/이미지(오디오 제외).
- 끝까지 넘겨 받는다(200행씩). 커서와 끝 판정은 **거르기 전 원본 쪽**으로 한다. 상한 2,000행 — 넘으면 "최대 2,000건 표시".
- 여는 순간·시퀀스를 바꿀 때·[새로 고침]에서만 묻는다(폴링 없음). 문맥(계정·서버·워크스페이스·프로젝트·P)이 바뀌면
  받던 응답을 버리고 다음 쪽도 묻지 않는다. 실패하면 같은 문맥의 마지막 성공 결과를 그대로 둔다.
- '끝까지 받음'은 **이번 조회가 끝까지 성공했을 때만**이다. 다시 받는 동안과 실패한 뒤에는 옛 결과가 화면에 남아 있어도
  끝까지 받은 것이 아니다.
- 폴더 연결 조회에 실패하면 '연결 없음'으로 치지 않는다 — 트리는 '온전하지 않음'으로 남는다.

클립의 미디어 상태는 셋이다.

| 상태 | 뜻 | 화면 |
|---|---|---|
| `ok` | 그 컷의 공유 목록에 있다 | 썸네일 |
| `missing` | 목록을 **끝까지** 받았는데 없다 | 붉은 줄무늬 '미디어 없음' |
| `unknown` | 실패·상한·조회 전 | 회색 줄무늬 '확인 못 함' |

`unknown` 을 '없음'으로 그리지 않는다. 클립은 어떤 상태에서도 자동으로 지우지 않는다.

## 4. 편집 문서 — localStorage

키 `ch.editTimeline:<계정 네임스페이스>:<project_id>:<P>` — 시퀀스마다 문서 하나.

```ts
interface EditClip { cut: string; gen: string; job?: string | null; track: number; off?: boolean; dur?: number; kind?: "video" | "image" }
interface EditDoc { v: 1; clips: EditClip[]; tracksOff: number[]; tracksLocked: number[]; muted?: boolean;
  cutsOn?: string[]; cutsOff?: string[]; hideOff?: boolean } // 컷(폴더) 비활성 — 기본값과 다르게 정한 것만(§7)
```

- `gen` = 팀 카드 id(서버 UUID). `job` = job_id — id 로 못 찾을 때 **그 컷에서 하나만 맞으면** 다시 잇는다.
- `dur` = 넣는 순간 배치에 쓴 길이(실측 → `params.duration` → 5초, 이미지 5초). 실측값이 오면 고쳐 적는다(되돌리기 단계 아님).
  목록·메타데이터를 못 받아도 배치가 변하지 않게 하려는 것이다.
- 불변식: (컷, 트랙)에 클립 하나 · 같은 (컷, 생성물)은 한 번만.
- **서버 주소는 키에 넣지 않는다.** 서버 이사는 DB 를 통째로 옮겨 id 가 유지된다. DB 복제본 서버도 같은 프로젝트·생성물 id 를
  가지므로 같은 편집 문서가 이어진다(의도한 동작).
- 읽을 때 버전·모양·불변식을 검증한다. 읽지 못한 문서는 **빈 문서로 덮지 않는다** — 화면에 알리고, 처음 저장할 때 원문을
  `<키>.bad` 로 옮긴 것을 확인한 뒤에만 덮는다.
- 바뀔 때마다 저장한다. 실패하면 '저장 안 됨'이 남고 다음 변경 때 다시 시도한다. **저장하지 못한 문서는 다른 시퀀스나
  탭에 다녀와도 버리지 않고**(메모리), 돌아오면 한 번 더 저장해 본다. 새로고침하면 사라진다.
- 다른 창의 `storage` 이벤트는 '바뀌었다'는 알림으로만 쓴다. 저장소를 다시 읽어, 이 창의 마지막 저장과 같으면 무시하고
  다르면 받아들인다(되돌리기는 비운다). 그 전에 시작한 지연 콜백(끌기 확정·길이 기록)은 `rev` 가 달라 버려진다.
- 자리를 비운 사이(다른 시퀀스·다른 탭) 다른 창이 저장했으면, 다시 열 때 그 문서의 되돌리기를 비운다 — 옛 되돌리기가
  남의 저장을 덮지 않게.
- 저장 못 한 편집과 다른 창의 저장이 겹치면(충돌) **알리기만 하고 알아서 덮지 않는다.** 몇 번을 오가도, 자동 길이 기록이 와도
  저장하지 않는다 — 사용자가 편집을 이어 갈 때만 저장한다. 충돌은 저장 못 한 문서에 묶어 둔 '그때 알던 원문'과 지금 저장소를
  비교해 가리므로, 다시 열 때마다 같은 답이 나온다.
- 되돌리기/다시 하기 = 문서별 메모리 스택(100단계). 탭을 오가도 남고 새로고침하면 사라진다. 확정된 길이(`dur`)는
  되돌리기 대상이 아니다 — 옛 문서를 되살려도 길이는 지금 것을 따른다.

> [!WARNING]
> **백업이 없다.** 캔버스 씬은 로컬 DB 백업이 있지만 편집 문서는 localStorage 뿐이다. 브라우저 프로필을 지우거나
> 다른 PC·다른 프로필에서 열면 편집이 없다. 팀 공유·백업이 필요해지면 DB 로 옮긴다.

## 5. 배치와 위치 (`lib/editTimeline.ts`, 순수)

- 클립 길이 = `dur`. 컷 길이 = 그 컷 클립들의 최대 길이(꺼진 것 포함 — 끌 때 길이가 출렁이지 않게). 빈 컷 = 5초.
- 보이는 클립 = 꺼지지 않은 것(클립·트랙) 중 아직 안 끝난 **가장 높은 트랙**. 위 클립이 짧으면 끝난 뒤 아래가 비친다.
  잠금은 보이기와 무관하다.
- **위치의 원천은 (컷 경로, 컷 안 시각)** 이다. 앞에 컷이 끼어들거나 앞 컷 길이가 바뀌어도 보던 자리가 유지된다.
  보던 컷이 사라지면 이름 순서로 그다음 컷 처음으로, 보던 컷이 짧아지면 컷 끝 직전으로 옮기고 재생을 멈춘다.
- 넣을 트랙 = 그 컷의 가장 높은 클립보다 위에서 **켜져 있고 안 잠긴 가장 낮은 트랙**(넣자마자 보이게).
- 잠긴 트랙의 클립은 빼기·끄기·옮기기 모두 거부하고, 옮길 때는 도착 트랙의 잠금도 본다. 여러 개 옮기기는 전부 될 때만.

## 6. 재생 (`lib/useEditPlayback.ts`)

`<video>` 하나의 주소를 갈아 끼우며 이어 튼다.

- 시계 주인은 항상 하나. 보이는 클립이 영상이고 정방향 재생이면 **영상이 시계**(받는 중·버퍼링이면 시간도 선다),
  빈 자리·이미지·역방향·재생 못 하는 영상은 rAF + `performance.now()`.
- **'보이는 소스가 바뀜'은 컷이 바뀌는 것과 별개 사건**이다. 같은 컷에서 위 클립이 끝나 아래가 드러날 때도 일어나고,
  그때 아래 영상은 0초가 아니라 보던 시각에서 시작한다.
- 소스를 갈 때 순서: 정지 → 번호 올림 → 주소 교체 → `loadedmetadata` → 목표 시각으로 탐색 → `seeked` → 재생.
- 위치를 옮길 때마다(훑기·재생 시작) 번호를 올린다. **마지막에 놓은 자리에 닿기 전에는 영상에 시계를 넘기지 않는다** —
  진행 중이던 옛 탐색이 끝나면 최신 자리로 한 번 더 보낸 뒤에 도착으로 친다.
- 배치가 바뀌어 위치를 보정하고 멈출 때는 영상의 옛 시각을 위치로 되받지 않는다.
- 재생 못 하는 영상은 정지화면으로 두고 길이만큼 지나간다. 적어 둔 길이보다 영상이 먼저 끝나면 그 클립의 끝으로 넘긴다.
- 탭이 가려지면 멈춘다. 떠날 때 rAF·이벤트·주소를 정리한다.
- 프레임마다 ref 로 고치는 것은 재생헤드·타임코드뿐이다. 보이는 클립·재생 상태는 바뀔 때만 React 에 알린다.
- 타임코드는 24fps 눈금이다(원본 프레임 단위 정확도 보장 아님).

> [!NOTE]
> 다음 클립을 미리 받지 않는다. 컷이 넘어갈 때 받는 시간만큼 선다(그동안 썸네일을 깐다). 거슬리면 영상 둘을 교대로 쓴다.

## 7. 조작

글자 키는 **물리 키**(`event.code`)로 본다 — 한/영 상태와 무관하다. 편집 키는 고정이고 단축키 설정 창에 없다.

| 키 | 동작 |
|---|---|
| Space | 재생/정지 |
| L · K · J | 정방향(다시 누르면 2·4·8배) · 정지 · 역방향(끊길 수 있음) |
| ← → | 한 프레임 · Shift 는 1초 |

클립 클릭 = 고르기(Ctrl·Shift 여러 개) + 재생헤드가 다른 컷에 있으면 그 컷으로 ·

  팀 생성물을 지우거나 옮기게 된다. 지금은 컷 더블클릭으로 여는 폴더 창에서 한다. 풀에 넣으려면 풀을 폴더 창처럼 앱의 격자·
  선택 상태로 그려야 한다(구조 변경 — 미정).
- 보기 방식·크기·정렬·싱글/듀얼은 **이 브라우저의 화면 설정**이다(`ch.editTimeline.ui` — 계정·시퀀스와 무관하게 하나, 편집 문서가
  아니라 되돌리기 대상도 아니다). 검색어는 남기지 않는다.
- 풀 안을 눌러도 편집 화면이 키를 받게 초점을 옮기지 않는다. 입력칸(검색·크기)만 초점을 받고, 검색칸의 Esc(접기)·Enter 나
  풀의 다른 곳을 누르면 초점을 떼어 Space·J·K·L 이 다시 편집 화면으로 간다.

  어느 카드인지 모른다) 넣지 않고 알린다. 그때 넣으면 같은 생성물이 두 트랙에 들어가거나 교체하면서 그 클립의 꺼짐이 사라진다.
  **그 카드만** 막는다 — 컷 전체를 막으면 목록이 2,000건에서 잘린 시퀀스에서는 영영 풀리지 않는다(Codex 코드 리뷰 2회).

### 싱글/듀얼 뷰어 (2026-10-08, Jay)

타임라인 뷰어의 시간 표시 오른쪽 단추로 바꾼다(다빈치의 Single Viewer Mode). **듀얼이면 왼쪽에 소스 뷰어**(`EditSourceViewer` —
미디어 풀에서 고른 생성물), 오른쪽에 타임라인 뷰어가 나란히 뜬다. 넣기 전에 후보와 지금 것을 나란히 보려는 것이다.

- 소스는 컷을 옮겨도 남는다(그 시퀀스의 공유 목록에 있는 동안). 소스로 보는 것은 타임라인을 바꾸지 않는다.
- 소스 영상은 **브라우저 기본 재생 막대**로 본다. 편집 키(Space·J·K·L·←→)는 언제나 타임라인 것이다 — 소스는 마우스로 조작한다.
  다빈치식 소스 조작(J/K/L·In/Out·끌어다 넣기)은 없다.
- 뷰어 아래 줄의 폭 기준은 창이 아니라 **뷰어 자신**이다(`container-type` — 좁으면 키 안내를, 더 좁으면 전체 길이를 숨긴다).
  미디어 풀과 듀얼 뷰어로 뷰어 폭이 창 폭과 따로 놀기 때문이다(창 폭 기준이던 때는 듀얼에서 단추와 글이 겹쳤다).

### 왼쪽 폴더 옆 표시 (2026-10-08, Jay)

왼쪽 폴더 목록에도 공유 & 리뷰 사이드바처럼 **새로 들어온 것(+N)·최종(★)·보류(R)** 가 보인다. 원천도 같다.

- ★·R·전체 = 폴더 개수 조회(`projectFolderCountsBatch`)의 같은 응답(`review_counts`). 총계와 상세가 안 맞거나 서버가 안 주면
  추정하지 않고 '전체 N'으로 보인다(`buildFolderCountTree` 의 규칙 그대로).
- +N = 기준선 이후 공유된 목록(`teamFreshAll`)에서 확인(카드 클릭)한 것을 뺀 것. 폴더 행은 하위 폴더의 것이 위로 모이고,
  프로젝트 행에도 붙는다. 기준선은 공유 & 리뷰에 처음 들어갈 때 생긴다 — 없으면 묻지 않는다. 폴더 창에서 카드를 누르면
  (확인) 그 자리에서 줄어든다.
- 폴더 창이 닫히거나 생성물이 바뀌었다는 알림이 오면 **숫자만 다시 받는다**(`reloadCounts` — 디스크 폴더는 다시 읽지 않고,
  받는 동안 트리를 치우지도 않는다. 실패하면 마지막 숫자를 둔다). 숫자는 **더 뒤에 떠난 조회의 것만** 덮는다(`countsRun`) —
  늦게 온 옛 응답도, 트리를 처음 받는 사이에 먼저 도착한 '다시 받기'의 숫자를 덮는 트리 조회도 막는다. 새 항목 조회도 마지막에
  떠난 것의 답만 쓴다(공간을 A→B→A 로 오갈 때 처음 A 의 늦은 답이 새 답을 덮지 않게 — Codex 코드 리뷰).

### 카드 우클릭 = 넣을 트랙 고르기 (2026-10-08, Jay)

미디어 풀의 카드, 그리고 컷 더블클릭으로 연 폴더 창의 카드를 **우클릭하면 지금 타임라인에 있는 트랙(V3·V2·V1)이 뜬다**
(`EditTrackMenu` — 트랙 줄 수는 타임라인과 같다: 3줄 이상, 가장 높은 클립까지). 고르면 그 카드가 그 컷의 그 트랙에 들어간다.

| 줄의 표시 | 고르면 |
|---|---|
| 비어 있음 | 그 트랙에 들어간다(쌓인다) |
| 교체 | 그 트랙에 있던 클립을 빼고 들어간다 |
| 지금 여기 | 이 카드가 이미 있는 트랙 — 고를 수 없다 |
| 잠김 | 잠긴 트랙이 걸린다(도착 트랙, 또는 이 카드가 지금 있는 트랙) — 고를 수 없다 |

- 이미 그 컷에 넣은 카드면 새로 넣지 않고 **그 클립을 옮긴다**(꺼짐·길이는 그대로, 떠난 트랙은 빈다). 끌어서 옮기기는 찬 자리와
  맞바꾸지만, 메뉴는 Jay 지정대로 교체다(`placeClip`). 한 번 고른 것이 되돌리기 한 단계다.
- 넣을 컷은 메뉴를 여는 순간에 정한다 — 미디어 풀은 재생헤드가 있는 컷, 폴더 창은 그 창의 컷. 보던 컷이나 창이 바뀌면 메뉴는 닫힌다.
- **편집 탭의 그 컷 공유 목록에 있는 카드만 받는다.** 창에서 W 를 '전체 보기'로 바꿔 보이는 다른 공간의 카드, 완료되지 않은 카드는
  넣어도 타임라인이 '미디어 없음'으로 보므로 받지 않고 알린다.
- 창의 카드 표("V1 - 선택 카드")는 창이 떠 있는 동안 살아 있다 — 편집 탭이 내용이 바뀔 때만 App 에 다시 알린다(`onPeekMarks`.
  글로 비교한다: 알릴 때마다 App 이 다시 그려지므로 객체로 비교하면 끝없이 돈다). 표는 `folderWindow` 가 아니라 따로 둔
  상태(`editMarks`)다 — 창의 조회 조건·'그 카드로 내려가기'가 `folderWindow` 객체에 묶여 있다.
- 메뉴는 body 로 옮겨 그린다(창이 떠 있는 동안 `.body` 는 inert). Esc 는 메뉴가 캡처 단계에서 먹어 뒤의 창이 같이 닫히지 않고,
  닫히면 초점을 열기 전 자리로 돌려준다. **떠 있는 동안 메뉴 밖에서 난 키는 뒤 화면(편집 키·라이브러리 키)으로 보내지 않는다**
  — 고를 줄이 하나도 없는 메뉴(전부 잠김)에서 M·R 이 뒤에서 실행되던 길이다. **Tab 도 메뉴를 닫는다** — 초점이 메뉴 밖 단추로
  나가면 Enter·Space 로 그 단추가 눌린다(전파를 막아도 단추의 기본 동작은 남는다). 줄은 ↑↓ 로 옮긴다(Codex 코드 리뷰 2회). 격자는 무엇을 눌렀는지만 알린다(`ThumbnailGrid.onCardMenu` — 안 준 화면은 브라우저 메뉴 그대로).

### 생성물 카드와 표 (2026-10-08, Jay)

미디어 풀 썸네일 보기의 **카드**(`EditCard`)는 라이브러리 카드와 같은 모양이다 — 상태색 테두리(공유 라임·보류 빨강·최종 골드)·S/★ 배지·
작성자 배지·▶. 값을 베끼지 않고 **라이브러리의 CSS 클래스를 그대로 쓴다**(`card`·`card-thumb`·`card-sf`·`creator-badge`·
`play-badge`·`card-bottom`·`card-here`). 카드 안 조작(공유·태그·코멘트)은 없다 — 그것은 컷 더블클릭으로 여는 폴더 창에서 한다.

- 넣은 카드 = 라이브러리의 '선택'과 같은 굵은 상태색 테두리(`.card.selected`). 풀에서 고른 카드(소스)는 바깥의 흰 테두리(`.ed-picked`).
- 아래 변 가운데의 표 = 폴더 창의 '방금 누른 카드'와 같은 자리·같은 모양. 타임라인에 넣은 카드마다 **"V1 - 선택 카드"**처럼
  트랙과 함께 붙는다. 지금 뷰어에 보이는 것만 라임(`.card-here`), 아래에 깔리거나 꺼진 것은 옅게(`.card-folder.static`).

### 컷 더블클릭 = 공유 & 리뷰의 '폴더 보기' 창 (2026-10-08, Jay)

컷 자리를 더블클릭하면 재생헤드를 그 컷으로 옮기고(이미 그 컷이면 그대로) 재생을 멈춘 뒤, **공유 & 리뷰 탭의 폴더 창과 같은 창**
(`App.renderFolderPeek` — 툴바·진짜 카드·선택 막대·색·태그·검토·일괄 작업)을 그 컷 폴더로 연다. 편집에서만 다른 점은 표다:
타임라인에 넣은 카드에 위의 "V1 - 선택 카드"가 붙고(`cardMarks`), 창은 지금 보이는 카드로 내려가서 열린다.
창 안의 클릭은 라이브러리의 '고르기'다 — 타임라인에 넣는 것은 카드 우클릭(위), 빼는 것은 미디어 풀(더블클릭)이나 타임라인(Delete)에서 한다.

그 창은 앱의 하나뿐인 목록 조회를 빌려 그리고 카드·액션의 동작이 `filters.tab` 에 묶여 있다. 그래서 창이 떠 있는 동안
**목록·카드·액션만 공유 & 리뷰로 본다**(`App` 의 `teamPeek` → `useLibraryFilters` 의 세 번째 인자).

- 밖에 내주는 `filters`·조회·공간 범위만 `tab: "team"` 이 되고(휴지통 보기도 끈다 — 목록 훅이 휴지통 API 를 고르는 열쇠다),
  **저장된 filters 는 그대로**다. 탭 저장·뒤로가기 기록(`useAppNavigation` 은 `storedTab` 을 쓴다)·다음 생성 위치를 건드리지 않는다.
  탭을 실제로 바꿨다 되돌리면 기록과 저장에 임시 상태가 샌다(Codex 설계 검토).
- 창의 문맥 = 계정·워크스페이스뿐이다(`editPeekCtx`). 창 안에서 W(자동/전체)를 바꾸는 것은 문맥 변경이 아니라 창이 유지된다.
  편집을 떠나면 그 렌더부터 `teamPeek && editOpen` 이 거짓이라 떠난 탭이 한순간도 공유 & 리뷰로 그려지지 않는다.
- 떠 있는 동안 편집 키는 쉬고(`keysActive`) 라이브러리 키가 듣는다(`libraryKeysOffRef = editOpen && !listPeek`). `.body` 는 inert.
- 닫으면 밑의 탭 목록을 비우고 원래 조회로 돌아가며, 편집 탭은 공유 목록을 다시 받는다(`reloadSignal`). 닫은 뒤에 끝난 변경
  (공유 해제·삭제)은 `libraryChanged` 알림으로 한 번 더 받는다(0.4초 몰아서).
- 문맥이 바뀌어 무효가 된 창은 목록을 비우지 않는다 — 바뀐 문맥의 조회가 이미 떠났고, 비우면 그 응답까지 버린다.

한계: 지금 보이는 카드가 첫 쪽(200장) 밖이거나 툴바 필터에 가려지면 그 카드로 내려가지 않는다. 공유 & 리뷰의 W 가 '전체 보기'면
창도 전체를 보여, 미디어 풀(자동 범위)과 목록이 다를 수 있다. 밑의 탭이 공유 & 리뷰일 때 창에서 W 를 바꾸면 그 탭에서 바꾼 것과
같아 그 탭의 보던 위치가 풀린다(다른 탭이면 건드리지 않는다). 목록 보기에서는 표가 카드 아래 변이 아니라 모델 이름 옆의 글이다.
창이 떠 있는 동안 도착한 '방금 만든 생성물'은 목록에 끼워 넣지 않는다(`usePromptCreatedActions` — 로컬 카드가 팀 목록에 섞이면
로컬 id 로 팀 요청이 나간다).

### 컷(폴더) 비활성과 숨기기 (2026-10-08, Jay)

- **기본값**: 공유물도 넣은 클립도 없는 빈 폴더, 그리고 다른 탭의 사이드바에서 비활성(d)으로 둔 폴더(`deactivated.ts` — 읽기만).
  '비었다'는 **지금 든 공유 목록이 끝까지 받은 결과일 때만** 믿는다(`list.known` — 다시 받는 동안·실패한 뒤에는 마지막으로
  끝까지 받은 목록이 그대로 남아 참이고, 2,000행에서 잘린 결과로 바뀌면 거짓이다).
- **D**: 고른 클립이 있으면 그 클립을, 없으면 재생헤드가 있는 컷(폴더)을 켜고 끈다. 컷 이름을 누르면 클립 고르기가 풀려
  이어서 누르는 D 가 그 폴더에 걸린다. 편집 탭에서 켜고 끈 것은 **이 편집 문서에만** 적는다(`cutsOn`·`cutsOff` — 기본값과
  다를 때만. 다른 탭의 폴더 비활성은 바꾸지 않는다). 되돌리기 대상이다.
- 비활성 컷은 이름에 줄이 그어지고 흐리다(왼쪽 폴더 목록도 회색). **[비활성화 폴더 숨기기]**(`hideOff`)를 켜면 배치에서 아예
  빠진다 — 타임라인에도 재생에도 없고, 문서의 클립은 그대로 남는다. 숨기기를 켠 채 지금 컷을 끄면 재생헤드는 다음 컷으로 간다.

키가 듣는 조건: 편집 탭이 떠 있고 · 위에 다른 창이 없고(`keysActive`) · 입력칸이 아니고 · 키가 body 나 편집 화면에서 났을 때.
실제로 쓴 키만 기본 동작을 막는다(Ctrl+=/- 의 페이지 확대 포함). 초점이 있는 단추의 Space 는 그 단추 것이라, 편집 화면의
단추들은 mousedown 에서 초점을 가져가지 않는다. 휠은 타임라인 안에서만 가로챈다.

(저장됨·뷰어가 그만큼 줄어듦) → Ctrl+누르기로 2장("2개 선택 · 비교") → 비교 창(영상 재생) → Esc → 더블클릭(크게 보기 창 — 영상
재생·[히스토리 보기]) → Esc → →가 한 프레임 감 → 빈 곳에서 끌어 상자로 8장(상자가 보이고 "8개 선택") → 비교 창 `버전 비교 (8)`.
생성 요청 0건·리소스 실패 외 콘솔 오류 0건. 폭 손잡이를 끈 뒤 ←·→ 가 풀 폭을 바꾸던 것(손잡이에 초점이 남음)을 실측으로 찾아
놓을 때 편집 화면으로 초점을 돌려주게 고쳤다(그 수정 뒤의 화면 재실측은 하지 않았다 — 자동 시험만).

**실측하지 못한 것**: 캔버스에서 생성이 도는 중에 편집 탭으로 넘어갔을 때의 완료 감시(유료 호출 금지 — 코드로만 확인) ·
클립을 마우스로 끌어 트랙 옮기기(키 Alt+↑/↓ 와 순수 함수 시험만) · 실제 공유 서버(프록시) 경유 · 긴 영상·느린 회선에서의 컷 넘김.
