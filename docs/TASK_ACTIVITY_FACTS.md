## 구현 계약

1. 관리 DB를 읽기 전용으로 읽어 팀 공간·프로젝트·폴더가 확인된 생성 기록을 연결한다.
   기존 폴더 작업 키를 재사용하고 새 행만 보장한다. 수동 태그 레인은 추측 확장하지 않는다.
2. 공유 콘텐츠와 팩트의 동일 생성물은 한 번만 집계한다. 생성자·비어 있지 않은 job ID 또는
   검증된 로컬 ID를 대조하며 다계정/중복/NULL의 모호한 연결은 만들지 않는다.
3. 공유 콘텐츠가 현재 존재하면 서버의 귀속·공유·최종 상태가 우선한다. 미공유 잔존본은
   대응 팩트의 이동·삭제를 반영한다. 조회 프로젝트 밖으로 이동한 팩트도 대조한다.
   서버 공유본 삭제/부재는 개인 원본 삭제의 증거가 아니다. 살아 있는 팩트는 미공유 작업
   메타로 유지하고, 소유자의 `is_deleted` 보고만 원본 작업 기록 제외의 근거로 삼는다.
   활성 서버 콘텐츠가 없으면 팩트의 낡은 공유/최종 표식으로 이를 복원하지 않는다.
   정상 서버 계약인 `is_final ⇒ shared`를 만족한 활성 콘텐츠의 최종 판정만 우선한다.
   최종만 있고 공유 행이 없는 모순된 레거시 데이터는 공유를 복원하지 않고 미공유 메타로 취급한다.
4. 팩트 열람은 기존 `read_all` 또는 본인 `(creator_uid, account_email)` 범위를 따른다.
   공유 컷 조회 권한은 기존 프로젝트 권한을 유지한다. 비공유 콘텐츠의 미디어 주소는
   관리 권한 여부와 무관하게 작업 목록 응답에서 제거한다.
5. 본인의 미공유 컷만 로컬 전용 배치 API로 썸네일을 보강한다. 소유자·팀 공간·프로젝트·폴더를
   다시 검사하고 다른 PC/없는 항목은 자리표시로 남긴다. 원격 재조회·미디어 저장은 하지 않는다.
6. 프런트의 작업 집계에는 미디어 없는 컷도 포함한다. 타인 미공유는 메타만 표시하고,
   팩트 식별자를 생성물 변경·수동 연결·비활성 API에 사용하지 않는다.
7. 목록/응답 캐시와 ETag는 조회자·권한으로 분리한다. 프런트는 계정·공간·요청 순서가
   달라지면 옛 응답과 썸네일을 폐기한다. 미리보기 실패는 작업 기록을 없애지 않는다.
8. 새 조회 API는 로컬 전용 및 변경 알림 제외로 분류한다. 완료본 저장의 기존 컷 판정 함수는
   변경하지 않는다. 별도 폴링·유료 생성·원본 다운로드는 추가하지 않는다.

### 조회 경계와 응답

- `include_activity`는 HTTP 입력으로 받지 않는다. `/tasks`·`/tasks-batch`·`/task-projects`는
  `_task_activity_access` 한 곳에서 공식 실행 모드로 결정한다. 실제 공유 팀 서버는 항상 `True`,
  단독 로컬·격리 dev는 엄격한 루프백 브라우저 검사 후 `False`로 기존 콘텐츠 표시를 보존한다.
  로컬·개인 공간 원본을 metadata_only로 바꾸지 않는다. 완료본 판정·저장 내부 경로도 그대로다.
- 모드 판별은 `_proxy.is_shared_team_server()`(AUTH on + NO_PROXY off)이며 요청 파라미터·
  토큰 유무·`configured` 값으로 바꾸지 않는다. 프록시 팀 요청은 라우터 전에 공유 서버로 위임되고,
  공유 서버 실패 시 로컬 콘텐츠로 폴백하지 않는다. HTTP 캐시/ETag에 모드 bool도 포함한다.
- 로컬 기존 콘텐츠 경로는 이미 이 PC의 계정 DB에 있는 콘텐츠를 표시하는 동작이다. 과거에
  받아 둔 팀 콘텐츠 캐시까지 원격에서 회수하는 기능은 추가하지 않는다. 새 private 팩트와 원문을
  결합하는 허가도 아니다. 새 서버 팩트 계약은 helper의 서버 모드를 명시한 격리 fixture로 검증하며,
  NO_PROXY를 끄거나 실제 서버에 연결하지 않는다.
- 로컬 출처 검사 실패는 403이며 빈 viewer로 강등해 미디어를 반환하지 않는다. 기존 가드처럼
  Origin/Referer 없는 native 요청은 루프백 조건으로 허용하되, 브라우저의 외부 Host/Origin/Referer와
  cross-site fetch 문맥은 거부한다. 새 CORS/인증 우회나 허용 출처 확대는 없다.
- 배치 응답은 기존 `Cache-Control: private, no-cache`와 `Vary: Accept-Encoding`을 유지한다.
  모드·DB 경로·조회자/권한 지문·내용 변경 표식으로 ETag를 분리하고 매 요청 권한 검사 후 재검증한다.
  `no-store`로 조건부 조회 최적화를 없애지 않는다. 공유 캐시는 private 응답을 재사용할 수 없다.
- `activity_read_all=False`를 명시적 기본값으로 한다. `activity_viewer=(uid,email)`이 없으면
  read_all이 True여도 미공유 메타를 반환하지 않는다(deny 우선). 확인된 조회자가 있을 때만
  `activity_read_all=True`로 전사 권한 범위를 연다. 관리자의 조회자 쌍도 명시적으로 넘긴다.
- `preview_owner=(uid,email)`은 전사 권한과 별개로 로그인 본인만이다. 없으면 로컬 식별 힌트가 없다.
- 캐시/ETag 범위에는 read_all 여부와 정규화한 조회자·preview_owner의 UID/이메일 쌍의
  SHA-256 지문을 포함한다. 식별자 원문을 응답 헤더나 로그에 남기지 않는다.
- 기존 `cuts`에 `metadata_only`를 추가한다. 팩트 전용 컷 ID는 `fact:<관리행 UUID>`,
  `linked=False`다. 콘텐츠 컷의 기존 ID와 `linked`는 보존한다. 본인에게만 `local_gen_id`와
  `job_id`를 미리보기 상관관계로 제공한다. 이 힌트를 서버 쓰기 ID로 사용하지 않는다.
- `POST /api/manage/local-task-previews`는 최대 500개 후보와 기대 viewer UID를 받아,
  본인 로컬 데이터에서만 썸네일/타입/경로/정식 로컬 ID를 반환한다. 다른 계정·공간·폴더는
  반환하지 않으며, 공유 서버 본체와 외부 브라우저 출처는 거부한다. 요청 동안 계정 키·UID를 고정한다.
- 본인 로컬 미리보기 실패는 작업 통계와 상태에 영향을 주지 않는다. 타인 미공유는 이미지
  요청 없이 표시하며, 프런트에 없는 식별자를 임의로 추측하지 않는다.

## 완료 조건

- 팩트만 수신한 폴더 생성물이 `생성`으로 표시된다.
- 공유·공유 해제·최종 지정·최종 해제 후 건수와 상태가 중복/역행하지 않는다.
- 일반 사용자와 관리자, 같은 폴더의 여러 생성자, 계정 전환의 권한 경계를 검증한다.
- 삭제·이동·개인/미상 귀속, job ID 없음/충돌, 기존 PM 편집·과거 작업을 검증한다.
- 로컬 미리보기는 본인만, 잘못된 위치·타인·공유 서버 직접 접속·오래된 응답은 차단한다.
- 동일 목록의 반복 조회는 불필요한 쓰기를 만들지 않으며 새 팩트는 캐시를 무효화한다.
- 관련 백엔드/프런트 회귀·빌드·아키텍처 검사 및 격리 화면 검증, Claude 독립 리뷰를 완료한다.

## 적용 범위와 제한

- 클라이언트와 서버가 함께 업데이트되어야 작업 메타와 본인 로컬 미리보기가 모두 동작한다.
  구서버는 기존 작업 표시를 유지하고 로컬 API가 없는 구클라이언트에서는 메타만 표시될 수 있다.
- 생성 기록의 도착은 기존 관리 동기화 주기를 따른다. 오프라인/미보고 과거 기록을 자동 복구하거나
  전체 로컬 파일을 스캔하는 기능은 이번 범위에 없다.
- fact가 없는 레거시 미공유 콘텐츠는 관리자에게 메타만 제공한다. 일반 사용자의 소유 계정을
  증명할 수 없으면 숨기며 UID/job 중복 등 모호한 연결에 미리보기 힌트를 제공하지 않는다.
  이는 공유 서버 규칙이다. 단독 로컬·개인 콘텐츠는 출처 검사 후 기존 표시를 보존한다.
- 서로 다른 계정이 같은 UID/job을 중복 보고하고 서버 콘텐츠 앵커가 전혀 없으면 별도 기록으로
  남을 수 있다. 근거 없이 소유권/계정 기록을 병합하지 않으며 기존 관리 장부와 같은 제한이다.
- 서버 공유본 삭제는 원래 생성물 삭제가 아니다. 유효한 미공유 활동은 남되 공유 원본을 복원하지 않는다.
- 새 DB·미디어 저장 정책 변경 없음. 후속 보완에서 콘텐츠/관리 DB에 nullable `task_activity_at`과
  선택적 전송 필드를 추가한다. 기존 행은 NULL이며 시작 시 정상 호환 마이그레이션만 수행한다.
  필요한 폴더 작업 행은 종전과 같은 방식으로 보장하고 PM 편집값은 보존한다. 운영 DB 수동 변경 없음.
- 사용자가 dev 재시작과 e001/c0010 본인 생성물 5개의 명시 복원을 승인했다. 다른 보관 기록은
  유지한다. 이후 dev 커밋도 승인했으며 설치본/운영 서버 적용·푸시·병합·배포는 승인 범위 밖이다.
- 단독 로컬/격리 dev 작업 목록은 localhost/127.0.0.1의 같은 PC 브라우저 전용이다.
  LAN으로 직접 여는 경우 403이며, 정상 작업자 허브의 공유 서버 위임과 실제 팀 서버 접근에는 영향 없다.
